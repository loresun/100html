# 礼物清单帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你正在为即将到来的节日、生日或纪念日做准备。你需要给不同的人准备礼物，但容易忘记谁需要什么、预算是多少、哪些已经买好了。这个网页就像一个**数字化的礼物管家**，帮你把所有送礼对象和礼物想法集中管理。

**适合场景：**
- 节日季（如圣诞节、春节）需要给多人准备礼物
- 为家人朋友的生日、纪念日提前规划
- 控制送礼预算，避免超支
- 跟踪礼物的准备进度（从想法到包装完成）

**不适合场景：**
- 需要复杂的多人协作（如家庭共同准备）
- 需要生成礼物建议（它只管理，不推荐）
- 需要与电商平台直接集成购买

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 送礼对象的姓名、场合（生日/节日等）、日期
- 每个对象下的具体礼物名称和价格
- 通过点击或选择来标记礼物的状态

**用户通常会做哪几步操作？**
1. **添加送礼对象**：点击右上角“新人选”按钮，填写姓名、场合和日期
2. **为每个人添加礼物**：在每个卡片下方的输入框里，输入礼物名称和价格，按回车添加
3. **跟踪进度**：
   - 点击礼物前的方框，快速标记为“已完成”或“未完成”
   - 点击状态文字（如“想法”），循环切换：想法 → 待买 → 已买 → 已包
4. **删除项目**：将鼠标悬停在礼物上，点击右侧的“×”删除；点击卡片右上角的垃圾桶删除整个送礼对象

**输出结果长什么样？**
- 每个送礼对象显示为一个卡片
- 卡片顶部显示姓名、场合和日期
- 礼物列表显示名称、价格和状态（用不同颜色区分）
- 卡片底部有进度条，显示已完成的礼物比例
- 页面顶部显示总预算和已支出金额

**容易忽略的使用细节：**
- **状态切换有两种方式**：点击方框是“想法/已完成”快速切换；点击状态文字是四步循环切换
- **数据自动保存**：所有操作都会自动保存到浏览器，关闭页面后数据还在
- **移动端适配**：在手机上，预算信息会显示在顶部卡片中
- **日期可选**：如果不填日期，只显示场合标签

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

### 1. 数据管理模块（JavaScript 函数）
- **职责**：存储所有送礼对象和礼物的数据，处理增删改查逻辑
- **关键设计**：使用 Alpine.js 的响应式数据，所有操作都更新 `recipients` 数组，自动触发界面更新

### 2. 界面展示模块（HTML + Tailwind CSS）
- **职责**：将数据可视化为用户友好的界面
- **包含**：
  - 顶部统计栏（预算/支出）
  - 送礼对象卡片网格
  - 每个卡片内的礼物列表
  - 空状态提示
  - 添加对象的弹窗

### 3. 状态跟踪模块
- **职责**：管理每个礼物的准备状态
- **状态流转**：想法 → 待买 → 已买 → 已包（四步循环）
- **视觉反馈**：不同状态对应不同颜色（灰色→黄色→绿色→粉色）

### 4. 本地存储模块
- **职责**：自动保存数据到浏览器，实现“关闭页面不丢数据”
- **实现方式**：监听 `recipients` 数据变化，自动保存到 `localStorage`

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入（添加对象/礼物） 
    → 更新 recipients 数组 
    → Alpine.js 检测到数据变化 
    → 自动更新界面显示
    → 同时触发 localStorage 保存
```

**最值得学习的设计：**
**“状态驱动界面”** 的思维。整个页面不直接操作 DOM，而是通过改变数据状态（如 `gift.status` 从 `'idea'` 变为 `'buy'`），让框架自动更新对应的界面元素。这种模式让代码更清晰、更容易维护。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：当前版本**没有使用 AI 或 Prompt**。这是一个纯前端的管理工具。

**如果我们要为它添加 AI 功能，可以这样设计：**

假设我们想添加“智能礼物推荐”功能：

**Prompt 扮演的角色：**
- 根据送礼对象的信息（年龄、性别、场合、关系）生成礼物建议
- 解决“不知道送什么”的问题

**关键变量会包括：**
```
收礼人：{{person.name}}
场合：{{person.occasion}}
关系：{{relationship}}（需要额外输入）
预算范围：{{budgetRange}}
兴趣关键词：{{interests}}
```

**如果只改 Prompt，不改代码：**
- 可以改变推荐风格（如从“实用型”变为“创意型”）
- 可以调整推荐数量
- 可以改变回复格式（列表式 vs 描述式）

**当前版本的学习价值：**
即使没有 AI，这个页面展示了如何构建一个**完整的数据管理应用**。你可以先掌握这个基础结构，再考虑在哪里插入 AI 功能（比如在添加礼物时，多一个“AI 推荐”按钮）。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：替换使用场景，保持结构不变**
- 把“送礼对象”改成你的场景，比如：
  - 学习计划 → “学习科目”
  - 项目管理 → “项目任务”
  - 购物清单 → “商品分类”
- 只改文字，不动代码结构

**第二步：调整数据字段**
- 修改 `newPerson` 对象中的字段：
  ```javascript
  // 原版
  newPerson: { name: '', occasion: '生日', date: '' }
  
  // 学习计划版
  newSubject: { name: '', difficulty: '中等', deadline: '' }
  ```
- 对应修改弹窗中的输入项

**第三步：改变状态逻辑**
- 修改礼物的四种状态：
  ```javascript
  // 原版：想法 → 待买 → 已买 → 已包
  // 学习版：未开始 → 进行中 → 复习中 → 已完成
  ```
- 调整状态对应的颜色和标签

**第四步：修改统计方式**
- 原版统计“预算”和“支出”
- 你的版本可能统计“总任务数”和“完成数”
- 修改 `totalBudget` 和 `totalSpent` 的计算逻辑

**从哪里下手最安全？**
从 **文字替换** 开始，然后是 **字段名修改**，最后才是 **逻辑调整**。每次只改一小部分，测试确保功能正常。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加预算分类
**当前**：只有一个总预算
**改造**：为每个送礼对象设置独立预算
- 在添加对象时增加“预算上限”字段
- 在卡片顶部显示“预算：¥XXX / 已用：¥YYY”
- 当超预算时，卡片边框变为红色警告

### 2. 添加分享功能
**当前**：数据只存在自己电脑
**改造**：生成可分享的链接
- 点击“分享”按钮，将数据编码到 URL 中
- 别人打开链接能看到只读版本的清单
- 使用 `URLSearchParams` 和 `btoa` 实现简单编码

### 3. 引入 AI 礼物推荐
**当前**：完全手动输入礼物
**改造**：添加“AI 推荐”按钮
- 在礼物输入框旁添加魔法棒图标
- 点击后调用 OpenAI API，基于对象信息生成 3-5 个建议
- 显示为可选择的下拉列表

### 4. 改进移动端体验
**当前**：在手机上功能完整但操作稍小
**改造**：
- 为移动端添加底部导航栏
- 增大点击区域（特别是删除按钮）
- 添加滑动删除手势
- 使用 `@touch` 事件替代部分 `@click`

### 5. 添加数据导入/导出
**当前**：只能通过界面操作
**改造**：
- 添加“导出为 JSON”按钮
- 添加“从 Excel 导入”功能（解析 CSV）
- 添加“一键清空”功能
- 在设置中添加数据备份提醒

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不适合团队协作**
   - 数据存在本地，无法多人同时编辑
   - **如果需要**：考虑使用 Google Sheets、Notion 或专门的项目管理工具

2. **没有智能推荐**
   - 只是一个“记录工具”，不会帮你出主意
   - **如果需要**：结合 ChatGPT 对话，或使用专门的礼物推荐网站

3. **无法直接购买**
   - 不能点击礼物跳转到电商平台
   - **如果需要**：手动添加商品链接字段，或使用浏览器书签管理

4. **没有提醒功能**
   - 不会在日期临近时提醒你
   - **如果需要**：将日期导出到日历应用，或使用待办事项工具

5. **数据有丢失风险**
   - 清空浏览器缓存会丢失所有数据
   - **重要数据**：定期导出备份，或考虑开发后端存储版本

**记住**：这个工具的核心价值是**帮你理清思路、跟踪进度**，而不是替代你的决策或记忆。把它当作数字化的便利贴，而不是万能管家。
