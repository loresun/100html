# Webtools 工具箱 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正在准备一个项目，需要计算预算分配。或者，你正在学习，需要一个番茄钟来管理时间。又或者，你只是想把一些零散的想法记下来。这个网页就像一个**数字瑞士军刀**，把多个常用的小工具整合在一个页面里，让你无需安装多个App或打开不同网站，就能快速完成这些日常小任务。

**适合什么情况？**
- **快速计算**：比如分配预算、单位换算等一次性计算
- **时间管理**：需要计时、倒计时、番茄工作法
- **简单记录**：记账、记笔记、列待办清单
- **临时工具需求**：不想为偶尔用一次的功能安装软件

**不适合什么情况？**
- **复杂数据处理**：如Excel表格、数据库操作
- **专业工具需求**：如图像编辑、代码编译
- **多人协作**：所有数据都保存在本地浏览器
- **长期项目管理**：工具功能相对简单，不适合复杂项目管理

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
页面中央有一个白色卡片区域，根据你选择的工具不同，会出现不同的输入框。比如：
- **预算计算器**：需要输入总预算和各项目比例
- **番茄钟**：需要设置专注时间和休息时间
- **记账工具**：需要输入金额、分类和备注

**用户通常会做哪几步操作？**
1. **选择工具**：页面加载后默认显示某个工具（如预算分配）
2. **填写参数**：在输入框中填入相应的数值或文字
3. **点击按钮**：点击"计算结果"、"开始"、"添加"等按钮
4. **查看结果**：在下方查看计算出的结果或计时状态

**输出结果长什么样？**
- **计算结果**：以清晰的卡片形式展示，如"项目A: ¥3,000"
- **计时器**：显示倒计时的数字时钟
- **清单**：显示已添加的项目列表，可勾选完成
- **统计数据**：如本月累计支出、记录条数等

**有哪些容易忽略的使用细节？**
1. **数据保存**：大部分工具的数据会自动保存在浏览器中，刷新页面不会丢失
2. **单位注意**：有些输入框有单位提示（如"元"、"分钟"），填写时要注意
3. **回车快捷**：在清单工具中，输入后按回车可直接添加项目
4. **设置入口**：右上角的齿轮图标可以配置API（如果需要AI功能）

## 【三】核心结构拆解（学习重点）

**页面由哪几个关键模块组成？**
1. **导航栏**：顶部区域，包含返回按钮和设置入口
2. **工具容器**：中央白色卡片，所有工具的"舞台"
3. **工具切换系统**：通过`tool.type`控制显示哪个工具
4. **数据管理**：每个工具独立的数据结构和状态
5. **设置面板**：弹出的API配置窗口

**每个模块承担什么职责？**
- **导航栏**：提供页面导航和全局设置入口
- **工具容器**：根据当前工具类型动态渲染对应的界面
- **工具逻辑**：每个工具类型有独立的计算/计时/处理函数
- **状态管理**：使用Alpine.js管理工具状态和数据
- **本地存储**：将用户数据保存到浏览器localStorage

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入 → Alpine.js数据绑定 → 工具处理函数 → 更新结果 → 渲染显示
      ↓
  自动保存到本地存储
```

**哪一部分是"这个网页最值得学习的设计"？**
**"一套代码，多种工具"的架构**最值得学习。它通过：
1. **统一的工具类型系统**（`type: 'formula' | 'timer' | ...`）
2. **动态界面渲染**：根据`tool.type`显示对应的HTML片段
3. **模块化的处理函数**：每个工具类型有独立的函数集
4. **一致的数据结构**：所有工具都遵循相似的数据模型

这种设计让你可以轻松添加新工具，而不用重写整个页面。

## 【四】Prompt / AI 逻辑是如何被设计的？

**注意**：当前提供的HTML代码中，AI功能主要通过外部`standalone.js`文件实现，页面本身主要展示配置界面。但从结构可以看出：

**Prompt 在这个页面中扮演什么角色？**
（根据设置面板推断）Prompt 可能是用来：
- **理解用户需求**：将自然语言转换为工具参数
- **生成建议**：基于输入数据提供优化建议
- **解释结果**：用更友好的语言说明计算结果

**它解决的是"理解问题"还是"生成问题"？**
从配置选项看，可能两者都有：
- **理解问题**：比如"帮我分配1万元预算" → 解析为具体参数
- **生成问题**：比如基于预算数据生成分配建议

**哪些信息是 Prompt 中的关键变量？**
从API配置推断，关键变量可能包括：
- 用户的具体输入数据
- 工具类型和上下文
- 期望的输出格式

**如果只改 Prompt，不改代码，会发生什么变化？**
- **改变交互方式**：从手动输入变为自然语言对话
- **改变输出质量**：结果解释更人性化或更专业
- **改变适用场景**：可能支持更复杂的查询

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）：**

**第一步：保持结构不变，替换使用场景**
- 修改`tool`对象中的`name`和`desc`，换成你的工具名称和描述
- 比如把"预算分配"改为"热量计算"，"总预算"改为"总热量"

**第二步：调整输入字段或 Prompt**
- 修改`tool.fields`数组，改变输入项的数量和标签
- 调整每个字段的`key`、`label`、`unit`等属性
- 比如从"项目A比例"改为"早餐热量比例"

**第三步：改变输出形式或展示方式**
- 修改结果渲染部分，可以改成图表、进度条等
- 调整CSS样式，改变颜色、布局
- 比如用环形图展示分配比例

**最安全的下手点：**
从**公式计算器**（`type: 'formula'`）开始模仿，因为：
1. 结构最清晰：输入 → 计算 → 输出
2. 代码最独立：处理逻辑集中在`calculate`函数
3. 风险最小：不涉及计时器、状态管理等复杂功能

## 【六】3–5 个可直接尝试的改造方向

**1. 增加"自定义工具"功能**
- **怎么做**：添加一个"创建新工具"按钮
- **具体操作**：让用户定义字段名称、计算公式、显示格式
- **效果**：用户可以根据自己需求创建专属工具

**2. 添加数据导出/导入**
- **怎么做**：在设置面板增加"导出数据"和"导入数据"按钮
- **具体操作**：将localStorage中的数据导出为JSON文件
- **效果**：数据可以备份或在不同设备间同步

**3. 增加工具分类和搜索**
- **怎么做**：在左侧添加工具分类导航栏
- **具体操作**：按"计算类"、"时间类"、"记录类"分类
- **效果**：工具多了之后更容易找到需要的功能

**4. 添加分享功能**
- **怎么做**：每个工具结果旁边添加"分享"按钮
- **具体操作**：生成包含当前参数和结果的URL
- **效果**：可以快速分享计算结果给他人

**5. 增加主题切换**
- **怎么做**：在设置中添加"深色模式"选项
- **具体操作**：通过CSS变量或Tailwind类切换主题
- **效果**：适应不同光线环境或个人偏好

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不适合复杂计算**
   - **例子**：需要多步骤迭代、条件判断的复杂公式
   - **替代方案**：使用Excel、Google Sheets或专业计算软件

2. **不适合大量数据管理**
   - **例子**：管理上百条记账记录或待办事项
   - **替代方案**：使用专业记账软件（如MoneyWiz）或任务管理工具（如Todoist）

3. **不适合实时协作**
   - **例子**：多人同时编辑预算或共享待办清单
   - **替代方案**：使用Google Docs、Notion或腾讯文档

4. **不适合离线重度使用**
   - **例子**：在没有网络时频繁使用AI相关功能
   - **替代方案**：使用本地安装的桌面应用

5. **不适合专业场景**
   - **例子**：企业级预算规划、正式项目时间跟踪
   - **替代方案**：使用专业项目管理工具（如Jira、Asana）

**记住**：这个工具的核心价值是**快速、简单、临时**。它不是为了替代专业软件，而是填补那些"偶尔需要但不想安装专门软件"的使用场景。
