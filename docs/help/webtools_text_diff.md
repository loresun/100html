# 文本差异对比工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景**：当你需要**精确找出两段文本之间的差异**时，这个工具就像一位细心的校对员。比如：
- **写作修改**：你改了一篇文章，想看看具体改了哪些词句
- **代码审查**：对比两个版本的代码，找出被修改的行
- **合同核对**：检查合同修改前后的条款变化
- **翻译校对**：对比原文和译文的对应关系

**适合情况**：
- 需要快速、直观地看到文本差异
- 对比内容在几百字到几千字之间
- 不需要保留复杂的格式（如表格、图片）

**不适合情况**：
- 对比整个文档或书籍（太长会卡顿）
- 需要对比带格式的文档（如Word、PDF）
- 需要合并差异或生成修改建议

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 左侧文本框：输入原始文本（比如旧版本）
- 右侧文本框：输入修改后的文本（比如新版本）

**操作步骤**：
1. 在两个文本框中分别粘贴或输入要对比的内容
2. 点击蓝色的“开始对比”按钮
3. 查看对比结果页面

**输出结果长什么样？**
- **绿色高亮**：新增的内容（新文本有而原文没有）
- **红色删除线**：删除的内容（原文有而新文本没有）
- **灰色普通文字**：没有变化的部分
- 顶部会显示统计：新增了多少处，删除了多少处

**容易忽略的细节**：
- 点击“加载示例”可以快速体验功能
- 每个文本框右上角都有“清空”按钮
- 对比完成后，点击“返回编辑”可以继续修改
- 换行符会被保留，所以段落格式很重要

## 【三】核心结构拆解（学习重点）

这个页面由**三个核心模块**组成：

### 1. 输入模块（双文本框）
- **职责**：接收用户输入的两段文本
- **设计亮点**：左右并排，视觉上形成“对比”的暗示
- 使用`x-model`实现数据双向绑定，输入即保存

### 2. 对比引擎模块（JavaScript函数）
- **职责**：计算文本差异并标记
- **处理流程**：
  1. 接收`text1`和`text2`
  2. 调用`diff_match_patch`库进行差异分析
  3. 将差异分类：新增(+1)、删除(-1)、相同(0)
  4. 统计数量并生成带样式的HTML

### 3. 结果展示模块
- **职责**：直观展示差异结果
- **设计亮点**：
  - 使用不同的背景色和装饰线区分增删
  - 顶部有统计数据和图例
  - 保持原文的换行和空格格式

**最值得学习的设计**：
- **状态切换模式**：`resultMode`变量控制显示输入界面还是结果界面
- **纯前端处理**：所有计算在浏览器完成，无需服务器
- **渐进式交互**：从输入→对比→查看结果→返回编辑，流程完整

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：这个工具**没有使用AI或Prompt**，它使用的是传统的文本对比算法。但我们可以从这个角度思考：

**如果这是一个AI工具，Prompt会扮演什么角色？**
- 可能会让AI“理解”对比的意图：“请找出两段文本的差异，并解释修改意图”
- 或者让AI“生成”修改建议：“基于这些差异，生成优化建议”

**当前工具的逻辑**：
- 解决的是“**精确比对**”问题，不是“理解”问题
- 算法关注字符级别的差异，不考虑语义
- 关键变量是`text1`和`text2`两个字符串

**学习点**：不是所有工具都需要AI。对于确定性的、规则明确的任务，传统算法往往更可靠、更快。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径**：

**第一步：保持骨架，换内容**
- 复制整个HTML结构
- 修改标题和描述，比如改成“代码差异对比”
- 保持两个文本框和对比按钮不变

**第二步：调整对比逻辑**
- 如果你对比的是代码，可以修改样式：
  ```css
  /* 代码专用样式 */
  .diff-ins { background: #e6ffed; }  /* GitHub新增样式 */
  .diff-del { background: #ffeef0; }  /* GitHub删除样式 */
  ```
- 可以添加行号显示

**第三步：改变展示方式**
- 从“并排显示”改为“上下滚动对比”
- 或者添加“只显示差异”的筛选按钮
- 增加导出功能（复制结果或下载）

**从哪里下手最安全？**
从**CSS样式**开始修改最安全。改变颜色、间距、字体，不会影响核心功能。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加文件上传功能
- **操作**：在文本框上方添加“上传文件”按钮
- **效果**：用户可以直接上传.txt文件，内容自动填入文本框
- **技术**：使用`<input type="file">`和`FileReader` API

### 2. 添加“忽略空格/大小写”选项
- **操作**：在对比按钮旁添加复选框
- **效果**：对比时忽略空格差异或大小写差异
- **技术**：在调用`diff_main`前预处理文本
  ```javascript
  if (ignoreSpace) {
    text1 = text1.replace(/\s+/g, ' ');
    text2 = text2.replace(/\s+/g, ' ');
  }
  ```

### 3. 改为实时对比模式
- **操作**：去掉“开始对比”按钮
- **效果**：用户在任意文本框输入时，右侧实时显示差异
- **技术**：使用`@input`事件监听，但需要防抖处理

### 4. 支持更多文件格式
- **操作**：添加“对比Markdown”、“对比JSON”等模式
- **效果**：不同模式下使用不同的对比策略
- **技术**：JSON可以先解析再对比结构

### 5. 添加分享功能
- **操作**：在结果页面添加“生成分享链接”
- **效果**：生成一个URL，打开后直接显示对比结果
- **技术**：使用URL的hash或query参数存储文本

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不适合长文档**：超过1万字符可能会卡顿
2. **不保留格式**：只处理纯文本，会丢失粗体、颜色等格式
3. **没有版本管理**：只是单次对比，不能保存历史
4. **语义理解有限**：把“很棒”改成“非常好”会被标记为完全替换，不会识别为同义替换

### 如果用户想做这些，应该换什么工具：

**想对比Word/PDF文档**：
- 使用专业的文档对比工具：Beyond Compare、WinMerge
- 或在线服务：draftable.com、diffnow.com

**想对比代码并合并修改**：
- 使用Git及相关工具（GitHub、GitLab的对比功能）
- 专用代码对比工具：Meld、Kdiff3

**想理解“为什么这样改”**：
- 需要AI工具：让ChatGPT分析修改意图
- 或人工协作工具：Google Docs的评论和修订功能

**想批量对比多个文件**：
- 使用命令行工具：`diff`命令（Linux/Mac）
- 或集成开发环境（IDE）的对比功能

---

**最后提醒**：这个工具的核心价值在于**简单直接**。当你需要快速查看两段文字哪里不同时，它是最佳选择。学习它的设计，你可以创造出各种“对比型”工具：图片对比、音频波形对比、数据表格对比等。关键是理解“输入A vs 输入B → 可视化差异”这个通用模式。
