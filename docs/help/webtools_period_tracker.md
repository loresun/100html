# 生理期追踪工具学习指南

## 【一】这个网页解决了什么问题？

**使用场景**：当你需要简单、私密地记录月经周期，并想了解自己的生理规律时，这个工具特别有用。比如：
- 你想预测下次月经大概什么时候来，好安排旅行或重要活动
- 你想了解自己的排卵期和易孕期，用于备孕或避孕参考
- 你想看看自己的月经周期是否规律，平均是多少天

**适合情况**：
- 个人日常记录，数据保存在自己的浏览器里
- 只需要基础预测（基于平均周期）
- 想要一个干净、直观的日历视图

**不适合情况**：
- 需要医学级精准预测（它只是简单计算）
- 多人共享或云端同步（数据只存在本地）
- 记录复杂症状或用药情况

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 月经开始日期（必填）
- 持续天数（默认5天）
- 流量程度（轻/中/重）

**用户通常会做哪几步操作？**
1. 点击右上角“记录”按钮
2. 在弹出的窗口中填写：哪天开始的、持续了几天、流量如何
3. 点击“保存”
4. 回到主页面，你会看到：
   - 日历上对应日期被标记为粉色（月经期）
   - 顶部卡片显示预测的下次月经和排卵期
   - 历史记录区域显示你刚添加的记录

**输出结果长什么样？**
- **预测卡片**：三张信息卡片，显示下次月经、排卵期和平均周期
- **可视化日历**：用不同颜色标记月经期（粉色）、排卵期（浅紫色）、易孕期（淡粉色）
- **历史列表**：按时间倒序显示你所有的记录

**容易忽略的使用细节**：
1. **点击日历日期可以直接记录**：不用每次都点“记录”按钮，直接点击日历上的某一天，会自动填充日期
2. **数据只存在本地**：清空浏览器缓存会丢失所有记录
3. **预测基于简单算法**：排卵期固定为“下次月经前14天”，易孕期为“排卵前后6天”
4. **需要至少2次记录**：平均周期和预测功能需要你记录至少2次月经

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

### 模块1：数据管理（大脑）
- **职责**：存储、计算、预测
- 包含：`records`数组、`addRecord()`、`deleteRecord()`、预测计算逻辑
- **输入**：用户填写的月经记录
- **处理**：计算平均周期 → 预测下次日期 → 标记日历状态
- **输出**：整理好的数据供其他模块显示

### 模块2：日历视图（眼睛）
- **职责**：可视化展示时间线
- 包含：月历网格、日期状态标记、月份切换
- **关键设计**：`calendarDays`计算器
  - 它知道如何“画”出一个月的日历（包括上个月和下个月的“补白”）
  - 为每一天计算状态：是月经期吗？是排卵期吗？是今天吗？

### 模块3：预测面板（仪表盘）
- **职责**：展示关键信息
- 包含：三张信息卡片
- **设计亮点**：数据驱动显示
  - 有数据时显示具体日期和倒计时
  - 没数据时显示“暂无数据”
  - 完全由`predictions`计算属性控制

### 模块4：记录表单（手）
- **职责**：收集用户输入
- 包含：弹窗表单、输入验证、数据保存
- **巧妙之处**：`newRecord`对象作为“草稿”
  - 每次保存后自动重置
  - 点击日历日期时自动填充日期

**最值得学习的设计**：
**“计算属性”模式**（如`predictions`、`calendarDays`）
- 它们不是固定数据，而是“根据其他数据实时计算出来的”
- 当`records`变化时，所有相关显示自动更新
- 这种“声明式”思维是现代Web开发的核心

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：这个网页**没有使用AI或Prompt**，它完全基于规则计算。但我们可以分析它的“逻辑设计”：

**逻辑在这个页面中扮演什么角色？**
它解决的是“**根据历史数据生成预测**”的问题。

**哪些信息是关键变量？**
1. `avgCycle`：平均周期天数（从历史记录算出）
2. `lastPeriod`：最近一次月经开始日期
3. 固定规则：排卵期 = 下次月经前14天

**如果改变逻辑规则，会发生什么？**
比如把“排卵期=下次月经前14天”改成“前13天”：
- 所有预测的排卵期都会提前1天
- 易孕期范围也会相应移动
- 日历上的颜色标记全部变化

**这告诉我们**：即使不用AI，清晰的业务逻辑设计也能做出有用的工具。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径**：

**第一步：保持骨架，换皮肤**
- 复制整个HTML结构
- 只改这些：
  - 标题（如改成“习惯追踪”）
  - 颜色（把粉色系换成蓝色系）
  - 图标（换一套Lucide图标）
- 此时功能完全一样，只是外观不同

**第二步：调整数据模型**
- 修改`newRecord`对象：
  ```javascript
  // 原版
  newRecord: { startDate: '', duration: 5, flow: '中' }
  
  // 改成“喝水记录”
  newRecord: { date: '', cups: 8, goal: 10 }
  ```
- 相应修改表单的输入字段

**第三步：改变计算逻辑**
- 修改`predictions`计算属性：
  - 不再计算月经/排卵
  - 改为计算“本周平均喝水量”、“达成目标天数”等
- 修改日历标记逻辑：
  - `isPeriodDay` → `isGoalDay`（是否达成目标）
  - 用不同颜色表示达成程度

**第四步：定制显示方式**
- 预测卡片显示不同的指标
- 历史记录显示不同的信息
- 图例说明不同的颜色含义

**从哪里下手最安全？**
从**CSS颜色和文字**开始改，这不会破坏功能。确认页面还能工作后，再一步步修改数据结构和逻辑。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加症状记录（简单）
- **怎么做**：在记录表单里加一个“症状”多选框
  ```html
  <select multiple>
    <option>腹痛</option>
    <option>情绪波动</option>
    <option>疲劳</option>
  </select>
  ```
- **效果**：历史记录可以显示伴随症状，帮助发现规律

### 2. 改用更科学的预测算法（中等）
- **怎么做**：引入“周期波动”计算
  - 当前：只用平均周期
  - 改进：记录最近3次周期的标准差，给出“可能范围”
- **效果**：预测从“某一天”变成“某几天内”，更符合实际情况

### 3. 添加数据导出/导入（实用）
- **怎么做**：
  - 导出：`JSON.stringify(this.records)` 生成可下载文件
  - 导入：文件上传 + `JSON.parse()`
- **效果**：换设备或浏览器时数据不丢失

### 4. 做成PWA（渐进式Web应用）（进阶）
- **怎么做**：
  1. 添加`manifest.json`文件
  2. 添加Service Worker缓存
  3. 支持“添加到主屏幕”
- **效果**：像手机App一样使用，可离线工作

### 5. 增加“提醒”功能（交互改进）
- **怎么做**：
  - 在预测卡片旁加“设置提醒”按钮
  - 使用浏览器通知API
  ```javascript
  Notification.requestPermission();
  new Notification('提醒：预计明天月经开始');
  ```
- **效果**：主动提醒，不用每天打开查看

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不是医疗工具**
   - 预测基于简单数学公式
   - 不考虑激素水平、疾病、药物影响
   - **如果用于重要医疗决策，请咨询医生**

2. **数据安全性有限**
   - 本地存储，但同一设备其他人可能看到
   - 没有加密
   - **如果隐私极其重要，需要额外保护**

3. **无法处理不规则周期**
   - 算法假设你周期基本规律
   - 多囊卵巢综合征（PCOS）等状况下预测可能不准

4. **没有社交或专业功能**
   - 不能分享给伴侣或医生
   - 不能生成医疗报告

### 如果用户想做X，应该换什么？
- **想要精准排卵预测** → 使用排卵试纸或专业备孕App
- **需要记录复杂症状** → 使用Clue、Flo等专业应用
- **想要医生参与** → 使用有医疗团队支持的健康平台
- **需要跨设备同步** → 使用有云服务的应用
