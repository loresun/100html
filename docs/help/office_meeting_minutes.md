# 智能会议纪要助手 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你刚开完一个冗长的线上会议，手头有一份由语音转文字工具生成的、充满口语、重复和逻辑跳跃的原始记录。或者，你从讨论群里复制了一大段杂乱的聊天记录。你需要快速整理出一份结构清晰、重点突出、可以直接分享或存档的正式会议纪要。这个工具就是为你准备的。

**适合情况：**
- **会后整理：** 将录音稿或速记整理成正式文档。
- **信息提炼：** 从冗长的讨论中快速提取关键决策和待办事项。
- **格式统一：** 为不同风格、不同语言的原始记录，输出统一、专业的纪要格式。

**不适合情况：**
- **实时记录：** 它不是一个在会议进行时同步记录的笔记工具。
- **高度保密内容：** 内容会发送到外部AI API进行处理，不适合处理敏感或机密信息。
- **精确的法律或财务记录：** AI可能遗漏或误解细节，此类重要文档仍需人工复核。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
一个大的文本框，用于粘贴任何未经整理的会议原始文本。例如：语音转文字稿、你的速记笔记、微信群聊记录等。

**用户通常会做哪几步操作？**
1.  **粘贴内容：** 将你的原始文本复制粘贴到左侧的“原始记录”区域。可以点击“粘贴”按钮，或直接按 `Ctrl+V`。
2.  **调整选项（可选）：** 在文本框下方，选择你想要的“纪要风格”（如标准商务、行动导向）和“源语言处理”方式（如自动识别、修复病句）。
3.  **一键生成：** 点击中央醒目的“✨ 一键生成会议纪要”按钮。
4.  **查看与导出：** 在右侧“整理结果”区域查看AI生成的、格式漂亮的纪要。你可以“复制全文”或“导出MD”文件。

**输出结果长什么样？**
输出是一份结构清晰的Markdown文档，通常包含：
- **会议主题、时间、参会人**
- **会议摘要**
- **详细讨论内容**
- **关键决策**（用蓝色框突出显示）
- **待办事项**（用绿色框突出显示，明确责任人和时间）

**有哪些容易忽略的使用细节？**
- **首次使用需配置API Key：** 第一次点击生成按钮时，会弹出设置窗口，你需要填入自己的DeepSeek API Key。这是调用AI能力的“钥匙”。
- **模型选择：** 在导航栏右侧可以选择“DeepSeek V3 (快速)”或“DeepSeek R1 (深度分析)”。R1模型会显示AI的“思考过程”，分析更深入，但速度可能稍慢。
- **思考过程：** 如果使用R1模型，结果区顶部会显示AI的推理链，这有助于你理解AI是如何整理信息的，也是一个很有趣的学习点。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

**1. 输入与配置模块（左侧面板）**
- **职责：** 接收用户最原始的、未经处理的数据，并让用户设定“如何加工”的偏好。
- **包含：**
    - **原始记录文本框：** 承载核心输入。
    - **功能按钮（清空/粘贴）：** 管理输入内容。
    - **配置选项（风格/语言）：** 将用户偏好转化为后续AI指令的参数。
- **逻辑：** `用户输入文本 + 用户选择配置` → 打包成待处理数据。

**2. AI处理与通信模块（不可见，但最关键）**
- **职责：** 作为“大脑”，将左侧的原始数据，按照规则，加工成右侧的成品。
- **包含：** `generateMinutes` 函数中的逻辑，特别是构建 **System Prompt（系统指令）** 和调用 **DeepSeek API** 的部分。
- **逻辑链路：**
    `原始文本 + 风格/语言选项` → **在代码中被组装成一段详细的System Prompt** → 通过HTTP请求发送给DeepSeek API → 接收AI返回的流式数据 → 分离出“思考内容”和“最终结果”。
- **最值得学习的设计：**
    - **Prompt工程：** 如何将用户在前端的简单选择（如下拉菜单），翻译成给AI的、精确且结构化的指令（`getStylePrompt` 和 `getLanguagePrompt` 函数）。这是前端交互与AI能力之间的“翻译器”。
    - **流式响应处理：** 代码不是等待AI全部生成完再显示，而是一边接收一边显示（`stream: true`），用户体验更流畅。同时，它还能巧妙地区分并分别展示“推理过程”和“最终答案”。

**3. 输出与展示模块（右侧面板）**
- **职责：** 优雅地呈现AI的处理结果，并提供导出工具。
- **包含：**
    - **结果展示区：** 将AI返回的Markdown文本实时渲染成美观的HTML（使用 `marked` 库）。
    - **特殊样式渲染：** 通过CSS，将AI生成的特定内容（如 `<div class="todo-item">`）渲染成带有颜色边框的醒目区块。
    - **工具按钮（复制/导出）：** 提供结果的使用闭环。
- **逻辑：** `AI返回的Markdown文本` → `marked.parse` 渲染为HTML → 应用自定义CSS样式 → 呈现给用户。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt扮演的角色：**
在这个页面中，Prompt（特别是System Prompt）扮演着 **“产品经理兼资深秘书”** 的角色。它不直接生成会议纪要，而是**定义生成规则**。它告诉AI：“请你以这样的身份（资深秘书），按照这样的标准（风格、语言、必须提取的要素），来处理用户给你的这份原始材料。”

**它解决的是“理解问题”还是“生成问题”？**
主要解决 **“理解问题”** 。它旨在让AI充分理解“一份好的、符合特定要求的会议纪要”应该是什么样子，从而引导AI的生成方向，确保输出结果的结构和质量符合预期。

**Prompt中的关键变量：**
1.  **角色设定：** `“你是一个拥有20年经验的高级行政秘书”` – 赋予AI特定的专业身份。
2.  **风格指令 (`${getStylePrompt(...)}`)：** 根据用户选择，动态插入对纪要结构、详略、语气的具体要求。
3.  **语言指令 (`${getLanguagePrompt(...)}`)：** 控制输出语言是保持原样、优化还是翻译。
4.  **强制提取项：** 明确要求必须提取“关键决策”和“待办事项”，甚至给出了前端的渲染格式提示（`<div class="todo-item">`）。这是连接AI生成内容与前端展示样式的关键桥梁。
5.  **格式要求：** `“使用 Markdown。标题层级清晰。”` – 确保输出能被后续代码正确渲染。

**如果只改Prompt，不改代码，会发生什么变化？**
变化会非常直接和巨大：
- **改变角色：** 如改成“敏捷教练”，输出会立刻偏向站会格式，更关注进度和阻碍。
- **改变提取项：** 如增加“遗留问题”或“风险点”，AI就会在纪要中新增这些板块。
- **改变格式指令：** 如要求输出表格，AI就会尝试以表格形式列出待办事项。
- **改变语气：** 如要求“语气轻松活泼”，整个纪要的文风都会改变。
**这证明了Prompt是控制AI行为的“高效杠杆”**，微调Prompt就能重塑产品功能。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步打造自己的AI工具：

**第一步：替换场景，保持骨架**
- **目标：** 做一个“读书笔记整理助手”。
- **操作：** 复制整个HTML结构。将标题“智能会议纪要助手”改为“智能读书笔记助手”。将左侧输入框的提示语从“粘贴会议记录”改为“粘贴书籍摘录、随想或杂乱笔记”。将右侧标题改为“整理后的读书笔记”。此时，界面变了，但功能逻辑（输入-处理-输出）完全没变。

**第二步：改造Prompt，重塑核心**
- **目标：** 让AI能整理读书笔记，而不是会议纪要。
- **操作：** 修改 `generateMinutes` 函数中的 `systemPrompt`。将角色从“行政秘书”改为“资深图书编辑”或“知识管理专家”。将处理要求从提取“决策、待办”改为提取“核心观点、金句摘抄、个人感悟、行动启发”。这是最核心的一步，决定了工具的本质。

**第三步：调整输入与输出配置**
- **目标：** 让配置选项更贴合新场景。
- **操作：** 将“纪要风格”下拉选项改为“笔记风格”，如“思维导图式”、“摘要式”、“批判性评论式”。将“源语言处理”改为“文本优化”，如“精简概括”、“扩写详解”、“转写为口语稿”。同时，调整输出区的CSS，为“金句”或“观点”设计新的高亮样式。

**从哪里下手最安全？**
**从第二步（改Prompt）下手最安全、见效最快。** 因为你不必立即修改页面布局或复杂逻辑，只需用文本编辑器修改 `systemPrompt` 字符串，就能立刻改变AI的行为，看到全新的输出效果。这能给你带来最直接的正反馈。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，提供更多上下文：**
    - **操作：** 在输入区增加几个文本框或下拉菜单，例如“会议主题（可选）”、“主要参会人（可选）”、“会议日期”。将这些信息也作为变量插入到System Prompt中，例如：“本次会议的主题是关于${userTopic}，主要参会者有${attendees}...”。这能帮助AI更准确地理解和组织内容。

2.  **切换或扩展AI模型后端：**
    - **操作：** 修改 `fetch` 请求的URL和请求头。例如，将DeepSeek API换成OpenAI的GPT-4o、Claude或国内的通义千问、文心一言等。只需根据对应平台的API文档，调整 `headers` 和 `body` 的结构即可。你甚至可以做一个模型选择器，让用户自由切换。

3.  **将单页应用拆分为引导式多步流程：**
    - **操作：** 将现有页面拆解。第一步页面只负责上传文本或文件。第二步页面展示AI初步提取的关键信息（如自动识别的参会人、时间）让用户确认或修改。第三步页面才是生成和调整最终纪要。这能提升复杂场景下的准确性和用户体验。

4.  **优化交互体验，增加中间编辑环节：**
    - **操作：** 不要让输出结果只是“只读”的。可以将其变为一个可编辑的富文本区域。让用户在AI生成的基础上，进行微调、增删。甚至可以增加一个“重新生成某段落”的按钮，针对用户选中的内容，调用AI进行局部优化。

5.  **增加历史记录和模板功能：**
    - **操作：** 利用浏览器的 `localStorage` 或连接后端数据库，保存用户生成过的纪要。提供一个历史列表页面。同时，允许用户将某次满意的输出保存为“模板”，下次可以直接应用该模板的风格和设置来生成新的纪要，实现个性化定制。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合做精确的逐字稿：** 它的设计目标是“整理、提炼、结构化”，而不是“一字不差地转写”。它会主动删除它认为的“废话”，因此**不适合需要完整对话记录的法律取证、学术访谈分析等场景**。这类场景应使用专业的转录工具并进行人工校对。

- **不适合处理高度专业化或歧义性强的讨论：** 例如，一场充满专业术语、代号和隐含前提的技术架构讨论，或者一场哲学辩论。AI可能无法准确理解深层语境和微妙分歧，导致提炼的关键决策偏离原意。**对于重要决策，AI纪要只能作为初稿，必须由参会者复核。**

- **不适合作为全自动的工作流枢纽：** 虽然它能导出Markdown，但它没有与Notion、飞书、Confluence等协作工具的直接集成能力。**如果你需要将纪要自动创建为团队Wiki页面或任务卡，应该寻找专门的集成工具或自行开发后端对接服务。**

- **不适合无网络环境或对延迟要求极高的场景：** 它完全依赖云端AI API，断网则无法工作。生成速度受模型、网络和文本长度影响。**对于需要离线、瞬时响应的记录场景，应选择本地运行的软件。**

---
**总结：** 这个网页是一个优秀的“前端界面 + AI Prompt工程”的范本。它展示了如何用一个简洁的界面封装复杂的AI指令，解决一个明确的痛点。通过学习它，你掌握的不是一个具体的会议工具，而是**构建一类AI驱动型工具的方法论**：定义场景、设计Prompt、构建交互、处理流式响应。现在，你可以尝试用它整理你的下一次会议记录，然后开始构思属于你自己的那个“助手”了。
