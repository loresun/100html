# 🔄 Turndown HTML转Markdown 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你从网上复制了一篇排版精美的文章，想把它保存到你的笔记软件（如Obsidian、Notion）中，但这些软件通常使用Markdown格式。手动将HTML标签一个个改成Markdown符号（如把`<h1>`改成`#`，把`<strong>`改成`**`）非常繁琐且容易出错。

这个网页就是你的**格式转换助手**。它专门解决“如何将网页内容（HTML格式）快速、准确地转换成更简洁、更通用的Markdown格式”这个问题。

**适合使用的情况：**
- 你从博客、新闻网站复制了内容，想转为Markdown做笔记。
- 你需要将富文本编辑器（如WordPress后台）生成的内容导出为Markdown。
- 你收到一封HTML格式的邮件，想提取核心文字并以Markdown保存。
- 你有一批旧的HTML文档，需要批量迁移到支持Markdown的新系统。

**不适合使用的情况：**
- 你需要转换的“网页”是复杂的单页应用（如包含大量JavaScript动态生成的内容），本工具可能无法正确处理。
- 你需要完美保留原始HTML的所有样式（如精确的字体、颜色、布局），Markdown的标记能力有限。
- 你需要转换图片、视频等媒体文件，本工具主要处理文本和基础结构。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 核心输入是一个**文本框**，里面默认有一段示例HTML代码。你可以完全清空它，粘贴你自己的HTML代码。

**用户通常会做哪几步操作？**
1.  **准备HTML**：从目标网页按`Ctrl+A`全选，`Ctrl+C`复制，然后回到这个页面，在左侧“HTML输入”框内`Ctrl+V`粘贴。
2.  **即时查看结果**：粘贴后，右侧的“Markdown输出”区域会**立刻**显示出转换后的Markdown文本。你无需点击任何“转换”按钮。
3.  **（可选）调整格式**：如果对转换后的样式不满意（比如希望标题用`===`下划线而不是`#`），可以在“转换配置”区域调整下拉选项。
4.  **（可选）使用快捷示例**：如果不确定自己的HTML是否标准，可以点击“快速转换示例”中的按钮（如“表格”、“代码块”），看看典型HTML是如何被转换的。
5.  **复制结果**：对输出满意后，点击输出框上方的“📋 复制”按钮，即可将Markdown文本复制到剪贴板，然后粘贴到任何地方。

**输出结果长什么样？**
输出是一段**纯文本**，但使用了不同的颜色高亮（如青色），使其更易读。它会将：
- `<h1>` 转换为 `# 标题`
- `<strong>` 转换为 `**加粗**`
- `<ul><li>` 转换为 `- 列表项`
- `<pre><code>` 转换为 ````代码块``` 
- 等等。

**有哪些容易忽略的使用细节？**
- **实时转换**：只要你在左侧输入框里打字或删除，右侧就会立刻更新。这是最方便的特性。
- **配置是全局的**：你更改任何一个配置选项（如“粗体分隔符”），**所有**已转换和未来转换的内容都会立即应用新规则。
- **示例的价值**：“加载示例”按钮和“快速转换示例”不仅是演示，更是你**学习和测试**的工具。点击它们，观察输入和输出的变化，你就能快速理解各种HTML标签对应的Markdown是什么。
- **错误提示**：如果你粘贴了格式非常混乱或错误的HTML，右侧可能会显示“转换错误”。这时，可以尝试点击“加载示例”获得一个干净、正确的HTML模板，再逐步修改。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个功能模块，像一个流水线车间：

1.  **输入与输出展示模块（车间两头）**
    - **职责**：`<textarea>` 是**原料入口**，用户在这里投入HTML“原料”。`<pre>` 是**成品出口**，实时展示产出的Markdown“成品”。它们构成了最直观的交互界面。
    - **设计亮点**：采用左右并排的布局，让用户能**即时对照**输入和输出，学习效果最好。

2.  **转换引擎模块（核心车间）**
    - **职责**：这是页面的“大脑”，但你看不见它。它由引入的 `TurndownService` 这个外部库担任。它的工作就是按照一套规则，把HTML标签“翻译”成Markdown符号。
    - **逻辑链路**：`用户输入HTML` → `TurndownService 按规则翻译` → `输出Markdown文本`。这个“翻译规则”就是下面要说的配置。

3.  **规则配置模块（车间控制台）**
    - **职责**：四个下拉菜单（标题样式、代码块风格等）就是**控制台**。它们不直接处理数据，而是告诉“转换引擎”（TurndownService）：“请按照我选择的这套规则来翻译”。
    - **关键设计**：每次更改配置，页面都会**重新创建一个新的TurndownService实例**并立即重新转换。这保证了配置更改能立刻生效，逻辑非常清晰。

4.  **示例与场景模块（使用说明书）**
    - **职责**：“快速转换示例”按钮是**预置的原料样本**，让你一键测试特定功能。“典型应用场景”卡片是**产品说明书**，告诉你这个工具能在哪些地方派上用场。它们共同降低了学习成本。

**最值得学习的设计：**
**“配置与执行分离”**。页面把“定义规则”（配置下拉菜单）和“执行转换”（`convert()`函数）完全分开了。`updateConfig()`函数只负责根据用户选择，组装一个新的规则配置对象，然后**调用**`convert()`。这种设计让代码结构清晰，易于维护和扩展。如果你想增加一个新的配置项，只需要在页面上加一个输入控件，并在`updateConfig()`里添加对应的配置属性即可。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **请注意**：当前这个网页版本**没有使用AI或Prompt**。它完全依赖一个确定性的规则库（Turndown）进行格式转换。这是一个非常重要的认知。

为了让你理解“如果这个工具用AI来实现会怎样”，我们可以做一个思想实验：

- **Prompt可能扮演的角色**：如果使用AI（如GPT），Prompt（提示词）会扮演“翻译官”的角色。它的任务可能是：“你是一个专业的格式转换专家。请将用户提供的HTML代码精确地转换为标准的Markdown格式。注意保留所有文本内容、链接和代码结构，但去除所有HTML标签和样式属性。”
- **解决什么问题**：AI主要解决的是“**理解与灵活生成**”问题。确定性规则库（如Turndown）可能无法处理一些不标准、怪异或新的HTML写法。而AI通过理解语义，有可能更鲁棒地处理这些情况，甚至能根据上下文优化输出。
- **关键变量**：在Prompt中，**用户输入的完整HTML代码**就是最核心的变量。此外，还可以将“配置选项”（如“请使用ATX风格标题”）也作为变量插入Prompt。
- **只改Prompt的影响**：如果只改Prompt而不改代码，AI的“工作方式”和“输出风格”会彻底改变。例如，Prompt从“精确转换”改为“用更口语化的总结风格转换”，那么输出可能从精确的Markdown变成一段包含Markdown的摘要。这显示了Prompt对AI应用结果的**决定性影响**。

当前这个工具选择使用规则库而非AI，是因为**格式转换是一个规则明确、需要高保真度和确定性的任务**，规则库更快、更准、更便宜。这是技术选型的一个经典案例。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“换壳-换芯-美化”的路径，安全地创建一个新工具：

**第一步：替换核心场景与库（保持骨架，更换器官）**
这是最安全、改动最小的起点。
1.  找一个你想转换的格式对。例如：**JSON → YAML**、**CSV → Markdown表格**、**简体中文 → 繁体中文**。
2.  在代码中，找到引入 `Turndown` 库的那一行（`<script src="...turndown.js">`），替换成能实现你目标功能的库（例如，用 `js-yaml` 库做JSON转YAML）。
3.  把页面标题、描述、按钮文字中所有“HTML”和“Markdown”换成你的新格式名（如“JSON”和“YAML”）。

**第二步：调整输入输出与配置（改造控制台）**
1.  **输入/输出**：左侧文本框的默认示例内容，换成你的新格式的示例。右侧输出框的样式可以保留。
2.  **配置选项**：将“转换配置”里的下拉菜单，替换为你的新工具所需的配置。例如，JSON转YAML工具可能需要“缩进空格数”、“是否排序键名”等选项。你需要修改`updateConfig()`函数，让它根据新选项来初始化你的新转换库。

**第三步：更新示例与逻辑（重写说明书）**
1.  修改 `loadSample()` 函数和 `samples` 对象里的示例数据，使其符合你的新场景。
2.  彻底重写“典型应用场景”部分，描述你的新工具能用在什么地方（例如，“将API返回的JSON配置转为更易读的YAML文件”）。
3.  检查并重命名所有函数和变量名，使其含义更清晰（例如，`convert()`可以改为`transformJsonToYaml()`）。

**从哪里下手最安全？**
从**第一步**开始最安全。先不要动任何JavaScript逻辑，只更换外部库和页面上的文字。这样你能确保页面基础布局和交互是正常的，然后再逐步深入修改核心功能。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合做“网页抓取”**：这个工具**不能**自动从某个网址抓取HTML。它只处理你手动复制粘贴或上传的HTML代码。如果你需要从网址直接转换，你需要的是一个**爬虫工具**，它先获取网页HTML，再交给本工具处理。
- **不适合做“富文本编辑器”**：它只有转换功能，没有编辑功能。你不能在输出框里直接修改Markdown并期望HTML输入框同步更新（这是反向转换）。如果你需要双向编辑，应该寻找或构建一个**所见即所得（WYSIWYG）的Markdown编辑器**。
- **不适合处理“高度样式化或布局复杂”的内容**：对于依赖`<div>`和CSS网格、Flexbox实现的复杂页面布局，转换成的Markdown会丢失所有布局信息，变得杂乱无章。它最适合转换以**文本和简单结构（标题、列表、段落）** 为主的文章类内容。
- **不适合保证100%的往返无损转换**：将A格式转为B格式，再转回A格式，很难保证和原来一模一样。如果你需要保留原始HTML的绝对完整性，你应该直接保存HTML文件，而不是依赖格式转换工具。

记住这个工具的本质：它是一个**专注于特定格式转换的、高效的“翻译器”**，而不是一个万能的“网页处理器”。理解它的边界，你就能在正确的场景下最大化地利用它，也能更清晰地知道何时需要寻找或创造其他工具。
