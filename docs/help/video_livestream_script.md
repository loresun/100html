# 直播/口播逐字稿专家 - 帮助文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一个内容创作者，需要准备一段口播内容。可能是：
- **短视频博主**：想拍一个60秒的爆款视频，但不知道开场怎么吸引人，中间怎么讲才不枯燥。
- **直播带货主播**：晚上有一场2小时的直播，需要一套完整的话术流程，从欢迎观众到最终逼单。
- **企业市场人员**：有一份生硬的产品说明书，需要把它变成主播能自然讲出来的“人话”。

这个网页就是你的 **“口播内容智能助理”**。它帮你把零散的想法、产品信息或书面文案，快速转化成结构清晰、适合朗读、甚至带有专业节奏标记的逐字稿。

**它适合在什么情况下使用？**
- **内容创作初期**：当你只有主题和核心信息，需要快速生成一个可用的脚本草稿。
- **效率提升**：不想从零开始写稿，希望AI提供专业结构和话术灵感。
- **风格转换**：需要将书面、官方的文字转换成亲切、口语化的表达。

**它不适合什么情况？**
- **完全替代人类创作**：它生成的是“草稿”和“框架”，最终的情感、个人风格和临场发挥仍需你来打磨。
- **高度专业或法律文书**：对于需要绝对精确、涉及法律条款的文稿，不应依赖AI生成。
- **实时提词**：它生成的是静态文本，不具备根据现场观众反应实时调整话术的能力。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **选择模式**：在左侧面板顶部，选择你的内容类型（短视频口播、直播带货、口语化转换）。
2.  **填写主题**：在“主题/产品”输入框，用一句话概括你要讲什么（例如：“夏日防晒霜选购指南”）。
3.  **提供详细信息**：在下方的大文本框中，输入更具体的内容。比如产品卖点、你想表达的核心观点、或者需要转换的原始书面文案。

**用户通常会做哪几步操作？**
1.  **选择场景**：根据你的需求，点击三个模式中的一个（如“直播带货”）。
2.  **细化设置**：选择模式后，下方会出现专属选项（如直播时长、类型）。
3.  **输入核心信息**：在“主题”和“详细信息”框中，尽可能清晰地描述你的需求。
4.  **一键生成**：点击橙色的“生成逐字稿”按钮。
5.  **查看与导出**：在右侧结果区域查看AI生成的稿子，可以“复制全文”或“导出TXT”文件。

**输出结果长什么样？**
输出结果是一个结构清晰的Markdown文档，通常包含：
- **分阶段大纲**：例如直播脚本的“聚人、留人、锁客、逼单”阶段。
- **带标记的逐字稿**：文中会包含 `【停顿】`、`**重读**`、`(语气词)` 等朗读提示。
- **实用建议**：如“黄金3秒开头”话术、拍摄建议、违禁词提醒等。
- **（如果使用Reasoner模型）深度思考过程**：一个可折叠的区域，展示AI是如何一步步构思出这个稿子的。

**有哪些容易忽略的使用细节？**
1.  **“详细信息”框是关键**：你填得越具体、越丰富，AI生成的内容就越贴切。不要只写一个标题。
2.  **模式专属设置**：别忘了选择“视频时长”、“直播类型”或“口语风格”，这会让结果更精准。
3.  **提示词可自定义**：点击顶部导航栏的“提示词”按钮，你可以修改每个模式下的AI“创作指令”，让它更符合你的口味。
4.  **先配置API**：第一次使用时，需要点击“API”按钮，填入你的DeepSeek API Key（需要自行申请）。
5.  **模型选择**：“Chat”模型响应快，“Reasoner (R1)”模型会展示思考过程，可能更严谨但稍慢。

## 【三】核心结构拆解（学习重点）

这个页面采用了清晰的 **“配置-生成-展示”** 模块化设计。

**关键模块与职责：**
1.  **控制面板（左侧）**：
    - **模式选择器**：定义任务类型，切换不同的输入表单和AI指令。
    - **动态输入表单**：根据所选模式，显示不同的输入字段（主题、详情、时长、风格等）。职责是收集用户的所有需求参数。
    - **生成触发器**：将收集到的所有参数打包，触发AI生成流程。

2.  **展示面板（右侧）**：
    - **空状态引导**：在无内容时，用图标和文字引导用户操作。
    - **结果渲染器**：核心是接收AI返回的Markdown文本，并将其渲染成美观易读的HTML。它还能高亮显示特定的标记（如停顿、语气词）。
    - **辅助功能区**：提供结果导出（TXT）、复制和模型思考过程查看功能。

3.  **配置层（顶部导航/弹窗）**：
    - **模型切换**：在底层切换不同的AI模型（Chat/Reasoner）。
    - **提示词管理**：允许高级用户修改驱动AI创作的“系统提示词”。
    - **API配置**：管理连接AI服务的密钥。

**输入 → 处理 → 输出 的逻辑链路：**
1.  **输入**：用户在左侧面板选择模式并填写信息。
2.  **组装**：点击生成后，前端代码做两件事：
    - 根据当前模式ID，取出对应的 **系统提示词**（一个详细的创作指令模板）。
    - 将用户填写的信息，组装成 **用户提示词**。
3.  **处理**：将“系统提示词”和“用户提示词”一起发送给DeepSeek API。
4.  **输出**：接收AI返回的流式文本，实时显示在右侧面板，并用Markdown解析器进行美化渲染。

**最值得学习的设计：**
**“模式”作为核心抽象** 是这个网页的精华。它不仅仅是一个标签，而是一套组合：
- 一套**专属的输入UI**（如表单字段）。
- 一份**定制的系统提示词**（创作指令）。
- 一种**预期的输出结构**。
这种设计将复杂的AI应用“场景化”，极大降低了用户的使用门槛，是构建实用AI工具的优秀范式。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt（提示词）在这里扮演 **“专业导演”** 的角色。系统提示词（如 `DEFAULT_PROMPTS` 里的内容）不是简单地让AI“写段话”，而是详细规定了：
- **身份**：你是什么专家？（如“金牌直播带货脚本撰写专家”）
- **核心方法论**：你要遵循什么流程？（如“聚人→留人→锁客→逼单”）
- **输出格式**：必须包含哪些部分？（如“黄金3秒开头”、“完整逐字稿”、“时间轴”）
- **写作原则**：要用什么语气、避免什么？（如“每句话不超过15个字”、“多用‘你’”）

**它解决的是“理解问题”还是“生成问题”？**
主要解决 **“生成问题”**，但也部分解决了“理解问题”。系统提示词的核心作用是 **约束和引导AI的生成过程**，确保它产出的内容符合特定场景的格式、风格和质量要求，而不仅仅是理解用户输入的主题是什么。

**哪些信息是 Prompt 中的关键变量？**
在系统提示词中，用 `##`、`###` 等标题和结构化列表定义的 **输出格式** 和 **写作原则** 是关键。在用户提示词中，关键变量是用户填写的 `【主题】`、`【视频时长】`、`【内容要求】` 等具体信息，它们被直接拼接到预设的指令模板中。

**如果只改 Prompt，不改代码，会发生什么变化？**
变化会非常直接和巨大：
- **改变身份指令**（如把“短视频专家”改成“科普播客主持人”），AI生成内容的整体视角和知识调性会变。
- **改变格式指令**（如要求输出“分镜脚本”而不是“逐字稿”），最终结果的排版和内容组织会完全不同。
- **改变风格指令**（如把“语气亲切”改成“语气激昂”），稿子的用词和情感色彩会随之改变。
这意味着，**这个网页的核心功能很大程度上是由Prompt定义的**，前端代码主要提供了一个修改和调用这些Prompt的友好界面。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的AI工具：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标**：做一个“周报生成器”或“邮件撰写助手”。
- **操作**：直接复制这个网页的HTML/JS代码。然后修改 `scriptModes` 数组，把你的场景加进去。例如，将“短视频口播”换成“工作周报”，将“直播带货”换成“客户邮件”。
- **此时**：UI和交互逻辑完全一样，只是文字变了。

**第二步：调整输入字段或 Prompt**
- **目标**：让工具更贴合你的新场景。
- **操作**：
    1.  在左侧面板，为你新增的“模式”设计需要的输入字段（如“本周重点工作”、“下周计划”、“需要支持”）。
    2.  在 `DEFAULT_PROMPTS` 对象中，为你的新模式编写一个专属的系统提示词，告诉AI如何根据这些字段生成周报。
- **此时**：你的工具已经能根据新输入，生成符合新场景的内容了。

**第三步：改变输出形式或展示方式**
- **目标**：让结果展示更专业。
- **操作**：修改右侧结果区域的渲染逻辑。例如，对于周报，你可能不想用Markdown渲染，而是想生成一个类似表格的视图，或者直接模仿公司周报模板的样式。你可以调整 `renderMarkdown` 函数或相关的CSS样式。
- **此时**：你的工具从内到外都变成了一个全新的应用。

**从哪里下手最安全？**
从 **修改 `DEFAULT_PROMPTS` 对象** 和 **`scriptModes` 数组** 开始。这是整个应用的“大脑”和“菜单”，改动它们能立刻看到效果，且几乎不会导致页面崩溃。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“角色设定”输入**：
    - **操作**：在左侧面板为每个模式增加一个“主播人设”下拉框，选项如“严谨专家”、“热情闺蜜”、“幽默大叔”。
    - **效果**：将用户选择的“人设”变量插入到系统提示词中，让AI生成的话术更贴合特定人设。

2.  **接入多模型API**：
    - **操作**：在API配置弹窗和模型切换处，增加对OpenAI GPT、Claude或国内大模型（如通义千问、智谱）的支持。
    - **效果**：用户可以根据内容类型、成本或效果偏好选择不同的AI模型，提升工具的灵活性。

3.  **拆解为“草稿-润色”多步流程**：
    - **操作**：将生成按钮改为“生成草稿”，生成后，在结果区域下方增加一个“AI润色”按钮，点击后可以针对草稿进行“更幽默”、“更简短”、“更正式”等方向的二次优化。
    - **效果**：将内容创作过程流程化，给予用户更多控制权。

4.  **优化交互体验**：
    - **操作**：增加“历史记录”功能，将每次生成的结果（连同输入参数）保存在本地，用户可以回顾、复用或对比不同版本的稿子。
    - **效果**：让工具从一个单次生成工具，变成一个可积累、可迭代的创作工作台。

5.  **增加音频预览功能**：
    - **操作**：集成一个文本转语音（TTS）API（如Azure Speech或阿里云语音合成）。生成逐字稿后，增加一个“试听”按钮，用AI语音朗读出来。
    - **效果**：让用户能直观感受稿子的朗读节奏和效果，这是文字无法替代的体验。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合生成完全原创的深度内容**：它的本质是“信息重组与格式转换”。如果输入信息空洞，输出也会缺乏真正的洞见。它无法替代你对行业的深刻理解。
- **不适合处理实时、动态信息**：它无法接入实时数据（如当前库存、实时评论），因此生成的直播话术中的“限量100件”只是一个模板，需要你手动更新为真实数据。
- **不适合作为最终交付物**：生成的稿子必须经过人工审核和修改。AI可能遗漏重要信息、使用不恰当的案例，或生成不符合你个人语言习惯的表达。它是最好的“第一稿助手”，但不是“终稿作者”。
- **如果想做实时互动提词器**：这个网页是静态的。如果你需要的是一个能跟随主播语速滚动、并能根据现场情况快速切换话术片的**提词器应用**，你需要完全不同的技术方案（如Web Speech API监听、话术片段数据库等）。
