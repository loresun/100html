# 一句话愿望 + 未来签 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你有一个心愿、目标或期许（比如“希望今年更稳定自在”、“想找到理想工作”），但不知道如何用优美、有仪式感的方式表达和记录时，这个网页可以帮你。它就像一个**数字时代的“许愿签”**，将你朴素的愿望，通过 AI 的润色，变成一段充满诗意和力量的祝福语，并封装在一张精美的卡片中。

**适合什么情况？**
- 个人许愿、新年目标设定、生日愿望记录。
- 需要一点仪式感来激励自己或朋友。
- 想生成一张漂亮的图片，分享到社交媒体或设为壁纸。
- 快速体验 AI 生成内容与前端设计结合的效果。

**不适合什么情况？**
- 需要长篇大论、逻辑严谨的文章或报告。
- 需要高度定制化、反复修改的正式文案。
- 需要保存大量历史记录并进行管理（它没有数据库）。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    - **一个文本框**：让你写下简短的愿望（一句话）。
    - **六个风格按钮**：让你选择卡片的视觉主题（如“金橙渐变”、“水墨中国”）。

2.  **用户通常会做哪几步操作？**
    1.  在左侧“写下你的愿望”框中，输入你的心愿（例如：希望今年能学会弹吉他）。
    2.  在“选择卡片风格”区域，点击一个你喜欢的模板缩略图。
    3.  点击中间的 **“生成未来签”** 按钮。
    4.  稍等几秒，右侧的卡片预览区就会显示出 AI 为你生成的、文采斐然的祝福语。
    5.  如果满意，点击生成按钮旁边的 **下载图标**，即可将这张精美的卡片保存为 PNG 图片。

3.  **输出结果长什么样？**
    - 一张视觉风格统一的卡片图片，包含：
        - 你输入的原始愿望（作为标题）。
        - AI 生成的一段 50-80 字的优美祝福语（作为正文）。
        - 当前日期和“AI 生成”的标识（作为脚注）。

4.  **有哪些容易忽略的使用细节？**
    - **首次使用需配置 API**：点击右上角的齿轮图标，在弹出的设置窗口中填入你自己的 DeepSeek API Key，否则无法生成内容。
    - **风格影响文案氛围**：虽然 AI 生成逻辑不变，但不同风格的卡片名称（如“御赐签”、“灵签”）会微妙地影响生成提示词，让文案更贴合主题。
    - **导出的是高分辨率图片**：得益于 `html2canvas` 库，导出的图片清晰度很高，适合分享。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个职责明确的模块：

1.  **控制面板模块（左侧）**
    - **职责**：接收用户输入，提供操作入口。
    - **包含**：愿望输入框、生成按钮、模板选择器、下载按钮、错误提示区。
    - **逻辑**：用户在此模块进行所有交互决策（输入什么、选什么风格、何时生成）。

2.  **展示渲染模块（右侧）**
    - **职责**：实时预览和最终呈现结果。
    - **包含**：卡片容器，内部结构分为标题区（用户愿望）、内容区（AI 生成文本）、脚注区（日期和来源）。
    - **逻辑**：它被动地接收来自控制面板的数据（愿望文本、选中模板索引、AI 生成文本），并应用对应的 CSS 类进行渲染。**“数据驱动视图”** 在这里体现得淋漓尽致。

3.  **AI 服务模块（隐藏的桥梁）**
    - **职责**：处理核心业务逻辑，连接用户输入与 AI 能力。
    - **包含**：`generate` 函数中的提示词工程、`callLLM` 函数中的 API 调用。
    - **逻辑**：`用户愿望` → `拼接成特定格式的 Prompt` → `调用 DeepSeek API` → `接收并清洗 AI 返回的文本` → `更新给展示模块`。

**最值得学习的设计：**
**“关注点分离”与“数据流”的清晰度。** 整个应用以 `wish`（愿望）、`cardText`（AI 文本）、`currentTemplate`（模板索引）这几个核心数据为中心。控制模块修改它们，展示模块监听它们并自动更新 UI，AI 模块在需要时异步获取数据来更新 `cardText`。这种结构使得代码易于理解和维护，也是现代前端框架（如 Vue、React）的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt 扮演的角色**：它是一个**高度结构化的指令模板**，将用户零散的愿望，包装成一个 AI 模型能出色完成的、具体的文案创作任务。

2.  **解决的是“生成问题”**：它不试图让 AI 理解愿望背后的复杂人生（理解问题），而是明确要求 AI **扮演一个特定角色**（占卜师），**按照特定格式和风格**（诗意、正能量、50-80字），**生成一个特定类型的内容**（未来签祝福语）。

3.  **Prompt 中的关键变量**：
    - **系统指令**：`你是一位温柔而智慧的占卜师...`（设定角色和基调）。
    - **用户愿望**：`「${wish.value}」`（这是唯一的动态变量，被嵌入到固定结构中）。
    - **具体约束**：字数、语言风格、内容导向、输出格式（确保结果可控）。

4.  **如果只改 Prompt，不改代码，会发生什么？**
    - **改变内容类型**：把“未来签祝福语”改成“毒舌吐槽”、“莎士比亚风格十四行诗”，网页就会生成完全不同风格的内容。
    - **改变格式**：要求“生成五条简短建议”，那么输出就会变成列表形式。
    - **改变角色**：把“占卜师”改成“科幻作家”，生成的内容就会充满科技感。
    - **核心体验不变**：网页的输入、选择风格、生成、导出的流程完全不变，但产出的内容性质天差地别。这展示了 **Prompt 作为“内容引擎”的可插拔性**。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：替换“场景”和“外壳”**
- **目标**：在不改动核心逻辑的情况下，做一个新东西。
- **操作**：
    1.  修改 `title`、`<h1>` 标题和描述，例如改成“AI 梦境记录器”、“一句话生成朋友圈文案”。
    2.  修改左侧输入框的 `placeholder` 和提示文字，例如从“写下你的愿望”改成“描述你昨晚的梦”或“输入产品名称”。
    3.  修改六个模板的名称和预览图标，使其符合新主题（如“梦境记录器”的模板可以是“清醒梦”、“噩梦”、“预言梦”等）。

**第二步：调整 Prompt（内容引擎）**
- **目标**：让 AI 生成你想要的内容。
- **操作**：
    1.  在 `generate` 函数中找到 `prompt` 变量。
    2.  修改系统指令 (`role: 'system'`) 中的“角色”描述，例如改成“你是一个梦境解析师”。
    3.  修改给用户的指令模板，将“愿望”替换为你的新输入项，并规定新的输出要求（如“用第一人称叙述，带点超现实色彩”）。

**第三步：改变视觉输出形式**
- **目标**：让最终呈现的样子更贴合新主题。
- **操作**：
    1.  在 `templates` 数组里，修改每个模板的 `label`（卡片上的小标题），如从“未来签”改成“梦境档案”。
    2.  深入修改 `card-template-1` 到 `card-template-6` 的 CSS 样式，改变颜色、背景、字体，甚至添加新主题的装饰元素（如星空、云朵、代码雨等）。

完成这三步，你就拥有了一个功能完整、主题全新的应用。此时，你对整个项目的结构已经了然于胸。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“情感基调”或“文体风格”选择**
    - **操作**：在控制面板增加一个下拉菜单，选项如“温馨鼓励”、“犀利毒舌”、“文言古文”、“科技报告”。
    - **实现**：将这个选择值作为一个新变量（如 `tone`），在构造 `prompt` 时拼接进去，例如：`请用${tone}的风格来书写...`。
    - **效果**：用户对生成内容的控制力更强，玩法更多。

2.  **本地化与多模型支持**
    - **操作**：在设置弹窗中，除了 DeepSeek，增加 OpenAI GPT、Claude 或国内 Moonshot、智谱等模型的选项和对应的 API Key 输入框。
    - **实现**：修改 `callLLM` 函数，根据用户选择的模型，切换不同的 API 端点、请求头和参数。
    - **效果**：用户可以选择自己拥有或更喜欢的模型，提升工具的可用性。

3.  **增加“历史记录”功能**
    - **操作**：在页面底部或侧边新增一个区域。
    - **实现**：每次成功生成后，将 `愿望`、`卡片文本`、`日期`、`模板索引` 作为一个对象存入 `localStorage` 的一个数组中，并在这个区域渲染成列表。可以点击历史记录重新预览。
    - **效果**：工具从一个“一次性生成器”变成了有记忆的“个人愿望库”。

4.  **优化交互：实时预览与防抖生成**
    - **操作**：为愿望输入框绑定输入事件。
    - **实现**：使用防抖函数（例如延迟 1 秒），在用户停止输入后自动调用 `generate` 函数，实现“边输入边预览”的效果。注意要处理好加载状态。
    - **效果**：交互更流畅、更即时，科技感更强。

5.  **分享功能与自定义文案**
    - **操作**：在下载按钮旁增加“复制文案”和“分享到 Twitter/微博”按钮。
    - **实现**：“复制文案”直接用 `navigator.clipboard.writeText` 实现。“分享”可以调用各平台的分享 SDK，或生成一个包含图片和文本的分享链接。
    - **效果**：从“个人工具”转向“社交传播工具”，增加用户粘性和传播性。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合做专业的文案创作或咨询**：AI 生成的内容具有随机性和通用性，虽然优美但缺乏真正的个人洞察和专业深度。如果需要商业文案、法律文件、心理咨询等，应寻求专业人士。
- **不适合处理复杂、多步骤的交互任务**：它的设计是“输入-生成-输出”的单次线性流程。如果你需要用户连续回答多个问题、进行复杂配置（如详细的人物设定、世界观），那么应该设计成多页表单或聊天机器人式的交互。
- **不适合需要极高稳定性和数据安全的生产环境**：API Key 前端存储有泄露风险，所有逻辑运行在用户浏览器端，无法保证服务永远可用。如需商用，必须搭建后端服务器来代理 API 调用、管理密钥和用户数据。
- **不适合替代真正的艺术设计**：虽然卡片模板精美，但它们是固定样式。如果需要完全自由、像素级控制的平面设计，应使用 Figma、Photoshop 等专业工具或更高级的可视化编辑器。

**总结**：这是一个出色的 **“概念验证”** 和 **“学习样板”** 。它完美展示了如何将前端设计、交互逻辑与 AI 能力快速结合，创造出一个有吸引力、可用的迷你产品。你的学习重点应该是理解其模块化架构和数据流，然后大胆地用 Prompt 和 CSS 去改造它，创造出属于你自己的、有趣的应用。
