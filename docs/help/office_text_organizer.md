# 长文本智能整理器 - 学习指南

你好！这份文档将帮助你理解、使用并改造这个“长文本智能整理器”。无论你是想直接用它，还是想学习它的设计思路并做出自己的版本，这里都有你需要的答案。

---

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你刚开完一个长达两小时的线上会议，聊天记录有好几百条。或者，你收到了一封包含几十条往来的邮件线程。又或者，你需要快速理解一份冗长的报告。面对这些“信息洪水”，手动梳理要点、决策和待办事项非常耗时且容易遗漏。

这个网页就是你的“信息助理”。它帮你**自动消化长文本，提炼出结构化的核心信息**。你不再需要逐字阅读，而是能立刻看到一份清晰的总结、待办清单和问题列表。

**适合什么情况？**
- 整理混乱的群聊记录，提取会议结论。
- 梳理邮件线程，明确各方立场和下一步行动。
- 快速阅读长篇文章或报告，抓取核心论点。
- 将非结构化的对话转化为可执行的待办事项。

**不适合什么情况？**
- 处理需要高度保密、绝对不能外传的敏感内容（因为内容会发送到外部AI API）。
- 进行需要精确法律、医学等专业判断的分析（AI可能出错）。
- 整理本身就是高度结构化、格式固定的文本（如财务报表），用专门的解析工具可能更高效。

## 【二】使用方式（给第一次接触的人）

**第一步：配置（首次使用）**
1.  点击右上角的“设置”按钮。
2.  在弹出的窗口中，输入你的 DeepSeek API Key（需要先去官网申请）。
3.  选择模型（推荐“DeepSeek R1”以获得更好的分析质量），然后点击“保存”。

**第二步：输入内容**
1.  **选择内容类型**：在左侧“内容类型”区域，根据你的文本选择（如“聊天记录”、“会议纪要”）。如果拿不准，就选“自动识别”。
2.  **粘贴文本**：将你的长文本（聊天记录、会议转录稿、邮件内容等）粘贴到下方的大文本框中。
3.  **（可选）上传文件**：也可以点击“上传 .txt/.md 文件”按钮，直接上传文本文件。

**第三步：设置整理选项**
在“整理选项”区域，勾选你希望AI执行的操作，例如：
-   `提取关键决策`：找出讨论后达成的结论。
-   `列出待办事项`：生成带有责任人的任务清单。
-   `过滤噪音`：自动去掉“你好”、“谢谢”等寒暄和表情符号。
-   `按主题分组`：将分散的讨论归类到不同主题下。
-   `识别未解决问题`：找出悬而未决的议题。

**第四步：生成结果**
点击绿色的“**开始智能整理**”按钮。稍等片刻（时间取决于文本长度），右侧就会显示出整理结果。

**输出结果长什么样？**
结果会以清晰的 Markdown 格式呈现，通常包括：
-   **核心要点总结**：一段话概括全文。
-   **关键决策列表**：用条目列出已决定的事项。
-   **待办事项清单**：格式为 `- [ ] 任务内容 | 负责人 | 截止时间`。
-   **主要讨论主题**：将对话按不同话题分组展示。
-   **未解决问题**：列出还需要跟进或讨论的议题。

**容易忽略的细节：**
1.  **“深度分析过程”可以展开**：结果上方有一个“🧠 深度分析过程”的折叠区域，点击可以查看AI是如何一步步思考得出最终结论的。这对于理解AI的逻辑和学习Prompt设计非常有帮助。
2.  **结果可以复制和导出**：整理完成后，可以使用结果右上角的“复制”按钮复制文本，或用“导出”按钮下载为一个 `.md` 格式的Markdown文件。
3.  **字符数估算**：在输入框下方，会显示一个基于字数的粗略估算（如“2 字符”），这能帮你对文本长度有个大致概念。

## 【三】核心结构拆解（学习重点）

这个页面采用了清晰的“左输入-右输出”布局，可以拆解为以下几个模块：

**1. 配置管理模块**
*   **职责**：管理用户的核心设置（API Key、模型选择），并将设置持久化保存在浏览器的本地存储中。
*   **逻辑**：用户点击“设置” -> 弹出窗口 -> 输入并保存 -> 设置被存入 `localStorage` -> 后续所有AI调用都使用此配置。

**2. 输入与参数控制模块（左侧）**
*   **职责**：收集用户的所有输入和偏好设置。
*   **组成**：
    *   **内容类型选择器**：让AI知道它要处理的是什么格式的文本。
    *   **文本输入区**：接收核心的待处理文本。
    *   **整理选项开关**：一系列复选框，让用户自定义AI的分析维度（如是否提取待办、是否分组等）。
*   **逻辑**：用户的所有选择（类型、文本、选项）都会被收集到一个叫 `form` 的数据对象中，为后续生成AI指令做好准备。

**3. AI 处理与通信模块（幕后核心）**
*   **职责**：将用户的输入和选项，转换成一个精心设计的“问题”（Prompt），然后调用外部AI API获取回答。
*   **关键函数**：`organizeText()` 和 `callDeepSeek()`。
*   **逻辑链路**：
    `用户点击整理` -> `检查配置` -> **`组装Prompt`**（系统指令 + 用户内容 + 选项）-> `调用DeepSeek API` -> `流式接收AI回复` -> `将回复分离为“思考过程”和“最终答案”` -> `更新页面数据`。

**4. 结果展示与交互模块（右侧）**
*   **职责**：优雅地呈现AI生成的内容，并提供后续操作。
*   **组成**：
    *   **空状态**：未处理时的引导界面。
    *   **思考过程面板**：可折叠，展示AI的“内心戏”。
    *   **结果展示面板**：使用 `marked` 库将AI返回的Markdown文本渲染成美观的HTML。
    *   **操作按钮**：“复制”和“导出”，提供结果的使用便利性。

**最值得学习的设计：**
**“流式处理”与“思考过程分离”**。这个页面没有傻等AI一次性生成全部内容，而是采用了“流式”接收，让用户可以边等边看到部分结果，体验更好。更重要的是，它利用了DeepSeek R1等模型能返回“推理过程”的特性，将思考过程（`reasoning_content`）和最终答案（`content`）分开接收和展示。这不仅让结果生成显得更“透明”，也是调试和优化Prompt的宝贵窗口。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 扮演的角色：**
Prompt 在这里是**总指挥官和格式规范**。它告诉AI：“你是谁”（专业文本整理专家）、“你要做什么”（分析长文本并结构化）、“具体怎么做”（根据用户勾选的选项逐条执行）以及“最终成果长什么样”（严格的Markdown格式）。

**它解决的是“生成问题”：**
它主要解决的是**如何根据一堆非结构化的输入，生成一份高质量、结构化输出**的问题。它需要理解用户模糊的选项（如“提取关键决策”），并将其转化为AI可执行的具体分析动作。

**Prompt 中的关键变量：**
1.  **系统指令 (`systemPrompt`)**：定义了AI的角色、任务、具体要求和**输出格式模板**。这是Prompt的骨架。
2.  **用户选项 (`analysisRequirements`)**：根据用户在前端勾选的复选框动态生成。这部分将用户意图翻译成AI能理解的任务列表，是Prompt的“血肉”。
3.  **内容类型 (`typeMap[form.contentType]`)**：告诉AI文本的体裁，帮助它采用更合适的分析策略。
4.  **原始文本 (`form.content`)**：需要被分析的核心材料。

**如果只改 Prompt，不改代码，会发生什么？**
整个页面的**核心功能将彻底改变**。例如：
-   你可以把系统指令从“文本整理专家”改成“法律条款审查员”，那么它输出的就会是风险点分析，而非会议纪要。
-   你可以修改输出格式，让它生成一个表格、一个JSON对象，或者一封正式的邮件。
-   你可以调整分析要求，比如增加“识别对话中的情绪变化”或“评估发言人的贡献度”。
**代码只是搬运工和展示架，Prompt 才是决定这个工具“是什么”和“做什么”的大脑。**

## 【五】如何模仿它，做出你自己的版本？

如果你想创建一个类似但用途不同的AI工具，请遵循以下安全的模仿路径：

**第一步：替换核心场景与Prompt（最安全、变化最大）**
*   **目标**：先做出一个“形似神不似”的版本。
*   **操作**：
    1.  复制整个HTML文件。
    2.  修改 `<title>` 和导航栏中的工具名称，比如改成“**合同条款审查助手**”。
    3.  找到代码中的 `systemPrompt` 变量，彻底重写它。将角色从“文本整理专家”改为“资深法务”，将任务从“整理信息”改为“识别合同风险”，将输出格式改为风险清单。
    4.  修改“内容类型”选项，将“聊天/会议/邮件”换成“采购合同/劳动合同/租赁协议”等。
    5.  修改“整理选项”，将“提取待办”等换成“识别模糊条款/检查违约责任/审核支付条款”等。

**第二步：调整输入与输出界面**
*   **目标**：让界面与新场景更匹配。
*   **操作**：
    1.  根据新场景，调整左侧输入区的说明文字和占位符。
    2.  调整右侧结果区域的标题和图标。
    3.  如果新场景需要不同的输入（如上载PDF），可以开始规划，但先保持文本框不变。

**第三步：改造数据处理逻辑**
*   **目标**：让代码更好地服务于新功能。
*   **操作**：
    1.  如果新工具需要处理文件（如图片、PDF），在 `handleFileUpload` 函数中增加对应的文件类型和解析逻辑（可能需要引入新的JS库）。
    2.  如果输出格式不再是Markdown，而是JSON或图表，则需要修改 `callDeepSeek` 函数中对返回数据的处理方式，以及 `exportResult` 函数的导出逻辑。

**从哪里下手最安全？**
**从第一步的 Prompt 和文字替换开始。** 这样你无需理解复杂的JS流式处理逻辑，就能立刻获得一个功能完全不同、但运行稳定的新工具。这是体验“Prompt即产品”力量最快的方式。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“角色视角”选择**：
    *   **操作**：在“整理选项”上方增加一个下拉框，让用户选择“作为项目经理整理”、“作为销售复盘”或“作为研发提取需求”。
    *   **实现**：将这个选择作为变量加入到 `userPrompt` 中，例如：“请站在【项目经理】的视角，对以下会议记录进行整理...”。
    *   **效果**：同一份文本能产出针对不同角色的定制化摘要，实用性大增。

2.  **支持多轮对话与精炼**：
    *   **操作**：在结果下方增加一个新的文本输入框和“继续提问”按钮。
    *   **实现**：点击按钮后，将用户的新问题和之前的对话历史（包括AI的整理结果）一起，作为新的上下文发送给AI。
    *   **效果**：用户可以对整理结果进行追问，如“请将第三个待办事项分解为更细的子步骤”，让工具从“一次性整理”变为“交互式分析”。

3.  **更换或兼容更多AI模型**：
    *   **操作**：在设置弹窗中，将模型选择从DeepSeek两款，扩展为支持OpenAI GPT、Claude、智谱AI等。
    *   **实现**：修改 `callDeepSeek` 函数为 `callAI`，内部根据用户选择的模型，切换不同的API地址、请求头和参数结构。
    *   **效果**：用户可以根据成本、速度、效果偏好自由选择模型，工具的适应性和灵活性更高。

4.  **优化交互体验**：
    *   **操作**：为“开始智能整理”按钮增加一个“中途取消”的功能。
    *   **实现**：在流式读取 (`reader.read()`) 的循环中检查一个取消标志，如果用户点击取消，则调用 `reader.cancel()` 并退出循环。
    *   **效果**：避免用户因等待过长或想修改输入而不得不刷新页面的糟糕体验。

5.  **本地缓存与历史记录**：
    *   **操作**：在页面左侧或新增一个侧边栏，展示历次整理任务的历史记录。
    *   **实现**：每次成功整理后，将时间、内容摘要和结果的关键信息存入 `localStorage` 或 `IndexedDB`。
    *   **效果**：用户可以回顾和查找之前的分析，形成一个有价值的知识库。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合处理绝对敏感信息**：所有文本都会通过互联网发送到DeepSeek的服务器。**切勿**用它整理包含商业秘密、未公开的个人隐私、国家安全信息等敏感内容。
    *   **应该怎么做**：对于这类需求，需要使用能部署在本地或私有环境的开源大模型方案。

2.  **不适合做事实核查或专业判断**：AI可能会“幻觉”出文本中不存在的信息，或对专业领域（法律、医疗、金融）做出不准确的解读。它的输出是“参考摘要”，而非“权威结论”。
    *   **应该怎么做**：对于重要决策，务必以原始文本和人类专家的判断为准。这个工具的作用是**提高信息处理效率**，而非**替代人类决策**。

3.  **不适合处理超长文本（有Token限制）**：所有AI模型都有单次处理的文本长度上限（上下文窗口）。虽然这个工具能处理很长的聊天记录，但如果是一整本书，可能会被截断或导致API调用失败。
    *   **应该怎么做**：对于超长文本，需要先进行人工或自动的分割，然后分段处理，最后再合并摘要。这需要更复杂的代码逻辑。

4.  **不适合作为实时转录工具**：它需要你提供完整的、已成文的文本。它不能直接连接你的会议软件或麦克风进行实时语音转文字和整理。
    *   **应该怎么做**：需要先使用专门的语音转文字工具（如讯飞听见、腾讯云语音识别）获得文本，再将文本粘贴到这里进行整理。
