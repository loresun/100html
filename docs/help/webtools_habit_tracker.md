# 习惯养成打卡 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景**：当你想要培养一个新习惯（比如每天阅读、运动、喝水），但总是容易忘记或缺乏动力时，这个工具可以帮助你。它像一个**可视化的习惯追踪器**，让你清晰地看到自己每天的坚持情况，通过“打卡”动作和直观的热力图，获得持续的正向反馈。

**适合**：
- 个人习惯养成（学习、健康、生活）
- 需要视觉激励来保持动力的人
- 想回顾自己一段时间坚持成果的场景

**不适合**：
- 需要团队协作或多人监督的习惯
- 需要复杂数据分析（如与心率、睡眠关联）
- 习惯频率不是“每日”的情况（如每周三次）

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    - **新增习惯**：点击右上角“新增习惯”按钮，在弹出的窗口中，你需要提供：
        - **图标**：从16个表情图标中选择一个代表你的习惯。
        - **名称**：给习惯起个名字（如“每天冥想10分钟”）。
        - **描述**：（可选）写下养成这个习惯的原因或目标。

2.  **用户通常会做哪几步操作？**
    1.  **创建习惯**：按照上述步骤添加你的第一个习惯。
    2.  **每日打卡**：在习惯卡片底部，点击蓝色的“今日打卡”按钮。点击后，按钮会变成绿色的“今日已打卡”。
    3.  **查看进度**：创建后，页面会为每个习惯生成一个**热力图**（由许多小方格组成）。你每天打卡，对应日期的小方格就会变成绿色（颜色越深，代表你近期打卡越连续）。同时，卡片顶部会显示“当前连续天数”、“累计打卡天数”和“完成率”。
    4.  **补打卡或纠错**：你可以直接点击热力图上**过去日期**的方格，来标记那天是否完成了习惯。点击一下打勾，再点击一下取消。
    5.  **删除习惯**：点击某个习惯卡片右上角的垃圾桶图标，可以删除它。

3.  **输出结果长什么样？**
    - 每个习惯会以一个**精美的卡片**形式展示。
    - 卡片下方是一个类似GitHub贡献图的**彩色热力图**，绿色方格代表打卡日，灰色代表未打卡。
    - 统计数据（连续天数、累计天数、完成率）会实时更新并显示在卡片上。

4.  **有哪些容易忽略的使用细节？**
    - **数据自动保存**：你所有的习惯和打卡记录都自动保存在你浏览器的本地（LocalStorage），关闭页面再打开数据还在。但**换一台电脑或清除浏览器数据就会丢失**。
    - **热力图交互**：鼠标悬停在热力图的每个小方格上，会弹出具体的日期和打卡状态。
    - **补打卡逻辑**：热力图允许你为过去的任何一天打卡或取消打卡，这会影响“连续天数”的计算（系统会从今天往前推算连续打卡的天数）。

## 【三】核心结构拆解（学习重点）

这个页面可以看作由四个核心模块组成：

1.  **状态管理模块（大脑）**
    - **职责**：它是整个应用的核心，用 `habits` 数组管理所有习惯数据。每个习惯是一个对象，包含名称、图标、描述，以及最重要的 `checks` 对象（用来记录每一天是否打卡）。
    - **关键设计**：它使用 Alpine.js 的 `x-data` 将应用状态（数据）和页面绑定在一起。数据一变，页面自动更新。

2.  **习惯列表展示模块（展示墙）**
    - **职责**：负责将 `habits` 数组中的每个习惯，渲染成一个完整的视觉卡片。它使用了 `x-for` 指令进行循环渲染。
    - **子模块**：
        - **头部**：显示图标、名称、连续天数标签。
        - **统计面板**：计算并展示核心数据。
        - **热力图**：根据 `checks` 数据和当前日期，动态生成过去26周的可视化图表。
        - **快速打卡按钮**：提供最便捷的当日打卡入口。

3.  **新增习惯模块（创建器）**
    - **职责**：通过一个弹出窗口（模态框）收集用户输入，并调用状态管理模块的 `addHabit` 函数，将新习惯对象添加到 `habits` 数组中。

4.  **持久化模块（记忆库）**
    - **职责**：利用浏览器的 `localStorage`，在 `habits` 数组每次变化时自动保存，并在页面加载时自动读取。这实现了“关掉网页再打开，数据还在”的效果。

**输入 → 处理 → 输出 的逻辑链路**：
- **输入**：用户点击“新增习惯”并填写表单。
- **处理**：`addHabit` 函数将输入数据组装成一个新的习惯对象，推入 `habits` 数组。状态变化触发 Alpine.js 的响应式系统。
- **输出**：响应式系统驱动“习惯列表展示模块”重新渲染，页面上立刻出现一张新的习惯卡片。

**最值得学习的设计**：
- **数据与视图的绑定**：使用 Alpine.js 这类轻量级框架，无需手动操作DOM。你只需要关心如何修改 `habits` 数组中的数据（如 `toggleCheck`），页面就会自动同步更新。这是现代前端开发的核心思想。
- **热力图的生成算法**：`getHeatmapData` 函数是亮点。它根据当前日期和星期几，倒推出过去26周里每一天的日期对象，再与打卡记录匹配，生成用于渲染的二维数组。这是一个将**数据逻辑**转化为**可视化信息**的经典案例。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：当前版本的代码**没有使用AI或Prompt**。它是一个纯粹的前端数据管理应用。但我们可以探讨如果未来要加入AI功能，Prompt可能扮演的角色，这对于理解AI应用设计很有帮助。

1.  **Prompt 可能扮演的角色**：
    - **习惯建议生成器**：根据用户目标（如“改善健康”），AI生成具体的习惯建议（“每天喝2升水”、“每周三次有氧运动”）。
    - **激励语生成器**：在用户打卡后，AI生成一句个性化的鼓励话语。
    - **数据分析师**：分析用户的打卡模式，用自然语言给出洞察（“你每周三的完成率较低，是否需要调整计划？”）。

2.  **它解决的是“理解问题”还是“生成问题”？**
    - 在上述场景中，主要是**生成问题**。AI需要根据一些输入（用户目标、打卡历史），生成新的、相关的文本内容（建议、鼓励、洞察）。

3.  **哪些信息是 Prompt 中的关键变量？**
    - 如果设计一个“生成鼓励语”的AI功能，Prompt可能包含：
        - `用户习惯名称`：如“每天阅读”。
        - `用户连续打卡天数`：如“7”。
        - `用户历史完成率`：如“85%”。
        - `今日日期/星期`：如“周一”。
        - `生成语气要求`：如“热情而简洁”。

4.  **如果只改 Prompt，不改代码，会发生什么变化？**
    - AI输出的**内容和风格**会完全不同。例如，把Prompt从“生成一句鼓励的话”改成“用莎士比亚的风格写一句赞美诗”，那么用户打卡后看到的激励语就会从“加油，你真棒！”变成“汝之坚持，犹如晨曦破晓，光辉且恒久。”

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的习惯追踪器或类似应用：

**第一步：替换核心主题与数据模型（最安全）**
- **目标**：做一个“情绪日记”或“项目任务追踪”。
- **操作**：
    1.  将 `habits` 改名为 `journals`（情绪日记）或 `tasks`（任务）。
    2.  修改 `newHabit` 对象的字段。例如，对于情绪日记，字段可以是 `icon`（表情😊😢）、`date`（日期）、`mood`（心情）、`content`（日记内容）。
    3.  将页面文字“习惯”全部替换为“情绪记录”或“任务”。

**第二步：调整输入表单和展示形式**
- **操作**：
    1.  在新增项目的模态框里，把“习惯名称”输入框改成“任务描述”或“心情选择下拉菜单”。
    2.  在展示卡片上，把“热力图”替换成其他展示方式，比如对于情绪日记，可以展示一个**日历视图**，不同心情用不同颜色填充日期格。

**第三步：修改核心交互逻辑**
- **操作**：
    1.  `toggleCheck` 函数可能不再适用。对于情绪日记，你可能需要一个 `addJournal` 函数来新增记录，一个 `editJournal` 函数来修改。
    2.  统计面板的计算逻辑也需要改变。例如，计算“本月平均心情指数”或“任务按时完成率”。

**从哪里下手最安全？**
从 **第一步** 开始。先只改变量名、文字和 `newHabit` 对象的字段结构，保持新增、删除、保存到本地存储的功能不变。这样你能立即看到一个可运行的、属于你的新应用雏形。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加习惯分类与筛选**
    - **操作**：在 `newHabit` 对象中增加一个 `category` 字段（如：健康、学习、工作）。在页面顶部添加几个筛选按钮（如“全部”、“健康”、“学习”），点击后，利用 `x-show` 或计算属性只显示对应分类的习惯。

2.  **为热力图赋予真实意义**
    - **操作**：当前热力图的颜色等级是随机的（`Math.random()`）。你可以改进 `getHeatmapData` 函数，让颜色深度代表**打卡强度**（如果未来增加“强度”输入）或**连续打卡的累积效应**（例如，连续打卡越长，当天颜色越深）。

3.  **加入简单的社交分享或目标设定**
    - **操作**：在每个习惯卡片上增加一个“分享成就”按钮。点击后，将“我已连续坚持[streak]天[habit.name]！”这段文本复制到用户剪贴板，方便他们粘贴到社交媒体。或者，增加一个“目标天数”字段，并展示一个进度条。

4.  **改善数据持久化与备份**
    - **操作**：增加一个“导出数据”按钮，将 `habits` 数组转换为JSON文件并下载。同时增加一个“导入数据”按钮，允许用户上传之前的备份文件来恢复数据。这解决了本地存储无法跨设备的问题。

5.  **引入微交互与动画增强体验**
    - **操作**：在点击“今日打卡”按钮时，除了变色，可以添加一个轻微的动画，比如按钮图标从空心圆环填充为实心对勾的过渡动画，或者触发一个微小的庆祝动效（如飘落几个表情），让打卡瞬间更有成就感。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为严肃的健康或医疗数据记录工具**
    - **局限性**：数据仅存储在本地浏览器，有丢失风险，且无加密。无法生成专业的趋势报告。
    - **替代方案**：如果需要记录血糖、血压等健康数据，应使用专业的健康类App或设备配套应用。

2.  **不适合管理复杂的、非每日性的项目任务**
    - **局限性**：它的模型基于“每日打卡”，无法很好地处理“每周一、三、五”、“每月一次”或带有子任务、依赖关系的复杂项目。
    - **替代方案**：使用专业的项目管理工具（如Trello, Notion, Todoist）或日历应用。

3.  **不适合需要强提醒和推送的场景**
    - **局限性**：它是一个网页，除非一直打开，否则无法主动发送提醒通知你该打卡了。
    - **替代方案**：如果需要强提醒，应使用手机的原生提醒事项App，或具有推送通知功能的习惯追踪类移动应用。

4.  **不适合多人共同追踪一个习惯**
    - **局限性**：数据完全本地化，无法实时同步和共享。
    - **替代方案**：使用支持共享的在线协作工具（如共享表格），或专门为小组习惯打卡设计的社交应用。
