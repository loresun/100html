# Markdown 预览器 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正在写一篇技术博客、一份项目文档，或者一份包含代码和列表的笔记。你习惯用 Markdown 这种轻量级标记语言来写，因为它简单高效。但是，你写的时候看不到最终效果，只能靠想象。这个网页就像一个“实时翻译官”，你在这边用 Markdown 语法写，它立刻在旁边（或同一个窗口）把最终排版好的样子展示给你看。它让你能一边写，一边确认格式是否正确，所见即所得。

**适合什么情况？**
- 快速撰写和预览 Markdown 格式的文档、博客、笔记。
- 学习 Markdown 语法，通过实时预览理解每个标记的作用。
- 需要将 Markdown 快速转换为独立 HTML 文件分享给他人。

**不适合什么情况？**
- 需要复杂排版、多栏布局或精确像素级设计的正式出版物。
- 需要多人协作编辑的文档（它没有云端保存和协作功能）。
- 处理包含大量图片、视频等富媒体且需要复杂管理的文档。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
一个大的文本输入框，你可以在里面输入任何文字，并使用 Markdown 语法（如 `# 标题`、`**粗体**`）来添加格式。

**用户通常会做哪几步操作？**
1.  **开始输入**：直接在左侧（或全屏时的唯一）编辑区输入你的内容。
2.  **使用工具栏**：如果记不住语法，可以点击上方的按钮（如“H1”、“粗体”、“列表”），它们会自动在光标处插入对应的 Markdown 符号。
3.  **切换视图**：通过顶部的“分屏”和“预览”按钮，可以切换是左右分屏（一边写一边看），还是全屏只看最终效果。
4.  **导出结果**：写完后，可以点击“复制HTML”将渲染好的 HTML 代码复制到剪贴板，或者点击“导出HTML”下载一个完整的、带样式的网页文件。

**输出结果长什么样？**
在右侧（或全屏时的）预览区域，你会看到一个排版清晰、样式美观的文档。标题有下划线，代码有高亮，列表有缩进，链接有颜色，和你平时在博客或文档网站上看到的效果一样。

**有哪些容易忽略的使用细节？**
- **加载示例**：如果你不知道怎么写，点击编辑器右上角的“加载示例”按钮，它会填充一份完整的示例文档，教你各种语法的写法。
- **视图模式**：在窄屏设备（如手机）上，“分屏”模式可能体验不佳，此时切换到“预览”模式专注查看结果会更合适。
- **字符统计**：编辑器底部会实时显示你输入的总字符数和行数，对需要控制篇幅的场景很有用。
- **插入文本的妙用**：工具栏的按钮不仅能在空白处插入符号，如果你先用鼠标选中了一段文字，再点击按钮（如“粗体”），它会自动用 `**` 包裹你选中的文字，非常方便。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个模块，像一个高效的生产线：

1.  **控制面板模块（顶部 Header）**
    *   **职责**：全局控制和导航。它决定了你是“分屏写”还是“全屏看”，并提供了最终成果的出口（导出）。
    *   **输入**：用户点击“分屏”、“预览”、“导出HTML”按钮。
    *   **处理**：改变 `view` 变量的值（控制界面布局），或触发文件下载。
    *   **输出**：界面布局切换，或浏览器下载一个 `.html` 文件。

2.  **编辑与预览显示模块（中部 Main Grid）**
    *   **职责**：这是核心工作区。它根据 `view` 的值，动态决定是显示“编辑器+预览”两栏，还是只显示“预览”一栏。
    *   **编辑器子模块**：
        *   **输入**：用户键盘输入 Markdown 文本。
        *   **处理**：文本被绑定到 `markdown` 变量。每次输入都触发 `updatePreview()` 函数。
        *   **输出**：更新 `markdown` 变量，并间接触发预览更新。
    *   **预览子模块**：
        *   **输入**：来自 `markdown` 变量转换后的 `html` 变量。
        *   **处理**：使用 `x-html` 指令将 HTML 字符串安全地渲染到 DOM 中。
        *   **输出**：在页面上展示格式化的文档。

3.  **格式工具栏模块（底部 Toolbar）**
    *   **职责**：降低使用门槛，提供快捷操作。它封装了常用的 Markdown 语法。
    *   **输入**：用户点击任意格式按钮。
    *   **处理**：调用 `insertText()` 函数，智能地在文本编辑框的光标位置（或选中文本周围）插入对应的 Markdown 标记符号。
    *   **输出**：编辑框中的文本内容被修改，并自动触发预览更新。

4.  **逻辑处理引擎（JavaScript 函数）**
    *   **职责**：这是页面的大脑，负责所有数据处理和状态管理。
    *   **核心链路**：`markdown` (用户输入) → `marked.parse()` (转换引擎) → `html` (处理结果) → `x-html` (渲染输出)。
    *   **关键函数**：
        *   `updatePreview()`: 桥梁，调用 `marked` 库进行转换。
        *   `insertText()`: 智能文本编辑的核心，处理光标和选区逻辑。
        *   `loadTemplate()` / `copyHTML()` / `downloadHTML()`: 提供数据示例和导出功能。

**最值得学习的设计：**
**“响应式状态驱动”的架构。** 整个应用围绕几个核心状态（`markdown`, `html`, `view`）运转。用户的所有操作（输入、点击按钮）都只是在修改这些状态。而页面布局（分屏/预览）、预览内容会自动响应状态的变化而更新。这种设计（借助 Alpine.js 实现）让逻辑非常清晰，数据和视图分离，是构建现代交互式网页的经典模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **重要提示**：当前这个 Markdown 预览器网页**没有使用 AI 或 Prompt**。它的核心是一个确定性的规则转换引擎（`marked` 库）。因此，这一节我们将探讨：**如果我们要为它加入 AI 能力，Prompt 逻辑可以如何设计？** 这能帮助你理解何时以及如何引入 AI。

**假设场景：** 我们增加一个“AI 润色”或“AI 生成摘要”按钮。

*   **Prompt 扮演的角色**：此时，Prompt 是给 AI 模型的“指令说明书”，告诉它如何加工我们输入的 Markdown 文本。
*   **解决什么问题**：它解决的是“生成问题”和“理解与改写问题”。例如，让 AI 根据现有内容生成一个摘要，或者将口语化的句子改写成更正式的文档风格。
*   **关键变量**：
    1.  **系统角色设定**：`你是一位专业的技术文档编辑。`
    2.  **用户输入（变量）**：`${markdown}` （将编辑器中的全部或部分文本填入）。
    3.  **具体任务指令**：`请为上面的 Markdown 文档生成一个不超过 100 字的摘要。` 或 `将以下文本的语气改写得更加正式和专业：`
*   **如果只改 Prompt，不改代码**：
    *   改变 AI 的“角色”（如从“技术编辑”变成“小学老师”），会直接影响输出文本的风格和用词难度。
    *   改变“任务指令”（如从“写摘要”变成“检查语法错误”），会得到完全不同的结果。
    *   改变对输出格式的要求（如“用列表形式给出三点建议”），AI 的回复结构也会相应改变。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的工具：

**第一步：替换核心转换逻辑（最安全的起点）**
保持现有的“双栏布局”、“状态管理”、“工具栏”结构完全不变。只替换掉 `marked` 库的功能。例如：
*   **目标**：做一个“JSON 格式化与验证器”。
*   **改造**：将 `marked.parse()` 替换为 `JSON.parse()` 和 `JSON.stringify(..., null, 2)`。左侧输入 JSON 字符串，右侧展示格式化后的漂亮 JSON 或错误信息。工具栏按钮可以改成“格式化”、“压缩”、“验证”等。

**第二步：调整输入与输出形式**
在第一步成功的基础上，根据新工具的特性调整界面。
*   **继续以 JSON 工具为例**：
    *   **输入**：可能不需要“加载示例”按钮，而是“加载默认配置”。
    *   **输出**：预览区可能不需要复杂的 CSS 样式，只需要一个 `<pre>` 标签展示高亮代码。可以增加一个错误信息显示区域。
    *   **工具栏**：按钮改为“格式化”、“压缩（去除空格）”、“转义/反转义”等。

**第三步：改变或增加功能模块**
当核心流程跑通后，可以增加新功能。
*   **还是 JSON 工具**：
    *   增加一个“模式切换”按钮，在“树状视图”和“原始视图”间切换。
    *   增加一个“导出”菜单，支持导出为 `.json` 文件或 `.csv` 文件。
    *   在底部增加一个“数据路径”输入框，允许用户输入类似 `data.users[0].name` 的路径来快速定位和查看部分数据。

**从哪里下手最安全？**
**从 `updatePreview()` 函数和它调用的转换库下手。** 这是整个应用的引擎。换掉它，你就换掉了工具的本质。页面框架（Alpine.js 状态管理、双栏布局）是通用的“外壳”，可以重复利用。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“主题切换”功能**：
    *   **操作**：在顶部控制栏加一个“主题”下拉菜单（如：亮色/暗色/护眼绿）。
    *   **实现**：定义几套不同的 CSS 变量或类名，切换时修改预览区域父容器或整个 `<body>` 的类名。可以让用户预览在不同风格下的文档效果。

2.  **集成“AI 辅助写作”**：
    *   **操作**：在工具栏增加“AI 续写”、“纠正语法”、“翻译”等按钮。
    *   **实现**：调用 OpenAI 或 Claude 等模型的 API。将当前选中的文本或整个文档作为 Prompt 的一部分发送。将 AI 返回的结果插入到编辑器光标处或提供一个替换选项。**注意**：这需要你有 API Key 并处理异步请求。

3.  **变为“多标签页”编辑器**：
    *   **操作**：在顶部增加标签页栏，可以新建、切换、重命名多个 Markdown 文档。
    *   **实现**：将 `markdown` 和 `html` 状态从一个变量变为一个数组或对象，用 `currentTabId` 来标识当前激活的文档。所有操作都基于当前激活的文档进行。数据可以用 `localStorage` 暂存。

4.  **支持“幻灯片演示模式”**：
    *   **操作**：增加一个“演示”视图按钮。
    *   **实现**：约定一种语法（例如用 `---` 分隔幻灯片），当切换到演示模式时，将 Markdown 按分隔符拆分，用全屏方式一张一张地展示渲染后的内容。可以搭配键盘左右键翻页。

5.  **添加“自定义 CSS” 侧边栏**：
    *   **操作**：在分屏视图下，增加第三个面板，或者一个可折叠的侧边栏。
    *   **实现**：允许用户输入自定义的 CSS 代码，并实时应用到预览区域。这能让用户微调最终输出的样式，比如修改字体、颜色、间距等，实现更个性化的预览。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合作为完整的“内容管理系统（CMS）”**：它没有后端，无法保存文档到数据库，无法管理用户，也无法实现版本历史。如果你需要这些，应该使用像 WordPress、Ghost 或专门的知识库软件（如 Obsidian Publish、Notion）。
*   **不适合进行复杂的图表绘制**：虽然 Markdown 支持简单的表格和代码块，但它无法渲染流程图、时序图、甘特图等。这类需求需要使用 Mermaid、PlantUML 等专业图表库，并集成到预览器中。
*   **不适合处理需要严格权限控制的文档**：所有转换都在浏览器前端完成，你输入的原始 Markdown 和生成的 HTML 对于懂得查看浏览器开发者工具的用户是可见的。**切勿用它来编辑或预览任何敏感、机密信息。**
*   **不适合替代专业的 IDE 或代码编辑器**：它的编辑功能非常基础，没有代码自动补全、语法高亮（针对 Markdown 本身）、函数跳转、项目管理等高级功能。编写大型项目文档时，使用 VS Code 等编辑器配合 Markdown 插件体验会更佳。

希望这份指南能帮助你不仅使用这个工具，更能理解其设计精髓，并创造出属于你自己的、更强大的应用。
