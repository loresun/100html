# AI 记忆卡片生成器 - 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你正在学习英语、准备考试，或者想快速掌握一个新领域的专业术语。你手头有一堆单词或概念，但把它们一个个做成记忆卡片（比如 Anki 卡片）非常耗时。这个网页就是你的“卡片制作助手”。

**适合的使用场景：**
- **语言学习者**：输入一批生词，快速生成带释义、例句和记忆技巧的卡片。
- **备考学生**：输入一个主题（如“机器学习”），让 AI 帮你提炼出核心概念并制成卡片。
- **知识整理者**：将零散的知识点（如历史事件、专业名词）快速结构化，便于复习。

**不适合的情况：**
- 你需要对已有卡片进行**精细编辑和批注**（它更适合批量生成，而非精细修改）。
- 你需要**完全离线**使用（它依赖网络和 AI 模型）。
- 你需要生成**图片、音频或多模态**的复杂卡片（它目前只生成纯文本）。

## 【二】使用方式（给第一次接触的人）

1.  **准备输入**：在左侧的文本框中，输入你想学习的单词、短语或一个主题。
    *   **示例1（单词列表）**：直接输入 `serendipity\nephemeral\npetrichor`（每行一个）。
    *   **示例2（主题指令）**：输入 `生成5个关于人工智能的高级词汇`。

2.  **首次配置**：点击页面右上角的“齿轮”图标，在弹出的设置窗口中，输入你的 **DeepSeek API Key**（你需要自行申请），然后点击“保存配置”。

3.  **生成卡片**：点击绿色的 **“生成卡片”** 按钮。稍等片刻，AI 就会为你制作好卡片。

4.  **浏览与学习**：
    *   右侧会显示第一张卡片，**正面**是单词或概念。
    *   **点击卡片**，它会翻转过来，显示**背面**的详细内容，包括释义、例句和记忆钩子。
    *   使用卡片上方的左右箭头按钮，可以**切换**到上一张或下一张卡片。

5.  **导出使用**：点击 **“导出 CSV”** 按钮，会下载一个文件。你可以将这个文件导入到 Anki 等记忆软件中，开始你的复习计划。

**容易忽略的细节：**
- **API Key 是必需的**：第一次使用或更换设备后，必须先在设置中配置 API Key，否则无法生成卡片。
- **输入格式灵活**：你可以混合输入单词和指令（如 `serendipity\n再生成3个关于音乐的词汇`），AI 会尝试理解。
- **卡片翻转有动画**：点击卡片后，等待翻转动画完成再点击箭头切换，体验更流畅。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，像一个高效的生产线：

1.  **输入与配置模块（左侧面板）**
    *   **职责**：接收用户的原始学习材料（输入框），并管理工具运行所需的“燃料”（API 配置）。
    *   **逻辑**：`用户输入文本` + `保存的API密钥` → 点击“生成”按钮 → 触发整个生成流程。

2.  **AI 处理引擎（隐藏的后台逻辑）**
    *   **职责**：这是网页的“大脑”。它不直接显示在界面上，但负责将用户的输入，按照预设的规则（Prompt），通过 API 请求 AI 模型，并解析返回的结果。
    *   **逻辑**：`用户输入` → 被包装成 `API 请求`（包含系统指令和用户输入）→ 发送给 `DeepSeek` → 接收 `JSON 格式的回复` → 解析并存储为卡片数据。

3.  **输出与交互模块（右侧预览区）**
    *   **职责**：将 AI 生成的结果，以美观、可交互的“记忆卡片”形式展示出来，并提供导航和导出功能。
    *   **逻辑**：`解析后的卡片数据` → 用“翻转卡片”的UI组件展示 → 用户点击（交互）→ 显示背面详情 → 用户导出（输出为文件）。

**最值得学习的设计：**
**“翻转卡片”的交互与数据展示的紧密结合。** 它不仅仅是一个炫酷的动画。`front`（正面）和 `back_def`、`back_example`、`back_hook`（背面）这三部分数据，被完美地映射到了卡片的两个物理面上。这种设计让“学习-测试”的闭环体验非常直观，是前端将数据模型与UI视图优雅结合的典范。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个页面中，**Prompt（系统指令）扮演着“产品经理”和“质量控制员”的双重角色**。它不直接生成答案，而是严格规定了AI生成答案的格式和内容标准。

1.  **解决什么问题**：它主要解决“**生成问题**”中的“**格式化问题**”。即确保AI输出的不是一段随意的文字，而是结构规整、可直接被程序使用的数据（JSON数组）。

2.  **关键变量**：
    *   **角色设定**：`你是一个辅助学习专家`。这给了AI一个基本的上下文和语气。
    *   **任务描述**：`为每个知识点生成一张记忆卡片`。明确了核心任务。
    *   **输出格式**：**这是最关键的**。它明确要求返回一个JSON数组，并详细定义了每个对象必须包含 `front`， `back_def`， `back_example`， `back_hook` 这四个字段及其含义。

3.  **只改 Prompt 的后果**：
    *   如果你想生成**选择题卡片**，可以修改Prompt，要求输出 `question`， `options`， `answer` 等字段。
    *   如果你想增加**词性标注**，可以在 `back_def` 旁边增加一个 `part_of_speech` 字段。
    *   **注意**：只改Prompt后，前端的展示逻辑（卡片正反面）不会自动适应新字段，你需要同步修改【输出与交互模块】的代码来展示新内容。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“三步替换法”，风险最低，成功率最高：

**第一步：替换核心场景与数据字段（最安全）**
保持网页的整体布局和交互（左输入右输出）完全不变。只修改：
*   **标题和描述**：比如改成“**AI 面试题生成器**”。
*   **输入框提示语**：从“输入单词...”改为“输入职位名称，如：前端开发、数据分析...”。
*   **Prompt 中的字段**：将 `front` 改为 `question`（问题），`back_def` 改为 `standard_answer`（标准答案），`back_example` 改为 `key_points`（考察要点），`back_hook` 改为 `related_questions`（关联问题）。

**第二步：调整输出展示界面**
根据第一步的新字段，修改右侧卡片预览的UI。
*   卡片正面显示 `question`。
*   卡片背面分为“标准答案”、“考察要点”、“关联问题”三个区块来展示。

**第三步：更换或扩展功能**
在核心功能跑通后，可以尝试：
*   **更换模型**：在API配置中，增加OpenAI GPT或国内其他模型的选项。
*   **增加输入选项**：在输入框旁增加一个下拉菜单，让用户选择卡片的难度（初级/高级）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“编辑”功能**：在卡片预览区域增加一个“编辑”图标。点击后，可以将当前卡片的正面、背面内容填充回左侧输入框（或一个新的编辑区域），允许用户微调后再重新生成或单独保存。这解决了“AI生成不完美，需要人工润色”的痛点。

2.  **实现“批量导出图片”**：利用 `html2canvas` 等库，将每张精美的翻转卡片渲染成图片，然后打包成ZIP下载。这样用户可以直接分享到社交媒体或打印出来，使用场景更广。

3.  **拆分为“生成”与“复习”两个页面**：
    *   **页面A（生成页）**：就是当前页面，负责生成和导出。
    *   **页面B（复习页）**：一个独立的页面，通过读取本地存储或URL参数来加载卡片数据，专注于全屏、无干扰的卡片翻转复习，甚至可以增加“标记为已掌握”的功能。

4.  **优化交互体验**：
    *   **键盘快捷键**：支持键盘左右键切换卡片，空格键翻转卡片，让学习流程更流畅。
    *   **生成历史**：在左侧面板下方增加一个区域，临时保存本次会话生成过的所有卡片列表，点击即可快速跳转预览，方便回顾。

5.  **接入文本转语音（TTS）**：为每个卡片的单词和例句增加一个“朗读”按钮。点击后调用浏览器的TTS API或第三方语音合成API进行发音，特别适合语言学习。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为精确的学术定义工具**：AI生成的释义和例句可能存在细微偏差或不完全准确，**不能替代权威词典或教科书**。它更适合辅助记忆和初步理解。
- **不适合处理极度专业化或小众的领域**：如果输入的术语非常冷门或领域极其专业，通用AI模型可能无法生成高质量的内容。
- **不适合需要复杂逻辑和推理的内容**：例如，生成数学证明步骤、法律条文分析等需要严格逻辑链的内容，它可能力不从心。
- **如果你想做的是**：一个需要实时协作、版本管理、支持多媒体嵌入的完整“记忆卡片系统”，那么你应该考虑使用 **Notion、Obsidian** 的插件，或直接开发一个更复杂的全栈应用。本网页的定位是“轻量、快速、一次性”的生成工具。
