# 书籍关系图生成器 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景**：
当你读完一本小说（如《三体》、《红楼梦》），或者需要快速梳理一本复杂书籍的人物关系、情节脉络时，这个工具能帮你一键生成清晰的可视化图表。它特别适合：
- **学生**：快速理解文学名著的人物关系，辅助阅读和复习。
- **读书会成员**：在讨论前，快速生成一张关系图作为讨论的视觉辅助。
- **内容创作者**：为书评、视频解说制作配套的示意图。

**不适合的情况**：
- 需要分析**非虚构类书籍**（如教科书、学术论文）的严谨逻辑结构时，此工具生成的关系图可能过于简化。
- 需要生成**精确到章节、页码**的详细情节时间线时。
- 当网络环境不佳或无法访问特定AI API时，核心功能将无法使用。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    *   唯一且核心的输入是**书名**。输入框位于页面中央，提示“例如：红楼梦、三体、百年孤独”。

2.  **用户通常会做哪几步操作？**
    *   **第一步：输入书名**。可以直接打字，也可以点击下方的“热门示例”按钮（如“红楼梦”）快速填充。
    *   **第二步：点击生成**。点击蓝色的“生成关系图”按钮。
    *   **第三步：查看与交互**。等待几秒后，页面中央会显示生成的关系图。你可以：
        *   **缩放与拖拽**：用鼠标滚轮缩放，按住拖拽移动图表。
        *   **查看源码**：点击“源码”按钮，查看生成图表背后的Mermaid代码。
        *   **导出**：点击“SVG”或“PNG”按钮，将图表保存为图片。
        *   **修改**：点击“对话修改”，用自然语言告诉AI如何调整图表（如“添加林黛玉和薛宝钗的姐妹关系”）。

3.  **输出结果长什么样？**
    *   输出是一个**可交互的流程图**。图中包含圆形或方形的节点（代表人物或概念），以及带有标签的连线（代表关系，如“父子”、“敌对”）。图表布局通常是自上而下（TD）或从左到右（LR）。

4.  **有哪些容易忽略的使用细节？**
    *   **首次使用需配置API**：点击页面右上角的齿轮图标⚙️，在设置面板中填入你自己的DeepSeek API Key和URL，否则无法生成图表。
    *   **版本历史**：点击左上角的时钟图标🕐，可以查看之前生成过的所有图表版本，并能一键切换回旧版本。
    *   **多版本兼容**：如果图表渲染失败，工具会自动尝试不同版本的Mermaid图表库，并在图表左上角显示当前使用的版本号。
    *   **全屏查看**：生成图表后，“全屏”按钮会亮起，点击后可沉浸式查看大图。

## 【三】核心结构拆解（学习重点）

这个页面由五个清晰独立的模块组成，像流水线一样协作：

1.  **输入与配置模块**
    *   **职责**：接收用户指令（书名）和系统配置（API信息）。
    *   **包含**：书名输入框、示例按钮、设置面板（API URL、Key、模型选择）。
    *   **逻辑**：用户输入 → 被`buildPrompt`函数包装 → 准备发送给AI。

2.  **AI处理模块**
    *   **职责**：作为“大脑”，将书名理解并转化为结构化的图表描述语言。
    *   **核心函数**：`fetchMermaidCode`。它调用AI API，发送精心设计的Prompt，并接收返回的Mermaid代码。
    *   **关键设计**：`sanitizeMermaidCode`函数。它像一个“代码清洁工”，修复AI返回代码中可能存在的语法问题（如错误引号），确保下一步能顺利渲染。

3.  **图表渲染与兼容模块**
    *   **职责**：将Mermaid代码变成可视化的SVG图形，并确保在不同环境下都能显示。
    *   **核心函数**：`renderMermaid`。
    *   **关键设计**：
        *   **多版本回退机制**：在`loadMermaidVersion`函数中预定义了多个Mermaid库的CDN地址。如果最新版渲染失败，会自动降级尝试旧版本，极大提高了工具的鲁棒性。
        *   **交互增强**：使用`svgPanZoom`库为生成的SVG图表添加了缩放、拖拽功能。

4.  **输出与交互模块**
    *   **职责**：向用户展示结果，并提供丰富的后续操作。
    *   **包含**：图表展示区、缩放控制按钮、导出按钮（SVG/PNG）、源码查看/复制、对话修改入口。
    *   **逻辑**：渲染成功的SVG → 提供给用户交互和导出。

5.  **状态与历史管理模块**
    *   **职责**：记住用户的操作历史，提升体验。
    *   **核心**：`versionHistory`数组和`saveVersion`函数。每次成功生成图表，都会将书名、代码、时间戳保存到`localStorage`和内存中。
    *   **价值**：实现了“撤销/重做”和“多版本比对”的雏形，是复杂应用的基础。

**最值得学习的设计**：
**“AI生成 + 本地渲染 + 优雅降级”的混合架构**。它没有将可视化完全交给AI（那样慢且不可控），也没有完全本地处理（那样不智能）。而是让AI做擅长的“结构化理解与描述”，让专业的图形库（Mermaid）做擅长的“可靠渲染”，并通过版本回退机制解决了外部依赖的稳定性问题。这是一个非常实用且可复用的前端AI应用模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt扮演的角色**：它是**翻译官**和**约束者**。它的任务是把用户模糊的“书名”翻译成精确的、机器可执行的“Mermaid图表描述代码”，同时用严格的规则约束AI的输出格式，防止它天马行空。

2.  **解决的是“生成问题”**：Prompt主要解决的是“根据需求生成特定格式代码”的问题。它不需要AI去“理解”图表本身，而是要求AI按照固定格式“输出”图表代码。

3.  **Prompt中的关键变量**：
    *   **核心变量**：`${bookTitle}`，即用户输入的书名，是Prompt动态变化的部分。
    *   **格式约束**：明确要求使用`graph TD`或`graph LR`。这是Mermaid的语法声明。
    *   **语法规则**：如“节点ID只用英文字母和数字”、“连线标签用 `|标签文字|` 格式”。这些是防止AI生成错误代码的关键。
    *   **输出格式**：严格要求用“```mermaid”和“```”包裹代码。这是为了后续能**自动提取**代码块，无需手动解析混乱的文本。

4.  **如果只改Prompt，不改代码，会发生什么？**
    *   **改变图表类型**：如果把Prompt中的`graph TD`（自上而下）改为`sequenceDiagram`（时序图），那么生成的将是书籍情节的时序图，而非人物关系图。页面渲染逻辑会自动适应。
    *   **改变内容侧重点**：如果Prompt要求“生成以家族斗争为主线的关系图”，那么AI会过滤掉非家族的人物，图表主题会发生变化。
    *   **改变样式**：如果Prompt增加“使用红色边框表示反派人物”，AI可能会在代码中添加样式定义，图表外观会改变。
    *   **风险**：如果新Prompt要求的语法超出了当前`sanitizeMermaidCode`函数的清理范围，或Mermaid库不支持，可能导致渲染失败。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于自己的AI可视化工具：

**第一步：替换核心主题与输入（最安全）**
*   **目标**：做一个“电影角色关系图生成器”。
*   **操作**：
    1.  将网页标题、提示语中的“书籍”全部改为“电影”。
    2.  将输入框的`placeholder`从“红楼梦、三体”改为“盗梦空间、复仇者联盟”。
    3.  修改`buildPrompt`函数中的提示语，将“根据书名...”改为“根据电影名...”。
*   **效果**：你现在已经拥有了一个能生成电影角色关系图的工具，其他所有功能（渲染、导出、历史）都正常工作。

**第二步：调整Prompt以改变输出结构**
*   **目标**：让工具生成“剧情时间线图”而非“人物关系图”。
*   **操作**：
    1.  深入研究Mermaid语法，找到适合做时间线的图表类型，如`gantt`（甘特图）或`timeline`。
    2.  重写`buildPrompt`函数，要求AI“生成一个按时间顺序排列的剧情关键事件甘特图”，并提供`gantt`语法的示例规则。
    3.  可能需要微调`sanitizeMermaidCode`函数，以处理新语法。
*   **效果**：输入电影名，输出的不再是网状关系图，而是一条纵向的时间轴。

**第三步：改变交互与展示形式**
*   **目标**：让图表在生成后可以点击节点查看详情。
*   **操作**：
    1.  研究Mermaid的`click`事件回调。
    2.  在`renderMermaid`函数成功渲染后，为SVG中的特定节点（如`<g>`标签）绑定点击事件。
    3.  点击事件可以弹出一个侧边栏，显示从AI响应中额外提取的该人物的简介（这可能需要修改Prompt让AI同时返回结构化数据）。
*   **效果**：你的工具从“静态图表”升级为“可交互的信息图”。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，让图表更精准**：
    *   **操作**：在书名输入框下增加一个“图表重点”下拉选择框，选项如：“人物关系”、“概念脉络”、“情节发展”、“权力结构”。
    *   **修改**：将选中的值作为变量传入`buildPrompt`，例如：“请重点生成关于`${focus}`的图表...”。
    *   **效果**：用户可控制AI生成图表的侧重点，实用性大增。

2.  **更换或扩展AI模型后端**：
    *   **操作**：在设置面板的“模型选择”下拉框中，增加其他支持的模型，如`gpt-3.5-turbo`、`claude-3-haiku`。同时修改`getApiConfig`函数和API请求格式，以兼容OpenAI或Anthropic的API接口。
    *   **效果**：用户可以根据成本、速度、效果选择不同的AI引擎，工具适应性更强。

3.  **将单页应用拆分为“生成”与“画廊”两个页面**：
    *   **操作**：
        *   新建一个`gallery.html`页面。
        *   将主页面中的“版本历史”功能强化并迁移到此页面，用于展示所有保存过的图表缩略图。
        *   在主页面生成图表后，增加“保存到画廊”按钮。
        *   使用`indexedDB`替代`localStorage`来存储更大量的图表数据。
    *   **效果**：应用结构更清晰，“画廊”页面适合分享和回顾自己的作品集。

4.  **优化PNG导出体验**：
    *   **操作**：当前PNG导出有时会丢失样式。可以改造`exportPngBtn`的点击事件，在导出前弹出一个预览模态框，让用户自定义导出尺寸、背景色，并实时预览效果，确认后再下载。
    *   **效果**：提供所见即所得的导出功能，避免用户下载不满意的图片。

5.  **添加“智能推荐”功能**：
    *   **操作**：在用户输入书名时，利用AI API的快速完成功能（如`/completions`端点），实时推荐相关的书籍或人物名称。
    *   **修改**：为书名输入框绑定`oninput`事件，去抖后调用一个轻量级AI接口，获取推荐词列表并显示在下拉框中。
    *   **效果**：提升输入体验，帮助用户发现关联内容。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做精确的知识图谱**：它生成的关系基于AI对书籍内容的概括和理解，可能存在错误、遗漏或简化。**不能**作为学术引用或精确的事实依据。如果需要构建严谨的知识图谱，应使用专门的工具（如Neo4j、Protégé）并人工录入和校验数据。
2.  **不适合处理超长或极度复杂的文本**：Prompt有长度限制，AI的上下文窗口也有限。它无法处理整本书的原文输入。如果想分析具体段落，应该使用具备“长文本阅读”功能的AI工具（如Kimi Chat、DeepSeek-R1），并将分析结果手动整理。
3.  **不适合作为稳定的生产环境工具**：其核心依赖（特定AI API的可用性、免费额度、Mermaid CDN）可能发生变化。**不要**将其用于需要7x24小时稳定运行的商业场景或关键任务中。对于此类需求，应自行部署后端服务，并缓存AI响应。
4.  **不适合无网络环境使用**：所有图表生成都依赖网络API调用。在没有互联网的环境下，它仅能查看之前生成并缓存在本地的历史版本。如需离线使用，需考虑集成本地大模型（如通过WebLLM），但这对前端性能要求极高。
