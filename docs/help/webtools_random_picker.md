# Webtools 工具箱 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人效率工具箱**，它解决了日常工作和学习中需要频繁切换不同工具的问题。

**使用场景举例：**
- 你正在写作业，需要计算一个复杂的公式，但又不想打开计算器应用
- 你准备开始学习，想用番茄钟来管理专注时间
- 你临时需要记录一些想法，但不想打开专门的笔记软件
- 你想快速统计本月花了多少钱，做个简单记账
- 你需要转换单位（比如公里到英里），但记不住换算公式

**适合的情况：**
- 快速、轻量的日常计算和记录需求
- 不需要专业软件功能的简单任务
- 希望所有常用小工具集中在一个页面
- 临时性的数据处理需求

**不适合的情况：**
- 需要专业数据分析或复杂图表
- 需要长期、系统性的数据管理
- 需要团队协作或多用户共享
- 需要离线保存大量历史数据

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 根据你选择的工具类型，输入框会变化：
  - 公式计算器：输入数字参数
  - 计时器/番茄钟：设置分钟数
  - 清单工具：输入待办事项
  - 记账工具：输入金额、分类、备注
  - 转换器：输入数值和选择单位

**用户通常会做哪几步操作？**
1. 从左侧导航栏选择需要的工具类型
2. 在对应的输入区域填写或选择参数
3. 点击操作按钮（如“计算结果”、“开始”、“添加”等）
4. 查看输出结果或状态变化

**输出结果长什么样？**
- 计算结果会显示在卡片中，有清晰的标签和数值
- 计时器会显示倒计时
- 清单会以列表形式展示，可勾选完成
- 记账会显示累计金额和记录列表

**有哪些容易忽略的使用细节？**
1. **自动保存**：笔记工具在你输入时会自动保存（有400ms延迟）
2. **键盘快捷键**：在清单工具中，输入后按回车可直接添加
3. **数据持久化**：大部分工具的数据会保存在浏览器本地
4. **响应式设计**：在手机上也能够正常使用，布局会自动调整

## 【三】核心结构拆解（学习重点）

这个页面采用了**模块化工具容器**的设计思路：

**关键模块组成：**
1. **工具选择器**（隐含在导航中）- 决定显示哪个工具界面
2. **工具配置区** - 根据工具类型动态显示不同的输入字段
3. **操作控制区** - 提供工具特定的操作按钮
4. **结果显示区** - 展示计算结果或当前状态
5. **设置面板** - 配置API等全局设置

**每个模块的职责：**
- **工具选择器**：管理当前激活的工具类型
- **工具配置区**：收集用户输入，验证数据格式
- **操作控制区**：触发计算、计时、添加等核心功能
- **结果显示区**：格式化并展示处理结果
- **设置面板**：管理外部服务配置

**输入 → 处理 → 输出 的逻辑链路：**
```
用户选择工具类型 → 显示对应界面 → 用户输入数据 → 
点击操作按钮 → 调用对应处理函数 → 更新结果展示 → 
（可选）保存到本地存储
```

**最值得学习的设计：**
**条件渲染的界面系统** - 通过 `x-show="tool.type === 'xxx'"` 实现了一套界面、多套逻辑。这是构建多功能应用的高效方式，避免了为每个功能创建独立页面。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个页面中，**Prompt 主要用于配置外部AI服务**（如DeepSeek）：

**Prompt 扮演的角色：**
- 定义AI模型的行为指令
- 设置生成内容的格式要求
- 包含用户输入的变量参数

**解决的是"生成问题"还是"理解问题"？**
主要是**生成问题** - 当工具需要AI辅助时（如文本处理、内容生成），Prompt会指导AI如何根据用户输入生成合适的输出。

**Prompt 中的关键变量：**
1. **用户输入数据**（来自工具配置区）
2. **工具类型上下文**（告诉AI现在是什么工具）
3. **输出格式要求**（如JSON、纯文本、列表等）
4. **角色设定**（如“你是一个数学助手”、“你是一个文案编辑”）

**如果只改 Prompt，不改代码，会发生什么变化？**
- AI生成的内容风格会改变
- 输出的格式和结构可能不同
- 处理相同输入可能得到完全不同的结果
- 但界面交互和基本功能保持不变

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）：**

**第一步：保持结构不变，替换使用场景**
- 将“公式计算器”改为“BMI计算器”
- 将“记账工具”改为“运动记录工具”
- 保持相同的HTML结构和CSS类名，只修改标签文字

**第二步：调整输入字段或 Prompt**
- 在现有工具类型基础上增加/减少输入字段
- 修改字段的验证规则（如最小值、最大值）
- 调整AI工具的Prompt指令，改变生成逻辑

**第三步：改变输出形式或展示方式**
- 将简单的数字显示改为进度条
- 为清单工具增加分类标签
- 为计时器添加声音提醒

**最安全的下手点：**
从**清单工具**开始模仿最安全，因为它逻辑简单，只有添加、删除、勾选三个基本操作，数据存储也相对直接。

## 【六】3–5 个可直接尝试的改造方向

1. **增加数据可视化**
   - 为记账工具添加月度支出饼图
   - 为计数器添加进度条显示
   - 使用Chart.js或简单的CSS动画实现

2. **添加分享功能**
   - 为每个工具结果生成分享链接
   - 支持将清单导出为文本或图片
   - 使用Web Share API或生成二维码

3. **实现工具联动**
   - 番茄钟结束后自动启动休息计时
   - 记账时可以从预设分类中选择
   - 笔记内容可快速转换为清单项

4. **增强本地存储**
   - 为每个工具添加数据备份/恢复
   - 支持导出为CSV或JSON文件
   - 添加数据清理和归档功能

5. **优化移动端体验**
   - 为常用操作添加手势支持
   - 优化小屏幕下的布局
   - 添加PWA支持，可安装为应用

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不适合复杂数据处理**
   - 如果需要处理Excel表格或大量数据
   - **应该使用**：Google Sheets、Excel、专业数据库软件

2. **不适合团队协作**
   - 所有数据都保存在本地浏览器
   - 无法多人同时编辑或查看
   - **应该使用**：Notion、Trello、飞书文档等协作工具

3. **不适合专业领域计算**
   - 工程计算、金融建模、统计分析等
   - **应该使用**：MATLAB、Python、专业计算软件

4. **不适合长期项目管理**
   - 没有版本控制、没有复杂任务依赖
   - **应该使用**：Jira、Asana、ClickUp等项目管理工具

5. **不适合敏感数据存储**
   - 没有加密、没有云备份、容易丢失
   - **应该使用**：密码管理器、加密笔记应用

**记住：** 这个工具箱的定位是**快速解决日常小问题**，而不是替代专业软件。它的价值在于便捷性和集成度，而不是功能的深度和广度。
