# 极简待办 - 学习与模仿指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正在电脑前工作或学习，脑子里突然蹦出几个需要完成的事情：“回复客户邮件”、“买牛奶”、“完成项目报告”。你不想打开一个复杂的软件，也不想被多余的功能干扰。这个网页就像一个**数字便利贴墙**，让你能快速记下这些想法，并给它们贴上“工作”、“生活”等标签和优先级。它适合在你需要**快速捕捉、轻量管理日常任务**时使用。

**适合情况：**
- 个人日常事务的快速记录与追踪。
- 需要区分任务类别（工作/生活/学习）和紧急程度。
- 希望有一个干净、无广告、不联网也能用的工具。
- 想从简单的“清单”和直观的“看板”两种视角查看任务。

**不适合情况：**
- 需要团队协作、分配任务给他人。
- 需要设置精确的提醒、日历或重复任务。
- 任务非常复杂，需要子任务、附件或详细描述。
- 需要强大的数据分析或长期项目规划。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **任务内容**：一个文本框，让你写下要做什么。
2.  **任务分类**：一个下拉菜单，可以选择“收件箱”、“工作”、“生活”、“学习”。
3.  **优先级**：另一个下拉菜单，可以选择“低”、“中”、“高”。

**用户通常会做哪几步操作？**
1.  **添加任务**：在顶部的输入框里写下任务（比如“写周报”），选好分类和优先级，然后按回车键或点击“+”按钮。
2.  **查看与管理**：
    - **列表视图**：默认视图。所有任务按添加顺序（未完成的在前）排列。你可以点击任务前的圆圈标记为“完成”，任务会变成灰色并加上删除线。鼠标悬停在任务上，右侧会出现垃圾桶图标用于删除。
    - **看板视图**：点击右上角的看板图标切换。任务会分成三列：“待办”、“高优先级（待办）”、“已完成”，让你一目了然。
3.  **查看统计**：页面中间有四个数据卡片，实时显示总任务数、待完成数、已完成数和完成率。

**输出结果长什么样？**
- 任务会以美观的卡片形式出现在下方区域。
- 每个任务卡片都显示你输入的内容、分类标签（如“工作”）、优先级标签（如“高”，并有不同颜色）和创建日期。
- 看板视图下，任务会被自动分组，高优先级任务会有醒目的左侧边框。

**有哪些容易忽略的使用细节？**
- **键盘快捷键**：在输入框里直接按 **回车（Enter）** 就能快速添加任务，比用鼠标点按钮更快。
- **数据自动保存**：你添加或修改的所有任务都会自动保存在你浏览器的本地存储中。即使关闭页面或浏览器，下次打开数据还在。
- **视图切换**：右上角有两个小图标，分别对应“列表”和“看板”视图，这是切换不同展示方式的关键。
- **删除的隐藏按钮**：在列表视图中，**只有把鼠标移到任务卡片上**，右侧才会出现删除按钮。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为五个模块，像搭积木一样组合在一起：

1.  **控制与输入模块（顶部）**
    - **职责**：接收用户创建新任务的所有指令。
    - **包含**：任务文本输入框、分类选择器、优先级选择器、添加按钮。
    - **逻辑**：用户填写信息 → 点击添加或按回车 → 信息被包装成一个“任务对象” → 加入到任务数组中。

2.  **数据统计模块（中部）**
    - **职责**：实时反馈任务管理的整体状况，提供成就感。
    - **包含**：四个数据卡片（总计、待办、完成、完成率）。
    - **逻辑**：每当任务数组发生变化 → 计算属性（如 `pendingCount`）自动重新计算 → 数据卡片显示更新。

3.  **任务展示模块 - 列表视图（下部）**
    - **职责**：以传统清单形式，清晰展示所有任务的详情和状态。
    - **包含**：循环渲染的每个任务卡片，包含完成复选框、文本、标签、日期和删除按钮。
    - **逻辑**：从任务数组中取出数据 → 按“未完成优先、新任务在前”排序 → 为每个数据生成一个HTML卡片。

4.  **任务展示模块 - 看板视图（下部）**
    - **职责**：以可视化面板形式，按任务状态（待办/高优/完成）进行分组，聚焦工作流。
    - **包含**：三个垂直列，每列展示过滤后的特定任务组。
    - **逻辑**：根据 `view` 变量切换显示 → 使用计算属性（如 `highPriorityTasks`）过滤出对应任务 → 在不同的列中渲染。

5.  **数据管理与逻辑模块（JavaScript 部分）**
    - **职责**：这是整个应用的大脑。负责维护任务数据、定义所有操作（增删改查）、处理业务逻辑（排序、过滤、统计）、以及与本地存储交互。
    - **核心**：`todoApp()` 函数返回的对象，包含了所有数据（`tasks`, `view`）和方法（`addTask`, `toggleComplete`）。

**输入 → 处理 → 输出 的逻辑链路：**
1.  **输入**：用户在输入模块填写信息并提交。
2.  **处理**：`addTask()` 方法被触发，创建一个新的任务对象（带ID、时间戳等），并推入 `tasks` 数组。
3.  **响应**：
    - 数据层：`tasks` 数组变化触发 `$watch`，自动保存到 `localStorage`。
    - 视图层：所有依赖 `tasks` 的计算属性（如 `sortedTasks`, `pendingCount`）自动更新。
    - UI层：Alpine.js 侦听到数据变化，自动重新渲染列表中受影响的部分，统计数字也立即更新。

**最值得学习的设计：**
**“响应式数据驱动UI”的极简实现。** 整个应用的状态（所有任务）被集中保存在 `tasks` 数组中。UI只是这个状态的一个“映射”或“视图”。当状态改变（增删改），所有依赖这个状态的UI部分（列表、看板、统计）都会**自动、同步地更新**，无需手动操作DOM。这是现代前端框架（如Vue, React）的核心思想，而这个页面用非常轻量的 Alpine.js 清晰地演示了这一点。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **请注意**：当前提供的这个“极简待办”网页**没有使用任何AI或Prompt**。它是一个纯前端、基于规则的应用。所有逻辑（如分类、优先级、过滤）都是通过开发者预先写好的JavaScript代码来处理的。
>
> 但我们可以借此机会思考，**如果**要引入AI，可以如何设计：

**假设的AI增强场景：**
我们可以增加一个“AI智能解析”按钮。用户输入一段自然语言，如“明天下午三点前要完成给张三的报价单，这个很重要”，AI帮我们自动提取出任务、分类、优先级和截止日期。

**在这种假设下：**
- **Prompt扮演的角色**：是给AI模型的指令，告诉它如何从用户的自然语言中提取结构化信息。
- **它解决的是“理解问题”**：将用户模糊、随意的输入，转化为程序可以处理的明确字段（文本、分类、优先级、日期）。
- **Prompt中的关键变量**：用户的原始输入文本。
- **如果只改Prompt**：例如，将Prompt从“提取任务信息”改为“同时评估任务所需时间”，那么AI的输出会多出一个“预估耗时”字段，但网页界面因为代码没改，无法显示这个新字段。这说明了**Prompt与代码逻辑需要匹配**。

**当前页面的启示**：在引入AI之前，必须先搭建好一个稳固的、结构化的数据模型（就像本应用中的 `task` 对象：`id, text, category, priority, completed, createdAt`）。AI的作用是更好地填充这个模型，而不是取代它。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个安全的路径，一步步创造出属于你的工具：

**第一步：替换核心概念与数据模型（最安全）**
- **保持HTML结构和CSS样式几乎不变**。
- **改变 `tasks` 对象的结构**：比如，你想做一个“个人电影收藏夹”。那么任务（`task`）就变成电影（`movie`）。字段可以改为：`title`（片名）、`genre`（类型，替代category）、`rating`（评分，替代priority）、`watched`（是否看过，替代completed）、`poster`（海报链接）。
- **相应地**，修改输入模块的下拉选项（类型改成“科幻”、“喜剧”等，评分改成“1-5星”）。

**第二步：调整视图与展示逻辑**
- **修改计算属性**：`pendingTasks` 可以改成 `unwatchedMovies`（未看电影），`completedTasks` 改成 `watchedMovies`（已看电影）。
- **修改看板视图的分组逻辑**：三列可以改为“想看”、“已看”、“最高评分”。
- **更新统计模块的文字**：“总任务”变成“总收藏”，“完成率”变成“观影率”。

**第三步：改变外观与交互细节**
- 修改 `tailwind.config.js` 或内联样式，更换主题颜色（比如从靛蓝色 `indigo` 换成深青色 `teal`）。
- 为电影卡片添加点击事件，跳转到豆瓣或IMDb链接。
- 将删除按钮的功能改为“从收藏夹移除”。

通过以上三步，你已经用相同的技术骨架，构建了一个全新的应用。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加任务详情与备注**：
    - **操作**：在 `task` 对象中增加一个 `notes`（字符串）字段。在任务卡片上添加一个“编辑”或“展开”图标，点击后可以显示/编辑一个多行文本框来记录更多细节。
    - **价值**：让工具从记录“做什么”延伸到记录“怎么做”。

2.  **引入简单的AI分类与排期**：
    - **操作**：集成一个轻量级AI API（如OpenAI或国内大模型）。在输入框旁添加“AI解析”按钮。用户输入“下周要和团队讨论项目预算”，点击后，AI自动将分类设为“工作”，优先级设为“中”，并尝试在 `createdAt` 旁生成一个 `dueDate`（截止日期）字段。
    - **价值**：大幅提升输入效率，展示AI如何与传统应用结合。

3.  **实现真正的看板拖拽功能**：
    - **操作**：使用一个轻量拖拽库（如 `@shopify/draggable`）。允许用户在看板视图的“待办”、“进行中”、“已完成”三列之间直接拖拽任务卡片来改变状态（需要为 `task` 增加 `status` 字段来替代简单的 `completed` 布尔值）。
    - **价值**：交互更直观，符合现代项目管理工具的使用习惯。

4.  **增加数据过滤与搜索**：
    - **操作**：在统计模块下方增加一个搜索框和一个过滤按钮组（按分类、优先级筛选）。添加一个 `searchQuery` 数据属性和一个 `filteredTasks` 计算属性。
    - **价值**：当任务数量增多时，帮助用户快速定位。

5.  **美化与增强空状态**：
    - **操作**：当前空状态比较简单。可以设计更精美的插画，并添加一些引导性文案或示例任务，比如“尝试添加‘每天喝8杯水’作为你的第一个健康任务”。
    - **价值**：提升新用户的首次使用体验和产品的整体质感。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合团队协作**：所有数据都保存在**你的个人浏览器**里。你无法分享任务列表给同事，也无法看到别人分配给你的任务。如果需要协作，应该使用像Trello、Asana、飞书任务或腾讯文档这样的在线协作工具。

2.  **不适合做复杂项目规划**：它缺乏任务依赖关系（A任务完成才能做B）、甘特图、里程碑、文件附件等功能。管理大型项目请使用专业的项目管理软件，如Microsoft Project、Jira或国产的Tapd、Teambition。

3.  **不适合做严格的时间管理**：它没有日历视图、没有闹钟提醒、不能设置精确到分钟的开始/结束时间。如果你需要严格的时间规划和提醒，应该使用日历类应用（如Google Calendar、Outlook）或专注番茄钟应用（如Forest、潮汐）。

4.  **数据有丢失风险**：虽然用了本地存储，但如果**你清除了浏览器缓存数据**，或者换了一台电脑、一个浏览器，所有任务都会消失。它不是一个可靠的数据永久备份方案。重要事务请务必在别处留有记录。

**总结**：这个网页是一个优秀的**个人生产力辅助工具**，它的优势在于**快速、轻便、专注**。理解它的边界，你就能在正确的场景下最大化地利用它，也能更清楚地知道何时该寻求更强大的工具。
