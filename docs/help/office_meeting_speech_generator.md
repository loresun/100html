# 会议临时发言稿生成器 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景**：
想象一下，你正在参加一个线上或线下会议，突然被领导点名：“小张，你对这个问题有什么看法？” 你毫无准备，大脑一片空白。或者，你虽然有一些想法，但不知道如何组织成一段清晰、有说服力的发言。这个网页就是你的“会议急救包”。

**适合什么情况？**
- **临时被点名发言**：需要快速组织语言，避免冷场。
- **准备不充分的会议**：对议题有大致了解，但没时间准备详细讲稿。
- **需要多角度观点**：想看看同一个话题，用“保守”、“中立”、“创新”等不同风格怎么说。
- **职场新人或非母语者**：希望获得符合职场规范的语言模板。

**不适合什么情况？**
- **需要高度专业或技术细节的发言**（如学术报告、代码评审）。
- **涉及敏感信息或需要严格保密的内部讨论**。
- **即兴辩论或深度互动讨论**（它生成的是单向陈述稿）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要填写几个关键信息：
1.  **会议主题**：这次会议主要讨论什么？（必填）
2.  **我的角色/部门**：你在会议中是什么身份？（必填）
3.  **核心观点**：你大概想说什么？（可选，不填AI会帮你构思）
4.  **发言类型**：是工作汇报、头脑风暴还是复盘总结？
5.  **发言时长**：你需要讲1分钟、2分钟还是更久？

**用户通常会做哪几步操作？**
1.  **配置**：首次使用，点击右上角“设置”，填入你的DeepSeek API Key（需要一个免费账户）。
2.  **填写**：在左侧区域依次填写会议主题、你的角色等信息。
3.  **生成**：点击底部大大的“一键生成发言稿”按钮。
4.  **选择与复制**：在右侧会看到3个不同风格的发言稿，浏览后，点击你喜欢的版本下方的“复制”按钮。
5.  **使用**：将复制的内容粘贴到你的会议笔记或直接参考发言。

**输出结果长什么样？**
右侧会并列显示3个“卡片”，例如：
-   **🛡️ 保守稳妥版**：语气正式，结构严谨，适合向上级汇报。
-   **⚖️ 中立客观版**：用数据和事实说话，体现专业性。
-   **🚀 大胆创新版**：提出新想法，更有冲击力。
每个卡片都包含完整的发言稿（用Markdown格式排版，有标题、列表，清晰易读），并预估了发言时间和字数。

**有哪些容易忽略的使用细节？**
1.  **“核心观点”是可选的**：如果你没想法，留空反而能让AI自由发挥，有时会有惊喜。
2.  **“深度分析过程”**：如果选择了“DeepSeek R1”模型，生成结果上方会有一个可展开的区域，展示AI的思考过程，这对学习如何结构化思考很有帮助。
3.  **复制有反馈**：点击“复制”后，对应的卡片边框会短暂变成高亮色（琥珀色），提示你复制成功。
4.  **配置是全局保存的**：设置好API Key后，刷新页面也不会丢失。

## 【三】核心结构拆解（学习重点）

这个页面采用了清晰的 **“输入-处理-输出”** 左中右布局，是典型的生产力工具设计。

**关键模块与职责：**
1.  **配置管理模块**（右上角设置）：
    -   **职责**：管理API密钥和AI模型选择，是应用运行的“钥匙”。
    -   **设计亮点**：将技术配置与核心功能界面分离，通过弹窗管理，保持主界面清爽。

2.  **输入表单模块**（左侧区域）：
    -   **职责**：收集用户的所有个性化需求。每个输入项（主题、角色、观点、类型、时长）都对应最终发言稿的一个生成维度。
    -   **设计亮点**：使用卡片式设计区分不同输入项，视觉层次清晰。“发言类型”和“发言时长”使用按钮式单选，比下拉菜单更直观、操作更快。

3.  **AI引擎模块**（核心逻辑，不可见）：
    -   **职责**：将表单数据组装成给AI的“指令”（Prompt），调用API，并处理返回的流式数据。
    -   **设计亮点**：它处理了最复杂的部分——与AI的通信、错误处理、以及将非结构化的AI回复解析成结构化的数据（JSON）。

4.  **结果展示模块**（右侧区域）：
    -   **职责**：将AI生成的结构化数据（3个发言稿）美观地呈现出来，并提供“复制”这一核心操作。
    -   **设计亮点**：采用“版本对比”设计，让用户一目了然地进行选择。每个版本都有图标、标题、描述、亮点标签和元数据（字数、时间），决策信息丰富。

**逻辑链路：**
`用户填写表单` → `点击生成按钮` → `前端将表单数据 + 预设模板 组合成完整的Prompt` → `调用DeepSeek API` → `接收AI返回的JSON格式数据` → `前端解析JSON，渲染出3个发言稿卡片` → `用户查看并复制`。

**最值得学习的设计：**
**“结构化输出”的强制约束**。网页没有让AI自由发挥写一段话，而是通过精心设计的Prompt，要求AI必须以指定的JSON格式返回数据，并且每个发言稿都要包含`title`, `desc`, `content`等字段。这保证了前端能稳定地解析和渲染，用户体验一致且可靠。这是将AI能力“产品化”的关键一步。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt扮演的角色**：
它是连接“用户原始需求”和“AI能力”的**翻译官和指挥官**。它把散乱的表单信息，翻译成AI能理解的具体任务，并严格指挥AI按照既定格式输出。

**解决的是“生成问题”**：
它主要解决“根据条件生成内容”的问题。系统Prompt里已经包含了如何写发言稿的专家知识（结构、注意事项），用户输入只是提供了本次生成的具体参数。

**Prompt中的关键变量**：
1.  **用户变量**：`${form.meetingTopic}`, `${form.myRole}`, `${form.coreIdeas}`, `${form.speechType}`, `${form.duration}`。这些是每次生成都会变化的动态部分。
2.  **任务指令常量**：要求生成3种风格、必须用JSON格式输出、发言稿必须包含的四个部分（开场、观点、论据、总结）。这些是固定不变的规则。
3.  **格式模板常量**：提供的JSON示例结构。这是给AI看的“填空题”标准答案格式。

**如果只改Prompt，不改代码，会发生什么？**
整个应用的行为会发生根本性改变。例如：
-   把生成“3种风格”改成生成“1个详细版和1个精简版”，输出结果立刻变化。
-   在Prompt里增加“请使用比喻手法”，发言稿的文风会改变。
-   修改JSON结构中的字段名（如把`title`改成`name`），前端代码会因为解析不到数据而显示异常。
**Prompt是驱动这个应用的“软件”**，而HTML/JS代码只是承载它的“硬件”。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个“换肤-换核-升级”的路径，安全地创建你的版本：

**第一步：保持结构不变，替换使用场景（最安全）**
-   **目标**：做一个功能相同但用途不同的工具。
-   **操作**：
    1.  修改网页标题和导航栏文字，例如改成“**小红书爆款标题生成器**”。
    2.  将左侧输入项替换：“会议主题”->“产品类型”；“我的角色”->“目标人群”；“发言类型”->“文案风格”（搞笑、种草、测评）；“发言时长”->“标题字数”。
    3.  修改右侧结果区的标题和描述，如“🛡️ 保守稳妥版”->“🔥 热榜跟风款”。
    4.  **此时，只需修改HTML中的文字和Vue数据里`speechTypes`等数组的内容，完全不用动JS逻辑和Prompt。**

**第二步：调整输入字段或Prompt（核心改造）**
-   **目标**：让工具更贴合新场景的需求。
-   **操作**：
    1.  在表单中增加或删除输入项。例如，增加一个“关键词”输入框。
    2.  **关键**：同步修改`systemPrompt`变量中对应的部分。把“会议信息”的模板换成你的“标题生成信息”模板，并更新对AI的“输出要求”。
    3.  调整`systemPrompt`中的风格描述和结构要求。例如，把“发言稿结构”改成“标题公式：痛点+解决方案+情绪词”。

**第三步：改变输出形式或展示方式（优化体验）**
-   **目标**：让结果呈现更符合新内容的特点。
-   **操作**：
    1.  修改结果卡片的布局。比如标题生成器可能不需要大段内容区，可以改成显示10个标题的列表。
    2.  增加新的交互按钮，如“一键生成10个”、“刷新这个风格”。
    3.  美化输出样式，针对标题使用更大的字体、更醒目的颜色。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“语气/情绪”调节器**：
    -   **操作**：在表单区增加一个滑块或选择器，选项为“正式/中性/轻松/激昂”。
    -   **修改**：将这个变量加入到Prompt中，例如：“请使用${tone}的语气撰写发言稿。”
    -   **效果**：让生成的内容在文风上控制更精细。

2.  **替换或增加AI模型后端**：
    -   **操作**：在设置弹窗中，将模型选择从DeepSeek扩展到OpenAI的GPT-4o、Claude或国内的通义千问、智谱GLM。
    -   **修改**：复制`callDeepSeek`函数，改为`callOpenAI`，并修改API地址、请求头和参数格式。在前端增加一个模型选择开关。
    -   **效果**：用户可以对比不同模型生成的质量和风格，找到最适合自己的。

3.  **增加“历史记录”功能**：
    -   **操作**：在页面底部或侧边栏增加一个区域，使用`localStorage`保存每次生成的会议主题和发言稿标题。
    -   **修改**：在`generateSpeeches`函数成功生成后，将本次的`form`数据和`speeches`的标题存入一个数组并保存。提供点击历史记录可快速回填表单的功能。
    -   **效果**：方便用户回顾和复用，工具实用性大增。

4.  **拆分为“快速生成”与“深度编辑”两个模式/页面**：
    -   **操作**：在生成按钮旁增加一个“进入深度编辑模式”的链接。
    -   **修改**：点击后，跳转或弹出一个新页面，将生成的发言稿内容放入一个可编辑的富文本编辑器（如TinyMCE）中，允许用户直接在AI草稿上修改、润色。
    -   **效果**：将AI定位为“初稿助手”，尊重并发挥用户最终的创作主权。

5.  **优化交互：增加语音朗读功能**：
    -   **操作**：在每个发言稿卡片上增加一个“朗读”按钮。
    -   **修改**：点击后，使用浏览器Web Speech API (`window.speechSynthesis`) 将`speech.content`朗读出来。
    -   **效果**：帮助用户预听发言效果，检查语流是否顺畅，特别适合需要脱稿演讲的场景。

## 【七】这个网页不适合做什么？（边界提醒）

-   **不适合生成需要即时互动和临场应变的内容**：它生成的是预先准备的讲稿。如果会议是自由辩论，对方会随时提问，这份讲稿无法帮你应对。
    -   **应该换什么**：需要锻炼的是即兴演讲能力和逻辑思维，而非依赖讲稿生成。

-   **不适合处理高度依赖上下文和隐性知识的话题**：例如，你们部门内部一个延续了半年的技术债务讨论，AI无法知晓之前的争论细节和人员立场。
    -   **应该换什么**：使用会议纪要工具（如飞书妙记、钉钉闪记）先厘清历史脉络，人工提炼关键点。

-   **不适合创造有严格版权或独特个人风格的作品**：如重要的产品发布会演讲、品牌宣言、诗歌文学创作等。AI生成的内容可能缺乏真正的灵魂和独特性，且存在版权模糊风险。
    -   **应该换什么**：聘请专业的文案策划或演讲撰稿人，或由创作者本人精心打磨。

-   **不适合作为思考的替代品**：它帮助你“表达”，但不能替代你“思考”。如果你对自己要说什么完全没概念，过度依赖AI可能会导致发言内容空洞、与自身认知脱节。
    -   **正确用法**：把它当作“思维扩写器”和“表达润色器”，输入你初步的想法（哪怕很零碎），让AI帮你组织和提升，而不是从零开始替你思考。
