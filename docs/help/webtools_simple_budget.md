# 极简记账 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你刚在便利店买完东西，想立刻记下这笔开销。你不想打开复杂的记账软件，也不想在手机里翻找很久。这个网页就是为这种**快速、临时的记账场景**设计的。

它适合：
- **即时记录**：在消费后几秒内完成记账
- **单一场景**：只记录支出，不记录收入或复杂账目
- **轻量使用**：不需要分析报表，只需要知道花了多少钱
- **移动优先**：在手机上单手就能操作

它不适合：
- **复杂记账**：需要记录收入、转账、多账户的情况
- **数据分析**：需要查看月度报表、消费趋势分析
- **长期管理**：需要分类预算、设置提醒等高级功能
- **多人共享**：家庭或团队共同记账

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 金额数字（通过数字键盘输入）
- 消费分类（从8个预设图标中选择）

**用户通常会做哪几步操作？**
1. 打开页面，看到顶部的“本月支出”总额
2. 点击下方8个分类图标中的一个（如“餐饮”）
3. 使用数字键盘输入金额（如“25.5”）
4. 点击右下角的黑色对勾按钮保存
5. 记录会立即出现在“最近记录”列表中

**输出结果长什么样？**
- 顶部实时更新“本月支出”总额
- 下方显示最近20条记录，每条包含：
  - 分类图标和名称
  - 金额（带负号表示支出）
  - 记录的日期和时间
  - 右侧有删除按钮（鼠标悬停显示）

**有哪些容易忽略的使用细节？**
1. **小数点只能输入一次**：如果已经输入了小数点，再点小数点无效
2. **金额有长度限制**：最多输入8位数字（防止误操作）
3. **删除需要确认**：点击垃圾桶图标会弹出确认对话框
4. **数据自动保存**：关闭页面再打开，记录还在
5. **分类选择有状态**：选中的分类会变成黑色背景

## 【三】核心结构拆解（学习重点）

这个页面由**四个关键模块**组成，每个模块职责清晰：

**1. 状态显示模块（顶部）**
- **职责**：展示全局状态
- **包含**：返回按钮、标题、本月支出总额
- **设计亮点**：总额实时计算，给用户即时反馈

**2. 输入控制模块（中部）**
- **子模块1：显示屏**
  - 显示当前输入金额和选中分类
  - 视觉上模仿计算器屏幕
- **子模块2：分类选择器**
  - 8个固定分类，用图标+文字表示
  - 选中状态有视觉反馈
- **子模块3：数字键盘**
  - 0-9数字、小数点、删除、清空、保存按钮
  - 保存按钮最大且突出（黑色对勾）

**3. 数据记录模块（底部）**
- **职责**：展示历史记录
- **包含**：每条记录的详情和删除功能
- **交互细节**：删除按钮默认隐藏，鼠标悬停才显示

**4. 数据管理模块（背后的JavaScript）**
- **职责**：处理所有数据逻辑
- **包含**：
  - 输入处理（append/del/clear）
  - 数据存储（localStorage）
  - 数据计算（月度汇总）
  - 数据展示（格式化日期/金额）

**输入 → 处理 → 输出 的逻辑链路：**
```
用户点击分类 → 选中状态更新 → 显示屏显示分类名
用户输入数字 → 字符串拼接 → 显示屏显示金额
用户点击保存 → 创建记录对象 → 存入数组 → 保存到本地存储 → 更新显示
```

**最值得学习的设计：**
**“计算器式”的输入体验**。整个交互流程模仿实体计算器：
- 大数字显示
- 物理按键感的按钮
- 即时的视觉反馈
- 符合“输入-确认”的肌肉记忆

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：这个网页**没有使用AI或Prompt**，它是一个纯前端的工具。但我们可以从这个角度思考：如果我们要为它添加AI功能，Prompt会如何设计？

**假设我们要添加“智能分类”功能：**
- **Prompt角色**：让AI根据消费描述自动分类
- **解决的问题**：从“理解问题”转向“生成分类建议”
- **关键变量**：
  1. 用户输入的文字描述（如“中午吃了牛肉面”）
  2. 预设的分类列表（餐饮、交通、购物等）
  3. 历史分类习惯（学习用户偏好）

**示例Prompt设计：**
```
你是一个智能记账助手。请根据用户的消费描述，从以下分类中选择最合适的一个：
分类列表：餐饮、交通、购物、娱乐、居住、买菜、医疗、其他

用户描述："{userInput}"
历史偏好：用户过去将类似消费归为"{historyCategory}"的比例是{percentage}%

请只返回分类名称，不要解释。
```

**如果只改Prompt，不改代码：**
- 可以改变AI的“性格”（更严谨/更宽松）
- 可以调整分类的优先级
- 可以增加多语言支持
- 可以添加消费建议（如“这笔消费比平时高20%”）

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 把“记账”换成其他需要快速记录的场景
- 例如：**心情日记**（分类换成情绪，金额换成强度）
- 例如：**喝水提醒**（分类换成饮料类型，金额换成毫升数）
- **只改**：标题、分类名称、图标、颜色主题

**第二步：调整输入字段或数据模型**
- 修改`categories`数组的内容
- 调整记录对象的字段（如添加“备注”字段）
- 改变数据存储的键名（localStorage的key）
- **保持**：输入逻辑、保存逻辑、显示逻辑不变

**第三步：改变输出形式或展示方式**
- 把列表视图改成日历视图
- 把数字显示改成图表显示
- 添加筛选或排序功能
- **注意**：每次只改一个部分，测试通过后再改下一个

**从哪里下手最安全？**
从**分类和图标**开始改。这是最表层的变化，不会影响核心逻辑：
1. 复制整个HTML文件
2. 修改`categories`数组里的`name`和`icon`
3. 修改页面标题
4. 测试保存和显示是否正常

## 【六】3–5 个可直接尝试的改造方向

**1. 增加备注输入**
- **操作**：在分类选择器下方添加一个文本输入框
- **存储**：在记录对象中添加`note`字段
- **显示**：在列表项中显示备注（可折叠/展开）
- **价值**：让记录更有上下文，知道钱花在哪里

**2. 改为收入/支出双模式**
- **操作**：在顶部添加“支出/收入”切换按钮
- **逻辑**：保存时根据模式决定金额正负
- **显示**：收入用绿色显示，支出用红色显示
- **计算**：月度汇总分开计算收入和支出

**3. 添加简单的图表分析**
- **操作**：在“最近记录”上方添加一个饼图区域
- **库**：使用Chart.js或简单的CSS绘制
- **数据**：按分类统计本月消费比例
- **交互**：点击图表区块筛选对应记录

**4. 支持自定义分类**
- **操作**：在分类网格最后添加“+”按钮
- **流程**：点击后弹出对话框，输入名称、选择图标
- **存储**：将自定义分类也存入localStorage
- **注意**：需要处理图标库的动态加载

**5. 添加数据导出功能**
- **操作**：在顶部添加“导出”按钮
- **格式**：导出为CSV或JSON文件
- **内容**：包含所有记录，带时间戳
- **用途**：备份数据或导入到其他软件分析

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不适合正式财务管理**
   - 没有对账功能
   - 没有预算设置
   - 没有多账户管理
   - **替代方案**：使用专业的记账软件如MoneyWiz、随手记

2. **不适合团队或家庭共享**
   - 数据存储在本地浏览器
   - 无法多人同时访问
   - 没有权限管理
   - **替代方案**：使用共享表格或专门的协作记账工具

3. **不适合深度数据分析**
   - 只有月度汇总
   - 没有趋势图表
   - 没有分类对比
   - **替代方案**：将数据导出到Excel或使用BI工具

4. **不适合大量历史数据**
   - 只显示最近20条
   - 没有分页或搜索
   - 性能可能随数据量下降
   - **替代方案**：使用数据库后端的完整应用

5. **不适合离线长期使用**
   - 依赖浏览器localStorage
   - 清除浏览器数据会丢失记录
   - 无法跨设备同步
   - **替代方案**：使用有云同步功能的移动应用
