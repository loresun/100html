# 用药提醒助手 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景**：当你需要每天按时服用多种药物时，很容易忘记“今天吃过了没有”或“该在哪个时间点吃”。这个网页就像一个数字化的药盒，帮你把不同药品按“早晨、中午、晚上、睡前”四个时段分类展示，并让你可以一键标记“已服用”。

**适合情况**：
- 需要长期服药（如慢性病管理）
- 同时服用多种药物，且服用时间不同
- 希望有简单的完成度统计
- 数据只需保存在自己设备上（无云端同步需求）

**不适合情况**：
- 需要精确到分钟提醒（无推送通知功能）
- 需要多人协作管理（如照顾老人用药）
- 需要长期历史记录分析
- 需要在不同设备间同步数据

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 药品名称（如“阿司匹林”）
- 剂量（如“1片/100mg”）
- 服用时间段（可多选：早晨、中午、晚上、睡前）
- 备注（可选，如“餐后服用”）

**用户通常会做哪几步操作？**
1. 点击右上角“+”按钮，添加第一个药品
2. 填写药品信息，选择服用时间段
3. 保存后，药品会出现在对应时间段的卡片中
4. 每次服药后，点击对应药品卡片，它会变成“已服用”状态（带删除线）
5. 页面顶部的“完成度”百分比会自动更新

**输出结果长什么样？**
- 按时间顺序排列的药品清单
- 已服用的药品会变灰、带删除线
- 右上角有绿色勾选标记
- 顶部显示当日完成百分比

**容易忽略的使用细节：**
1. **时间段是多选的**：一个药可以同时在“早晨”和“晚上”服用
2. **数据保存在本地**：关闭浏览器后数据不会丢失，但换设备或清除缓存会丢失
3. **删除是永久的**：点击垃圾桶图标会直接删除药品（有确认提示）
4. **完成度按天重置**：每天都是新的开始，昨天的记录不影响今天

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

### 模块1：数据管理模块（JavaScript对象）
- **职责**：存储所有药品信息、服用记录
- **关键数据结构**：
  - `meds`：药品列表，每个药品有id、名称、剂量、时间段等
  - `logs`：服用记录，按日期和“药品_时间”组合键存储
  - `timeSlots`：固定的四个时间段定义

### 模块2：时间线展示模块（HTML + Alpine.js）
- **职责**：按时间段分组显示药品
- **工作流程**：
  1. 遍历`timeSlots`生成四个时间段标题
  2. 对每个时间段，从`meds`中筛选出属于该时间段的药品
  3. 为每个药品生成卡片，并根据`logs`判断是否已服用
  4. 点击卡片时调用`toggleMed`切换服用状态

### 模块3：添加药品模态框
- **职责**：收集用户输入的药品信息
- **设计亮点**：
  - 使用`x-show`控制显示/隐藏
  - 时间段选择用按钮组实现，视觉反馈清晰
  - 保存前验证必填字段（名称和时间段）

### 模块4：状态计算与持久化
- **职责**：计算完成度、处理本地存储
- **关键逻辑**：
  - `completionRate`：实时计算已服用药品占比
  - `localStorage`：页面加载时读取，数据变化时自动保存

**最值得学习的设计**：
> **“状态驱动视图”的简洁实现**：整个应用的状态（meds, logs）是单一数据源，所有界面变化都是状态的反映。点击药品→更新logs→界面自动重绘。这种模式让代码逻辑非常清晰，是现代化Web应用的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

**重要说明**：这个版本**没有使用AI或Prompt**。它是一个纯前端的数据管理应用。

**如果这是一个AI增强版本，Prompt可能会这样设计：**

假设我们要添加“智能用药建议”功能：
```
角色：你是专业的药剂师助理。

用户提供了以下药品信息：
- 药品名称：[用户输入的药品名]
- 当前剂量：[用户输入的剂量]
- 服用时间段：[用户选择的时间段]

请根据你的专业知识：
1. 检查药品名称是否常见，如有拼写错误请纠正
2. 提供标准的剂量单位建议（如mg、ml、粒等）
3. 根据药品类型，建议最佳的服用时间（如“餐前”、“餐后”、“空腹”）
4. 如果有常见的药物相互作用提醒，请一并说明

输出格式：
- 纠正后的药品名：[如有]
- 标准剂量建议：[建议]
- 服用时间建议：[建议]
- 注意事项：[如有]
```

**Prompt在这个页面中可能扮演的角色**：
- **理解问题**：解析用户输入的模糊药品信息
- **生成问题**：根据药品信息生成个性化的服用建议

**关键变量**：
- 药品名称（可能包含拼写错误）
- 用户输入的剂量格式
- 选择的时间段

**如果只改Prompt，不改代码**：
- 可以改变AI回复的专业程度和详细程度
- 可以调整建议的侧重点（如更关注副作用 vs 更关注服用时间）
- 可以改变输出格式，但界面可能无法正确显示

## 【五】如何模仿它，做出你自己的版本？

### 安全改造路径（从易到难）：

**第一步：保持结构不变，替换使用场景**
- 将“用药提醒”改为“每日任务追踪”
- 药品→任务，剂量→预估时间，时间段→优先级（高/中/低）
- 服用→完成，完成度→任务完成率
- **这是最安全的起点**，只需修改文字和图标

**第二步：调整输入字段**
- 增加“紧急程度”选择（红/黄/绿）
- 增加“重复频率”（每日/每周/每月）
- 增加“关联标签”（工作/学习/生活）
- 修改`newMed`对象和添加模态框即可

**第三步：改变数据展示方式**
- 从“时间线”改为“看板”（待办/进行中/已完成）
- 或改为“日历视图”，按日期分布
- 这需要重写`getMedsForTime`类似的筛选逻辑

**第四步：增强交互**
- 添加“拖拽排序”功能
- 添加“批量操作”（全选、批量删除）
- 添加“搜索/过滤”功能

**从哪里下手最安全？**
> **从修改`timeSlots`数组开始**。这是定义应用“时间维度”的核心，修改它只会影响分组方式，不会破坏核心逻辑。比如改成`['上午', '下午', '晚上']`或`['工作日', '周末']`。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加“药品库存管理”
- **添加字段**：当前库存数量、每次服用消耗量、最低库存提醒
- **计算逻辑**：根据服用记录自动计算剩余量
- **提醒功能**：库存低于阈值时，药品卡片显示警告色
- **代码位置**：在`meds`对象中添加`stock`字段，在`toggleMed`中减少库存

### 2. 改为“团队协作”版本
- **添加用户概念**：每个药品有“负责人”
- **共享数据**：使用简单的后端API或Firebase实时数据库
- **操作记录**：谁在什么时间标记了服用
- **改造步骤**：
  1. 添加用户登录/选择界面
  2. 将`localStorage`改为API调用
  3. 在日志中记录用户ID

### 3. 添加“历史记录与统计”
- **新页面**：点击完成度百分比进入统计页
- **数据显示**：过去7天/30天的服用趋势图
- **统计维度**：按时服用率、最常忘记的药品、最佳服用时间段
- **技术实现**：使用Chart.js或简单的CSS图表

### 4. 集成“语音输入与提醒”
- **语音添加**：“嘿，添加布洛芬，早晚各一次”
- **语音识别**：使用Web Speech API
- **语音提醒**：到点时浏览器通知+语音播报
- **渐进增强**：作为可选功能，不影响核心使用

### 5. 改为“通用习惯追踪器”
- **抽象化**：药品→习惯项目，服用→打卡
- **灵活时间段**：允许用户自定义时间段（如“起床后”、“午休时”）
- ** streak 统计**：连续打卡天数
- **社交功能**：分享打卡成果（可选）

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性说明：

1. **不适合医疗级精准管理**
   - 无药品相互作用检查
   - 无剂量计算（如根据体重调整）
   - 无处方验证
   - **如果需要**：应使用专业的医疗管理APP或咨询药师

2. **不适合紧急情况**
   - 无推送通知（用户必须主动打开页面）
   - 无离线提醒（关闭浏览器即失效）
   - 无紧急联系人功能
   - **如果需要**：使用手机系统自带的提醒APP或智能药盒硬件

3. **不适合复杂用药方案**
   - 无法处理“隔日服用”、“每周一次”等复杂周期
   - 无法处理“逐渐减量”的用药方案
   - 无法关联检查结果调整用药
   - **如果需要**：使用专业的慢性病管理软件

4. **不适合数据安全要求高的场景**
   - 数据仅存在本地浏览器
   - 无备份、无加密
   - 设备丢失=数据丢失
   - **如果需要**：选择有云端同步和加密功能的应用

### 核心定位：
> 这是一个**轻量级的个人用药记忆辅助工具**，不是医疗设备，也不是专业医疗软件。它的价值在于“简单解决一个具体问题”，而不是“覆盖所有用药场景”。

**给学习者的最后建议**：
这个项目的精华在于它的“架构清晰性”。你可以看到：
- 数据如何定义（meds, logs）
- 数据如何变化（toggleMed, addMed）
- 视图如何响应数据变化（x-text, x-show, x-for）

尝试改造时，先想清楚“我的数据是什么样子”，然后修改数据模型，最后调整界面。这个顺序会让你事半功倍。
