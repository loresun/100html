# Prompt 资产管理器 - 学习与使用指南

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一个经常使用 AI 工具的内容创作者、产品经理或开发者。你积累了很多精心设计的 Prompt（指令），它们分散在各个文档、聊天记录里。当你想复用某个“写产品介绍的优秀 Prompt”时，却怎么也找不到；或者找到了，但不确定这是不是最新版本。

这个网页就是一个**个人或团队的 Prompt 知识库**。它帮你：
- **集中管理**：把所有 Prompt 像文件一样收集在一个地方。
- **版本追踪**：每次修改 Prompt 都会自动保存历史版本，可以随时回滚。
- **快速测试**：选中一个 Prompt，可以直接在页面内与 AI 对话，验证它的效果。
- **协作评审**：可以为 Prompt 添加备注，记录改进思路，适合团队使用。

**适合场景**：
- 个人整理常用的 AI 指令模板（如写作、编程、翻译）。
- 小团队共享和迭代用于工作的标准 Prompt。
- 学习 Prompt 工程时，记录不同版本的效果对比。

**不适合场景**：
- 需要复杂权限管理（如公司级多部门协作）。
- 需要将 Prompt 直接集成到自动化工作流中（它更偏向“管理”而非“调用”）。
- 管理海量（如上万条）Prompt，因为当前搜索和筛选功能较为基础。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 你看到的首先是一个卡片列表，里面有一些示例 Prompt（如“新品发布脚本 Prompt”）。
- 页面顶部有搜索框、分类/状态筛选器、星标筛选，以及“新建”、“导入/导出”按钮。

**用户通常会做哪几步操作？**
1.  **浏览与筛选**：在顶部通过关键词、分类（如“营销”、“产品”）或状态（如“草稿”、“已发布”）快速找到想要的 Prompt。
2.  **查看详情**：点击任意卡片，会弹出一个大窗口，在这里你可以：
    - **预览**：完整查看 Prompt 内容和描述。
    - **编辑**：修改标题、描述、分类、状态和 Prompt 内容本身。**保存时会自动创建历史版本**。
    - **查看历史**：浏览所有旧版本，鼠标悬停可预览内容，可以“回滚”到旧版或“复制”。
    - **添加评审备注**：记录为什么修改，或同事的反馈。
3.  **测试 Prompt**：在详情页点击“AI 对话测试”，会打开一个聊天窗口。你输入的对话，会**以当前 Prompt 作为系统指令**发送给 AI，让你直观感受 Prompt 的效果。
4.  **创建与管理**：
    - 点击“新建”来添加一个全新的 Prompt。
    - 点击卡片上的星星可以标记重要 Prompt。
    - 使用“导入/导出”功能来备份你的整个库，或从 CSV 文件恢复。

**输出结果长什么样？**
- 主界面：一个整洁的卡片网格，每张卡片显示标题、状态、描述和最后更新时间。
- 详情弹窗：一个功能丰富的面板，集中了查看、编辑、版本管理、对话测试所有功能。
- AI 对话窗口：一个模拟的聊天界面，显示你和 AI 的对话记录。

**有哪些容易忽略的使用细节？**
1.  **AI 测试需要 API Key**：首次进行 AI 对话测试前，你需要先在浏览器的 `localStorage` 中存入一个名为 `deepseek_api_key` 的密钥（例如在浏览器开发者工具的 Console 中运行 `localStorage.setItem('deepseek_api_key', '你的key')`）。页面没有提供可视化设置入口。
2.  **“回滚”操作是替换**：在历史版本中点击“回滚”，会用选中的版本**直接替换当前内容**，同时当前内容会变成一个历史版本。这不是“复制一份”，而是真正的版本切换。
3.  **导入/导出的数据格式**：导出的是 CSV 文件。如果你想手动编辑或从其他工具迁移，需要了解其字段结构（标题、内容、状态等）。
4.  **快捷键**：在 AI 对话窗口，可以使用 `Ctrl + Enter` 快速发送消息。

## 【三】核心结构拆解（学习重点）

这个页面不是一堆功能的堆砌，而是由几个职责清晰的模块组成：

**1. 资产管理模块（核心）**
- **职责**：存储、展示、筛选所有 Prompt 数据。它是整个应用的“状态中心”。
- **组成**：顶部的筛选栏（搜索、分类、状态、星标） + 中部的卡片网格。
- **逻辑**：`assets` 数组存储所有数据 -> `filteredAssets` 根据筛选条件实时计算并显示 -> 任何修改最终都会保存到 `localStorage`。
- **值得学习的设计**：**响应式计算属性 (`computed`)**。`filteredAssets` 会根据 `filters` 对象的变化自动重新计算并更新界面，无需手动触发刷新。这是 Vue 框架的高效应用。

**2. 详情与编辑模块**
- **职责**：提供对单个 Prompt 的“增删改查”深度操作。
- **组成**：一个弹窗，内部通过 Tab 页（预览、编辑、历史版本、评审备注）组织功能。
- **逻辑**：点击卡片 -> 打开弹窗并加载对应数据 -> 用户在对应 Tab 操作 -> 操作结果更新到 `assets` 数组并持久化。
- **值得学习的设计**：**“状态同步”模式**。`editForm` 对象作为编辑态的临时数据，与真实的 `currentAsset` 数据分离。保存时，再将 `editForm` 的数据合并回 `currentAsset`。这避免了在编辑过程中直接污染原始数据。

**3. 版本控制模块**
- **职责**：记录 Prompt 的修改历史，支持回滚和查看。
- **组成**：在“历史版本” Tab 下，以时间倒序列出版本卡片。
- **逻辑**：每次保存编辑时，都会将**编辑前**的完整 Prompt 数据快照，作为一个新对象存入 `asset.versions` 数组。回滚时，则将版本数据交换。
- **值得学习的设计**：**业务逻辑的封装**。`rollbackVersion` 方法不仅替换了当前内容，还巧妙地将当前内容作为新版本插入到被回滚版本的位置，保持了版本历史的连贯性。这是一个完整的、可用的版本控制最小实现。

**4. AI 对话测试模块**
- **职责**：在应用内快速验证 Prompt 的实际效果。
- **组成**：另一个弹窗，包含模型选择、聊天记录展示区和输入框。
- **逻辑**：打开窗口 -> 用户输入消息 -> 将 **当前 Prompt 作为 `system` 消息** + 对话历史作为 `messages` 发送给 DeepSeek API -> 返回结果显示。
- **值得学习的设计**：**Prompt 的“系统角色”化应用**。它没有直接让用户看到拼接后的 Prompt，而是利用 LLM API 的 `system` 角色参数，优雅地将管理的 Prompt 作为对话背景。这演示了如何将“管理的资产”连接到“实际的使用场景”。

**输入 → 处理 → 输出 的逻辑链路：**
```
用户操作（点击、输入、筛选）
    ↓
触发 Vue 方法（如 `openDetailModal`, `sendMessage`）
    ↓
修改 `data` 中的状态（如 `assets`, `aiChat.messages`）
    ↓
Vue 的响应式系统自动更新 `computed` 属性（如 `filteredAssets`）和 DOM
    ↓
界面重新渲染，用户看到结果
```

**最值得学习的设计**：
**“以数据为中心”的架构**。整个应用的状态（所有 Prompt、筛选条件、弹窗状态、聊天记录）都集中在 Vue 的 `data` 对象中。UI 只是这些状态的映射。这种设计使得功能模块之间的数据流动非常清晰，也易于持久化（整个 `assets` 数组可以一键存到 `localStorage`）。这是构建复杂交互型单页应用（SPA）的核心思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
在这里，Prompt 是**被管理的核心资产对象**，而不仅仅是发给 AI 的一段文本。每个 Prompt 对象都附带了元数据（标题、描述、状态、分类）和管理数据（版本历史、评审备注）。

**它解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**。AI 对话测试模块的核心目的是：验证你设计的这个 Prompt（作为系统指令）能否引导 AI 生成符合你预期的回答。例如，你管理着一个“写小红书文案”的 Prompt，通过对话测试，你可以快速检查它生成的文案风格是否合适。

**哪些信息是 Prompt 中的关键变量？**
在对话测试的 API 调用中，关键变量是：
- `system`: 其内容来自 `currentAsset.content`，即你正在查看或测试的那个 Prompt 的完整文本。
- `messages`: 由 `aiChat.messages` 数组（用户和 AI 的历史对话）构成。
- `model`: 由 `aiChat.model` 决定（如 `deepseek-chat`）。
这些变量共同决定了 AI 的回复。

**如果只改 Prompt，不改代码，会发生什么变化？**
变化会非常直接和明显：
1.  **对话测试的结果会立刻改变**：因为发送给 AI 的系统指令变了，AI 的角色和行为也会随之改变。例如，把 Prompt 从“你是一个严肃的学者”改成“你是一个幽默的段子手”，AI 的回复风格会截然不同。
2.  **筛选和搜索的结果可能改变**：如果你修改了 Prompt 的标题、描述、分类或内容，这些信息会被用于关键词搜索和分类筛选。
这恰恰体现了这个工具的价值：**通过修改 Prompt 资产本身，就能控制 AI 的行为，而无需改动任何程序代码。**

## 【五】如何模仿它，做出你自己的版本？

如果你想创建一个类似的管理工具（比如“代码片段库”、“设计资源库”、“演讲稿模板库”），可以遵循这个安全的模仿路径：

**第一步：保持结构不变，替换核心数据模型**
- **最安全**：先不要动 HTML 和 CSS 布局。
- 找到 `data()` 函数里 `assets` 数组的示例数据。把你的“资产”字段映射上去。
    - 例如，做“代码片段库”：把 `title` 改成 `snippetName`，`content` 改成 `code`，`category` 改成 `language`（如 JavaScript, Python），`status` 改成 `type`（如 `function`, `snippet`, `boilerplate`）。
- 修改 `statusOptions` 和相关的标签显示函数（`statusLabel`, `statusBadgeClass`），使其符合你的新状态类型。

**第二步：调整输入与展示字段**
- 在“编辑”Tab 的表单中，增加、删除或修改输入框。例如，为代码片段增加一个“依赖项”文本框。
- 在卡片和详情页的“预览”Tab，修改展示方式。例如，将普通的 `<pre>` 展示代码，改为使用类似 `highlight.js` 的语法高亮组件。
- **关键**：确保每一步修改都同步更新 `editForm` 对象和数据显示逻辑。

**第三步：改变核心功能（版本/测试）**
- **版本控制**：逻辑可以完全复用。它保存的是整个资产对象的快照，所以你的新字段也会自动被版本记录。
- **测试功能**：这是最具定制空间的部分。
    - 如果你做的是代码片段库，“测试”可能变成“在 CodeSandbox 中运行”。
    - 如果你做的是演讲稿模板库，“测试”可能变成“生成语音朗读”。
    - 修改 `openAiChat` 和 `sendMessage` 方法，将其替换为调用你自己的 API 或服务。

**从哪里下手最安全？**
从 **`data()` 中的默认数据和 `statusOptions`** 开始改。这不会破坏界面和交互，但能立刻让应用变成你的主题。然后逐步修改相关的文本标签（如把“Prompt”全部替换为“代码片段”）。这样每一步都能看到可运行的结果，风险最小。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“变量插值”与“快速填充”功能**
    - **操作**：在 Prompt 内容编辑框中，支持 `{{变量名}}` 的语法。在详情页预览或 AI 测试时，弹出一个侧边栏，让用户填写这些变量（如 `{{产品名}}`、`{{目标受众}}`），然后自动替换到 Prompt 中再发送。
    - **价值**：让 Prompt 从固定模板变成可配置模板，实用性大增。

2.  **更换或增加 AI 模型提供商**
    - **操作**：修改 `aiChat` 中的 `model` 选项，增加 `gpt-4o`、`claude-3` 等。同时修改 `sendMessage` 方法中的 API 端点（`https://api.deepseek.com/v1/chat/completions`）和请求头，适配 OpenAI 或 Anthropic 的格式。
    - **价值**：可以对比同一个 Prompt 在不同模型下的效果，成为真正的“Prompt 测试平台”。

3.  **拆分为“库浏览”与“编辑台”双页面模式**
    - **操作**：将当前的详情弹窗，改造成一个独立的页面（如 `editor.html?id=xxx`）。主页面（`index.html`）只负责浏览、筛选和跳转。通过 URL 参数传递资产 ID。
    - **价值**：更适合复杂、长时间的编辑场景；便于分享单个 Prompt 的编辑链接。

4.  **增加“使用统计”与“效果评分”**
    - **操作**：在每个资产对象中增加 `usageCount` 和 `rating` 字段。每次通过“AI对话测试”或未来可能的“直接调用”后，累加计数。在详情页增加一个简单的五星评分组件，让用户记录这个 Prompt 的好坏。
    - **价值**：数据驱动优化。你可以一眼看出哪个 Prompt 最常用、评价最好，从而集中精力优化核心资产。

5.  **优化交互：拖拽排序与批量操作**
    - **操作**：引入一个轻量的拖拽库（如 `Sortable.js`），让卡片可以手动排序。在顶部增加复选框，支持“全选”、“批量导出”、“批量修改状态”等功能。
    - **价值**：提升大量资产时的管理效率，交互更现代。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为生产环境的 Prompt 调度中心**
    - **局限性**：所有数据存在用户浏览器的 `localStorage` 中，无法跨设备同步，团队无法共享同一份实时数据，数据有丢失风险（清除浏览器数据即消失）。
    - **如果你需要**：多人实时协作，或需要将 Prompt 集成到你的软件产品中自动调用。
    - **应该换用**：后端数据库（如 Firebase, Supabase） + 提供 API 的服务。这个网页的代码可以作为**非常优秀的前端原型**，直接对接你的后端。

2.  **不适合进行复杂的 Prompt 工程实验**
    - **局限性**：它的版本控制是线性的，不支持分支、合并。它的测试功能是对话式的，不支持 A/B 测试、批量测试或自动化评估（如用评分模型自动判断输出质量）。
    - **如果你需要**：像管理代码一样管理 Prompt，进行复杂的迭代实验。
    - **应该换用**：结合 Git 进行版本管理，并使用专门的 Prompt 实验平台或自己编写测试脚本。

3.  **不适合管理高度结构化或带附件的知识**
    - **局限性**：它管理的资产本质上是“文本”+“元数据”。如果你的“资产”是复杂的 JSON 结构、图片、或需要关联多个文件，它无法处理。
    - **如果你需要**：管理带示例图片的 UI 设计提示词，或结构化的数据生成模板。
    - **应该换用**：可以扩展它的数据模型（在 `assets` 中增加新字段来存储文件链接或结构化数据），或者使用更通用的笔记/知识库软件（如 Notion）。

**总结**：这个网页是一个**功能完整、设计优雅的“最小可行产品”（MVP）**。它完美地解决了个人或小团队 Prompt 管理中的核心痛点，并提供了清晰的扩展路径。它的最大价值在于提供了一个可以直接运行、学习和修改的**优秀范本**，你可以基于它，快速构建出适合自己特定需求的管理工具。
