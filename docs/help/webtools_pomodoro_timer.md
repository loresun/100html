# 专注番茄钟 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在准备考试、写工作报告或学习新技能，但总是被手机通知、网页弹窗打断，无法长时间保持专注。这个网页就是你的**数字专注伙伴**。

**适合场景：**
- 需要深度工作/学习时（如写代码、写论文、复习备考）
- 希望用结构化方法管理时间（工作25分钟，休息5分钟）
- 想要可视化看到自己的专注成果
- 在单一设备上工作，需要简洁的计时工具

**不适合场景：**
- 需要频繁切换任务的工作（如客服、紧急事务处理）
- 团队协作需要同步计时
- 需要复杂任务管理功能（如待办清单、优先级排序）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 三个模式按钮：专注、短休、长休
- 一个大圆形控制按钮（开始/暂停）
- 重置按钮
- 设置中的时长数值

**典型使用流程：**
1. **选择模式**：默认是“专注”模式（25分钟）
2. **开始计时**：点击中间的圆形按钮，按钮会开始呼吸动画
3. **专注工作**：期间不要切换页面，保持专注
4. **休息提醒**：时间到会有提示，根据设置自动或手动切换到休息模式
5. **查看进度**：底部的小圆点显示今日完成的专注次数

**输出结果长什么样？**
- 大数字倒计时（如“24:37”）
- 状态提示文字（“保持专注...”）
- 底部进度圆点（每完成一次专注，增加一个实心点）
- 浏览器标签页也会显示剩余时间

**容易忽略的细节：**
1. **长休逻辑**：每完成4次专注，才会出现长休息选项
2. **自动切换**：在设置中开启“自动开始休息”后，专注结束会自动开始休息计时
3. **数据保存**：设置和完成次数会自动保存在浏览器中，下次打开还在
4. **呼吸动画**：计时运行时，开始按钮有脉动效果，直观显示状态

## 【三】核心结构拆解（学习重点）

这个页面由**5个关键模块**组成：

### 1. 模式切换模块
- **位置**：页面顶部的三个按钮
- **职责**：让用户在“工作-短休-长休”三种状态间切换
- **设计亮点**：使用不同颜色区分状态，当前模式有高亮效果

### 2. 计时显示模块
- **位置**：页面中央的大数字
- **职责**：直观显示剩余时间，提供状态文字提示
- **设计亮点**：极简的数字显示，减少视觉干扰

### 3. 控制中心模块
- **位置**：计时下方的两个圆形按钮
- **职责**：开始/暂停计时，重置当前计时
- **设计亮点**：主按钮有呼吸动画，强化“进行中”的感知

### 4. 进度追踪模块
- **位置**：页面底部的小圆点
- **职责**：可视化展示今日完成情况
- **设计亮点**：每4个一组，暗示“专注4次后长休”的番茄工作法规则

### 5. 设置面板模块
- **位置**：点击右上角齿轮弹出的浮层
- **职责**：让用户自定义时长和功能偏好
- **设计亮点**：使用本地存储保存设置，下次打开依然有效

**输入 → 处理 → 输出 链路：**
```
用户点击“开始” → JavaScript启动计时器 → 每秒更新显示 → 时间到触发完成逻辑 → 更新进度并提示
```

**最值得学习的设计：**
**状态驱动的UI更新** - 整个页面围绕`mode`（模式）、`isRunning`（是否运行）、`timeLeft`（剩余时间）这几个核心状态构建。状态一变，所有相关显示自动更新。这是现代前端框架的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：这个页面没有使用AI或Prompt，但我们可以分析它的“逻辑设计”

**计时逻辑扮演的角色：**
在这个页面中，计时逻辑相当于一个“规则引擎”，它决定了：
- 什么时候切换模式
- 什么时候算完成一次专注
- 什么时候该长休而不是短休

**解决的是“流程控制”问题：**
逻辑主要解决“接下来该做什么”的决策问题，例如：
- 专注结束后 → 该短休还是长休？（由完成次数决定）
- 休息结束后 → 自动回到专注模式

**关键规则变量：**
1. `completedPomodoros % 4 === 0` - 判断是否该长休
2. `settings.autoBreak` - 决定是否自动切换
3. `mode` - 当前处于什么阶段

**如果只改逻辑，不改界面：**
- 把“每4次长休”改成“每3次长休”
- 把“专注25分钟”改成“专注52分钟”（52/17工作法）
- 增加“跳过本次休息”的功能
界面几乎不用改，但工作流程完全变了。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

### 第一步：保持骨架，换皮肤（最安全）
- 复制整个HTML结构
- 只修改CSS样式：改颜色、字体、圆角大小
- 替换图标（Lucide图标库有其他图标）
- 目标：做出一个“看起来不同但功能一样”的番茄钟

### 第二步：调整计时规则
- 修改`settings`对象的默认值
- 改变`completeTimer()`中的逻辑
- 例如：实现“90分钟深度工作法”
- 目标：适应不同的时间管理方法

### 第三步：改变数据展示方式
- 把底部的小圆点改成进度条
- 在页面上显示“今日总专注时间”
- 添加“历史记录”表格
- 目标：提供更丰富的数据反馈

### 第四步：扩展使用场景
- 添加“当前任务”输入框
- 为每次专注添加标签（学习、工作、阅读）
- 增加“成就系统”（连续专注X天）
- 目标：从“计时器”变成“专注管理系统”

**从哪里下手最安全？**
从**修改CSS样式**开始。改颜色、大小、间距不会破坏功能，但能立即看到效果，建立信心。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加任务管理
- 在开始前输入“本次专注要做什么”
- 专注结束后询问“完成度如何？（1-5星）”
- 保存每次专注的任务和评分
- **技术点**：在`localStorage`中存储数组对象

### 2. 添加音效和通知
- 开始、结束、最后一分钟添加提示音
- 使用浏览器通知API（`new Notification()`）
- 即使切换到其他标签页也能收到提醒
- **技术点**：`<audio>`元素或Web Audio API

### 3. 实现团队协作版
- 添加“房间号”输入，多人共享同一个计时器
- 使用WebSocket或Firebase实时同步状态
- 显示“还有X人正在专注”
- **技术点**：实时数据库或WebSocket连接

### 4. 增加数据统计页面
- 新开一个`stats.html`页面
- 用图表展示“每周专注趋势”
- 显示“最佳专注时段”分析
- **技术点**：Chart.js图表库，数据从localStorage读取

### 5. 集成待办清单
- 左侧添加任务列表
- 专注时显示当前任务
- 完成专注后可以勾选任务
- **技术点**：左右分栏布局，任务状态管理

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不适合复杂项目管理**
   - 没有任务依赖关系
   - 没有截止日期管理
   - 如果需要，应该用Trello、Notion等专业工具

2. **不适合精确的时间追踪**
   - 无法导出详细的时间日志
   - 不能按客户/项目分类
   - 如果需要，应该用Toggl、Harvest等时间追踪工具

3. **不适合团队时间协调**
   - 没有共享日历功能
   - 不能查看队友的可用时间
   - 如果需要，应该用Google Calendar、Calendly

4. **不适合作为最终产品**
   - 数据只存在本地，换设备就丢失
   - 没有用户账户系统
   - 如果要发布为正式产品，需要后端数据库和用户系统

### 如果用户想做...
- **“记录每项任务的实际耗时”** → 用时间追踪类App
- **“和团队同步工作节奏”** → 用共享计时工具或会议软件
- **“管理包含多个步骤的项目”** → 用项目管理软件
- **“分析我的时间使用模式”** → 用有数据分析功能的时间管理工具
