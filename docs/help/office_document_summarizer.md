# 文档摘要工具 - 帮助与学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你刚开完一个冗长的会议，收到了一份几十页的项目报告，或者需要快速浏览一篇长文章。你没有时间逐字阅读，但又必须抓住核心信息。这个工具就是你的“信息过滤器”，它能帮你快速消化长文本，提炼出关键要点、待办事项和核心结论，让你在几分钟内掌握原本需要半小时才能读完的内容。

**适合情况：**
- 快速阅读会议记录、报告、研究论文、新闻文章。
- 处理邮件线程，提取行动项和决策点。
- 学习时，为长章节或教材做内容摘要。
- 需要从文档中提取结构化信息（如背景、问题、方案）。

**不适合情况：**
- 需要对文本进行深度分析、批判性思考或提出原创观点。
- 处理高度机密或敏感信息（数据会发送到外部AI服务）。
- 文本本身极短（如一两句话），摘要价值不大。
- 需要100%精确无误的法律或医疗文件解读。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **文档内容**：你可以直接粘贴大段文字，或者上传 `.txt` 或 `.md` 格式的文本文件。
2.  **你的偏好设置**：选择你想要的摘要形式（如要点列表）、长度，以及是否要额外提取待办事项和关键词。

**用户通常会做哪几步操作？**
1.  **配置**：首次使用时，点击右上角“设置”按钮，输入你的 DeepSeek API Key 并选择模型（推荐 R1）。
2.  **输入内容**：在左侧区域，选择“粘贴文本”或“上传文件”，将你的长文档内容放入。
3.  **定制摘要**：选择你想要的“摘要模式”（如“要点列表”）和“摘要长度”。可以展开“高级选项”进行微调。
4.  **生成**：点击蓝色的“生成摘要”按钮。
5.  **查看与使用结果**：在右侧区域查看生成的摘要。你可以“复制”文本，或“导出”为 Markdown 文件保存。

**输出结果长什么样？**
输出是一个结构清晰、易于阅读的文本块。例如，选择“要点列表”模式，你可能会看到：
```
**核心要点**：
- 项目因资源不足面临延期风险。
- 团队提议采用敏捷冲刺来追赶进度。
- 关键决策需在下周五前由管理层批准。
```
如果启用了“提取待办事项”，下面还会有一个复选框列表；如果使用了 R1 模型，你还能展开看到 AI 的“思考过程”。

**有哪些容易忽略的使用细节？**
- **API Key 是必须的**：不配置就无法使用。点击设置中的“(获取 Key)”链接可以跳转到官网申请。
- **模型选择影响结果**：“R1 深度提炼”模型速度稍慢，但分析更深入，且会展示思考过程；“V3 快速摘要”模型更快。
- **思考过程可查看**：使用 R1 模型时，结果上方的“R1 深度分析过程”可以点击展开，能看到 AI 是如何一步步推导出摘要的，这对理解 AI 逻辑很有帮助。
- **导出功能**：导出的 Markdown 文件包含了生成时间、模式等元信息，方便归档。

## 【三】核心结构拆解（学习重点）

这个页面是一个经典的 **“参数化输入 -> AI 处理 -> 格式化输出”** 的单页应用。我们可以把它拆解成几个清晰的模块：

1.  **配置与状态管理模块**
    *   **职责**：管理用户的核心设置（API Key、AI 模型），并将它们保存到浏览器的本地存储中。这样下次打开页面时，配置还在。
    *   **设计亮点**：`localStorage` 的运用实现了“记忆功能”，提升了用户体验。

2.  **输入与参数控制模块（左侧面板）**
    *   **职责**：收集用户的所有输入和偏好。
    *   **子模块**：
        *   **输入方式切换器**：在“粘贴”和“上传”间切换，适应不同场景。
        *   **内容输入区**：核心文本输入框或文件上传区域。
        *   **模式选择器**：提供四种预设的摘要“模板”（一句话、要点、结构化、全面）。
        *   **参数调节器**（高级选项）：让用户微调输出长度和是否提取额外信息。
    *   **设计亮点**：将复杂的 AI 任务参数（如摘要结构、长度、附加任务）转化为直观的按钮、下拉框和复选框，**极大降低了用户的使用门槛**。

3.  **AI 通信与逻辑模块（核心引擎）**
    *   **职责**：将前端的输入和参数，“翻译”成 AI 能理解的指令（Prompt），并调用 AI API 获取结果。
    *   **关键函数**：`buildSystemPrompt()` 和 `buildUserPrompt()`。前者定义了 AI 的“角色”和任务规则，后者注入了具体的用户文档和参数。
    *   **逻辑链路**：`用户输入 + 参数` → `拼接成系统Prompt和用户Prompt` → `调用DeepSeek API` → `流式接收并解析AI回复`。

4.  **结果展示与交互模块（右侧面板）**
    *   **职责**：优雅地展示 AI 生成的内容，并提供后续操作。
    *   **子模块**：
        *   **状态展示器**：显示加载动画、空状态或最终结果。
        *   **Markdown 渲染器**：使用 `marked` 库将 AI 返回的 Markdown 文本渲染成美观的 HTML。
        *   **思考过程展示器**（条件性）：专门展示 R1 模型的推理链，增加了透明度和可学习性。
        *   **动作按钮组**：“复制”和“导出”提供了结果的使用闭环。

**最值得学习的设计：**
**动态 Prompt 构建系统**。这是本页面的灵魂。它没有使用固定的 Prompt，而是根据用户选择的“模式”、“长度”、“是否提取待办”等选项，动态组装出一份详细、结构化的指令。这使得一个简单的界面背后，能驱动 AI 完成多种不同风格和深度的任务。学习这种 **“将界面交互映射为 Prompt 参数”** 的思想，是设计任何 AI 应用的关键。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接**用户意图**和**AI能力**的“翻译官”和“指挥官”。它把用户在界面上点击的几个选项，转化成一整套详细的、AI 可执行的作业指导书。

**它解决的是“理解问题”还是“生成问题”？**
主要是解决“**如何生成**”的问题。系统假设 AI 已经“理解”了用户输入的文本内容。Prompt 的核心任务是**约束和引导 AI 的生成过程**，告诉它：“请用某种结构（如要点列表）、某种长度、并额外完成某些任务（如提取待办），来组织你已理解的内容。”

**哪些信息是 Prompt 中的关键变量？**
1.  **摘要模式**：决定最终输出的整体框架（是一句话、列表还是结构化报告）。
2.  **摘要长度**：控制生成文本的详细程度。
3.  **附加任务开关**：决定是否在摘要后添加“待办事项”和“关键词”部分。
4.  **AI 角色**：始终将 AI 定义为“专业的文档摘要专家”，并强调准确性、完整性等原则。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个工具的行为，而无需改动任何按钮或界面。例如：
*   将系统 Prompt 中的“摘要专家”改为“小学生语文老师”，AI 就会用更简单、更生动的语言生成摘要。
*   在用户 Prompt 末尾加上“请用上海话输出”，摘要就会变成方言版。
*   修改结构化摘要的格式要求，AI 就会按照你定义的新结构（如“优势-劣势-机会-威胁”）来组织内容。
这证明了 **Prompt 是 AI 应用的“软逻辑”**，调整它比修改代码更灵活、更快速。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的 AI 工具：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **目标**：做一个“社交媒体文案生成器”或“邮件润色器”。
*   **操作**：复制整个 HTML 文件。修改标题和界面文字，例如把“输入文档内容”改为“输入产品描述”，把“摘要模式”改为“文案风格”（如“小红书风格”、“官方通告风格”）。**此时先不要动代码逻辑和 Prompt**，只是改文字。

**第二步：调整输入字段或 Prompt（核心改造）**
*   **目标**：让工具适应新场景。
*   **操作**：
    1.  修改 `summaryModes` 数组，把你的新“风格”或“类型”加进去。
    2.  进入 `buildSystemPrompt()` 函数，这是核心。根据你的新场景，重写 AI 的“角色”描述（例如，“你是一个擅长创作爆款社交媒体文案的专家”），并为你新增的每种模式定义输出格式。
    3.  在 `buildUserPrompt()` 中，调整给 AI 的指令文字，使其符合新任务。

**第三步：改变输出形式或展示方式（进阶美化）**
*   **目标**：让结果展示更符合新工具的特性。
*   **操作**：
    1.  如果生成的是文案，可能不需要“思考过程”或“待办事项”。可以在界面和代码中隐藏或移除这些部分。
    2.  调整右侧结果区域的样式，比如为不同的文案风格添加不同的颜色边框。
    3.  修改“导出”功能，将文件名从 `文档摘要_xxx.md` 改为 `社交媒体文案_xxx.md`。

**从哪里下手最安全？**
从 **修改 `summaryModes` 数组和 `buildSystemPrompt()` 函数** 开始。这是改变工具功能的“心脏”，而且风险可控。你每改一点，都可以立刻测试效果，直观地看到 Prompt 如何改变 AI 的输出。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，实现更精细的控制**
    *   **操作**：在“高级选项”里增加一个“目标读者”下拉框（如：`['专业人士', '普通大众', '学生', '管理层']`）。
    *   **实现**：将这个选项作为变量传入 `buildSystemPrompt()`，在 Prompt 中添加一条指令，如“请确保摘要内容易于被[目标读者]理解”。

2.  **切换或增加 AI 模型/API**
    *   **操作**：在设置弹窗中，除了 DeepSeek，增加对 OpenAI GPT、Claude 或国内其他大模型的支持。
    *   **实现**：复制并修改 `callDeepSeek()` 函数为 `callAIProvider()`，根据用户选择的提供商，改变 `fetch` 请求的 URL、Headers 和 Body 结构。这能让你对比不同模型的效果。

3.  **将单次摘要拆分为“对话式”摘要**
    *   **操作**：增加一个“对话”面板，允许用户基于已生成的摘要继续提问，例如“把第三点解释得更详细些”或“基于此摘要写一个执行计划”。
    *   **实现**：维护一个消息历史数组 `messageHistory`，每次生成摘要或后续提问时，都将对话内容追加进去，然后带着全部历史调用 API。这会将工具从“处理器”升级为“协作者”。

4.  **优化交互体验与可视化**
    *   **操作**：为生成的“关键词标签”设计成可点击的标签云样式；为“待办事项”添加本地勾选保存功能。
    *   **实现**：使用 CSS 美化关键词的展示。将待办事项列表的勾选状态用 `localStorage` 保存，实现一个简单的任务跟踪功能。这能极大提升结果的可用性。

5.  **支持更多文件格式与内容提取**
    *   **操作**：允许上传 PDF、Word 或图片文件，并自动提取其中的文字。
    *   **实现**：集成前端库（如 `pdf.js`、`mammoth.js`、`Tesseract.js`），在文件上传后，先调用这些库进行文本提取，再将提取到的文本填入输入框。这能覆盖更真实的办公场景。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合做事实核查**：AI 摘要可能遗漏或误读原文中的细微事实。它只是提炼，不是验证。对于关键数据，请务必回溯原文。
*   **不适合处理非文本核心的信息**：如果文档的价值在于复杂的图表、公式或特定格式，本工具无法处理这些元素，摘要会丢失关键信息。
*   **不适合完全替代阅读**：对于需要深度理解、品味语言或把握情感色彩的文学作品、重要合同等，AI 摘要只能作为预览，绝不能替代完整阅读。
*   **不适合无网络环境**：所有处理依赖云端 AI API，断网时无法使用。
*   **如果用户想做**：对多篇文档进行对比分析、从文档中生成数据图表、或进行完全私密的离线处理。
*   **应该换用**：专门的文献分析软件、数据可视化工具，或部署在本地私有环境的大模型应用。
