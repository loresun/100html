# 知识碎片/金句提取器 - 帮助文档

---

## 【一】这个网页解决了什么问题？

**使用场景**：当你阅读了一篇长文章、观看了一个长视频，或者整理了大量笔记后，想要快速抓住其中的核心观点、金句，或者将其转化为适合社交媒体（如小红书）传播的卡片式内容时，这个工具可以帮你“一键提炼”。

*   **适合什么情况？**
    *   **学习复盘**：读完一篇深度报告或书籍章节，想摘录核心观点和金句。
    *   **内容创作**：将长视频的字幕、播客文稿转化为可分享的“知识卡片”或“金句集锦”。
    *   **信息整理**：面对杂乱无章的会议记录或笔记，需要快速梳理出结构化大纲。

*   **不适合什么情况？**
    *   **需要精确原文引用**：它生成的是AI提炼和转述的内容，不适合直接作为学术引用。
    *   **处理高度专业或机密文本**：内容会发送到外部AI API，存在隐私风险。
    *   **需要实时对话或深度追问**：它是一个“一次性”的提炼工具，不支持与AI进行多轮交互。

## 【二】使用方式（给第一次接触的人）

1.  **准备输入**：在左侧“原文内容”框中，粘贴你想要处理的长文本。这可以是一篇文章、一段字幕、一份笔记等。
2.  **选择模式**：在“提取模式”下，选择你的目标：
    *   **💎 提取金句**：AI会从原文中摘录或总结出10条精华句子。
    *   **🧩 卡片大纲**：AI会将原文拆解成4-6张适合社交媒体发布的卡片（包含标题、内容和视觉建议）。
3.  **开始提炼**：点击蓝色的 **⚡ 开始提炼** 按钮。
4.  **首次使用需配置**：如果这是你第一次使用，会弹窗要求你输入 **DeepSeek API Key**。你需要先去 [DeepSeek 平台](https://platform.deepseek.com/) 注册并获取API密钥，然后粘贴保存。
5.  **查看结果**：等待片刻（页面会有加载动画），结果会显示在右侧区域。
    *   **金句模式**：以引文卡片的形式展示，每条金句都可以单独复制。
    *   **卡片大纲模式**：以信息卡片的形式展示，每张卡片代表一页内容，并包含视觉建议。

**容易忽略的细节**：
*   **API配置是必须的**：不配置API密钥，功能无法使用。密钥保存在你的浏览器本地，不会上传到别处。
*   **模型选择**：顶部导航栏可以选择“Chat (V3)”或“Reasoner (R1)”模型，后者可能推理能力更强，但速度可能稍慢或成本不同，你可以根据需求尝试。
*   **一键生成图片**：在“卡片大纲”模式下，结果右上角有一个 **一键生成图片** 按钮。点击后，会将当前大纲数据传递给另一个工具（需要该工具页面存在），用于进一步生成视觉卡片。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，像一个流水线工厂：

1.  **输入与配置模块（左侧面板）**
    *   **职责**：接收用户原始材料（文本），让用户选择处理方式（模式），并触发处理流程。它也是整个应用的“控制台”。
    *   **包含**：文本输入框、模式选择按钮、提炼触发按钮、API配置入口、状态栏。
    *   **逻辑**：用户在此完成 **所有准备工作**。

2.  **AI处理引擎（不可见，但最关键）**
    *   **职责**：这是页面的“大脑”。它不直接显示在UI上，但负责将左侧的输入和配置，通过精心设计的指令（Prompt），调用外部AI API，并获得结构化结果。
    *   **逻辑**：`用户输入 + 模式选择` → `组装成特定的Prompt` → `发送给DeepSeek API` → `接收并解析JSON格式的回复`。

3.  **结果展示模块（右侧面板）**
    *   **职责**：将AI返回的原始数据，以美观、易用、符合场景的形式呈现给用户。它负责“包装”和“交付”。
    *   **包含**：空状态提示、加载动画、以及两种模式（金句列表/卡片网格）的展示模板。
    *   **逻辑**：接收AI处理引擎的产出 → 根据结果类型选择对应的UI模板进行渲染 → 提供复制、导出等交互功能。

**最值得学习的设计**：
**“模式”作为核心抽象**。整个应用围绕“金句”和“卡片”两种输出模式构建。这不仅体现在UI上有两个模式按钮，更关键的是，**切换模式会完全改变发送给AI的指令（Prompt）和最终结果的渲染模板**。这种设计让一个工具轻松解决了两个相关但不同的用户需求，代码结构也非常清晰。如果你想做一个多功能的AI工具，这是一个很好的范式。

## 【四】Prompt / AI 逻辑是如何被设计的？

*   **Prompt的角色**：在这个页面中，Prompt是**翻译官**和**任务说明书**。它把用户的“一堆文字”和“想要金句”这个模糊需求，翻译成AI能精确理解的、可执行的具体任务。
*   **解决什么问题**：它主要解决**生成问题**。AI的任务不是理解“这篇文章在说什么”（虽然它需要理解才能生成），而是根据指令**生成**符合特定格式（JSON）和内容要求（金句或卡片）的文本。
*   **关键变量**：
    1.  **角色设定**：`You are an expert editor`（专家编辑）或 `You are a social media content strategist`（社交媒体策略师）。这给了AI一个“人设”，引导其以特定视角思考。
    2.  **任务指令**：`Extract 10 golden quotes...` 或 `Break down the text into a structured outline...`。这是最核心的要求。
    3.  **输出格式**：`Output strictly in JSON format: { “quotes”: [...] }`。这是强制AI返回结构化数据的关键，方便前端代码直接解析使用。
    4.  **用户输入**：`Original Text:\n${input.text}`。这是AI需要处理的原始材料。
*   **如果只改Prompt，不改代码**：
    *   **改变输出内容**：例如，把金句数量从10条改成5条，或者要求卡片大纲必须包含“行动号召”部分。
    *   **改变输出风格**：例如，要求金句“用更口语化的网络语言表达”，或要求卡片标题“全部使用疑问句”。
    *   **改变输出结构**：例如，让AI在JSON中返回一个`summary`字段和一个`quotes`字段。**但请注意**，如果JSON结构变了，前端解析代码（`json.quotes`）就会出错，导致页面无法正常显示。所以改Prompt时，如果涉及结构变化，前端代码也需要相应调整。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径**：

1.  **第一步：复制骨架，替换场景**
    *   保留完整的HTML/CSS/JS框架。
    *   修改标题、描述、图标，将“知识提炼”场景换成你的目标场景，例如：“**会议纪要转待办**”、“**用户反馈分析器**”、“**短视频脚本生成器**”。
    *   此时，界面看起来是你的新工具，但功能还是提炼金句。

2.  **第二步：改造输入和Prompt**
    *   **调整输入**：如果新场景需要不同的输入，修改左侧面板。例如，“用户反馈分析器”可能需要一个“反馈类型”下拉选择框（bug、建议、咨询）。
    *   **重写Prompt**：这是核心。根据你的新场景，重写 `systemPrompt`。例如，对于“会议纪要转待办”，Prompt可能是：`你是一个高效的项目助理。请从以下会议记录中提取出具体的行动项（Action Items）。每个行动项需包含负责人、任务描述和截止时间（如果提及）。以JSON格式输出：{ “action_items”: [ {“owner”: “”, “task”: “”, “due”: “”}, ...] }`。

3.  **第三步：定制化输出展示**
    *   根据AI返回的新JSON数据结构，修改右侧的结果展示模板。
    *   沿用现有的卡片或列表样式，但调整内部字段的展示。例如，展示“行动项”时，可以用标签显示负责人，用红色突出显示临近的截止日期。
    *   增加或修改交互按钮，如“导出为CSV”、“分享到钉钉”。

**从哪里下手最安全？**
从 **第二步的Prompt** 开始。因为修改Prompt是纯文本操作，风险最低。你可以先在DeepSeek的官方Playground里测试你的新Prompt，确保AI能返回你想要的JSON格式。一旦Prompt测试成功，再回头去微调前端输入和输出部分，就会非常有信心。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入选项，提升可控性**：
    *   **具体操作**：在模式选择下方，增加一个“**提炼强度**”滑块或下拉菜单（如：简洁 / 详细 / 完整）。
    *   **如何实现**：将这个选项的值（如 `detail_level: 'concise'`）加入到发送给API的请求体中，并在Prompt里体现，例如：`...请以${detailLevel}的风格进行提炼...`。

2.  **本地缓存历史记录**：
    *   **具体操作**：在左侧面板或新页面增加一个“**历史记录**”区域，自动保存用户每次的输入和结果。
    *   **如何实现**：使用 `localStorage` 或 `IndexedDB` 存储每次 `processContent` 成功后的 `input.text`、`mode` 和 `result`。提供一个列表视图供用户查看和重新加载。

3.  **拆分并优化交互流程**：
    *   **具体操作**：将“配置API”和“选择模型”从顶部导航移到更显眼的位置，或者做成首次使用的引导步骤。
    *   **如何实现**：页面加载后检查 `apiConfig`，如果为空，则自动高亮显示设置按钮或直接弹出引导蒙层，避免用户输入完文本才发现不能用。

4.  **支持多模型/多API供应商**：
    *   **具体操作**：在API设置弹窗中，增加供应商选择（如：DeepSeek, OpenAI, 智谱AI），并根据选择显示不同的API Key输入框。
    *   **如何实现**：扩展 `apiConfig` 对象，包含 `provider` 和不同供应商的 `key`。在 `processContent` 函数中，根据 `provider` 动态构造请求的URL和请求头。

5.  **增加结果后处理与编辑功能**：
    *   **具体操作**：允许用户对AI生成的金句或卡片进行**在线编辑**、**删除**、**重新排序**。
    *   **如何实现**：将 `result.value.data` 变为一个响应式数组，并为每个条目添加“编辑”按钮。点击后，将文本内容变为可编辑的输入框。这能极大提升工具的实用性。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合做精确的事实核查或数据验证**：AI可能会对原文进行概括、转述，甚至产生“幻觉”（生成原文中没有的信息）。它提炼的是“观点”和“结构”，而非“事实”。
*   **不适合处理需要绝对保密的内部文档**：所有输入文本都会通过网络发送到DeepSeek的服务器。**切勿**使用此工具处理公司机密、个人隐私、未公开的源代码等敏感信息。
*   **不适合替代专业的编辑或内容策略师**：对于非常重要的内容（如品牌宣传稿、产品发布文案），AI提炼的结果可以作为初稿或灵感参考，但仍需要专业人员进行审核、润色和最终定稿。
*   **如果需要“对话式”深度分析**：这个工具是“投喂-产出”的单次模式。如果你需要对文章进行层层追问、对比分析、逻辑辩论，应该使用ChatGPT、Claude等产品的对话界面，或者需要改造本工具，加入聊天历史记录功能。

**总结**：这是一个出色的“**内容减负和转译**”工具，擅长将**长**变**短**，将**杂乱**变**有序**。明确它的边界，就能在合适的场景下让它发挥最大价值，并启发你创造出更多解决特定痛点的小工具。
