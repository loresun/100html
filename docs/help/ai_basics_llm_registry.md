# 自定义大模型注册中心 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景**：当你需要同时使用多个不同服务商（如 OpenAI、DeepSeek、通义千问等）的大语言模型时，每个模型都有自己的 API 地址、密钥和参数。这个网页就像一个“模型管理中心”，让你在一个地方统一管理所有模型的配置信息。

**适合情况**：
- 你开发了多个需要调用 AI 模型的网页应用
- 你在不同项目间切换时，不想每次都重新输入 API 密钥
- 你想对比不同模型的参数设置
- 你需要将配置分享给团队成员

**不适合情况**：
- 你只需要使用单一模型，且不打算切换
- 你需要实时监控 API 调用状态或费用
- 你需要复杂的权限管理（多人编辑权限控制）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 服务商信息：名称、API 地址、密钥
- 模型信息：名称、ID、上下文长度、温度参数
- 通过“导入”功能粘贴已有的 JSON 配置

**用户通常会做哪几步操作？**
1. **首次打开**：页面会自动加载预设模板（DeepSeek、OpenAI 等）
2. **选择服务商**：点击左侧列表中的服务商名称
3. **配置服务商**：在右侧填写或修改 API 地址和密钥
4. **管理模型**：在“模型清单”区域添加、修改或删除模型
5. **保存与使用**：所有修改自动保存，其他页面可通过 `localStorage.llm_registry` 读取

**输出结果长什么样？**
- 配置数据以 JSON 格式存储在浏览器本地
- 包含所有服务商和模型的完整信息
- 可以通过“导出配置”按钮复制到剪贴板

**容易忽略的使用细节：**
1. **自动保存**：所有修改都会立即保存，无需手动点击保存按钮
2. **密钥安全**：API Key 输入框是密码类型，但实际以明文存储在本地（浏览器开发者工具可见）
3. **快速模板**：左下角的模板按钮可以一键添加常用服务商
4. **配置检测**：页面会自动检测其他网页留下的配置痕迹

## 【三】核心结构拆解（学习重点）

**页面由四个关键模块组成：**

1. **服务商列表模块（左侧）**
   - **职责**：展示所有服务商，提供快速选择入口
   - **特点**：支持新增、模板导入、显示模型数量

2. **服务商配置模块（右上）**
   - **职责**：编辑当前选中服务商的基础信息
   - **特点**：包含名称、ID、API URL、密钥等核心字段

3. **模型清单模块（右中）**
   - **职责**：管理当前服务商下的所有模型
   - **特点**：每个模型可独立配置参数，支持“设为当前选择”

4. **配置识别模块（右下）**
   - **职责**：自动检测并导入其他页面的配置
   - **特点**：实现配置的跨页面迁移

**输入 → 处理 → 输出 的逻辑链路：**
```
用户操作（点击/输入）
    ↓
Vue 响应式数据更新
    ↓
自动触发 watch 监听
    ↓
保存到 localStorage
    ↓
其他页面读取 localStorage.llm_registry
```

**最值得学习的设计：**
- **数据驱动 UI**：所有界面变化都基于 `providers` 数组的变化
- **响应式计算属性**：`activeProvider` 自动根据选中 ID 找到对应数据
- **本地存储同步**：通过 `watch` 监听数据变化，实现自动保存
- **模块化状态管理**：在单个 Vue 组件内实现了清晰的状态流转

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
这个页面本身不涉及 AI 调用，而是**管理调用 AI 所需的配置**。它解决的是“配置管理”问题，而不是“理解”或“生成”问题。

**哪些信息是关键变量？**
1. **服务商级别**：`baseUrl`（API 地址）、`apiKey`（密钥）
2. **模型级别**：`model.id`（模型标识符）、`temperature`（温度参数）、`contextLimit`（上下文长度）

**如果只改 Prompt，不改代码，会发生什么变化？**
由于这不是一个直接调用 AI 的页面，所以“Prompt”在这里指的是**配置模板**。例如：
- 修改 `providerTemplates` 数组：可以添加新的预设服务商
- 修改模板中的模型参数：可以调整默认的温度、上下文长度
- 这些修改会影响“快速模板”按钮的行为和初始数据

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：替换使用场景（最安全）**
- 保持代码结构完全不变
- 只修改文字描述：把“大模型注册中心”改为“我的 API 密钥管理器”、“数据库连接池”等
- 修改 `providerTemplates` 中的预设数据

**第二步：调整输入字段**
- 在服务商配置中：增加/删除字段（如“区域”、“版本号”）
- 在模型配置中：修改参数类型（如把“温度”改为“超时时间”）
- 保持字段绑定的方式不变：`v-model="fieldName"`

**第三步：改变数据存储方式**
- 修改 `STORAGE_KEY` 常量的值
- 调整保存的数据结构（在 `saveState` 函数中）
- 保持 `localStorage` 的基本使用模式

**第四步：定制化功能**
- 在“快速模板”区域添加你自己的常用配置
- 修改“配置检测”逻辑，适配你的其他应用

4. **改进 UI/UX**

## 【七】这个网页不适合做什么？（边界提醒）

**局限性：**
1. **不是 API 调用工具**：它只管理配置，不能直接发送请求给 AI 模型
2. **没有权限控制**：所有配置以明文存储在本地，不适合多人协作或敏感环境
3. **不支持动态更新**：如果服务商添加了新模型，需要手动添加
4. **缺乏版本管理**：配置覆盖保存，没有历史版本回溯

**如果你需要：**
- **实时调用 AI**：应该使用专门的聊天或代码生成页面
- **团队协作**：应该开发后端服务，实现配置的权限管理和共享
- **监控 API 使用**：需要集成计费系统和调用日志
- **自动发现模型**：需要定期调用服务商的模型列表接口

**学习建议**：这个页面的核心价值在于展示了如何用 Vue 3 的响应式系统构建一个**数据管理界面**。即使你不做 AI 相关开发，这种“列表-详情-编辑”的模式和本地存储的同步机制，可以应用到任何配置管理场景中。
