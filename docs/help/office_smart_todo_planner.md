# 智能待办清单 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景**：
想象一下，你手头有一堆杂乱的待办事项：工作邮件、学习计划、生活琐事、健康目标……它们都挤在你的脑子里或便签上，让你感到焦虑，不知从何下手。这个网页就像一个**私人时间管理教练**，它帮你把这些杂乱的任务“喂”给AI，AI会像一个经验丰富的专家一样，帮你理清思路：哪些事必须马上做？哪些可以放一放？每件事大概要花多久？它们之间有没有先后顺序？

**适合情况**：
- **任务繁杂，需要理清优先级**：当你面对一堆任务，感到无从下手时。
- **需要客观的时间估算**：对自己完成任务的时间没有把握，希望AI给出参考。
- **希望优化日程安排**：想根据自己一天中的高效时段（如上午或晚上）来安排任务。
- **学习时间管理方法**：想直观地看到艾森豪威尔矩阵等经典方法如何应用于自己的任务。

**不适合情况**：
- **需要精确到分钟的日程安排**：它提供的是任务分析和建议，不是日历或日程表。
- **处理高度机密或敏感任务**：任务内容会发送到外部AI API，请勿输入敏感信息。
- **替代专业的项目管理工具**：对于复杂的、多人协作的、有严格时间线的项目，应使用专业工具（如Trello, Asana）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **待办事项列表**：在左侧大文本框中，一行一个任务，例如：
    ```
    完成项目报告
    去超市买菜
    预约牙医
    学习Vue.js第3章
    ```
2.  **分析选项**：几个复选框，决定AI分析哪些方面（如排序、估时、分类等）。
3.  **可用时间与偏好**（可选）：选择你今天有多少空闲时间，以及你在哪个时段效率最高。

**用户通常会做哪几步操作？**
1.  **配置**：首次使用，点击右上角“设置”，填入你的DeepSeek API Key并保存。
2.  **输入**：在左侧文本框里列出你的任务。
3.  **选择**：勾选你希望AI帮你分析的功能（默认全选即可）。
4.  **分析**：点击大大的紫色“开始 AI 智能分析”按钮。
5.  **查看**：等待几秒到几十秒，在右侧查看AI生成的分析报告。

**输出结果长什么样？**
结果是一个结构清晰的Markdown文档，通常包含：
- **艾森豪威尔矩阵**：将你的任务分为“重要紧急”、“重要不紧急”等四类，并附上预计时间和分类标签。
- **今日推荐执行清单**：一个按优先级排好序的任务列表，并解释为什么这样排。
- **任务依赖关系**：指出哪些任务需要先完成另一些任务。
- **时间管理建议**：根据你的任务和偏好，给出几条实用建议。

**有哪些容易忽略的使用细节？**
1.  **API Key是必需的**：不填Key无法使用，点击分析按钮会弹出设置窗口提醒你。
2.  **“深度分析过程”可展开**：结果上方有一个“🧠 深度分析过程（点击展开）”区域，点击可以看到AI思考的中间步骤，这对理解其判断逻辑很有帮助。
3.  **结果可以复制和导出**：分析结果右上角有“复制”和“导出”按钮，可以保存为文本或Markdown文件。
4.  **模型选择影响结果**：在设置中，“DeepSeek R1”模型会进行更深度的推理，分析更细致，但可能稍慢。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

**1. 输入与配置模块（左侧）**
*   **职责**：收集用户的所有原始输入和偏好设置。
*   **包含**：
    *   **任务输入区**：接收纯文本任务列表。
    *   **分析选项区**：一组复选框，本质上是用户向AI“点菜”，告诉它需要提供哪些服务（排序、估时等）。
    *   **时间约束区**：提供额外的上下文信息（有多少时间、什么时候状态好），让AI的建议更个性化。
*   **设计亮点**：将复杂的分析需求拆解成简单的复选框，用户无需理解专业术语（如“艾森豪威尔矩阵”），勾选即可。这是一种优秀的**用户体验抽象**。

**2. AI处理与通信模块（不可见，但最关键）**
*   **职责**：作为用户界面和AI大脑之间的“翻译官”和“信使”。
*   **工作流程**：
    1.  **组装Prompt**：将用户输入（任务文本）、选项（复选框状态）、上下文（时间偏好）按照预定格式，拼接成一个给AI的“请求说明书”（即System Prompt和User Prompt）。
    2.  **调用API**：将组装好的Prompt通过网络发送给DeepSeek AI的服务器。
    3.  **流式接收**：以“流”的形式逐步接收AI的回复，并实时将“思考过程”和“最终答案”分开显示在页面上。
*   **最值得学习的设计**：**“流式响应”处理**。代码没有等AI全部想完再一次性显示结果，而是一边接收一边显示。这不仅能即时给用户反馈（避免长时间白屏等待），还能将AI的“推理过程”和“最终答案”分离展示，增加了透明度和趣味性。

**3. 结果展示与交互模块（右侧）**
*   **职责**：优雅地呈现AI的分析结果，并提供后续操作。
*   **包含**：
    *   **空状态**：引导用户开始操作。
    *   **思考过程面板**：可折叠，默认隐藏，满足好奇和深度学习的用户。
    *   **结果主面板**：使用Markdown渲染，使结果结构化、美观易读。
    *   **操作按钮**：“复制”和“导出”，将结果转化为可持久使用的资产。
*   **设计亮点**：**结果的可操作化**。分析结果不是“只读”的，用户可以复制到剪贴板或导出为文件，真正融入到自己的工作流中。

**逻辑链路**：
`用户输入任务 & 选择选项` → `前端组装成结构化Prompt` → `通过网络发送给AI API` → `流式接收并分离“推理/答案”` → `在界面渲染Markdown结果` → `用户复制/导出结果`

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt的角色**：
在这个页面中，Prompt是**驱动AI工作的完整指令手册**。它不仅仅是一个问题，而是包含了角色设定、任务目标、分析框架、输出格式和具体数据。

**解决的是“理解问题”还是“生成问题”？**
两者都是，但更偏向于**“结构化生成”**。它的核心是让AI理解“如何分析”以及“如何呈现分析结果”。它把开放性的“帮我看看这些任务”变成了一个结构化的分析报告生成任务。

**Prompt中的关键变量**：
1.  **分析要求列表 (`analysisRequirements`)**：由用户勾选的复选框动态生成。这是Prompt中最灵活的部分，决定了AI报告包含哪些章节。
2.  **用户上下文 (`contextInfo`)**：包括时间偏好和可用时间，让AI的建议更具个性化。
3.  **待办事项文本 (`form.todos`)**：最核心的原始数据。
4.  **严格的输出格式**：从 `## 📊 艾森豪威尔矩阵分类` 到 `## 💡 时间管理建议`，这个固定的格式确保了每次输出都结构一致，方便用户阅读和前端展示。

**如果只改Prompt，不改代码，会发生什么？**
你可以彻底改变这个应用的功能，而无需改动一行HTML/JS代码。例如：
*   把“时间管理专家”改成“旅行规划师”，把任务列表改成“想去的景点”，Prompt要求AI按地理位置、游览时间、兴趣点来规划行程——页面就变成了**智能旅行规划器**。
*   把输出格式改成菜谱格式，输入“冰箱里的食材”——页面就变成了**剩菜食谱生成器**。
**Prompt是应用逻辑的“软配置”**，修改它成本最低，效果最直接。

## 【五】如何模仿它，做出你自己的版本？

这是一个安全的“三步模仿法”：

**第一步：保持结构不变，替换核心场景（最安全）**
*   **不要动**：HTML布局、CSS样式、Vue.js数据绑定逻辑、API调用函数。
*   **只需改**：
    1.  页面标题和图标。
    2.  左侧输入区的标题、提示文字和文本框的`placeholder`。例如，把“输入待办事项”改成“输入你的旅行目的地”。
    3.  分析选项的文案。例如，把“优先级排序”改成“按景点类型排序”，把“智能时间估算”改成“估算游览时间”。
    4.  右侧空状态的引导文字。

**第二步：调整输入字段和Prompt（赋予新灵魂）**
*   **修改`form`对象**：在JS代码中，根据新场景增加或删减表单字段。比如旅行规划，可以加“旅行天数”、“预算范围”、“旅行风格（穷游/奢华）”等。
*   **重写`systemPrompt`**：这是最关键的一步。重新定义AI的角色、任务和输出格式。例如，角色变成“资深旅行规划师”，输出格式变成“每日行程安排”、“预算分配”、“必打卡与备选清单”等。

**第三步：改变输出形式或展示方式（优化体验）**
*   **调整结果渲染**：如果新场景的结果更适合用表格、地图或图片展示，可以引入新的库（如图表库）来渲染`result.value`中的数据。
*   **增加新的交互**：比如，在旅行规划结果中，为每个景点增加一个“收藏”按钮。

**从哪里下手最安全？**
从**第一步**开始，只修改文字内容。你会立即得到一个外观完全不同但运行逻辑一模一样的“新”应用。这能给你最大的信心，然后再逐步深入第二步和第三步。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“能量消耗”标签输入**：
    *   **操作**：在“分析选项”区增加一个复选框“标记任务能量消耗（脑力/体力/混合）”。在Prompt中要求AI根据任务的能量消耗类型，结合用户的“时间偏好”，建议在高效时段做脑力活，低效时段做体力活。
    *   **效果**：让日程建议从单纯的时间管理升级到“精力管理”。

2.  **切换为本地模型/其他API**：
    *   **操作**：修改`callDeepSeek`函数中的API端点（`https://api.deepseek.com/v1/chat/completions`）和请求头。例如，换成OpenAI的GPT-4o、Anthropic的Claude，甚至使用Ollama本地部署的模型（端点改为`http://localhost:11434/api/chat`）。
    *   **效果**：获得不同风格或成本的分析，或完全在本地运行保护隐私。

3.  **拆分为“分析”与“执行”两个页面**：
    *   **操作**：将当前页面作为“分析页”。新增一个“执行页”，通过URL参数或本地存储接收分析结果，并将其渲染成一个可交互的清单（每个任务前有复选框，点击可标记完成，并显示进度条）。
    *   **效果**：形成一个完整的“计划-执行”闭环，工具属性更强。

4.  **优化交互：增加任务示例和快捷输入**：
    *   **操作**：在任务输入框旁边增加一个“加载示例”按钮，点击后自动填充几行示例任务。或者，在输入框下方提供几个“快捷标签”按钮（如“5分钟”、“工作”、“健康”），点击后自动在光标处插入对应标签。
    *   **效果**：降低用户的使用门槛，引导用户输入更规范、更利于AI理解的信息。

5.  **增加历史记录功能**：
    *   **操作**：每次分析后，将输入的任务和结果摘要（如第一条建议）保存到`localStorage`中。在页面顶部或新增一个侧边栏，展示历史记录列表，点击可以重新加载当时的分析和结果。
    *   **效果**：方便用户回顾和比较不同日期的计划，使工具更具实用性。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做精确的日历调度**：它不会把你的任务安排到具体的日历时间槽里。如果你需要“下午2点-3点开会”，请使用Google Calendar、Outlook或Fantastical等日历应用。
2.  **不适合处理复杂项目依赖**：虽然它能检测简单的依赖（如“买材料”→“做蛋糕”），但对于大型项目中的关键路径法（CPM）、甘特图等复杂依赖管理，它是无能为力的。请使用Microsoft Project、OmniPlan或ClickUp等专业项目管理软件。
3.  **不是决策替代器**：AI的优先级排序是基于常见逻辑和你的描述进行的**推测**。对于涉及重大利益、价值观或复杂人际关系的任务优先级，它无法替代你的个人判断。请将它的建议视为“参谋意见”而非“最终命令”。
4.  **不是即时通信工具**：分析过程需要网络请求和AI计算时间（几秒到几十秒），无法实现毫秒级响应。不能用于需要实时对话的场景。

**总结**：这个网页是一个出色的**个人任务分析与规划助手**，它擅长将混乱转化为清晰，将直觉转化为计划。它的核心价值在于**利用AI进行结构化思考辅助**。学会它的设计模式，你可以将这种“输入-处理（AI）-结构化输出”的范式应用到无数其他领域。
