# 帮助文档：Webtools 工具箱

## 【一】这个网页解决了什么问题？

这个网页是一个**多功能在线工具箱**，它解决了日常工作和学习中需要快速使用各种小型工具的需求。

**使用场景举例：**
- 你正在组织一场团队活动，需要将20个人随机分成4个小组。
- 你正在学习，想用番茄钟法管理自己的专注和休息时间。
- 你临时需要计算一个复杂的公式，但不想打开专业的计算软件。
- 你想快速记录几笔零散的开销，看看本月花了多少钱。
- 你需要一个简单的待办事项列表来规划今天的工作。

**它适合在什么情况下使用？**
- **临时性需求**：不需要安装软件，打开网页就能用。
- **轻量级任务**：处理简单的计算、计时、记录等。
- **多场景切换**：一个页面内集成了多种工具，方便切换。
- **数据仅需短期保存**：数据保存在浏览器本地，关闭页面可能会丢失（除非工具支持导出）。

**它不适合什么情况？**
- **复杂专业计算**：如工程计算、财务建模，应使用专业软件（如Excel、MATLAB）。
- **长期数据存储**：重要的待办事项、记账数据应使用更专业的应用（如Todoist、随手记），并确保云同步。
- **高精度计时**：如体育比赛计时、科学实验，需要更精确的计时器。
- **团队协作**：所有数据仅在本地，无法多人共享和编辑。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
页面加载后，你会看到一个整洁的工具界面。输入内容完全取决于你**当前选中的工具**。例如：
- 在“随机分组器”中，你需要输入“名单”和“组数”。
- 在“记账工具”中，你需要输入“金额”、“分类”和“备注”。
- 在“公式计算器”中，你需要输入公式要求的各个参数。

**用户通常会做哪几步操作？**
1.  **选择工具**：从左侧的工具列表中点击你想用的工具（如“随机分组”、“番茄钟”、“笔记”）。
2.  **填写输入**：在工具主区域，根据提示填写必要的输入框。
3.  **执行操作**：点击工具对应的按钮（如“生成结果”、“开始”、“记录一笔”）。
4.  **查看结果**：结果会立即显示在输入区域下方。
5.  **（可选）管理结果**：对于列表类工具（如待办、记账），你可以勾选完成或删除条目。

**输出结果长什么样？**
输出形式多样，但都设计得清晰易读：
- **文本/数字结果**：通常在一个有边框的卡片内，用大号字体突出显示。
- **列表结果**：以整洁的列表项展示，每项可能包含描述和数值。
- **计时器**：以大型数字显示倒计时或已用时间。

**有哪些容易忽略的使用细节？**
1.  **数据是临时的**：大多数工具的数据都保存在你当前浏览器的本地，**清理浏览器缓存或换一台电脑，数据就没了**。重要数据请手动备份。
2.  **自动保存**：像“笔记”工具，你输入内容时会自动保存（有防抖延迟）。但像“待办清单”，勾选完成后需要工具本身支持自动保存逻辑。
3.  **工具切换**：切换工具时，当前工具的状态和数据会保留，下次切回来还在。
4.  **设置按钮**：页面右上角的齿轮图标是“API配置”，仅当工具需要调用AI（如DeepSeek）时才需要设置，普通工具无需理会。

## 【三】核心结构拆解（学习重点）

这个页面的设计精髓在于 **“一套框架，多种工具”** 的模块化思想。

**页面由哪几个关键模块组成？**
1.  **导航栏模块**：顶部区域，包含返回链接和设置按钮。职责是提供页面导航和配置入口。
2.  **工具展示区模块**：中间的核心区域。职责是**根据当前选择的工具类型，动态渲染对应的界面和逻辑**。
3.  **工具逻辑模块**：这是一个“看不见”的模块，存在于JavaScript中。每个工具类型（`formula`, `timer`, `list`等）都对应着一套预定义的数据结构和函数。职责是定义工具的行为、数据模型和交互函数。

**每个模块承担什么职责？**
- **导航栏**：固定、通用，与具体工具无关。
- **工具展示区**：它是一个“空容器”和“路由器”。它通过 `x-show="tool.type === 'xxx'"` 这样的条件判断，来决定显示哪个工具的子界面。它本身不包含工具的具体HTML，所有工具的UI都是按需加载的。
- **工具逻辑模块**：这是大脑。它定义了：
    - `tool` 对象：包含工具的名字、描述、类型、输入值、结果值等所有状态。
    - 操作函数：如 `calculate()`, `startTimer()`, `addListItem()` 等，用于处理用户交互。

**输入 → 处理 → 输出 的逻辑链路是怎样的？**
以“公式计算器”为例：
1.  **输入绑定**：用户在输入框中输入数字。通过 `x-model.number="tool.values[field.key]"`，输入值被实时绑定到 `tool` 对象的数据模型中。
2.  **触发处理**：用户点击“计算结果”按钮，触发 `calculate(tool)` 函数。
3.  **函数执行**：`calculate` 函数读取 `tool.values` 中的所有输入值，按照预定义的公式进行计算。
4.  **更新状态**：将计算结果赋值给 `tool.result`。
5.  **输出渲染**：因为 `tool.result` 发生了变化，页面中通过 `x-show="tool.result"` 和 `x-text="tool.result"` 控制的部分会自动更新，显示出结果卡片。

**哪一部分是“这个网页最值得学习的设计”？**
**条件渲染与状态驱动的UI**。
整个页面没有为12种工具写12个独立的HTML文件，而是共用一套模板。通过 `tool.type` 这个核心状态变量，配合 `x-show` 指令，像开关一样控制不同工具界面的显示与隐藏。这使得增加一个新工具变得非常容易：只需要在JS中定义好该工具的数据和函数，然后在HTML的“工具展示区”里为它添加一段对应的条件渲染块即可。这种设计极大地提高了代码的可维护性和可扩展性。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：根据提供的代码，此页面集成了AI功能（通过DeepSeek API），但在当前显示的HTML片段中，AI相关的工具界面（如可能存在的“AI对话”、“文本处理”等）并未被渲染出来。设置面板暴露了API配置。以下分析基于这种集成模式。

**Prompt 在这个页面中扮演什么角色？**
Prompt（提示词）是用户与AI模型沟通的“指令”或“问题描述”。在这个工具箱中，当用户使用AI类工具（如“AI写作助手”、“智能总结”）时，用户输入的文本、选择的选项，连同系统预设的指令，会共同组合成一个完整的Prompt，发送给AI API。

**它解决的是“理解问题”还是“生成问题”？**
主要是“生成问题”。例如，用户输入“帮我写一封感谢信”，Prompt的任务是让AI理解这是一封需要生成的正式信件，并据此创造内容。也可能解决“理解问题”，例如用户输入一段混乱的笔记，Prompt要求AI“将其整理成结构清晰的大纲”，这需要AI先理解原文。

**哪些信息是 Prompt 中的关键变量？**
1.  **系统指令**：预设的AI角色和任务框架（如“你是一个专业的翻译”）。
2.  **用户输入**：用户在工具中输入的主要文本内容。
3.  **工具参数**：用户选择的选项（如翻译的“目标语言”、总结的“长度”）。
4.  **上下文**：可能包含的历史对话或之前处理的内容（如果工具支持多轮对话）。

**如果只改 Prompt，不改代码，会发生什么变化？**
AI工具的行为和输出质量会发生**根本性变化**。
- **改变任务**：将系统指令从“翻译”改为“润色”，AI就会从翻译员变成编辑。
- **改变风格**：在Prompt中加入“用幽默风趣的口吻”，AI的生成风格会立刻改变。
- **改变输出结构**：要求“用分点列表输出”和“用一段话输出”，结果格式完全不同。
因此，**优化Prompt是优化AI类工具最直接、成本最低的方法**。代码只负责收集信息和发送请求，而Prompt决定了请求的“质量”和“方向”。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，从复制到创新：

**第一步：复制骨架，替换内容（最安全）**
1.  复制整个HTML、CSS和JS结构。
2.  在JavaScript的`tools`定义数组中，找到你想修改或替换的工具。例如，你不想要“记账工具”，想要一个“习惯打卡器”。
3.  将`ledger`工具的数据结构复制一份，修改`type`（如改为`habit`）、`name`、`desc`，并重新设计`fields`（如将“金额”改为“习惯名称”，“分类”改为“打卡次数”）。
4.  在HTML中找到 `x-show="tool.type === 'ledger'"` 的整个`div`块，复制它，将条件改为 `x-show="tool.type === 'habit'”`，并根据新的数据结构修改其中的输入框和显示逻辑。

**第二步：调整交互逻辑**
1.  在JavaScript中找到操作函数（如`addLedgerEntry`），复制并重命名为`addHabitRecord`。
2.  修改这个函数内部的逻辑，使其符合新工具的需求（例如，不再是累加金额，而是增加打卡计数并记录日期）。
3.  在HTML中，将按钮的 `@click="addLedgerEntry(tool)"` 改为 `@click="addHabitRecord(tool)"`。

**第三步：改变外观和体验**
1.  使用Tailwind CSS类，修改新工具模块的颜色、间距、布局。例如，把按钮从`bg-indigo-600`改成`bg-green-600`。
2.  考虑增加新的UI元素，比如为习惯打卡器增加一个日历视图的显示区域。

**从哪里下手是最安全的？**
从**修改一个现有工具**开始最安全。比如，把“计数器”改造成“喝水提醒器”。保留其“计数”和“清零”的核心逻辑，只改变标签文字、目标设定（如每天8杯水）和外观。这样你只需要改动极小范围的代码，就能得到一个全新的工具，风险最低。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加数据持久化与导出**
    *   **问题**：所有数据存在内存或`localStorage`，无法迁移或备份。
    *   **改造**：为每个列表类工具（待办、记账、笔记）增加“导出”按钮，将数据生成JSON或CSV文件并下载。同时增加“导入”功能，实现数据恢复。
    *   **技术点**：使用 `Blob` 对象和 `URL.createObjectURL` 实现前端文件下载。

2.  **引入更丰富的AI工具**
    *   **问题**：当前AI工具可能比较基础。
    *   **改造**：利用已有的API配置框架，新增如“会议纪要生成器”（上传音频文本->输出纪要）、“代码解释器”（粘贴代码->解释功能）、“旅行规划器”（输入目的地和天数->生成行程草案）。
    *   **技术点**：设计更复杂的Prompt模板，并可能需要处理文件上传（转文本）。

3.  **实现工具间的数据流转**
    *   **问题**：工具之间是孤立的，比如不能在“随机分组”结果出来后，直接一键将分组名单导入到“待办清单”分配给各组。
    *   **改造**：增加一个全局的“剪切板”或“数据暂存区”。在任何工具的结果区域，增加一个“复制到工作区”的按钮。在其他工具的输入区，增加一个“从工作区粘贴”的下拉菜单。
    *   **技术点**：使用一个全局的Vue/ Alpine.js响应式对象来存储共享数据。

4.  **优化移动端体验与离线使用**
    *   **问题**：虽然用了响应式设计，但移动端操作（如小的输入框、按钮）可能仍不便。
    *   **改造**：针对移动端调整布局，例如将某些多列布局在手机上改为垂直堆叠。使用`serviceWorker`将核心页面和JS缓存，实现离线可用（PWA）。
    *   **技术点**：编写`manifest.json`和`service-worker.js`文件。

5.  **增加用户自定义工具**
    *   **问题**：工具是开发者预设的，用户无法添加自己想要的。
    *   **改造**：创建一个“自定义工具生成器”。允许用户通过表单定义工具名称、输入字段（文本、数字、下拉框）、和一个JavaScript公式（用于计算）。系统动态生成这个工具的界面和逻辑。
    *   **技术点**：动态组件渲染、安全的`eval`替代方案（如`Function`构造函数或表达式解析库）。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做专业的项目管理**：它的待办清单过于简单，缺少优先级、标签、子任务、提醒、项目分类和团队协作功能。如果你需要管理复杂项目，请使用 **Trello、Asana、Notion** 等专业工具。
2.  **不适合做正式的财务管理**：记账工具没有分类报表、月度对比、预算设置、多账户管理和数据图表分析。对于个人或家庭财务，请使用 **随手记、MoneyWiz、YNAB**；对于企业，请使用 **用友、金蝶** 等财务软件。
3.  **不适合处理敏感或大量文本**：笔记工具是纯文本且本地存储，没有加密、版本历史、富文本编辑和强大的搜索功能。对于知识管理或敏感记录，请使用 **Obsidian、Notion、OneNote** 或专业的密码管理器。
4.  **不适合作为高可靠性的唯一工具**：由于依赖浏览器环境和本地存储，数据有意外丢失的风险（浏览器崩溃、手动清空缓存）。**切勿**将其作为重要数据的唯一存储点，应定期导出备份。
5.  **不适合进行复杂的科学或工程计算**：公式计算器只能处理预设的简单公式。对于需要自定义复杂公式、矩阵运算、绘图或符号计算的任务，请使用 **Wolfram Alpha、Matlab、Python (NumPy/SciPy)**。
