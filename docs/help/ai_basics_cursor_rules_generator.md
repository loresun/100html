# AI 编辑器规则生成器 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景**：当你使用 Cursor 或 Windsurf 这类 AI 编辑器时，每次都要重复告诉 AI 你的项目偏好（比如“用 Vue 3”、“用中文回复”、“用 Tailwind CSS”），这个过程很繁琐。这个网页帮你把这些偏好打包成一个配置文件，让 AI 编辑器“记住”你的习惯。

**适合情况**：
- 你经常使用 Cursor/Windsurf 进行前端开发
- 你的项目有固定的技术栈偏好（如 Vue + Tailwind）
- 你希望 AI 生成的代码能符合你的项目规范
- 你不想每次对话都重复同样的指令

**不适合情况**：
- 你的项目技术栈经常变化（每次都要重新生成）
- 你需要非常复杂的、条件性的规则（这个工具只支持简单的开关）
- 你使用的是其他 AI 编辑器（如 GitHub Copilot，它有自己的配置文件格式）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 4个复选框：单文件 HTML、Tailwind CSS、Vue 3、中文回复
- 一个文本框：可以输入额外的自定义指令

**用户通常会做哪几步操作？**
1. 根据你的项目习惯，勾选相应的复选框
   - 如果你的项目是单个 HTML 文件，勾选“单文件 HTML 架构”
   - 如果你用 Tailwind CSS，勾选“Tailwind CSS”
   - 如果你用 Vue 3，勾选“Vue 3”
   - 如果你希望 AI 用中文回复，勾选“中文回复”
2. （可选）在“额外指令”文本框中输入你的特殊要求
3. 右侧会自动生成对应的规则文本
4. 点击“复制内容”按钮复制生成的规则
5. 在你的项目根目录创建一个名为 `.cursorrules` 的文件，粘贴进去

**输出结果长什么样？**
```
You are an expert Frontend Developer specializing in Vibe Coding.

# Project Architecture
- SINGLE FILE HTML ONLY. No build steps (npm, webpack, vite).
- All CSS/JS must be included via CDN links in the <head>.
- Do not suggest installing npm packages.
- Keep the structure: <html><head>...</head><body><div id="app">...</div><script>...</script></body></html>

# Styling
- Use Tailwind CSS for all styling.
...
```

**容易忽略的使用细节**
- 规则文件必须放在**项目根目录**，文件名必须是 `.cursorrules`（注意前面的点）
- 勾选“单文件 HTML 架构”后，AI 就不会建议你安装 npm 包了
- “额外指令”文本框的内容会原样添加到规则中，注意格式要清晰
- 复制成功后按钮会短暂显示“已复制!”，然后恢复原状

## 【三】核心结构拆解（学习重点）

**页面由哪几个关键模块组成？**

1. **配置模块（左侧）**
   - 职责：收集用户的偏好设置
   - 包含：4个偏好选项组 + 1个自定义指令文本框
   - 每个选项都有清晰的标题和说明文字

2. **展示模块（右侧）**
   - 职责：实时显示生成的规则，并提供复制功能
   - 包含：代码展示区 + 复制按钮 + 使用说明提示

3. **逻辑模块（JavaScript）**
   - 职责：将用户的选择转换为规则文本
   - 包含：数据绑定、计算属性、复制功能

**输入 → 处理 → 输出 的逻辑链路**
```
用户勾选/输入 → Vue 数据绑定更新 → computed 属性重新计算 → 生成规则文本 → 实时显示在右侧
```

**最值得学习的设计**
- **实时预览**：用户每做一个选择，右侧立即更新，体验流畅
- **关注点分离**：配置、展示、逻辑三个模块职责清晰
- **渐进式增强**：基础功能（勾选+复制）很简单，但可以扩展（自定义指令）

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
这个页面生成的不是直接给 AI 的 Prompt，而是给 AI 编辑器的“规则文件”。这些规则会作为背景知识，影响 AI 的所有后续回答。

**它解决的是“理解问题”还是“生成问题”？**
主要是“理解问题”。它告诉 AI：“请按照这些规则来理解我的需求”，而不是“请生成一个具体的东西”。

**哪些信息是 Prompt 中的关键变量？**
- 项目架构约束（是否单文件）
- 技术栈偏好（Tailwind、Vue）
- 语言偏好（中文）
- 用户自定义的额外规则

**如果只改 Prompt，不改代码，会发生什么变化？**
- 改变规则的具体内容（比如把“用 Vue 3”改成“用 React”）
- 改变规则的严格程度（比如把“优先使用”改成“必须使用”）
- 改变规则的格式（比如添加更多分类、更详细的说明）

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）**

**第一步：保持结构不变，替换使用场景**
- 把“前端开发规则”换成“Python 数据分析规则”
- 复选框改成：使用 Pandas、使用 Matplotlib、添加中文注释、使用 Jupyter 风格
- 输出文件改成 `.cursorrules` 或 `.windsurfrules`（格式不变）

**第二步：调整输入字段或 Prompt**
- 增加更多技术选项：React、Svelte、TypeScript 等
- 增加“严格程度”滑块：从“建议使用”到“必须使用”
- 在 Prompt 中添加更多具体示例

**第三步：改变输出形式或展示方式**
- 增加“预览”功能：展示这个规则下 AI 可能生成的代码示例
- 增加“导出为不同格式”：支持 Cursor、Windsurf、GitHub Copilot 等不同编辑器
- 增加“分享”功能：生成一个链接，别人可以访问你的配置

**最安全的入手点**：从第一步开始，只改文字内容和复选框选项，不改代码结构。

## 【七】这个网页不适合做什么？（边界提醒）

**局限性**
1. **不是代码生成器**：它只生成规则文件，不生成实际代码
2. **规则是静态的**：一旦生成，不会根据上下文动态调整
3. **只适用于特定编辑器**：主要针对 Cursor/Windsurf，其他编辑器可能需要手动转换
4. **无法处理复杂条件**：比如“如果是组件就用 Composition API，如果是页面就用 Options API”

**如果你需要...**
- **生成具体代码**：应该直接使用 Cursor/Windsurf 的聊天功能
- **动态调整规则**：可能需要更复杂的工具，或者直接修改规则文件
- **适用于所有 AI 工具**：需要研究不同工具的配置文件格式，分别生成
- **团队共享规则**：应该将规则文件提交到 Git 仓库，而不是每人单独生成

**记住**：这个工具是“规则的起点”，不是“规则的终点”。复杂的项目可能需要手动编辑生成的规则文件。
