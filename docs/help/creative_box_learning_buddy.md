# 深度学习伙伴 - 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你正在学习一个新概念，比如“量子力学”或“JavaScript闭包”。你打开搜索引擎，得到的是零散的知识点；你问AI助手，它直接给你答案。你感觉自己“知道”了，但并没有真正“理解”。

这个网页就是为解决这个问题而生的。它模拟了一位**苏格拉底式的导师**，在你学习时，不直接告诉你答案，而是通过连续提问，引导你一步步自己思考、建立知识之间的联系。它适合当你**想深入理解一个概念，而不是仅仅获取信息**时使用。例如，准备考试前的深度复习、探索一个全新领域的入门、或者锻炼自己的批判性思维。

**它不适合**需要快速查找事实、寻求操作步骤（如“如何安装软件”）或进行创意写作（如写诗、写代码）的场景。在这些情况下，直接提问的聊天机器人效率更高。

## 【二】使用方式（给第一次接触的人）

1.  **开始**：打开页面，你会看到一个简洁的启动界面。在输入框中写下你想学习的**主题**，比如“区块链原理”或“文艺复兴艺术”。
2.  **对话**：点击“开始探索”后，页面会切换。AI伙伴会向你提出第一个引导性问题（如：“要理解它，你认为我们首先应该从哪里开始呢？”）。
3.  **互动**：在下方的输入框中，**输入你的思考、回答或疑问**，然后发送。AI会根据你的回答，提出下一个问题，如此往复，形成一场探索式的对话。
4.  **输出**：对话会以聊天气泡的形式展示在屏幕上，你的发言在右侧（紫色背景），AI的提问在左侧（灰色背景）。整个对话过程就是你思考的轨迹。
5.  **结束与总结**：
    *   点击“生成学习小结”，AI会基于整个对话，为你整理一份结构化的学习笔记。
    *   点击“重新开始”，可以清空当前对话，回到初始页面。

**容易忽略的细节**：
*   **API密钥**：这个网页需要连接DeepSeek的AI服务。代码默认从浏览器的本地存储中读取一个名为 `global_llm_config` 的配置来获取密钥。首次使用前，你需要通过其他方式（如浏览器控制台）预先设置好这个密钥，否则对话无法进行。
*   **提问技巧**：你的回答越具体、越深入，AI提出的后续问题就越有针对性，学习效果越好。不要只回答“是”或“不是”。
*   **总结时机**：建议在进行了多轮有质量的对话后再生成小结，这样内容会更丰富。

## 【三】核心结构拆解（学习重点）

这个网页可以清晰地分为三个模块，像一个精心设计的舞台：

1.  **启动模块 (`#setup-screen`)**：
    *   **职责**：获取学习目标。它是整个应用的“大门”，只做一件事——让用户输入主题。
    *   **设计亮点**：极简，只有一个输入框和一个按钮，避免任何干扰，让用户快速进入学习状态。

2.  **对话学习模块 (`#learning-screen`)**：
    *   **职责**：承载核心的苏格拉底式教学互动。它本身又包含三个子模块：
        *   **控制栏**：显示当前主题，并提供“总结”和“重置”两个关键操作按钮。
        *   **聊天窗口 (`#chat-window`)**：展示对话历史的“舞台”。这里动态生成和排列用户与AI的消息气泡。
        *   **输入区**：用户进行互动的“麦克风”，包含输入框和发送按钮。
    *   **设计亮点**：**状态驱动的界面切换**。通过显示(`.hidden`类)和隐藏页面区块，实现了从“设置”到“学习”场景的无缝转换，逻辑清晰。

3.  **总结模态框 (`#summary-modal`)**：
    *   **职责**：提供学习成果的“快照”。它是一个浮动在页面顶层的弹出层，在不离开主对话界面的情况下，展示AI生成的总结。
    *   **设计亮点**：**非侵入式反馈**。它通过半透明背景遮罩聚焦用户注意力，总结完成后可轻松关闭，体验流畅。

**逻辑链路**：
`用户输入主题` → `系统记录主题并初始化AI角色（系统Prompt）` → `AI提出第一个问题` → `用户回答` → `系统将对话历史发送给AI API` → `AI根据全部历史生成下一个问题` → `循环...` → `用户请求总结` → `系统基于全部历史请求总结` → `展示总结`。

**最值得学习的设计**：
**“对话历史（`conversationHistory`数组）作为应用状态核心”**。整个应用都围绕这个数组运转：它记录了从系统指令到每一轮问答的所有信息，并每次都将完整的数组发送给AI。这确保了AI拥有完整的上下文，能够进行连贯的、有深度的引导。这是构建复杂对话应用的基础模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

*   **Prompt的角色**：它是AI的“角色设定”和“行为准则”。在这里，Prompt（`systemPrompt`变量）将AI定位为“采用苏格拉底式教学方法的深度学习伙伴”，并明确规定其行为：“不直接回答问题”、“通过提出启发性问题引导”、“保持简洁”、“总是以一个问题结束”。
*   **解决的问题**：它主要解决“**生成问题**”的难题。没有这个Prompt，AI会像一个普通的问答机器人。有了它，AI被“编程”为一个持续的提问者，从而解决了“如何持续引导用户思考”这个交互设计问题。
*   **关键变量**：
    1.  **教学法**：“苏格拉底式”是关键指令。
    2.  **目标**：“引导用户自己思考和探索”设定了交互的目的。
    3.  **格式要求**：“总是以一个问题结束”确保了对话的可持续性。
*   **如果只改Prompt**：整个应用的行为会发生根本性变化。例如，将Prompt改为“你是一个严格的考试官，负责出题和批改”，那么AI就会从引导者变为考核者。将“总是以一个问题结束”改为“请用比喻来解释”，AI就会变成擅长类比讲解的老师。**Prompt是控制AI行为的“软代码”**。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于自己的版本：

1.  **第一步：替换场景与角色（最安全）**
    *   保持所有HTML结构和CSS样式完全不变。
    *   只修改两处文本：网页标题（`<title>`和`<h1>`中的“深度学习伙伴”）和描述语。
    *   **重点修改`systemPrompt`**。例如，你想做一个“创业点子辩论伙伴”，可以将Prompt改为：“你是一个犀利的创业顾问。针对用户提出的创业点子，你不评价好坏，而是提出潜在的风险、未被满足的需求或更强的竞争对手可能如何反击。每次只提出一个最关键的挑战性问题。”
    *   此时，一个全新的“辩论伙伴”应用就诞生了，而前端代码无需任何改动。

2.  **第二步：调整输入与输出形式**
    *   在启动页面，增加新的输入字段。例如，在“创业点子”旁增加一个“目标用户”的输入框。
    *   修改`startLearning`函数，将这些新字段的值也传递给AI（可以拼接到主题中，或作为新的系统消息）。
    *   这一步开始涉及JavaScript逻辑的微调，但结构是稳固的。

3.  **第三步：改变交互与展示**
    *   如果你觉得聊天窗口的形式不适合你的应用，可以修改`#chat-window`的展示方式。例如，对于“辩论伙伴”，可以将AI的挑战性问题用更醒目的“警告框”样式展示。
    *   可以增加新的功能按钮，比如“给我一个反击论点示例”，这需要你新增一个函数，并向AI发送一个特定的Prompt来获取不同风格的回复。

**下手最安全的地方永远是 `systemPrompt` 和界面上的文字**，这能立刻改变应用的本质。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“学习风格”选择**：在启动页面增加下拉菜单，让用户选择“苏格拉底式”、“比喻大师式”、“案例分析式”等。根据选择，动态切换 `systemPrompt` 的内容。这能立即提升工具的个性化程度。
2.  **本地保存对话记录**：使用浏览器的 `localStorage`，在每次对话更新时自动保存 `conversationHistory`。并增加一个“历史回顾”页面或侧边栏，让用户可以查看和继续过往的对话。
3.  **切换AI模型/服务**：将 `API_URL` 和 `API_MODEL` 变量改为可配置的。例如，允许用户选择使用OpenAI的GPT-4或Claude。你可以在设置面板中让用户填入不同服务的API密钥。这能让你比较不同模型的教学效果。
4.  **增加多媒体支持**：改造“学习小结”功能，使其不仅能生成文字，还能请求AI生成一个**思维导图的大纲格式**（如Markdown列表），然后在前端用简单的缩进和连线展示出来，让知识结构可视化。
5.  **优化交互体验**：为AI的“思考”过程添加更丰富的状态提示。例如，当AI在生成问题时，不仅显示“...”，还可以随机显示一些提示语，如“正在思考一个更深层的问题...”、“联系你刚才提到的概念...”。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合快速信息检索**：如果你需要立刻知道“爱因斯坦的生日”或“Python列表排序的语法”，请直接使用搜索引擎或标准AI问答工具。本工具的设计目的是慢思考，不是快答案。
*   **不适合生成创意内容**：虽然AI能力强大，但本工具的角色设定（提问者）和交互流程（问答循环）不适用于协同写作、编程或艺术创作。强行使用会效率低下。
*   **不适合替代系统学习**：它是一位优秀的“思考陪练”，但无法替代结构化的课程、教材或实践。它帮助你消化知识，但不能无中生有地建立完整的知识体系。
*   **技术局限性**：其效果严重依赖于所选AI模型的理解和推理能力，以及网络稳定性。对于高度专业或前沿的领域，AI可能会提出不准确或肤浅的问题。

**如果你想做的是**：一个能直接解答问题、编写代码、润色文章的工具，你应该寻找或构建一个**指令响应型**的聊天界面，其核心是一个简洁的用户请求Prompt，而非本应用中的“引导式”系统Prompt。
