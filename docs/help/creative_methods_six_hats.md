# 六顶思考帽分析工具 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你需要对一个商业决策、产品方案或待解决问题进行全面评估时，这个工具能帮你快速获得多角度的分析。比如，团队在讨论“是否要推出订阅制会员”时，常常会陷入单一视角的争论。这个工具能一次性提供六个不同维度的思考，让你看到问题的全貌，避免思维盲区。

**适合情况：**
- 个人或小团队在决策前需要结构化思考
- 需要快速获得不同角度的观点和提问
- 希望将复杂的思考过程可视化呈现
- 作为头脑风暴的启动工具

**不适合情况：**
- 需要深度数据分析和定量计算
- 涉及高度专业领域（如法律、医疗）的最终决策
- 实时协作讨论（这是单机工具）
- 替代真实的团队讨论和共识形成

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **选择模式**：从“战略决策”、“产品评估”、“问题解决”中选择一个
2. **议题/方案**：填写你要分析的具体内容，比如“是否要推出订阅制会员”
3. **背景补充（选填）**：提供相关数据、限制条件等额外信息

**用户通常会做哪几步操作？**
1. 在左侧面板填写你的分析需求
2. 点击“生成六帽分析”按钮
3. 等待AI生成结果（约10-30秒）
4. 查看右侧生成的六个思考帽分析
5. 如有需要，点击“导出为图片”保存结果

**输出结果长什么样？**
结果会以六个彩色卡片的形式展示，每张卡片代表一顶“思考帽”：
- **白帽**（灰色背景）：事实与数据
- **红帽**（粉色背景）：直觉与情感  
- **黑帽**（深灰背景）：风险与问题
- **黄帽**（黄色背景）：价值与机会
- **绿帽**（绿色背景）：创意与方案
- **蓝帽**（蓝色背景）：过程与控制

每个卡片包含：观点摘要 + 2-3个关键提问。最后还有一个“综合建议”部分。

**容易忽略的使用细节：**
1. **API设置**：第一次使用前，需要点击右上角“API设置”配置你的AI API密钥
2. **模式选择**：不同模式会微调AI的思考方向，但核心六帽结构不变
3. **背景补充**：这里的信息会直接影响AI的分析深度，填得越具体越好
4. **导出功能**：只有在生成结果后才能使用“导出为图片”

## 【三】核心结构拆解（学习重点）

这个页面由**四个关键模块**组成：

**1. 配置与输入模块（左侧面板）**
- **职责**：收集用户的分析需求
- **包含**：模式选择器、议题输入框、背景补充框、生成按钮
- **设计亮点**：将复杂输入简化为三个核心字段，降低使用门槛

**2. AI处理引擎（JavaScript逻辑）**
- **职责**：将用户输入转化为AI能理解的Prompt，调用API，解析返回结果
- **关键函数**：`callModel()`负责API通信，`generate()`负责流程控制
- **设计亮点**：使用JSON作为AI输出格式，确保结构一致性

**3. 可视化展示模块（右侧面板）**
- **职责**：将AI返回的结构化数据以美观的卡片形式展示
- **包含**：六帽卡片网格、综合建议区域、原始数据展示（备用）
- **设计亮点**：通过颜色编码（bg-slate-50等）直观区分不同思考帽

**4. 系统设置模块（弹出层）**
- **职责**：管理API配置，支持不同AI服务商
- **包含**：DeepSeek配置、自定义API配置
- **设计亮点**：配置本地存储，用户设置一次即可长期使用

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入 → 拼接Prompt → 调用AI API → 解析JSON → 应用颜色映射 → 渲染卡片
```

**最值得学习的设计：**
**“结构化Prompt + 强制JSON输出”** 的组合。这个设计确保了：
1. AI输出始终是机器可解析的格式
2. 前端展示代码可以稳定运行，不会因为AI的“自由发挥”而崩溃
3. 用户获得的是标准化、可比较的分析结果

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演的角色：**
Prompt是**翻译官**和**格式控制器**。它将用户的自然语言需求，翻译成AI能执行的“六顶思考帽分析任务”，并强制AI按照特定格式输出。

**解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**。AI不需要“理解”六顶思考帽的深层理论，只需要按照给定的格式和角度“生成”相应的内容。Prompt把复杂的思维框架简化为一个填空任务。

**Prompt中的关键变量：**
1. **议题内容**：用户输入的`this.topic`
2. **补充信息**：用户输入的`this.context`
3. **模式提示**：根据`this.mode`选择的`HAT_HINTS`中的提示语
4. **输出格式**：严格的JSON结构定义

**如果只改Prompt，不改代码，会发生什么变化？**
1. **改变分析角度**：可以把“六顶思考帽”换成“SWOT分析”、“5W1H”等其他框架
2. **调整输出深度**：可以要求AI提供更多问题、更详细的建议
3. **改变语言风格**：可以让AI用更正式或更轻松的语气输出
4. **增加特定约束**：比如“请从初创企业角度思考”、“请考虑预算限制在10万内”

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 最小改动：只改标题、描述和Prompt中的“六顶思考帽”为其他分析框架
- 例如：改为“SWOT分析工具”、“决策矩阵评估器”
- 此时只需修改HTML中的文字和JavaScript中的Prompt模板

**第二步：调整输入字段或Prompt**
- 根据新场景增加/减少输入字段
- 例如：做“用户画像生成器”可以增加“年龄”、“职业”、“使用场景”等字段
- 修改Prompt模板，让AI按照新框架输出

**第三步：改变输出形式或展示方式**
- 调整右侧的展示布局
- 例如：SWOT分析可以用四个象限展示，而不是六张卡片
- 修改颜色方案、布局结构

**从哪里下手最安全？**
从**修改Prompt模板**开始最安全。在`generate()`函数中找到`userPrompt`变量，先尝试：
1. 把“六顶思考帽”换成其他框架名称
2. 调整JSON结构中的字段名
3. 测试AI是否能正确响应

这样可以在不破坏前端代码的情况下，验证核心功能是否可行。

## 【六】3–5个可直接尝试的改造方向

**1. 增加“角色扮演”输入**
- **操作**：在输入区域增加“分析视角”选择，如“CEO视角”、“产品经理视角”、“用户视角”
- **实现**：在Prompt中加入“请从[视角]的角度进行分析”
- **效果**：让分析更具针对性，适合不同岗位的使用者

**2. 改为多轮对话式分析**
- **操作**：将一次性生成改为逐步生成，每次生成一顶“帽子”的分析
- **实现**：将`generate()`函数拆分为6次API调用，每次聚焦一个角度
- **效果**：降低单次请求的token消耗，允许用户中途调整方向

**3. 集成多个AI模型对比**
- **操作**：在设置中允许选择多个模型，同时或依次调用
- **实现**：修改`callModel()`支持多模型，结果并排展示或标签切换
- **效果**：用户可以看到不同模型的分析差异，选择最合适的

**4. 增加“历史记录”功能**
- **操作**：在页面底部增加历史分析列表
- **实现**：使用`localStorage`存储每次的分析输入和结果摘要
- **效果**：用户可以回顾之前的分析，建立个人决策知识库

**5. 优化为团队协作工具**
- **操作**：将单机工具改为可分享链接的协作工具
- **实现**：为每个分析生成唯一ID，使用URL参数传递
- **效果**：团队成员可以查看同一份分析，并在基础上评论补充

## 【七】这个网页不适合做什么？（边界提醒）

**局限性说明：**

1. **不适合做最终决策工具**
   - 这个工具提供的是**思考角度**，不是**决策答案**
   - AI的分析基于公开知识和模式识别，可能忽略特定行业的隐性知识
   - **如果要做重大决策**：应该结合专家咨询、数据分析和团队讨论

2. **不适合处理高度专业领域问题**
   - 对于法律、医疗、金融等专业领域，AI可能提供不准确或危险的建议
   - **如果需要专业分析**：使用专门的行业分析工具或咨询专业人士

3. **不适合替代深度研究**
   - 工具给出的“事实”（白帽）可能不完整或过时
   - **如果需要全面事实**：应该进行系统的市场调研、用户访谈、数据分析

4. **不适合实时动态场景**
   - 分析结果是静态的，基于输入时的信息
   - **如果需要实时分析**：应该使用专门的BI工具或实时数据看板

5. **不适合创意发散阶段的头脑风暴**
   - 虽然绿帽提供创意，但受限于AI的“平均化”思维
   - **如果需要突破性创意**：应该进行真正的头脑风暴、设计冲刺等工作坊

**核心提醒：**
这个工具的最佳定位是“**思考启动器**”和“**视角提醒器**”。它帮你快速打开思路，看到可能忽略的角度，但真正的深度思考、专业判断和团队共识，还需要人的参与。
