# Offer 对比与谈薪话术 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你收到多个工作录用通知（Offer），需要快速、清晰地比较它们的优劣，并希望获得专业的谈薪建议时，这个工具就派上用场了。它特别适合在以下情况使用：
*   **决策困难期**：面对2-3个各有优劣的Offer，难以抉择。
*   **谈薪准备期**：需要与HR进行薪资谈判，但不知道如何开口、如何争取。
*   **信息整理期**：Offer信息杂乱（薪资、福利、地点等），需要一个结构化的对比视图。

**适合谁用？**
*   正在求职的职场新人或资深人士。
*   需要客观建议来辅助决策的人。
*   不擅长谈判，希望获得话术模板的人。

**不适合什么情况？**
*   **单一Offer决策**：如果你只有一个Offer，且核心问题是“接不接”，而不是“选哪个”，这个工具的分析价值会降低。
*   **复杂法律/财务咨询**：它不提供具有法律效力的合同审查或详细的税务规划。
*   **完全依赖AI做决定**：它提供的是基于你输入信息的分析和建议，最终的职业决策仍需你结合自身情况判断。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
页面左侧有四个输入框：
1.  **Offer信息**：把每个Offer的关键信息（公司、岗位、薪资、福利、地点）逐行写进去。
2.  **个人优先级**：用“>”符号排出你最看重的因素，比如“成长性 > 薪资 > 稳定性”。
3.  **当前/期望薪资**：写明你现在的工资和你期望的底线。
4.  **谈薪底线与顾虑**：写下你在谈判中绝对不能退让的点，以及你的担心。

**用户通常会做哪几步操作？**
1.  **填写信息**：在左侧表单中，尽可能详细地填写你的Offer和个人情况。
2.  **点击生成**：点击绿色的“生成对比与话术”按钮。
3.  **查看结果**：在右侧“分析结果”区域，等待并查看AI生成的分析报告。
4.  **使用结果**：你可以复制话术、导出文本，或者根据分析调整你的谈判策略。

**输出结果长什么样？**
生成的结果是一份结构清晰的Markdown文档，通常包含：
*   **一个对比表格**：直观展示各Offer在薪资、成长、地点等方面的优劣。
*   **关键权衡与推荐**：根据你填写的“优先级”，给出倾向性建议。
*   **谈薪策略**：告诉你谈判的底线、可以争取的点以及沟通节奏。
*   **话术模板**：提供可直接使用的邮件和电话沟通范例。
*   **风险提示**：提醒你可能忽略的风险和备选方案。

**有哪些容易忽略的使用细节？**
*   **细节决定质量**：在“Offer信息”里写得越具体（例如：“年终奖3个月”、“有期权但分4年归属”、“试用期6个月薪资打8折”），AI的分析就越精准。
*   **优先级是关键**：“个人优先级”是AI为你做推荐的核心依据，一定要认真填写。
*   **先配置后使用**：第一次使用时，需要点击右上角的设置按钮，填入你自己的DeepSeek API Key，否则无法生成内容。
*   **深度思考过程**：如果选择了“R1”模型，结果区域会有一个可展开的“深度思考过程”板块，展示了AI的分析逻辑，这对理解其推荐理由很有帮助。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个核心模块：

**1. 输入配置模块（左侧面板）**
*   **职责**：收集用户所有的原始信息和偏好设置。它是整个应用的“数据源”。
*   **组成**：四个表单字段（`offers`, `priorities`, `salaryRange`, `concerns`）和操作按钮（生成、清空）。
*   **设计亮点**：表单设计极度简洁，只问最关键的问题，降低了用户的使用门槛。

**2. AI处理与输出模块（右侧面板）**
*   **职责**：展示AI的“思考”和“创作”结果。它是应用价值的“呈现区”。
*   **组成**：结果展示区、操作区（复制、导出）、以及可选的“深度思考过程”抽屉。
*   **设计亮点**：使用 `marked.js` 库将AI返回的Markdown文本实时渲染成美观的HTML，使专业报告阅读体验更佳。

**3. 系统控制模块（设置浮层）**
*   **职责**：管理应用的“大脑”（AI模型）和“思维方式”（Prompt）。它是应用的“后台控制台”。
*   **组成**：API Key输入框、模型选择器、自定义提示词框。
*   **设计亮点**：将技术配置（API Key）和业务定制（提示词）分离，并通过本地存储（`localStorage`）保存，提升了用户体验的连贯性。

**逻辑链路：**
**输入**（用户填写表单）→ **处理**（点击按钮，前端将表单数据+Prompt模板拼接，通过API发送给AI）→ **输出**（前端流式接收AI回复，并实时渲染到页面）。

**最值得学习的设计：**
**“流式处理”与“状态分离”**。页面在调用AI时采用了“流式传输”（`stream: true`），这意味着AI生成一个字就显示一个字，用户无需漫长等待。同时，它将AI的“最终答案”（`content`）和“思考过程”（`reasoning`）作为两个独立的数据流接收和保存，既给了用户简洁的结果，又保留了透明的推理路径，这种设计在需要解释性的AI应用中非常高级。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接“用户输入”和“AI能力”的**翻译官**和**任务指挥官**。它把用户零散的信息（几个文本框）翻译成一个结构化的、AI能理解的复杂任务。

**它解决的是“理解问题”还是“生成问题”？**
两者兼有，但更偏向**“生成问题”**。它的核心任务是：**“请你根据我提供的这些信息，生成一份包含特定章节的专业报告。”** 它首先确保AI理解上下文（“你是谈薪顾问”），然后给出明确的输出指令（“输出Markdown，结构包含1,2,3,4,5”）。

**哪些信息是 Prompt 中的关键变量？**
Prompt 中动态变化的部分（即从表单获取的）是关键变量：
*   `{this.form.offers}`
*   `{this.form.priorities}`
*   `{this.form.salaryRange}`
*   `{this.form.concerns}`
*   `{this.promptConfig.custom}`（来自设置的自定义追加指令）

**如果只改 Prompt，不改代码，会发生什么变化？**
AI 的**输出内容和风格**会立刻改变。例如：
*   在“自定义提示词”里追加“**话术请更强势一些**”，那么生成的话术模板语气就会变得更坚定。
*   把Prompt里的“输出结构”从5部分改成3部分，那么AI生成的报告就会只包含你指定的那3部分。
*   把开头的“你是求职谈薪顾问”改成“你是职业规划师”，那么AI回复的视角和侧重点也会随之变化。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的AI工具：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **目标**：先做出一个能跑通的“新外壳”。
*   **操作**：
    1.  修改网页标题和Logo文字（如改为“旅行路线规划器”）。
    2.  将左侧输入框的标签和提示语全部换掉（如“Offer信息”改为“目的地列表”，“个人优先级”改为“旅行偏好”）。
    3.  修改右侧输出区域的标题（如“分析结果”改为“行程规划报告”）。
    4.  此时先**不要动**JavaScript核心逻辑和Prompt。

**第二步：调整输入字段与核心Prompt**
*   **目标**：让AI处理你的新问题。
*   **操作**：
    1.  在 `buildPrompt()` 函数中，重写那个固定的提示词模板。用你的新场景替换旧描述，并定义你想要的输出结构。
    *（例如：“你是一名旅行规划师。请根据目的地和偏好，输出行程规划，使用中文，输出Markdown...输出结构：1)每日行程表 2)预算估算 3)注意事项...”）*
    2.  根据新Prompt的需要，回头微调左侧的表单字段，增加或删除输入项。

**第三步：改变输出形式或交互体验**
*   **目标**：优化，让它更符合你的需求。
*   **操作**：
    1.  修改结果区域的导出功能，比如将“导出TXT”改为“导出PDF”（需要引入新库）。
    2.  调整UI颜色、布局，让界面风格更贴合你的主题。
    3.  可以增加一个“历史记录”功能，将每次生成的结果保存下来。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加结构化输入，提升分析精度**
    *   **操作**：将“Offer信息”这个大文本框，拆分成针对每个Offer的多个小表单（公司、月薪、年终奖、股票、年假等）。这样前端可以先将数据整理成更结构化的JSON，再传给AI，能极大减少AI的解析错误，让对比更精准。

2.  **切换或扩展AI模型后端**
    *   **操作**：在设置面板中，除了DeepSeek，增加对OpenAI GPT、Claude或国内其他大模型（如通义千问、智谱）的支持。只需修改 `streamChat` 函数中的API地址、请求头和参数格式即可。这能让用户根据成本、速度、效果选择最合适的模型。

3.  **拆解流程，打造多步骤向导**
    *   **操作**：将单页应用改为多步骤表单。例如：
        *   **步骤一**：收集所有Offer详细信息。
        *   **步骤二**：填写个人偏好与优先级。
        *   **步骤三**：预览AI生成的对比报告。
        *   **步骤四**：基于报告，生成定制化谈薪话术。
    *   **好处**：用户体验更引导性，尤其适合信息量大的复杂决策。

4.  **优化交互，增加即时反馈与示例**
    *   **操作**：
        *   在每个输入框下方增加一个“查看示例”的链接，点击后可以填充示例数据，帮助用户理解该怎么填。
        *   在用户点击“生成”后，除了按钮变灰，可以将左侧表单也轻微禁用或半透明化，并给出更明确的进度提示（如“正在分析A公司与B公司的福利差异...”），提升等待体验。

5.  **引入简单计算，辅助AI分析**
    *   **操作**：在将数据发送给AI之前，前端先做一些基础计算。例如，自动计算每个Offer的“年度总包”（月薪*12 + 年终奖），并将这个计算结果也放入Prompt中。这样AI就能直接基于更准确的数据进行高阶分析，而不是自己算数。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合做最终的合同审查**：AI生成的话术和建议是通用模板，不能替代律师或专业人士对具体劳动合同条款（如竞业协议、知识产权归属）的审查。
*   **不适合处理极端复杂的个性化情境**：如果您的求职情况涉及非常特殊的行业、地域政策、家庭因素或复杂的股权激励，AI基于通用知识的建议可能不够深入。此时应寻求该领域的资深人士或职业咨询师的一对一服务。
*   **不能保证谈判结果**：这个工具提供的是策略和话术，能否谈判成功取决于市场环境、公司政策、面试表现等多种不可控因素。它是一款**辅助决策和准备的效率工具**，而非结果保证器。
*   **不应用于完全自动化的沟通**：生成的话术模板需要您根据实际情况进行修改和润色，切勿直接复制粘贴用于正式邮件或电话，以免显得生硬或不真诚。
