# 会员权益包装器 - 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你负责一个会员项目（比如电商会员、视频会员、健身会员），手上有这些权益：
- 免费配送
- 专属客服
- 生日礼金
- 积分加倍

**问题来了：** 这些“功能列表”很枯燥，用户看了没感觉。你需要为不同场景（拉新、续费、升级）和不同渠道（落地页、短信、公众号）写出有吸引力的文案。

**这个网页就是你的“文案包装工厂”：**
- **适合场景：** 当你需要快速为会员权益生成多版本、多场景的营销文案时
- **典型用户：** 运营人员、营销人员、产品经理、小企业主
- **不适合：** 需要完全原创的文学创作、需要深度品牌调性定制、需要法律合规审核的正式合同

## 【二】使用方式（给第一次接触的人）

### 页面输入是什么？
左侧面板有7个输入区域：
1. **会员等级**：点击选择（普通、银卡、金卡、钻石等）
2. **会员权益**：文本框，每行一条权益
3. **价格信息**：原价和现价（可选）
4. **目标场景**：选择1-5个场景（拉新、续费、升级等）
5. **输出渠道**：选择1-6个渠道（落地页、短信、公众号等）
6. **品牌名称**：你的会员叫什么名字（可选）
7. **额外要求**：特殊要求，比如“要年轻化语言”

### 用户通常会做哪几步操作？
1. **填写核心信息**：选等级 → 输入权益列表 → 选场景和渠道
2. **补充细节**：填价格、品牌名、目标人群（可选）
3. **点击生成**：点击紫色“生成会员卖点文案”按钮
4. **查看结果**：右侧会按场景展示文案，可以切换场景和渠道筛选
5. **复制使用**：点击文案右上角的复制按钮，或导出全部

### 输出结果长什么样？
生成的结果会这样组织：
- **顶部摘要**：显示会员等级、权益数量、价格
- **场景标签**：可以点击切换不同场景
- **文案卡片**：每个渠道生成2个版本，用Markdown格式呈现（有标题、列表、强调）
- **导出选项**：可以复制当前场景或导出全部为Markdown文件

### 有哪些容易忽略的使用细节？
1. **权益输入格式**：一定要每行一条，空行会被忽略
2. **场景最少选1个**：至少要选一个场景才能生成
3. **渠道最少选1个**：至少要选一个渠道
4. **API Key设置**：第一次使用前，点击右上角设置图标，输入DeepSeek API Key
5. **模型选择**：右上角可以切换“快速模型”和“深度模型”，后者会显示思考过程
6. **额外要求**：这里可以写具体风格要求，比如“用emoji”、“突出省钱”

## 【三】核心结构拆解（学习重点）

这个页面由5个关键模块组成：

### 模块1：输入配置面板（左侧）
- **职责**：收集所有生成参数
- **设计亮点**：将复杂的营销需求拆解成直观的选项（等级、场景、渠道）
- **值得学习的设计**：使用“标签式”选择（场景和渠道），比下拉菜单更直观

### 模块2：结果展示区（右侧）
- **职责**：分层展示生成结果
- **子模块**：
  - 会员摘要卡（视觉突出）
  - 场景切换标签（导航）
  - 渠道筛选器（过滤）
  - 文案卡片列表（主要内容）
- **值得学习的设计**：结果按“场景→渠道→版本”三级组织，符合实际工作流

### 模块3：AI调用引擎（JavaScript部分）
- **职责**：构造Prompt → 调用API → 解析结果
- **输入→处理→输出链路**：
  1. 收集所有输入参数
  2. 构建系统提示词（定义AI角色）
  3. 构建用户提示词（结构化描述需求）
  4. 调用DeepSeek API（流式接收）
  5. 解析JSON结果并渲染
- **最值得学习的设计**：Prompt被精心设计成“结构化需求文档”，而不是简单的问题

### 模块4：配置管理系统
- **职责**：保存API Key、模型选择
- **设计亮点**：使用localStorage，配置一次，所有工具共享

### 模块5：交互反馈系统
- **职责**：Toast提示、加载动画、复制功能
- **值得学习的设计**：完整的用户反馈闭环（生成中→成功/失败→复制确认）

## 【四】Prompt / AI 逻辑是如何被设计的？

### Prompt在这个页面中扮演什么角色？
Prompt是**需求翻译官**和**质量控制员**：
- 把零散的用户输入（等级、权益、场景）翻译成AI能理解的“营销任务”
- 确保AI输出的格式、数量、质量符合预期

### 它解决的是“理解问题”还是“生成问题”？
**两者都有，但重点是“质量控制”**：
- **理解问题**：告诉AI“会员权益”和“营销文案”的区别
- **生成问题**：约束AI按特定格式（JSON）、特定数量（每个渠道2版）、特定风格输出

### 哪些信息是Prompt中的关键变量？
Prompt中有几个**结构化变量**：
1. **场景策略映射**：每个场景对应不同的文案策略
   ```text
   - 新用户拉新：强调权益价值、省钱计算
   - 续费提醒：强调权益即将失效、续费折扣
   ```
2. **渠道字数要求**：每个渠道有明确的字数限制
3. **输出格式约束**：严格的JSON结构，包含scene、channel、version、content

### 如果只改Prompt，不改代码，会发生什么变化？
**变化会非常明显**：
- 改**场景策略** → AI对同一场景的文案角度会变
- 改**渠道要求** → 短信可能从40字变成30字，风格更紧凑
- 改**输出格式** → 如果去掉JSON约束，AI可能返回纯文本，页面就无法解析了
- 改**AI角色**：从“营销专家”改成“段子手” → 文案会变得幽默搞笑

## 【五】如何模仿它，做出你自己的版本？

### 安全模仿路径（从易到难）

**第一步：保持结构不变，替换使用场景**
- **最小改动**：只改文字，不改代码
- **操作**：
  1. 把“会员等级”改成“产品套餐”（基础版、专业版、企业版）
  2. 把“会员权益”改成“产品功能”
  3. 把“场景”改成“销售阶段”（售前咨询、试用转化、老客复购）
  4. 把“渠道”改成“内容形式”（产品页、广告语、详情页）
- **效果**：立即得到一个“产品功能卖点包装器”

**第二步：调整输入字段**
- **操作**：
  1. 在HTML中找到输入字段的标签和placeholder，修改文字
  2. 在JavaScript中找到`memberLevels`、`scenes`、`channels`数组，修改里面的选项
  3. 保持变量名不变，只改显示文字
- **示例**：把`scenes`从拉新/续费改成“春节促销/618大促/双11”

**第三步：调整Prompt策略**
- **操作**：
  1. 找到`generateCopy`函数里的`systemPrompt`和`userPrompt`
  2. 修改“各场景策略”部分，定义你的场景策略
  3. 修改“渠道字数要求”，适应你的渠道特点
- **关键**：保持JSON输出格式不变，只改Prompt内容

**第四步：改变输出展示**
- **操作**：
  1. 修改结果区域的标题和图标
  2. 调整文案卡片的样式（颜色、边框）
  3. 修改导出文件的文件名和格式

## 【六】3–5个可直接尝试的改造方向

### 1. 增加“竞品对比”模块
- **具体操作**：
  - 在输入面板增加“竞品权益”文本框
  - 在Prompt中加入：“请突出我们相比竞品的3个优势”
  - 在结果展示区增加“对比优势”标签
- **效果**：文案会自动强调差异化优势

### 2. 增加“情感基调”选择器
- **具体操作**：
  - 增加单选按钮：理性说服/情感打动/紧迫感/稀缺性
  - 在Prompt中加入：“文案情感基调：${selectedTone}”
  - 在额外要求中自动添加对应指令
- **效果**：同一套权益可以生成不同情绪风格的文案

### 3. 支持多模型对比
- **具体操作**：
  - 在设置中增加OpenAI、Claude等API配置
  - 生成时同时调用2-3个模型
  - 结果展示时并列显示不同模型的版本
- **效果**：可以看到GPT-4、Claude、DeepSeek对同一需求的不同理解

### 4. 增加“A/B测试”功能
- **具体操作**：
  - 为每个文案增加“点赞/点踩”按钮
  - 将用户反馈保存到localStorage
  - 在下次生成时提示：“上次用户最喜欢的是XXX风格的文案”
- **效果**：系统会学习你的偏好，越用越准

### 5. 拆分成“工作流”模式
- **具体操作**：
  - 页面1：输入权益，生成核心卖点
  - 页面2：选择场景，生成场景化文案
  - 页面3：选择渠道，适配渠道格式
  - 页面4：批量导出和分享
- **效果**：更适合复杂的多步骤文案创作

## 【七】这个网页不适合做什么？（边界提醒）

### 明确的局限性

1. **不适合生成法律/合规文案**
   - **原因**：AI可能遗漏重要免责声明、条款细节
   - **应该用**：专业法律文档工具+律师审核

2. **不适合深度品牌调性定制**
   - **原因**：Prompt只能定义大致风格，无法深入品牌灵魂
   - **应该用**：品牌手册+资深文案人工创作

3. **不适合超长内容（如白皮书、深度文章）**
   - **原因**：Token限制和上下文长度限制
   - **应该用**：专门的长文生成工具，分段生成

4. **不适合完全替代人工创意**
   - **原因**：AI生成的是“合格线以上”的文案，不是“惊艳”的文案
   - **应该用**：AI生成初稿 → 人工优化点睛之笔

5. **不适合实时/动态数据**
   - **原因**：无法连接实时数据库（如库存、实时价格）
   - **应该用**：API集成方案，动态替换Prompt中的变量
