# 城市微旅行地图 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你突然有半天空闲时间，想在一个城市里走走看看，但又不想做复杂的攻略。这个网页就是你的“即时旅行规划师”。它适合在以下场景使用：
- **临时起意**：朋友突然来访，你想带TA体验城市特色，但只有3小时。
- **碎片时间**：出差间隙、周末下午，想探索新地方但时间有限。
- **灵感获取**：对熟悉的城市感到无聊，想发现新的角落。

**不适合**：
- 需要详细交通、预算、预订信息的完整旅行规划
- 跨城市或多日行程安排
- 对景点有特殊要求（如无障碍设施、亲子友好等）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 城市名称（如“上海”、“北京”）
- 时间段描述（如“下午3小时”、“周末上午”）

**用户通常会做哪几步操作？**
1. 首次使用时，点击右上角齿轮图标，输入你的DeepSeek API Key并保存
2. 在左侧卡片中输入城市和时间
3. 点击“生成路线”按钮
4. 等待几秒钟，右侧卡片会显示生成的6个旅行节点

**输出结果长什么样？**
右侧会显示一个3×2的网格，每个格子是一个“旅行节点”，例如：
- Stop 1: 外滩观景台
- Stop 2: 南京路步行街
- Stop 3: 豫园茶楼
...共6个建议地点

**容易忽略的使用细节：**
- **必须先配置API Key**：否则点击生成会提示错误
- **时间段要具体**：“下午3小时”比“3小时”更好
- **节点是建议顺序**：你可以按顺序走，也可以自由组合
- **刷新页面配置还在**：API Key会保存在浏览器本地

## 【三】核心结构拆解（学习重点）

这个页面由**四个关键模块**组成：

**1. 配置模块（隐藏）**
- **职责**：管理AI API的访问凭证
- **位置**：点击右上角齿轮弹出的浮层
- **逻辑**：用户输入API Key → 保存到本地存储 → 后续请求使用

**2. 输入模块（左侧卡片）**
- **职责**：收集用户的核心需求
- **包含**：城市输入框、时间输入框、生成按钮
- **逻辑**：用户填写 → 点击按钮 → 触发生成函数

**3. 输出模块（右侧卡片）**
- **职责**：可视化展示AI生成的结果
- **包含**：6个节点的网格布局
- **逻辑**：接收AI返回的文本 → 分割成数组 → 按网格展示

**4. AI通信模块（看不见的后台）**
- **职责**：与DeepSeek API对话，获取智能建议
- **逻辑**：拼接Prompt → 发送HTTP请求 → 解析响应 → 更新界面

**最值得学习的设计：**
**“最小可行产品”思维**：整个页面只做一件事——生成6个节点。没有多余功能，输入极简，输出直观。这种“单点突破”的设计让学习和模仿变得非常容易。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演什么角色？**
Prompt是“翻译官”，把用户的简单输入（城市+时间）翻译成AI能理解的详细任务。

**它解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**。系统Prompt已经定义了AI的角色（城市旅行规划师），用户Prompt则提供了具体参数。

**Prompt中的关键变量：**
```text
系统Prompt：你是城市旅行规划师，输出 6 个微旅行节点。
用户Prompt：城市：{city.value}\n时间：{time.value}\n请输出 6 个微旅行节点，适合 3 小时。
```
- `{city.value}`：用户输入的城市
- `{time.value}`：用户输入的时间段

**如果只改Prompt，不改代码，会发生什么变化？**
- 改系统Prompt：改变AI的“人设”，如改成“美食探店达人”
- 改用户Prompt：改变输出格式，如要求“每个节点附带推荐理由”
- 代码完全不用动，但页面功能已经变了

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 目标：先确保能跑通
- 操作：只改文字和Prompt
- 示例：改成“书店探店地图”
  - 标题：“城市书店探索地图”
  - 输入：城市 + 阅读偏好（如“文学”、“社科”）
  - Prompt：“城市：{city}\n偏好：{preference}\n请推荐6家有特色的书店”

**第二步：调整输入字段或Prompt**
- 目标：让应用更贴合你的需求
- 操作：增加/减少输入框，调整Prompt细节
- 示例：增加“旅行主题”下拉菜单
  - 选项：历史、美食、艺术、自然
  - Prompt中加入：“主题：{theme}”

**第三步：改变输出形式或展示方式**
- 目标：优化用户体验
- 操作：改布局、加图标、丰富信息
- 示例：每个节点显示预计停留时间、交通方式图标

**从哪里下手最安全？**
从**修改Prompt**开始！这是零风险、即时见效的改动。改完Prompt，点击生成，立刻能看到变化。

## 【六】5个可直接尝试的改造方向

**1. 增加输入维度，让推荐更精准**
- 增加“旅行人数”选择（单人、情侣、家庭）
- 增加“预算范围”滑块（经济、中等、豪华）
- 在Prompt中加入这些参数

**2. 更换AI模型或API提供商**
- 换成OpenAI GPT：改API端点、请求格式
- 换成本地模型：使用Ollama等本地部署
- 比较不同模型的推荐质量

**3. 拆分成“规划”和“执行”两个页面**
- 页面1：生成路线（现有功能）
- 页面2：查看详情（点击节点展开描述、地图、照片）
- 使用路由或简单跳转实现

**4. 优化交互体验**
- 生成时显示加载动画
- 节点可拖拽重新排序
- 添加“收藏路线”功能
- 一键复制所有节点到剪贴板

**5. 增加实用功能**
- 集成地图API，显示节点实际位置
- 计算节点间步行/交通时间
- 生成可分享的图片或链接
- 添加用户评分/反馈系统

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不是专业旅行规划工具**
   - 缺少：具体地址、开放时间、门票价格、实时交通
   - 如果用户需要这些，应该使用高德/百度地图、大众点评等专业App

2. **不是个性化推荐引擎**
   - 无法学习你的历史偏好
   - 如果用户想要“根据我上次喜欢的路线推荐新的”，需要用户账户和历史数据系统

3. **不是实时信息查询**
   - 所有推荐基于AI的通用知识，可能过时
   - 如果用户需要“今天下午哪个展览人少”，需要实时数据接口

4. **不是协作工具**
   - 无法多人共同编辑路线
   - 如果团队需要一起规划，应该使用飞书文档、腾讯文档等协作工具

**一句话总结：**
这个网页是“灵感生成器”，不是“执行手册”。它帮你快速获得想法，但具体执行需要结合其他工具和你的判断。
