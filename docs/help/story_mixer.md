# 跨界故事合成器 - 帮助与学习文档

---

## 【一】这个网页解决了什么问题？

**使用场景**：当你需要创意灵感，或者想为写作、游戏设计、头脑风暴寻找新颖的题材时，这个工具非常有用。比如，你是一个编剧，想为一部新剧寻找一个“咖啡师”和“宇航员”碰撞出的火花；或者你是一个老师，想用一个有趣的故事来引入一个跨学科的话题。它通过将两个看似不相关的概念（角色和职业）强行组合，激发你的想象力，生成三条简短、有趣的“跨界”故事线。

**适合情况**：
- 快速获取创意种子或故事梗概
- 进行头脑风暴，打破思维定式
- 为短篇创作、角色扮演游戏（RPG）或短视频脚本寻找灵感

**不适合情况**：
- 需要完整、长篇、逻辑严谨的故事创作
- 需要高度定制化、符合特定世界观或历史背景的叙事
- 需要直接用于商业发布的成熟剧本

## 【二】使用方式（给第一次接触的人）

1.  **首次设置**：打开页面后，点击右上角的齿轮图标（⚙️），在弹出的窗口中输入你的 **DeepSeek API Key**（需要自行申请），然后点击“保存配置”。
2.  **输入你的想法**：在左侧的输入框中，分别填写一个“角色”（比如：图书管理员）和一个“职业”（比如：特工）。
3.  **生成故事**：点击“生成故事”按钮。稍等片刻，页面右侧就会出现三个卡片。
4.  **查看结果**：
    - 每个卡片的正面会显示一个故事标题（例如：“午夜档案：图书管理员的秘密任务”）。
    - **将鼠标悬停在卡片上**，卡片会翻转过来，背面会显示该标题对应的简短剧情简介。
5.  **容易忽略的细节**：
    - **鼠标悬停才能看详情**：故事简介藏在卡片背面，需要鼠标放上去才会翻转显示。
    - **API Key 是必须的**：不配置 API Key 就无法生成故事，系统会提示你。
    - **输入可以很天马行空**：不要局限于常规组合，试试“园丁”和“黑客”、“外卖员”和“国王”，可能会有意想不到的惊喜。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

1.  **控制与输入模块（左侧卡片）**
    - **职责**：接收用户的核心创意输入（角色和职业），并触发故事生成流程。
    - **构成**：两个输入框 + 一个生成按钮 + 错误提示区域。
    - **逻辑**：用户输入 → 点击按钮 → 触发 `generate` 函数 → 进入处理流程。

2.  **故事展示模块（右侧三个卡片）**
    - **职责**：以吸引人的交互形式，展示 AI 生成的成果。
    - **构成**：三个具有“翻转”效果的卡片容器。每个卡片正面显示故事标题，背面显示详细简介。
    - **逻辑**：接收处理模块传来的故事数据数组 → 循环渲染三个卡片 → 用户通过悬停与卡片交互。

3.  **配置管理模块（设置弹窗）**
    - **职责**：管理应用的关键外部依赖（API Key 和模型选择），并将配置持久化保存在浏览器本地。
    - **构成**：一个模态弹窗，包含 API Key 输入框和模型下拉菜单。
    - **逻辑**：用户打开设置 → 修改配置 → 点击保存 → 配置被存入 `localStorage` → 后续所有 API 调用使用新配置。

**核心逻辑链路**：
`用户输入 (角色/职业)` → `拼接成特定格式的 Prompt` → `通过配置的 API 发送给 AI 模型` → `接收 AI 返回的文本` → `解析文本，提取标题和简介` → `更新“故事展示模块”的数据` → `渲染出可交互的卡片`。

**最值得学习的设计**：
- **“翻转卡片”的展示方式**：这是一个成本极低但体验极佳的交互设计。它将核心信息（标题）和详细信息（简介）分层，保持了界面的简洁，同时通过悬停触发动画，赋予了结果探索的趣味性，完美匹配了“灵感探索”这一使用场景。
- **配置与功能的分离**：将 API Key 等配置项放在一个独立的弹窗中管理，并使用 `localStorage` 持久化，使得核心功能页面非常干净，也方便用户多次使用。这是构建可配置型 AI 工具页面的一个经典模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt 的角色**：Prompt 在这里是 **“指令翻译官”和“格式约束器”**。它把用户简单的两个词输入，翻译成 AI 能够理解的具体创作任务，并严格规定了 AI 输出的格式，方便后续程序自动处理。

2.  **解决的问题**：它主要解决 **“生成问题”**。系统不需要 AI 去理解“什么是跨界”，这个逻辑已经隐含在工具的设计里了。Prompt 的核心任务是要求 AI 基于给定的两个概念进行创造性生成。

3.  **关键变量**：
    - `角色：${character.value}`：这是第一个创意种子。
    - `职业：${profession.value}`：这是第二个创意种子，与角色形成反差或融合。
    - `输出 3 条跨界故事`：明确数量要求。
    - `格式：\n1. 标题 - 简介\n2. ...`：这是**最关键的部分**，它强制 AI 按照“编号. 标题 - 简介”的格式回答，这样后端的 `JavaScript` 代码才能用 `split(‘ - ’)` 等方法可靠地解析出标题和简介。

4.  **只改 Prompt 的效果**：
    - 如果改成 `请输出 1 条详细的故事大纲，包含起因、经过、高潮、结局`，那么生成的内容会从三条短梗概变成一条长大纲，但**页面会显示错误**，因为代码仍然试图解析成三条“标题-简介”。
    - 如果保持格式不变，只改描述，例如 `请用武侠风格输出 3 条跨界故事...`，那么生成的故事风格会变，但页面能正常解析和显示。
    - **结论**：修改 Prompt 可以极大地改变生成内容的**风格、细节和方向**，但如果改变了输出格式，就必须同步修改解析它的 JavaScript 代码，否则前端无法正确展示。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步替换，最终得到一个属于你的全新工具：

**第一步：替换核心概念与界面文案（最安全）**
- 保持所有代码结构、API调用和卡片交互完全不变。
- 修改页面标题和描述，例如改为 **“奇幻生物生成器”**。
- 将左侧输入框的提示文字从“角色”、“职业”改为 **“生物类型”（如：猫）** 和 **“魔法元素”（如：时间）**。
- 相应地，修改生成按钮上的提示文字。

**第二步：改造 Prompt 与解析逻辑**
- 进入 `generate` 函数，找到 `prompt` 变量。
- 将其内容修改为符合你新主题的指令，例如：`生物类型：${creature.value}\n魔法元素：${element.value}\n请输出 3 种奇幻生物设定，格式：\n1. 生物名 - 特征与能力描述`。
- 因为输出格式从“标题 - 简介”变成了“生物名 - 描述”，所以解析逻辑可能不用大改，但变量名 `title` 和 `detail` 在故事里是合适的，在你的版本里可能改为 `name` 和 `description` 会更贴切，这需要微调 `stories.value` 的映射部分。

**第三步：调整展示模块的视觉提示**
- 找到右侧卡片中显示“故事线”和“剧情简介”的文字，将它们改为 **“奇幻生物 #1”** 和 **“特征描述”**。
- 至此，一个全新的“奇幻生物生成器”就诞生了，它拥有了全新的功能，但保留了原项目稳定的交互模式和代码框架。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“风格”或“语气”选项**：
    - **操作**：在输入模块增加一个下拉菜单，选项如：“轻松幽默”、“黑暗悬疑”、“史诗奇幻”、“科幻硬核”。
    - **改造点**：将这个选项作为变量加入到 Prompt 中，例如：`...请以${mood.value}的风格，输出3条跨界故事...`。这样用户能对生成的故事基调有更强控制。

2.  **将输出从“3条故事”改为“1条详细故事”**：
    - **操作**：修改 Prompt，要求 AI 生成一个包含“背景、人物、冲突、转折、结局”的完整段落。同时，将右侧三个卡片区域改为一个大的、支持滚动的文本框来展示这个长故事。
    - **学习点**：理解如何根据输出内容体量的变化，来调整前端的展示容器和交互方式。

3.  **增加“灵感库”或“历史记录”功能**：
    - **操作**：每次成功生成故事后，不仅显示在右侧，还将“角色-职业”组合以及生成的故事标题列表，保存到 `localStorage` 的另一个键下。在页面底部或侧边栏增加一个区域，列出所有历史生成记录，点击可以重新加载当时的结果。
    - **学习点**：学习更复杂的数据持久化应用，以及如何设计非核心但提升体验的附加功能。

4.  **替换视觉主题与交互动画**：
    - **操作**：修改 `style` 标签中的背景渐变颜色、卡片阴影和边框。将卡片“翻转”动画（`transform: rotateY`）改为“向上滑动”显示详情（`transform: translateY`）或“淡入”效果。
    - **学习点**：在不影响功能逻辑的前提下，通过修改 CSS 来彻底改变产品的视觉风格和感觉，这是前端开发的核心技能之一。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合生成可直接商用的内容**：AI 生成的故事是灵感起点，可能存在逻辑漏洞、陈词滥调或版权不清晰的问题，需要人工深度打磨和原创性审查。
2.  **不适合进行复杂或专业的领域构思**：例如，如果你想生成一个符合真实医学流程的“医生-侦探”故事，或者一个细节准确的“历史学家-程序员”穿越剧情，这个工具过于简单，无法保证专业性。你需要更专业的工具或自行深入研究。
3.  **不适合需要连续对话或深度迭代的场景**：这个工具是“一次性”的生成。如果你希望基于第一个故事，让 AI 继续扩展第二章、第三章，或者根据你的反馈修改某个情节，它无法做到。你需要的是一个具备对话上下文管理功能的聊天机器人式应用。
4.  **不适合无网络环境使用**：其核心能力完全依赖云端 AI API，断网时毫无用处。

**如果你想做上述事情**：
- 对于专业创作，请使用 **Scrivener, Final Draft** 等专业写作软件，并辅以人工研究。
- 对于需要深度迭代，请使用 **ChatGPT, Claude** 等聊天界面直接进行多轮对话。
- 对于离线使用，需要考虑部署本地大模型，这完全超出了当前网页的技术范畴。
