# 营养餐计划 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你需要为一周（7天）规划每日三餐（早、午、晚、加餐）时，这个工具能帮你快速记录和整理。比如：
- 健身爱好者想提前规划一周的健康餐食
- 家长为孩子准备一周的菜单
- 想控制饮食的人记录每日摄入
- 需要根据菜单生成采购清单去超市购物

**适合情况：**
- 个人或家庭的简单餐食规划
- 需要可视化一周饮食安排
- 希望快速生成食材清单

**不适合情况：**
- 需要精确计算卡路里或营养成分
- 多人协作规划（如宿舍、办公室）
- 需要复杂的食谱步骤说明
- 长期（超过一周）的饮食规划

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 点击任意一天的任意一餐（如“周一早餐”）
- 在弹出的编辑框中输入餐食内容

**用户通常会做哪几步操作？**
1. **浏览**：先看整个一周的空白网格
2. **点击编辑**：点击你想规划的餐食格子（如“周二午餐”）
3. **输入内容**：在弹出窗口中输入食物名称（如“鸡胸肉、西兰花、米饭”）
4. **快速添加**：可以使用右侧的常用食材标签快速输入
5. **保存**：点击保存按钮
6. **生成清单**：规划完成后，点击右上角“生成采购单”查看所有食材
7. **复制清单**：将清单复制到剪贴板，带去超市

**输出结果长什么样？**
- 主页面：7×4的网格，显示每天的早、午、晚、加餐内容
- 采购清单：去重后的食材列表，每项前面有个绿色圆点

**容易忽略的使用细节：**
1. **自动保存**：输入的内容会自动保存在浏览器中，刷新页面不会丢失
2. **今日高亮**：当天对应的列会有浅绿色背景提示
3. **清空功能**：右上角垃圾桶图标可以一键清空整周计划
4. **快速标签**：编辑时右侧的“+ 燕麦”等按钮可以快速添加常见食材
5. **空格处理**：输入时用逗号或换行分隔不同食材，系统会自动识别

## 【三】核心结构拆解（学习重点）

**页面由四个关键模块组成：**

1. **控制栏模块**（顶部）
   - 职责：提供全局操作（返回、生成清单、清空）
   - 包含：标题、功能按钮

2. **周视图网格模块**（主体）
   - 职责：展示一周7天×4餐的完整视图
   - 包含：日期标题、餐食卡片、编辑触发区域

3. **编辑弹窗模块**（模态框）
   - 职责：提供餐食内容的编辑界面
   - 包含：文本输入框、快速标签、保存/取消按钮

4. **采购清单模块**（模态框）
   - 职责：展示和导出食材清单
   - 包含：去重后的列表、复制功能

**输入 → 处理 → 输出 的逻辑链路：**
```
用户点击餐食格子 → 打开编辑弹窗 → 输入食材 → 保存到本地存储
↓
用户点击“生成采购单” → 提取所有食材 → 去重处理 → 展示清单
↓
用户点击“复制” → 转换为文本 → 写入剪贴板
```

**最值得学习的设计：**
**数据存储与视图分离**的设计思路。页面将“数据”（`meals`对象）和“视图”（7×4网格）完全分开：
- 数据用 `{ "0_breakfast": "燕麦,牛奶" }` 这样的键值对存储
- 视图通过 `getMeal(dayIdx, typeId)` 函数动态获取数据显示
- 好处：修改数据存储方式不影响视图，反之亦然

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：这个版本**没有使用AI或API**，但我们可以分析它的“逻辑设计模式”，这对理解如何添加AI功能很重要。

**当前逻辑的角色：**
- 解决的是“**整理与展示**”问题，而不是“生成”问题
- 核心逻辑是：从用户输入的文本中提取、去重、组织信息

**如果这是AI版本，关键变量会是：**
1. **用户输入**：饮食偏好、禁忌、目标（减脂/增肌）
2. **约束条件**：预算、烹饪时间、食材可获得性
3. **输出格式**：需要AI按照“食材1, 食材2, 食材3”的格式返回

**如果只改逻辑，不改代码结构：**
- 当前：手动输入 → 简单分割 → 去重展示
- 改为AI：输入需求 → AI生成完整一周食谱 → 自动填充网格
- 只需修改 `generateShoppingList()` 和编辑逻辑，页面结构几乎不变

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 将“营养餐计划”改为“学习计划表”
- 将“早/午/晚/加餐”改为“语文/数学/英语/自习”
- 将“食材”改为“学习内容”
- 这是最安全的开始，因为只改文字，不动代码逻辑

**第二步：调整输入字段或逻辑**
- 修改 `commonDidhes` 数组为你的常用标签
- 调整 `mealTypes` 中的图标和名称
- 例如改成运动计划：`[{ id: 'cardio', name: '有氧', icon: 'heart' }, ...]`

**第三步：改变输出形式或展示方式**
- 修改采购清单的生成逻辑
- 例如学习计划表：生成“本周重点复习内容”
- 或者运动计划：生成“需要准备的装备清单”

**从哪里下手最安全？**
从第19-22行和56-59行开始修改，这些是显示文本，不会破坏功能：
```javascript
// 修改这里：
days: ['周一', '周二', '周三', '周四', '周五', '周六', '周日'],
// 改为：
days: ['第一阶段', '第二阶段', '第三阶段', '第四阶段', '第五阶段'],

// 修改这里：
mealTypes: [
    { id: 'breakfast', name: '早餐', icon: 'coffee' },
    // ...
]
// 改为：
mealTypes: [
    { id: 'planning', name: '规划', icon: 'clipboard-list' },
    // ...
]
```

## 【六】3–5个可直接尝试的改造方向

**1. 增加智能推荐功能**
- **怎么做**：在编辑弹窗添加“智能推荐”按钮
- **技术点**：调用AI API（如OpenAI），Prompt示例：“根据[已输入的早餐]，推荐营养均衡的午餐，只返回食材名称，用逗号分隔”
- **效果**：点击后自动填充合理的餐食建议

**2. 改为协作版本**
- **怎么做**：添加“分享本周计划”功能
- **技术点**：生成分享链接，使用URL参数或简单后端存储
- **效果**：家人可以共同编辑同一周的计划

**3. 增加营养分析**
- **怎么做**：添加“营养概览”面板
- **技术点**：建立食材-营养成分映射表（简易版）
- **效果**：显示本周总蛋白质、碳水、脂肪估算值

**4. 优化采购清单逻辑**
- **怎么做**：识别食材单位（如“200g鸡胸肉”）
- **技术点**：修改 `generateShoppingList()` 中的分割逻辑
- **效果**：合并相同食材并累加数量，而不只是去重

**5. 添加食谱库功能**
- **怎么做**：右侧添加常用食谱面板
- **技术点**：预定义几个完整食谱对象
- **效果**：点击“糖醋排骨套餐”自动填充“排骨、糖、醋、姜...”

## 【七】这个网页不适合做什么？（边界提醒）

**局限性：**
1. **不精确**：只是食材列表，没有分量、烹饪方法、时间
2. **不智能**：不会检查营养均衡性或食物相克
3. **不持久**：数据只存在本地浏览器，换设备就丢失
4. **不协作**：无法多人同时编辑或分享

**如果用户想做X，应该：**
- **需要精确计算卡路里** → 使用“薄荷健康”等专业App
- **需要完整食谱步骤** → 使用“下厨房”等食谱App
- **需要长期饮食记录** → 使用Excel或Notion建立数据库
- **需要专业营养建议** → 咨询营养师，而非使用此工具

**记住**：这个工具的核心价值是**快速规划与可视化**，而不是深度分析或专业指导。它的美在于简单直接，改造时也要保持这个核心优势。
