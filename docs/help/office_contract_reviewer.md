# 合同审查助手 - 帮助与学习指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景**：
想象一下，你正准备签署一份租赁合同、服务协议或劳动合同。面对密密麻麻的法律条文，你既担心错过隐藏的风险条款，又不想为了一份普通合同就花费高昂的律师费。这个网页就像一个“法律风险扫描仪”，帮你快速识别合同中的潜在问题。

**适合情况**：
- **个人用户**：签署租房合同、兼职协议、小额服务合同时，想快速了解风险点。
- **初创团队**：在资源有限的情况下，对供应商合同、保密协议进行初步筛查。
- **学习场景**：法律或商科学生，想了解合同审查的基本框架和常见风险。

**不适合情况**：
- **重大法律事务**：涉及房产买卖、股权投资、知识产权转让等高风险合同。
- **正式法律意见**：需要具有法律效力的审查意见或法庭证据。
- **高度定制化合同**：涉及复杂商业逻辑、特殊行业监管的合同。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **合同文本**：你需要粘贴或上传合同的完整文字内容。
2.  **合同信息**：选择合同类型（如租赁、服务）和你的角色（甲方或乙方）。
3.  **审查重点**：勾选你关心的审查方向，如“高风险条款识别”。

**用户通常会做哪几步操作？**
1.  **粘贴合同**：将你的合同文本复制到左侧的大文本框中。
2.  **配置信息**：在下方选择合同类型和你的立场（例如，作为“乙方”签署服务合同）。
3.  **设置API**：首次使用时，点击右上角“设置”，填入你的DeepSeek API密钥（需要自行申请）。
4.  **开始审查**：点击红色的“开始智能审查”按钮。
5.  **查看报告**：等待片刻，右侧会生成一份结构化的风险分析报告。

**输出结果长什么样？**
审查完成后，你会看到一个**Markdown格式的报告**，通常包含：
- **风险评分**：一个总体的风险等级（高/中/低）。
- **高风险条款清单**：逐条列出最危险的条款，附上原文、风险分析和修改建议。
- **模糊条款**：指出哪些地方表述不清。
- **缺失条款**：提醒这类合同通常该有但没写进去的内容。
- **关键数字核验表**：检查金额、日期等是否合理。
- **整体建议**：最终给出“可以签署”、“谨慎签署”或“不建议签署”的结论。

**有哪些容易忽略的使用细节？**
- **API密钥是必需的**：工具本身不提供AI能力，你需要去DeepSeek官网免费申请一个API Key并填入设置。
- **文件上传只支持纯文本**：只能上传 `.txt` 或 `.md` 文件，不支持PDF或Word。如果是PDF，需要先将其内容转为纯文本。
- **“法律推理过程”可展开**：报告上方有一个可折叠的区域，点击可以查看AI分析合同时的思考过程，这对理解结论很有帮助。
- **结果可以导出**：生成报告后，可以使用“复制”或“导出”按钮将结果保存下来。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个模块，像一个高效的生产线：

1.  **用户输入与配置模块（左侧面板）**
    - **职责**：收集所有必要的审查信息。它把复杂的法律审查，分解为“合同内容”、“背景信息”、“审查偏好”三个简单部分。
    - **输入**：用户提供的原始合同文本和选项。
    - **输出**：一个结构化的数据对象（代码中的 `form` 对象），包含了AI所需的一切上下文。

2.  **AI通信与控制模块（看不见的引擎）**
    - **职责**：管理用户设置（API Key），并负责与DeepSeek API进行“对话”。它处理了最复杂的部分：网络请求、数据流式接收、错误处理。
    - **输入**：配置好的API密钥和用户输入模块产生的 `form` 数据。
    - **处理**：将 `form` 数据拼接成精心设计的 **Prompt（指令）**，然后发送给AI。
    - **输出**：从AI那里接收到的、逐步生成的文本流（`reasoning` 和 `result`）。

3.  **结果展示与交互模块（右侧面板）**
    - **职责**：将AI返回的原始文本，友好、清晰地呈现给用户，并提供后续操作。
    - **输入**：AI生成的原始文本。
    - **处理**：使用 `marked` 库将Markdown文本转换成美观的HTML格式。
    - **输出**：易于阅读的审查报告，以及“复制”、“导出”等实用功能。

4.  **UI与状态管理模块（贯穿始终）**
    - **职责**：管理整个页面的视觉状态和用户体验。例如，加载中的旋转图标、按钮的禁用状态、设置弹窗的开关。
    - **关键设计**：**“状态驱动UI”**。这是最值得学习的设计。页面显示什么（空状态、加载中、完整报告），完全由 `isLoading`、`result` 这几个变量的值决定。这让逻辑非常清晰。

**逻辑链路**：
```
用户输入合同文本和选项 → 点击“审查”按钮 → 前端将输入拼接成Prompt → 调用DeepSeek API → 流式接收AI回复 → 实时更新到页面 → 渲染为格式化的报告
```

**最值得学习的设计**：
**“配置即Prompt”** 的设计思想。整个左侧输入面板，本质上是在让用户为一个复杂的Prompt（系统指令）填写变量。合同类型、用户角色、审查重点，这些选项最终都变成了给AI的精确指令的一部分。这使得AI的输出高度可控、符合预期。

## 【四】Prompt / AI 逻辑是如何被设计的？

- **Prompt的角色**：它是整个应用的 **“大脑编程指令”**。它定义了AI的角色（合同审查专家）、任务（分析风险）、以及最重要的——**输出格式**。没有这个精心设计的Prompt，AI只会返回一段随意的、难以使用的文字。

- **解决的问题**：它同时解决了 **“理解问题”** 和 **“生成问题”**。
    - **理解**：通过系统Prompt告诉AI：“你是专家，合同类型是X，用户角色是Y，要重点看A、B、C”。
    - **生成**：通过严格的Markdown格式要求，强制AI输出结构统一、内容完整的报告。

- **Prompt中的关键变量**：
    1.  `合同类型` 和 `我的角色`：让AI的分析具有针对性。分析“劳动合同”和“租赁合同”的关注点完全不同。
    2.  `审查要求`：来自用户勾选的复选框。这动态调整了AI审查的侧重点。
    3.  `合同文本`：作为用户Prompt的核心内容，是AI分析的具体对象。

- **如果只改Prompt，不改代码，会发生什么？**
    整个应用的功能会彻底改变。例如：
    - 把系统Prompt里的“合同审查专家”改成“广告文案写手”，把用户Prompt里的合同文本改成产品描述，这个工具就变成了一个 **“广告文案优化器”**。
    - 修改输出格式部分，就可以让AI生成表格、清单、邮件草稿等任何你需要的结构化内容。
    - **Prompt是应用的灵魂，前端界面只是收集Prompt参数的“外壳”**。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个安全的“三步替换法”，创建一个全新的AI工具：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标**：先做一个能跑起来的“新外壳”。
- **操作**：
    1.  修改网页标题和导航栏名称，例如改为“**短视频脚本分析助手**”。
    2.  修改左侧输入模块的标签和选项：
        - “合同文本”文本框 → “脚本文本”文本框。
        - “合同类型”单选 → “视频类型”单选（如“产品测评”、“知识科普”、“剧情短片”）。
        - “我的角色” → “创作目标”（如“提升转化”、“增加互动”、“品牌曝光”）。
        - “审查重点”复选框 → “分析维度”复选框（如“检查节奏”、“优化开头5秒”、“标注广告法违禁词”）。
    3.  此时点击按钮，AI还是会返回合同审查报告，但我们已经完成了界面改造。

**第二步：调整输入字段或Prompt（赋予新灵魂）**
- **目标**：让AI执行新任务。
- **操作**：
    1.  找到代码中的 `systemPrompt` 变量。
    2.  彻底重写它：将角色从“合同审查专家”改为“**短视频内容策略专家**”。
    3.  重写输出格式：把“高风险条款”部分改成“**节奏问题点**”，把“缺失条款”改成“**建议添加的爆点元素**”等。
    4.  调整 `userPrompt`，让它引导AI分析“脚本文本”。
    5.  现在，你的工具已经能生成一份“**脚本优化报告**”了。

**第三步：改变输出形式或展示方式（个性化打磨）**
- **目标**：让结果展示更符合新场景。
- **操作**：
    1.  修改结果区域的标题，如“合同审查报告” → “脚本诊断报告”。
    2.  可以调整颜色主题（将代码中所有的 `red` 替换为 `blue` 或 `green`）。
    3.  在导出功能中，修改默认的文件名，如 `合同审查报告.md` → `脚本诊断报告.md`。
    4.  （进阶）如果你希望结果以分栏形式对比原文和建议，可以修改右侧结果区的HTML结构。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“行业”或“地域”输入选项**：
    - **操作**：在“合同信息”部分增加一个下拉菜单，让用户选择“行业”（如科技、餐饮、教育）或“国家/地区”。
    - **效果**：将这些信息加入Prompt，AI可以给出更符合特定行业惯例或地方法律法规的建议，让分析更具针对性。

2.  **切换或支持多个AI模型/API**：
    - **操作**：在设置弹窗中，除了DeepSeek，增加OpenAI GPT、Claude、智谱AI等选项。修改 `callDeepSeek` 函数，使其能根据选择调用不同的API端点。
    - **效果**：用户可以选择自己拥有密钥或更偏好的模型，有时不同模型在不同任务上各有优劣。

3.  **将“单页应用”拆分为“引导式多步流程”**：
    - **操作**：将当前左右分栏的布局，改为多个步骤页面（可使用Vue的动态组件实现）。
    - **步骤1**：上传/粘贴合同。
    - **步骤2**：填写合同背景信息。
    - **步骤3**：选择审查重点。
    - **步骤4**：查看报告。
    - **效果**：对于非常长的合同或复杂选项，流程更清晰，用户体验更专注。

4.  **增加“历史记录”功能**：
    - **操作**：在页面顶部或侧边增加一个“历史”按钮。每次审查后，将 `form` 数据、时间戳和报告摘要保存到浏览器的 `localStorage` 中。
    - **效果**：用户可以回顾之前审查过的合同，方便对比或再次查看，工具实用性大大提升。

5.  **优化交互：实现“边输入边预览”字数或简单统计**：
    - **操作**：在合同文本框下方，实时显示更丰富的统计信息，如“段落数”、“疑似条款数”、“‘甲方’出现次数 vs ‘乙方’出现次数”的简单对比图（可用CSS简单绘制）。
    - **效果**：在AI分析前，用户就能对合同有一个快速的、量化的初步印象，提升工具的“专业感”和交互趣味。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为最终法律决策依据**：这是最重要的限制。AI可能会遗漏关键细节、误解复杂语境，或无法知晓最新的判例和地方法规。任何涉及重大利益的合同，**“仅供参考”后的“务必咨询专业律师”是必须执行的步骤**。

- **不适合处理非文本或格式混乱的输入**：它无法直接解析PDF中的表格、图片、手写注释或盖章。如果合同文本是从PDF转换而来且格式错乱，分析质量会急剧下降。

- **不适合进行深度谈判推演**：它只能基于现有文本进行分析和提出修改建议，无法模拟“如果对方坚持某条款，我可以提出哪些替代方案”这样的多轮谈判策略。

- **如果用户需要的是“合同起草”**：这个工具的核心是“审查”而非“创作”。虽然你可以通过修改Prompt让它尝试生成合同草案，但这远不如使用专门的合同模板库或起草工具可靠。对于起草，你应该寻找能提供标准模板并支持变量填充的工具。

**总结**：把这个网页看作一个强大的“**初筛雷达**”和“**学习辅助**”。它擅长快速发现常见问题、提供分析思路，但不能替代人类专家的最终判断和创造性解决能力。
