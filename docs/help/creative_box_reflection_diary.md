# AI 反思日记助手 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你每天想写日记，但常常不知道写什么，或者只是简单记录流水账。这个网页就像一个“会提问的日记本”，每天自动给你三个有深度的问题，引导你进行真正的自我反思。它还会定期帮你回顾，从零散的记录中发现自己的成长模式和潜在问题。

**适合什么情况：**
- 希望养成每日反思习惯，但缺乏方向感的人
- 想要通过写作进行自我探索和情绪梳理
- 需要定期回顾，从过去的记录中提取洞察
- 喜欢结构化引导，而不是面对空白页发呆

**不适合什么情况：**
- 需要完全自由、无格式的随意书写
- 希望日记绝对私密（数据存储在浏览器本地，但非加密）
- 需要即时、复杂的情绪分析或专业心理咨询

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **自动输入**：每天首次打开，AI会自动生成三个反思问题
2. **你的回答**：在每个问题下方的文本框里写下你的想法

**用户通常会做哪几步操作？**
1. 打开网页 → 看到今天的三个问题
2. 认真思考并回答每个问题
3. 点击“保存今日反思”按钮
4. （可选）月底时点击“生成本月报告”，查看AI分析

**输出结果长什么样？**
- **每日界面**：三个问题 + 你的回答文本框
- **历史记录**：右侧显示过往日记的日期和简短摘要
- **月度报告**：一段结构化的文字分析，包含主题发现、进步识别、模式分析和成长建议

**容易忽略的使用细节：**
1. **数据存储位置**：所有日记都保存在你当前浏览器的本地存储中。换浏览器或清空缓存会丢失数据。
2. **API密钥需要预先配置**：这个页面依赖一个“全局配置”来获取AI API密钥。首次使用前，你需要先在其他页面设置好密钥。
3. **问题每天更新**：如果当天已经生成过问题，刷新页面也不会变。但如果你没保存，回答会丢失。
4. **必须回答所有问题**：只有三个问题都填写了内容，才能保存。

## 【三】核心结构拆解（学习重点）

这个页面由四个清晰模块组成：

**1. 问题生成与展示模块**
- **职责**：每天自动获取三个反思问题，并以美观的形式展示
- **逻辑**：检查本地是否有今日问题 → 有则直接显示 → 无则调用AI生成 → 保存问题到本地
- **关键设计**：使用`localStorage`缓存问题，避免每天重复调用API

**2. 回答收集与存储模块**
- **职责**：提供输入区域，并安全保存用户的回答
- **逻辑**：用户输入 → 验证是否全部填写 → 将“问题+答案”打包 → 存入`localStorage`
- **值得学习的设计**：使用`dataset`属性将问题和答案关联存储，保持数据完整性

**3. 历史记录模块**
- **职责**：展示过往日记的“快照”，方便快速回顾
- **逻辑**：从存储读取所有日记 → 按日期排序 → 显示日期和第一题的摘要
- **设计亮点**：简单的摘要展示（前50字符），平衡了信息量和页面整洁

**4. 月度报告生成模块**
- **职责**：分析一个月内的所有日记，生成结构化洞察
- **逻辑**：筛选本月日记 → 整理成文本 → 发送给AI分析 → 格式化展示结果
- **最值得学习的设计**：**“数据聚合+AI解读”模式**。不是简单罗列日记，而是让AI从多篇日记中发现模式，这是从“记录”到“洞察”的关键跃升。

**整体输入→处理→输出链路：**
```
用户打开页面 → AI生成/加载问题 → 用户回答 → 本地保存
                                      ↓
月底时：聚合本月数据 → AI分析 → 生成报告 → 用户获得洞察
```

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演什么角色？**
它是两个关键环节的“指令手册”：
1. **问题生成环节**：告诉AI“请生成3个独特的、深刻的、用于每日反思的开放式问题”
2. **报告生成环节**：告诉AI如何分析日记，并明确要求四个分析维度

**它解决的是“理解问题”还是“生成问题”？**
两者都有：
- **生成问题**：从零创造三个有质量的反思问题
- **理解问题**：理解一个月日记的内容，并按照特定框架进行分析

**Prompt中的关键变量：**
1. **数量约束**：“3个”问题
2. **质量要求**：“独特的、深刻的、开放式”
3. **格式要求**：严格的JSON数组格式
4. **分析框架**：四个明确的报告部分（主题、进步、模式、建议）
5. **角色设定**：“人生导师”、“数据分析师和个人成长顾问”

**如果只改Prompt，不改代码，会发生什么变化？**
- 改问题生成Prompt → 改变问题的风格、深度、类型（如改为感恩日记问题）
- 改报告生成Prompt → 改变分析的角度和重点（如改为职业发展分析）
- 改角色设定 → 改变AI的“语气”和专业知识领域（如改为“心理咨询师”）

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：替换使用场景，保持核心结构**
- 想一个新场景：比如“每日感恩记录”、“读书笔记”、“健身日志”
- 保持“生成问题→回答→保存→定期报告”的四步结构
- 只修改文字描述和颜色主题

**第二步：调整输入字段和Prompt**
- 修改问题数量：从3个改为2个或5个
- 重写Prompt：例如改为“请生成3个帮助我发现生活中小确幸的问题”
- 调整文本框：可以改为评分滑块、多选项等

**第三步：改变输出形式**
- 报告格式：从段落改为列表、时间线或关键词云
- 历史展示：从文字摘要改为日历视图或情绪图标
- 增加导出功能：添加“导出为PDF”或“分享链接”

**从哪里下手最安全？**
从**修改CSS样式和文字内容**开始。把“反思日记”改成你的主题，调整颜色，这是零风险的第一步。确认页面能正常显示后，再尝试修改Prompt。

## 【六】3–5个可直接尝试的改造方向

**1. 增加情绪标签输入**
- **怎么做**：在每个问题回答旁，添加“情绪选择器”（😊 😐 😢等）
- **价值**：让月度报告不仅能分析文字，还能分析情绪变化趋势
- **技术点**：在保存数据时多存一个`mood`字段

**2. 改为多模型支持**
- **怎么做**：在全局配置中增加模型选择（DeepSeek、GPT、Claude等）
- **价值**：用户可以根据需求选择不同风格的AI
- **技术点**：修改`callApi`函数，根据选择动态改变API端点

**3. 拆分为多页面应用**
- **怎么做**：将“每日记录”和“报告查看”分成两个独立页面
- **价值**：更清晰的专注模式，适合移动端使用
- **技术点**：使用简单的路由（如URL hash）或直接做两个HTML文件

**4. 增加社交分享（匿名化）**
- **怎么做**：添加“分享今日感悟”按钮，自动生成一张美观的卡片图
- **价值**：满足用户的分享欲，同时保护隐私（只分享想分享的部分）
- **技术点**：使用Canvas或第三方库生成图片，调用分享API

**5. 实现数据备份与同步**
- **怎么做**：添加“导出数据”和“导入数据”按钮
- **价值**：解决本地存储的最大痛点——数据易丢失
- **技术点**：使用`JSON.stringify`导出，`FileReader`读取导入

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不适合深度心理治疗**
   - 这个工具是“自我反思助手”，不是心理咨询师
   - 如果你有严重的情绪困扰或心理问题，请寻求专业帮助

2. **不适合大规模数据管理**
   - 所有数据存在浏览器本地，不适合存储多年的大量日记
   - 如果日记超过几百篇，页面加载和报告生成可能变慢

3. **不适合多人协作**
   - 没有用户系统，所有数据都在当前设备上
   - 无法实现家庭共享日记或团队反思

4. **不适合实时分析**
   - 报告生成需要手动触发，且依赖API调用（可能有延迟）
   - 无法实现“每写一句就实时反馈”的交互模式

**如果你需要：**
- **完全私密的加密日记** → 考虑使用专业的日记App（如Day One）
- **多人共同记录** → 考虑使用在线协作文档（如Notion）
- **即时情绪分析与干预** → 考虑使用专业的心理健康App
- **长期、大量的日记存储** → 考虑自建数据库或使用云服务

---

**最后提醒**：这个网页最核心的价值不是代码本身，而是它展示的“AI增强型工具”设计模式——用AI提供结构化引导，用本地存储保护隐私，用定期分析创造持续价值。你可以把这个模式应用到无数个领域，创造属于你自己的“智能助手”。
