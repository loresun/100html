# 问题解决画布 (5W1H) - 帮助文档

--------------------------------

## 【一】这个网页解决了什么问题？

这个网页是一个**结构化思考辅助工具**，它帮助你在面对复杂或模糊的问题时，能够快速理清思路、抓住重点并形成行动计划。

**使用场景举例：**
- **项目启动前**：你接到一个“提升用户活跃度”的任务，但不知从何下手。使用这个工具，可以帮你拆解出“谁（Who）是目标用户”、“为什么（Why）活跃度低”、“如何（How）提升”等关键问题。
- **复盘会议前**：一个营销活动效果不佳，你需要带领团队分析原因。使用“复盘优化”模式，可以系统性地回顾“在哪里（Where）出了问题”、“什么时候（When）出现了转折点”。
- **个人规划时**：你想“学习一门新技能”，但感到迷茫。输入这个想法，工具会引导你思考“学什么（What）”、“何时学（When）”、“需要什么资源（How）”，帮你把模糊愿望变成清晰计划。

**它适合：**
- 处理**非结构化、定义模糊**的问题。
- 需要**快速启动思考**，避免陷入“空想”或“思维混乱”。
- 希望得到一个**可视化、可分享**的分析框架。

**它不适合：**
- 解决有**明确、单一答案**的数学或技术问题。
- 替代专业的项目管理软件进行**任务跟踪和协作**。
- 处理需要**实时数据计算或复杂模型模拟**的决策。

## 【二】使用方式（给第一次接触的人）

1.  **打开页面**：你会看到左侧是输入区，右侧是空白的结果展示区。
2.  **配置API（首次使用必做）**：
    *   点击右上角的 **“API 设置”** 按钮。
    *   选择模型提供方（如 DeepSeek），并填入你的 **API Key**（你需要自行在对应平台申请）。
    *   点击“保存”。设置会保存在你的浏览器里，下次无需重复操作。
3.  **输入你的问题**：
    *   **选择模式**：根据你的目的，在“澄清问题”、“制定行动方案”、“复盘优化”中选择一个。
    *   **问题描述**：在文本框中，用一两句话描述你面临的核心问题或挑战。例如：“新产品的用户注册流程流失率很高。”
    *   **已知信息（选填）**：可以补充一些背景，如“目前注册需要5步”、“主要用户是25-35岁人群”。
4.  **生成画布**：点击蓝色的 **“生成画布”** 按钮。稍等片刻，AI 会进行分析。
5.  **查看与使用结果**：
    *   右侧会生成一个 **6宫格的画布**，分别对应 Who（谁）、What（什么）、When（何时）、Where（何地）、Why（为什么）、How（如何）。每个格子都包含了 AI 对该维度的分析要点和“下一步行动”提示。
    *   画布下方会生成一个更详细的 **“行动清单”**，用 Markdown 格式列出具体步骤。
    *   你可以点击 **“导出为图片”**，将整个分析结果保存下来，用于会议分享或个人存档。

**容易忽略的细节：**
- **模式选择很重要**：它会影响 AI 分析的侧重点。“澄清问题”会更注重定义范围，“制定行动方案”则直接输出可执行步骤。
- **已知信息是“加速器”**：填写已知信息能让 AI 的分析更贴合你的实际情况，避免泛泛而谈。
- **结果可以迭代**：如果你对某一部分不满意，可以**修改问题描述或已知信息，再次点击生成**，AI 会给出新的分析。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

1.  **控制与配置模块**（页面顶部及设置弹窗）
    *   **职责**：提供全局导航（返回）、触发核心功能（生成、导出）、管理应用“大脑”的配置（API 设置）。它是整个应用的“开关和调节器”。
    *   **逻辑**：用户在此进行初始化设置（API Key）和触发主要动作（点击按钮）。

2.  **输入与逻辑处理模块**（左侧面板及背后的 JavaScript 函数）
    *   **职责**：
        *   **输入面板**：收集用户原始想法（问题、模式、背景）。
        *   **逻辑核心 (`problemCanvasApp` 函数)**：这是页面的“大脑”。它负责将用户的输入**组装成给 AI 的指令（Prompt）**，调用 AI API，再把 AI 返回的文本**解析并整理**成前端能方便展示的结构化数据（如 `result.canvas` 数组）。
    *   **输入→处理→输出链路**：
        *   **输入**：用户填写表单。
        *   **处理**：点击“生成” → 函数将表单数据拼接成 Prompt → 调用 AI API → 收到 AI 回复（JSON 字符串）→ 解析 JSON。
        *   **输出**：将解析后的数据（画布数组、行动文本）存入 `result` 对象。

3.  **渲染与展示模块**（右侧结果区域）
    *   **职责**：将 `result` 对象中的结构化数据，以美观、易读的视觉形式（卡片网格、Markdown 渲染）呈现给用户。同时提供“导出图片”的变现功能。
    *   **逻辑**：监听 `result` 数据的变化 → 使用 Alpine.js 的模板语法 (`x-if`, `x-for`) 动态生成 HTML → 使用 `marked` 库将 Markdown 文本转为 HTML → 使用 `html2canvas` 将整个区域转为图片。

**最值得学习的设计：**
- **“数据状态驱动视图”的极简实践**：整个应用围绕一个核心的 `result` 数据对象。它的变化（从空数组到被填充）直接驱动右侧视图从“等待中”变为“结果展示”。这是现代前端框架（如 React、Vue）的核心思想，这里用轻量的 Alpine.js 清晰地演示了出来。
- **清晰的职责分离**：输入模块只管收集，逻辑模块只管处理和存数据，展示模块只管根据数据渲染。这使得代码结构清晰，未来要修改样式或增加输入项都非常方便。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个页面中，**Prompt 是连接人类模糊想法与 AI 结构化输出的“翻译官”和“模具”**。

1.  **扮演的角色**：它不是一个简单的问答，而是一个**严格的输出格式指令**。它告诉 AI：“请用你的分析能力，但必须把结果按照我指定的 JSON 格式装好。”
2.  **解决的问题**：它同时解决了 **“理解问题”** 和 **“生成问题”**。
    *   **理解**：通过 `系统提示词` (“你是结构化问题解决顾问...”) 为 AI 设定角色和专业领域。
    *   **生成**：通过 `用户提示词` 中的具体指令，强制 AI 生成包含特定字段（`key`, `label`, `answer`, `next`）的 JSON 和 Markdown 文本。
3.  **关键变量**：
    *   `问题：${this.topic}`：用户的核心疑问，是分析的起点。
    *   `模式：${CANVAS_HINTS[this.mode]}`：引导 AI 调整回答的侧重点（澄清、计划或复盘）。
    *   **最关键的**：`请输出严格 JSON：...` 这一段。它定义了输出数据的“模具”，是获得结构化数据而非杂乱文本的核心。
4.  **只改 Prompt 的效果**：如果你只修改 Prompt 而不动代码，你可以彻底改变这个工具的功能性质。
    *   **例子1**：把 5W1H 框架换成 **SWOT 分析**（优势、劣势、机会、威胁），并相应修改 JSON 结构，这个工具就变成了一个“SWOT 分析生成器”。
    *   **例子2**：把 Prompt 改成“请根据以下产品描述，生成一份用户故事地图，包含角色、活动、任务...”，工具就变成了“用户故事生成器”。
    *   **核心**：代码（模具工厂）不变，但通过替换 Prompt（更换模具），就能生产出完全不同形状的产品（分析结果）。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步打造属于自己的 AI 工具：

**第一步：复制骨架，替换场景（最安全）**
1.  复制整个 HTML 文件。
2.  修改标题、描述等文字内容，比如把“问题解决画布”改为“【你的场景】分析器”，例如“短视频创意脑暴器”。
3.  **此时不要动任何 JavaScript 代码**。先确保原功能在你的环境下能正常运行（记得配 API Key）。

**第二步：调整输入字段**
1.  在左侧输入面板，根据你的新场景，**增加、删除或修改输入框**。
    *   例如，做“短视频创意脑暴器”，你可以增加“目标平台”（抖音/视频号）、“视频类型”（科普/搞笑）、“核心关键词”等字段。
2.  在 Alpine.js 的 `x-data` 中，找到对应的数据项（如 `topic`, `context`），相应地增加或重命名它们。

**第三步：重铸“模具”（修改 Prompt）**
1.  这是**改造的核心**。找到 `generate()` 函数里的 `systemPrompt` 和 `userPrompt`。
2.  重写 `systemPrompt`，重新定义 AI 的角色，如“你是一个资深短视频策划专家”。
3.  重写 `userPrompt`，将新增加的输入字段变量（如 `目标平台`）拼接进去，并**设计你想要的输出格式**。
    *   例如，要求 AI 输出：`{"创意点": ["点子1", "点子2"...], "脚本梗概": "..."}`。
4.  **关键**：你设计的输出格式（JSON），必须与下一步要展示的方式匹配。

**第四步：改变输出展示**
1.  根据你新设计的输出格式，修改右侧结果区域的模板。
2.  如果输出是创意点列表，就用 `x-for` 循环渲染一个列表。
3.  如果输出是脚本，可能就直接用 `x-html` 渲染一大段 Markdown 文本。
4.  至此，一个属于你的新工具就诞生了。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“风格”或“语气”选项**：
    *   **操作**：在输入区增加一个下拉框，选项如“专业严谨”、“幽默风趣”、“简洁直白”。
    *   **修改**：将这个选项变量加入到 `userPrompt` 中，例如：“请用${tone}的语气进行分析和撰写。”
    *   **效果**：让生成的画布和行动清单更符合你的使用场景（如给老板汇报用专业型，团队内部分享用幽默型）。

2.  **从“一次性分析”变为“多轮对话优化”**：
    *   **操作**：在生成的每个 5W1H 卡片上，增加一个“**优化此点**”的小按钮。
    *   **修改**：点击按钮时，将当前卡片的内容作为新的上下文，向 AI 发起一次新的、聚焦的请求，例如：“关于‘Why’部分，请进一步深挖三个根本原因。”
    *   **效果**：工具从一个生成器，进化成一个可以与你深度对话、迭代式打磨方案的思考伙伴。

3.  **更换或扩展分析框架**：
    *   **操作**：在“模式”下拉框旁边，增加一个“**分析框架**”下拉框。
    *   **修改**：选项包括“5W1H”、“SWOT”、“PDCA循环”、“用户旅程图”等。根据选择的不同，动态改变 `userPrompt` 中要求输出的 JSON 结构，并相应调整右侧的渲染模板。
    *   **效果**：一个工具，多种思维模型，适用性大大增强。

4.  **本地存储与案例管理**：
    *   **操作**：在页面顶部增加一个“**保存本次分析**”按钮和一个“**历史案例**”下拉列表。
    *   **修改**：点击保存时，将当前的输入和完整的 `result` 对象以时间戳命名，存入 `localStorage`。历史案例下拉列表读取这些存档，选择后能自动填充输入框并渲染结果。
    *   **效果**：方便你回顾和对比不同问题的分析思路，形成个人知识库。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做精确的数据分析与决策**：
    *   **局限性**：它的分析基于 AI 的语言模型和你的描述，**没有接入真实数据**（如数据库、用户行为数据）。对于“哪个渠道的 ROI 最高”这类需要精确计算的问题，它只能给出推测性方向。
    *   **正确做法**：应使用数据分析工具（如 Google Analytics, Looker）或专业的商业智能（BI）软件进行分析后，再将结论作为“已知信息”输入本工具，用于制定行动计划。

2.  **不适合替代复杂的项目管理**：
    *   **局限性**：它生成的“行动清单”是文本性的建议，**不具备任务分配、进度跟踪、依赖关系管理、团队协作**等功能。
    *   **正确做法**：将本工具生成的行动清单，导入到专业的项目管理工具（如 Notion, Trello, Jira, Asana）中，进行细化、分配和跟踪。

3.  **不适合处理高度专业化、有标准流程的领域问题**：
    *   **局限性**：对于法律条文解读、医疗诊断、精密工程技术问题等，AI 可能产生“幻觉”或遗漏关键细节，存在风险。
    *   **正确做法**：此类问题应咨询领域内的持证专家，本工具仅可作为会前个人梳理初步想法的辅助手段，绝不能替代专业意见。

**总结**：请始终将它视为一个 **“思维启动器”和“结构化助手”** ，而非“决策执行者”。它的价值在于帮你理清思路、打开视角，而具体的验证、执行和深化，需要你结合其他工具和专业能力来完成。
