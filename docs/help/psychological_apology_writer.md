# 道歉信生成器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景**：
当你因为自己的言行伤害了他人（恋人、父母、朋友、同事），想要真诚道歉却不知如何开口时，这个工具能帮你。它特别适合那些：
- 情绪激动，难以组织清晰语言
- 担心说错话让关系更糟
- 想要遵循专业的沟通框架（非暴力沟通）
- 需要根据不同对象调整语气和内容

**不适合的情况**：
- 需要即时、面对面的沟通（这是工具，不能替代当面交流）
- 涉及法律纠纷的正式道歉函
- 完全不想反思，只想敷衍了事
- 对方明确表示“不想听任何解释”的情况

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要填写四个关键信息：
1. **道歉场景**：选择对方是谁（恋人/父母/朋友/同事）
2. **语气风格**：选择信件的整体感觉（正式/亲密/轻松）
3. **具体错误**：描述你做错了什么事
4. **对方感受**：猜测或知道对方现在的心情
5. **你的反思**：你从这件事中学到了什么

**用户通常会做哪几步操作？**
1. 点击右上角齿轮图标，输入你的 DeepSeek API Key（第一次使用必须）
2. 在左侧表单中填写上述五个信息
3. 点击“生成道歉信”按钮
4. 等待几秒钟，右侧会显示生成的道歉信
5. 可以复制内容或下载为文本文件

**输出结果长什么样？**
生成的信件会以美观的格式显示，包含：
- 清晰的标题和分段
- 基于非暴力沟通的结构（承认错误→理解感受→承担责任→补救措施）
- 符合你选择的场景和语气
- 如果使用“深度思考”模型，还能看到AI的思考过程

**容易忽略的使用细节**：
- **API Key 是必须的**：第一次使用一定要先点设置图标输入
- **模型选择**：V3（快速）适合一般情况，R1（深度思考）会显示推理过程，更细致但稍慢
- **三个文本框都要填**：否则生成按钮是灰色的
- **思考过程可展开**：如果使用R1模型，记得点击“深度思考过程”查看AI如何分析

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

**1. 配置管理模块**
- **位置**：右上角设置按钮 → 弹窗
- **职责**：管理API连接和生成规则
- **关键设计**：将敏感信息（API Key）和可调参数（Prompt）集中管理，与主逻辑分离

**2. 输入收集模块**
- **位置**：左侧白色卡片区域
- **职责**：结构化收集用户的具体情况
- **关键设计**：用下拉菜单限定范围（场景/语气），用文本框收集自由内容，平衡了灵活性与指导性

**3. AI处理模块**
- **位置**：代码中的 `generate()` 函数
- **职责**：将用户输入拼接成Prompt，调用AI API，处理返回的流数据
- **关键设计**：使用流式响应（stream），让用户看到生成过程，而不是干等

**4. 结果展示模块**
- **位置**：右侧白色卡片区域
- **职责**：展示生成内容，提供后续操作（复制/下载）
- **关键设计**：区分“思考过程”和“最终结果”，用Markdown渲染提升可读性

**输入 → 处理 → 输出 的逻辑链路**：
```
用户填写表单 → 拼接成结构化Prompt → 加上系统指令 → 发送给AI → 
流式接收数据 → 分离思考内容和正文 → 分别渲染展示 → 提供导出功能
```

**最值得学习的设计**：
**Prompt的“双层结构”**：系统Prompt定义框架和原则（不变），用户Prompt填充具体内容（可变）。这样既保证了专业性，又保持了灵活性。这是AI应用设计的核心模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演的角色**：
它是连接“用户需求”和“AI能力”的**翻译官**。把用户零散的情绪和事件，翻译成AI能理解并有效处理的指令。

**解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**，但也包含了理解：系统Prompt让AI“理解”非暴力沟通框架，用户Prompt让AI“理解”具体情境，然后AI“生成”符合框架和情境的道歉信。

**Prompt中的关键变量**：
1. **系统Prompt中的固定部分**：
   - 角色设定：“心理咨询师和沟通专家”
   - 框架要求：“非暴力沟通四步结构”
   - 风格指导：“避免‘但是’”、“真诚表达”
   - 场景适配规则：“对恋人更亲密...”

2. **用户Prompt中的动态部分**：
   - `{{scenario}}`：道歉对象
   - `{{tone}}`：语气风格  
   - `{{mistake}}`、`{{feelings}}`、`{{reflection}}`：用户填写的具体内容

**如果只改Prompt，不改代码，会发生什么？**
- 改系统Prompt → 改变生成信件的**底层逻辑和风格**
  - 例：改成“商务道歉函模板” → 生成正式商业道歉
  - 例：强调“幽默化解” → 生成轻松搞笑的道歉
- 改用户Prompt结构 → 改变**需要用户填写的信息**
  - 例：增加“希望达成的效果”字段 → 生成更有目标导向的信件

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径**：

**第一步：保持结构不变，替换使用场景**
- 最小改动：只改文字和图标
- 将“道歉信”改为“感谢信”、“情书”、“会议纪要”
- 将“场景”选项改为“感谢对象”、“关系类型”、“会议类型”
- **这是零风险起步**，所有代码逻辑完全复用

**第二步：调整输入字段和Prompt**
- 修改左侧表单的标签和字段
- 例：做“旅行计划生成器”
  - 场景 → 旅行类型（海岛/城市/探险）
  - 语气 → 预算等级（经济/舒适/豪华）
  - 具体错误 → 想去的地方
  - 对方感受 → 特殊需求
  - 你的反思 → 旅行时间
- 相应调整系统Prompt和用户Prompt的模板

**第三步：改变输出形式或展示方式**
- 修改右侧结果区域的展示逻辑
- 例：改为“分点列表”而不是“完整信件”
- 例：增加“一键分享到社交媒体”按钮
- 此时需要改动少量JavaScript代码

**从哪里下手最安全？**
从**文字替换**开始。先不改任何代码逻辑，只改HTML中的文字内容和选项值。确保基本功能正常后，再逐步深入。

## 【六】3–5个可直接尝试的改造方向

**1. 增加“个性化元素”输入**
- **具体操作**：在表单中添加“对方的昵称”、“你们之间的内部梗”、“共同回忆的关键词”
- **效果**：生成的道歉信会更个性化，避免模板感
- **改动位置**：在`formData`中添加字段，在用户Prompt中引用

**2. 切换为本地模型或其它API**
- **具体操作**：将`fetch`请求的URL改为本地Ollama（如`http://localhost:11434/api/chat`），调整请求格式
- **效果**：完全免费，数据隐私性更好
- **改动位置**：`generate()`函数中的API调用部分

**3. 拆分为“快速生成”和“深度编辑”两个页面**
- **具体操作**：
  - 页面1：保持现有简单表单，快速生成初稿
  - 页面2：将生成的道歉信作为可编辑文本框，让用户逐句修改，AI辅助优化
- **效果**：从“全自动”升级为“人机协作”
- **技术点**：用`localStorage`传递生成结果到第二个页面

**4. 增加“语气强度”滑块**
- **具体操作**：将“语气风格”下拉菜单改为滑块，从“非常正式”到“非常随意”
- **效果**：更精细地控制生成风格
- **改动位置**：用`<input type="range">`替换`<select>`，在Prompt中描述强度

**5. 添加“历史记录”功能**
- **具体操作**：每次生成后自动保存到本地，左侧增加历史列表
- **效果**：可以回顾、比较、复用之前的道歉信
- **技术点**：用`localStorage`存储数组，用`v-for`渲染列表

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性**：

1. **不适合替代真实沟通**
   - 这个工具生成的是“文本草案”，不是“关系修复”
   - 如果对方需要的是你的态度、眼神、语气，信件只是辅助
   - **边界**：不能因为有了完美信件，就不去当面道歉

2. **不适合处理复杂情感纠纷**
   - 如果涉及长期积累的矛盾、信任破裂、价值观冲突
   - AI无法理解你们关系的全部历史和微妙动态
   - **应该**：寻求专业心理咨询师帮助

3. **不适合法律或正式场合**
   - 生成的道歉信没有法律效力
   - 如果涉及合同违约、商业赔偿、法律纠纷
   - **应该**：咨询律师，起草正式法律文书

4. **不适合“敷衍了事”**
   - 如果你内心并不认为自己有错，只是被迫道歉
   - AI生成的真诚文字会与你的真实态度产生割裂
   - **结果**：对方可能觉得更虚伪，关系更糟

5. **不适合完全依赖AI思考**
   - “深度思考过程”展示的是AI的推理，不是你的反思
   - 最终的信件应该融入你自己的真实想法
   - **正确用法**：以AI生成为起点，用自己的话修改、补充

**记住**：这个工具最好的使用方式是——**你先认真思考，用工具帮你表达；而不是让工具替你思考，你只是抄写**。
