# 多模型对比测试器 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在为一个重要项目撰写文案，或者在学习一个复杂概念。你手头有几个不同的AI模型（比如一个擅长快速回答，另一个擅长深度推理），但你不知道哪个模型给出的答案更符合你的需求。手动一个个去问，不仅效率低，还很难直观地比较。

这个网页就是为你解决这个问题的。它像一个**AI模型“比武擂台”**，让你可以：
*   **并行测试**：一次性向多个AI模型发送同一个问题，让它们同时“作答”。
*   **直观对比**：将不同模型的回答并排展示，方便你从内容、风格、速度等维度进行比较。
*   **深度评估**：除了看最终答案，还能查看某些模型的“思考过程”，并为你满意的答案打分。

**适合场景**：
*   在多个AI模型（如GPT-4、Claude、DeepSeek等）间选择最适合你任务的模型。
*   测试不同Prompt（指令）对同一模型效果的影响。
*   快速获取同一问题的多种视角和风格的答案，激发灵感。
*   学习和研究不同AI模型的输出差异与特点。

**不适合场景**：
*   需要与AI进行多轮、复杂的对话（它专注于单次Prompt的对比）。
*   处理需要上传文件、分析图片等非文本任务。
*   在完全离线的环境下使用（需要调用在线API）。

## 【二】使用方式（给第一次接触的人）

1.  **准备输入**：在页面中央的大文本框中，输入你想测试的问题或指令（Prompt）。例如：“写一首关于春天的五言绝句”或“用通俗语言解释区块链原理”。
2.  **选择“选手”**：在“选择对比模型”区域，点击你想对比的模型卡片。至少选择两个模型，卡片被选中后会高亮显示。
3.  **开始“比武”**：点击蓝色的 **“⚔️ 开始对比”** 按钮。
4.  **观察“战况”**：
    *   页面会显示多个结果卡片，每个卡片对应一个模型。
    *   你会看到答案**逐字逐句地流式出现**，就像有人在实时打字。
    *   对于具备“思考过程”的模型（如R1），你可以点击“查看思考过程”了解它是如何一步步推导出答案的。
5.  **评估与保存**：
    *   阅读答案后，你可以点击卡片顶部的星星（★）进行评分（1-5星）。
    *   可以复制单个答案，或使用顶部的“导出”按钮将所有结果保存为TXT或Markdown文件。

**容易忽略的细节**：
*   **首次使用需配置**：点击右上角的“设置”图标，输入你的DeepSeek API Key，否则无法运行。
*   **布局切换**：右上角有两个布局按钮（“口”和“三”），可以切换结果卡片是**水平并排**还是**垂直排列**，适应不同屏幕宽度。
*   **历史记录**：每次对比都会自动保存，点击“历史”可以查看、重新加载或删除过去的测试记录。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个模块，像一个高效的生产线：

1.  **控制面板模块（输入与配置）**
    *   **职责**：接收用户指令（Prompt），让用户选择要对比的“AI选手”（模型），并触发对比任务。
    *   **组成**：Prompt输入框、模型选择卡片、开始按钮。
    *   **逻辑**：`用户输入Prompt + 选择模型` → `点击开始` → 触发后续所有流程。

2.  **API通信与数据处理模块（看不见的引擎）**
    *   **职责**：这是页面的**核心大脑**。它负责同时向多个AI模型的API接口发送请求，并以“流式”方式接收数据，实时分发给前端展示。
    *   **关键设计**：`Promise.all()` 方法实现了**并行调用**，极大提升了效率。`fetch` API的流式处理（`reader.read()`）让答案能够**逐字显示**，体验更佳。

3.  **结果展示与交互模块（输出与反馈）**
    *   **职责**：将每个模型的回答清晰、美观地呈现出来，并提供评分、复制等交互功能。
    *   **组成**：多个结果卡片。每个卡片包含：模型信息、加载/错误状态、流式回答内容、思考过程（如有）、评分星星、复制按钮、字数统计。
    *   **逻辑**：接收来自“引擎”的数据流 → 实时更新对应卡片的内容 → 渲染Markdown格式 → 提供交互工具。

4.  **辅助功能模块（提升体验）**
    *   **职责**：管理历史记录、API设置、数据导出等，让工具更实用、更完整。
    *   **组成**：历史记录弹窗、设置弹窗、导出/复制按钮、Toast提示。

**最值得学习的设计**：
**“状态驱动”的UI更新**。页面没有直接操作DOM，而是通过Vue管理一系列“状态”变量（如 `results` 对象、`isRunning` 布尔值）。当状态改变时（如API返回了新内容），UI会自动、高效地重新渲染对应的部分。这使得复杂的并行流式更新逻辑变得清晰可控。

## 【四】Prompt / AI 逻辑是如何被设计的？

*   **Prompt的角色**：在这个页面中，Prompt是**唯一的、统一的测试输入**。它就像发给所有AI模型的同一份“考卷”，确保了对比的公平性。
*   **解决的问题**：它主要解决“**生成问题**”。用户通过Prompt来“指挥”AI生成所需的内容（解释、创作、分析等）。页面本身不负责“理解”Prompt的意图，而是将其原样传递给AI模型。
*   **关键变量**：Prompt文本框中的**全部内容**就是关键变量。它的每一个字、每一个标点、甚至换行，都会影响AI的生成结果。
*   **只改Prompt会怎样**：这是最安全、最有效的实验方式。例如：
    *   将“写一首诗”改为“写一首幽默的打油诗”，所有模型的输出风格都会随之改变。
    *   在Prompt末尾加上“请用列表形式回答”，所有模型的答案结构都会变成列表。
    *   这意味着，**你可以不修改任何一行代码，仅通过优化Prompt，就能彻底改变这个工具的输出效果和应用场景**。

## 【五】如何模仿它，做出你自己的版本？

如果你想创建一个类似的工具，但用于其他场景，请遵循以下安全路径：

1.  **第一步：替换“场景”与“选手”**
    *   **最安全**：保持所有代码结构不变。
    *   **修改 `availableModels` 数组**：将DeepSeek模型换成其他你熟悉的API模型（如OpenAI的GPT-4o、Anthropic的Claude等）。只需更新`id`、`name`、`description`和`icon`。
    *   **修改 `callModel` 函数中的API地址和请求格式**，以适配你新换的模型服务商。

2.  **第二步：调整输入与输出**
    *   **修改输入**：如果你需要更多输入项（如“写作风格”、“目标读者”），可以在控制面板模块添加新的输入框，并将这些变量加入到发送给API的Prompt中。
    *   **修改输出展示**：在结果卡片中，你可以增加新的展示维度。例如，如果对比翻译模型，可以增加“原文”与“译文”的对照区域；如果对比代码生成，可以增加一个“运行测试”的按钮。

3.  **第三步：改变核心逻辑与交互**
    *   **进阶修改**：如果你不仅想对比模型，还想对比**同一个模型的不同参数**（如温度、最大生成长度），你可以在控制面板增加滑块控件，并在API调用时传入这些参数。
    *   **改变交互**：将“并行对比”改为“顺序对比+自动评估”。例如，让模型A生成答案后，自动让模型B去评价模型A的答案，实现交叉评审。

**从哪里下手最安全？**
从 **`availableModels` 数组**和 **`callModel` 函数**开始。这是连接你自定义AI服务的桥梁，改动范围清晰，容易调试。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“系统指令”输入框**：在Prompt输入框上方，增加一个可选的“系统指令”输入框。系统指令用于设定AI的角色（如“你是一位资深律师”），这能让对比测试更具针对性。在API调用时，将系统指令作为 `messages` 数组的第一条消息。
2.  **集成多服务商API**：不止于DeepSeek，同时集成OpenAI、Google Gemini、Moonshot等多家服务商的模型。在模型选择区按服务商分组，并让用户为每个服务商单独配置API Key。
3.  **引入自动评估指标**：除了人工评分，可以增加简单的自动评估。例如，在结果卡片中自动计算答案的“字数”、“关键信息密度”（通过关键词匹配），或调用一个轻量级的情感分析API来判断答案的“积极/消极”倾向。
4.  **创建“Prompt模板库”**：在Prompt输入框旁边增加一个“模板”按钮，点击后弹出一个常用Prompt模板列表（如“写邮件”、“头脑风暴”、“代码审查”等），用户点击即可快速填入，降低使用门槛。
5.  **优化为“A/B测试工作台”**：将核心逻辑从“多模型对比”转变为“单模型多Prompt对比”。允许用户输入两个略有不同的Prompt（A和B），用同一个模型生成答案，从而精细地测试Prompt措辞的微小变化对结果的影响。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合进行复杂、保密的工作**：它需要将你的Prompt发送到第三方API服务器。**切勿输入个人隐私信息、公司机密或敏感数据**。
*   **不适合作为最终生产工具**：它是一个**测试和比较工具**，界面和功能都围绕对比设计。如果你需要一个稳定、功能单一的AI对话或写作工具，应该使用专门的Chat应用或集成到你的工作流中（如Notion AI、Cursor等）。
*   **不适合处理实时性要求极高的任务**：由于依赖网络API，响应速度受网络和服务器影响，不适合需要毫秒级响应的场景。
*   **不适合完全不懂API的用户**：使用者需要自行申请并配置API Key，并了解相关费用。如果用户只想免费、开箱即用地体验AI，应该去使用ChatGPT官网等直接提供界面的服务。
