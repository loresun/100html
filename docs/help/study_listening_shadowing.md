# 听力跟读训练 - 帮助与学习文档

---

## 【一】这个网页解决了什么问题？

**使用场景：**
想象你正在学习一门外语，比如英语或日语。你希望练习“跟读”——这是一种高效的听力与口语训练方法，即先听一段材料，然后模仿其语音、语调、语速进行复述。但你找不到既符合你当前水平（如“入门”），又贴合你兴趣主题（如“旅行”、“面试”）的练习材料。这个网页就是为你设计的。你只需要告诉它“我想练什么主题、什么难度”，它就能在几秒钟内为你生成一份量身定制的跟读训练计划。

**适合情况：**
- 语言学习者想进行自主、个性化的跟读练习。
- 需要快速获得结构化的学习材料（短文、步骤、重点词汇）。
- 希望练习材料能匹配特定场景（如商务、旅行、考试）。

**不适合情况：**
- 需要真人语音示范或即时发音纠正（本工具不提供音频）。
- 需要长篇、复杂的语法讲解或深度文化背景分析。
- 需要与其他学习者互动或获得教师反馈。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    *   **语言与主题**：一个文本框，输入你想练习的主题，例如“日语旅行”、“英语面试”。
    *   **难度**：一个下拉菜单，选择“入门”、“中级”或“高级”。
    *   **API 设置**：一个隐藏的设置面板，用于输入你的 DeepSeek API Key 和选择模型（V3 或 O1）。**这是使用前必须配置的一步。**

2.  **用户通常会做哪几步操作？**
    1.  **首次使用**：点击右上角“API 设置”，输入你的 API Key，选择模型（V3 速度较快，O1 逻辑更强），点击“保存配置”。
    2.  **日常使用**：在左侧面板输入“主题”（如“法语点餐”），选择“难度”（如“中级”）。
    3.  **生成材料**：点击“生成跟读素材”按钮。
    4.  **开始练习**：在右侧面板阅读生成的“短文”，按照“训练步骤”一步步跟读，并重点掌握“高频表达”。

3.  **输出结果长什么样？**
    右侧面板会显示一个结构清晰的训练脚本：
    *   **短文**：一段围绕你指定主题编写的、长度适中的外语短文。
    *   **训练步骤**：一个分步指南，例如“1. 先通读全文 2. 逐句跟读 3. 尝试背诵”。
    *   **高频表达**：几个从短文中提炼出的、值得重点学习的词汇或短语，以彩色标签形式展示。

4.  **有哪些容易忽略的使用细节？**
    *   **API Key 是必须的**：不配置 API Key，点击生成会失败。Key 需要从 DeepSeek 官网获取。
    *   **主题要具体**：输入“英语面试”比只输入“英语”效果更好。
    *   **输出是纯文本**：没有语音，你需要自己朗读或寻找其他工具辅助发音。
    *   **模型切换**：右上角的 V3/O1 按钮和 API 设置里的下拉菜单是联动的，切换一个，另一个会同步。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块：

1.  **控制与配置模块（左侧面板 + 顶部栏）**
    *   **职责**：接收用户的“主题”和“难度”指令，并提供系统配置入口（API Key、模型选择）。
    *   **逻辑**：用户在此输入需求 → 点击“生成”按钮 → 触发 AI 调用。

2.  **内容展示模块（右侧面板）**
    *   **职责**：以结构化的方式（短文、步骤、短语标签）呈现 AI 生成的内容。
    *   **逻辑**：接收并解析 AI 返回的 JSON 数据 → 将数据填充到对应的 HTML 元素中 → 展示给用户。

3.  **AI 交互与数据处理模块（JavaScript 逻辑）**
    *   **职责**：这是页面的“大脑”。它负责：
        *   管理用户配置（`studyShared.js` 辅助）。
        *   根据用户输入，**组装成发给 AI 的指令（Prompt）**。
        *   调用 AI API，并处理返回的数据（解析 JSON，处理错误）。
        *   将处理后的数据更新到页面上（Alpine.js 响应式数据绑定）。
    *   **逻辑链路**：
        `用户输入（主题/难度）` → `拼接成 Prompt` → `调用 AI API` → `解析 JSON 响应` → `更新页面数据` → `用户看到结果`

**最值得学习的设计：**
**“结构化 Prompt + 结构化输出”的闭环设计。** 页面没有让 AI 自由发挥，而是通过一个精心设计的 Prompt，要求 AI 返回一个固定的 JSON 格式。这样，前端代码就能稳定地预期到返回的数据结构（`script`， `steps`， `phrases`），并轻松地将其映射到页面的不同区域进行展示。这种设计使得前端与 AI 的协作清晰、可靠，是构建 AI 应用的关键模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt 扮演的角色**：它是连接用户意图和 AI 能力的“翻译官”和“任务说明书”。它把用户简单的“主题”和“难度”信息，转化成一个 AI 能精确理解的、复杂的创作任务。

2.  **解决的是“生成问题”**：它主要解决的是“根据要求生成内容”的问题，而不是“理解用户复杂意图”的问题。用户的输入（主题、难度）本身就是清晰的需求。

3.  **Prompt 中的关键变量**：
    *   `{this.level}`：动态插入用户选择的难度（入门/中级/高级），让 AI 调整短文用词和句式的复杂度。
    *   `{this.topic}`：动态插入用户输入的主题，这是 AI 创作短文的核心方向。
    *   **输出格式指令**：`输出 JSON：{“script”:“短文”,“steps”:[“步骤1”,“步骤2”],“phrases”:[“表达1”,“表达2”]}，仅返回 JSON。` 这是确保数据可用的最关键部分。

4.  **如果只改 Prompt，不改代码，会发生什么？**
    *   **改变内容风格**：例如，在 Prompt 里加上“请用幽默风趣的风格写作”，生成的短文风格会大变。
    *   **调整输出结构**：例如，要求增加一个 `“vocabulary”: [“单词1:解释1”, ...]` 字段。但由于前端代码没有为这个新字段准备展示位置，所以数据虽然能拿到，却不会显示在页面上。
    *   **改变任务本质**：例如，把 Prompt 改成“请生成关于{topic}的五个选择题”，那么这个页面就从一个跟读训练器变成了一个测验生成器（但同样，需要前端配合展示）。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的 AI 小工具：

**第一步：替换核心场景与输入（最安全）**
*   **目标**：做一个“新闻摘要生成器”。
*   **操作**：
    1.  复制整个 HTML 文件，重命名。
    2.  将标题“听力跟读训练”改为“新闻摘要生成器”。
    3.  将“语言与主题”输入框的标签和提示语改为“新闻主题或关键词”，例如“人工智能最新突破”。
    4.  将“难度”下拉菜单改为“摘要长度”（如：简短、中等、详细）。
    5.  此时，点击生成，AI 还是会返回跟读材料，但我们已经改变了用户界面。

**第二步：调整 Prompt 以匹配新场景**
*   **目标**：让 AI 生成新闻摘要，而不是跟读材料。
*   **操作**：
    1.  找到 `generate()` 函数里的 `prompt` 变量。
    2.  将其内容修改为：`请根据主题“${this.topic}”，生成一份${this.level}长度的新闻摘要。\n\n输出 JSON：{“summary”: “摘要正文”, “key_points”: [“要点一”, “要点二”], “source_hint”: “可参考的媒体类型”}，仅返回 JSON。`
    3.  现在，AI 会根据你的新指令生成新闻摘要格式的数据。

**第三步：调整输出展示以匹配新数据**
*   **目标**：让页面正确显示新闻摘要。
*   **操作**：
    1.  在右侧面板，将“跟读脚本”标题改为“新闻摘要”。
    2.  将“短文”部分改为显示 `summary` 数据。
    3.  将“训练步骤”部分改为显示 `key_points` 数据（可以改标题为“核心要点”）。
    4.  将“高频表达”部分改为显示 `source_hint` 数据（可以改标题为“信息来源提示”）。
    5.  至此，一个全新的“新闻摘要生成器”就诞生了。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入，让 Prompt 更精准**：
    *   **操作**：在左侧面板增加一个“文本风格”下拉菜单，选项为“正式”、“口语化”、“书面报告”。
    *   **修改**：在 Prompt 中加入 `以${this.style}的风格`。这样用户能控制生成短文的语体。

2.  **切换 AI 模型或服务**：
    *   **操作**：修改 `studyShared.callLLM` 函数（在 `study-shared.js` 中），使其支持 OpenAI、Claude 或智谱 AI 的 API。
    *   **修改**：在 API 设置面板增加对应模型的选择项和 API Key 输入框。这能让你对比不同模型在该任务上的效果。

3.  **优化交互体验**：
    *   **操作**：为生成的“高频表达”标签增加点击功能。
    *   **修改**：给每个短语标签绑定点击事件，点击后，可以用另一个 AI 调用（或本地查询）来显示该短语的详细解释、例句或发音（用音标表示）。

4.  **拆分或扩展页面功能**：
    *   **操作**：将“生成”和“练习”拆成两个页面或两个标签页。
    *   **修改**：第一个页面负责生成材料。生成后，增加一个“开始练习”按钮，跳转到第二个页面。第二个页面专注于练习流程，例如可以逐句显示短文，并提供录音和回放功能（需调用浏览器录音 API）。

5.  **增加本地存储与历史记录**：
    *   **操作**：使用浏览器的 `localStorage`。
    *   **修改**：每次成功生成材料后，将主题、难度和生成的内容（JSON）保存为一个历史记录。在页面侧边栏或底部增加一个“历史记录”区域，点击可以快速加载之前的练习材料。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **它不是语音合成或评估工具**：它**不提供**短文的标准发音音频，也**无法**对你的跟读录音进行评分或纠正口音。如果你需要这些功能，应寻找专门的语音学习软件（如 Duolingo, Rosetta Stone）或使用 TTS（文本转语音）API 和语音识别 API 来增强本工具。

2.  **它不是深度互动教学系统**：它无法回答你关于短文中某个语法点的追问，也不能根据你的练习表现动态调整下一步的训练计划。它是一个“一次性材料生成器”。对于深度互动学习，你需要 ChatGPT 等聊天界面，或专业的智能辅导系统。

3.  **它不是内容精确性保障工具**：AI 生成的内容可能存在事实性错误、语法瑕疵或不地道的表达。对于关键的学习内容（如专业术语、考试要点），它生成的材料**必须**由使用者或教师进行审校。它更适合作为灵感来源和辅助练习材料，而非权威教材。

**总结**：这个网页是一个出色的 **“AI 赋能的内容快速生成模板”**。你学会了它的核心——如何用清晰的 Prompt 和前端结构来驾驭 AI 的生成能力。现在，你可以将这个模式应用到无数个需要“按需生成结构化内容”的场景中去了。
