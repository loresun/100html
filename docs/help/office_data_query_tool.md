# 正则 & SQL 生成器 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正在处理一份文档，需要找出里面所有的邮箱地址，但你不知道正则表达式怎么写。或者，你需要从数据库里查询“最近一周下单超过3次的用户”，但SQL语法记不清了。这个网页就像一个“翻译官”，把你用日常语言描述的需求，直接转换成可用的代码。

**适合情况：**
- **快速原型开发**：当你需要快速写一个正则或SQL来验证想法时。
- **学习辅助**：当你对某个语法不熟悉，想看看AI是怎么写的，并附带解释。
- **非程序员协作**：产品经理、运营同学想描述一个数据需求，让工程师能直接拿到可执行的代码。

**不适合情况：**
- **生产环境直接使用**：生成的代码需要经过人工审查和测试，不能直接用于关键业务。
- **极其复杂或定制化的逻辑**：AI可能无法完全理解涉及复杂业务规则或特定数据库架构的深层需求。
- **离线环境**：需要联网调用AI API。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **一个选择**：页面顶部有两个按钮，让你选择要生成“正则表达式”还是“SQL查询”。
2.  **一段描述**：一个大文本框，让你用大白话写下你的需求。

**用户通常会做哪几步操作？**
1.  **选择类型**：点击“正则表达式”或“数据库查询”切换。
2.  **描述需求**：在文本框中，用自然语言写下你想做什么。例如：“找出所有以`139`开头的手机号”或“从`orders`表里找出金额大于100且状态是‘已支付’的订单”。
3.  **点击生成**：按下“🚀 生成代码”按钮。
4.  **查看结果**：右侧黑色代码区会显示生成的代码和解释。
5.  **复制使用**：点击右上角的“复制”按钮，将代码粘贴到你的编辑器或数据库工具中。

**输出结果长什么样？**
输出区域是一个深色背景的代码框，包含两部分：
- **代码**：醒目的绿色文字，就是可以直接使用的正则表达式或SQL语句。
- **解释说明**：灰色小字，用中文解释了这段代码是如何工作的，帮助你理解。

**有哪些容易忽略的使用细节？**
- **首次使用需配置**：第一次点击“生成代码”时，会弹出一个设置窗口，要求你填入DeepSeek的API密钥。你需要先去DeepSeek官网申请一个。
- **模型选择**：导航栏右侧可以切换“快”和“精准”两种AI模型。简单任务用“快”，复杂或需要推理的用“精准”。
- **思考过程**：如果使用“精准”模型，结果上方可能会显示AI的“思考过程”（灰色斜体字），这有助于你理解AI是如何拆解你的问题的。
- **SQL默认方言**：生成的SQL默认为MySQL语法。如果你的数据库是PostgreSQL或SQLite，可能需要微调。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块：

**1. 控制与输入模块（左侧面板）**
- **职责**：接收用户的意图。它通过“类型切换按钮”让用户选择任务领域（Regex/SQL），再通过“文本框”收集用户的具体需求描述。
- **关键设计**：`type`变量是整个应用的状态核心，它决定了界面文案、提示语和后续发给AI的指令。

**2. AI处理与通信模块（不可见，但最关键）**
- **职责**：作为“翻译官”。它接收用户输入和任务类型，构造一个特定的请求（Prompt）发送给AI API，然后解析AI返回的结果。
- **逻辑链路**：
  用户输入 + 任务类型 → 拼接成特定Prompt → 调用DeepSeek API → 解析返回的JSON → 提取`code`和`explanation`。
- **最值得学习的设计**：**“系统指令 + 用户输入”的Prompt结构**。系统指令（`你是一个正则表达式专家...`）限定了AI的角色和输出格式，确保了结果的可用性和一致性。

**3. 结果展示与输出模块（右侧面板）**
- **职责**：清晰、结构化地呈现结果。它不仅仅展示代码，还提供了“解释说明”，并附带了便捷的“复制”功能。
- **关键设计**：**结果的可解释性**。展示“解释说明”让这个工具从“黑盒”变成了“学习工具”，这是它区别于普通代码生成器的亮点。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt扮演的角色：**
Prompt在这里是一个**严格的指令模板和格式约束器**。它告诉AI：“现在请你扮演某个专家，并且必须用我规定的JSON格式回答。”

**它解决的是“生成问题”：**
用户已经清晰地描述了“要什么”（理解已完成），Prompt解决的是“如何规范地生成答案”的问题。它确保了生成的代码是可直接使用的，且附带了解释。

**Prompt中的关键变量：**
1.  **角色指令**：`你是一个正则表达式专家` 或 `你是一个 SQL 专家`。这设定了AI的上下文。
2.  **任务指令**：`用户描述需求，你生成 Regex/SQL`。明确了核心任务。
3.  **输出格式指令**：`请返回 JSON: { "code": "...", "explanation": "..." }`。这是最关键的部分，强制AI以结构化数据回应，方便前端代码直接解析和展示。

**如果只改Prompt，不改代码，会发生什么？**
- **改变角色**：把“正则表达式专家”改成“Python代码专家”，它就能生成Python代码。
- **改变格式**：在JSON里增加一个`"tips"`字段，AI就会在回复中填充这个字段，但前端需要相应修改才能展示它。
- **改变约束**：在Prompt里加上“请生成兼容JavaScript的正则”，生成的代码风格就会变化。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）：**

**第一步：替换场景，保持骨架（最安全）**
- **目标**：做一个“邮件内容生成器”。
- **操作**：
  1.  把“正则/SQL”切换按钮改成“商务邮件/个人邮件”。
  2.  把输入框提示语改成“例如：写一封跟进上周会议的合作邀约邮件”。
  3.  修改Prompt中的角色为“你是一位专业的邮件撰写助手”，并调整输出JSON格式，比如`{ "subject": "邮件主题", "body": "邮件正文", "tips": "写作要点" }`。
  4.  调整结果展示区域，分别显示`subject`和`body`。

**第二步：调整输入，丰富指令**
- **目标**：让生成更可控。
- **操作**：在输入区域增加几个下拉菜单或输入框，比如“语气（正式/随意）”、“长度（简短/详细）”。将这些选项也拼接到Prompt里发给AI，例如：“请以[正式]的语气，撰写一封[简短]的邮件。”

**第三步：改变输出与交互**
- **目标**：提升体验。
- **操作**：
  1.  将纯文本结果展示，改为更接近邮件客户端的样式（有发件人、收件人模拟框）。
  2.  增加“一键发送到Gmail”或“导出为.eml文件”的按钮（这需要更复杂的后端或浏览器API支持）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“示例库”或“历史记录”**
    - **操作**：在输入框下方增加一个“常用示例”下拉菜单，点击即可填充预设描述（如“验证身份证号”）。或者将每次的输入和结果保存到`localStorage`，在侧边栏显示历史记录，方便复用。

2.  **切换不同的AI模型/API**
    - **操作**：在设置弹窗中，增加一个API提供商的选择（如OpenAI、通义千问、智谱AI）。为每个提供商准备对应的API端点URL和密钥输入框。这能让你对比不同模型的效果，并避免单一服务故障。

3.  **增加“测试”或“验证”功能**
    - **操作**：
      - **对于正则**：在结果下方增加一个“测试区域”，用户可以输入一段文本，实时看到当前正则表达式的匹配高亮结果。
      - **对于SQL**：提供一个简单的数据库表结构输入框（或示例），让用户可以验证SQL语法是否正确（这可能需要一个轻量级的SQL解析库或模拟后端）。

4.  **拆分为独立应用并增加用户系统**
    - **操作**：将正则生成器和SQL生成器拆分成两个独立的HTML页面，各自有更专业的定制选项（如SQL方言选择、正则标志选择）。进一步，可以增加后端，实现用户登录、保存模板、团队共享等功能。

5.  **优化交互反馈**
    - **操作**：将“复制成功”的`alert`弹窗，改为页面角落一个更优雅的、几秒后自动消失的提示条（Toast）。在生成代码时，可以尝试使用流式传输（Streaming），让代码和解释像打字一样逐个显示出来，体验更流畅。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合生成复杂业务逻辑的完整代码**：它擅长生成单条、目标明确的表达式或查询语句。如果你需要生成一个完整的用户注册函数，包含异常处理、数据库连接等，它可能无法给出可直接运行的完整代码。
- **不适合作为语法学习的唯一来源**：AI的解释可能过于简略或偶尔不准确。它应该作为**辅助和启发工具**，而不是取代官方文档或系统性的学习。
- **不适合处理敏感数据**：不要将含有真实个人信息、公司内部数据或敏感SQL查询的描述输入进去，因为数据会发送到第三方AI服务。
- **如果需求模糊或存在歧义**：AI可能会生成错误的代码。例如，你说“查一下上个月的数据”，AI可能不知道你指的“数据”是哪个表、哪些字段。此时，你应该换用更专业的数据库管理工具（如Navicat、DBeaver）或与数据工程师直接沟通。

**如果你想做的是：**
- **构建一个完整的、带界面的应用程序**：应该学习Vue/React等前端框架，并设计更复杂的状态管理和组件结构。
- **需要一个离线的代码生成工具**：应该寻找本地的代码片段库（如VS Code的Snippets）或使用能本地运行的代码大模型（如Ollama）。
- **进行复杂的数据分析和可视化**：应该使用专业的BI工具，如Tableau、Power BI或Python的Pandas+Jupyter Notebook。
