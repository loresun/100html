# 多平台内容改写助手 - 学习指南

---

## 【一】这个网页解决了什么问题？

**使用场景**：当你有一篇核心内容（如产品介绍、观点分享、活动通知），需要根据不同社交平台的风格要求，快速生成多个版本时，这个工具能帮你一键完成。

- **适合**：
    - 市场运营人员需要将同一产品信息发布到小红书、公众号、微博等多个平台
    - 自媒体创作者希望将长文拆解成适合不同平台的短内容
    - 学生/职场人想学习不同平台的文案风格差异
- **不适合**：
    - 需要深度创作、完全原创的内容
    - 对格式有严格排版要求（如公众号需要插入图片位置）
    - 需要实时与AI对话、反复修改的场景

---

## 【二】使用方式（给第一次接触的人）

1. **准备输入**：
   - 在左侧“原始内容”框中粘贴或输入你的文章、段落或想法
   - 内容可以是任何你想改编的文字，比如博客草稿、产品说明、个人感悟

2. **选择平台**：
   - 在“选择目标平台”区域，点击你想要的平台图标（如小红书、公众号、Twitter等）
   - 可以多选，系统会为每个平台生成一个独立版本

3. **开始生成**：
   - 点击蓝色的“🚀 开始改写”按钮
   - 如果是第一次使用，会提示你输入DeepSeek API Key（需要自己申请）

4. **查看结果**：
   - 右侧会以卡片形式展示每个平台的改写结果
   - 每张卡片包含：平台名称、生成的内容、复制按钮、重试按钮
   - 如果使用“Reasoner”模型，还能展开看到AI的思考过程

**容易忽略的细节**：
- 点击右上角的“提示词设置”可以修改每个平台的改写要求
- 点击卡片上的“复制”图标可以直接复制内容到剪贴板
- 使用“导出全部”可以一次性下载所有平台的内容为文本文件

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

### 1. 控制面板模块（左侧）
- **职责**：接收用户输入，控制生成流程
- 包含：内容输入框、平台选择器、生成按钮
- **输入→处理→输出**：用户输入内容 → 选择平台 → 点击生成 → 触发API调用

### 2. 结果展示模块（右侧网格）
- **职责**：并行展示多个平台的生成结果
- 每个平台一个卡片，独立显示状态（加载中/完成/错误）
- 支持单个重试、复制、查看思考过程

### 3. 提示词管理系统（模态窗口）
- **职责**：存储和管理每个平台的“改写规则”
- 每个平台有独立的系统提示词，定义了该平台的风格要求
- 用户可以自定义修改，设置会保存在本地

### 4. API通信层（后台逻辑）
- **职责**：与DeepSeek API交互，处理流式响应
- 将用户内容+平台提示词组合成完整Prompt发送
- 实时接收AI返回的内容，分发给对应的结果卡片

**最值得学习的设计**：
- **“平台即配置”**：每个平台不是一个硬编码的功能，而是一组可配置的提示词+图标+名称。这种设计让扩展新平台变得极其简单——只需在`platforms`数组中添加一项，并配置对应的提示词。
- **并行处理与独立状态管理**：每个平台的生成任务独立运行、独立显示状态，互不干扰。这是通过`Promise.all`和独立的结果对象实现的。

## 【四】Prompt / AI 逻辑是如何被设计的？

### Prompt的角色
在这个页面中，Prompt扮演的是**风格转换器**和**格式规范器**的角色。它不是简单地让AI“改写文字”，而是明确告诉AI：“你现在是XX平台的专家，请按照XX平台的风格规则来改写”。

### 解决的是“理解问题”还是“生成问题”？
**两者都有，但重点是“理解问题”**：
- **理解**：让AI理解“小红书风格”与“公众号风格”的本质区别
- **生成**：基于这种理解，生成符合特定格式要求的内容

### Prompt中的关键变量
1. **角色设定**：“你是小红书爆款文案专家”、“你是微信公众号资深编辑”
2. **平台规则**：字数限制、语气要求、结构规范、特殊元素（如话题标签）
3. **内容占位符**：`{{content}}`（在代码中实际是拼接，但逻辑相同）

### 如果只改Prompt，不改代码，会发生什么？
- 改变语气：把专业语气改成幽默语气
- 改变结构：增加“开头金句”、“结尾提问”等要求
- 改变格式：要求输出Markdown、HTML或纯文本
- **甚至改变功能**：把“内容改写”变成“内容总结”、“标题生成”、“翻译”等

## 【五】如何模仿它，做出你自己的版本？

### 安全模仿路径（从易到难）：

**第一步：替换使用场景（最安全）**
- 保持代码结构完全不变
- 修改`platforms`数组：把“小红书、公众号”换成你的场景，比如：
  ```javascript
  const platforms = [
    { id: 'student', name: '学生版', icon: 'graduation-cap' },
    { id: 'teacher', name: '教师版', icon: 'users' },
    { id: 'parent', name: '家长版', icon: 'home' }
  ];
  ```
- 修改对应的`DEFAULT_PROMPTS`，定义每个角色的改写要求

**第二步：调整输入字段**
- 当前只有一个“原始内容”输入框
- 可以增加：“目标读者年龄”、“语气偏好”、“字数限制”等额外控制
- 将这些额外信息拼接到Prompt中

**第三步：改变输出形式**
- 当前是卡片式网格布局
- 可以改为：标签页切换、对比视图（左右对照）、时间线视图
- 或者增加“一键发布到草稿箱”功能（需要平台API）

**从哪里下手最安全？**
从**修改`DEFAULT_PROMPTS`对象**开始。这是零风险修改，即使改错了也不会破坏程序功能，而且能立即看到效果变化。

## 【六】3–5个可直接尝试的改造方向

### 1. 增加“风格强度”滑块
- **操作**：在平台选择下方添加一个滑块，范围从“轻微改写”到“彻底重写”
- **实现**：将滑块值（如0-10）添加到Prompt中：“请进行[强度]程度的改写”
- **效果**：用户可以根据需要控制改写幅度

### 2. 支持多模型切换
- **操作**：在现有的DeepSeek模型选择旁，增加“OpenAI GPT-4”、“Claude”等选项
- **实现**：在`callDeepSeek`函数中根据选择调用不同API
- **效果**：可以对比不同模型在同一任务上的表现

### 3. 添加“历史记录”功能
- **操作**：在左侧增加一个侧边栏或下拉菜单
- **实现**：每次生成后，将“原始内容+平台选择+结果”保存到`localStorage`
- **效果**：用户可以回顾之前的改写，避免重复工作

### 4. 实现“平台模板”共享
- **操作**：在提示词设置窗口增加“导入/导出模板”按钮
- **实现**：将`customPrompts`对象导出为JSON文件，或从文件导入
- **效果**：用户可以分享自己精心调校的平台提示词模板

### 5. 增加“A/B测试”模式
- **操作**：为每个平台生成2-3个不同版本（如不同标题风格）
- **实现**：修改`processPlatform`，对同一平台调用多次API，使用略有不同的Prompt变体
- **效果**：用户可以选择效果最好的版本

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不是创作工具**：它基于已有内容进行改编，不适合从零开始创作
2. **无法保证质量**：生成内容的质量完全依赖Prompt设计和AI能力，需要人工审核
3. **没有版本管理**：无法跟踪内容的多次修改历史
4. **缺乏协作功能**：不支持多人同时编辑或评论

### 如果用户想做X，应该换什么工具：
- **想做深度原创**：使用Notion、Obsidian等写作工具+AI辅助
- **需要团队协作**：使用Google Docs、飞书文档的协作功能
- **要求精准排版**：直接在目标平台（如公众号编辑器）内使用AI插件
- **需要内容管理**：使用专门的内容管理系统（CMS）或Airtable

**核心学习收获**：这个网页展示了如何将**AI能力**通过**清晰的界面**和**可配置的规则**，封装成一个解决特定工作流的工具。你学到的不是“如何调用API”，而是“如何设计一个让非技术人员也能用好AI的产品界面”。
