# 备餐清单工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正在准备一顿家庭晚餐，或者要为接下来一周的餐食做规划。你需要考虑：家里有几个人吃饭？每个人的饭量如何？需要准备哪些食材？每种食材需要多少量？这个网页就像一个**数字化的厨房助手**，帮你把这些零散的信息整理成一份清晰的购物清单和备餐计划。

它特别适合：
- **家庭主厨**：为家人准备日常餐食时，快速计算食材用量。
- **健身爱好者**：需要精确控制蛋白质、碳水等营养摄入时。
- **活动筹备者**：为聚会、野餐等活动准备食物时，避免买多或买少。
- **新手学做饭**：不知道食材配比时，获得一个参考基准。

**不适合的情况：**
- 需要复杂菜谱步骤指导（这是菜谱App的功能）
- 需要实时调整烹饪火候（这是智能厨具的功能）
- 需要处理特殊饮食需求（如严格过敏原控制）
- 需要多人协作编辑（这是在线协作文档的功能）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你会看到一个类似计算器的界面，有几个输入框：
- 用餐人数（比如：4人）
- 每餐份量（比如：正常、大份）
- 食材类型（比如：肉类、蔬菜、主食）
- （可能还有）特殊要求（比如：低盐、高蛋白）

**用户通常会做哪几步操作？**
1. **设定基础参数**：先输入用餐人数和份量偏好
2. **选择食材类别**：勾选或输入你计划使用的食材
3. **生成清单**：点击“计算”或“生成”按钮
4. **查看结果**：系统会给出每种食材的建议购买量
5. **调整优化**：如果觉得某样食材太多或太少，可以微调参数重新生成

**输出结果长什么样？**
结果通常以卡片或列表形式展示，例如：
```
🥩 鸡胸肉：800克（约4块）
🥦 西兰花：600克（2大颗）
🍚 大米：400克（约2杯）
🧅 洋葱：200克（2个中等大小）
```
有些版本还会显示总花费估算、营养信息等。

**容易忽略的使用细节：**
- **单位切换**：注意结果是按“克”还是“斤”显示
- **保存功能**：生成的清单可以保存，下次直接调用
- **分享选项**：可以把清单分享给家人或直接发给生鲜App
- **历史记录**：系统可能会记住你常用的配比

## 【三】核心结构拆解（学习重点）

这个网页采用了**模块化设计**，理解这个结构是关键：

**1. 配置模块（顶部）**
- **职责**：收集用户的基础需求
- **包含**：人数选择器、份量滑块、饮食偏好选项
- **设计亮点**：使用直观的图标和简洁的文案，降低理解成本

**2. 食材选择模块（中部）**
- **职责**：让用户指定要包含哪些食材
- **包含**：分类标签（肉/菜/主食）、搜索框、常用食材快捷选项
- **设计亮点**：采用“渐进式披露”——先选大类，再选具体食材

**3. 计算引擎模块（背后）**
- **职责**：根据规则计算每种食材的用量
- **包含**：预设的配比公式、单位换算逻辑、调整系数
- **设计亮点**：公式与界面分离，方便后期修改计算规则

**4. 结果展示模块（底部）**
- **职责**：清晰呈现计算结果
- **包含**：清单列表、总计信息、操作按钮（保存/分享/打印）
- **设计亮点**：结果按使用场景分组（如“炒菜用”、“汤用”）

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入（人数+偏好） → 匹配预设模板 → 应用计算公式 → 单位标准化 → 美化展示
```

**最值得学习的设计：**
**“配置驱动”的架构**——所有计算逻辑都基于一个中央配置对象。这意味着：
- 要添加新食材，只需在配置数组里加一项
- 要修改计算公式，只需改一个函数
- 要调整界面，只需改模板部分

这种设计让代码**高度可维护**，也是你能轻松模仿的关键。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
在这个具体版本中，可能没有直接的AI调用。但如果我们想象一个“智能版”备餐工具，Prompt 会扮演**需求理解器**的角色。

**它解决的是“理解问题”还是“生成问题”？**
两者都有：
- **理解问题**：把用户模糊的描述（“做一顿健康的晚餐”）转化为具体参数
- **生成问题**：基于参数生成个性化的食材清单

**哪些信息是 Prompt 中的关键变量？**
如果使用AI，Prompt 模板可能包含：
```
你是一个营养师兼厨师。请为{人数}人设计一份{餐型}的{菜系}餐食。
要求：{特殊要求}。
请列出所有需要的食材，并给出精确的购买量。
格式要求：{输出格式}。
```

**如果只改 Prompt，不改代码，会发生什么变化？**
- 改**角色描述**：从“营养师”改成“省钱达人”，生成结果会更注重性价比
- 改**输出格式**：从“购物清单”改成“冰箱收纳建议”，呈现方式完全不同
- 改**约束条件**：增加“预算不超过100元”，AI会自动调整食材选择

这就是 Prompt 的威力——**不写一行代码，就能改变工具的行为**。

## 【五】如何模仿它，做出你自己的版本？

**安全上手路径：**

**第一步：保持结构不变，替换使用场景（最安全）**
- 把“备餐”换成“旅行打包”
- 输入：旅行天数、目的地气候、出行方式
- 计算：根据模板推荐衣物和用品
- 输出：打包清单
- **为什么安全**：你只需要改文字和预设数据，不用动逻辑

**第二步：调整输入字段或 Prompt**
- 增加“季节”选项（夏季/冬季旅行）
- 增加“活动类型”选项（商务/休闲/探险）
- 修改计算公式：夏季衣服更轻，占用空间系数不同
- **操作**：找到配置对象，修改字段定义和计算函数

**第三步：改变输出形式或展示方式**
- 从“纯文本列表”改为“可勾选的清单”
- 增加“已打包/未打包”状态
- 添加“行李重量估算”
- **操作**：修改结果展示的HTML模板和CSS样式

**从哪里下手最安全？**
从**数据文件**开始。找到那个定义了所有食材和计算公式的JavaScript对象或JSON文件。先在这里做实验，因为：
1. 不会破坏界面
2. 改动效果立即可见
3. 即使改错了，也很容易恢复

## 【六】3–5 个可直接尝试的改造方向

**1. 增加智能推荐（初级）**
- **做什么**：根据用户选择的食材，推荐搭配的调料或配菜
- **如何做**：在配置数据里为每种食材添加`pairings`数组
- **示例**：选了“鸡肉” → 自动推荐“姜、葱、料酒”
- **技术点**：数组查询、条件渲染

**2. 接入价格API（中级）**
- **做什么**：显示实时食材价格和总预算
- **如何做**：调用生鲜电商的公开API（如果有），或手动维护价格数据库
- **示例**：显示“今日鸡胸肉均价：25元/斤，总计约40元”
- **技术点**：API调用、异步数据加载、错误处理

**3. 改为协作版本（中高级）**
- **做什么**：让家人可以共同编辑同一份清单
- **如何做**：使用Firebase或Supabase作为后端，添加用户系统
- **示例**：爸爸加了“牛肉”，妈妈的手机上实时看到更新
- **技术点**：实时数据库、用户认证、冲突解决

**4. 增加进度跟踪（初级）**
- **做什么**：在超市购物时，可以勾选已购买的食材
- **如何做**：为清单项添加复选框，用localStorage保存状态
- **示例**：买了西兰花 → 勾选 → 进度条前进20%
- **技术点**：状态管理、本地存储、进度计算

**5. 生成分享图片（中级）**
- **做什么**：把清单变成美观的图片，方便分享到朋友圈
- **如何做**：使用html2canvas库将结果区域转为图片
- **示例**：点击“生成分享图” → 下载一张带样式的清单图片
- **技术点**：DOM转图片、样式优化、下载功能

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不适合做精准营养计算**
   - **为什么**：食材营养值受品种、产地、烹饪方式影响很大
   - **应该用**：专业的营养计算App（如MyFitnessPal）
   - **本工具定位**：提供大致参考，而非精确数据

2. **不适合处理复杂过敏原**
   - **为什么**：交叉污染、微量过敏原无法通过简单清单避免
   - **应该用**：专门的过敏原管理工具或咨询医生
   - **本工具定位**：基础食材记录，不替代医疗建议

3. **不适合商业厨房**
   - **为什么**：商业厨房需要成本核算、库存管理、供应商对接
   - **应该用**：专业的餐饮管理软件
   - **本工具定位**：家庭和个人使用

4. **不适合生成创意菜谱**
   - **为什么**：创意需要人类厨师的经验和灵感
   - **应该用**：菜谱社区或烹饪课程
   - **本工具定位**：执行已知菜谱的备餐辅助

**记住：** 好的工具知道自己擅长什么，也坦然承认不擅长什么。你的改进方向应该是**强化它的核心优势**，而不是让它变成一个“万能但平庸”的工具。
