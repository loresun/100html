# 决策辅助工具 - 学习与模仿指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景**：
当你面临一个重要的选择（比如换工作、创业、搬家、投资），感到纠结、信息混乱或难以权衡时，这个工具可以帮你。它就像一个“思维教练”，引导你使用专业的分析框架（如SWOT、利弊分析），将模糊的困扰转化为结构化的分析报告，帮你理清思路，看到不同选择的潜在结果和风险。

**适合情况**：
- 个人或团队面临非紧急但重要的决策。
- 决策涉及多个因素（情感、金钱、风险、机会），需要系统梳理。
- 你希望跳出自己的思维定式，获得一个结构化的外部视角。

**不适合情况**：
- 需要即时答案的紧急决策（如危机处理）。
- 纯粹依赖精确数据或复杂计算的决策（如金融建模）。
- 已经拥有明确、可执行的决策流程的团队。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **思维框架**：从6种预设的分析方法（如利弊分析、SWOT）中选择一种。
2.  **决策场景**：在文本框中详细描述你面临的问题和背景。
3.  **备选方案**：（可选）列出你正在考虑的几个选项，每行一个。
4.  **决策标准**：（可选）写下你做决定时最看重的因素（如薪资、成长、稳定）。

**用户通常会做哪几步操作？**
1.  **描述问题**：在“决策场景”框里，尽可能详细地写下你的处境和困惑。
2.  **选择工具**：根据问题的性质，选择一个看起来最合适的“思维框架”。如果不确定，从“利弊分析”开始最安全。
3.  **（可选）补充信息**：如果有明确的选项或标准，填在对应框里。如果没有，完全可以留空，AI会帮你梳理。
4.  **点击分析**：点击页面底部橙色的“开始深度分析”按钮。
5.  **查看报告**：等待片刻，右侧会生成一份详细的Markdown格式分析报告。

**输出结果长什么样？**
输出是一份结构清晰的**决策分析报告**，通常包括：
-   **决策场景总结**：复述并确认你的问题。
-   **备选方案**：列出并可能补充选项。
-   **核心分析**：根据你选择的框架（如SWOT的四个象限）进行详细拆解。
-   **关键风险提示**：指出每个选项可能存在的陷阱。
-   **最终建议**：给出一个综合性的、可操作的行动建议。
报告格式美观，支持标题、列表、表格，并可以展开查看AI的“深度推理过程”。

**有哪些容易忽略的使用细节？**
1.  **首次使用需配置**：第一次点击“开始深度分析”会弹出设置窗口，需要填入你自己的DeepSeek API Key。
2.  **留空也是输入**：“备选方案”和“决策标准”留空时，AI会基于你的场景进行推断和生成，这本身就是一种有用的输入方式。
3.  **利用“推理过程”**：点击“🧠 深度推理过程”可以展开查看AI一步步的思考，这对于理解分析逻辑和学习思考方式非常有价值。
4.  **结果可导出**：生成报告后，可以使用“复制”或“导出”按钮将结果保存为文本或Markdown文件。

## 【三】核心结构拆解（学习重点）

这个页面采用了经典的 **“输入-处理-输出”** 单页应用结构，清晰地将用户界面与AI逻辑分离。

**关键模块与职责：**
1.  **配置管理模块** (`设置弹窗`)：
    -   **职责**：管理用户凭证（API Key）和模型选择。
    -   **设计亮点**：将敏感配置与主功能分离，并通过`localStorage`在本地保存，提升用户体验。

2.  **输入收集模块** (`左侧输入区`)：
    -   **职责**：通过表单（单选、文本框）收集用户的**决策场景**、**思维框架选择**、**备选方案**和**决策标准**。
    -   **设计亮点**：将复杂的决策分析拆解为几个简单的填空步骤，降低了使用门槛。“思维框架”用卡片式单选呈现，直观展示了每种工具的特点。

3.  **AI逻辑处理模块** (`analyzeDecision` 函数)：
    -   **职责**：这是**最核心的模块**。它不直接处理界面，而是负责：
        -   根据用户选择的框架，组装对应的 **System Prompt**（系统指令）。
        -   将用户的输入整理成 **User Prompt**（用户问题）。
        -   调用AI API，并实时处理返回的流式数据，分别更新“推理过程”和“最终结果”。
    -   **设计亮点**：采用了 **“框架模板”** 设计。每个思维框架（如SWOT）都对应一个预定义的输出模板和描述。这使得扩展新的分析框架变得非常简单——只需在`frameworkMap`对象中添加一个新条目即可。

4.  **结果展示模块** (`右侧结果区`)：
    -   **职责**：展示AI返回的“推理过程”（可折叠）和“分析报告”，并提供复制、导出功能。
    -   **设计亮点**：使用`marked`库将AI返回的Markdown文本实时渲染成美观的HTML。将详细的“推理过程”默认折叠，保持了界面的简洁，同时满足了高级用户的好奇心。

**逻辑链路：**
**用户输入** (场景+框架+选项) → **前端组装Prompt** (结合框架模板) → **调用AI API** (DeepSeek) → **流式接收并解析响应** (分离推理与内容) → **前端渲染结果** (Markdown转HTML) → **用户获得报告**

**最值得学习的设计：**
**“框架模板”与Prompt的动态组装**。这是本工具的灵魂。它没有将复杂的分析逻辑写在代码里，而是通过精心设计的Prompt，将不同的“思维框架”作为变量注入，引导AI按特定结构输出。这种设计实现了**业务逻辑（如何分析）与程序逻辑（如何调用）的解耦**，使得工具极其灵活，易于维护和扩展。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt在这里扮演了 **“分析策略调度员”和“输出格式控制器”** 的双重角色。它不是一个简单的提问，而是一份详细的“工作说明书”，告诉AI：
1.  **扮演什么角色**：专业的决策分析顾问。
2.  **使用什么工具**：用户选择的特定思维框架。
3.  **如何处理缺失信息**：如果用户没给方案或标准，AI需要自己推断。
4.  **必须包含哪些分析部分**：如总结、分析、风险、建议。
5.  **最终报告长什么样**：严格的Markdown标题和结构。

**它解决的是“理解问题”还是“生成问题”？**
主要解决 **“生成问题”** 。它的核心任务是：在“理解”用户决策场景的基础上，“生成”一份符合特定框架、结构严谨、内容深入的分析报告。它通过强约束的格式要求，将AI天马行空的生成能力，引导至解决具体问题的轨道上。

**哪些信息是 Prompt 中的关键变量？**
1.  `{selectedFramework.name}`：用户选择的框架名称（如“SWOT分析”）。
2.  `{selectedFramework.template}`：对应框架的报告内容模板（如SWOT的四个象限描述）。
3.  `{form.scenario/options/criteria}`：用户输入的具体决策信息。

**如果只改 Prompt，不改代码，会发生什么变化？**
变化会非常巨大且直接：
-   **改变分析深度**：修改分析要求（如“提供具体数据支撑”），报告会变得更量化。
-   **改变输出风格**：修改输出格式（如要求用表格对比），报告的外观会完全不同。
-   **改变AI角色**：将“决策顾问”改为“风险评估师”，整个报告的侧重点会从“建议”转向“预警”。
-   **扩展新框架**：在`frameworkMap`里添加一个新框架及其模板，页面上就会立刻多出一个可用的分析工具。**这证明了Prompt是此类应用业务逻辑的核心载体。**

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地从模仿走向创新：

**第一步：保持结构不变，替换使用场景（最安全）**
-   **目标**：先做出一个能跑通的“换皮”版本。
-   **操作**：
    1.  复制整个HTML文件。
    2.  修改`<title>`和导航栏中的“决策辅助工具”为你新工具的名字（如“个人职业规划师”）。
    3.  修改`frameworks`数组，将“利弊分析”、“SWOT”等，替换为你的领域下的分析方法（如“技能差距分析”、“市场匹配度评估”）。
    4.  修改所有输入框的`placeholder`提示文字，使其符合你的新场景（如将“决策场景”改为“职业发展现状描述”）。
-   **此时**，你已经有了一个外观全新、但内核逻辑完全相同的工具。

**第二步：调整输入字段或 Prompt（核心改造）**
-   **目标**：让工具更贴合你的具体需求。
-   **操作**：
    1.  **增删输入项**：在左侧表单中增加或删除文本框。例如，增加一个“**行业趋势**”的输入框，让AI结合大环境进行分析。
    2.  **重写Prompt**：这是最关键的一步。深入研究`systemPrompt`和组装`userPrompt`的部分。根据你的新场景，重新定义AI的“角色”、分析“要求”和报告“格式”。确保新Prompt能引导AI产出你想要的答案。
    3.  **更新框架模板**：同步修改`frameworkMap`中每个框架的`template`，使其与你新写的Prompt格式要求匹配。

**第三步：改变输出形式或展示方式（体验优化）**
-   **目标**：让结果展示更符合用户习惯。
-   **操作**：
    1.  **修改结果样式**：调整`.prose`下的CSS，改变报告标题颜色、表格样式等。
    2.  **增加可视化**：如果分析结果包含评分数据，可以考虑用简单的图表库（如Chart.js）将加权评分矩阵绘制成柱状图，让结果更直观。
    3.  **改变交互**：例如，将“备选方案”从文本框改为可以动态添加/删除的列表项。

**从哪里下手最安全？**
**从【第一步】开始，然后立刻进入【第二步】中的“重写Prompt”**。因为Prompt决定了工具的能力上限，先通过修改Prompt验证你的想法是否可行，成本最低，效果最直接。界面调整可以放在最后。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“历史记录”功能**：
    -   **操作**：使用`localStorage`不仅保存配置，也保存每次的分析记录（时间、场景摘要、框架）。在页面左侧或新增一个页面，展示历史记录列表，并支持点击重新加载查看。
    -   **价值**：让用户能够回顾和对比不同时期的决策思考过程，工具实用性大增。

2.  **切换或增加AI模型后端**：
    -   **操作**：在设置弹窗的“模型选择”中，除了DeepSeek，增加OpenAI GPT、Claude或国内其他大模型的选项。修改`callDeepSeek`函数为`callAIAPI`，在里面根据选择调用不同的API端点。
    -   **价值**：为用户提供选择，利用不同模型的特长（如GPT的创造力，Claude的长文本分析），并避免单一API服务中断的风险。

3.  **拆分为“引导”与“分析”两个页面**：
    -   **操作**：将当前页面拆解。第一个页面专注于“问题澄清”，通过更互动的方式（如多步问答）引导用户理清场景、选项和目标。确认后，跳转到第二个页面（即现在的页面）进行深度分析。
    -   **价值**：对于复杂决策，分步引导能获得更高质量的用户输入，从而提升最终分析报告的相关性和深度。

4.  **引入“协作分析”模式**：
    -   **操作**：为“备选方案”和“决策标准”输入框添加“分享链接”功能。生成一个唯一链接，他人打开后可以在同一套输入参数下，选择**不同的**思维框架进行分析，从而获得多角度的报告，便于团队讨论。
    -   **价值**：将工具从个人思考辅助升级为团队决策辅助工具。

5.  **优化“框架选择”的交互**：
    -   **操作**：不要一次性展示所有框架。可以先让用户描述场景，然后AI根据场景描述，**推荐1-3个最适用的框架**供用户选择。这需要先调用一次AI进行轻量级分析。
    -   **价值**：降低用户的选择负担，让工具显得更智能、更贴心。

## 【七】这个网页不适合做什么？（边界提醒）

-   **不适合做精确的量化预测**：它提供的成本收益分析、加权评分中的数值，是基于语义理解的合理估算，**并非精确的财务测算或数据模型**。如果需要基于大量历史数据的精准预测，应使用专业的统计分析软件或定制算法。
-   **不适合替代专业领域咨询**：在医疗、法律、金融投资等高风险专业领域，此工具的分析**仅能作为开阔思路的参考**，绝不能替代执业医师、律师或金融顾问的专业判断和建议。
-   **不适合处理高度模糊或定义不清的问题**：如果用户连自己面临的核心问题都无法清晰描述（例如“我感觉一切都不对劲”），工具很难给出有价值的分析。它需要一定程度的“问题结构化”作为输入起点。
-   **不适合实时动态决策**：它的分析基于提交时刻的静态信息快照。对于市场行情瞬息万变、信息快速更新的决策（如日内股票交易），此工具的分析报告可能迅速过时。

**如果你想做的是上述事情，应该：**
-   寻求专业软件（如Excel、Python+pandas用于数据分析）。
-   咨询该领域的专家。
-   使用专门的预测模型或实时数据API来构建工具。
