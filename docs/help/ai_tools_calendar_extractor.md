# 日历提取器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景**：
想象一下，你收到一封邮件、看到一份会议纪要，或者朋友发来一段旅行计划，里面包含了多个日期、时间和地点信息。你需要把这些零散的日程安排，一个个手动添加到你的手机日历或电脑日历里，这个过程非常繁琐且容易出错。

这个网页就像一个“日程信息翻译官”。你只需要把包含日程的文字（比如“下周三下午3点开会”）粘贴进去，它就能自动识别出所有事件，并生成一个标准的日历文件（.ics格式）。你可以直接把这个文件导入到苹果日历、谷歌日历、Outlook等任何主流日历应用中，所有事件就一次性添加好了。

**适合什么情况？**
*   **处理非结构化文本**：从聊天记录、邮件、文档中提取日程。
*   **批量添加事件**：一次性处理包含多个会议、课程或行程安排的文本。
*   **快速创建日历**：为活动、项目计划或旅行行程快速生成可分享的日历文件。

**不适合什么情况？**
*   **处理高度结构化数据**：如果你的数据已经是整齐的表格（如Excel），有更专业的工具可以直接导入。
*   **需要复杂重复规则的事件**：比如“每月的最后一个周五”，这类复杂规则需要日历应用本身来设置。
*   **对时间解析精度要求极高**：AI虽然智能，但面对非常模糊或歧义的时间描述（如“几号来着，好像是月初”），仍可能出错，需要人工核对。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **核心输入**：一个大的文本框，用于粘贴任何包含时间、事件描述的文本。
2.  **辅助输入**：
    *   **参考日期**：一个日期选择器，用于帮助AI理解“明天”、“下周”这样的相对时间。默认是今天。
    *   **默认提醒**：一组按钮，可以设置事件默认提前多久提醒（如“15分钟前”）。

**用户通常会做哪几步操作？**
1.  **粘贴文本**：将你的日程文本复制粘贴到左侧的大文本框里。
2.  **（可选）设置参考日期和提醒**：如果文本里有“明天”，确保参考日期是对的；如果希望所有事件都有提醒，点选一下。
3.  **点击提取**：按下那个显眼的 **“📅 提取日历事件”** 按钮。
4.  **检查与编辑**：在右侧，你会看到一个事件列表。你可以逐个检查AI提取的结果，点击小铅笔图标可以修改标题、时间、地点等细节。
5.  **导出日历**：
    *   **下载选中**：勾选你需要的事件，然后点击“下载选中”。
    *   **下载系列日历**：点击“下载系列日历”，会生成一个包含所有事件的`.ics`文件。
    *   **预览代码**：切换到“ICS代码预览”标签页，可以看到生成的文件内容。

**输出结果长什么样？**
最终输出是一个后缀为 `.ics` 的文件。用日历应用打开后，它会变成你日历里一个个带有标题、时间、地点和提醒的日程条目，和你手动添加的一模一样。

**有哪些容易忽略的使用细节？**
1.  **必须先配置API Key**：第一次使用时，点击右上角的“设置”按钮，填入你的DeepSeek API Key，否则无法使用AI提取功能。
2.  **参考日期很重要**：如果你粘贴的文本是上周写的，里面说“明天”，请把参考日期改成文本撰写时的日期，否则AI会按“今天”来推算。
3.  **事件可以单独操作**：每个事件卡片右上角有三个小图标，可以**单独下载**、**复制代码**或**删除**该事件，无需操作整个列表。
4.  **使用示例**：如果不确定输入格式，可以点击左下角“示例文本”中的链接，快速加载测试内容。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，像一个高效的生产线：

**1. 输入与配置模块（左侧面板）**
*   **职责**：收集用户的原始数据和偏好设置。
*   **包含**：文本输入框、参考日期选择器、提醒设置按钮、提取触发按钮。
*   **设计亮点**：将**核心输入（文本）** 和**辅助配置（日期、提醒）** 明确分离，让用户操作意图清晰。

**2. 处理与状态管理模块（JavaScript逻辑）**
*   **职责**：这是页面的大脑，负责协调所有操作。它基于Alpine.js框架，管理着所有数据状态（如`events`数组、`selectedEventIds`等）。
*   **关键函数**：
    *   `extractEvents()`：核心函数，负责组装Prompt、调用AI API、解析返回的JSON数据。
    *   各种工具函数：如生成唯一ID、格式化时间、操作选中状态等。
*   **设计亮点**：**状态与视图的自动绑定**。当`events`数组更新时，右侧的事件列表会自动重新渲染，无需手动操作DOM。这是现代前端框架（如Vue、React）的核心思想，这里用轻量的Alpine.js实现。

**3. 输出与交互模块（右侧面板）**
*   **职责**：可视化展示结果，并提供丰富的交互手段。
*   **包含**：
    *   **空状态/加载状态**：友好的占位图，提升体验。
    *   **事件列表视图**：以卡片形式展示事件，支持勾选、编辑、单条操作。
    *   **代码预览视图**：以语法高亮形式展示生成的ICS文件源码，满足技术用户的好奇心或调试需求。
    *   **底部操作栏**：提供批量导出、清空等聚合操作。
*   **设计亮点**：**“预览-编辑-导出”的一体化工作流**。用户无需在不同页面或工具间切换，在一个界面内即可完成从AI提取到人工校准再到最终导出的全过程。

**逻辑链路：**
`用户输入文本` → `点击提取按钮` → `前端组装Prompt并调用AI API` → `AI返回结构化JSON` → `前端将JSON转换为事件对象数组` → `事件数组驱动视图更新` → `用户编辑/选择事件` → `前端根据选择的事件生成ICS文件` → `浏览器下载文件`

**最值得学习的设计：**
**“渐进式呈现”的交互设计**。页面没有一次性展示所有复杂功能。初始状态只有一个简单的输入框。提取后，才展示可编辑的事件列表和多个导出选项。这种根据用户操作步骤逐步提供功能的方式，降低了认知负担，使工具既强大又易用。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 在这里扮演 **“结构化信息提取器”** 的角色。它的任务不是进行开放式的对话或创作，而是严格按照指令，从一段非结构化的自然语言文本中，识别并抽取出格式固定的数据（日历事件）。

**它解决的是“理解问题”还是“生成问题”？**
主要解决 **“理解问题”**，并附带一个严格的 **“格式化生成问题”**。AI需要理解文本中关于时间、事件、地点的描述，但更重要的是，它必须将这种理解转化为一个预先定义好的JSON数据结构，不能自由发挥。

**哪些信息是 Prompt 中的关键变量？**
1.  **系统提示（System Prompt）**：定义了AI的“角色”（日历事件提取专家）和核心规则（必须输出JSON，解析相对日期等）。这是AI行为的基础。
2.  **用户提示（User Prompt）中的动态部分**：
    *   `{this.referenceDate}`：参考日期，是用户提供的变量。
    *   `{this.inputText}`：用户输入的原始文本，是核心变量。
3.  **输出格式示例**：在用户提示中明确给出了期望的JSON结构，这是引导AI生成正确格式的“模板”。

**如果只改 Prompt，不改代码，会发生什么变化？**
1.  **改变提取规则**：例如，在Prompt中增加“如果事件是会议，则在描述中自动添加‘请提前准备材料’”，那么所有提取出的会议事件描述都会带上这句话。
2.  **调整输出格式**：例如，要求AI额外提取“参与人”字段，并添加到JSON中。虽然前端界面暂时不会显示这个新字段，但API返回的数据已经包含了，为后续功能扩展打下了基础。
3.  **切换处理语言**：如果将Prompt中的指令和示例全部改为英文，那么这个工具就变成了一个英文日程提取器。
4.  **改变AI的“性格”**：通过修改系统Prompt，可以让AI更保守（只提取绝对明确的信息）或更积极（尝试推测和补全信息）。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，像搭积木一样创建一个属于自己的AI工具：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **目标**：做一个“食谱提取器”。
*   **操作**：
    1.  复制整个HTML文件。
    2.  将页面标题、Logo、说明文字全部改为与食谱相关。
    3.  将输入框的提示文本改为：“粘贴包含食谱的文本，例如：先准备两个鸡蛋，加入50克面粉，用200度烤箱烤20分钟...”。
    4.  此时，界面焕然一新，但功能逻辑还是日历提取。

**第二步：调整输入字段和 Prompt（核心改造）**
*   **目标**：让AI能提取食谱信息。
*   **操作**：
    1.  修改左侧的“参考日期”等无关输入，可以换成“菜系分类”（下拉选择）或“份数”（数字输入）。
    2.  **最关键的一步**：重写 `extractEvents()` 函数中的 `systemPrompt` 和 `userPrompt`。
        *   系统Prompt改为：“你是一个专业的食谱解析专家...”
        *   用户Prompt中的输出JSON格式示例改为：`{“recipes”: [{“name”: “菜名”, “ingredients”: [“材料1”, “材料2”], “steps”: [“步骤1”, “步骤2”], “cook_time”: “20分钟”}]}`
    3.  相应地，将代码中所有 `event` 改为 `recipe`，`events` 改为 `recipes`。

**第三步：改变输出形式或展示方式（优化体验）**
*   **目标**：让食谱展示更美观。
*   **操作**：
    1.  在右侧的“事件列表视图”中，修改卡片模板。将显示时间、地点的部分，替换为显示材料列表、烹饪步骤。
    2.  可以增加新的展示视图，如“购物清单视图”，将所有食谱的材料自动汇总去重。
    3.  修改导出功能，从下载`.ics`文件变为下载`.json`食谱文件或生成可打印的PDF。

**从哪里下手最安全？**
从 **修改静态文本和UI标签** 开始，然后是 **调整Prompt**，最后再改动 **数据展示和导出逻辑**。这样每一步都能看到可见的变化，且风险可控。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入字段，提升提取精度**：
    *   **操作**：在输入框下方增加一个“时区”选择下拉框。将这个时区信息加入到Prompt中（如“所有时间均视为[用户选择的时区]时间”）。
    *   **效果**：对于跨时区协作的日程文本，AI能更准确地生成绝对时间，避免时区混淆。

2.  **切换或扩展AI模型与API**：
    *   **操作**：在设置弹窗中，除了DeepSeek，增加对OpenAI GPT、Claude或国内其他大模型的支持。修改 `extractEvents()` 函数中的API请求地址和参数格式。
    *   **效果**：用户可以选择不同模型，平衡成本、速度与准确性。也为工具提供了冗余备份。

3.  **拆解流程，增加“确认”步骤**：
    *   **操作**：将“提取”和“编辑/导出”拆成两个页面或两个明显的步骤。第一步页面只负责输入和提取，展示一个简洁的不可编辑的事件概览。用户点击“确认”后，再进入第二个页面进行精细编辑和导出。
    *   **效果**：流程更清晰，尤其适合在提取结果很多时，让用户先宏观确认再微观调整。

4.  **优化交互，增加“智能建议”**：
    *   **操作**：在用户编辑单个事件时，除了手动输入，可以增加一个“小灯泡”按钮。点击后，用当前事件的标题或描述作为Prompt，让AI建议一个更合适的时间或地点（例如：“这个会议放在哪个会议室更合适？”）。
    *   **效果**：将AI从一次性提取工具，升级为持续性的编辑助手，交互更智能。

5.  **增加社交化或协作功能**：
    *   **操作**：在底部操作栏增加“生成分享链接”按钮。点击后，将当前所有事件数据上传到后端或生成一个加密的数据片段，形成一个短链接。其他人打开链接即可看到相同的事件列表并下载。
    *   **效果**：从一个个人工具变为团队协作工具，方便共享活动日程或项目计划。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为永久日历管理系统**：
    *   **局限性**：它不存储数据，所有操作发生在浏览器内存中，刷新页面就会丢失。生成的ICS文件是“只读”的，导入日历后，在日历里的修改不会同步回这个工具。
    *   **应该怎么做**：如果需要管理复杂的、需要持续更新的日历，请直接使用Google Calendar、Outlook等专业的日历服务。

2.  **不适合处理法律、医疗等对准确性要求极高的正式日程**：
    *   **局限性**：AI提取可能存在误差，尽管提供了编辑功能，但初始错误可能导致用户疏忽。
    *   **应该怎么做**：对于法庭开庭、医疗预约等关键日程，必须人工核对原始文件，并使用官方系统或人工方式录入。

3.  **不适合解析图片或PDF中的日程**：
    *   **局限性**：它只能处理纯文本。如果你有一张会议海报的截图或PDF日程表，它无法直接读取。
    *   **应该怎么做**：需要先用OCR（光学字符识别）工具将图片/PDF中的文字提取出来，再将提取出的文本粘贴到本工具中使用。

4.  **不适合创建具有复杂依赖关系的项目计划**：
    *   **局限性**：它生成的是独立的日历事件，事件之间没有关联性（如任务A完成后才能开始任务B）。
    *   **应该怎么做**：应使用专业的项目管理软件，如Asana、Trello、Microsoft Project或甘特图工具。
