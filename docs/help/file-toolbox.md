# Utils 文件处理工具箱 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你手头有一份PDF报告需要拆分成单页发给不同部门，或者有一份很长的会议记录TXT文件，需要快速找到所有提到“预算”的段落。这个网页就是一个**本地文件处理助手**，它让你无需安装任何软件、也无需担心文件上传到陌生服务器的隐私风险，直接在浏览器里完成常见的文件整理工作。

**适合什么情况？**
- **隐私敏感处理**：处理合同、内部报告等不愿上传到第三方服务的文件。
- **快速轻量操作**：只需要简单的拆分、合并、查找，不想打开笨重的专业软件。
- **临时性任务**：偶尔需要处理文件，不值得为此安装一个软件。

**不适合什么情况？**
- **处理超大文件**（例如几百MB的PDF或GB级的文本），浏览器可能会卡顿或崩溃。
- **需要复杂编辑**（如精细的PDF排版、文本格式批量转换）。
- **需要自动化或批量处理**大量文件（它一次只能处理一个或几个文件）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- **文件**：你的PDF、TXT或Markdown (.md) 文件。
- **参数**：比如要拆分的页码范围、水印文字、搜索的关键词等。

**用户通常会做哪几步操作？**
1.  **选择工具**：在页面顶部选择“PDF工具”、“TXT/MD工具”或“PDF合并”。
2.  **上传文件**：点击对应区域的文件选择按钮，从电脑里选中你的文件。
3.  **设置参数**：
    - *PDF工具*：输入页码范围（如“1-3,5”），或设置水印文字、大小。
    - *文本工具*：输入要查找的关键词，选择查看上下文的行数。
4.  **执行操作**：点击对应的功能按钮，如“按页拆分”、“开始搜索”。
5.  **获取结果**：处理完成后，浏览器会自动下载结果文件（ZIP包或单个文件）。

**输出结果长什么样？**
- **PDF拆分/合并**：会下载一个ZIP压缩包，里面是拆分后的单个PDF文件，或直接下载合并后的PDF。
- **文本搜索**：右侧会列出所有包含关键词的段落，点击可以跳转到原文位置。也可以导出为一个包含所有结果的TXT文件。
- **文本拆分**：会下载一个ZIP包，里面是按你设定的规则（行数或大小）分割好的多个TXT文件。

**有哪些容易忽略的使用细节？**
1.  **所有操作都在本地**：页面顶部有“本地解析·无需上传服务器”的提示，请放心使用。
2.  **PDF预览是单页的**：右侧只能预览当前页，需要用“上一页/下一页”按钮翻看。
3.  **文本搜索支持定位**：点击搜索结果，左侧的原文视图会自动滚动并高亮显示命中行。
4.  **Markdown渲染**：只有上传`.md`文件时，“Markdown”预览按钮才会亮起可用。
5.  **文件选择后可以移除**：在“PDF合并”功能中，选错的文件可以点击旁边的“移除”按钮删掉。

## 【三】核心结构拆解（学习重点）

这个页面可以看作一个**多功能文件处理台**，由几个清晰的模块组成：

**1. 控制面板模块（左侧）**
- **职责**：接收用户的“指令”。它提供了三个工具标签页（PDF、文本、合并），每个标签页下是具体的功能表单（上传、参数设置、执行按钮）。
- **逻辑**：用户在这里完成“选择工具 -> 上传文件 -> 配置选项 -> 触发动作”的全过程。它是整个应用的“输入端”和“控制中心”。

**2. 预览与反馈模块（右侧）**
- **职责**：向用户展示“当前状态”和“处理结果”。
    - *PDF工具*：显示当前页的预览，让用户确认文件内容。
    - *文本工具*：双栏显示，左侧是带行号的纯文本，右侧是Markdown渲染效果（如果适用）。下方展示搜索结果。
- **逻辑**：它实时响应左侧的操作。上传文件后立即显示预览；执行搜索后立即展示结果列表。实现了“操作即反馈”的即时体验。

**3. 数据处理引擎（背后的JavaScript逻辑）**
- **职责**：真正的“工人”。它调用不同的库来处理文件：
    - `pdf-lib`：负责PDF的拆分、合并、加水印（创建和修改PDF）。
    - `pdf.js`：负责PDF的渲染和预览（解析和显示PDF）。
    - `JSZip`：负责将多个结果文件打包成一个ZIP供下载。
    - `marked`：负责将Markdown文本转换成HTML进行渲染。
- **逻辑**：这是一个清晰的 **“文件数据 -> 内存处理 -> 输出Blob -> 触发下载”** 的管道。所有复杂操作都被封装在一个个函数里（如 `splitPdfByPage`），通过按钮触发。

**最值得学习的设计：状态管理**
整个应用用一个清晰的 `x-data` 对象 (`utilsApp()`) 管理所有状态。例如：
- `pdfState` 对象管理着PDF文件、当前页码、水印设置等所有相关信息。
- `activeTab` 变量控制着显示哪个工具界面。
这种设计让代码非常整洁：界面通过 `x-show`、`x-text` 等指令直接绑定状态，业务逻辑函数则专注于操作这些状态数据。这是构建复杂交互应用的核心思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

**注意**：当前这个版本的网页**没有使用AI或Prompt**。它是一个纯粹基于规则和算法的本地文件处理工具。

**如果我们要为它添加AI功能，Prompt会如何设计？**
假设我们想增加一个“AI总结文本”的功能，那么Prompt的设计会是这样：
1.  **角色**：扮演一个专业的文档分析助手。
2.  **任务**：总结用户上传的文本文件的核心内容。
3.  **关键变量**：
    - `{fileContent}`：用户上传的文本内容。
    - `{summaryLength}`：用户选择的总结长度（如“简短”、“详细”）。
4.  **变化**：如果只修改Prompt，比如从“总结核心内容”改为“提取所有行动项和负责人”，那么AI的输出就会从一份摘要变成一份待办事项列表，而网页的界面和代码完全不用改动。

这个例子说明了，在AI应用中，**Prompt是连接用户意图和AI能力的“翻译官”和“指挥官”**。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个“替换-调整-创新”的路径，安全地开始：

**第一步：保持骨架，替换场景（最安全）**
- **目标**：做一个“本地图片处理工具箱”。
- **做法**：完全沿用现在的HTML布局和状态管理结构。
    - 把“PDF工具/TXT工具”标签改成“尺寸调整/格式转换/添加滤镜”。
    - 左侧面板放上传图片的按钮和参数（如缩放比例、滤镜类型）。
    - 右侧面板用 `<canvas>` 或 `<img>` 标签来预览图片。
    - 背后的逻辑改用 `Canvas API` 来处理图片，而不是 `pdf-lib`。

**第二步：调整输入与核心逻辑**
- 在第一步的基础上，根据新场景增加或删减输入字段。例如，为图片工具增加“裁剪比例”、“圆角半径”等输入框。
- 重写核心的JavaScript函数。例如，把 `splitPdfByPage` 函数重写为 `resizeImage` 函数，里面调用 `canvasContext.drawImage` 来实现缩放。

**第三步：改变输出与交互形式**
- 输出不一定总是下载文件。比如图片处理工具，可以增加一个“复制到剪贴板”的按钮。
- 交互可以更丰富。比如在图片预览区域，允许用户拖拽一个框来选择裁剪区域。

**从哪里下手最安全？**
从 **第一步** 开始最安全。先原封不动地复制HTML和CSS结构，只修改文字标签和按钮名称，让界面变成你的新主题。这样你能立刻得到一个能运行的新页面框架，然后再逐步替换背后的“内脏”（JavaScript函数）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“批量重命名”工具**：
    - **怎么做**：新增一个“文件整理”标签页。允许用户上传多个任意类型的文件，提供一个输入框让用户输入命名规则（例如“报告_{序号}”），点击后批量重命名并打包下载。
    - **技术点**：使用 `File` API 和 `JSZip`，核心是字符串替换逻辑。

2.  **集成轻量AI功能（如文本润色）**：
    - **怎么做**：在文本工具面板增加一个“AI润色”按钮。上传文本后，点击按钮，将文本内容通过 `fetch` 发送到 OpenAI 或 DeepSeek 等提供免费额度的API，将返回的润色后文本显示在右侧新开辟的预览区，并提供下载。
    - **技术点**：学习调用外部API，设计一个简单的Prompt（如“请以更正式/更简洁的风格重写以下文本”）。

3.  **升级PDF工具：增加“OCR识别”选项**：
    - **怎么做**：在PDF操作区增加一个复选框“提取图片中的文字”。处理PDF时，如果勾选，则使用 `pdf.js` 提取页面中的图片元素，然后调用一个本地的OCR库（如Tesseract.js）进行识别，将识别出的文本附加到输出中。
    - **技术点**：集成更复杂的库（Tesseract.js），处理异步流程和性能问题。

4.  **改善用户体验：增加操作历史记录**：
    - **怎么做**：在页面底部或侧边栏增加一个折叠面板“最近操作”。每当用户成功完成一次处理（如下载了拆分后的ZIP），就在这个面板里添加一条记录，包含时间、操作类型和文件名。点击记录可以快速重新下载（如果浏览器缓存允许）。
    - **技术点**：使用 `localStorage` 在本地存储操作历史，实现一个简单的历史列表组件。

5.  **拆分为多个独立页面**：
    - **怎么做**：将目前的三个主要功能（PDF处理、文本处理、PDF合并）拆分成三个独立的HTML文件。每个页面只专注于一件事，代码更简洁。用一个统一的主页（index.html）来链接它们。
    - **技术点**：学习简单的多页面站点组织，共享通用的CSS和JS库。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做专业的文件编辑**：
    - **局限性**：它无法进行复杂的PDF编辑（如修改文本、调整排版）、也无法进行深入的文本格式处理（如调整字体、样式）。
    - **该用什么**：如果需要深度编辑，请使用专业的桌面软件，如 Adobe Acrobat (PDF)、Microsoft Word 或 VS Code (文本)。

2.  **不适合处理超大批量或自动化任务**：
    - **局限性**：所有操作都需要手动点击上传、设置、执行。无法一次性对上百个文件进行相同操作，也无法设定规则让系统自动处理。
    - **该用什么**：如果需要批量自动化，应该学习使用脚本语言，如 Python（利用 PyPDF2, pandas 等库）或 Shell 命令。

3.  **不适合作为永久文件存储或协作平台**：
    - **局限性**：所有处理结果都直接下载到你的电脑，页面本身不保存任何文件。无法分享处理链接给同事，也无法在线存储中间结果。
    - **该用什么**：如果需要协作和存储，应该使用 Google Drive、腾讯文档、语雀等在线办公套件。

**记住这个工具箱的定位：它是一个“瑞士军刀”，用于快速、临时的本地小任务，而不是“重型机床”。** 了解它的边界，你就能在正确的场景下高效地使用它，并在需要更强大功能时知道该转向何处。
