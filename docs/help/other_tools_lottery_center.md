# 2026新年抽奖中心 - 帮助文档

## 【一】这个网页解决了什么问题？

这个网页是一个**线上年会/活动抽奖工具**，专门解决线下抽奖活动中的几个痛点：

- **使用场景**：公司年会、团队活动、社区聚会等需要现场抽取幸运观众的场合。主持人可以打开这个网页，导入参与人员名单和奖品设置，通过四种不同的视觉化抽奖模式（老虎机、转盘、词云星球、序号抽取）来活跃现场气氛，让抽奖过程更加有趣和透明。
- **适合情况**：适合50-500人规模的活动，需要快速、公平、有仪式感地抽取多个奖项。特别适合需要大屏幕展示、与现场观众互动的场景。
- **不适合情况**：不适合需要复杂抽奖规则（如按部门分配名额、权重抽奖）、需要与外部系统（如CRM、OA）对接、或需要实时在线投票+抽奖结合的场景。

## 【二】使用方式（给第一次接触的人）

### 页面输入是什么？
1. **参与人员名单**：通过“名单设置”弹窗输入，每行一人，支持“姓名,工号”格式
2. **奖品设置**：通过“奖品设置”弹窗输入，每行格式“奖品名称,数量”
3. **抽奖参数**：选择当前要抽的奖品、抽取人数（1-5人）

### 用户通常会做哪几步操作？
1. **初始化设置**：
   - 点击“名单设置”按钮，粘贴或输入参与人员名单
   - 点击“奖品设置”按钮，设置各个奖项的名称和数量
   - 点击“确认解析”保存设置

2. **开始抽奖**：
   - 在“当前奖品”下拉框选择要抽的奖项
   - 在“抽取人数”输入框设置本次要抽几人（最多5人）
   - 选择喜欢的抽奖模式（四种模式可随时切换）
   - 点击“🎯 开始抽奖”按钮，页面会开始动画效果
   - 点击“🛑 停止抽奖”按钮，系统会随机选出中奖者

3. **查看与管理结果**：
   - 中奖结果会立即显示在“恭喜中奖”区域
   - 所有历史记录在下方“抽奖记录”中查看
   - 可点击“📥 导出结果”将数据保存为CSV文件

### 输出结果长什么样？
- **即时展示**：中奖者姓名（和工号）会以金色卡片形式弹出
- **历史记录**：按时间倒序排列，显示奖品、姓名、工号、抽奖时间
- **导出文件**：CSV格式，可用Excel打开，包含所有抽奖记录

### 有哪些容易忽略的使用细节？
1. **名单格式灵活性**：支持“姓名,工号”或“工号,姓名”两种顺序，系统会自动识别中文姓名
2. **奖品数量自动管理**：某个奖品抽完后会自动标记为“不可选”，并自动切换到下一个有库存的奖品
3. **数据自动保存**：所有设置和抽奖记录都会自动保存在浏览器本地，刷新页面不会丢失
4. **模式切换自由**：四种抽奖模式只是视觉效果不同，抽奖逻辑完全一样，可随时切换
5. **最大抽取人数限制**：一次最多抽5人，这是为了保持界面清晰和动画效果

## 【三】核心结构拆解（学习重点）

### 页面由哪几个关键模块组成？
1. **配置管理模块**（弹窗部分）
   - 职责：接收和处理用户输入的原始数据（名单、奖品）
   - 包含：名单设置弹窗、奖品设置弹窗

2. **控制面板模块**（顶部操作区）
   - 职责：提供抽奖参数设置和操作按钮
   - 包含：奖品选择器、人数选择器、开始/停止按钮、设置按钮

3. **展示引擎模块**（中间主区域）
   - 职责：根据当前模式显示相应的抽奖动画
   - 包含：老虎机、转盘、词云星球、序号抽取四种展示器

4. **结果管理模块**（底部区域）
   - 职责：显示当前和历史抽奖结果，提供导出功能
   - 包含：当前中奖者展示区、历史记录列表、导出按钮

5. **状态管理模块**（隐式，通过Vue响应式数据实现）
   - 职责：维护所有数据状态和业务逻辑
   - 包含：候选池、奖品库存、抽奖历史、当前状态等

### 输入 → 处理 → 输出 的逻辑链路
```
用户输入名单/奖品 → 解析为结构化数据 → 存入响应式状态
      ↓
用户点击“开始抽奖” → 启动对应模式的动画 → 持续随机显示候选者
      ↓
用户点击“停止抽奖” → 从候选池随机选取 → 更新状态并显示结果
      ↓
结果自动保存 → 可查看历史 → 可导出CSV
```

### 哪一部分是“这个网页最值得学习的设计”？
**状态与展示的分离设计** 是最值得学习的：
- 抽奖的核心逻辑（随机选择、数据更新）是统一的，与展示模式无关
- 四种展示模式只是同一套数据的四种不同“视图”
- 通过 `currentMode` 这个单一变量控制整个界面的展示形态
- 这种设计让代码易于扩展：要新增一种抽奖模式，只需添加新的展示组件，而不需要修改抽奖逻辑

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：这个网页没有使用AI或Prompt，但我们可以分析它的“业务逻辑设计”

### 逻辑在这个页面中扮演什么角色？
虽然没有AI Prompt，但页面的**业务逻辑**扮演了类似的角色：它定义了“如何理解用户输入”和“如何产生输出”。

### 它解决的是“理解问题”还是“生成问题”？
主要解决**理解问题**：
- **名单解析逻辑**：自动识别“张三,A001”中的姓名和工号，无论顺序如何
- **奖品解析逻辑**：将“特等奖,1”解析为结构化的奖品对象
- **抽奖规则逻辑**：理解“当前奖品库存”、“剩余候选人数”等约束条件

### 哪些信息是关键变量？
1. **pool**：当前可抽的候选人员数组
2. **prizes**：奖品配置数组（含库存）
3. **currentPrize**：当前选中的奖品
4. **drawCount**：本次要抽取的人数

### 如果只改逻辑，不改界面，会发生什么变化？
例如修改名单解析逻辑：
- 原逻辑：自动识别中文姓名
- 新逻辑：强制要求“工号,姓名”格式
- 结果：用户必须按新格式输入，否则解析失败

## 【五】如何模仿它，做出你自己的版本？

### 模仿路径（从安全到创新）

**第一步：保持结构不变，替换使用场景**
- 最安全的起点：只改文案和视觉主题
- 例如做成“课堂点名工具”：
  - 改标题为“课堂随机点名”
  - 改奖品为“回答问题”、“上台演示”等任务
  - 保持四种展示模式，只是含义变了
  - 名单改为学生名单

**第二步：调整输入字段或数据逻辑**
- 修改名单解析逻辑，支持更多格式
- 增加“分组”字段，实现按组抽奖
- 修改奖品逻辑，支持“无限数量”的奖品类型

**第三步：改变输出形式或展示方式**
- 增加“中奖音效”功能
- 修改词云星球为“照片墙”模式，显示人员照片
- 增加“全屏模式”按钮，更适合大屏幕展示

**从哪里下手最安全？**
从 **CSS样式变量**（`:root` 中的颜色定义）开始修改是最安全的。改颜色主题不会影响功能，但能立即获得“属于自己的感觉”。

## 【七】这个网页不适合做什么？（边界提醒）

### 明确局限性
1. **不适合需要“绝对公平审计”的场景**
   - 虽然使用`Math.random()`，但这不是密码学安全的随机数
   - 如果需要可验证的公平性（如彩票），需要更复杂的算法

2. **不适合超大规模（万人以上）名单**
   - 所有数据存在浏览器内存中，万人名单可能影响性能
   - 词云星球模式只显示前30人，大量人员无法看到

3. **不适合需要“复杂规则”的抽奖**
   - 如：经理中奖概率是员工的2倍
   - 如：每个部门至少要有1人中奖
   - 如：已中奖的人不能再参与后续抽奖（本系统支持，但更复杂规则不支持）

4. **不适合“实时在线投票+抽奖”**
   - 没有用户登录和实时投票功能
   - 如果需要“观众投票选出候选人，然后从中抽奖”，需要完全不同的架构

### 如果用户想做X，应该换什么工具？
- **如果需要与公司通讯录集成**：考虑使用企业微信/钉钉的开放API，或使用现成的SaaS抽奖工具
- **如果需要百万级用户的在线抽奖**：考虑使用专门的抽奖平台或自行开发后端系统
- **如果需要严格的公平性证明**：考虑使用区块链或可验证随机函数（VRF）的技术方案
- **如果需要与现场灯光、音乐联动**：考虑使用专业的活动管理软件或硬件控制系统
