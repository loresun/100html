# Webtools 工具箱 - 帮助文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人工具箱**，它解决了日常工作和生活中需要快速使用各种小型工具的需求。想象一下，你正在学习或工作，突然需要计算每日饮水量、记录一笔开销、或者开启一个番茄钟来专注。你不需要去下载多个App或打开复杂的软件，这个页面把所有常用的小工具都集合在了一起。

**适合的使用场景：**
- **快速计算**：如根据体重估算每日饮水量。
- **时间管理**：需要计时、专注（番茄钟）或记录时间（秒表）。
- **随手记录**：临时记下待办事项、笔记或记账。
- **单位换算**：快速进行长度、重量等单位的转换。
- **简单生成**：根据几个输入项，生成一些随机或计算的结果。

**不适合的情况：**
- **复杂数据处理**：如处理大型Excel表格或进行专业的数据分析。
- **长期、专业的项目管理**：它没有团队协作、甘特图等高级功能。
- **需要离线或极高安全性的场景**：数据默认保存在浏览器本地，更换设备或清除缓存会丢失。

## 【二】使用方式（给第一次接触的人）

1.  **打开页面**：你会看到一个标题为“每日饮水量估算”的工具界面。
2.  **理解工具**：页面顶部有工具的名称和简短描述，告诉你这个工具是做什么的。
3.  **进行输入**：
    *   对于“饮水量计算器”，你需要在对应的输入框里填写你的**体重**等信息。
    *   如果是“记账工具”，你需要填写金额、分类和备注。
    *   每个工具的输入区域都很直观，通常就是输入数字、文字或选择选项。
4.  **触发计算/操作**：找到并点击那个醒目的**蓝色按钮**（如“计算结果”、“记录一笔”、“开始”等）。
5.  **查看结果**：结果会直接显示在按钮下方。可能是计算出的饮水量、累计的账单、正在倒计时的时间，或者你刚刚添加的待办事项列表。

**输出结果长什么样？**
- **数字结果**：通常在一个有边框的卡片里，用大号字体突出显示。
- **列表结果**：如待办清单或记账记录，会以一条条项目的形式排列，你可以勾选完成或删除。
- **计时显示**：会有一个动态更新的数字，显示剩余或已过时间。

**容易忽略的使用细节：**
- **数据自动保存**：你在笔记工具里输入的内容，或者在清单里添加的项目，**会自动保存**在你的浏览器里。刷新页面不会丢失，但换一台电脑就看不到了。
- **设置入口**：页面右上角有一个齿轮图标⚙️，点击可以配置AI模型的API Key（部分高级功能可能需要）。
- **返回主页**：左上角的“返回 Webtools”链接暗示这个页面可能是一个更大工具箱的一部分。

## 【三】核心结构拆解（学习重点）

这个页面的设计非常清晰，采用了 **“一个框架，多种工具”** 的模块化思想。

**关键模块：**

1.  **工具配置与状态管理模块（大脑）**：
    *   **职责**：这是页面的核心。它通过 `x-data="webtoolPage(...)"` 定义了一个统一的数据和逻辑中心。所有工具的类型、名称、输入值、结果都存储在这里，并且控制着当前显示哪个工具界面。
    *   **输入**：用户选择的工具标识（如 `water_intake_calculator`）。
    *   **处理**：根据工具标识，加载对应的工具定义（名称、描述、类型、默认值等）。
    *   **输出**：为页面提供渲染所需的所有动态数据。

2.  **动态界面渲染模块（身体）**：
    *   **职责**：根据“大脑”提供的工具类型（`tool.type`），显示对应的用户界面。这是页面中 `x-show="tool.type === '...'"` 的部分。
    *   **子模块**：页面主体部分包含了近10种工具界面（公式计算、计时器、番茄钟、清单、记账等）。**同一时间只显示一个**。
    *   **逻辑**：`tool.type` 是开关。如果它是 `'formula'`，就显示计算器界面；如果是 `'list'`，就显示清单界面。

3.  **通用交互与样式模块（皮肤与骨骼）**：
    *   **职责**：提供一致的视觉风格和基础交互。包括顶部的导航栏、统一的卡片容器、按钮样式、输入框样式等。这主要通过 **Tailwind CSS** 类来实现。
    *   **作用**：让所有不同的工具看起来属于同一个家族，体验一致。

**输入 → 处理 → 输出 的逻辑链路（以“饮水量计算”为例）：**
1.  **输入**：用户在体重输入框输入“70”。
2.  **触发**：用户点击“计算结果”按钮，调用 `calculate(tool)` 函数。
3.  **处理**：`calculate` 函数（在 `standalone.js` 中）读取 `tool.values` 中的所有输入值，按照预定义的公式（如：体重(kg) * 30 ml）进行计算。
4.  **输出**：将计算结果赋值给 `tool.result`。页面自动检测到 `tool.result` 变化，动态更新DOM，将结果显示在按钮下方的卡片中。

**最值得学习的设计：**
**基于数据类型的条件渲染架构。** 它没有为每个工具写一个独立的HTML文件，而是定义了一套工具类型的“协议”（`formula`, `timer`, `list`等）。每个工具只需按照协议提供配置数据，主页面框架就能自动渲染出对应的界面并绑定交互逻辑。这使得**添加一个新工具变得非常高效**，只需要在数据层增加配置，无需大改HTML结构。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：在当前提供的页面代码中，AI功能并未在主体界面直接体现，但设置面板中出现了DeepSeek API的配置项。这表明该工具箱**预留了AI能力扩展接口**。以下分析基于这种设计意图。

1.  **Prompt扮演的角色**：在这个工具箱的上下文中，Prompt（提示词）很可能被设计为**驱动特定工具的核心指令**。例如，在“文本工具”中，Prompt可能被用来定义“请将以下文本翻译成英文”或“请总结以下段落”。
2.  **解决哪类问题**：它主要解决**生成问题**和**复杂理解/转换问题**。比如：
    *   **生成**：根据“随机/生成器”中的几个关键词，生成一首诗或一个故事。
    *   **理解与转换**：在“文本工具”中，对用户输入进行摘要、润色、翻译或格式转换。
3.  **Prompt中的关键变量**：通常是用户的输入。例如，在文本处理工具中，整个用户输入的文本就是Prompt的关键变量部分。系统可能会将用户输入拼接到一个预设的指令模板中，形成完整的Prompt发送给AI。
4.  **只改Prompt，不改代码的变化**：这是该设计强大之处。假设“文本工具”的默认Prompt是“请润色以下文字：{用户输入}”。如果你将后台配置的Prompt改为“请以莎士比亚的风格改写：{用户输入}”，那么整个工具的功能就从“润色”变成了“风格化改写”，而前端界面代码完全不需要动。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循一个“由内到外，由易到难”的路径来安全地模仿：

**第一步：替换内容，理解数据（最安全）**
-   找到 `standalone.js` 文件（虽然未提供，但可从页面逻辑推断），里面应该有一个工具列表。
-   尝试修改一个现有工具的数据。比如，把“每日饮水量估算”的工具描述、输入字段的标签（如把“体重”改成“身高”）、单位（把“kg”改成“cm”）和计算公式。
-   这样你就能在不触碰HTML和CSS的情况下，理解工具是如何被“数据”定义的。

**第二步：创建一种新的工具类型**
-   在 `standalone.js` 的工具列表里，复制一个现有工具的配置对象（比如`formula`类型）。
-   修改它的 `type` 为一个新名字（例如 `'bmi'`），并定义新的 `fields`（身高、体重）和计算逻辑。
-   在HTML主体部分，找到其他工具类型的显示块（如 `x-show="tool.type === 'formula'"`），在其旁边仿照着添加一个新的块：`<div x-show="tool.type === 'bmi'" x-cloak> ... </div>`。
-   在这个新块里，使用类似的Tailwind CSS类，编写BMI计算器需要的输入框和按钮，并绑定对应的函数（如 `calculateBMI(tool)`）。

**第三步：改变外观和布局**
-   保持功能不变，只修改样式。例如，把主卡片的背景色从白色改成浅蓝色，把主要按钮的颜色从靛蓝色改成绿色。
-   尝试调整布局，比如把某些工具的输入框从两列布局改成单列布局。

通过这三步，你就能完全掌握这个项目的结构，并创造出属于自己的个性化工具箱。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“天气查询”工具**：
    *   **操作**：新增一个 `type` 为 `'weather'` 的工具。

    *   **输出**：显示该城市的当前温度、天气状况图标。
    *   **学习点**：如何集成第三方API到现有架构中。

2.  **为“清单工具”增加分类和优先级**：
    *   **操作**：在添加待办事项的输入区域旁，增加一个“分类”下拉选择框（工作、生活、学习）和一个“优先级”选择（高、中、低）。
    *   **处理**：修改 `addListItem` 函数，保存这些额外信息。
    *   **输出**：在每条待办事项前显示优先级标签（如红色角标），并增加按分类筛选的功能。
    *   **学习点**：如何扩展已有工具的数据结构和功能。

3.  **将“记账工具”数据可视化**：
    *   **操作**：在记账工具的结果区域，增加一个“图表”选项卡。
    *   **处理**：引入一个轻量级图表库（如 Chart.js）。当点击“图表”时，遍历 `tool.entries`，按分类汇总金额。
    *   **输出**：绘制一个饼图，直观展示各类别的消费占比。
    *   **学习点**：如何在前端进行简单的数据聚合和可视化。

4.  **实现工具间的数据流转**：
    *   **操作**：在“笔记工具”旁边增加一个按钮“生成待办清单”。
    *   **处理**：点击后，将笔记内容通过AI API（需配置）进行分析，提取出行动项，并自动调用 `addListItem` 函数添加到清单工具中。
    *   **输出**：清单里自动多了几条从笔记中提取的任务。
    *   **学习点**：如何设计工具之间的联动，创造自动化工作流。

## 【七】这个网页不适合做什么？（边界提醒）

-   **不适合做复杂、长期的财务管理**：它的记账功能极其简单，没有账户管理、预算规划、报表导出等功能。如果需要这些，应该使用专业的财务软件如 `MoneyWiz`、`随手记` 或在线表格。
-   **不适合做团队协作**：所有数据都保存在本地浏览器，无法与他人共享或同步。如果需要协同编辑清单或项目计划，应该使用 `Notion`、`飞书文档` 或 `Trello`。
-   **不适合处理敏感信息**：虽然可以设置API Key，但整个应用的前端代码是公开的，不适合存储任何密码、密钥或个人隐私信息。记住“前端无秘密”。
-   **不适合替代专业计算/设计软件**：它的计算器和转换器只能处理简单公式和常用单位。对于工程计算、统计分析或图形设计，请使用 `MATLAB`、`SPSS`、`Figma` 等专业工具。

这个工具箱的精髓在于 **“轻、快、即用即走”** 。理解它的边界，你就能更好地利用它，也知道何时该寻求更强大的专业工具。
