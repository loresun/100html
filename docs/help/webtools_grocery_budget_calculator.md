# 买菜预算计算器 - 学习与改造指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你正准备去超市或菜市场采购一周的食材。你心里有个大概的预算，但不确定具体能买多少东西，或者想看看在不同消费水平下，你的预算能支撑多久。这个网页就像一个“买菜财务顾问”，帮你快速理清预算、家庭人数和消费周期之间的关系，让你对日常开支有更清晰的掌控。

**适合情况：**
- 家庭主妇/主夫规划每周食材采购
- 合租室友计算分摊的伙食费
- 个人记录和监控食品消费习惯
- 需要快速估算“人均每日伙食费”的场景

**不适合情况：**
- 需要精确到每样商品价格的详细购物清单
- 涉及复杂折扣、优惠券的计算
- 商业餐饮的成本核算（需要更专业的工具）
- 长期（如年度）的财务规划

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你会看到几个简单的数字输入框，通常包括：
- **总预算**：你计划花在买菜上的总金额
- **家庭人数**：吃饭的人数
- **天数**：这些食材要支撑多少天
- （可能还有其他如“人均餐数”等）

**操作步骤：**
1. 在对应的输入框中填写你的数字（比如：预算500元、3个人、7天）
2. 点击“计算结果”按钮
3. 查看下方显示的计算结果

**输出结果长什么样？**
结果会以清晰的小卡片形式展示，例如：
- **人均每日花费**：23.8元/人/天
- **总周期人均花费**：166.7元/人
- **每日总花费**：71.4元/天

**容易忽略的细节：**
- 输入数字后**必须点击“计算结果”按钮**，不会自动计算
- 可以尝试调整某个数字，看看其他结果如何变化
- 结果会根据你输入的单位（元、人、天）自动调整显示
- 如果输入了不合理的数字（如天数为0），可能会得到无意义的结果

## 【三】核心结构拆解（学习重点）

这个页面实际上是一个**多功能工具集合**的框架，买菜计算器只是其中一种工具。理解这个框架结构比理解具体计算更重要。

**关键模块组成：**

1. **工具导航与框架模块**
   - 顶部导航栏（返回按钮、设置按钮）
   - 工具标题和描述区域
   - 设置弹窗（用于配置API等）

2. **工具类型分发器**
   - 这是页面的核心设计：通过`tool.type`判断当前是哪种工具
   - 页面同时定义了**10种不同类型的工具模板**，但一次只显示一种

3. **具体工具实现模块**（以公式计算器为例）
   - **输入区域**：动态生成的输入字段（基于`tool.fields`配置）
   - **计算按钮**：触发计算逻辑
   - **结果展示区**：支持单结果和多项结果两种显示方式

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入数字 → 点击计算按钮 → 调用calculate()函数 → 
根据预定义的公式计算 → 更新tool.result → 页面自动重新渲染显示结果
```

**最值得学习的设计：**
**“配置驱动”的UI生成模式**。注意看代码中的`tool.fields`部分——工具的输入字段不是硬编码在HTML里的，而是通过一个配置数组动态生成的。这意味着：
- 要添加新的计算字段，只需修改配置，不用改HTML
- 同样的界面可以复用于不同的计算场景
- 这种模式让代码更易于维护和扩展

## 【四】Prompt / AI 逻辑是如何被设计的？

**重要说明：** 从提供的代码看，这个买菜计算器**并没有使用AI或Prompt**，它是一个纯粹的公式计算器。但是，页面框架预留了AI集成的能力（通过设置中的DeepSeek API配置）。

**如果这是一个AI增强版本，可能会这样设计：**

**Prompt扮演的角色：**
将结构化数据（预算、人数、天数）转化为自然语言建议，例如：
> “根据您500元的预算、3口之家、7天的周期，建议您：优先购买米面粮油等主食，蔬菜选择当季便宜的，肉类可以适当减少……”

**解决的是“生成问题”：**
AI不是用来理解“什么是预算”，而是基于计算结果生成个性化的购物建议、省钱技巧或食谱推荐。

**Prompt中的关键变量：**
- 计算出的数值结果（人均每日花费等）
- 用户原始输入
- 可能的额外上下文（如季节、地区）

**如果只改Prompt，不改代码：**
- 可以改变建议的风格（从严谨的财务建议变成幽默的生活小贴士）
- 可以增加或减少建议的详细程度
- 可以针对不同人群优化建议（学生、家庭、老年人）

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：替换使用场景，保持结构不变**
- 不要动HTML结构和JavaScript框架
- 找到`standalone.js`中关于`grocery_budget_calculator`的定义
- 将工具名称、描述、字段标签改成你的场景
  - 例如改成“健身计划计算器”
  - 字段改为：每周训练天数、每次训练时长、目标周期

**第二步：调整输入字段和计算公式**
- 在工具配置中修改`fields`数组，定义你需要的输入字段
- 在`calculate`函数中找到对应的计算逻辑，修改计算公式
- 确保结果标签（`resultLabel`）与你的场景匹配

**第三步：改变输出展示方式**
- 如果结果不止一个，确保使用数组格式的`result`
- 调整结果卡片的样式或布局
- 考虑是否需要添加解释性文字

**从哪里下手最安全？**
**从修改配置开始**。这个页面的强大之处在于，很多功能都通过`tool`对象的配置实现。先尝试只修改配置数据，不碰HTML和核心逻辑，这样即使出错也容易恢复。

## 【六】3–5 个可直接尝试的改造方向

**1. 增加“智能建议”功能**
- **操作**：在现有计算器下方添加一个“获取AI建议”按钮
- **实现**：点击后调用DeepSeek API，将计算结果作为Prompt的一部分发送
- **Prompt示例**：“用户预算{预算}元，家庭{人数}人，计划使用{天数}天。请提供3条具体的买菜省钱建议。”
- **效果**：从单纯计算升级为“计算+建议”的智能工具

**2. 扩展为“多场景计算器集合”**
- **操作**：在页面顶部添加工具切换选项卡
- **实现**：利用现有的框架，配置多个不同的公式计算器
- **场景示例**：
  - 租房预算计算器（租金、水电、面积）
  - 旅行花费计算器（交通、住宿、餐饮）
  - 学习计划计算器（总课时、每日学习时间、完成天数）
- **优势**：一个页面满足多种计算需求

**3. 添加数据可视化**
- **操作**：在结果区域引入简单的图表库
- **实现**：使用Chart.js或类似库，将结果以饼图或柱状图展示
- **示例**：预算分配图、人均花费趋势图
- **注意**：先从静态图表开始，再考虑交互式图表

**4. 增加本地存储功能**
- **操作**：让计算器“记住”用户上次的输入
- **实现**：使用`localStorage`在用户输入时自动保存
- **扩展**：甚至可以保存多次计算记录，形成简单的历史记录
- **用户体验**：下次打开页面时，数据还在，无需重新输入

**5. 优化为响应式专业工具**
- **操作**：针对移动设备优化交互
- **实现**：
  - 输入时自动聚焦下一个字段
  - 添加“快速填充”按钮（如“典型三口之家”）
  - 计算结果可一键复制
  - 添加分享功能（生成结果摘要图）
- **目标**：让工具在手机上也能流畅使用

## 【七】这个网页不适合做什么？（边界提醒）

**局限性说明：**

1. **不适合复杂财务规划**
   - 这个计算器只做简单的乘除运算
   - 如果涉及利率、通胀、复利等复杂计算，需要专业的财务计算器或Excel

2. **不适合商品级详细预算**
   - 它不会告诉你“500元能买多少斤猪肉、多少斤蔬菜”
   - 对于需要详细商品清单的场景，建议使用专门的记账APP或电子表格

3. **不适合多人协作场景**
   - 所有数据只存在于当前浏览器
   - 如果需要和家人共享预算规划，建议使用在线协作文档或专门的家庭记账APP

4. **不适合动态价格计算**
   - 它假设价格是固定的
   - 现实中菜价每天变化，这个工具无法接入实时价格数据

**如果用户想做X，应该换什么工具：**
- **想做详细的购物清单和比价** → 使用超市官方APP或比价网站
- **想做长期的消费趋势分析** → 使用专业记账软件（如挖财、随手记）
- **需要多人共同管理家庭开支** → 使用协同工具（如腾讯文档、飞书）或家庭记账APP
- **需要根据营养需求规划食谱和预算** → 寻找专业的膳食规划软件
