# Webtools 工具箱 - 帮助文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人工具箱**，它解决了你在日常学习、工作或生活中，需要快速使用各种小型工具，但又不想安装多个App或打开复杂软件的问题。

**使用场景举例：**
- 你正在学习，需要计时25分钟，然后休息5分钟（番茄钟）。
- 你需要快速记录一笔开销，看看本月花了多少钱（记账）。
- 你有一个待办事项清单，想随时添加和勾选完成（清单工具）。
- 你需要一个简单的秒表来测量某个动作的时间。
- 你想把一段文字转换成大写，或者计算一个简单的公式。

**它适合在什么情况下使用？**
- **快速、轻量的任务**：当你需要完成一个简单、独立的任务，不想被复杂软件干扰时。
- **临时性需求**：比如临时需要计时、记账或做笔记，用完即走。
- **学习与模仿**：你想了解如何用代码构建一个包含多种功能的单页面应用。

**它不适合什么情况？**
- **复杂的数据处理**：比如需要复杂图表、大量数据计算的财务分析。
- **团队协作**：这个工具的数据只保存在你的浏览器里，无法与他人共享。
- **专业领域任务**：比如专业的视频编辑、代码编译或大型项目管理。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
这个页面本身是一个“工具箱外壳”。你需要从主页（`index.html`）选择一个具体的工具（如“抛硬币”、“番茄钟”、“记账本”）进入。每个工具都有自己独特的输入框、按钮和设置。

**用户通常会做哪几步操作？**
1.  **选择工具**：从主页进入你想用的工具页面。
2.  **查看界面**：页面会加载该工具的专属界面，上面有名称、描述、输入区域和操作按钮。
3.  **输入与操作**：
    - **对于计时类工具（如番茄钟）**：设置时间，点击“开始”、“暂停”、“重置”。
    - **对于记录类工具（如清单、记账）**：在输入框填写内容，点击“添加”或按回车键。
    - **对于计算类工具（如公式计算器）**：填写数字，点击“计算结果”。
4.  **查看结果**：操作后，结果会直接显示在页面上方的结果区域。

**输出结果长什么样？**
- **计时/计数类**：通常是一个大号的数字显示，如“25:00”或“3”。
- **记录/清单类**：以列表形式展示你添加的条目，每条都可以操作（如删除、勾选）。
- **计算/生成类**：在一个有边框的卡片里显示计算结果或生成的文本。

**有哪些容易忽略的使用细节？**
1.  **数据存储**：你添加的清单、笔记、记账数据都**只保存在你当前浏览器的本地存储中**。如果你清除了浏览器数据或换了电脑，数据会丢失。
2.  **设置按钮**：页面右上角的齿轮图标（⚙️）是 **API 配置**，主要用于需要调用AI模型（如DeepSeek）的高级工具。对于大部分基础工具（计时、清单），你不需要理会它。
3.  **实时保存**：在“笔记工具”中，你输入内容时会**自动保存**（有400毫秒延迟），无需手动点击保存按钮。
4.  **返回主页**：点击左上角的“返回 Webtools”可以回到工具选择页面。

## 【三】核心结构拆解（学习重点）

这个网页采用了 **“外壳-插件”** 的模块化设计，非常清晰，是学习的重点。

**页面由哪几个关键模块组成？**
1.  **导航栏模块**：顶部区域，包含返回链接和设置按钮。职责是提供页面导航和全局配置入口。
2.  **工具容器模块**：中间最大的白色卡片区域。它是一个**动态容器**，职责是根据当前加载的“工具类型”，显示对应的界面和逻辑。
3.  **工具类型子模块**：容器内部，通过 `x-show="tool.type === 'xxx'"` 控制显示。例如 `timer`（计时器）、`list`（清单）、`ledger`（记账）等。每个子模块都有自己的HTML结构、数据模型和操作函数。
4.  **设置弹窗模块**：一个浮在页面顶层的弹窗，用于配置API密钥等。职责是管理应用级配置。

**每个模块承担什么职责？**
- **导航栏**：全局UI和导航。
- **工具容器**：充当路由器，决定显示哪个工具界面；并作为数据总线，持有当前工具的所有状态（`tool` 对象）。
- **工具子模块**：负责具体功能的**视图渲染**和**用户交互绑定**。它定义了用户看到什么、能输入什么、能点击什么按钮。
- **设置弹窗**：管理外部服务（如AI API）的配置。

**输入 → 处理 → 输出 的逻辑链路是怎样的？**
以 **“清单工具” (`type: 'list')** 为例：
1.  **输入**：用户在输入框打字，数据绑定到 `tool.input` 变量。
2.  **触发处理**：用户点击“添加”按钮或按回车键，触发 `addListItem(tool)` 函数。
3.  **核心处理**：`addListItem` 函数（在引用的 `standalone.js` 中）会：
    - 从 `tool.input` 获取文本。
    - 生成一个带 `id`、`text`、`done` 状态的新条目对象。
    - 将这个对象 `push` 到 `tool.items` 数组中。
    - 清空输入框。
    - 调用 `saveList(tool)` 将整个 `tool.items` 数组保存到浏览器本地。
4.  **输出**：由于 `tool.items` 数组被更新，页面上通过 `<template x-for="(item, index) in tool.items">` 循环渲染的部分会自动重新生成HTML，新的条目就出现在列表里了。

**哪一部分是“这个网页最值得学习的设计”？**
**动态工具加载与统一数据管理模型**。
- 它没有为每个工具写一个独立的HTML文件，而是用一个**统一的页面框架**，通过改变一个核心的 `tool` 对象（包含 `type`, `name`, `fields`, `values` 等属性）来切换完全不同功能的界面。
- 这种设计使得**添加一个新工具变得非常容易**：你只需要在 `standalone.js` 里定义好这个工具的数据结构和函数，然后在页面HTML里为它写一段对应的“子模块”HTML代码（用 `x-show` 控制）。框架和交互逻辑都是复用的。
- 这是构建可扩展Web应用的经典思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
在这个版本的代码中，**Prompt并没有直接出现在前端HTML里**。设置弹窗中配置的DeepSeek API Key和模型选择，暗示了某些工具（可能是“文本工具”或“生成器”）未来会调用AI API。在这些工具中，Prompt将是**预先设计好的一段文本模板**，用于指导AI如何理解用户的输入并生成合适的回复。

**它解决的是“理解问题”还是“生成问题”？**
从“文本工具”、“生成器”这类工具的名称推断，它主要解决的是**生成问题**。例如，用户输入一些关键词，Prompt会指导AI“根据这些关键词生成一段故事”或“将这段文字翻译成英文”。

**哪些信息是 Prompt 中的关键变量？**
如果存在，关键变量通常是：
1.  **用户输入**：来自页面输入框的内容，会被插入到Prompt模板中。
2.  **工具指令**：描述这个工具要做什么的固定文本，例如“你是一个翻译助手，请将以下中文翻译成英文：”。
3.  **格式要求**：对AI输出格式的约束，比如“请用JSON格式输出”或“只输出结果，不要解释”。

**如果只改 Prompt，不改代码，会发生什么变化？**
假设“文本工具”调用了AI，且只修改其Prompt模板：
- **功能本质变化**：例如，将Prompt从“翻译成英文”改成“总结成一句话”，那么这个工具就从“翻译器”变成了“总结器”。
- **输出质量变化**：优化Prompt的措辞、增加示例，可以显著提高AI输出结果的准确性和可用性。
- **用户体验变化**：用户感受到的是工具的能力发生了改变，而界面和操作方式完全没变。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“模仿路径”，从最安全、最简单的改动开始：

**第一步：替换内容，理解结构（最安全）**
- **目标**：在不改动任何逻辑的情况下，创建一个“新”工具。
- **操作**：
  1.  在 `standalone.js` 文件中，找到一个现有工具的定义（比如 `listTool` 清单工具）。
  2.  复制整个工具对象，修改它的 `id`, `name`, `desc`，创建一个新的工具对象，例如 `wishListTool`（愿望清单）。
  3.  在HTML中，找到 `<!-- 清单工具 -->` 对应的那个 `<div>` 块。
  4.  复制整个块，将 `x-show="tool.type === 'list'"` 改为 `x-show="tool.type === 'wishlist'"`（与你JS中定义的 `type` 一致）。
  5.  微调这个HTML块里的文字，比如把“输入内容”改成“输入你的愿望”。
- **结果**：你现在拥有了一个外观和清单一模一样，但名字和描述不同的“愿望清单”工具。通过这一步，你理解了工具是如何从JS定义映射到HTML显示的。

**第二步：调整数据模型和交互**
- **目标**：让工具的功能发生实际变化。
- **操作**：继续修改你上一步创建的 `wishListTool` 对象和对应的HTML。
  - **在JS中**：给工具对象增加新属性。例如，增加一个 `priority`（优先级）字段到每个愿望条目中。
  - **在HTML中**：在列表的每个条目里，增加一个选择框 `<select>` 来让用户选择优先级（高、中、低），并使用 `x-model` 绑定到 `item.priority`。
  - **在JS函数中**：修改 `addListItem` 和 `saveList` 函数，确保能处理这个新字段。
- **结果**：你的愿望清单工具现在有了“优先级”功能，它和原来的清单工具已经不同了。

**第三步：创建全新的工具类型**
- **目标**：实现一个完全不同的功能。
- **操作**：
  1.  **设计数据模型**：在JS中定义一个全新的工具对象。例如一个 `diceTool`（掷骰子），它可能需要 `sides`（骰子面数）和 `result`（结果）属性。
  2.  **编写核心函数**：在JS中写一个 `rollDice(tool)` 函数，用来生成随机数并更新 `tool.result`。
  3.  **编写视图模板**：在HTML中，找一个结构简单的工具模块（如“计数器”）作为参考，编写一个新的 `<div x-show="tool.type === 'dice'">` 模块。里面包含设置面数的输入框、一个“掷骰子”按钮和显示结果的区域。
  4.  **绑定交互**：确保按钮的 `@click` 事件调用你写的 `rollDice` 函数。
- **结果**：你成功向这个工具箱添加了一个全新的“掷骰子”工具。

## 【六】3–5 个可直接尝试的改造方向

1.  **为现有工具增加数据导出功能**
    - **问题**：清单、记账的数据锁在浏览器里，无法带走。
    - **改造**：在“清单工具”的HTML模块底部，增加一个“导出”按钮。点击后，调用 `JSON.stringify(tool.items)` 将数据转为字符串，并显示在一个 `<textarea>` 中让用户复制，或者创建一个下载链接。
    - **进阶**：再增加一个“导入”按钮和输入框，允许用户粘贴JSON字符串来恢复数据。

2.  **将“番茄钟”与“笔记”工具结合**
    - **问题**：专注结束后，有时想记录刚才的收获。
    - **改造**：修改番茄钟的逻辑，当每次“专注阶段”结束时，自动弹出一个小的提示框或直接聚焦到“笔记工具”的输入框，鼓励用户记录。
    - **实现**：在 `startPomodoro` 的计时器回调函数中，当判断 `phase` 从 `work` 切换到 `break` 时，可以尝试自动切换到 `note` 工具，或者设置一个全局标志。

3.  **为工具添加“云同步”雏形**
    - **问题**：数据无法跨设备。
    - **改造**：利用设置弹窗里已有的API配置。选择一个简单的云存储服务（如Supabase或腾讯云COS的简单接口），修改 `saveList`, `loadTool` 等函数。在保存时，不仅存本地，也尝试调用API将数据发送到云端（需要用户配置了API Key）；在加载时，优先尝试从云端拉取数据。
    - **注意**：这是一个较大的改动，涉及网络请求和错误处理，但能极大提升工具实用性。

4.  **优化UI/UX：增加主题切换和响应式改进**
    - **问题**：只有一种颜色主题，在夜间使用可能刺眼。
    - **改造**：
        - 在设置弹窗里增加一个“主题”选择（浅色/深色）。
        - 在JS中监听这个选择，动态为 `<body>` 标签添加或移除一个 `dark` 类。
        - 在CSS中，为所有颜色定义CSS变量，并编写两套主题变量。例如：`:root { --bg-color: white; --text-color: black; }` 和 `.dark { --bg-color: #1a1a1a; --text-color: #e5e5e5; }`，然后将HTML中的颜色类替换为这些变量。
    - **结果**：让你的工具箱拥有夜间模式。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合处理敏感或重要数据**
    - **局限性**：数据存储在浏览器本地，容易被清除，且没有加密。**切勿**用它记录密码、重要证件号或唯一的业务数据。
    - **应该怎么做**：对于重要数据，请使用专业的、有端到端加密和可靠备份的笔记或密码管理软件，如 Obsidian、1Password 等。

2.  **不适合进行复杂、连锁的任务自动化**
    - **局限性**：每个工具都是孤立的。你不能设置“当番茄钟结束 → 自动打开笔记工具 → 自动填入特定文本”这样的工作流。
    - **应该怎么做**：如果需要自动化工作流，应该学习使用专业的自动化平台，如 n8n、Zapier，或者编写更复杂的脚本。

3.  **不适合作为团队协作工具**
    - **局限性**：所有数据都是本地存储，无法实时共享给他人查看或编辑。
    - **应该怎么做**：团队协作应使用 Google Docs、腾讯文档、Trello、飞书等支持实时协同的在线工具。

4.  **不适合替代专业软件**
    - **局限性**：它的“记账”功能极其简单，没有分类报表、预算管理；“笔记”功能没有富文本、文件夹管理。
    - **应该怎么做**：对于深度需求，请使用专业软件：财务管理用 MoneyWiz、随手记；笔记用 Notion、语雀；项目管理用 Trello、Asana。

**总结**：这个网页是一个优秀的**学习范例**和**个人效率辅助工具**。它的价值在于展示了如何用清晰的架构组织多个功能，并为你提供了可以随意修改和扩展的“代码沙盒”。请享受改造它的过程，并清晰地认识到它的能力边界。
