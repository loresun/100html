# 账单日历 - 学习与使用指南

---

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你每个月都要处理房租、信用卡、水电费等一堆账单。它们到期日不同，容易忘记，导致逾期罚款。这个网页就像一个**个人账单管家**，帮你把所有待付账单集中在一个日历式的列表中，让你一眼看清“什么时间、要付多少钱”，并可以轻松标记已付。

**适合情况：**
- 个人或家庭管理每月固定支出。
- 需要简单、直观地追踪待付账单，避免遗忘。
- 希望快速了解本月财务压力（待付总额）和已完成的支付。

**不适合情况：**
- 需要复杂的预算规划、收入记录或投资跟踪。
- 需要多人协作或共享账单。
- 需要对接真实的银行账户进行自动扣款或对账。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要输入每笔账单的四个核心信息：
1.  **账单名称**：如“3月房租”、“XX信用卡”。
2.  **分类**：从预设的类别（房租、水电、信用卡等）中选择一个。
3.  **金额**：填写具体金额。
4.  **到期日**：选择日历上的日期。

**用户通常会做哪几步操作？**
1.  **添加账单**：点击右上角绿色的“记一笔”按钮，在弹出的窗口中填写上述信息，然后点击“保存”。
2.  **查看与管理**：
    *   默认进入“待支付”标签页，这里按到期日顺序列出了所有未付账单。
    *   查看顶部卡片，了解“待支付”总额和“本月已付”总额。
    *   找到需要处理的账单，点击右侧的“支付”按钮。
    *   支付时，如果账单设置了“按月重复”，系统会询问你是否自动生成下个月的账单。
3.  **查看历史**：点击“历史记录”标签页，可以查看所有已支付的账单，也可以在这里删除记录。

**输出结果长什么样？**
*   **待支付列表**：每个账单是一个美观的卡片，显示名称、分类图标、到期日和金额。**已逾期的账单会变成醒目的红色**。
*   **统计卡片**：顶部两个卡片动态显示待付总额和本月已付总额。
*   **历史记录**：已支付的账单会变成灰色，并打上勾选标记，移到历史列表中。

**有哪些容易忽略的使用细节？**
1.  **重复账单功能**：在添加账单时，最下方有一个“按月重复”的复选框。勾选后，当你标记这笔账单为“已支付”时，它会询问你是否自动创建一份下个月同一天的账单。**这个功能非常适合房租、月供等固定支出。**
2.  **数据存储**：所有账单数据都保存在你**浏览器的本地存储（LocalStorage）** 中。这意味着：
    *   换一台电脑或浏览器，数据不会同步。
    *   清除浏览器缓存后，数据会丢失。
    *   这是为了演示的简便性，也是你学习时可以模仿的点。
3.  **逾期判断**：系统会自动比较账单的“到期日”和“今天”的日期。如果到期日已过，账单卡片会显示“已逾期”标签并变红。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为五个模块，各司其职：

1.  **数据管理模块（核心大脑）**
    *   **职责**：在内存中维护一个`bills`数组，存储所有账单对象。每个对象包含`id, name, amount, date, category, status, repeat`等属性。负责数据的增删改查（CRUD）逻辑。
    *   **关键设计**：使用 **计算属性（`get unpaidBills()`）** 来动态筛选和排序数据。例如，`unpaidBills`自动从`bills`中过滤出`status`为`'unpaid'`的项并按日期排序。这种“声明式”逻辑让界面更新变得非常简单。

2.  **状态展示模块（信息面板）**
    *   **职责**：页面顶部的两个统计卡片。它们不负责计算，只负责显示由数据模块计算好的`unpaidTotal`和`paidTotal`。
    *   **输入→处理→输出**：`bills`数据变化 → 触发`unpaidTotal`计算属性重新计算 → 卡片上的数字自动更新。

3.  **视图切换模块（标签页）**
    *   **职责**：通过一个`tab`变量（值为`'unpaid'`或`'history'`）控制当前显示哪个列表。这是典型的**条件渲染**思路。
    *   **逻辑链路**：用户点击标签 → 改变`tab`变量 → `x-show="tab === 'unpaid'"`等指令控制下方对应的`<div>`显示或隐藏。

4.  **列表渲染模块（主要内容）**
    *   **职责**：根据当前标签和对应的计算属性（`unpaidBills`或`historyBills`），使用`x-for`指令循环渲染出每一个账单卡片。
    *   **最值得学习的设计**：**卡片UI与数据状态的强绑定**。卡片的颜色（是否逾期）、图标（根据分类）、文字都通过函数（`isOverdue`, `getIcon`, `formatDate`）实时从数据中计算得出。这使得UI能智能地响应数据变化。

5.  **表单交互模块（添加/修改入口）**
    *   **职责**：弹出一个模态窗口（Modal），收集用户输入，并通过`addBill`方法将新账单对象提交给数据管理模块。
    *   **关键设计**：使用一个`form`对象来双向绑定（`x-model`）所有输入字段的值，表单提交时，直接使用这个对象来生成新账单。

**这个网页最值得学习的设计：**
**“单一数据源”和“响应式”的架构。** 所有UI状态（显示什么列表、统计数字、卡片样式）都源于一个核心的`bills`数组。当这个数组发生变化（增、删、改状态），所有依赖它的计算属性、列表、统计数字都会自动、同步地更新。这极大地简化了状态管理的复杂度，是构建现代交互式Web应用的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **注意：** 当前提供的这个账单日历网页**没有使用AI或Prompt**。它是一个纯前端的数据管理应用。因此，这一部分我们将探讨 **“如果”要加入AI功能，可以如何设计**，这本身也是一个重要的学习点。

**假设我们要加入一个功能：“用自然语言快速添加账单”，例如输入“下个月5号交房租3000元”，系统自动解析并填充表单。**

1.  **Prompt扮演的角色**：Prompt将成为**用户自然语言与结构化数据之间的翻译官**。它需要指导AI模型（如GPT）从一段文本中提取出“账单名称”、“金额”、“日期”、“分类”等关键信息。

2.  **解决的是“理解问题”**：它需要让AI理解“房租”、“电费”可能对应“家居”分类，“下个月5号”需要转换成具体的日期格式（如2024-04-05）。

3.  **Prompt中的关键变量**：
    *   **用户输入**：`{user_input}`（变量）
    *   **分类列表**：`{categories}`（常量，如[‘房租’， ‘水电’， ‘信用卡’…]）
    *   **输出格式要求**：必须严格指定AI返回一个JSON对象，例如`{“name”: “”, “amount”: 0, “date”: “”, “category”: “”}`。

4.  **如果只改Prompt，不改代码，会发生什么变化？**
    *   **提高准确性**：优化Prompt可以让AI更准确地识别金额中的数字和日期中的模糊表述（如“月底”、“下周”）。
    *   **扩展能力**：通过修改Prompt，可以让AI识别更多信息，比如“这是一笔重复账单”，从而自动勾选“按月重复”复选框。
    *   **改变交互**：Prompt的引导方式变了，用户说话的方式也可以更随意，从“填表”变成“对话”。

## 【五】如何模仿它，做出你自己的版本？

这是一个非常清晰的项目结构，非常适合作为模板进行二次创作。

**第一步：保持结构不变，替换使用场景（最安全）**
这是风险最小的起步方式。不要动任何核心代码逻辑，只做“表面替换”。
*   **目标**：做一个“个人任务看板”。
*   **操作**：
    1.  将“账单”改名为“任务”。
    2.  将“分类”改为“优先级”（高、中、低）或“项目”（工作、学习、生活）。
    3.  将“金额”字段改为“预估耗时（小时）”。
    4.  将“到期日”改为“截止日期”。
    5.  将“支付”按钮改为“完成”按钮。
    6.  将顶部的统计卡片改为“待完成任务”、“本周已完成”。
    7.  修改`categories`数组中的图标和名称。至此，一个全新的任务管理工具就诞生了。

**第二步：调整输入字段或数据模型**
在第一步成功的基础上，开始修改数据本身。
*   **目标**：让“任务看板”支持子任务。
*   **操作**：
    1.  在`form`对象和账单/任务对象中，增加一个`parentId`字段。
    2.  在`addBill`函数中，处理父子关系的逻辑。
    3.  在列表渲染时，根据`parentId`来缩进显示子任务。
    这一步开始涉及逻辑修改，需要更小心。

**第三步：改变输出形式或展示方式**
改变UI的呈现方式，给用户新的视角。
*   **目标**：为“账单日历”增加一个真正的日历视图。
*   **操作**：
    1.  增加第三个标签页，叫“日历视图”。
    2.  在这个标签页下，使用一个第三方日历库（如`FullCalendar`）或自己用CSS Grid画一个简单的月历。
    3.  将`bills`数据按日期映射到日历的每一天格子中显示。
    这一步主要考验的是UI集成能力。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加账单备注/图片附件功能**：
    *   **操作**：在表单中添加一个`<textarea>`用于备注，和一个`<input type=”file”>`用于上传图片（如缴费单截图）。数据存储时，图片可以转换为`Base64`字符串存到`localStorage`，或上传到免费图床。在账单卡片上增加一个图标，点击可以展开查看备注和图片。

2.  **更换数据存储方式，实现多设备同步**：
    *   **操作**：将`localStorage`替换为云数据库。可以使用**Supabase**或**Firebase**的免费计划。代码中`init()`从云端读取，`addBill`、`markPaid`等操作在修改本地数据后，同步调用API更新云端。这是从“玩具”应用到“实用”应用的关键一步。

3.  **拆分为多页面，并增加账单分析**：
    *   **操作**：将当前单页面应用（SPA）拆解。
        *   `index.html`：主列表页（即当前页面）。
        *   `analysis.html`：分析页。使用`Chart.js`库，从`bills`数据中生成图表，如“每月支出趋势图”、“分类占比饼图”。两个页面通过URL参数或共享`localStorage`来传递数据。

4.  **优化交互体验：增加拖拽排序与筛选**：
    *   **操作**：引入一个轻量级拖拽库（如`SortableJS`）。允许用户在“待支付”列表里通过拖拽来手动排序优先级。在列表顶部增加一个下拉筛选器，可以按“分类”或“是否逾期”来过滤显示的账单。

5.  **增加简单的预算提醒功能**：
    *   **操作**：在页面顶部或设置中，允许用户设置一个“月度预算总额”（如5000元）。计算`unpaidTotal`（待付） + `paidTotal`（本月已付）得到“本月总支出”，并与预算比较。当总支出接近或超过预算时，在界面上用明显的颜色或警告图标进行提示。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为专业的会计或财务软件**：它没有复式记账、账户管理、损益表、资产负债表等专业功能。如果你需要管理公司财务或进行复杂的个人资产配置，应该使用**专业的财务软件**（如QuickBooks、金蝶、或者薄荷记账等更专业的App）。

2.  **不适合需要严格安全性和持久化存储的场景**：由于数据仅存储在浏览器本地，它极易丢失，且没有任何安全防护。**绝对不能**用于存储任何敏感信息（如真实的银行账号、密码）。对于重要数据，必须使用有后端验证和数据库的成熟服务。

3.  **不适合处理复杂、非重复性的现金流记录**：例如，记录每天零散的咖啡、午餐消费，它会显得非常繁琐。它的设计更适合管理**规律性、金额较大的固定支出**。对于日常记账，使用支持快速扫码输入、有丰富类别的记账App体验会更好。

4.  **不适合团队或家庭共享**：它没有用户系统，数据无法在家人或室友之间共享和协同编辑。如果需要共同管理家庭账单，应该寻找支持**多用户共享**的在线工具。

希望这份指南能帮助你不仅会使用这个工具，更能理解其设计精髓，并最终创造出属于你自己的、更棒的应用！
