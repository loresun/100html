# 家务清单 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你住在一个公寓或家里，每天/每周都有各种家务要做：洗碗、拖地、整理房间……事情一多就容易忘记，或者不清楚哪些已经完成、哪些还没做。这个网页就是一个**个人家务任务管理器**。

**适合的使用场景：**
- **个人或合租者**：用来追踪自己或室友的家务完成情况。
- **希望建立清洁习惯的人**：通过可视化的进度条和“整洁度”分数，获得完成任务的成就感。
- **需要分区域管理**：比如厨房、客厅、卫生间分开，思路清晰。

**不适合的情况：**
- **需要严格时间安排或提醒**：它没有定时通知功能。
- **多人协作与责任分配**：它无法区分任务由谁完成，也没有复杂的权限管理。
- **处理非常复杂或项目化的任务**：它只适合简单的、重复性的日常家务。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 页面加载后，你会看到预设的几个区域（如厨房、客厅）和对应的家务列表。
- 每个家务项前面有一个方框，后面可能有一个垃圾桶图标。

**用户通常会做哪几步操作？**
1.  **完成任务**：点击家务项前面的方框（✅），表示你今天完成了这项家务。完成的项目会变成灰色并带有删除线。
2.  **添加新家务**：在每个区域的底部，有一个输入框，输入家务名称（如“擦窗户”）后按回车键，即可添加到该区域。
3.  **添加新区域**：滚动到页面底部，点击“添加新区域”按钮，输入区域名称（如“阳台”），就会创建一个全新的家务分组。
4.  **删除家务**：将鼠标悬停在家务项上，右侧会出现一个垃圾桶图标，点击即可删除该项。
5.  **折叠/展开区域**：点击每个区域的标题栏，可以收起或展开该区域下的所有家务，方便浏览。

**输出结果长什么样？**
- **视觉反馈**：完成的家务会打勾、变灰、加删除线。每个区域标题下有一个细长的进度条，显示该区域的任务完成比例。
- **核心数据**：页面右上角有一个圆形进度环和“整洁度”百分比，这是所有家务的总体完成度。
- **持久化**：你所有的操作（添加、删除、完成）都会自动保存在你的浏览器里。下次打开同一台电脑的同一个浏览器，数据还在。

**有哪些容易忽略的使用细节？**
- **“上次完成”时间**：每个家务项下方会显示“上次: 今天”或具体日期。这有助于你回忆某项家务是多久前做的。
- **频率标签**：每个家务右侧有一个“每日”或“每周”的小标签。目前这是预设的，但它是未来可以扩展的重要信息。
- **“整洁度”计算逻辑**：它只计算**今天**是否完成。如果你昨天完成了所有家务，但今天还没做，整洁度会显示0%。它是一个“当日完成度”指标。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为几个模块，每个模块各司其职：

1.  **状态与数据管理模块（大脑）**
    - **职责**：存储所有数据（区域、家务、完成状态），并计算衍生数据（进度、分数）。它通过 `choreApp()` 函数返回的对象来实现。
    - **关键数据**：`areas` 数组是核心，每个 `area` 包含 `chores` 数组。`localStorage` 用于数据持久化。

2.  **信息展示与交互模块（脸和手）**
    - **顶部状态栏**：显示全局“整洁度”分数和环形进度图。
    - **可折叠区域卡片**：每个卡片展示一个区域（如厨房）及其所有家务。它负责：
        - 显示区域名称和图标。
        - 展示该区域的线性进度条。
        - 提供折叠/展开的交互。
        - 容纳其下的“家务项列表”和“添加家务输入框”。
    - **家务项列表**：每个家务项是一个可交互单元，负责：
        - 显示任务名称、频率、上次完成时间。
        - 提供“完成/取消”的勾选框交互。
        - 提供“删除”交互（鼠标悬停出现）。

3.  **数据输入模块（嘴）**
    - **“添加新区域”按钮**：触发弹窗，输入新区域名称。
    - **每个区域底部的输入框**：用于快速向该区域添加新家务。

**输入 → 处理 → 输出 的逻辑链路：**
- **用户点击勾选框** → `toggleChore` 函数被调用 → 更新对应 `chore` 的 `lastDone` 日期 → `areas` 数据变化触发 `$watch` → 数据保存至 `localStorage`，同时 `score` 和 `getAreaProgress` 自动重新计算 → 界面上的进度条、分数、勾选状态立即更新。

**最值得学习的设计：**
- **响应式数据流**：使用 Alpine.js 的 `x-data` 和响应式属性，任何数据的修改都会自动、高效地更新到界面的相关部分。你不需要手动操作DOM去更新进度条或分数，只需关心数据本身。
- **模块化的组件思维**：虽然写在一个文件里，但通过模板循环 (`x-for`) 和条件显示 (`x-show`)，将“区域卡片”和“家务项”变成了可复用的视觉单元。数据结构和UI结构高度对应，易于理解和修改。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **注意**：当前版本的代码**没有**使用AI或Prompt。它是一个纯前端、离线运行的任务管理应用。
>
> 但我们可以探讨，**如果**要引入AI，Prompt可以如何设计，这也是一个重要的学习点。

**假设我们想增加一个功能：“AI智能推荐家务”**，那么Prompt可能会扮演以下角色：

1.  **扮演的角色**：一个“家务任务生成器”或“任务拆分顾问”。
2.  **解决的问题**：解决“生成问题”。用户输入一个模糊目标（如“来个大扫除”），AI需要将其分解成具体的、可执行的家务列表。
3.  **Prompt中的关键变量**：
    - `target`：用户输入的目标（如“彻底清洁厨房”）。
    - `area`：目标区域（如“厨房”）。
    - `detail_level`：要求的详细程度（如“简单步骤”或“深度清洁清单”）。
    - `existing_chores`：该区域已存在的家务（避免重复推荐）。
4.  **如果只改Prompt，不改代码，会发生什么？**
    - 生成的建议会变得不同。例如，Prompt从“生成日常清洁任务”改为“生成春季大扫除任务”，AI返回的任务列表会从“洗碗、擦台面”变成“清洗抽油烟机、整理橱柜、给冰箱除霜”等。
    - **但代码需要相应调整**来调用AI API、处理返回结果并添加到`areas`数据中。单纯改Prompt而不改调用它的代码是无效的。

## 【五】如何模仿它，做出你自己的版本？

如果你想做一个类似风格但用途不同的应用，请遵循以下路径：

**第一步：替换核心概念（最安全）**
- **保持结构完全不变**：还是顶部状态栏、可折叠卡片、列表项、底部输入。
- **替换数据模型**：把 `areas` 改成 `projects`（项目），把 `chores` 改成 `tasks`（任务）。把“整洁度”改成“项目完成度”。
- **替换文案和图标**：把“厨房”、“洗碗”换成你的领域名词，如“学习计划”、“背单词50个”。

**第二步：调整数据字段和简单逻辑**
- 在 `defaultData` 里填充你自己的初始数据。
- 修改 `getFreqLabel` 函数，比如把“每日/每周”改成“高/中/低”优先级。
- 修改 `isDone` 的逻辑，比如任务可能不是按天算，而是有“未开始/进行中/已完成”多个状态。

**第三步：改变展示和交互方式**
- 修改进度条的颜色或样式（通过Tailwind CSS类）。
- 增加新的交互，比如给任务拖拽排序、添加备注。
- 改变输出形式，比如增加一个“生成今日报告”的按钮，将完成情况汇总成一段文字。

**从哪里下手最安全？**
从 **第一步** 开始，只改名字和静态数据。运行起来，确保基础功能完好。这是风险最低、成就感最快的入门方式。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加任务属性，丰富管理维度**
    - **操作**：为每个 `chore` 对象增加 `priority`（优先级：高、中、低）和 `estimatedTime`（预计耗时）字段。
    - **展示**：在任务名称旁用不同颜色的小点表示优先级，在任务行末尾显示预计时间。
    - **价值**：让任务管理更精细，可以优先处理高优先级任务。

2.  **引入简单的AI建议功能（需API）**
    - **操作**：在“添加新区域”按钮旁增加一个“AI生成示例任务”按钮。点击后，调用一个AI API（如OpenAI或国内大模型），Prompt为：“请为[区域名称]生成5个常见的清洁或整理家务任务，用中文，用逗号分隔”。将返回的文本解析成多个家务并添加。
    - **价值**：帮助用户快速初始化一个区域，提供灵感。

3.  **拆分为“规划”与“执行”两个视图**
    - **操作**：在顶部增加一个选项卡，切换“所有任务”和“今日聚焦”。
    - **逻辑**：“今日聚焦”视图只显示频率为“每日”的任务，或者用户手动标记为“今日待办”的任务。
    - **价值**：减少信息过载，帮助用户专注当天的核心任务。

4.  **优化交互体验**
    - **操作**：实现拖拽排序功能，允许用户手动调整家务的顺序或在不同区域间移动任务。可以使用一个简单的拖拽库。
    - **操作**：为“完成”操作添加一个令人愉悦的动画效果，比如勾选框放大缩小、任务项淡出。
    - **价值**：提升应用的操作感和趣味性。

5.  **增加数据统计与回顾页面**
    - **操作**：在页面底部或侧边栏增加一个“统计”链接，跳转到一个新页面。该页面用图表（如使用Chart.js）展示过去一周/月的任务完成趋势、各区域耗时比例等。
    - **价值**：从“记录”上升到“分析”，帮助用户了解自己的习惯模式。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做严格的时间管理或日历**：它没有开始时间、截止日期、提醒通知功能。如果你需要“下午3点打电话”，应该使用日历或专业的待办事项应用（如Todoist、Microsoft To Do）。
2.  **不适合复杂的团队协作**：它没有用户系统，数据全保存在本地浏览器。无法分配任务给他人，也无法同步查看他人的完成情况。团队协作应使用Trello、Asana或飞书任务等工具。
3.  **不适合管理依赖关系复杂的项目**：这里的任务是独立、平行的。如果你的任务像“先买水泥，才能砌墙，然后才能刷漆”这样有前后依赖，你需要使用甘特图或专业的项目管理软件。
4.  **不适合处理大量、需要搜索和过滤的任务**：当任务超过几十个时，没有搜索和标签过滤功能会很难管理。它更适合管理一个家庭常规的、数量有限的重复性事务。

**总结**：这个网页是一个优秀的**个人轻量级日常事务追踪器**的范例。它的价值在于清晰的结构、即时的反馈和优雅的交互。通过学习它，你掌握的是如何用现代前端工具构建一个数据驱动、状态自管理的交互式Web应用的核心模式。
