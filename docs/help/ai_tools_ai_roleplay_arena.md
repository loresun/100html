# AI 模拟对练场 (Roleplay Arena) 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你刚写完一篇文案、一个产品介绍，或者想好了一个观点。在公开发布之前，你心里没底：“别人会怎么想？会不会有人挑刺？普通用户能看懂吗？” 你希望有人能提前帮你“压力测试”一下，但身边不一定有合适的人选，或者不好意思麻烦别人。

这个网页就是你的**私人压力测试沙盒**。它让 AI 扮演不同类型的“对手”（比如爱抬杠的网友、挑剔的客户、完全不懂的小白、专业的同行），对你的内容进行模拟提问、质疑和挑战。你可以实时回应，与 AI 进行多轮对话，从而提前发现文案的漏洞、逻辑的薄弱点，或者理解上的障碍。

**适合在什么情况下使用？**
- 文案、广告语、产品介绍的发布前测试。
- 演讲稿、辩论观点的模拟演练。
- 产品功能描述、用户手册的“小白友好度”测试。
- 任何需要从不同视角审视的文字内容。

**不适合什么情况？**
- 需要真实、有深度的人类情感反馈（如小说、诗歌）。
- 涉及高度机密或敏感信息的内容（所有对话会发送到外部 AI 服务）。
- 需要获得最终、权威的“对错”评判（AI 的质疑本身也可能有误）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **待测试文案/观点**：一个大文本框，让你粘贴或输入你想测试的文字。
2.  **选择对手**：一个下拉菜单，让你选择 AI 扮演的角色（杠精、甲方、小白、专家）。
3.  **API 设置**：首次使用需要点击右上角“设置”，输入你的 AI API Key（例如 DeepSeek 的 Key）。

**用户通常会做哪几步操作？**
1.  **准备**：在左侧文本框粘贴你的文案，选择一个你想挑战的“对手”角色。
2.  **开战**：点击“开始压力测试”按钮。AI 会立刻以你选择的角色身份，对你的文案发起第一轮“攻击”或质疑。
3.  **回应**：在右下角的输入框里，输入你的解释、反驳或修改后的文案，然后按回车或点击发送按钮。
4.  **迭代**：AI 会根据你的回复，继续扮演角色与你对话。你可以不断修改文案、调整说法，直到你觉得能应对这些挑战为止。

**输出结果长什么样？**
对话会以聊天气泡的形式展示在右侧主区域。你的发言在右侧（蓝色气泡），AI 的发言在左侧（白色气泡）。如果你选择了“深度内核”模型，AI 的回复前会有一个“查看思考过程...”的折叠区域，点击可以看 AI 是如何一步步推理出这个回复的。

**有哪些容易忽略的使用细节？**
- **模型切换**：页面顶部有两个模型按钮。“V3.2”适合快速对话，“R1（深度内核）”会展示思考过程，回复可能更严谨但稍慢。可以随时切换。
- **思考过程**：使用 R1 模型时，别忘了点开“查看思考过程...”，这是学习 AI 如何“扮演角色”和“分析问题”的绝佳窗口。
- **API Key 保存**：设置里的 API Key 会保存在你的浏览器本地，下次打开页面无需再次输入（除非清空浏览器数据）。
- **中途换角色**：一旦开始对话，当前选择的角色会固定下来。如果想换角色测试同一段文案，需要刷新页面重新开始。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个职责分明的模块：

1.  **配置与启动模块（左侧面板）**
    - **职责**：接收用户的“测试材料”（文案）和“测试条件”（对手角色），并触发整个流程的开始。
    - **输入**：用户输入的文案、选择的角色。
    - **处理**：将用户输入和角色选择打包，组合成第一条给 AI 的指令。
    - **输出**：触发 AI 调用，生成第一条挑战性回复。

2.  **对话展示与交互模块（右侧主区域）**
    - **职责**：可视化地呈现整个模拟对战的对话历史，并提供用户继续对话的输入接口。
    - **输入**：来自 AI 的回复、来自用户的回复。
    - **处理**：将消息按角色（用户/AI）格式化、用 Markdown 渲染文本、自动滚动到底部。
    - **输出**：一个直观、可滚动的聊天界面。

3.  **AI 引擎与逻辑模块（幕后核心）**
    - **职责**：与外部 AI API 通信，管理对话历史，并确保 AI 始终“扮演”指定的角色。
    - **输入**：包含系统指令（角色设定）和完整对话历史的消息数组。
    - **处理**：通过 `fetch` API 将消息发送到配置的 AI 服务端点，并处理返回的响应（包括普通回复和思考过程）。
    - **输出**：结构化的 AI 回复内容，被送入“对话展示模块”。

**逻辑链路：**
`用户输入文案&选择角色` → `【配置模块】组合初始Prompt` → `【AI引擎】调用API` → `【展示模块】显示AI回复` → `用户输入反驳` → `【AI引擎】将新回复加入历史，再次调用API` → `【展示模块】更新对话` → ...（循环）

**最值得学习的设计：**
**“系统提示词（System Prompt）的动态管理”**。这是本页面的灵魂。它不是把角色设定写死在代码里，而是根据用户的选择，动态生成一条 `system` 指令（如“你是一个网络杠精...”），并**在每一次后续对话中，都确保这条指令被放在历史消息的最前面**。这保证了 AI 在整个多轮对话中，都不会“忘记”自己扮演的角色，行为保持一致。这是构建角色扮演类 AI 应用的关键技巧。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 在这里是 **“角色定义器”和“任务指挥棒”**。它不直接生成文案，而是指挥 AI **“如何思考”和“如何回应”**。

**它解决的是“理解问题”还是“生成问题”？**
主要是 **“理解问题”**，更准确地说是 **“立场与风格理解问题”**。Prompt 的核心任务是让 AI 理解：“你现在不是中立的助手，而是‘杠精喷子’，请用这个身份的思维方式和语言风格来评价用户给的文案。”

**哪些信息是 Prompt 中的关键变量？**
1.  **角色描述**：例如“你是一个网络杠精，喜欢断章取义、攻击逻辑漏洞，说话刻薄。” 这是最关键的变量，直接由用户选择决定。
2.  **用户文案**：`context` 变量的内容，是 AI 评价的具体对象。
3.  **对话历史**：用户和 AI 之前的每一轮对话，都会被加入 Prompt，让 AI 的回应具有连续性。

**如果只改 Prompt，不改代码，会发生什么变化？**
变化会非常巨大且直接：
- **改变角色**：在“选择对手”下拉菜单里增加一个选项（如“暖心鼓励师”），并修改对应的 Prompt 描述（如“你是一个善于发现闪光点的鼓励者...”），AI 就会从“挑刺”变成“夸夸”。
- **改变任务**：把 Prompt 从“评价文案”改成“模拟面试官提问”，这个工具就瞬间变成了一个“AI 模拟面试”工具。
- **改变风格**：在角色描述里加入“请用莎士比亚戏剧的腔调说话”，AI 的回复就会充满古风韵脚。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个安全的路径，一步步创造出属于你的 AI 对话工具：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标**：先做一个能跑起来的“变体”。
- **操作**：不要动任何代码逻辑。只修改文字。
    1.  修改网页标题，比如改成“AI 面试模拟器”。
    2.  修改左侧面板的标签：“待测试文案/观点”改成“你的简历和自我介绍”。
    3.  修改“选择对手”下拉框的选项：把“杠精喷子”等，换成“技术面试官”、“HR 面试官”、“压力面试官”。
    4.  修改按钮文字：“开始压力测试”改成“开始模拟面试”。
    5.  修改提示语：“AI 将扮演对方角色对你的文案提出质疑...”改成“AI 将扮演面试官对你的简历进行提问...”。
- **结果**：你已经得到了一个结构完全相同，但用途全新的工具。

**第二步：调整输入字段或 Prompt**
- **目标**：让工具更贴合新场景。
- **操作**：
    1.  增加输入字段：在左侧面板增加一个“应聘职位”的输入框。
    2.  深化 Prompt：修改每个“面试官”角色对应的 Prompt。例如，在“技术面试官”的 Prompt 中加入：“你将针对 `{应聘职位}` 相关的技能进行深度提问，问题由浅入深。”
    3.  修改初始指令：把 `startBattle` 函数里给 AI 的第一条消息，从“请开始评价”改成“请开始基于这份简历和职位要求进行面试”。
- **结果**：你的工具现在能进行更有针对性的模拟面试了。

**第三步：改变输出形式或展示方式**
- **目标**：优化体验，提供额外价值。
- **操作**：
    1.  在对话结束后，增加一个“生成面试评价报告”的按钮。
    2.  点击后，将整个对话历史再次发送给 AI，但使用一个新的 Prompt：“请总结刚才的模拟面试，给面试者提供三点优点和改进建议。”
    3.  将 AI 生成的总结报告展示在一个新的弹出框或页面区域。
- **结果**：你的工具从一个简单的对话模拟，升级为带有复盘功能的教练工具。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“自定义角色”功能**：
    - **操作**：在下拉菜单最后加一个“自定义”选项。选择后，下方出现一个新的文本框，让用户自由输入角色描述（如“一个来自唐朝的诗人”）。
    - **效果**：工具的可玩性和适用范围爆炸性增长，用户可以让 AI 扮演任何他们想象的角色。

2.  **引入“多轮角色切换”或“多方辩论”**：
    - **操作**：在对话过程中，增加一个“切换对手”按钮。点击后，可以选择另一个角色介入对话。界面可以用不同颜色区分不同角色的发言。
    - **效果**：从一对一的“攻防战”，变成一对多甚至多对多的“辩论会”，更能模拟复杂的真实反馈环境。

3.  **优化为“文案迭代助手”**：
    - **操作**：在每条 AI 的质疑气泡旁，增加一个“采纳建议并修改文案”的小按钮。点击后，左侧的原始文案输入框内容会自动更新为融合了你回复和 AI 建议的新版本。
    - **效果**：将“测试”和“修改”流程无缝衔接，真正成为文案创作的协同工具。

4.  **本地化与隐私增强**：
    - **操作**：集成一个能在浏览器中本地运行的轻量级 AI 模型（如通过 WebLLM 运行 Phi-3 或 Llama 3.1 的小尺寸版本），并提供“本地模式”选项。
    - **效果**：处理敏感文案时无需担心数据出域，且完全免费，但响应速度可能较慢。

5.  **增加对话导出与分享功能**：
    - **操作**：在聊天区域顶部增加“导出为 Markdown”、“复制对话链接”等按钮。导出内容可以包含角色设定和完整对话。
    - **效果**：方便用户保存精彩的攻防记录，或分享给同事朋友进行二次讨论，增加工具的实用性和传播性。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为“真理仲裁器”**：AI 的质疑是基于其角色扮演和训练数据生成的，**不一定正确或合理**。它可能提出无意义的抬杠。它的价值在于“提供不同视角”，而非“给出标准答案”。如果你需要验证事实或逻辑的绝对正确性，应查阅权威资料或进行专业咨询。

2.  **不适合处理高度创意或情感评估**：对于诗歌、小说、艺术陈述等高度依赖人类独特情感和审美的内容，AI 的“杠精”或“专家”视角可能无法提供有价值的反馈，甚至可能带来误导。这类内容更适合寻求同类创作者或目标受众的真实感受。

3.  **不适合替代真实用户测试**：尤其是对于产品界面、交互流程等，AI 模拟的“小白用户”无法真正模拟出操作上的困惑、视觉上的忽略或情绪上的挫败感。对于重要的产品，必须进行真实的可用性测试。

4.  **不适合在无审查情况下生成公开内容**：虽然这是一个测试工具，但 AI 在激烈角色扮演下生成的内容，有可能包含不恰当、偏激或冒犯性的言论。**切勿将未经审核的 AI 对话直接作为公开内容发布**。你始终是内容的最终负责人。

**如果你想做的是：**
- **获得真实用户的定量数据** → 使用 A/B 测试工具或调查问卷。
- **进行深度的逻辑谬误检查** → 使用专门的逻辑分析工具或请教领域专家。
- **需要安全、私密地处理机密信息** → 使用完全离线的软件或确保使用本地化模型的工具。

希望这份文档能帮助你不仅用好这个工具，更能理解其设计精髓，并最终创造出属于你自己的、更精彩的 AI 应用。祝你玩得开心，学有所成！
