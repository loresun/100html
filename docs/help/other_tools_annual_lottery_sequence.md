# 年会抽奖工具帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你正在组织一场公司年会，参会者都拿着一个带编号的座位牌。主持人想按顺序叫号抽奖，或者从某个编号区间（比如“老员工区”的1-50号）里随机抽取。这个网页就是为这种**有明确编号体系**的抽奖场景设计的。

**适合场景：**
- 年会、庆典等有座位号或编号牌的活动
- 需要按编号顺序（如1号、2号、3号…）抽取的场景
- 需要从特定编号范围（如“VIP区1-20号”）随机抽取的场景
- 希望记录每次抽奖结果，并能导出存档

**不适合场景：**
- 没有编号的随机抽奖（如从名单里直接随机）
- 需要复杂权重或概率的抽奖（如按工龄加权）
- 需要实时联网或多人同时参与的大型抽奖

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **名单输入框**：输入参与抽奖的人员名单，每行一个人。格式可以是“姓名,编号”或“编号,姓名”，如“张三,001”或“001,张三”。
2. **奖品输入框**：输入奖品列表，每行一个奖品，如“一等奖｜旅行券”。
3. **数字输入框**：在“区间抽取”部分，输入起始和结束编号。

**用户通常会做哪几步操作？**
1. **准备阶段**：在左侧输入名单和奖品 → 点击【解析名单】按钮。
2. **查看名单**：确认下方表格中显示的编号和姓名是否正确。
3. **开始抽奖**：
   - 想按顺序抽：点击【按序抽取】，会从当前序号开始抽取。
   - 想从某个范围抽：设置起始和结束编号 → 点击【区间随机抽取】。
4. **查看结果**：右侧会显示当前中奖者和奖品，下方是历史记录。
5. **导出结果**：抽奖结束后，点击【导出结果】下载CSV文件。

**输出结果长什么样？**
- **当前中奖者区域**：显示“姓名（可选编号）”和获得的奖品。
- **历史记录列表**：按时间倒序显示所有中奖记录，格式如“一等奖｜旅行券：张三（编号001）”。
- **导出的CSV文件**：包含奖品、姓名、编号、时间四列，可用Excel打开。

**容易忽略的使用细节：**
- **名单解析有智能识别**：无论你写“张三,001”还是“001,张三”，它都能正确识别姓名和编号。
- **序号会自动递增**：按序抽取后，当前序号会自动+1，下次会抽下一个编号。
- **奖品循环使用**：如果奖品数量少于中奖人数，会从头开始循环分配。
- **隐藏编号功能**：点击【显示/隐藏编号】可以控制结果中是否显示编号，适合对外展示。

## 【三】核心结构拆解（学习重点）

这个页面由**三个核心模块**组成：

**1. 数据准备模块（左侧上半部分）**
- **职责**：接收用户输入的原始数据，进行清洗和格式化。
- **输入**：用户粘贴的名单文本、奖品文本。
- **处理**：`parseEntries()`函数智能识别姓名和编号；`splitList()`分割文本行。
- **输出**：结构化的`entries`数组（包含id和name）、`prizes`数组。

**2. 抽奖控制模块（左侧下半部分）**
- **职责**：管理抽奖逻辑和候选池状态。
- **关键状态**：
  - `pool`：当前可被抽取的候选人列表（已中奖的会被移除）
  - `currentIndex`：按序抽取的当前位置
  - `rangeStart/End`：区间抽取的范围
- **核心函数**：
  - `drawSequential()`：按当前序号抽取
  - `drawRange()`：从指定编号区间随机抽取
  - `resetPool()`：重置候选池（重新开始）

**3. 结果展示模块（右侧整个部分）**
- **职责**：实时显示抽奖结果和历史记录。
- **动态展示**：使用`currentDisplay`和`currentPrize`显示最新结果。
- **历史管理**：`history`数组存储所有记录，支持倒序显示。
- **导出功能**：`exportResults()`将历史记录转为CSV下载。

**逻辑链路：**
```
输入名单/奖品 → 解析为结构化数据 → 初始化候选池
    ↓
选择抽奖模式（顺序/区间） → 从候选池筛选/抽取 → 更新结果展示
    ↓
记录到历史 → 可选导出 → 可重置重新开始
```

**最值得学习的设计：**
**候选池（pool）的维护机制**。它通过`splice()`方法从`pool`中移除已中奖者，确保不会重复中奖。这种“状态隔离”的设计让抽奖逻辑变得清晰且可靠，是值得模仿的核心思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：这个网页**没有使用AI或Prompt**，它是一个纯前端工具。但我们可以从“智能解析”的角度来理解类似的设计思路。

**“智能解析”扮演的角色：**
在这个页面中，`parseEntries()`函数起到了类似“Prompt理解”的作用。它需要理解用户可能输入的各种格式（姓名在前、编号在前、用逗号还是顿号分隔），并输出统一的结构化数据。

**它解决的是“理解问题”：**
- **问题**：用户输入格式不统一（“张三,001” vs “001,张三”）
- **解决方案**：通过规则判断（检测中文字符、检测纯数字）来推断哪个是姓名、哪个是编号
- **关键变量**：`firstHasCjk`（第一个是否含中文）、`/^\d+$/`（是否纯数字）

**如果只改解析逻辑，不改代码：**
如果你修改`parseEntries()`中的判断规则，比如：
- 支持更多分隔符（如“|”或空格）
- 识别英文名和工号的组合
- 添加部门信息解析

那么整个网页就能处理更多样化的输入格式，而无需改动其他抽奖逻辑。这体现了“输入解析”与“核心逻辑”分离的设计优势。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：替换使用场景（最安全）**
保持所有代码结构不变，只修改：
- 页面标题和描述文字
- 输入框的提示文本（如改为“学生名单，学号,姓名”）
- 导出文件的名称（如改为“班级抽奖结果.csv”）

**第二步：调整输入字段**
- **增加字段**：在名单解析中增加“班级”或“部门”字段
- **修改格式**：调整`parseEntries()`支持你的特定格式
- **简化/复杂化**：如果不需要编号，可以简化；如果需要更多信息，可以扩展

**第三步：改变展示方式**
- **修改UI样式**：更换颜色、字体、布局适应你的主题
- **增加展示元素**：如显示剩余人数、中奖概率等
- **改变结果格式**：如用更大的字体显示中奖者，添加动画效果

**从哪里下手最安全？**
从**修改静态文本和样式**开始。先改标题、提示文字、颜色，确保页面能正常运行。然后再尝试修改`parseEntries()`函数来处理你的数据格式。最后再考虑增加新功能。

## 【六】3–5个可直接尝试的改造方向

**1. 增加“部门/分组”抽奖功能**
- **具体操作**：在名单输入中支持三列“姓名,编号,部门”

- **具体操作**：增加“一次抽取N人”的输入框和按钮

- **具体操作**：抽中后自动用语音读出“恭喜XXX获得一等奖”

- **体验提升**：让抽奖更有仪式感

**5. 改为“团队竞赛计分板”**
- **彻底改造**：将抽奖逻辑改为计分逻辑
- **输入**：团队名单和比赛项目
- **功能**：记录每个团队的得分，实时排名
- **核心不变**：数据解析、状态管理、结果展示的结构可以复用

## 【七】这个网页不适合做什么？（边界提醒）

**局限性说明：**

1. **不适合大规模实时抽奖**
   - 如果超过几百人，页面性能可能下降
   - 没有后端支持，无法处理数千人的名单
   - **替代方案**：使用数据库+后端API的专门抽奖系统

2. **不适合需要“公平算法”验证的场景**
   - 随机算法使用浏览器的`Math.random()`，不适合需要审计的正式场合
   - **替代方案**：使用可验证的随机算法或第三方公证服务

3. **不适合多人协同操作**
   - 这是一个单机网页，无法多人同时操作或观看
   - **替代方案**：开发具有WebSocket实时同步的版本

4. **不适合复杂的抽奖规则**
   - 如“前10号中奖概率加倍”、“管理层最后抽”等复杂规则
   - **替代方案**：在抽奖逻辑中添加权重计算和规则引擎

5. **不适合需要持久化存储的场景**
   - 刷新页面后数据会丢失
   - **替代方案**：添加本地存储（localStorage）或连接数据库

**记住**：这个工具最适合**中小型、有编号体系、规则简单**的线下活动。如果你的需求超出了这些范围，建议基于这个思路进行扩展，或寻找更专业的工具。
