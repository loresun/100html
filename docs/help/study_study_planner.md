# 学习规划师 - 帮助文档

---

## 【一】这个网页解决了什么问题？

想象一下，你有一个学习目标，比如“三个月学会Python编程”或“半年内考过雅思7分”。你充满动力，但面对漫长的学习周期，不知道如何把大目标拆解成每天、每周可以执行的小任务。这个网页就是你的**个人学习规划助手**。

**适合的使用场景：**
- 你有一个明确、有时间限制的学习目标（考证、学技能、学语言）。
- 你需要一个结构化的计划来指导日常学习，避免盲目和拖延。
- 你希望计划能考虑到你的投入时间（每周几天，每次多久）。

**不适合的情况：**
- 目标非常模糊，比如“提升自我”或“变得更好”。
- 需要即时、动态调整的短期任务（如“今天下午复习什么”）。
- 需要与真人教练进行深度互动和个性化反馈的场景。

---

## 【二】使用方式（给第一次接触的人）

**1. 页面输入是什么？**
- **学习目标**：一个文本框，填写你的具体目标。
- **每周学习天数**：一个数字输入框，选择1到7天。
- **每次学习时长**：一个数字输入框，选择30到180分钟。

**2. 用户通常会做哪几步操作？**
1.  在左侧面板填写你的学习目标（例如：“6个月掌握前端开发”）。
2.  根据你的实际情况，选择每周能投入几天，以及每次学习多久。
3.  点击蓝色的 **“生成学习计划”** 按钮。
4.  稍等片刻，右侧面板就会显示出为你定制的计划。

**3. 输出结果长什么样？**
计划会分为三个清晰的部分显示在右侧：
- **阶段规划**：用列表形式展示整个学习周期被分成了哪几个大阶段（如：基础入门、核心突破、冲刺复习）。
- **每周重点**：一段文字描述，告诉你每周应该聚焦学习什么内容。
- **复盘建议**：一段文字，提供如何定期检查学习效果、调整方法的建议。

**4. 有哪些容易忽略的使用细节？**
- **API设置**：页面右上角有“API设置”按钮。第一次使用或生成失败时，需要点击它，填入你自己的DeepSeek API密钥，网页才能正常工作。
- **模型切换**：右上角有“V3”和“O1”两个小按钮，可以切换AI模型。O1可能推理能力更强，但响应可能稍慢或费用不同，你可以根据需求尝试。
- **目标描述**：目标写得越具体、越有场景，生成的计划可能越贴合你的需求。例如，“3个月通过JLPT N2”就比“学日语”要好得多。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块：

**1. 输入配置模块（左侧面板）**
- **职责**：收集用户的所有个性化条件。它是整个应用的“控制面板”。
- **包含**：目标输入框、时间设置（天/分钟）、生成按钮。
- **逻辑**：用户在这里设定参数 → 点击按钮触发后续所有流程。

**2. 计划展示模块（右侧面板）**
- **职责**：清晰、结构化地呈现AI生成的结果。它是应用的“报告面板”。
- **包含**：三个固定的展示区域（阶段、每周、复盘）。
- **逻辑**：接收处理模块传来的结构化数据 → 按预定格式渲染到对应位置。

**3. 后台处理模块（JavaScript逻辑）**
- **职责**：作为“中间人”，连接前端输入和AI服务，并处理数据。
- **关键流程**：
    1.  **组装Prompt**：将用户输入（目标、天数、时长）拼接成一个给AI的指令（Prompt）。
    2.  **调用API**：将组装好的Prompt发送给DeepSeek的AI模型。
    3.  **解析响应**：收到AI返回的文本后，提取出JSON格式的数据。
    4.  **更新界面**：将解析后的数据（阶段、每周、复盘）分别赋值给右侧面板对应的显示区域。

**最值得学习的设计：**
**“结构化输出”的约束**。它没有让AI自由发挥，而是通过Prompt明确要求AI返回一个特定格式的JSON。这样，前端JavaScript就能稳定地解析数据，并精准地填充到页面三个对应的位置。这种“前端定义结构，AI填充内容”的模式，使得应用非常可靠和可控，是AI结合Web应用的经典设计。

## 【四】Prompt / AI 逻辑是如何被设计的？

**1. Prompt扮演的角色**
Prompt在这里是一个**精确的指令生成器**。它把用户散乱的输入（目标、时间）转化成一个AI能清晰理解的、带有明确输出格式要求的任务描述。

**2. 解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**。AI不需要去“理解”这个网页是什么，它只需要理解Prompt里的任务：“根据给定的目标和时间，生成一份学习计划”，并按照指定的格式（JSON）来生成内容。

**3. Prompt中的关键变量**
- `“${this.goal}”`：用户的学习目标，是计划的核心。
- `每周 ${this.days} 天，每次 ${this.minutes} 分钟`：计划的约束条件，决定了计划的密度和节奏。
- `返回 JSON：{“phases”:[...],“weekly”:“...”,“review”:“...”}`：这是**最关键**的部分，它锁定了输出的格式，让程序可以自动化处理。

**4. 如果只改Prompt，不改代码，会发生什么？**
- **改变计划风格**：例如在Prompt里加上“请用轻松活泼的语气”，输出的文字风格会变。
- **调整结构**：例如要求返回 `“books”: [“推荐书单”]`，AI会生成这个字段，但网页上不会显示，因为前端没有对应的展示代码。
- **更换领域**：把“学习目标”改成“健身目标”，Prompt稍作修改，AI就能生成健身计划，但网页标题和说明文字还是“学习”，会显得不匹配。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个“最小改动”路径，安全地创建一个新应用：

**第一步：替换核心概念与文案（最安全）**
- 将“学习规划师”改为你的主题，如“健身计划师”、“旅行规划师”。
- 将“学习目标”输入框的标签和提示语改为你的主题目标，如“健身目标”、“旅行目的地”。
- 将右侧输出部分的标题改为对应概念，如“阶段规划”改为“训练周期”，“每周重点”改为“每周训练”。

**第二步：调整输入字段**
- 根据你的新主题，思考需要哪些参数。例如“健身计划师”可能需要“当前体重”、“目标体重”、“每周训练天数”。
- 在左侧面板中，增加、删除或修改输入框，并确保JavaScript中接收这些数据的变量名相应改变。

**第三步：重写核心Prompt**
- 这是应用的“灵魂”。根据你的新主题和输入字段，重新编写发送给AI的Prompt。
- **务必保持输出JSON的格式不变**（即 `phases`, `weekly`, `review` 这三个键名），这样你就不需要修改右侧的显示代码。你可以只改变对这些键名的解释，例如 `phases` 可以理解为“健身阶段”，`weekly` 理解为“每周训练安排”。

**第四步：微调UI与提示**
- 更改颜色、背景图，使其符合新主题的风格。
- 检查所有说明文字，确保它们与新主题一致。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加个性化输入**：
    - 增加一个下拉菜单，让用户选择**当前水平**（如：零基础、有基础、进阶）。将这个变量加入Prompt，AI就能生成更具针对性的计划。

2.  **切换AI服务与模型**：
    - 在API设置中，增加对OpenAI（GPT）、Claude等其它模型的支持。只需修改 `study-shared.js` 中的 `callLLM` 函数，使其能适配不同API的调用方式。

3.  **实现计划保存与历史记录**：
    - 利用浏览器的 `localStorage`，每次生成计划后，将输入参数和结果保存起来。在页面底部或侧边栏增加一个“历史计划”列表，方便用户回顾和比较。

4.  **优化交互体验**：
    - 在生成计划时，将按钮变为不可点击并显示加载动画（已实现）。可以进一步在右侧展示区域显示一个**骨架屏**（灰色占位条），让用户明确知道内容正在加载。
    - 为生成的“每周重点”内容增加**展开/收起**功能，或者将其拆分成更清晰的周次列表。

5.  **拆分为多步骤向导**：
    - 将当前单页面的输入，改成一个多步骤的表单。例如：第一步填写目标，第二步选择时间，第三步确认生成。这更适合需要收集更多复杂信息的场景。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合做精确的日程排期**：它生成的是“每周重点”这样的指导性计划，而不是“周一9点-10点背单词”的精确日历。如果你需要后者，应该使用日历类应用或更专业的项目管理工具。
- **不适合替代专业教学或咨询**：对于学术辅导、医疗康复、金融投资等需要专业资质的领域，它生成的计划仅为通用参考，不能替代专业人士的评估和方案。
- **不适合处理极度复杂或创造性的目标**：例如“写一部获奖小说”或“解决一个未知的科学问题”。这类目标路径不明确，AI难以做出可靠分解，更需要的是人类的深度思考和探索。
- **不适合无网络环境使用**：它完全依赖在线的AI API，没有网络就无法生成任何计划。
