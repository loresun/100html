# 同人小说生成器 - 帮助与学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你是一个同人小说爱好者，心中有一个喜欢的作品（比如《原神》），并且对其中两个角色的互动有了一些模糊的想法。你想写一段他们之间的对话，但可能不擅长构思情节、把握角色性格，或者单纯觉得“动笔”很麻烦。这个工具就是为你准备的。它像一个“对话编剧助手”，帮你把零散的想法（角色、场景、主题）快速组织成一篇结构完整、风格鲜明的对话体小说片段。

**适合什么情况？**
- **灵感速写：** 快速将一闪而过的角色互动点子变成文字。
- **写作练习：** 学习如何构建对话、塑造角色。
- **内容创作：** 为社交平台（如Lofter、微博）生成短篇同人内容。
- **娱乐体验：** 纯粹享受“定制”一段属于自己喜好故事的过程。

**不适合什么情况？**
- **创作长篇连载小说：** 它生成的是独立片段，缺乏长篇的情节架构和伏笔设计能力。
- **需要高度原创性的严肃文学创作：** 其核心是基于现有IP和设定进行衍生，而非从零构建全新世界。
- **替代深度的人工编辑：** 生成的内容需要人工进行润色、调整和逻辑校对。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要填写几个关键信息：
1.  **原作信息：** 故事基于哪个作品（如“哈利波特”）。
2.  **角色设定：** 至少两个角色的**名字**和**性格特点**（如“赫敏：聪明好学，有点急性子”）。
3.  **情节设定：** **场景**（如“霍格沃茨图书馆的深夜”）和**情节走向**（如“一起研究一本禁书”）。
4.  **风格与篇幅：** 选择想要的文风（甜蜜、搞笑等）和大致字数。

**用户通常会做哪几步操作？**
1.  **配置：** 首次使用时，点击右上角齿轮图标，填入你的 DeepSeek API Key。
2.  **构思：** 在左侧面板依次填写上述信息。你可以点击“添加角色”来创作多人对话。
3.  **生成：** 点击底部紫色的“开始创作”按钮。
4.  **等待与欣赏：** 右侧区域会像打字一样，逐步显示出生成的小说。如果选择了“R1 深度”模型，你还能展开看到AI的“思考过程”。
5.  **后续操作：** 生成后，可以使用“续写”让故事继续，或“复制”、“导出”保存结果。

**输出结果长什么样？**
输出是一篇格式清晰的对话体小说。通常包含一个AI拟定的标题，然后是正文。正文中，**角色对话会用「」标出并高亮显示**，角色名会用不同颜色标注，中间穿插着动作和场景描写。整体看起来就像一段专业的剧本或小说节选。

**有哪些容易忽略的使用细节？**
- **API Key 是必填项：** 不填就无法生成，工具本身不提供AI能力。
- **角色名字很重要：** AI主要依靠你填写的角色名来区分对话者，请确保名字准确且独特。
- **“世界观补充”和“额外要求”是强力工具：** 如果你对原作有特殊理解（如“这个世界的魔法需要付出代价”），或对文笔有特别要求（如“多用比喻”），填在这里效果显著。
- **“提示词设置”可以深度定制：** 如果你不满意默认的生成风格，可以在这里修改给AI的“核心指令”，让它完全按你的思路来写。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块：

**1. 输入配置模块（左侧面板）**
- **职责：** 收集用户所有创作意图。它被进一步细分为“原作信息”、“角色设定”、“情节设定”三个子卡片，职责分明地收集世界观、人物和剧情三大要素。
- **设计亮点：** **动态表单设计。** “角色设定”部分允许用户动态添加或删除角色输入框，既保证了最低要求（2个角色），又给予了灵活性（最多6个）。这种交互模式在处理不定长列表输入时非常实用。

**2. AI 引擎与逻辑模块（不可见，但最关键）**
- **职责：** 将用户的输入转化为AI能理解的指令（Prompt），并管理API调用、流式接收响应。
- **逻辑链路：**
    - **输入：** 用户在左侧面板填写的所有数据。
    - **处理：** `buildSystemPrompt()` 和 `buildUserPrompt()` 函数将这些数据拼接成一段结构严谨、要求明确的文本（即Prompt）。
    - **输出：** 将Prompt发送给DeepSeek API，并以**流式（stream）** 方式逐步获取AI生成的文本，实时显示在页面上，营造出“正在创作”的体验。

**3. 输出展示与交互模块（右侧面板）**
- **职责：** 优雅地展示生成结果，并提供后续操作（续写、复制、导出、清空）。
- **设计亮点：** **多功能结果查看器。** 它不仅展示美化后的正文（高亮对话、角色名），还能：
    - **展示思考过程：** 当使用R1模型时，可折叠查看AI的推理链，这对学习AI如何构思很有帮助。
    - **提供内容操作：** “续写”功能实际上是带着已有上下文再次调用AI，实现了简单的多轮交互。“导出”功能将结果和元数据打包成TXT文件。

**最值得学习的设计：**
**“流式响应（Streaming） + 局部更新”的体验优化。** 代码中的 `streamChat` 函数是关键。它没有等待AI生成全部内容再一次性显示，而是像流水一样，收到一点就显示一点（`this.result = fullContent`）。同时，它通过`UPDATE_INTERVAL`进行“节流”，避免因更新太频繁导致页面卡顿。这种设计极大地提升了用户在面对较长文本生成时的等待体验，让过程变得可知、可控。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接**用户意图**和**AI能力**的“翻译官”和“导演”。它把散乱的输入框信息，翻译成AI能严格执行的创作任务清单。

**它解决的是“理解问题”还是“生成问题”？**
主要解决**“生成问题”**，但也包含了“理解问题”。系统Prompt（`buildSystemPrompt`）负责让AI理解“对话体同人小说作家”这个**身份和写作规范**（如用「」标注对话）。用户Prompt（`buildUserPrompt`）则负责定义本次生成的**具体任务**（根据这些角色、在这个场景、用这种风格写一个故事）。

**哪些信息是 Prompt 中的关键变量？**
所有用户输入都是变量，但最关键的是：
- **角色信息 (`characterInfo`):** 尤其是角色名和性格，这直接决定了对话的质量和一致性。
- **场景与情节 (`settings.scene`, `settings.plot`):** 为AI提供了故事发生的起点和方向。
- **风格与篇幅要求 (`styleMap[settings.style]`, `lengthMap[settings.length]`):** 控制了成品的“调性”和规模。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个工具的输出，而无需懂一行代码：
- **改变文体：** 将系统Prompt中的“对话体小说作家”改为“新闻记者”，用户Prompt中的要求改为“写一篇新闻报道”，它就能生成新闻稿。
- **改变领域：** 将“同人小说”相关描述改为“产品广告文案”，输入“产品特点”和“目标人群”，它就能生成广告语。
- **改变格式：** 在系统Prompt中严格要求“每段以要点符号开头”，输出就会变成列表式。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）：**

**第一步：保持结构不变，替换使用场景（最安全）**
这是最简单的改造。不要动任何HTML和JS结构，只改文字和Prompt。
- **目标：** 做一个“短视频脚本生成器”。
- **操作：**
    1.  修改网页标题和所有界面文字（如“同人小说”改为“短视频脚本”）。
    2.  修改左侧输入框的标签和提示语（如“角色设定”改为“出镜人物”，“情节设定”改为“视频主题”）。
    3.  修改 `styleOptions`（如“甜蜜”改为“搞笑”、“知识科普”、“情感共鸣”）。
    4.  **最关键的一步：** 在 `buildSystemPrompt` 函数中，将身份描述改为“你是专业的短视频编剧”，将写作规范改为脚本格式（如“场景：”、“旁白：”、“人物动作：”）。

**第二步：调整输入字段或数据结构**
在第一步的基础上，根据新场景增加或减少输入项。
- **操作：**
    1.  为“短视频脚本生成器”增加一个“视频平台”选择框（抖音、B站、视频号），这个选项会作为变量加入到用户Prompt中。
    2.  如果不需要“世界观补充”，可以在HTML中注释掉或隐藏这个输入框。

**第三步：改变输出形式或展示方式**
让生成的内容以更符合新场景的方式呈现。
- **操作：**
    1.  修改 `formatDialogue` 函数，让它不再高亮「」对话，而是高亮“【场景】”或“<镜头>”等脚本标记。
    2.  在导出功能中，将文件后缀从 `.txt` 改为 `.md` (Markdown)，并调整导出内容的排版格式。

**从哪里下手最安全？**
从 **修改 `buildSystemPrompt` 和 `buildUserPrompt` 这两个函数里的文本内容** 开始。这能让你立刻看到工具核心功能的改变，风险极低，成就感最强。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“示例参考”输入框：**
    - **操作：** 在“情节设定”卡片下增加一个文本区域，让用户可以粘贴一段他喜欢的文字风格作为示例。
    - **改造：** 在 `buildUserPrompt` 中，将这段示例文本附加到提示词末尾，例如：“请参考以下文字的写作风格和节奏：`[用户粘贴的示例]`”。这能让AI的模仿更精准。

2.  **切换为支持多模态的API：**
    - **操作：** 将API调用从DeepSeek Chat切换为支持图像生成的API（如OpenAI的DALL·E或国内的相关平台）。
    - **改造：** 修改 `streamChat` 函数，将Prompt发送给图像生成API。同时，将输出区域从显示文本改为显示图片。这样，你就得到了一个“同人场景插图生成器”。

3.  **拆分为“创作”与“灵感库”两个页面：**
    - **操作：** 创建两个HTML文件：`index.html`（生成页面）和 `gallery.html`（灵感库）。
    - **改造：** 在当前页面的“导出”功能旁增加一个“保存到灵感库”按钮。点击后将本次的输入参数和生成结果一起保存到浏览器的 `localStorage` 或一个模拟的JSON数据库中。在 `gallery.html` 中读取并展示这些保存的记录，用户可以点击某条记录直接载入到生成器中进行修改或续写。这增加了工具的实用性。

4.  **优化交互：增加“一键随机灵感”按钮：**
    - **操作：** 在生成按钮旁边增加一个“给我灵感”按钮。
    - **改造：** 预定义几个数组，包含随机的“场景”、“风格”、“主题”等。点击按钮时，用JavaScript随机从这些数组中选取内容，自动填充到对应的输入框中。这能帮助用户克服“开头难”的问题。

5.  **增强编辑体验：实现“在线润色”模式：**
    - **操作：** 生成结果后，在结果区域上方增加一个“进入编辑模式”按钮。
    - **改造：** 点击后，将显示结果的 `div` 切换为一个可编辑的 `contenteditable` 的 `div` 或 `textarea`，允许用户直接在网页上修改AI生成的内容。并提供“请求AI润色此段”的按钮，将用户修改后的文本发送给AI进行局部优化。这形成了创作闭环。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为最终出版物的直接来源：** AI生成的内容可能存在逻辑漏洞、角色OOC（脱离角色性格）、或知识性错误。它必须经过人工的严格审阅、编辑和重写。
- **不适合处理极度复杂或新颖的设定：** 如果您的原创世界观非常复杂，远超常见ACG作品的范畴，AI可能无法准确理解并呈现。它更擅长在已知框架内进行组合与演绎。
- **不适合需要深度交互和分支选择的叙事：** 这是一个**单线程、一次性**的生成工具。它不能制作像《底特律：变人》或视觉小说那样拥有复杂分支选择的故事树。
- **如果用户想做X，应该换什么工具或方式：**
    - **想做长篇连载：** 应使用专业的写作软件（如Scrivener, yWriter）进行大纲和章节管理，本工具仅可用于激发某些片段的灵感。
    - **想做互动叙事游戏：** 应学习使用专门的互动叙事平台（如Twine, Ink）或游戏引擎（如Unity, Ren‘Py）。
    - **想获得完全原创的文学构思：** 应回归传统的创作方法，如自由写作、头脑风暴、阅读积累，AI工具更适合在已有构思的基础上进行拓展和细化。
