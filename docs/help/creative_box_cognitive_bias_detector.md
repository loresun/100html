# 认知偏差检测器 - 学习与模仿指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你在做决策、表达观点或进行自我反思时，可能会不自觉地陷入一些思维陷阱。比如，你可能会因为“上次失败了，所以这次也一定会失败”而放弃尝试，或者因为“我准备得很充分，所以结果一定很好”而过度自信。这个工具就像一个“思维镜子”，帮你照出这些潜在的逻辑漏洞。

**适合情况：**
- **个人反思：** 在做出重要决定（如职业选择、投资）后，检查自己的思考过程是否客观。
- **内容创作：** 写作、辩论或公开演讲前，审视自己的论点是否存在逻辑弱点。
- **团队讨论：** 分析会议记录或讨论内容，识别集体可能存在的思维偏差。
- **学习辅助：** 作为心理学、逻辑学或批判性思维的学习工具。

**不适合情况：**
- **寻求心理治疗：** 这不是专业的心理诊断或治疗工具。
- **完全替代人类判断：** AI的分析是基于模式识别，不能替代深度的人类共情和情境理解。
- **实时对话分析：** 它处理的是静态文本，不适合分析快速流动的对话。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个文本框，用于输入你的一段观点、判断或决策理由。

**用户通常会做哪几步操作？**
1.  **输入观点：** 在文本框中写下你想分析的句子或段落。例如：“这个新项目不可能成功，因为我们团队从来没做过类似的东西。”
2.  **开始检测：** 点击蓝色的“开始检测”按钮。
3.  **查看报告：** 等待几秒钟，页面会显示一份“认知偏差分析报告”。
4.  **使用报告：** 你可以阅读报告，使用右上角的按钮“复制”或“下载”报告。

**输出结果长什么样？**
报告分为两个主要部分：
1.  **检测到的潜在认知偏差：** 以醒目的卡片形式列出。每张卡片包含：
    - **偏差名称**（如“消极预测偏误”）
    - **定义解释**
    - **从你文本中引用的原句**
    - **详细分析**（说明为什么这句话体现了该偏差）
2.  **总结与反思建议：** 一段综合性的文字，为你提供整体的反思角度和改进建议。

**有哪些容易忽略的使用细节？**
- **设置面板：** 点击页面右上角的齿轮图标，可以打开设置面板，自定义AI模型的API地址和密钥。如果你有自己的API密钥，可以在这里配置。
- **空结果：** 如果AI没有检测到明显偏差，会显示“未检测到明显的认知偏差”，这本身也是一个有用的反馈。
- **文本长度：** 输入非常长或非常短的文本可能影响分析效果。一段清晰的、包含理由的陈述（2-5句话）通常效果最好。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个职责明确的模块：

**1. 用户交互模块 (UI Layer)**
- **职责：** 获取用户输入，并美观地展示结果。
- **组成：** 标题区、输入文本框、按钮、结果展示区（偏差卡片、总结）、设置面板。
- **关键设计：** 将“设置”功能（API配置）隐藏在一个可滑出的侧边面板中，保持了主界面的简洁。

**2. 逻辑控制模块 (Controller)**
- **职责：** 协调整个流程，像交通指挥中心。
- **工作流：**
    1.  监听“开始检测”按钮的点击。
    2.  获取用户输入的文本。
    3.  调用“AI通信模块”发送请求，同时显示“加载中”动画。
    4.  收到AI回复后，调用“结果渲染模块”来更新页面。
    5.  处理“复制”和“下载”报告的请求。

**3. AI通信模块 (AI Gateway)**
- **职责：** 负责与后端AI服务（如DeepSeek API）对话。
- **核心动作：** 它接收用户文本，然后**按照一个精心设计的模板（Prompt）** 包装成AI能理解的指令，通过HTTP请求发送出去，最后把AI的回复带回给逻辑控制模块。

**4. 结果渲染模块 (Renderer)**
- **职责：** 把AI返回的原始数据（通常是JSON格式）转换成漂亮的HTML卡片和段落。
- **工作流：** 它解析AI返回的JSON数据，然后动态生成对应的HTML元素（如`.bias-card`），并插入到页面中指定的位置（`#biases-container`）。

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入文本 → 逻辑控制器 → (包装Prompt) → AI通信器 → (调用API) → AI模型
                                                                 ↓
报告下载/复制 ← 结果渲染器 ← (解析JSON) ← 逻辑控制器 ← AI通信器
```

**最值得学习的设计：**
**“Prompt工程”与“前端展示”的松耦合设计。** AI返回的是结构化的JSON数据，前端只是根据这个结构来渲染。这意味着：
- 你可以**只改Prompt**，让AI分析其他东西（如逻辑谬误、情感倾向），而前端代码几乎不用动。
- 你可以**只改前端渲染**，用不同的方式（如图表、思维导图）展示同样的JSON数据，而不用改AI逻辑。
这种分离让系统非常灵活，易于维护和扩展。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt是给AI的“**工作说明书**”和“**输出格式规范**”。它告诉AI：“你现在是心理学家，任务是分析文本找认知偏差，并且必须严格按照我给的JSON格式把结果吐出来。”

**它解决的是“理解问题”还是“生成问题”？**
它同时解决了两个问题：
1.  **理解问题：** 通过“你是一位专攻认知偏差的心理学家”来设定AI的角色，引导其用特定领域的知识来理解文本。
2.  **生成问题：** 通过严格的JSON格式模板，强制AI的输出是结构化的数据，而不是随意的散文，这极大方便了前端程序的后续处理。

**哪些信息是 Prompt 中的关键变量？**
- **`${statement}`：** 这是唯一的动态变量，即用户输入的文本。整个Prompt都围绕分析它而构建。
- **JSON结构定义：** `detected_biases`数组和`summary`字段的格式是固定的，这是前端代码所依赖的“数据合同”。

**如果只改 Prompt，不改代码，会发生什么变化？**
- **改变分析领域：** 将“认知偏差”改为“逻辑谬误”、“修辞手法”或“文章风格”，网页就变成了“逻辑谬误检测器”、“修辞分析器”。
- **改变输出结构：** 如果在JSON中增加一个`confidence_level`（置信度）字段，AI会在分析中附带这个信息，但**前端不会显示它**，因为渲染代码不认识这个新字段。你需要同步修改前端渲染逻辑来利用新数据。

## 【五】如何模仿它，做出你自己的版本？

这是一个低风险的“三步替换法”，你可以从最安全的一步开始：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标：** 先做出一个能跑起来的、属于你自己的工具。
- **操作：**
    1.  复制整个HTML代码，保存为新文件。
    2.  修改`<title>`和页面标题（如`<h1>`），比如改成“**我的文章灵感生成器**”。
    3.  修改输入框上方的提示文字，例如：“输入一个主题词，AI将为你生成写作灵感。”
    4.  修改按钮文字，如“开始生成”。
    5.  此时，点击按钮会调用原来的“认知偏差”分析，这没关系，我们下一步就改核心。

**第二步：调整输入字段或 Prompt（核心改造）**
- **目标：** 改变工具的核心功能。
- **操作：**
    1.  **修改Prompt：** 找到`getPrompt`函数。将里面的系统指令和JSON模板完全重写。例如，如果你想做“灵感生成”，Prompt可以改为：“你是一位创意写作教练。根据用户提供的主题‘${topic}’，生成3个独特的写作灵感。以JSON格式返回：`{"inspirations": [{"title": "...", "core_idea": "..."}]}`”
    2.  **（可选）修改输入：** 如果你的新功能需要不同的输入（如多个输入框、下拉选择），在此步骤修改HTML中的表单部分。

**第三步：改变输出形式或展示方式（个性化界面）**
- **目标：** 让结果展示符合你的新主题。
- **操作：**
    1.  修改结果区域的标题，如“灵感列表”。
    2.  重写`renderResult`函数。根据你新Prompt中定义的JSON结构（如`data.inspirations`），用新的HTML模板来渲染。比如，把“偏差卡片”改成“灵感卡片”。
    3.  调整CSS样式，改变颜色、图标，使其符合新工具的气质（如创意工具可以用更活泼的颜色）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，让分析更精准：**
    - **操作：** 在输入框上方增加几个单选按钮或复选框，让用户选择**上下文**，例如：“分析场景：[ ] 个人决策 [ ] 商业论证 [ ] 社交媒体帖子”。
    - **改造点：** 将这个选择作为变量加入到Prompt中，例如：“请以${context}的视角，分析以下文本...”。这样AI能给出更贴合场景的分析。

2.  **切换或扩展AI模型后端：**
    - **操作：** 在设置面板的“模型选择”下拉菜单中，增加其他API的选项，如`gpt-4o`、`claude-3-sonnet`，并对应修改`api-url`的默认值。
    - **改造点：** 修改`getApiUrl()`和`getApiKey()`函数，使其能根据不同的模型选择，拼接不同的API端点和请求头。这让你可以对比不同模型的分析效果。

3.  **将单次分析扩展为对话式反思：**
    - **操作：** 在分析结果下方，增加一个“追问”输入框和按钮。
    - **改造点：** 点击“追问”后，将用户的新问题和之前的分析历史，一并作为上下文发送给AI。这需要修改消息数组，将历史对话也包含进去（`messages`数组），实现多轮交互，引导用户深度反思。

4.  **优化交互体验与可视化：**
    - **操作：** 使用一个简单的图表库（如Chart.js）。
    - **改造点：** 如果检测到多个偏差，不再只是列表，可以增加一个“偏差分布”饼图或条形图，直观展示各类偏差的占比。这需要让Prompt中的JSON返回每个偏差的`type`或`category`字段。

5.  **拆解为“创建”与“浏览”两个页面：**
    - **操作：** 创建`index.html`（分析页面）和`history.html`（历史记录页面）。
    - **改造点：** 每次生成报告后，将报告数据（输入文本、分析结果、时间戳）用`localStorage`或`IndexedDB`保存起来。在`history.html`中列出所有历史记录，并可以点击查看详情。这增加了工具的实用性。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做专业的心理或医学诊断：** 认知偏差是普遍的思维模式，但此工具无法识别临床意义上的认知扭曲或精神健康问题。如果有人需要心理帮助，应寻求专业心理咨询师或医生。
2.  **不适合作为辩论中“攻击”他人的工具：** 它的设计初衷是**自我反思**和**提升自我认知**。如果用来机械地指责他人“你有XX偏差”，可能会破坏沟通，因为它缺乏对他人情境和情感的完整理解。
3.  **不适合处理高度依赖专业知识的领域判断：** 例如，对于“这个手术方案风险很高”的判断，偏差检测可能指出“消极偏误”，但真正的风险需要医学专业知识。AI无法替代领域专家。
4.  **不适合分析非文本或极度模糊的输入：** 它依赖于清晰的语言表述。对于一首抽象诗、一幅画，或者一句非常含糊的“我感觉不好”，它的分析可能流于表面或产生误导。

**如果你想做的是：**
- **实时分析对话情绪：** 需要寻找专门的“情感分析API”并设计流式交互界面。
- **构建一个专业的决策辅助系统：** 需要整合更多框架（如SWOT分析）、数据输入，并可能涉及更复杂的后端逻辑。
- **创建一个娱乐性的“性格测试”：** 需要设计一套问题和评分逻辑，与当前的分析型Prompt思路不同。

希望这份指南能帮助你不仅使用这个工具，更能理解其设计精髓，并创造出属于你自己的、有价值的AI应用。动手修改，从第一步开始吧！
