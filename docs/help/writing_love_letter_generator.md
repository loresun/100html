# 情书生成器 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你需要向心仪的人、伴侣或重要的人表达情感，但苦于文笔有限、不知如何下笔，或者希望获得更专业、更有创意的表达方式时，这个工具可以帮你。它特别适合以下情况：
*   **特殊场合**：生日、纪念日、情人节，需要一封特别的信。
*   **情感表达**：初次表白、道歉、挽回、表达思念，需要合适的措辞。
*   **创意辅助**：想给日常情话增加一些新意和浪漫色彩。

**不适合的情况：**
*   **需要完全原创、高度个人化的创作**：AI生成的内容是基于模式和示例的，可能无法完全替代你内心最独特、最私人的感受。
*   **处理严肃或复杂的沟通**：如涉及重大分歧、法律事务或深度心理咨询，AI生成的情书可能过于表面，无法解决根本问题。
*   **完全替代真实互动**：情书是情感的载体，但无法取代面对面的交流、倾听和共同经历。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    *   **Ta的信息**：对方的称呼（如“宝贝”）和你们的关系（如“女朋友”）。
    *   **写作场景**：这封信的目的（如“生日祝福”、“道歉”），以及你想包含的具体回忆或心情。
    *   **文风与字体**：选择你喜欢的文字风格（浪漫、文艺、可爱等）和信纸的显示字体。

2.  **用户通常会做哪几步操作？**
    1.  在左侧面板依次填写或选择“收信人信息”、“写作场景”。
    2.  挑选一种你喜欢的“文风”和“信纸字体”。
    3.  点击页面底部大大的 **“开始书写情书”** 按钮。
    4.  稍等片刻，右侧就会生成一封完整的情书。
    5.  你可以“复制情书”直接使用，或者“换种写法”让AI重新生成，还可以点击“撒花”获得浪漫的屏幕特效。

3.  **输出结果长什么样？**
    生成的情书会显示在一张设计精美的复古信纸上，带有横线纹理和装饰边框。文字会根据你选择的字体和风格呈现。如果使用了“深情”模型，你还可以展开查看“AI的深情构思”，了解AI的思考过程。

4.  **有哪些容易忽略的使用细节？**
    *   **首次使用需配置API**：点击右上角的设置按钮（齿轮图标），填入你自己的DeepSeek API Key，否则无法生成。这个Key只保存在你的电脑本地。
    *   **“想说的话”是灵魂**：在“写作场景”部分多写一些你们的独特回忆或你的真实感受，AI能据此生成更个性化、更打动人的内容。
    *   **模型选择**：导航栏的“灵感”和“深情”按钮代表两种AI模型。“灵感”响应更快，“深情”会产生更详细的思考过程，文笔可能更细腻。
    *   **撒花特效**：生成情书后，可以多次点击“撒花”按钮，让屏幕上飘落更多花瓣。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

1.  **控制面板模块（左侧）**
    *   **职责**：收集用户的所有输入和偏好设置。它像是一个“配方收集器”，明确需要哪些“原料”（对方信息、场景、风格）来制作情书。
    *   **子模块**：收信人信息表单、场景选择器、文风按钮组、字体选择器、生成按钮。
    *   **逻辑**：用户在此模块进行所有选择 -> 数据被实时保存在`input`对象中 -> 点击生成按钮时，触发后续流程。

2.  **展示与输出模块（右侧）**
    *   **职责**：向用户呈现结果和状态。它有三种状态：空状态（等待输入）、加载状态（正在生成）、结果状态（展示情书）。
    *   **核心设计**：**信纸组件**。它不仅仅是一个文本框，而是通过复杂的CSS（背景纹理、渐变、伪元素）模拟出复古信纸的视觉效果，极大增强了输出的情感价值和沉浸感。
    *   **逻辑**：接收生成结果 -> 应用选中的字体 -> 在信纸容器中渲染文本 -> 提供复制、重试等操作按钮。

3.  **AI引擎与逻辑模块（脚本部分）**
    *   **职责**：作为大脑，处理数据、调用AI、管理状态。它连接了输入和输出。
    *   **关键函数**：
        *   `buildPrompt()`：将用户输入的结构化数据，拼接成一段给AI的详细“写作指令”（Prompt）。
        *   `generate()`：负责调用DeepSeek API，并以流式（stream）方式接收AI的回复，实现“逐字打出”的效果，提升体验。
    *   **逻辑链路**：`用户输入` -> `buildPrompt()` -> `调用API` -> `流式接收并更新DOM` -> `最终结果渲染到展示模块`。

**最值得学习的设计：**
**“Prompt工程”与“用户体验”的紧密结合**。它没有简单地将用户输入框直接扔给AI，而是通过`buildPrompt()`函数，将零散的表单数据（称呼、关系、场景、风格、回忆）组织成一段角色明确、要求清晰、带有示例的“写作任务描述”。这确保了AI输出的内容高度符合用户预期。同时，流式输出、精美的信纸UI、花瓣动画等，共同营造了一种“创作仪式感”，而不仅仅是一个工具。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt扮演的角色**：它是连接**用户意图**和**AI能力**的“翻译官”和“导演”。它告诉AI：“现在请你扮演一个专业情书作家，根据这些具体信息（A、B、C），按照这种风格（D），写一封满足这些要求（E、F、G）的信。”
2.  **解决的问题**：主要解决“**生成问题**”。它需要AI根据给定的约束条件（风格、场景、内容）创造出一段全新的、符合要求的文本。
3.  **关键变量**：
    *   **系统角色**：`你是一位专业的情书作家...`
    *   **用户变量**：`称呼：${name}`， `关系：${relationship}`， `场景：${occasion}`
    *   **风格变量**：`写作风格：${styleDesc}` (由`getStyleDescription`函数映射)
    *   **核心内容**：`用户想说的话/回忆：${memories}`
    *   **格式指令**：`开头用...`， `长度适中...`， `不要使用Markdown...`
4.  **只改Prompt的影响**：如果你只修改`buildPrompt()`函数中的提示文本，而不改动任何页面代码，你可以彻底改变这个应用的功能。例如：
    *   把“情书作家”改成“短视频脚本编剧”，把“情书”要求改成“产品广告文案”，它就能变成一个广告生成器。
    *   调整风格描述，可以创造出全新的文风（如“科幻风格”、“摇滚歌词风格”）。
    *   修改格式指令，可以让AI输出诗歌、对话体、甚至是一段JSON数据。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从最安全、改动最小的地方开始）：**

1.  **第一步：替换主题与输入字段（最安全）**
    *   **目标**：做一个“节日祝福生成器”。
    *   **操作**：
        *   修改网页标题和主标题。
        *   将“收信人信息”改为“接收人信息”（称呼、关系如“同事/长辈/朋友”）。
        *   将“写作场景”改为“节日类型”（春节、中秋、圣诞）和“祝福主题”（健康、事业、学业）。
        *   将“文风”改为“祝福风格”（正式、幽默、温馨）。
        *   **此时，页面结构、交互逻辑、API调用完全不变。**

2.  **第二步：重写核心Prompt**
    *   **目标**：让AI生成祝福语而非情书。
    *   **操作**：修改`buildPrompt()`函数。将系统指令从“情书作家”改为“节日祝福语创作专家”，并相应调整所有描述和要求。这是功能转变的核心。

3.  **第三步：调整输出展示形式**
    *   **目标**：让界面更符合节日氛围。
    *   **操作**：
        *   修改CSS中的颜色变量（`:root`），将玫瑰色系改为节日色系（如春节用红金色）。
        *   替换信纸背景，可以换成贺卡、红包或灯笼的样式。
        *   将“撒花”特效改为“放烟花”或“飘雪花”。
        *   修改字体选项，增加更喜庆或正式的字体。

**从哪里下手最安全？**
从**第一步**开始。先只改HTML中可见的文本和标签，不动JavaScript逻辑。这样你能立刻看到一个外观不同的页面，并且所有功能依然正常。这能帮你建立信心，并理解数据是如何流动的。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加个性化输入**：
    *   **操作**：在输入面板增加“**共同爱好**”、“**第一次见面地点**”、“**Ta最喜欢的___**”等更具体的字段，并将这些信息加入到`buildPrompt()`中。这能让生成的情书细节更丰富、更个人化。

2.  **切换或增加AI模型/API**：
    *   **操作**：在设置面板或导航栏增加一个下拉菜单，允许用户选择不同的AI服务提供商（如OpenAI的GPT、Anthropic的Claude、智谱AI等）。你需要在`generate()`函数中根据选择，修改请求的URL、Headers和Body格式。

3.  **实现“历史记录”与“收藏”功能**：
    *   **操作**：利用浏览器的`localStorage`，在生成情书后，不仅显示出来，还将它（连同当时的输入参数）保存到一个数组里。然后新增一个“历史”页面或侧边栏，用来查看、重新编辑或再次生成过去的情书。

4.  **优化交互体验**：
    *   **操作**：
        *   **一键替换段落**：在生成的情书旁，为每个段落添加一个“改写此段”的小按钮，让用户可以对不满意部分进行局部优化，而无需重写整篇。
        *   **情感强度滑块**：增加一个滑块，让用户选择“含蓄”到“热烈”的情感强度，并将这个参数（如“请用${value}级的情感浓度来写”）加入到Prompt中。
        *   **语音朗读**：利用浏览器的`SpeechSynthesis` API，添加一个“朗读情书”按钮，让AI用语音读出生成的内容。

5.  **拆分为多页面应用**：
    *   **操作**：将当前单页面拆解。
        *   **页面A（引导页）**：选择写信类型（情书、道歉信、感谢信）。
        *   **页面B（信息填写页）**：根据不同类型，展示不同的输入表单。
        *   **页面C（结果页）**：展示生成结果，并提供分享（生成图片海报）、下载（PDF/TXT）等高级功能。
    *   **好处**：逻辑更清晰，可以针对不同场景做更深度的定制。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合生成需要承担法律或严肃承诺的文字**：例如合同条款、具有法律效力的道歉声明、医疗建议等。AI生成的内容不具备法律效力，且可能不准确。
2.  **不适合完全替代深度、真实的沟通**：如果你们的关系出现了严重问题，一封无论多优美的AI情书可能只是“创可贴”，无法替代真诚的、可能困难的面对面交流。
3.  **不适合创作高度依赖个人独特经历和视角的文学作品**：比如你要写一部自传体小说中的关键情节，AI无法拥有你的记忆和情感深度，它只能提供模式和套路。
4.  **不适合在无网络或API失效时使用**：这是一个强依赖云端AI服务的工具。如果你的API额度用完、Key失效或没有网络，它将无法工作。

**如果你想做X，应该换什么工具或方式？**
*   **想写法律文书**：请咨询律师或使用专业的法律文件起草软件。
*   **需要进行深度情感沟通或心理咨询**：建议寻求专业的心理咨询师，或使用经过认证的心理互助平台。
*   **想进行纯粹的、不受影响的个人创作**：关掉这个工具，打开一个空白文档，写下你脑海中浮现的第一个词。
