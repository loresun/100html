# FAQ 问答生成器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景：**
想象你是一名电商运营、产品经理或内容创作者。你刚推出了一款新产品（比如一款智能水杯），需要为它的销售页面、官网或客服系统准备一份“常见问题解答（FAQ）”。手动编写这些问题和答案非常耗时，而且你希望它们不仅仅是回答问题，更要能**打消顾客疑虑、突出产品卖点、最终促进购买**。

这个网页就是你的“AI内容助手”。你只需输入产品的基本信息，它就能自动生成一套结构完整、语言专业、且带有营销引导性的FAQ列表。它特别适合：
*   **快速搭建产品页面**：为新上架的商品快速生成详情页FAQ模块。
*   **统一客服口径**：为客服团队提供标准、专业的回答话术库。
*   **内容营销**：为社交媒体、私域社群准备预热或答疑内容。

**不适合什么情况？**
*   **需要完全原创、无AI痕迹的文案**：生成的内容基于通用模板，可能缺乏独特的品牌个性。
*   **处理高度专业、依赖实时数据的问答**：例如法律咨询、医疗诊断或股票行情，它无法接入实时数据库或保证绝对准确。
*   **替代深度市场调研**：它生成的是“可能”被问到的问题，而非通过真实用户反馈收集的“实际”问题。

## 【二】使用方式（给第一次接触的人）

1.  **准备工作**：点击页面右上角的“设置”按钮，输入你的 DeepSeek API Key（需要自行申请）。这是让网页调用AI能力的“钥匙”。
2.  **描述你的产品**：
    *   **产品/服务名称**（必填）：给你的产品起个名字，如“冰川速冷咖啡机”。
    *   **产品详细信息**（必填）：详细描述它的功能、卖点、适用人群等。信息越详细，生成的问题越精准。
3.  **定制你的FAQ**：
    *   **FAQ类型**：勾选你希望覆盖的问题方向，如“产品功能”、“物流配送”、“质量保障”等。
    *   **生成数量**：拖动滑块，选择想生成多少条问答（5-20条）。
    *   **应用场景**：选择FAQ用在何处，如“电商详情页”或“客服话术库”，AI会根据场景调整语气。
    *   **额外要求**：可以输入特定要求，如“面向大学生群体，强调性价比”。
4.  **一键生成**：点击页面左侧底部的 **“✨ 一键生成 FAQ”** 按钮。等待15-30秒，AI会进行思考并生成。
5.  **查看与使用结果**：
    *   右侧区域会展示生成的所有问答卡片，每条都包含问题、详细回答、分类和可能的购买引导语。
    *   你可以**复制单条**、**复制全部**或**导出为TXT文件**直接使用。
    *   如果使用了“DeepSeek Reasoner”模型，还可以点击“查看 AI 深度思考过程”，了解AI是如何分析产品并构思问题的。

**容易忽略的细节：**
*   **API Key是核心**：不配置Key，点击生成只会弹出设置窗口。
*   **产品信息要具体**：只写“很好用的空气净化器”，AI很难发挥。写上“适用面积、噪音值、滤网等级、价格”等，结果会好得多。
*   **“提示词”设置是高级玩法**：点击右上角“提示词”，你可以修改驱动AI的“指令模板”，从而彻底改变生成风格和格式，无需改动代码。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块，像一个高效的内容生产线：

1.  **控制面板（左侧）**
    *   **职责**：收集用户的所有“生产指令”。它把零散的需求（产品是什么、要什么类型、用在哪儿）结构化成一份清晰的“生产订单”。
    *   **输入**：用户填写的表单数据。
    *   **处理**：将表单数据整理、拼接，为下一步的AI调用做好准备。
    *   **输出**：一份结构化的数据对象，包含了生成FAQ所需的所有参数。

2.  **AI引擎（不可见，但最关键）**
    *   **职责**：页面的“大脑”。它接收控制面板的“订单”，结合内置的“说明书”（Prompt），调用外部AI API进行真正的创作。
    *   **输入**：结构化数据 + 系统/用户提示词（Prompt）。
    *   **处理**：通过API将请求发送给DeepSeek模型，并以“流式”方式接收AI的回复，实时解析数据。
    *   **输出**：一个符合预定格式（JSON）的FAQ数据数组。

3.  **展示与输出区（右侧）**
    *   **职责**：将AI生成的“数据产品”进行精美的包装和交付。
    *   **输入**：AI引擎返回的原始FAQ数据。
    *   **处理**：将数据渲染成易于阅读的卡片式UI，并添加复制、导出等实用功能。
    *   **输出**：可供用户直接使用或分享的格式化内容（屏幕展示、剪贴板文本、TXT文件）。

**逻辑链路：**
`用户填写表单` → `控制面板整理数据` → `拼接Prompt并调用AI API` → `AI生成JSON格式答案` → `展示区渲染为美观卡片` → `用户复制或导出`

**最值得学习的设计：**
**“数据与展示分离”**。整个页面的核心是中间那份JSON数据。左侧面板负责生产这份数据所需的原料，右侧面板负责美化展示这份数据。AI引擎是黑盒。这种设计让每个模块职责清晰，未来如果你想更换UI样式（比如变成表格），或者更换AI模型（比如用GPT），只需要修改对应的模块，而不会牵一发而动全身。代码中的 `result.value` 对象就是连接这一切的“数据桥梁”。

## 【四】Prompt / AI 逻辑是如何被设计的？

*   **Prompt的角色**：它是AI的“角色卡”和“任务说明书”。`系统提示词(System Prompt)` 定义了AI的身份（电商运营专家）和核心任务（写高转化FAQ）。`用户提示词(User Prompt)` 则给出了具体的产品信息、格式要求和写作要点。
*   **解决什么问题**：它同时解决了“理解问题”和“生成问题”。首先让AI理解“什么是高转化的FAQ”，然后指导它根据变量信息生成具体内容。
*   **关键变量**：在用户提示词中，用 `{花括号}` 包裹的部分就是变量，如 `{productName}`, `{productInfo}`, `{count}`, `{platform}`。这些会在用户点击生成时，被替换成真实输入的值。
*   **只改Prompt的效果**：你可以彻底改变这个工具的行为，而不用写一行代码。例如：
    *   把系统提示词改成“你是一位严谨的律师”，用户提示词改成“根据以下条款生成法律风险问答”，它就变成了一个**法律QA生成器**。
    *   在用户提示词中修改输出格式要求，比如要求生成Markdown表格或XML格式，AI就会照做。
    *   改变写作风格要求，如“用00后的网络流行语风格”，生成的内容语气会完全不同。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从易到难）：**

1.  **第一步：替换场景，保持骨架（最安全）**
    *   **目标**：做一个“社交媒体帖子生成器”。
    *   **操作**：不要动任何HTML和JS代码。只修改两处：
        *   **文字**：把页面标题、输入框的标签（如“产品/服务名称”改为“帖子主题”，“产品详细信息”改为“内容要点”）。
        *   **Prompt**：在提示词设置中，将系统提示词改为“你是一个爆款社交媒体文案写手”，用户提示词改为“请根据以下主题和要点，生成{count}条不同风格的微博/小红书帖子...”。保留 `{变量}` 格式。
    *   **效果**：你立刻得到了一个全新工具，结构、交互、美观程度完全不变。

2.  **第二步：调整输入字段**
    *   **目标**：让工具更贴合新场景。
    *   **操作**：在左侧控制面板的HTML中，增加或替换一些输入字段。例如，增加一个“平台”选择框（微博/小红书/抖音），并将这个新变量（如 `{socialPlatform}`）加入到用户提示词的变量列表中。同时，在JS的 `input` 对象和 `buildUserPrompt` 函数中对应增加这个字段的处理逻辑。
    *   **效果**：你的工具输入更精细，AI生成的内容针对性更强。

3.  **第三步：改变输出形式**
    *   **目标**：展示结果更符合新场景。
    *   **操作**：修改右侧展示区的HTML和CSS。例如，将FAQ卡片改成模仿小红书笔记的样式（加上封面图占位、标签、点赞图标）。同时，修改 `copyAllFAQ` 和 `exportFAQ` 函数，让导出的文本格式符合帖子要求（比如加上话题标签 `#`）。
    *   **效果**：工具的最终产出物在形式和体验上完全定制化。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“风格模板”选择**：
    *   **操作**：在输入面板增加一个下拉框，选项如“专业严谨风”、“亲切活泼风”、“科技极客风”。在提示词中对应增加一个 `{tone}` 变量，并根据选择，在系统提示词开头动态添加“请使用{风格}风格进行写作”。
    *   **效果**：用户无需手动修改复杂的提示词，就能一键切换内容风格。

2.  **接入多模型API，实现降级备援**：
    *   **操作**：在API设置中，除了DeepSeek，增加OpenAI GPT、智谱GLM等模型的选项和Key输入框。在 `generateFAQ` 函数中，根据选择使用不同的API端点地址和请求格式。
    *   **效果**：当一个AI服务不稳定时，可以快速切换到另一个，提升工具可靠性。

3.  **拆分为“编辑-预览”工作流**：
    *   **操作**：生成结果后，在每个FAQ卡片上增加“编辑”按钮。点击后，可以在当前页面内直接修改问题和答案，并实时预览。修改后的内容可以保存到新的结果集中。
    *   **效果**：将工具从“全自动生成”升级为“AI辅助编辑”，实用性大增。

4.  **优化交互体验**：
    *   **操作**：为“生成”按钮添加防重复点击机制；在流式生成时，在右侧展示区实现答案的逐条“打字机”效果输出，而非等待全部完成再一次性显示。
    *   **效果**：让等待过程更有期待感，用户体验更流畅。

5.  **增加“示例库”功能**：
    *   **操作**：在页面空状态区域或新增一个标签页，展示几个经典产品的优秀FAQ生成案例（如“iPhone”、“戴森吹风机”）。用户点击“使用此示例”可以快速填充表单。
    *   **效果**：降低新用户的学习成本，直观展示工具潜力。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合生成需要100%准确无误的内容**：例如，生成医疗健康建议、财务投资建议或法律合同条款。AI可能产生“一本正经的胡说八道”，必须由领域专家严格审核。
*   **不适合替代复杂的用户调研**：它生成的是基于常见模式的“预测性问题”，而非来自真实用户访谈、评论分析的“真实痛点”。用于初步搭建可以，但优化产品仍需深入调研。
*   **不适合处理超长或极度复杂的说明书**：输入框的文本长度有限，且AI对极其复杂技术文档的理解和提炼能力有瓶颈。对于大型软件或工业设备，更适合用知识库问答系统。
*   **如果用户想做**：一个能与用户实时对话、根据追问动态调整答案的**智能客服机器人**。
*   **应该换什么工具**：应该使用专门的开源框架（如LangChain、Dify）或云服务（如阿里云、腾讯云的智能客服平台），搭建基于知识库的检索增强生成（RAG）系统，而非本页的一次性生成模式。
