# 大模型生成器工具 - 学习与使用指南

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一名内容创作者、产品经理或数据分析师，每天需要处理大量文本任务：写产品文案、总结会议纪要、批量生成内容、对比不同AI模型的回答……如果每次都手动打开聊天窗口，复制粘贴、调整格式，效率会非常低。

这个网页就是一个 **“AI工作流工具箱”**。它把常见的AI文本处理任务，预先打包成了16种标准化的“模式”。你不需要每次都重新构思如何提问，而是像选择工具一样，直接使用对应的模式，填入你的具体内容，就能快速得到结构化的结果。

**适合的场景：**
- **内容创作**：快速生成不同风格的文案、标题、摘要。
- **数据处理**：批量处理列表数据（如为每个产品生成描述）。
- **方案对比**：用同一个问题测试不同AI模型或参数，横向比较结果。
- **流程自动化**：将多步骤任务（如翻译+总结）串联起来一次性完成。

**不适合的场景：**
- **需要深度、开放式对话**：它侧重于“任务处理”，而不是自由聊天。
- **处理非文本内容**：如图片、音频、视频的生成或分析。
- **需要极高定制化或复杂逻辑判断**的任务。

## 【二】使用方式（给第一次接触的人）

**第一步：配置你的“引擎”**
1.  点击页面右上角的齿轮图标（⚙️），打开设置面板。
2.  填入你的大模型API密钥和地址（例如DeepSeek、OpenAI等）。
3.  点击“测试连接”，确保顶部的红色状态点变绿，表示配置成功。

**第二步：选择你的“工具”**
-   页面上方有一排标签页，如“一进一出”、“多字段整合”、“批量同构”等。每个标签代表一种处理文本的特定方法。
-   首次打开默认是 **“一进一出”** 模式，这是最基础的问答模式。

**第三步：使用一个模式（以“多字段整合”为例）**
1.  点击 **“多字段整合”** 标签。
2.  在左侧输入区域，你会看到几个已经填好示例的字段：`产品名称`、`产品描述`、`目标受众`、`风格要求`。
3.  你可以直接修改这些字段的内容。例如，把“极速空气炸锅”改成你的产品名。
4.  中间有一个 **“提示词模板”** 文本框。它用 `{产品名称}` 这样的占位符，将你上面填的字段自动组合成一个完整的提问。
5.  点击 **“提交”** 按钮。
6.  稍等片刻，右侧的“输出”区域就会显示AI根据你的所有信息生成的宣传文案。

**输出结果什么样？**
-   通常是一段格式整洁的文本。
-   下方会显示本次请求消耗的时间和Token数量。
-   输出框上方有复制、下载、分享等操作按钮。

**容易忽略的细节：**
1.  **模式切换**：**每个标签页都是完全独立的工作区**。在“一进一出”里输入的内容，不会自动带到“多字段整合”里。切换标签时注意保存或复制需要的内容。
2.  **参数调节**：很多模式下方有“温度”、“最大长度”等滑块和输入框。**“温度”值越高，AI的回答越随机、有创意；值越低，回答越稳定、可预测。** 根据任务需求调整。
3.  **模板编辑**：在“多字段整合”、“批量同构”等模式中，核心是那个“提示词模板”。**你可以自由修改模板的文字和占位符格式**，让它更适合你的任务。

## 【三】核心结构拆解（学习重点）

这个网页可以看作一个 **“模式选择器” + “任务处理器”** 的组合。它的结构非常清晰：

**1. 控制面板模块（顶部）**
-   **职责**：提供全局设置（API配置）和模式导航。
-   **设计亮点**：将16种复杂功能通过标签页归类，界面清爽，降低了用户的学习成本。

**2. 模式容器模块（中部主体）**
-   **职责**：承载当前选中模式的所有交互元素。这是页面的核心，每个标签页对应一个独立的“容器”。
-   **设计亮点**：**“输入区-处理区-输出区”的横向布局**。左侧配置任务，右侧查看结果，符合从左到右的操作逻辑。

**3. 通用任务处理流程（以任一模式为例）**
```
用户输入/选择 (左侧表单) 
    → 
前端组装 (将表单值填入模板，生成最终Prompt) 
    → 
网络请求 (调用设置好的API) 
    → 
结果处理与展示 (在右侧区域渲染，并计算耗时、Token数)
```

**最值得学习的设计：**
-   **“模板+占位符”的抽象层**：这是本工具的灵魂。它没有把AI调用写死，而是让用户通过修改模板来定义任务逻辑。例如，“多字段整合”模式本质上是一个**信息收集表单**和一个**可定制的文本模板**的结合。这种设计使得工具的可扩展性极强，**你不需要改代码，只需要改模板文字，就能创造出新的应用场景**。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个工具里，**Prompt（提示词）是连接用户意图和AI能力的“转换器”或“配方”**。

1.  **扮演的角色**：Prompt不是直接让用户写的，而是由工具**根据用户在前端表单的输入，动态组装而成**。它解决的是 **“将结构化数据转化为AI能理解并执行的任务描述”** 的问题。
2.  **关键变量**：Prompt中的关键变量就是那些 **`{占位符}`**，例如 `{产品名称}`、`{item}`、`{items}`。这些占位符会在请求发出前，被替换成表单中对应的真实值。
3.  **只改Prompt的效果**：这是理解本工具威力的关键。**如果你只修改某个模式里的提示词模板，而不动任何代码，你立刻就改变这个模式的功能。**
    -   *例子*：把“多字段整合”的模板从“写一篇宣传文案”改成“列出{产品名称}的5个优缺点”，那么这个模式瞬间就从“文案生成器”变成了“产品分析器”。

## 【五】如何模仿它，做出你自己的版本？

如果你想做一个类似但服务于自己需求的工具，请遵循这个安全的路径：

**第一步：复制骨架，替换场景（最安全）**
1.  复制整个HTML结构。
2.  修改标题、主题色，让它看起来是你的工具。
3.  **重点**：从16个模式中挑选一个最接近你需求的（例如，你需要批量处理数据，就选“批量同构”模式）。
4.  修改这个模式的**标题、输入字段的标签和默认值**。比如，把“产品名称”改成“文章标题”，把“风格要求”改成“情感基调”。

**第二步：调整输入与Prompt逻辑**
1.  在选定的模式中，根据你的新字段，调整左侧的输入表单（增加、删除或修改输入框）。
2.  **核心操作**：重写“提示词模板”文本框里的内容。使用你新定义的字段名作为占位符，构思一个能清晰指导AI完成你特定任务的Prompt。
3.  **测试**：填入一些示例数据，点击提交，看AI的输出是否符合你的预期。不断微调Prompt直到满意。

**第三步：改变输出与交互形式**
1.  如果AI返回的是结构化数据（如列表、JSON），你可以修改右侧输出区域的渲染方式。例如，将纯文本显示改为卡片列表或表格。
2.  可以增加新的操作按钮，比如“一键发布到博客”、“保存到数据库”等（这需要后端支持）。

**从哪里下手最安全？**
**从“一进一出”或“多字段整合”这两个模式开始模仿。** 它们的逻辑最直观，前端代码结构也相对简单。先实现一个模式跑通，再考虑增加复杂度。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“Prompt模板市场/库”**：
    -   **操作**：在页面侧边栏或新增一个标签页，提供一个“模板库”。里面预置各种写好的Prompt模板（如“小红书爆款标题生成”、“周报总结”、“代码注释生成”）。
    -   **效果**：用户无需自己写Prompt，点击即可应用，大大提升工具的实用性和用户体验。

2.  **集成更多模型供应商**：
    -   **操作**：在API设置中，将模型选择下拉框从固定的DeepSeek模型，扩展为支持OpenAI、Claude、智谱AI、月之暗面等多个供应商的模型列表。这可能需要一个统一的后端来适配不同API。
    -   **效果**：用户可以在同一个界面方便地切换和对比不同厂商的AI模型。

3.  **增加“历史记录”和“项目”功能**：
    -   **操作**：添加一个侧边栏或底部区域，保存用户每次的输入和输出。允许用户为一系列操作创建“项目”并命名。
    -   **效果**：方便回溯、复用和版本管理，使工具从“一次性工具”升级为“生产力工作台”。

4.  **优化交互：实时预览与流式输出**：
    -   **操作**：在用户修改Prompt模板时，在下方实时显示一个“预览”区域，展示替换占位符后的最终Prompt样子。
    -   **操作**：对于“流式输出”模式，实现真正的逐字输出效果，而不是等待全部生成完毕再显示。
    -   **效果**：提升交互的即时感和流畅度。

5.  **拆分为“轻量版”与“专家版”**：
    -   **操作**：默认只显示最常用的3-5个模式（如“一进一出”、“多字段整合”、“批量处理”）。设置一个“展开专家模式”的按钮，点击后才显示全部16个模式。
    -   **效果**：对新用户更友好，避免被过多选项吓到，同时保留了高级功能的可访问性。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为聊天机器人**：它的设计是“任务导向”而非“对话导向”。它没有维护对话历史上下文的能力，每次请求都是独立的。如果你需要多轮深入探讨一个问题，应该使用ChatGPT、Claude等原生聊天界面。
2.  **不适合处理高精度、事实性要求极强的任务**：例如，法律条文分析、医疗诊断建议、精确的财务计算等。AI可能产生“幻觉”（编造信息），且本工具没有内置事实核查机制。
3.  **不适合完全不懂Prompt的用户直接创造复杂工作流**：虽然它提供了模板，但用户仍需对如何设计有效的Prompt有基本理解。如果用户胡乱填写字段和模板，得到的输出质量会很低。
4.  **不适合企业级、高并发的自动化流程**：这是一个前端工具，API密钥暴露在浏览器端，存在安全风险。且没有任务队列、失败重试、用量监控等机制。企业级应用需要搭建有后端服务的、更健壮的系统。

**总结**：这个网页是一个出色的 **“前端AI应用原型”** 和 **“Prompt工程实践平台”**。它完美地展示了如何通过良好的界面设计，将AI能力封装成易用的工具。你的学习重点应该是理解其 **“数据表单 + 可配置模板 = 动态Prompt”** 的核心模式，并将其思想应用到自己的项目中。
