# 数据大小转换工具 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在处理一个文件传输任务，需要知道“500MB的文件用10Mbps的网速下载需要多久”，或者你在配置服务器时，需要将“1TB的存储空间”换算成“能存放多少张平均5MB的照片”。这个网页就是为这类**日常数字换算需求**而设计的。

**适合的使用场景：**
- 快速进行单位换算（如数据大小、时间、货币等）
- 需要一次性看到多个换算结果，方便对比
- 在学习和工作中进行简单的数学计算
- 作为个人效率工具集的一部分

**不适合的情况：**
- 需要复杂公式或专业领域的计算（如工程计算、统计分析）
- 需要保存大量历史记录或生成报告
- 需要与其他系统集成或自动化处理

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个或多个数字输入框（比如“数值”、“从哪个单位”、“到哪个单位”）
- 有时会有下拉菜单选择单位类型

**用户通常会做哪几步操作？**
1. 在“数值”框中输入你想换算的数字（比如 1024）
2. 在“从”下拉菜单中选择原始单位（比如“KB”）
3. 在“到”下拉菜单中选择目标单位（比如“MB”）
4. 点击“换算”按钮

**输出结果长什么样？**
- 结果会显示在一个浅灰色的卡片中
- 上方有小字说明这是什么结果（如“换算结果”）
- 下方用大号加粗字体显示具体数值（如“1 MB”）

**有哪些容易忽略的使用细节？**
- 页面右上角的“设置”按钮可以配置API（虽然当前工具可能用不到）
- 有些工具类型（如“公式计算器”）会有多个输入字段同时变化
- 输入数字时可以直接用键盘上下箭头微调
- 页面会自动保存你的输入和配置到浏览器本地

## 【三】核心结构拆解（学习重点）

这个页面采用了**“一个框架，多种工具”**的设计思路：

**关键模块组成：**
1. **导航栏** - 返回按钮和设置入口
2. **工具标题区** - 显示当前工具名称和描述
3. **动态内容区** - 根据工具类型显示不同的界面
4. **设置面板** - API配置（可隐藏）

**每个模块的职责：**
- **导航栏**：提供全局导航和设置入口
- **工具标题区**：告诉用户这是什么工具、能做什么
- **动态内容区**：这是核心，根据`tool.type`显示对应的输入输出界面
- **设置面板**：管理外部服务配置

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入数字和单位选择
    ↓
Alpine.js 数据绑定（x-model）
    ↓
点击“换算”按钮触发函数
    ↓
调用对应的计算函数（如 runConverter）
    ↓
执行换算逻辑
    ↓
更新 tool.result 数据
    ↓
界面自动重新渲染显示结果
```

**最值得学习的设计：**
**“类型驱动”的界面渲染机制**。整个页面只有一个HTML结构，但通过`x-show="tool.type === 'converter'"`这样的条件判断，可以渲染出10种不同的工具界面。这意味着：
- 添加新工具只需定义新的`type`和对应的HTML片段
- 代码复用率极高
- 维护成本低

## 【四】Prompt / AI 逻辑是如何被设计的？

**注意：** 从当前代码看，这个页面**本身没有使用AI或Prompt**。设置面板中的DeepSeek API配置是为其他可能集成了AI功能的工具准备的。

**如果这是一个AI工具页面，Prompt会如何设计？**
假设我们要做一个“智能单位换算”功能，Prompt可能这样设计：

```
角色：你是一个专业的单位换算助手。

任务：根据用户输入进行单位换算，并给出解释。

输入信息：
- 原始数值：{value}
- 原始单位：{fromUnit}
- 目标单位：{toUnit}
- 用户可能的用途：{context}（可选）

要求：
1. 先进行准确换算
2. 用通俗语言解释换算关系
3. 如果换算结果不常见，给出一个现实中的类比
4. 如果单位不兼容，礼貌提示并建议可用单位

示例输出格式：
【换算结果】{result} {toUnit}
【解释】{explanation}
【类比】{analogy}
```

**Prompt中的关键变量：**
- `{value}`：用户输入的数字
- `{fromUnit}`/`{toUnit}`：单位类型
- `{context}`：使用场景（让回答更贴切）

**如果只改Prompt，不改代码：**
- 可以改变AI回答的风格（从专业到幽默）
- 可以增加或减少输出信息的详细程度
- 可以针对不同用户群体定制解释方式

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持框架不变，替换工具类型**
1. 复制整个HTML结构
2. 在`standalone.js`中找到一个现有的工具定义（如`converter`）
3. 复制这个工具对象，修改`type`、`name`、`desc`等基本信息
4. 在HTML中找到对应的`x-show="tool.type === 'converter'"`区块
5. 复制这个区块，修改`type`匹配你新定义的工具

**第二步：调整输入字段**
1. 修改工具对象中的`fields`数组或输入字段定义
2. 调整HTML中的输入框数量、标签文字、单位
3. 确保`x-model`绑定的变量名与工具对象中的属性名一致

**第三步：实现计算逻辑**
1. 在`standalone.js`中找到对应的计算函数（如`runConverter`）
2. 复制并重命名函数
3. 修改内部的换算逻辑
4. 将结果赋值给`tool.result`

**第四步：测试并优化**
1. 检查所有数据绑定是否正确
2. 测试边界情况（如输入0、负数、极大值）
3. 优化显示格式（如数字保留几位小数）

## 【六】3–5 个可直接尝试的改造方向

**1. 增加“常用换算”快捷按钮**
- **操作**：在输入区域下方添加一行按钮，如“1GB→MB”、“1小时→秒”
- **效果**：用户无需重复输入常见换算
- **实现**：每个按钮绑定一个函数，点击时自动填充数值和单位

**2. 添加“换算历史”功能**
- **操作**：在结果区域下方显示最近5次换算记录
- **效果**：方便对比和回溯
- **实现**：用一个数组存储历史记录，每次换算后unshift新记录

**3. 实现“双向实时换算”**
- **操作**：去掉“换算”按钮，输入时自动实时计算
- **效果**：体验更流畅，类似计算器
- **实现**：使用`@input`监听输入变化，用`debounce`防抖

**4. 增加“单位说明”悬浮提示**
- **操作**：在每个单位标签旁添加问号图标，hover时显示该单位的定义
- **效果**：帮助用户理解单位含义
- **实现**：用`title`属性或自定义tooltip组件

**5. 支持“自定义换算公式”**
- **操作**：在设置中添加“自定义单位”功能
- **效果**：用户可以定义自己的换算规则（如“1箱=24瓶”）
- **实现**：增加一个表单让用户输入单位名称和换算系数

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不适合复杂计算**
   - 如果需要进行多步骤、带条件的计算（如“如果A>B则C=D否则C=E”）
   - **应该使用**：专业的计算器应用或Excel

2. **不适合批量处理**
   - 如果需要一次性换算1000个数据
   - **应该使用**：脚本语言（Python、JavaScript）或批处理工具

3. **不适合高精度科学计算**
   - 如果需要保留10位小数或进行误差分析
   - **应该使用**：专业数学软件（MATLAB、Mathematica）

4. **不适合团队协作**
   - 如果需要多人共享换算结果或协同编辑
   - **应该使用**：在线协作文档或专门的项目管理工具

5. **不适合离线复杂使用**
   - 虽然页面可以离线运行，但数据保存在本地浏览器
   - 如果换设备或清空缓存，数据会丢失
   - **重要数据应该**：手动导出或使用云同步服务
