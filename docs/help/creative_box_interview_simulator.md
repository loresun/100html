# 面试官模拟器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景：**
想象你正在准备一场重要的面试，感到紧张，不知道面试官会问什么，也不知道自己的回答是否得体。这个网页就像一个“面试陪练”，让你在一个安全、私密的环境里，与一个AI面试官进行模拟面试。你可以选择不同的职位、公司类型和面试风格，获得接近真实的面试体验和即时反馈。

**适合什么情况？**
- 面试前的实战演练，熟悉面试流程
- 练习特定岗位（如前端工程师、产品经理）的专业问题
- 改善自己的表达方式和逻辑结构
- 在没有真人陪练的情况下，获得基本的面试反馈

**不适合什么情况？**
- 需要高度专业、行业特定的深度技术面试（如特定框架的底层原理）
- 需要真人互动、观察非语言沟通（如肢体语言、眼神交流）的练习
- 作为最终面试表现的唯一评判标准（AI反馈有其局限性）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **面试配置**：你需要选择6个关键选项：
   - **面试职位**：你想练习的岗位（如前端工程师、产品经理）
   - **公司类型**：你心仪的公司类型（如科技创业公司、外企）
   - **工作经验**：你对应的经验水平
   - **面试风格**：你希望面对的面试官风格（友好轻松、专业严肃等）
   - **面试时长**：预计的模拟时长
   - **重点考察**：你希望被重点评估的能力

2. **设置面板**（右上角齿轮图标）：
   - **AI模型**：选择不同的AI模型（影响回答风格和深度）
   - **API密钥**：输入你的DeepSeek API密钥（首次使用需要）

**用户通常会做哪几步操作？**
1. **配置阶段**：在页面中央的“面试配置”区域，选择好所有选项。
2. **开始面试**：点击蓝色的“开始面试”按钮。
3. **对话阶段**：
   - 阅读AI面试官的开场白和第一个问题
   - 在下方文本框中输入你的回答
   - 点击发送按钮（或按Enter）
   - 观察右侧边栏的实时评分和进度变化
4. **控制选项**：可以使用“提示”按钮获取思路，“跳过”按钮跳过硬问题，“结束面试”提前终止。
5. **查看结果**：面试结束后，页面会显示详细的评估报告。

**输出结果长什么样？**
- **对话界面**：类似微信聊天的气泡对话框，左侧是面试官（紫色），右侧是你（绿色）。
- **实时侧边栏**：显示面试进度条、四个维度的实时评分（专业知识、沟通表达等）、问题统计。
- **最终报告**：一个独立的卡片，包含总分、综合评价、优势列表、改进建议和详细分析。

**有哪些容易忽略的使用细节？**
1. **API密钥**：第一次使用时，需要点击右上角齿轮图标，在设置面板中输入你的DeepSeek API密钥。如果留空，它会尝试读取浏览器中可能存在的全局配置。
2. **回答格式**：你的回答是纯文本输入，但尽量保持结构清晰（可以使用分点），AI会更好地理解。
3. **提示功能**：当卡住时，点击“提示”按钮，AI会给出思考方向，而不是直接答案。
4. **进度保存**：你的API密钥和模型选择会自动保存在浏览器本地，下次打开无需重新输入。
5. **移动端适配**：在手机上使用时，侧边栏会移到主内容下方，布局会自动调整。

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成，像一个精心设计的舞台剧：

### 模块1：配置面板（面试配置 + 设置面板）
- **职责**：收集用户的“面试剧本”参数。就像导演在开拍前确定演员、场景和风格。
- **输入**：用户通过下拉菜单选择的6个配置项。
- **处理**：将这些选项组合成一个完整的“面试场景描述”。
- **输出**：一组结构化数据，用于初始化整个面试流程。

### 模块2：对话引擎（聊天区域 + API调用）
- **职责**：整个应用的大脑，负责与AI模型对话，生成问题和评估。
- **输入**：用户配置 + 用户的历史回答。
- **处理**：
  1. 将配置和对话历史**组装成特定的Prompt**（指令）。
  2. 通过`callAPI`函数发送给DeepSeek API。
  3. 解析AI返回的JSON格式结果。
- **输出**：下一个问题、对当前回答的反馈、实时评分。

### 模块3：状态管理器（侧边栏 + 全局变量）
- **职责**：记录和展示面试的“生命体征”。
- **关键变量**：
  - `interviewSession`：存储当前面试的元数据（面试官信息、问题总数等）。
  - `interviewData`：存储用户的所有回答和累计评分。
  - `currentQuestion`：跟踪当前进行到第几个问题。
- **输出**：实时更新的进度条、分数、问题计数。

### 模块4：视图渲染器（所有显示相关的函数）
- **职责**：根据数据变化，更新页面的显示。就像舞台的灯光和布景。
- **关键函数**：
  - `displayMessage()`：在聊天区域添加新的对话气泡。
  - `updateScores()`：更新侧边栏的分数显示。
  - `displayResult()`：渲染最终的评估报告。

**逻辑链路：**
```
用户选择配置 → 点击“开始” → 生成初始化Prompt → 调用API → 解析结果 → 显示开场
      ↓
用户输入回答 → 生成评估Prompt → 调用API → 解析反馈和下一问 → 更新评分和进度
      ↓
（循环直到结束）→ 生成最终评估Prompt → 显示详细报告
```

**最值得学习的设计：**
**“状态与视图分离”**。这是本页面最精妙的地方。所有的面试数据（配置、回答、分数）都保存在JavaScript的全局变量（如`interviewData`）中。页面显示（HTML）只是这些数据的“镜像”。当数据变化时，调用对应的渲染函数（如`updateScores`）来更新镜像。这种设计让代码逻辑清晰，易于调试和扩展。如果你想增加一个新的评分维度，只需要在数据对象里加一个字段，然后修改对应的渲染函数即可。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演什么角色？**
Prompt是**翻译官**和**导演**的结合体。它把用户的选择和对话历史，“翻译”成AI模型能理解的、具体的任务指令，同时“导演”AI以特定的角色（专业面试官）和格式（JSON）进行回应。

**它解决的是“理解问题”还是“生成问题”？**
两者都有，但更偏向**生成问题**。核心逻辑是：
1. **初始化时**：Prompt告诉AI：“根据这些配置（职位、公司等），生成一个面试官人设和开场问题。”
2. **对话中**：Prompt告诉AI：“这是用户的回答，请给出反馈，并提出下一个问题。”
3. **结束时**：Prompt告诉AI：“这是所有对话历史，请生成一份评估报告。”

**哪些信息是Prompt中的关键变量？**
Prompt是**模板字符串**，其中被替换的部分是关键变量：
- `{getPositionName(position)}`：职位名称
- `{experience}`：工作经验
- `{response}`：用户的上一条回答
- `{currentQuestion}/${totalQuestions}`：当前进度
这些变量来自页面的输入或状态，动态插入到固定的Prompt模板中。

**如果只改Prompt，不改代码，会发生什么变化？**
变化会非常直接和巨大：
- **改变面试官性格**：修改`callAPI`函数中的`system`角色内容（如“你是一个严厉的资深技术专家”），AI的提问风格和反馈语气会立刻改变。
- **改变评估维度**：修改请求评估的Prompt模板，要求评估“创新能力”而非“领导力”，最终报告的重点就会转移。
- **改变问题类型**：在初始化Prompt中强调“多问一些关于项目管理的实际案例”，AI生成的问题类型就会偏向案例分析。
**这证明了Prompt是控制AI行为的“高效杠杆”**，调整它往往比修改代码逻辑更快捷。

## 【五】如何模仿它，做出你自己的版本？

如果你想创建一个类似的AI对话应用（比如“健身教练模拟器”、“留学顾问模拟器”），请遵循以下安全路径：

**第一步：保持结构不变，替换使用场景（最安全）**
- **不要动HTML/CSS结构**：页面的布局（配置区、聊天区、侧边栏）是通用的。
- **只改文字**：把“面试职位”改成“健身目标”（增肌、减脂、塑形），把“公司类型”改成“训练场所”（健身房、居家、户外），把“面试风格”改成“教练风格”（严厉、鼓励、科学）。
- **此时功能完全一样**，只是主题变了。这是建立信心的关键一步。

**第二步：调整输入字段或Prompt**
- **增加/减少配置项**：如果你的场景不需要“工作经验”，就删掉这个下拉菜单，并在生成Prompt时不再包含这个变量。
- **重写Prompt模板**：在`callAPI`函数中，把关于面试的指令，改成关于你的新场景的指令。例如，把“你是一个专业的面试官”改成“你是一个专业的私人健身教练”。
- **修改评估维度**：在侧边栏和Prompt中，把“专业知识、沟通表达”改成“动作标准度、耐力表现、计划完成度”。

**第三步：改变输出形式或展示方式**
- **微调UI**：改变颜色主题（把紫色渐变换成橙色，更适合运动主题）。
- **丰富结果展示**：在最终报告里，除了文字，是否可以生成一个简单的“每周训练计划表”？
- **这一步可以慢慢来**，先确保核心的对话流程跑通。

**从哪里下手最安全？**
从**第二步的“重写Prompt模板”** 开始。因为：
1. 它不涉及复杂的HTML/CSS修改。
2. 效果立竿见影，你立刻能看到AI以新角色和你对话。
3. 即使写错了，也很容易回退或调整。

## 【六】3–5 个可直接尝试的改造方向

1. **增加语音输入/输出功能**
   - **怎么做**：使用浏览器的`Web Speech API`（`SpeechRecognition`和`SpeechSynthesis`）。
   - **具体操作**：在回答文本框旁增加一个麦克风按钮，点击后录制语音并转换成文字发送。同时，可以增加一个开关，让AI的回答以语音形式读出。
   - **价值**：让模拟面试更真实，同时练习口语表达。

2. **引入“题库”与“自由对话”混合模式**
   - **怎么做**：在配置阶段增加一个选项“问题来源：AI生成 / 从题库选择 / 混合模式”。
   - **具体操作**：在代码中预置一个常见面试问题库（JSON格式）。如果选择题库，则从库中随机抽取问题，但AI仍然负责根据你的回答生成反馈和后续问题。
   - **价值**：确保问题更标准、更贴近真实面试，避免AI偶尔生成奇怪的问题。

3. **将单次面试拆分为“准备-模拟-复盘”多页面流程**
   - **怎么做**：创建多个HTML页面或用`display:none/block`切换视图。
   - **具体操作**：
     - **准备页**：引导用户填写简历要点或技能清单。
     - **模拟页**：就是现在的页面。
     - **复盘页**：更强大的报告，支持将本次面试记录导出为PDF，或与历史记录对比成长曲线。
   - **价值**：用户体验更完整，更像一个系统的培训工具。

4. **优化交互：增加“示例回答”和“回答记录本”**
   - **怎么做**：在用户卡顿时，除了“提示”，可以增加一个“查看示例”按钮，展示一个该问题的优秀回答范例（可来自内置题库）。同时，在侧边栏增加一个“记录本”区域，自动摘录用户自认为精彩的回答，方便面试后回顾。
   - **价值**：学习性更强，不仅是被评估，还能主动学习优秀答案。

5. **更换或扩展API后端**
   - **怎么做**：修改`callAPI`函数，支持多个AI服务商。
   - **具体操作**：在设置面板增加“服务商”选项（DeepSeek、OpenAI、智谱AI等），根据选择切换请求的URL、头部信息和参数格式。甚至可以设计一个“降级策略”，当主API调用失败时，自动尝试备用API。
   - **价值**：提升工具的可靠性和灵活性，不受单一服务商限制。

## 【七】这个网页不适合做什么？（边界提醒）

1. **不适合作为真实招聘的决策工具**
   - **局限性**：AI的评分基于文本模式和常见标准，无法像人类HR一样进行综合、感性的判断，也无法识别简历造假或深入核实项目细节。
   - **应该怎么做**：真实的公司招聘，请务必结合真人面试、背景调查和实操测试。

2. **不适合练习高度复杂的专业领域或前沿技术**
   - **局限性**：AI的知识有截止日期，且可能无法理解非常小众或最新的技术框架、学术理论。
   - **应该怎么做**：准备此类面试，应查阅最新的官方文档、技术博客，并在专业社区（如Stack Overflow、GitHub）与同行交流。

3. **不适合模拟压力面试或非常规面试形式**
   - **局限性**：当前的模拟是基于有序的问答。它无法模拟群面、无领导小组讨论、现场白板编程、长时间高压追问等场景。
   - **应该怎么做**：寻找专门的模拟面试工作坊、使用支持多人视频的会议软件与朋友练习，或参加企业开放的模拟面试活动。

4. **不适合完全替代人际沟通练习**
   - **局限性**：你面对的是一个文本接口，无法练习眼神交流、微笑、握手、坐姿等非语言沟通技巧，也无法感受真实的人际互动张力。
   - **应该怎么做**：将其作为补充工具，最重要的练习仍然是和真人（朋友、导师、职业顾问）进行角色扮演。

**总结**：把这个网页看作一位**7x24小时在线的、耐心的初级陪练员**。它能帮你熟悉流程、打磨话术、建立信心。但通往顶尖选手的道路，还需要更高级的教练（真人指导）和更真实的赛场（实战经验）。
