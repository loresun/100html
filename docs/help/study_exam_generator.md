# AI 试题生成器 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

想象一下，你正在准备一个考试，或者想测试自己对某个知识点的掌握程度。你需要一套练习题，但手头没有现成的资料，或者现有的题目不够有针对性。这个网页就像一个**随身的出题老师**，你只需要告诉它你想练习什么、要多少题、难度如何，它就能在几秒钟内为你生成一套完整的、可以立即作答并自动评分的试卷。

**适合的使用场景：**
- 学生考前自主复习，快速生成针对特定知识点的练习题。
- 老师或培训师需要为不同水平的学生准备差异化练习材料。
- 任何学习者想检验自己对一个新概念（如“英语时态”、“机器学习基础”）的理解。

**不适合的情况：**
- 需要高度专业化、依赖特定教材或考纲的题目。
- 需要主观题（如论述、作文）的评估。
- 需要保证题目100%准确无误、且经过权威认证的正式考试场景。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要填写三个核心信息：
1.  **学习领域**：你想练习的主题，比如“英语时态”、“Python列表操作”、“中国近代史”。
2.  **难度**：从“基础”、“进阶”、“高阶”中选择。
3.  **题量**：想生成多少道题（3-10道）。

**用户通常会做哪几步操作？**
1.  **配置**：首次使用，点击右上角“API 设置”，输入你的 DeepSeek API Key 并选择模型（V3或O1），然后保存。
2.  **生成**：填写好“学习领域”、“难度”、“题量”后，点击“生成试卷”按钮。
3.  **作答**：等待几秒后，题目会显示出来。在每个题目下方，点击你认为正确的选项。
4.  **评分**：所有题目答完后，点击页面底部的“自动评分”按钮，系统会立刻给出分数和每道题的解析。

**输出结果长什么样？**
输出是一份清晰、美观的电子试卷。每道题包括：
- 醒目的题号。
- 清晰的题干。
- 四个选项，每个选项在一个可点击的卡片中。
- 评分后，会显示“回答正确/错误”，并给出正确答案和详细的解析。

**有哪些容易忽略的使用细节？**
- **API Key 是必须的**：不配置 API Key，页面无法工作。它被安全地保存在你的浏览器本地。
- **输入要具体**：“学习领域”越具体（如“英语现在完成时” vs “英语”），生成的题目质量通常越高。
- **模型切换**：右上角的 V3 和 O1 按钮可以切换 AI 模型。O1 推理能力更强，但生成速度可能稍慢，成本也可能不同。
- **答案保存在本地**：刷新页面后，你生成的题目和选择的答案会消失，需要重新生成。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个功能模块：

1.  **控制面板模块**
    *   **职责**：接收用户的出题指令。它包含了三个输入框（主题、难度、题量）和一个“生成”按钮。
    *   **逻辑**：用户在此设定需求 → 点击按钮 → 触发 `generate` 函数，将参数组合成 Prompt 发送给 AI。

2.  **试题展示与交互模块**
    *   **职责**：动态渲染 AI 返回的题目，并提供答题界面。这是页面的主体。
    *   **逻辑**：AI 返回 JSON 数据 → 被 `questions` 数组接收 → Alpine.js 的 `x-for` 指令循环生成每一道题的 HTML 结构 → 用户点击选项，答案被记录在 `answers` 对象中。

3.  **评分与反馈模块**
    *   **职责**：计算分数并展示结果。位于页面底部。
    *   **逻辑**：用户点击“自动评分” → 触发 `calculate` 函数 → 遍历 `answers` 和 `questions`，比对答案 → 更新 `score` 并显示每道题的解析。

4.  **配置管理模块**
    *   **职责**：管理 API 密钥和模型选择。通过一个弹出窗口实现。
    *   **逻辑**：配置信息被保存在浏览器的 `localStorage` 中（通过 `study-shared.js`），每次调用 AI 时读取使用。

**最值得学习的设计：前后端职责分离与状态驱动视图**
这个网页最巧妙的地方在于，它**没有自己的服务器**，却实现了完整的应用逻辑。其核心是：
*   **前端（本页面）** 负责：收集用户输入、构建清晰的 Prompt、管理答题状态、渲染漂亮的界面、处理评分逻辑。
*   **后端（AI API）** 负责：理解 Prompt、运用知识、生成结构化的题目数据。
*   **状态驱动**：所有动态内容（题目、答案、分数、加载状态）都绑定在 Alpine.js 组件的状态变量（如 `questions`, `answers`, `isLoading`）上。状态一变，页面自动更新。这是一种非常现代且高效的前端开发模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接用户意图和 AI 能力的**精确指令说明书**。它把用户模糊的“帮我出几道题”的想法，翻译成 AI 能够严格执行的、格式化的生产任务。

**它解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**，但也包含了“理解”的部分。AI 需要理解“英语时态”、“基础难度”这些概念，但其核心任务是按照严格的格式要求（JSON、4个选项、包含解析）去创造内容。

**哪些信息是 Prompt 中的关键变量？**
Prompt 是一个模板字符串，其中 `${this.topic}`, `${this.count}`, `${this.level}` 是三个**关键变量**，它们直接来自用户的输入。改变它们，就改变了 AI 生成内容的方向。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个应用的功能，而无需改动一行 HTML 或 JS 逻辑。例如：
*   把“生成选择题”的指令改成“生成填空题”，AI 就会开始生成填空题。
*   在要求里加上“选项不能超过15个字”，生成的选项就会更简洁。
*   把输出格式从 JSON 改成 Markdown 列表，页面就会显示乱码（因为代码期望解析 JSON）。所以，**Prompt 的修改必须与代码中解析数据的部分相匹配**。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的 AI 小工具：

**第一步：替换核心场景与输入（最安全）**
保持所有代码结构不变，只修改文字和输入字段。例如，做一个“AI 周报生成器”：
*   将“学习领域”标签改为“本周工作内容”。
*   将“难度”标签和选项改为“汇报风格”（如：简洁、详细、数据驱动）。
*   将“题量”改为“要点数量”。
*   相应地修改页面标题和提示文字。

**第二步：重构 Prompt 以匹配新场景**
在 `generate` 函数中，重写 Prompt 模板。例如：
`请根据以下内容：“${this.workContent}”，生成一份 ${this.style} 风格的工作周报，包含 ${this.count} 个核心要点。要求返回 JSON 格式...`
这是应用转型的关键一步，决定了 AI 产出什么。

**第三步：调整输出展示方式**
根据新 Prompt 返回的数据结构，修改试题展示模块的模板。如果 AI 返回的是 `{“summary”: “...”, “keyPoints”: [...]}`，你就需要把渲染题目和选项的代码，改成渲染摘要和要点列表。
*先确保你能在控制台正确收到并解析新格式的 AI 回复，再动手改页面。*

## 【六】3–5 个可直接尝试的改造方向

1.  **增加题目类型选择**：在控制面板增加一个“题型”下拉菜单（如：选择题、判断题、连线题）。在 Prompt 中增加对应变量，并让 AI 根据题型生成不同格式的题目。这是对核心功能的直接增强。
2.  **持久化试卷与历史记录**：利用 `localStorage` 或 `IndexedDB`，将每次生成的试卷和答案保存下来。可以增加一个“历史试卷”侧边栏，方便用户回顾错题。这能极大提升工具实用性。
3.  **优化交互体验**：
    *   **逐题验证**：用户每选一个答案，立即显示对错和解析，无需等待全部答完再评分。
    *   **计时功能**：增加一个倒计时器，模拟真实考试环境。
    *   **语音读题**：利用浏览器的 Web Speech API，为题目添加“朗读”按钮，辅助学习。
4.  **切换或扩展 AI 服务**：代码中 AI 调用逻辑封装在 `studyShared.callLLM` 中。你可以修改这个共享模块，使其支持 OpenAI、Claude 或智谱 AI 等不同供应商的 API，并在设置面板中让用户选择。
5.  **拆分为多步骤向导**：将当前的单页应用，拆分成“配置 -> 生成 -> 答题 -> 复盘”多个页面。这更适合题目数量多、流程复杂的场景，可以利用浏览器路由（如 Vue Router, React Router）来实现。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为权威评估工具**：AI 生成的题目和答案可能存在事实性错误、歧义或偏见。它本质是一个**辅助练习和启发思考的工具**，不能替代教科书、权威题库或老师的专业判断。
2.  **不适合处理高度动态或私密数据**：所有数据（你的 API Key 除外）都在浏览器前端处理，并与 AI 公司的服务器通信。**切勿输入个人隐私信息、公司机密或实时性极强的数据**到“学习领域”中。
3.  **不适合完全离线的环境**：它的核心功能依赖网络 API 调用。没有网络，就无法生成新题目。
4.  **如果需要更复杂的逻辑（如智能组卷、知识图谱关联）**：这个工具是“描述即生成”的模式。如果你需要根据用户答题情况动态调整下一题难度（自适应测试），或者从庞大的题库中按知识点权重抽题，你需要设计更复杂的后端逻辑和数据库，这超出了当前前端单页应用的范畴。

**总结**：这个网页是一个出色的范例，展示了如何用最精简的代码（纯前端）结合强大的 AI API，快速构建一个有用、易用且美观的交互式应用。理解它的模块化设计和“状态-Prompt-视图”的协作流程，是你构建更多类似创意工具的关键。
