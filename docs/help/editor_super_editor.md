# 超级编校编辑器 - 学习指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景：**
当你有一份需要优化、润色或整理的文档（如工作报告、学术草稿、博客文章、翻译稿）时，这个工具可以帮你快速完成“编校”工作。它特别适合处理那些你感觉“意思到了，但表达不够好”的文本。

**适合什么情况？**
- **内容润色：** 想让文章更流畅、专业、有逻辑。
- **长文档处理：** 需要分段处理几千字的长文，避免一次性发送给AI导致效果不佳或超限。
- **对比学习：** 想直观看到AI具体修改了哪些地方，学习更好的表达方式。
- **快速摘要：** 需要从长文中提取核心要点和摘要。

**不适合什么情况？**
- **创作全新内容：** 它主要优化已有文本，而不是从零开始生成故事或创意。
- **高度专业或格式化的文本：** 如法律合同、程序代码、数学公式，AI可能无法准确理解专业规则。
- **要求100%准确无误的场景：** AI编校结果仍需人工最终审核，不能完全替代专业编辑。

## 【二】使用方式（给第一次接触的人）

**1. 页面输入是什么？**
- **你的文档：** 可以直接在文本框粘贴，或上传 `.txt`、`.md` 或 `.docx` 文件。
- **你的要求：** 在“编校配置”中，告诉AI你想怎么改（例如：“修正语法，让语气更正式”）。

**2. 用户通常会做哪几步操作？**
1.  **准备内容：** 粘贴或上传你的文档。
2.  **（可选）拆分段落：** 点击“自动拆分段落”，系统会把长文档切成适合AI处理的小块。
3.  **设置要求：** 点击右上角“API设置”，填入你的DeepSeek API Key，并选择或编写“编校提示词”（比如选择“文字润色”预设）。
4.  **开始编校：**
    - **短文档（<1000字）：** 直接点“全文编校”。
    - **长文档：** 点“分段编校”，系统会逐段或并行处理。
5.  **查看与导出：**
    - 在右侧对比“原文”和“编校稿”。
    - 点击“生成差异对比”，高亮显示所有修改。
    - 满意后点击“下载编校版本”。

**3. 输出结果长什么样？**
- **编校稿：** 一个优化后的完整文本，显示在右侧“编校稿”区域。
- **差异对比：** 绿色高亮是新增或修改的文本，红色带删除线的是被删减的文本。
- **压缩摘要：** 在左侧面板，生成一段摘要和几个要点。
- **逐段结果：** 可以看到每一小段原文和AI修改后的样子。

**4. 有哪些容易忽略的使用细节？**
- **API Key是必须的：** 第一次使用一定要点“API设置”填入，否则所有功能都无法工作。
- **分段模式的选择：**
    - **顺序模式：** 适合小说、论述文等需要前后呼应的文章，AI会参考前面已修改的内容。
    - **并行模式：** 适合段落独立的清单、报告，速度更快。
- **字数提示：** 如果文档很长却点了“全文编校”，系统会弹出警告，建议你改用“分段编校”。
- **配置会保存：** 设置好的API Key和提示词会保存在浏览器里，下次打开还在。

## 【三】核心结构拆解（学习重点）

这个页面可以看作一个 **“文档处理流水线”** ，由几个清晰模块组成：

**1. 输入与预处理模块（左侧面板）**
- **职责：** 接收原始文档，并为其“加工”做好准备。
- **包含：** 文件上传、内容预览、自动拆分段落、内容压缩提取。
- **关键设计：** “自动拆分段落”不是简单按字数切割，而是先按自然段落（双换行）分，再智能合并，保证每个部分语义完整。

**2. AI编校控制中心（中间顶部面板）**
- **职责：** 这是整个工具的“大脑”，指挥AI如何工作。
- **包含：** 编校模式选择、进度条、当前提示词预览、各种操作按钮。
- **关键设计：** 将“全文处理”和“分段处理”明确分开，并给出适用场景提示，防止用户误用。

**3. 结果展示与对比模块（右侧及下方面板）**
- **职责：** 多维度呈现AI的工作成果，方便用户评估。
- **包含：** 原文/编校稿并排对比、逐段编校详情、高亮差异对比。
- **关键设计：** **“差异对比”功能**，使用`diff-match-patch`库生成直观的修改痕迹，这是学习和理解AI修改思路的利器。

**4. 配置管理模块（设置弹窗）**
- **职责：** 管理所有“魔法参数”，让工具变得灵活。
- **包含：** API密钥、模型选择、分段字数、编校模式、核心提示词。
- **关键设计：** 提供**预设提示词**，让非技术用户也能快速选择常见任务（润色、逻辑梳理等）。

**逻辑链路：**
```
输入文档 → 预处理（拆分/预览） → 用户设定编校要求 → AI按模式处理 → 输出编校稿 → 生成差异对比 → 导出结果
```

**最值得学习的设计：**
**“分段编校的上下文机制”**。当处理长文档时，AI不是孤立地看某一段，而是会看到“上一段+当前段+下一段”作为上下文。这保证了编校后的段落依然能和前后文连贯，避免了“段段优秀，拼起来别扭”的问题。这是处理长文本的核心思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

**1. Prompt扮演的角色：**
在这里，Prompt是 **“编校任务说明书”** 。它不负责理解文档内容（那是AI的基础能力），而是负责**定义“如何生成”编校后的文本**，即提出具体的修改要求和规则。

**2. 解决的是“生成问题”：**
它明确告诉AI：“请你扮演资深编校专家，按照XXX要求（如修正语法、统一术语），对下面这段文字进行编校，并且只输出结果，不要加解释。” 这解决了“让AI按照特定风格和规则生成文本”的问题。

**3. Prompt中的关键变量：**
- **核心要求 (`corePrompt`):** 用户自定义的编校指令，是Prompt的灵魂。
- **上下文文本:** 在分段编校时，自动插入的“上文参考”和“下文参考”。
- **输出格式指令:** 严格规定“仅输出编校后的内容”，防止AI返回多余信息。

**4. 如果只改Prompt，不改代码，会发生什么？**
整个工具的行为会发生**根本性变化**。例如：
- 将Prompt从“文字润色”改为“翻译成英文”，工具就变成了**翻译器**。
- 改为“提取所有行动项并生成待办清单”，工具就变成了**会议纪要分析器**。
- 改为“用幽默风趣的网络语言重写”，工具就变成了**风格转换器**。
**代码提供管道，Prompt决定管道里流什么水。** 这是本工具设计最精妙的地方，也是你未来模仿和改造的突破口。

## 【五】如何模仿它，做出你自己的版本？

如果你想做一个类似工具，但用于其他场景（如AI客服话术优化、短视频脚本润色），请遵循以下安全路径：

**第一步：替换使用场景和界面文案（最安全）**
- 保持所有代码结构、模块布局完全不变。
- 只修改文字：把“超级编校编辑器”改成你的工具名（如“短视频脚本优化器”）。
- 修改各模块的标题和说明文字，使其符合你的新场景。

**第二步：调整输入字段和Prompt预设**
- 在“配置管理模块”中，修改 `promptPresets` 数组。把你的新场景的典型任务写成预设Prompt。
    - 例如，对于脚本优化器，预设可以是：“节奏感优化”、“反转悬念强化”、“口语化改写”。
- 可以微调输入框的提示语，如把“粘贴文档...”改为“粘贴脚本...”。

**第三步：改变输出形式或展示方式**
- 如果新场景需要不同的结果展示，可以修改“结果展示模块”。
- 例如，对于脚本优化，除了并排对比，可以增加一个“分镜/节奏标记”的预览区域。
- 这一步改动较大，建议在前两步成功运行后再尝试。

**从哪里下手最安全？**
**直接从修改 `promptPresets` 开始。** 这是零风险、高回报的改动。你立刻就能得到一个行为完全不同但运行稳定的新工具。例如，仅仅把预设改成针对代码注释、英文邮件或小红书文案的优化，你就拥有了三个新工具。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加风格/角色预设：**
    - **操作：** 在 `promptPresets` 数组中新增选项，如“科技媒体风格”、“政府公文风格”、“幼儿园老师讲故事风格”。
    - **效果：** 用户一键切换，让同一份内容拥有不同风格的版本，工具适用性大增。

2.  **接入多模型API，实现“专家会诊”：**
    - **操作：** 在API设置中增加模型选择（如OpenAI GPT-4o、Claude、智谱GLM）。在后台，将同一段文本用不同模型编校，然后把结果并列展示给用户。
    - **效果：** 用户可以看到不同AI的修改偏好，博采众长，选择最满意的一版。

3.  **拆分为“工作流”页面：**
    - **操作：** 将当前单页面的功能拆成三步向导页：
        1.  **上传与分析页：** 只负责导入和智能分段。
        2.  **编校配置页：** 专注于选择风格、模型等参数。
        3.  **结果审阅页：** 专注于对比、差异查看和导出。
    - **效果：** 用户体验更专注，尤其适合复杂的多步骤任务。

4.  **增加“自定义词典”或“术语库”功能：**
    - **操作：** 在设置中增加一个文本框，让用户输入“必须保留的术语”（如公司名、产品名、特定缩写）或“替换词典”（如“手机”一律改为“智能手机”）。
    - **效果：** 将这些信息动态插入到发送给AI的Prompt中，确保编校不改变关键术语，专业性更强。

5.  **优化交互体验：**
    - **操作：** 在“逐段编校结果”模块，为每一段增加“采纳”、“拒绝”、“手动编辑”按钮。用户点击“采纳”，该段编校稿才会最终合并；点击“拒绝”则保留原文；点击“编辑”可弹出小文本框微调。
    - **效果：** 将工具从“全自动”升级为“人机协同”，给予用户最终控制权，结果质量更高。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做事实核查或信息验证：**
    - **局限性：** AI可能会润色一段包含错误事实的文字，让它读起来更可信，但不会去验证事实本身。
    - **应该怎么做：** 对于新闻稿、学术论文等，编校后务必由人工进行事实核对。

2.  **不适合处理高度结构化或格式敏感的内容：**
    - **局限性：** 对于表格、复杂列表、特定缩进格式的代码，AI可能在编校过程中破坏原有结构。
    - **应该怎么做：** 使用专门的表格处理工具或代码格式化工具。

3.  **不适合作为最终发布前的唯一检查：**
    - **局限性：** AI可能会遗漏一些细微的语境错误，或产生不符合本地文化习惯的表达。
    - **应该怎么做：** 将其作为强大的“初稿优化助手”，但重要文档的终审必须由真人完成。

4.  **不适合完全创造性的写作：**
    - **局限性：** 它的核心是“优化”而非“创造”。如果你给它的原文质量极差或信息量极少，它很难生成精彩的全新内容。
    - **应该怎么做：** 对于从零开始的创作，应使用侧重于“生成”的AI工具，或采用“先生成大纲/初稿，再使用本工具优化”的组合流程。

**记住：这个工具是你写作过程中的“副驾驶”，能极大提升效率和质量，但“方向盘”和最终目的地，始终应该掌握在你自己手中。**
