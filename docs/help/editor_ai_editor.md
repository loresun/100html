# AI 智能编辑器 - 帮助文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你正在写一篇文章、报告或邮件，突然卡住了：
- 某段话感觉不够流畅，但不知道怎么改
- 写到一半，不知道接下来该写什么
- 想让语言更生动、更专业，但自己改起来很费劲

这个网页就是你的“AI 写作搭档”。它在你写作时随时待命：
- **选中一段文字** → AI 帮你改写、润色、翻译
- **按 Tab 键** → AI 帮你自动续写下一句
- **所有修改都有记录** → 随时可以查看和对比

**适合的场景：**
- 写作时遇到瓶颈，需要灵感或润色
- 需要快速修改邮件、报告的语言风格
- 学习如何用不同方式表达同一内容

**不适合的场景：**
- 需要生成整篇长文（它更适合“边写边改”）
- 需要严格的格式排版（如论文、简历）
- 需要多人协作编辑

## 【二】使用方式（给第一次接触的人）

### 1. 准备工作
- 打开页面后，点击右上角 **“API 设置”**
- 输入你的 DeepSeek API Key（需要先注册获取）
- 点击保存

### 2. 开始写作
- 在中间的大白框中直接打字或粘贴文字
- 这就是你的“编辑器”，像使用 Word 一样简单

### 3. 核心操作（两种方式）

**方式一：修改选中文字**
1. 用鼠标选中一段你想修改的文字
2. 会自动弹出一个小浮窗
3. 在浮窗中输入你的要求，比如：“让这段话更简洁”
4. 点击发送或按 Enter
5. AI 会立即修改选中的文字，并用蓝色高亮显示

**方式二：自动续写**
1. 把光标放在你想继续写的位置
2. 直接按 **Tab 键**
3. AI 会根据上下文自动续写下一句/段
4. 新内容会用绿色高亮显示

### 4. 查看结果
- 右侧边栏会记录**每一次修改**
- 可以看到：修改前 vs 修改后
- 如果用了“Reasoner”模型，还能看到 AI 的思考过程

### 5. 容易忽略的细节
- **高亮会慢慢消失**：AI 修改的内容会高亮 2 秒后淡出，这是为了不干扰阅读
- **预设指令**：浮窗下方有快捷按钮，比如“润色一下”，点一下就不用打字了
- **模型切换**：右上角可以切换“Chat”和“Reasoner”，后者会显示思考过程但稍慢
- **内容自动保存**：关掉页面再打开，你的文章还在

## 【三】核心结构拆解（学习重点）

这个页面由 **4 个核心模块** 组成：

### 模块 1：可编辑区域（Editor）
- **职责**：用户输入和显示文章内容
- **特点**：使用 `contenteditable="true"` 让整个区域变成“富文本编辑器”
- **关键设计**：监听用户的“选中文本”动作，这是触发 AI 帮助的起点

### 模块 2：浮窗控制器（Popup Controller）
- **职责**：在用户选中文字时，精准弹出修改窗口
- **工作流程**：
  1. 用户选中文字 → 获取选中位置坐标
  2. 在选中文字正下方弹出小窗口
  3. 自动聚焦到输入框，让用户直接打字
- **最值得学习的设计**：`getBoundingClientRect()` 获取精确位置 + Vue 的 `transition` 动画，体验非常流畅

### 模块 3：AI 处理器（AI Processor）
- **职责**：调用 API 并处理返回结果
- **输入 → 处理 → 输出** 链路：
  ```
  用户输入 + 选中文字 + 上下文
        ↓
  组装成 Prompt（系统指令 + 用户需求）
        ↓
  调用 DeepSeek API（支持流式返回）
        ↓
  实时显示结果（边生成边显示）
        ↓
  插入到编辑器中，并添加高亮动画
  ```
- **关键技巧**：不仅传选中文字，还传了“前后 500 字”作为上下文，让 AI 理解文章整体

### 模块 4：历史记录器（History Tracker）
- **职责**：记录每一次修改，支持“时光机”查看
- **数据结构**：每个记录包含 {类型, 原文, 修改后, 用户指令, 时间戳, AI思考过程}
- **存储**：用 `localStorage` 保存在浏览器本地

**最值得学习的设计**：
整个页面的“状态管理”非常清晰：
- 用户操作（选中/按键）→ 触发事件 → 更新状态 → 更新 UI
- 所有数据（文章、历史、配置）都自动保存到本地
- 修改时的“高亮淡出”动画，既提示了修改位置，又不干扰后续阅读

## 【四】Prompt / AI 逻辑是如何被设计的？

### 1. Prompt 扮演的角色
在这个页面中，Prompt 是 **“翻译官”**：
- 把用户的简单指令（如“润色一下”）翻译成 AI 能理解的详细任务
- 把编辑器的复杂状态（选中文字+上下文）打包成 AI 需要的格式

### 2. 解决的是“理解问题”
核心挑战：如何让 AI 知道“只修改选中部分，不要动其他内容”？
解决方案是通过 Prompt 明确划定边界：
```
【全文上下文参考】：（前后500字）
【当前选中文本】：（用户选中的）
【修改需求】：（用户输入的）
请修改【当前选中文本】：
```

### 3. Prompt 中的关键变量
- **系统指令**：定义 AI 的角色和行为约束（如“只输出修改后的选中部分”）
- **上下文窗口**：前后各 500 字，让 AI 保持风格一致
- **用户需求**：用户输入的修改指令
- **模型标记**：区分是“改写”还是“续写”任务

### 4. 如果只改 Prompt，不改代码
- **改系统指令**：比如从“文章编辑助手”改成“代码审查助手”，AI 就会用程序员口吻提建议
- **改输出限制**：去掉“只输出修改部分”，AI 可能会返回整段重写的文章
- **改上下文长度**：减少到 100 字，AI 可能忽略文章整体风格

**实验建议**：在“预设配置”里修改“Tab 续写提示词”，体验 Prompt 如何影响生成风格。

## 【五】如何模仿它，做出你自己的版本？

### 安全起步路径：

**第一步：替换场景，保持骨架**
- 保持所有代码结构不变
- 只改文字：把“文章编辑”改成你的场景，比如“代码注释生成器”、“邮件助手”
- 改预设指令：换成你场景的常用指令，如“添加注释”、“改成正式语气”

**第二步：调整输入字段**
- 在浮窗输入框上方增加“下拉菜单”，让用户选择修改类型（如：风格、长度、语言）
- 或增加“滑块”控制生成长度
- **关键**：只改 Vue 模板中的表单部分，不动核心逻辑

**第三步：改变输出形式**
- 当前是“直接替换选中文字”，你可以改成：
  - 在旁边显示建议（不直接修改原文）
  - 提供多个版本让用户选择
  - 用不同颜色区分不同类型的修改
- **关键**：修改 `submitModification` 函数末尾的 DOM 操作部分

**最安全的下手点**：
从 `presets` 数组开始改！这是纯数据修改，不会破坏任何功能。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加“多版本建议”
**当前**：AI 只给一个修改版本
**改造**：让 AI 生成 3 个不同风格的版本，用小卡片并列显示，让用户点击选择
**代码提示**：修改 `callDeepSeek` 的 Prompt，要求“提供3个版本”，然后修改结果显示逻辑

### 2. 支持“自定义快捷键”
**当前**：只有 Tab 键触发续写
**改造**：让用户自定义快捷键，比如 Ctrl+B 触发“简化”、Ctrl+I 触发“扩写”
**代码提示**：在设置面板增加快捷键配置，修改 `handleKeyUp` 函数

### 3. 添加“风格模板”
**当前**：用户需要自己描述需求（如“更正式”）
**改造**：增加风格预设按钮：“商务风”、“小红书体”、“知乎体”、“科技报道”
**代码提示**：每个风格对应一个预设 Prompt，点击时替换浮窗中的输入内容

### 4. 实现“真正的撤销/重做”
**当前**：历史记录只能查看，不能一键还原
**改造**：点击历史记录时，直接替换编辑器中的对应内容
**代码提示**：需要记录每次修改的“位置信息”，实现时较复杂，可作为进阶挑战

### 5. 支持“多模型切换”
**当前**：只支持 DeepSeek
**改造**：增加 OpenAI、Claude、智谱等模型选项
**代码提示**：修改 `callDeepSeek` 函数为通用 `callAI`，根据选择调用不同 API

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性说明：

1. **不是“全文生成器”**
   - 如果你需要从零生成一篇长文，应该用专门的 AI 写作工具
   - 这个工具的核心价值是“修改和续写”，不是“从头创作”

2. **没有格式排版功能**
   - 无法处理复杂排版：表格、页眉页脚、目录
   - 如果需要生成格式规范的文档（如论文、报告），应该用 Word + AI 插件

3. **本地存储的风险**
   - 所有内容都存在你的浏览器里，换电脑或清缓存就没了
   - 重要文档请定期复制保存到其他地方

4. **无法处理专业领域内容**
   - 虽然可以修改文字，但对法律、医学等专业内容可能给出错误建议
   - 专业文档请务必由人类专家审核

### 如果用户想做 X，应该换什么：

- **想多人协作编辑** → 用 Notion、语雀的协作功能
- **需要严格版本控制** → 用 Git 管理文本文件
- **批量处理多篇文章** → 用 Python 脚本调用 API
- **离线使用** → 需要部署本地大模型版本
