# 指标异常检测 + 解读 - 帮助文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一名运营人员或数据分析师，每天都要盯着各种业务数据报表（比如网站访问量、销售额、服务器负载）。数据量一大，光靠人眼很难快速发现哪些数据点“不对劲”。这个网页就是你的**数据异常哨兵**。

**适合的使用场景：**
- **日常数据巡检**：每天导入一份简单的 CSV 数据，快速扫描有无异常波动。
- **临时数据排查**：收到同事发来的数据片段，想立刻知道有没有问题点。
- **报告辅助**：在制作数据报告时，需要为图表中的异常点附上通俗易懂的解释。

**不适合的情况：**
- **需要实时监控**：它是一次性分析工具，不是持续监控的仪表盘。
- **处理复杂多维数据**：它目前只处理“日期+一个指标”的简单二维数据。
- **进行深度统计分析**：它的异常检测算法（基于标准差）比较简单，不适合金融风控等需要高精度模型的场景。

## 【二】使用方式（给第一次接触的人）

**1. 页面输入是什么？**
- 一个简单的 CSV 格式文本。默认已经有一行示例数据。
- 格式是：第一行是表头（如“日期,指标”），下面每行是具体数据（如“2024-01-01,120”）。

**2. 用户通常会做哪几步操作？**
- **第一步：准备数据**。你可以直接修改文本框里的示例数据，或者粘贴你自己的数据（确保是 CSV 格式）。
- **第二步：配置 API**。首次使用需要点击右上角的齿轮图标，在弹出的窗口中输入你的 DeepSeek API Key 并保存。
- **第三步：点击“检测异常”**。页面会开始处理。
- **第四步：查看结果**。左侧会生成折线图，异常点会用更显眼的红点标出；右侧的“AI 解读”区域会生成一段文字，解释异常可能的原因。

**3. 输出结果长什么样？**
- **左侧图表**：一条折线显示数据趋势。如果某个数据点被判定为异常，它会变成一个更大的、颜色更深的红点。
- **右侧解读**：一段由 AI 生成的文字，例如：“1月2日的指标值（300）显著高于平均水平。可能原因是当日有促销活动或外部流量引入。建议核查当日运营动作，并关注后续是否回落。”

**4. 有哪些容易忽略的使用细节？**
- **API Key 是必须的**：不配置就无法获得 AI 解读，但图表仍然会生成。
- **数据格式要严格**：表头和数据之间不能有空行，数据值最好是数字。
- **解读是“生成”的**：AI 的解释是基于你给的数据和简单的异常标记推理出来的，不一定100%准确，需要你结合业务知识判断。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块，像一个流水线：

**模块一：数据输入与处理模块**
- **职责**：接收用户输入的原始 CSV 文本，并将其解析成程序能理解的数据（日期列表和数值列表）。
- **关键动作**：`Papa.parse` 库负责解析 CSV，随后计算数据的平均值和标准差，并根据“偏离平均值超过1.3倍标准差”的规则标记异常点。
- **输入 → 处理 → 输出**：`原始CSV文本` → `解析、计算、标记` → `日期数组、数值数组、异常点布尔数组`。

**模块二：可视化模块**
- **职责**：将处理后的数据用图表直观地展示出来，并高亮异常点。
- **关键动作**：使用 Chart.js 库绘制折线图。在配置数据点时，根据“异常点布尔数组”来动态设置每个点的颜色和大小，让异常点更醒目。
- **最值得学习的设计**：**数据与样式的绑定**。它没有单独去画异常点，而是通过修改同一个数据序列中每个点的样式属性来实现高亮。这是一种高效且优雅的数据可视化思路。

**模块三：AI 解读生成模块**
- **职责**：将数据、异常点信息打包成一个问题（Prompt），发送给 AI 模型，获取并展示解读文本。
- **关键动作**：构建一个清晰的 Prompt，包含数据字段、所有数值、被标记的异常值，然后调用 DeepSeek API。返回的结果直接显示在页面上。
- **输入 → 处理 → 输出**：`数据、异常值` → `构建Prompt、调用API` → `AI生成的解读文本`。

**逻辑链路全景：**
`用户输入CSV` → `解析并计算异常` → `同时进行`：
1.  `异常标记+数据` → `绘制图表`。
2.  `异常值+数据` → `构建Prompt` → `调用AI API` → `生成解读`。

## 【四】Prompt / AI 逻辑是如何被设计的？

**1. Prompt 扮演的角色：**
Prompt 在这里是一个**任务指令单**。它把枯燥的数据（数值、异常点）转换成一个 AI 能够理解和回答的具体问题，引导 AI 扮演“数据分析师”的角色来生成解读。

**2. 解决的是“生成问题”：**
它主要解决“**生成**”问题。AI 并不需要“理解”复杂的异常检测算法（那是前端代码做的），它的任务是根据我们提供的“事实”（这些点异常了）和上下文，**生成一段符合人类阅读习惯的原因分析和建议**。

**3. Prompt 中的关键变量：**
- **`数据字段`**：告诉 AI 我们在分析什么（如“指标”）。
- **`数据`**：提供完整的数值序列，让 AI 了解整体情况。
- **`异常点`**：明确指出哪些值被标记为异常，这是 AI 进行分析的核心依据。
- **`指令`**：“请给出可能原因 + 建议，控制在 120 字以内。” 这限定了回答的格式和长度。

**4. 如果只改 Prompt，不改代码，会发生什么？**
- **改变回答风格**：把“数据分析师”改成“幽默的侦探”，AI 的解读语气会大变。
- **改变回答内容**：在指令里加上“请从技术、运营、市场三个角度分析”，AI 的回答结构会立刻调整。
- **改变回答深度**：去掉“120字以内”的限制，AI 可能会生成更冗长的分析。
- **注意**：Prompt 的改动不会影响异常检测的算法和图表展示，它只改变右侧的文本内容。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循这个“三步替换法”，风险最低，成功率最高：

**第一步：保持结构不变，替换使用场景**
- **目标**：先做出一个能跑通的、属于你自己的工具。
- **操作**：不要动任何代码逻辑。只修改以下内容：
    - 网页标题和描述（如改成“服务器负载异常分析器”）。
    - 输入框的默认示例数据（换成你的业务数据格式，如“时间,CPU使用率”）。
    - 图表标签和颜色（在 `chartInstance` 配置里修改 `label` 和 `borderColor`）。

**第二步：调整输入字段或 Prompt**
- **目标**：让工具更贴合你的具体需求。
- **操作**：
    - 如果数据格式固定，可以增加一个上传 CSV 文件的功能，替代文本框。
    - **重点修改 Prompt**：根据你的场景重写。例如，对于服务器监控，Prompt 可以是：“数据字段：CPU使用率。以下时间点的数值被检测为异常：[...]。请以运维工程师的身份，列出最可能的三种技术原因及紧急检查步骤。”

**第三步：改变输出形式或展示方式**
- **目标**：优化用户体验和结果呈现。
- **操作**：
    - 将 AI 解读从一段文本改为分点列表。
    - 在图表下方增加一个表格，详细列出每个异常点的数据、计算出的偏差值等。
    - 为“检测异常”按钮添加加载动画，提升交互反馈。

**从哪里下手最安全？**
从 **修改 Prompt** 和 **网页标题/文案** 开始。这完全不会影响程序运行，却能立刻让这个工具看起来像是为你量身定做的。接着可以尝试替换示例数据，最后再考虑改动图表样式。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加异常检测算法选项**：
    - **操作**：在设置面板里增加一个下拉菜单，让用户选择检测算法，如“标准差法（当前）”、“移动平均法”、“箱型图法（IQR）”。
    - **效果**：工具适应性更强，用户可以为不同类型的数据（平稳型、周期型）选择合适的方法。

2.  **允许批量上传或历史记录**：
    - **操作**：增加一个“上传CSV文件”的按钮。同时，将每次分析的数据和结果保存到浏览器的 `localStorage` 中，在侧边栏形成一个历史记录列表，方便回溯。
    - **效果**：提升处理真实数据文件的便利性，并支持简单的数据管理。

3.  **切换或兼容多个 AI 模型/API**：
    - **操作**：在 API 设置中，除了 DeepSeek，增加对 OpenAI GPT、通义千问等模型的支持。只需修改 `callLLM` 函数中的请求地址和参数格式。
    - **效果**：用户可以根据自己的账户和偏好选择不同的 AI 引擎，有时能获得不同风格的解读。

4.  **优化交互：一键复制与分享**：
    - **操作**：在 AI 解读框的右上角添加两个小图标按钮：“复制文本”和“生成分享链接”。复制功能可用 `navigator.clipboard.writeText` 实现；分享链接可以将当前数据和结果编码后生成一个 URL。
    - **效果**：极大方便了团队协作和报告整合。

5.  **从单指标扩展到多指标对比**：
    - **操作**：修改数据解析逻辑，允许 CSV 有多个指标列（如“日期,访问量,销售额,转化率”）。在图表中绘制多条折线，并为每条线独立检测异常。AI Prompt 也需要调整，让其能综合分析多个指标的异常关联。
    - **效果**：工具能力从“点分析”升级到“面分析”，能发现更复杂的关联异常。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做高精度、生产级的异常检测**：
    - **局限性**：其核心算法（1.3倍标准差）非常基础，在数据分布不均匀或有强烈趋势/季节性时，误报和漏报率会很高。
    - **应该怎么做**：如果需要用于正式业务监控，应使用更专业的时序数据库（如 InfluxDB）和异常检测算法库（如 Prophet、PyOD），或直接使用 Datadog、阿里云 SLS 等商业监控产品。

2.  **不适合处理非时序数据或复杂查询**：
    - **局限性**：它隐含假设第一列是时间/标签，第二列是数值。无法处理客户信息表、订单明细表等需要关联、筛选、聚合的数据。
    - **应该怎么做**：这类分析应使用专业的 BI 工具（如 Tableau、Power BI）或编写 Python 脚本进行。

3.  **不适合作为 AI 分析的唯一或最终依据**：
    - **局限性**：AI 的解读是基于有限信息的“合理推测”，并非事实诊断。它没有连接你的数据库、日志系统，也不知道业务背景。
    - **应该怎么做**：将 AI 解读视为一个“智能提示”或“分析起点”，必须由领域专家结合更多信息进行验证和决策。切勿完全自动化依赖其结论。
