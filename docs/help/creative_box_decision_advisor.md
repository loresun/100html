# AI 决策顾问 - 学习与改造指南

--------------------------------

## 【一】这个网页解决了什么问题？

这个网页解决的是**个人或团队在面临重要选择时，难以系统化、理性地分析不同选项**的问题。

**使用场景举例：**
- 你正在考虑是否要换工作，在几个offer间犹豫不决
- 团队需要决定下一个产品功能开发哪个方向
- 个人想投资理财，但不确定哪种方式更适合自己
- 面临多个居住城市的选择，每个都有优缺点

**适合的情况：**
- 需要权衡多个因素（如薪资、发展、风险、个人偏好）的复杂决策
- 希望获得结构化分析，而不是仅凭直觉
- 需要将模糊的“感觉”转化为可比较的量化数据

**不适合的情况：**
- 需要即时、快速决定的紧急情况
- 决策完全依赖精确数据计算（如财务投资回报率）
- 涉及高度专业领域、需要专家深度咨询的问题

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **决策难题**：用一句话描述你面临的选择困境
2. **备选方案**：列出2个或更多具体选项
3. **维度评分**：在AI建议的评估维度上，为每个方案打分

**用户通常会做哪几步操作？**
1. 在第一步输入你的决策难题（如“我应该买房还是继续租房？”）
2. 点击“下一步”，在第二步添加具体方案（如“方案一：购买XX小区二手房”、“方案二：续租当前公寓”）
3. 再次点击“下一步”，等待AI生成评估维度（如“资金压力”、“通勤便利”、“长期增值”等）
4. 为每个方案在各个维度上拖动滑块打分（1-10分）
5. 点击“请求AI分析”，等待生成报告

**输出结果长什么样？**
- **柱状图**：直观展示各方案综合得分对比
- **AI综合建议**：一段详细的文字分析，解释每个方案的优劣，并给出推荐理由

**有哪些容易忽略的使用细节？**
1. **API设置**：右上角齿轮图标可以配置AI服务，如果没设置过，第一次使用会提示
2. **方案数量**：可以点击“添加更多方案”增加选项，但建议控制在3-5个，太多会降低分析质量
3. **评分主观性**：打分完全基于你的个人判断，要诚实地反映你的真实偏好
4. **重新开始**：分析完成后，点击“重新开始”会刷新整个页面，之前的数据不会保存

## 【三】核心结构拆解（学习重点）

这个页面采用了经典的**向导式（Wizard）设计**，将复杂决策过程分解为四个线性步骤：

**关键模块与职责：**

| 模块 | 职责 | 技术实现要点 |
|------|------|-------------|
| **1. 设置面板** | 管理AI服务配置 | 右侧滑出面板、本地存储(localStorage)、与全局配置联动 |
| **2. 步骤导航器** | 控制流程进度 | CSS类切换(`.active`)、状态管理(`decisionData`对象) |
| **3. 数据收集层** | 收集用户输入 | 文本框、动态添加输入框、滑块评分控件 |
| **4. AI交互层** | 与AI模型通信 | `callApi()`函数、Prompt构建、错误处理 |
| **5. 结果展示层** | 可视化分析结果 | Chart.js图表、AI文本格式化显示 |

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入决策难题 → AI生成评估维度 → 用户评分 → AI分析评分数据 → 生成图表和建议
```

**最值得学习的设计：**
**“分步收集 + AI辅助结构化”的混合模式**。这个设计巧妙之处在于：
1. **降低认知负担**：不让用户一开始就思考所有评估标准
2. **AI作为“脚手架”**：先让AI建议评估维度，用户只需在此基础上评分
3. **数据驱动可视化**：将主观评分转化为客观图表，增强说服力

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演的角色：**
AI在这里扮演了**两个角色**：
1. **维度生成专家**（第三步）：从用户模糊的问题中提取关键评估标准
2. **决策顾问**（第四步）：基于量化数据提供综合分析和建议

**解决的是“理解问题”还是“生成问题”？**
主要是**“结构化理解”问题**：
- 将用户的自然语言描述转化为可评估的维度列表
- 将用户的评分数据转化为有逻辑的分析报告

**Prompt中的关键变量：**
1. **`${dilemma}`**：用户的原始问题描述
2. **`${JSON.stringify(decisionData.options)}`**：用户评分数据的结构化表示
3. **系统角色指令**：如“你是一个决策分析专家”、“你是一位经验丰富的决策顾问”

**如果只改Prompt，不改代码，会发生什么变化？**
- **改变分析风格**：将“决策顾问”改为“风险投资家”或“生活教练”，分析角度会完全不同
- **调整输出格式**：要求AI用“优点/缺点”列表代替段落分析
- **增加分析深度**：要求AI考虑更多因素，如长期影响、机会成本等
- **改变维度数量**：修改“5个最关键维度”为“3个核心维度”或“7个全面维度”

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径（从易到难）：**

**第一步：保持结构不变，替换使用场景**
- 将“决策顾问”改为“旅行规划师”、“健身计划制定器”或“学习路径选择器”
- 只需修改页面标题、说明文字和输入框的提示文本
- **示例**：改为“AI旅行规划师”，第一步输入“我想规划一次假期”，第二步输入目的地选项

**第二步：调整输入字段或Prompt**
- 在现有步骤中添加/删除输入项
- **简单调整**：在第二步增加“预算限制”输入框
- **Prompt调整**：修改AI生成维度的指令，如“请从性价比、体验独特性、安全性的角度提出评估维度”

**第三步：改变输出形式或展示方式**
- 将柱状图改为雷达图（更适合多维度比较）
- 在AI建议前增加“关键洞察”摘要框
- 添加“导出报告”按钮，将结果保存为文本

**从哪里下手最安全？**
从**修改文案和视觉样式**开始最安全：
1. 修改`<title>`和`<h1>`中的文字
2. 调整CSS中的颜色变量（`:root`中的颜色值）
3. 更改输入框的`placeholder`提示文本
4. 这些修改几乎零风险，不会破坏核心功能

## 【六】3–5个可直接尝试的改造方向

**1. 增加“权重”设置功能**
- **具体做法**：在第三步，让用户不仅能给每个维度打分，还能设置每个维度的重要性权重（如“薪资发展”权重40%，“工作压力”权重30%）
- **技术实现**：为每个维度添加一个权重滑块，在计算总分时进行加权计算
- **学习价值**：理解如何实现更复杂的评分算法

**2. 支持多模型切换和比较**
- **具体做法**：在设置面板增加“同时使用多个模型”选项，让DeepSeek和另一个模型（如OpenAI）分别分析，并排展示结果
- **技术实现**：修改`callApi()`函数支持多个端点，并行调用，分别展示
- **学习价值**：学习异步编程、Promise.all()的使用

**3. 拆分为“快速模式”和“深度模式”**
- **具体做法**：首页增加选择按钮。快速模式跳过维度生成，使用预设维度；深度模式保持现有流程
- **技术实现**：在第一步前增加选择步骤，根据选择跳转到不同的流程分支
- **学习价值**：学习条件流程控制和状态管理

**4. 增加“历史决策”库**
- **具体做法**：添加侧边栏或新页面，保存用户的历史决策记录，可查看、对比
- **技术实现**：使用localStorage或IndexedDB存储结构化数据，新增历史记录页面
- **学习价值**：学习本地数据存储和检索，页面间数据传递

**5. 引入“协作决策”功能**
- **具体做法**：生成分享链接，让多人对同一决策进行独立评分，然后汇总比较
- **技术实现**：为每个决策生成唯一ID，使用URL参数传递，汇总多个用户的评分数据
- **学习价值**：学习数据聚合、基本的多用户系统设计

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不适合需要精确数据支持的决策**
   - **如**：投资组合优化、工程方案选择
   - **应改用**：专业分析软件、电子表格建模

2. **不适合高度专业化领域**
   - **如**：医疗诊断、法律咨询、财务审计
   - **应改用**：咨询领域专家、专业服务机构

3. **不适合实时或动态变化的决策**
   - **如**：股市交易、应急响应、实时调度
   - **应改用**：专门的数据仪表盘、实时监控系统

4. **不适合完全客观、无需个人偏好的选择**
   - **如**：数学问题求解、物理实验设计
   - **应改用**：计算工具、模拟软件

5. **不适合替代深度的人际沟通**
   - **如**：关系问题、团队冲突解决、职业发展规划
   - **应改用**：专业咨询、教练辅导、团队工作坊

**核心定位提醒：**
这个工具是**思考的辅助框架**，而不是**答案的生成机器**。它的价值在于帮助用户结构化思考过程，而不是代替用户做决定。最好的使用方式是将其作为个人或团队讨论的起点，而不是终点。
