# OKR 目标制定助手 - 帮助文档

## 【一】这个网页解决了什么问题？

这个网页解决的是**个人或团队在制定目标时，缺乏结构化方法和专业指导**的问题。

**适合的使用场景：**
- **个人规划**：你是一名员工，需要为自己下个季度的工作设定清晰、可衡量的目标。
- **上下对齐**：你的领导已经制定了部门目标，你需要思考如何将自己的工作与上级目标对齐，确保自己的工作能有效支撑团队。
- **任务拆分**：你是一名团队负责人，需要将一个大目标合理地分解给不同的团队成员，确保分工明确、责任到人。

**不适合的情况：**
- 制定非常模糊、非业务性的个人生活目标（如“变得更健康”）。
- 需要即时、动态调整和追踪目标进度的场景（它只负责“制定”，不负责“追踪”）。
- 当你的目标完全无法量化，或者你没有任何初步想法时，AI可能无法凭空创造。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要提供一些基本信息，核心是选择一种“模式”，然后填写对应的内容：
1.  **选择模式**：你是为自己定目标、承接领导的目标，还是给团队分目标？
2.  **基础信息**：目标的时间周期（如Q1季度）和你的角色/部门。
3.  **模式专属信息**：
    *   **个人制定**：你的核心业务目标是什么？有什么资源或限制？
    *   **承接领导**：领导的OKR原文是什么？你的具体职责是什么？
    *   **拆分团队**：你自己的OKR原文是什么？团队成员都有谁，各自擅长什么？

**用户通常会做哪几步操作？**
1.  打开页面，在左侧“制定模式”中选择一个（比如“个人制定”）。
2.  填写“时间周期”和“角色/部门”。
3.  根据你选择的模式，在下方出现的文本框中填写对应内容。
4.  （可选）点击“高级选项”，可以调整目标数量、是否包含风险评估等。
5.  点击蓝色的“生成 OKR”按钮。
6.  等待几秒到几十秒，在右侧“生成结果”区域查看AI为你制定的详细OKR方案。

**输出结果长什么样？**
结果会以清晰的Markdown格式展示，通常包括：
- 一个总标题，如 `## 📊 Q1 OKR - 产品经理`
- 多个目标（O），每个目标下有：
    - **目标说明**：解释这个目标的意义。
    - **关键结果（KR）**：3-5个可量化的结果，通常有“从X提升到Y”的格式。
    - **风险评估**和**资源需求**（如果勾选了高级选项）。
- 最后的“执行建议”，包括优先级、里程碑等。

**有哪些容易忽略的使用细节？**
1.  **必须先配置API Key**：第一次使用时，点击右上角“设置”按钮，填入你的DeepSeek API Key并保存，否则无法生成。
2.  **模式切换会清空内容**：当你从“个人制定”切换到“承接领导”时，之前填写的个人目标内容会消失，因为输入框完全不同了。
3.  **“高级选项”是折叠的**：默认只显示基础输入，点击“高级选项”可以展开，调整目标数量和额外内容。
4.  **R1模型的推理过程**：如果选择了“R1深度推理”模型，生成结果上方会有一个可展开的区域，展示AI的思考过程，这对学习如何分析问题很有帮助。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个大模块：

**1. 输入配置模块（左侧面板）**
*   **职责**：收集用户的所有意图和背景信息。
*   **子模块**：
    *   **模式选择器**：决定整个应用的逻辑流向（个人/承接/拆分）。
    *   **基础信息区**：收集目标周期和角色，这是所有模式的共性。
    *   **动态表单区**：根据所选模式，显示不同的文本框来收集特定信息。这是**条件渲染**的典型应用。
    *   **高级选项区**：提供更精细的控制参数（如目标数量）。
    *   **行动按钮**：触发所有后续逻辑。

**2. AI处理与通信模块（不可见，在代码中）**
*   **职责**：作为“大脑”，将用户输入转化为给AI的指令，并处理AI的回复。
*   **关键逻辑**：
    *   **输入**：用户填写的数据 + 选择的模式。
    *   **处理**：
        1.  **构建系统提示词**：告诉AI“你是一个OKR专家，需要遵循什么原则，输出什么格式”。这部分是固定的知识框架。
        2.  **构建用户提示词**：将用户输入的数据，按照当前模式，组织成一个具体的问题，填入系统提示词设定的框架中。
        3.  **调用API**：将组合好的“系统提示词+用户提示词”发送给DeepSeek API，并接收流式返回的结果。
    *   **输出**：原始的AI生成文本（Markdown格式）和可能的推理过程。

**3. 结果展示与交互模块（右侧面板）**
*   **职责**：优雅地呈现AI生成的内容，并提供后续操作。
*   **子模块**：
    *   **状态显示**：空状态、加载动画、错误提示。
    *   **内容渲染区**：将AI返回的Markdown文本转换成美观的HTML进行展示。
    *   **推理过程区**：单独展示R1模型的“思考过程”，帮助用户理解AI的决策逻辑。
    *   **操作区**：提供“复制”和“导出”功能，让结果可以被轻松使用。

**最值得学习的设计：**
**“模式驱动”的动态表单与提示词构建**。整个应用的核心不是一堆固定的输入框，而是一个“模式”开关。这个开关同时控制了三件事：
1.  **前端界面**：显示不同的输入表单。
2.  **系统提示词**：为AI注入不同模式的特别说明（如“拆分时要确保分工明确”）。
3.  **用户提示词**：用不同的模板组织用户输入的数据。
这种设计使得一个工具能干净利落地解决三个相关但不同的问题，代码结构清晰，用户体验连贯。这是构建复杂AI应用的一个优秀范式。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 在这里扮演着 **“专业教练”和“格式规范员”** 的双重角色。它一方面将AI塑造成一个OKR专家，另一方面严格规定了AI输出的结构和内容。

**它解决的是“理解问题”还是“生成问题”？**
两者都有，但更偏向于 **“结构化生成问题”**。
*   “理解问题”：系统提示词中关于OKR原则、SMART标准的描述，是为了让AI理解“什么是好的OKR”。
*   “生成问题”：用户提示词将零散的信息（如“提升留存率”）填入一个明确的生成任务中（“请为我制定3个目标，每个目标3个KR…”），并强制要求输出特定的Markdown格式。

**哪些信息是 Prompt 中的关键变量？**
关键变量都来自用户的输入和选择：
1.  **模式**：决定使用哪一套生成逻辑。
2.  `form.period`（时间周期）和 `form.role`（角色）：出现在标题和上下文中。
3.  模式专属信息：如 `form.businessGoal`（业务目标）、`form.leaderOKR`（领导OKR）等，是AI生成内容的核心依据。
4.  `form.objectiveCount` 等高级选项：直接作为生成数量要求传递给AI。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个工具的功能，而无需改动任何按钮或布局。例如：
*   将系统提示词中的“OKR专家”改为“敏捷用户故事编写专家”，将用户提示词中的“目标”改为“用户故事”，它就能变成一个**用户故事生成器**。
*   在系统提示词中增加“请用幽默风趣的语言”，整个输出风格就会变得轻松活泼。
*   修改输出格式，比如要求AI输出一个表格，那么右侧的展示结果就会以表格形式呈现。Prompt是控制AI行为的“软开关”。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的AI工具：

**第一步：替换核心场景与模式（最安全）**
保持整个页面结构（左侧输入、右侧输出）和代码框架完全不变。只修改以下内容：
*   **标题和文字**：把“OKR目标制定助手”改为你的工具名，如“周报生成助手”。
*   **模式定义**：把“个人制定、承接领导、拆分团队”三种模式，改为你的场景下的不同模式，例如“技术周报、销售周报、项目复盘周报”。
*   **输入字段标签**：将“核心业务目标”改为“本周重点工作”，“领导OKR”改为“上级重点关注事项”。

**第二步：重写Prompt，重塑AI角色**
这是改变功能的核心。在代码中找到 `buildSystemPrompt` 和 `buildUserPrompt` 函数。
*   在 `buildSystemPrompt` 中，将关于OKR的原则全部替换成你新场景的原则（如“周报的要点：突出成果、量化数据、指出问题、规划下周”）。
*   在 `buildUserPrompt` 中，修改每个模式下的提问模板，确保它能把第一步中你新设计的输入字段，组织成一个逻辑通顺的请求给AI。
*   同时，修改输出的格式要求，让AI生成你想要的样式（如“## 本周总结 ## 下周计划”）。

**第三步：调整展示与交互细节**
根据新工具的需求，微调界面：
*   **UI微调**：更改颜色主题（修改Tailwind CSS类），更换图标。
*   **输出处理**：如果你不需要“推理过程”，可以隐藏相关代码。如果你需要额外的操作，比如“一键发送邮件”，可以增加按钮。
*   **导出格式**：修改 `exportResult` 函数，将文件名从 `OKR_xxx.md` 改为 `WeeklyReport_xxx.md`。

**从哪里下手最安全？**
从 **第一步** 开始最安全。因为你不触碰任何核心逻辑（Vue响应式数据、API调用函数），只是修改静态文本和字段名称。你能立刻看到一个外观上全新的工具，并且可以测试基础的表单交互是否正常。之后再进行第二步的Prompt改造，功能就随之改变了。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“示例库”功能**：
    *   **操作**：在输入区旁边或下方增加一个“查看示例”按钮。点击后，弹出一个窗口，展示几个写好的、不同角色的OKR示例（如“产品经理示例”、“市场专员示例”）。
    *   **效果**：帮助不知道如何下手的用户获得灵感，可以直接点击“使用此示例”来填充表单，降低使用门槛。

2.  **增加“风格定制”选项**：
    *   **操作**：在“高级选项”中增加一个“输出风格”下拉菜单，选项可以是“专业严谨”、“简洁直接”、“鼓舞人心”等。
    *   **实现**：在 `buildSystemPrompt` 函数的末尾，根据用户的选择，追加一句指令，如“请使用简洁直接、避免冗余形容词的语言风格进行输出。”

3.  **拆分为“制定”与“评审”两个页面**：
    *   **操作**：创建两个HTML文件。第一个是当前的“制定页”。第二个是“评审页”，其输入框用于粘贴已有的OKR草案，AI的角色从“制定者”变为“评审员”，Prompt改为要求AI从SMART原则、挑战性、可衡量性等角度给出修改建议和评分。
    *   **效果**：工具功能更完整，覆盖了目标管理的“制定-评审”闭环。

4.  **优化交互：保存草稿与历史记录**：
    *   **操作**：利用浏览器的 `localStorage`，在用户离开页面时自动保存当前表单的所有内容。在页面顶部增加一个“历史记录”下拉菜单，列出之前保存的草稿或生成记录，支持快速加载。
    *   **效果**：防止意外刷新导致输入内容丢失，方便用户进行多次迭代和修改，体验更友好。

5.  **接入多模型API，实现“专家会诊”**：
    *   **操作**：在API设置中，除了DeepSeek，增加对OpenAI GPT、Claude等模型的支持。在生成时，提供一个“多模型对比”选项，可以同时或依次调用多个模型生成OKR，并将结果并排展示在右侧。
    *   **效果**：用户可以获得不同“AI专家”的视角，综合参考，做出更优决策。这能直观展示不同模型的特点。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为最终的、权威的目标决策工具**：它生成的OKR是基于你提供的有限信息和AI的通用知识。它缺乏对你所在公司具体文化、历史数据、人际关系的深度理解。**输出结果必须由你和你的领导进行最终评审和确认**，不能直接当作正式考核文件。
2.  **不适合动态追踪和更新**：这个工具只解决了“从0到1”的制定问题。它没有进度更新、完成度标记、历史版本对比等功能。如果你需要追踪OKR执行过程，应该使用专门的OKR管理软件（如OKR、飞书OKR、Tita等）。
3.  **不适合生成极度创新或突破性目标**：AI的训练数据基于已有的模式和知识，它更擅长优化和重组已知信息。对于需要颠覆性思维的“从0到1”的突破性目标，AI可能只能提供常规思路。这类目标更需要人类的直觉和创造力。
4.  **不适合在无网络或API失效时使用**：这是一个完全依赖云端AI服务的工具。没有网络，或者DeepSeek API服务出现故障、额度用尽时，工具将完全无法工作。它不是一个离线可用的本地软件。

**总结**：这是一个强大的“**目标起草助手**”和“**思维启发工具**”。它能极大地提升你制定结构化目标的效率和质量，但绝不能替代你的独立思考、团队讨论和实际管理流程。
