# 口语模拟练习 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你正在准备一场重要的外语面试，或者即将去国外旅行需要练习点餐对话。你希望有一个“陪练伙伴”，能根据你的具体需求，快速生成一个真实、可演练的对话场景。这个网页就是你的**AI口语陪练生成器**。

- **适合场景**：
    - **考前突击**：快速生成特定主题（如“雅思口语Part 2”）的模拟对话。
    - **场景演练**：为特定情境（如“酒店入住”、“餐厅投诉”）准备语言素材。
    - **自学跟读**：获得一个结构化的对话脚本和重点词汇，用于模仿和背诵。

- **不适合场景**：
    - **实时对话练习**：它生成的是静态脚本，无法像真人或AI聊天机器人那样与你实时互动、纠音。
    - **深度语法讲解**：它侧重于生成实用对话，而非系统性地讲解语法规则。
    - **长篇内容创作**：它生成的对话长度和复杂度有限，不适合用于撰写演讲稿或长篇文章。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    - **场景**：你想练习的对话情境，比如“英语面试”、“日语点餐”。
    - **角色**：你在对话中扮演的身份，比如“求职者”、“旅客”。

2.  **用户通常会做哪几步操作？**
    1.  在左侧面板的“场景”和“角色”输入框中，填写你想练习的内容。
    2.  点击蓝色的 **“生成对话脚本”** 按钮。
    3.  稍等片刻，右侧面板就会自动刷新，显示出为你生成的完整内容。

3.  **输出结果长什么样？**
    右侧面板会生成三部分内容：
    - **对话脚本**：一个完整的、分角色（如“面试官”、“求职者”）的对话，每句话都清晰标明了说话者。
    - **高频表达**：一些该场景下常用的短语或词汇，以彩色标签的形式展示。
    - **自测问题**：几个与场景相关的问题，你可以用来检验自己是否理解了对话，或进行拓展思考。

4.  **有哪些容易忽略的使用细节？**
    - **API设置**：页面右上角的“API设置”按钮。首次使用或生成失败时，需要点击它，填入你自己的DeepSeek API密钥，网页才能正常工作。
    - **模型切换**：右上角的“V3”和“O1”按钮可以切换AI模型。O1可能推理能力更强，但速度可能稍慢；V3是通用模型。你可以都试试，看哪个生成的内容更合你意。
    - **返回格式**：AI被严格要求返回**纯JSON数据**。如果生成失败，很可能是AI返回的格式不符合要求，可以尝试重新生成或简化你的输入。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个模块：

1.  **控制模块（左侧面板）**
    - **职责**：接收用户的指令（场景和角色），并触发“生成”动作。
    - **逻辑**：用户填写输入 → 点击按钮 → 该模块收集输入信息，并调用核心的AI处理函数。

2.  **展示模块（右侧面板）**
    - **职责**：以清晰、美观的格式呈现AI生成的结果。
    - **结构**：它又细分为三个子模块：
        - **对话区**：以“气泡”形式展示对话，突出说话者。
        - **高频词区**：用标签云展示重点词汇，视觉上很醒目。
        - **问题区**：以列表形式展示自测问题。
    - **逻辑**：接收处理模块传来的结构化数据 → 分别填充到三个对应的区域进行渲染。

3.  **逻辑处理模块（隐藏在背后的JavaScript）**
    - **职责**：这是**最核心的模块**。它负责：
        - 将用户的“场景”和“角色”拼接成一个给AI的指令（Prompt）。
        - 调用AI接口（DeepSeek API）并发送这个指令。
        - 接收AI返回的文本，并从中解析出结构化的数据（对话、高频词、问题）。
        - 将解析好的数据交给“展示模块”去显示。

**输入 → 处理 → 输出 的逻辑链路：**
`用户输入（场景、角色）` → `拼接成Prompt` → `调用AI API` → `解析AI返回的JSON` → `将数据填充到页面模板` → `用户看到结构化的对话脚本`

**最值得学习的设计：**
**“结构化输出”与“模板化展示”的紧密结合**。整个应用的核心是让AI返回一个固定格式的JSON数据。前端页面则预先为这个JSON的每个部分（`dialogue`, `highlights`, `questions`）设计好了对应的HTML展示模板。这种设计使得前端展示非常稳定，无论AI生成什么具体内容，页面布局都不会乱，同时后端（AI）和前端的职责非常清晰。

## 【四】Prompt / AI 逻辑是如何被设计的？

- **Prompt扮演的角色**：它是连接用户意图和AI能力的**翻译官**和**指令官**。它把用户简单的“场景”和“角色”关键词，翻译成AI能理解的、具体的创作任务。

- **解决的是“生成问题”**：它主要解决的是“根据要求生成内容”的问题，而不是“理解用户复杂意图”的问题。这里的用户意图已经很明确了。

- **Prompt中的关键变量**：
    1.  `{this.scenario}`：用户输入的“场景”，是对话发生的背景。
    2.  `{this.role}`：用户输入的“角色”，决定了对话的视角和用语。
    3.  **严格的输出格式指令**：`返回 JSON：{“dialogue”:[...],“highlights”:[...],“questions”:[...]}，仅返回 JSON。` 这是确保数据能被程序正确解析的关键。

- **如果只改Prompt，不改代码，会发生什么？**
    - **改变内容风格**：例如，在`system`指令里将“口语教练”改为“莎士比亚剧作家”，生成的对话会充满古风戏剧腔。
    - **调整输出结构**：例如，在Prompt里要求JSON中增加一个`“vocabulary”: [“单词”: “解释”]`的字段。由于前端代码没有为这个新字段准备展示模板，所以数据虽然能拿到，但不会显示在页面上。
    - **变更任务类型**：例如，将Prompt改成“生成一份关于{场景}的演讲大纲”，那么AI就会生成大纲文本，但页面依然会试图把它当成对话JSON来解析，导致显示错误。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步打造你的专属工具：

**第一步：替换核心概念（最安全）**
保持整个页面结构、代码逻辑完全不变，只替换“使用场景”。例如，你想做一个“短视频脚本生成器”。
- 将页面标题、说明文字中的“口语模拟”改为“短视频脚本”。
- 将输入框的标签“场景”改为“视频类型”（如：美食测评、知识科普），“角色”改为“主播人设”（如：幽默吃货、严谨教授）。
- 将右侧输出标题改为“脚本正文”、“核心梗概”、“拍摄要点”。

**第二步：调整输入与Prompt**
在第一步的基础上，修改生成逻辑。
- 在`generate`函数中，修改Prompt模板，例如：`请生成一个{视频类型}的短视频脚本，主播人设为{主播人设}。返回JSON：{“script”: [“镜头”: “画面描述”, “audio”: “台词或配音”], “keyPoints”: [], “shootingTips”: []}`
- 同时，记得将JavaScript中`dialogue`, `highlights`, `questions`这些变量名，改为与你新设计的JSON字段对应的名字（如`script`, `keyPoints`, `shootingTips`）。

**第三步：改变输出展示方式**
让前端展示匹配你的新数据结构。
- 在右侧面板的HTML模板中，将遍历`dialogue`的部分改为遍历`script`，并可能将显示方式从“气泡对话”改为“分镜表格”。
- 相应地修改`highlights`和`questions`对应的HTML部分，以展示`keyPoints`（关键点）和`shootingTips`（拍摄建议）。

**从哪里下手最安全？**
从**第一步**开始。仅仅修改文字和标签，不碰代码逻辑，可以让你立即看到一个“换皮”版的应用，建立信心。然后第二步修改Prompt和变量名，第三步调整HTML模板，每一步的风险都是可控的。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，让生成更精准**：
    - **增加“语言水平”下拉框**：选项如“初级”、“商务”、“流利”。将选项值加入到Prompt中，例如：“请生成一个适合**{语言水平}** 学习者的{场景}对话...”。
    - **增加“对话长度”选择**：选项如“简短（3轮）”、“中等（6轮）”、“详细（10轮）”。在Prompt中明确要求对话轮数。

2.  **增强交互与练习功能**：
    - **添加“角色扮演”模式**：在生成的对话旁，为每一句“对方”的话添加一个“朗读”按钮（调用浏览器TTS API）或“录音跟读”按钮，让用户能真正“说”出来。
    - **增加“隐藏/显示答案”功能**：将“高频表达”的中文解释或“自测问题”的参考答案 initially 隐藏，用户点击后才显示，增强自测效果。

3.  **优化输出与保存体验**：
    - **增加“一键复制”按钮**：在对话脚本区域增加一个按钮，点击后可将整个对话文本复制到剪贴板，方便粘贴到其他笔记软件中。
    - **添加本地历史记录**：使用浏览器的`localStorage`，将用户最近生成的几次脚本保存下来，方便回顾和对比。

4.  **切换或扩展AI后端**：
    - **接入其他模型**：代码中已对API调用做了抽象（`studyShared.callLLM`）。你可以尝试修改配置，接入OpenAI GPT、Claude或国内的其他大模型API，对比生成效果。
    - **实现“重试/优化”功能**：在生成结果下方添加“换一种说法”或“更正式一些”等按钮，点击后会在原Prompt基础上附加新的要求（如“请让对话更正式”），重新调用AI生成。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为主要的口语练习工具**：它提供的是**素材**，而非**互动**。真正的口语提升需要大量的实时输出、反馈和纠错。它更适合作为准备阶段的素材库生成器。
- **不适合生成高度专业或精确的内容**：对于法律、医疗、金融等专业领域的对话，AI生成的内容可能存在事实性错误或不准确，不可直接用于实际场合，仅能作为语言表达的参考。
- **不适合处理过于复杂或开放的创意任务**：它的输入非常简单（两个短文本），因此无法理解复杂的、多层次的用户需求。例如，你想生成一个“包含三次反转的悬疑故事对话”，仅靠目前的输入框很难实现。
- **如果用户的需求是**：需要一个能实时听懂我的发音并纠正的陪练。那么应该转向使用专门的**语音识别+AI对话**类应用，如多邻国、ChatGPT的语音对话功能等。
- **如果用户的需求是**：需要系统性地学习一门语言的语法体系。那么应该使用**教科书、在线课程（如Coursera）或系统性的学习App（如Rosetta Stone）**。
