# 批量OCR识别工具 - 帮助与学习指南

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一名行政人员，手头有几十张同事的名片需要录入系统；或者你是一名财务，需要从一堆发票照片中提取金额和日期；又或者你是一名学生，想把教材里的表格图片快速转换成可编辑的Excel。手动打字？太慢。用传统OCR软件？往往格式混乱，无法结构化。

这个网页就是为解决这类 **“从图片批量提取结构化信息”** 的痛点而生的。它利用先进的AI视觉模型，不仅能“看见”图片里的文字，还能“理解”这些文字属于什么类别（如姓名、金额、日期），并整理成整齐的表格。

**适合使用的情况：**
*   **批量处理：** 一次性处理多张同类型图片（如一堆名片、一叠发票）。
*   **结构化提取：** 需要将图片中的信息按固定字段（姓名、电话、金额等）整理出来。
*   **轻度自动化：** 替代重复性的手动录入工作，提升效率。

**不适合使用的情况：**
*   **高精度、法律文书识别：** 对于合同、法律文件等要求100%准确率的场景，仍需人工核对。
*   **复杂版式或手写体：** 如果图片排版极其复杂或为潦草手写体，识别效果可能不佳。
*   **实时视频流识别：** 它处理的是静态图片文件，而非实时视频流。

## 【二】使用方式（给第一次接触的人）

1.  **准备工作：** 点击右上角“模型配置”，选择一个AI模型（默认推荐“智谱GLM-4V”），并填入对应的API密钥（需要到对应平台免费注册获取）。
2.  **选择模板：** 在左侧“识别模板”区域，根据你的图片类型选择一个模板（如“名片识别”、“票据/发票”）。
3.  **上传图片：**
    *   **方式一（拖拽）：** 直接将电脑里的图片文件拖到左侧的虚线框内。
    *   **方式二（点击）：** 点击虚线框，在弹出的窗口中选择多张图片。
    *   上传后，下方会显示图片缩略图列表，可以预览或删除单张。
4.  **开始识别：** 点击绿色的“开始批量识别”按钮。处理过程中，你可以看到进度条、成功/失败计数。
5.  **获取结果：**
    *   识别成功后，右侧表格会显示每张图片的识别结果，以清晰的字段名和值呈现。
    *   你可以点击单条结果旁的“复制”按钮，或使用右上角的“导出Excel/CSV/JSON”按钮批量导出所有数据。

**输出结果什么样？**
结果是一个结构化的表格。例如，选择“名片识别”模板后，识别结果会像这样在表格中展开：
| 姓名 | 职位 | 公司 | 电话 | 邮箱 |
| :--- | :--- | :--- | :--- | :--- |
| 张三 | 产品经理 | ABC科技 | 13800138000 | zhangsan@abc.com |

**容易忽略的细节：**
*   **API密钥是必须的：** 工具本身不提供AI能力，需要你自行申请免费API密钥来驱动。
*   **模板是关键：** 选对模板（如名片 vs 发票）能极大提升识别准确率和结构化效果。
*   **并发控制：** 在“模型配置”里可以调整“并发数量”。设置太高可能导致API调用过快被限制，一般3-5即可。
*   **支持重试：** 如果某张图片识别失败，可以直接在该图片的结果行点击“重试”按钮，无需重新处理全部。

## 【三】核心结构拆解（学习重点）

这个网页可以清晰地分为四个核心模块，像一条流水线一样工作：

1.  **配置与输入模块（左侧面板）**
    *   **职责：** 让用户告诉程序“用什么规则”和“处理什么”。
    *   **包含：** 模型配置弹窗、识别模板选择、文件上传区。
    *   **逻辑：** 用户在这里完成所有准备工作：选AI模型、选信息提取模板、上传图片。

2.  **任务调度与处理模块（后台逻辑）**
    *   **职责：** 高效、稳定地管理批量识别任务。
    *   **包含：** `startBatchOCR()`, `processBatch()`, `processImage()` 函数。
    *   **逻辑：** 这是网页的“大脑”。它接收图片列表，按照用户设置的并发数，有序地调用AI API，并跟踪每张图片的处理状态（成功/失败/处理中）。**最值得学习的设计就是这里的“并发控制”逻辑**，它用 `Promise.race` 实现了一个简单的并发队列，既提高了速度，又避免了因请求过多导致API被限流。

3.  **AI交互模块（桥梁）**
    *   **职责：** 与不同的AI视觉API进行通信，并翻译用户的需求。
    *   **包含：** `callVisionAPI()`, `buildPrompt()` 函数。
    *   **逻辑：** 这是网页的“翻译官”。它根据用户选择的模板，动态生成一段给AI的“指令”（Prompt），然后将图片和这段指令一起发送给选定的AI API（如GLM-4V），最后把AI返回的文本解析成程序能用的数据。

4.  **结果展示与导出模块（右侧面板）**
    *   **职责：** 直观呈现结果，并提供数据导出能力。
    *   **包含：** 结果表格、导出按钮（Excel/CSV/JSON）。
    *   **逻辑：** 实时更新每张图片的识别状态，将结构化的JSON数据渲染成易读的表格。导出功能则将内存中的数据转换成标准文件格式，方便用户在其他软件（如Excel）中使用。

**核心逻辑链路：**
**用户配置（模板+API）** → **上传图片** → **任务调度（并发处理）** → **AI交互（发送Prompt+图片）** → **解析AI回复** → **更新状态/展示结果** → **导出数据**

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个工具中，**Prompt（提示词）是连接用户意图与AI能力的“指令手册”**。

*   **扮演的角色：** Prompt 解决的是 **“理解问题”** 。它告诉AI：“这是一张[名片/发票]图片，请重点找出[姓名、电话、金额]这些信息，并以严格的JSON格式返回给我。”
*   **关键变量：** Prompt 的核心内容由用户选择的 **“识别模板”** 动态决定。例如，“名片识别”模板的Prompt会包含 `姓名、职位、公司、电话、邮箱` 这些字段名。
*   **如果只改Prompt，不改代码：**
    *   **改变提取字段：** 你可以修改模板中的`fields`数组，比如在名片模板里增加“微信号”字段，AI就会尝试去寻找并提取这个新信息。
    *   **改变输出格式：** 你可以修改`buildPrompt()`函数里的文本，要求AI以XML、YAML甚至纯文本列表的形式返回，结果展示模块虽然可能无法直接解析，但你能看到AI返回内容的变化。
    *   **改变任务性质：** 你可以将Prompt从“提取信息”改为“描述图片内容”、“分析图表趋势”或“解答图片中的数学题”。这样，工具就从“OCR提取器”变成了“图片问答机”。

## 【五】如何模仿它，做出你自己的版本？

如果你想做一个类似但用途不同的工具（比如“批量图片内容审核工具”或“商品图片信息提取器”），请遵循以下安全路径：

**第一步：替换核心场景与模板（最安全）**
*   **目标：** 保持所有技术框架不变，只改变用途。
*   **操作：** 修改 `templates` 数组。例如，做“商品图提取器”，就创建 `{id: ‘product’, name: ‘商品信息’, fields: [‘商品名’, ‘品牌’, ‘价格’, ‘规格’]}` 等新模板。这是风险最低的改动，因为程序的主体逻辑完全不用动。

**第二步：调整AI交互逻辑**
*   **目标：** 让AI更好地为新场景服务。
*   **操作：** 修改 `buildPrompt()` 函数。根据你的新模板，编写更精准的指令。例如，对于商品图，Prompt可以是：“请识别这张商品图片中的文字和视觉元素，提取出商品名称、品牌、价格和主要规格说明。”

**第三步：改变输入与输出形式**
*   **目标：** 优化用户体验，使其更贴合新场景。
*   **操作：**
    *   **输入：** 可以限制上传文件为特定类型（如只允许正方形图片），或增加“图片分类”步骤。
    *   **输出：** 修改结果表格的列名，或者增加新的导出格式（如直接生成商品上架用的CSV模板）。你还可以在结果旁增加“审核通过/不通过”的按钮，实现简单的内容审核流程。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“自定义字段”模板：** 在模板选择区增加一个“自定义”选项，允许用户在识别前，自己输入一组想要提取的字段名（如“客户编号”、“合同号”）。这能极大提升工具的灵活性。
2.  **集成本地OCR引擎：** 除了调用云端AI API，可以集成一个开源的本地OCR引擎（如Tesseract.js）。增加一个“模型配置”选项为“本地识别”，供用户在无网络或处理敏感图片时使用。这涉及到在 `callVisionAPI` 函数中增加一个新的分支。
3.  **结果后编辑与合并：** 允许用户在结果表格中直接双击修改识别有误的字段值。同时，可以增加“合并结果”功能，例如将多张名片的识别结果自动去重后合并成一个通讯录文件。
4.  **优化交互体验：**
    *   **批量操作：** 在结果表格增加复选框，支持用户选择部分成功的结果进行导出。
    *   **历史记录：** 利用浏览器的 `localStorage` 保存最近几次的识别任务记录和结果，方便用户回溯。
    *   **快捷键：** 为常用操作（如全选图片、开始识别、导出）添加键盘快捷键。
5.  **拆分为多页面/工作流：** 将“上传配置”、“处理中”、“结果查看”拆分成三个独立的页面或视图。这样结构更清晰，也便于将来扩展更复杂的处理流程（例如，在“结果查看”页增加一个“批量打印标签”的下一步操作）。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合做“高保真”文档还原：** 它专注于提取**文字内容**并将其**结构化**，但不会保留原始图片的排版、字体、颜色等样式信息。如果你需要将一份扫描的PDF完美还原成可编辑的Word文档（保持原样式），应该使用专业的PDF转换软件或Adobe Acrobat等工具。
*   **不适合做“实时”或“流式”识别：** 它的工作模式是“上传-处理-返回”，不适合摄像头实时取景识别、或持续监控视频流中的文字。这类需求需要寻找专门的实时OCR SDK或API。
*   **不适合处理极端情况或作为唯一数据源：** 对于非常重要的数据（如法律文件、财务凭证），AI识别结果**必须**经过人工核对确认，不能直接作为最终数据使用。它是一个强大的**辅助工具**，而非完全可靠的**自动化解决方案**。
*   **不适合无网络环境：** 当前版本严重依赖云端AI API，在没有互联网连接的情况下无法工作。如需离线使用，需按改造方向2所述，集成本地识别引擎。
