# 选择纠结终端 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你面临多个选择，感到犹豫不决时，这个工具能帮你快速做出决定。比如：
- 中午和同事纠结“吃什么”
- 周末不知道安排什么活动
- 购物时在几件商品间摇摆不定
- 需要随机分配任务或抽签

**适合情况：**
- 选项数量有限（2-10个为佳）
- 每个选项的“价值”差不多，没有绝对优劣
- 你只是需要有人帮你“推一把”
- 想要一个有趣、可视化的决策过程

**不适合情况：**
- 需要理性分析的重要决策（如投资、职业选择）
- 选项之间有明确的优劣差异
- 需要多人投票或共识的决策
- 需要记录决策历史或统计分析

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 你需要输入几个备选选项（比如“火锅”、“日料”、“快餐”）
- 可以通过文本框手动添加，也可以使用预设快速填充

**用户通常会做哪几步操作？**
1. **添加选项**：在“选项管理”区域输入你的备选项，点击“添加”
2. **选择模式**：点击顶部的“转盘”或“随机”切换决策方式
3. **开始决策**：
   - 转盘模式：点击“开始转动”，指针会随机停在某个选项上
   - 随机模式：点击“随机抽取”，选项会快速闪烁后停在结果上
4. **查看结果**：页面会突出显示被选中的选项

**输出结果长什么样？**
- 转盘模式：一个彩色转盘旋转后，指针指向的选项会显示在下方卡片中
- 随机模式：一个大号文字显示最终结果，配上一句“就决定是你了！”

**容易忽略的使用细节：**
1. **最少需要2个选项**：按钮在少于2个选项时会变灰禁用
2. **回车键添加**：输入选项后按回车可以直接添加，不用点按钮
3. **自动保存**：你添加的选项会被保存在浏览器里，下次打开还在
4. **预设功能**：如果没想法，可以直接用“午餐吃什么”等预设快速开始

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成：

### 1. 模式切换模块（顶部按钮）
- **职责**：让用户在“转盘”和“随机”两种视觉体验间切换
- **设计亮点**：使用简单的状态变量控制整个页面的显示逻辑

### 2. 决策展示模块（中间大区域）
- **转盘子模块**：
  - 输入：选项列表、随机数
  - 处理：计算每个扇区的角度和颜色，执行旋转动画
  - 输出：旋转后指向的选项
- **随机子模块**：
  - 输入：选项列表
  - 处理：快速随机切换显示，制造悬念效果
  - 输出：最终选中的选项

### 3. 选项管理模块（下方面板）
- **职责**：
  - 接收用户输入的选项
  - 展示当前所有选项
  - 提供删除和预设功能
  - 自动保存到本地存储

### 4. 状态管理模块（背后的JavaScript）
- **职责**：
  - 维护`options`数组（所有选项）
  - 管理`mode`状态（当前模式）
  - 处理`result`（决策结果）
  - 控制`isSpinning`等动画状态

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入选项 → 存入options数组 → 选择决策模式 → 
触发决策函数 → 生成随机数 → 映射到具体选项 → 
执行动画效果 → 显示结果
```

**最值得学习的设计：**
**状态驱动的UI更新**。整个页面只维护几个核心状态（options, mode, result），UI会自动根据这些状态重新渲染。这是现代前端框架的核心思想，这个页面用Alpine.js轻量级地实现了它。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：这个页面**没有使用AI或Prompt**，它是一个纯粹的随机决策工具。但我们可以从这个角度思考：如果我们要加入AI，会怎么设计？

**如果我们要加入AI建议功能：**
- **Prompt可能扮演的角色**：将用户的选项列表和决策场景描述给AI，让AI给出“智能推荐”
- **解决的是“理解问题”**：AI需要理解“午餐吃什么”和“投资哪个项目”的决策权重不同
- **关键变量**：
  1. 选项列表
  2. 决策场景描述（如“工作日午餐，预算50元以内”）
  3. 用户偏好（如“我不吃辣”）
- **只改Prompt的效果**：同样的代码，Prompt不同，AI给出的推荐理由和结果会完全不同

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 改标题和文案：“选择纠结终端” → “团队任务分配器”
- 改预设按钮：“午餐吃什么” → “开发任务”、“设计任务”、“测试任务”
- 改颜色主题：修改`bg-gradient-to-br from-violet-500...`这行，换一套配色

**第二步：调整输入字段**
- 当前：只有一个文本输入
- 可以改为：选项 + 权重（数字输入）
- 或者：选项 + 分类标签（下拉选择）

**第三步：改变输出形式**
- 当前：只显示一个结果
- 可以改为：显示前3个推荐，并给出理由
- 或者：生成一个决策报告，可以分享给他人

**最安全的下手点：**
从**修改预设数据**开始。找到`loadPreset()`函数，把里面的`lunch`、`yesno`、`weekend`换成你自己的场景。这是零风险修改，不会破坏任何功能。

## 【六】3–5 个可直接尝试的改造方向

### 1. 增加选项权重
**具体做法**：
- 修改`options`数组，从`['选项A', '选项B']`变成`[{text: '选项A', weight: 2}, {text: '选项B', weight: 1}]`
- 在添加选项时，增加一个“权重”输入框
- 修改随机算法，让权重高的选项有更高概率被选中

### 2. 加入决策历史
**具体做法**：
- 新增一个`history`数组，每次决策后把结果和时间戳存进去
- 在页面底部添加“历史记录”面板
- 可以查看过去10次决策的结果分布

### 3. 多人协作模式
**具体做法**：
- 增加“创建房间”功能，生成一个分享链接
- 其他人访问链接可以添加自己的选项
- 所有人就绪后，房主点击“开始决策”，大家同时看到结果

### 4. 增强转盘视觉效果
**具体做法**：
- 让转盘旋转时有速度变化（快→慢）
- 增加音效：旋转声、停止声、庆祝声
- 结果出现时，有放大或弹跳动画

### 5. 导出/分享功能
**具体做法**：
- 添加“截图”按钮，把当前转盘和结果保存为图片
- 生成决策摘要：“在A/B/C/D中，最终选择了B”
- 支持分享到微信、微博等社交平台

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **没有理性分析**：它只是随机选择，不考虑选项的实际优劣
2. **没有记忆学习**：不会根据你过去的选择调整概率
3. **没有多人权重**：不能处理“团队投票，经理一票顶三票”的情况
4. **没有复杂条件**：不能处理“如果选A，就不能选B”的约束条件

### 如果用户想做X，应该换什么工具：

**如果你想做：重要的人生/财务决策**
- **换用**：决策矩阵工具、SWOT分析模板、专业咨询
- **理由**：需要理性分析每个选项的利弊和风险

**如果你想做：团队民主投票**
- **换用**：投票工具（如腾讯投票、问卷星）
- **理由**：需要收集每个人的意见，并可能加权计算

**如果你想做：长期习惯培养（如“今天做什么运动”）**
- **换用**：习惯追踪App（如习惯清单）
- **理由**：需要记录历史、分析偏好、渐进调整

**如果你想做：有约束的分配（如“把这些任务分给3个人，每人工作量差不多”）**
- **换用**：算法分配工具、项目管理软件
- **理由**：需要满足特定约束条件，纯随机可能不公平
