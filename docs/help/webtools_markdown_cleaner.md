# Markdown 清理器 - 学习与模仿指南

## 【一】这个网页解决了什么问题？

想象一下，你从网页上复制了一段包含格式标记、链接、图片代码的文本，想把它粘贴到纯文本编辑器或聊天框中。直接粘贴会带上各种 `**`、`#`、`[链接](地址)` 这样的标记，看起来很杂乱。这个网页就像一个“文本净化器”，能帮你把这些格式标记去掉，只留下干净的纯文字。

**适合的使用场景：**
- 从技术文档、博客文章复制内容到不支持Markdown的地方
- 清理从AI助手生成的带有格式的回复
- 准备要发送给不支持富文本的聊天工具的内容
- 快速查看一段Markdown文档的纯文本内容

**不适合的情况：**
- 需要保留格式（如加粗、标题层级）的转换
- 处理包含复杂表格、数学公式的Markdown
- 需要批量处理大量文件
- 需要将Markdown转换为其他格式（如HTML、PDF）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个大的文本框，让你粘贴或输入带有Markdown格式的文本
- 比如：`**重要提示**：请查看[文档](https://example.com)`

**用户通常会做哪几步操作？**
1. 找到页面中间的文本框
2. 粘贴或输入带有Markdown格式的文本
3. 点击“处理文本”按钮
4. 查看下方显示的清理结果

**输出结果长什么样？**
- 在文本框下方会出现一个显示区域
- 标题会显示“清理后的文本”
- 内容会变成纯文本格式，比如上面的例子会变成：`重要提示：请查看文档`
- 所有格式标记（`**`、`#`、`[]()`等）都被移除了

**有哪些容易忽略的使用细节？**
- 文本框支持直接输入，也支持粘贴
- 处理是实时或接近实时的（取决于实现）
- 清理后的文本可以直接用鼠标选中复制
- 如果输入为空，点击处理按钮可能不会有任何变化

## 【三】核心结构拆解（学习重点）

这个页面采用了“工具套件”的设计模式，Markdown清理器只是其中一个工具。让我们看看它的模块化结构：

**1. 导航模块**
- 顶部导航栏：提供返回主页和设置入口
- 职责：页面导航和全局配置访问

**2. 工具信息模块**
- 显示当前工具的名称和描述
- 职责：告诉用户这是什么工具、能做什么

**3. 输入处理模块（核心）**
- 输入区：大文本框接收Markdown文本
- 处理按钮：触发清理操作
- 职责：收集用户输入，启动处理流程

**4. 输出展示模块**
- 结果标签：说明这是什么结果
- 结果内容区：显示清理后的纯文本
- 职责：清晰展示处理结果

**5. 配置模块（弹出层）**
- API密钥和模型选择
- 职责：为需要AI能力的工具提供后端配置

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入Markdown文本 → 点击处理按钮 → 程序移除格式标记 → 显示纯文本结果
```

**最值得学习的设计：**
- **条件渲染系统**：页面根据`tool.type`动态显示不同的工具界面
- **统一的数据模型**：所有工具共享相似的数据结构（`tool.input`、`tool.output`等）
- **响应式布局**：使用Tailwind CSS确保在不同设备上都能良好显示

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个特定页面中，**没有直接使用Prompt或AI**。这是一个纯前端的文本处理工具。

**如果这是一个AI增强版本，可能会这样设计：**
- **Prompt角色**：指导AI如何清理Markdown
- **解决的问题**：“生成问题” - 让AI重新表述或总结内容，而不仅仅是移除标记
- **关键变量**：用户输入的文本、清理的严格程度、是否保留某些元素
- **只改Prompt的效果**：可以让AI做不同的事情，比如“只保留标题”、“将链接转为脚注”等

**当前实现的启示**：
即使没有AI，清晰的工具设计和用户界面也能解决实际问题。这是学习“工具设计思维”的好例子。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：理解并复制基础结构**
1. 创建一个新的HTML文件
2. 复制页面的基本框架（`<head>`中的CSS/JS引用，`<body>`的基本结构）
3. 重点关注“文本工具”部分（`tool.type === 'text'`的那个`<div>`）

**第二步：替换使用场景和逻辑**
1. 修改工具名称和描述
2. 改变文本框的提示文字（placeholder）
3. 修改按钮文字
4. **关键**：在`standalone.js`中找到`runTextTool`函数，修改它的处理逻辑

例如，如果你想做一个“英文大小写转换器”：
- 将工具名称改为“英文大小写转换”
- 描述改为“将英文文本转换为全大写、全小写或首字母大写”
- 修改处理逻辑：`tool.output = tool.input.toUpperCase()`（全大写示例）

**第三步：调整界面和交互**
1. 可以增加单选按钮让用户选择转换类型（大写/小写/首字母大写）
2. 调整结果展示方式
3. 添加“复制结果”按钮提升用户体验

## 【六】3–5 个可直接尝试的改造方向

**1. 增加预处理选项**
- 添加复选框：“移除所有链接”、“保留加粗标记”、“转换标题为纯文本加冒号”
- 让用户可以选择清理的严格程度

**2. 转换为AI增强版本**
- 使用配置中的DeepSeek API
- 修改Prompt为：“请将以下Markdown文本转换为纯文本，保留所有实质内容但移除所有格式标记。如果有关键的强调内容，可以用括号注明（重要）。”
- 这样AI可以更智能地处理复杂情况

**3. 增加批量处理功能**
- 添加“上传文件”按钮
- 支持批量处理多个Markdown文件
- 提供“一键下载所有清理结果”

**4. 改进结果展示**
- 并排显示“原文本”和“清理后文本”以便对比
- 添加语法高亮显示被移除的部分
- 添加字数统计、行数统计等信息

**5. 扩展为格式转换套件**
- 增加工具类型选择：“Markdown转HTML”、“HTML转Markdown”、“纯文本转Markdown”
- 使用相同的界面结构，只需修改处理逻辑

## 【七】这个网页不适合做什么？（边界提醒）

**局限性：**
1. **不是完整的Markdown解析器**：它只是移除标记，不理解嵌套结构或复杂语法
2. **没有语法检查**：不会告诉你输入的Markdown是否有错误
3. **本地处理限制**：复杂处理（如表格转换）需要更强大的解析库
4. **无版本控制**：不会保存你的处理历史

**如果你需要：**
- **完整的格式转换**：使用Pandoc、Typora等专业工具
- **实时Markdown预览**：使用StackEdit、MarkText等编辑器
- **团队协作和版本历史**：使用GitHub、GitLab的Markdown功能
- **处理大量文件**：使用命令行工具如`pandoc`或编写脚本

**记住**：这个工具最适合快速、简单的单次清理任务。对于复杂需求，应该选择更专业的工具。
