# 工资可视化工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你拿到一份工作offer，上面写着“月薪15,000元”，但实际到手能有多少？这个网页帮你快速估算扣除五险一金和个人所得税后，每月实际能拿到多少钱。它特别适合：
- 正在比较不同offer的求职者
- 想了解自己工资构成的上班族
- 需要向家人解释“为什么工资条上的数字和谈的不一样”的情况

**不适合的情况：**
- 需要精确计算年终奖、专项附加扣除等复杂税务场景
- 不同城市社保政策差异较大的精确计算（本工具使用标准比例估算）
- 作为正式的税务申报依据

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **税前月薪**：输入你与公司约定的月工资总额
2. **公积金比例**：通过滑块选择（通常5%-12%）
3. **高级设置**（可选）：可自定义社保和公积金的计算基数

**操作步骤：**
1. 在“税前月薪”框中输入你的工资数字
2. 拖动“公积金比例”滑块到你公司的实际比例
3. 点击“计算实发金额”按钮（或直接修改数字，页面会自动计算）

**输出结果长什么样？**
- **左侧卡片**：显示每月实际到手金额及其占比
- **右侧卡片**：列出五险一金扣除和个人所得税的具体金额
- **中间图表**：用彩色圆环图直观展示工资分配比例
- **底部列表**：详细列出每一项扣除的具体金额

**容易忽略的细节：**
- 页面会**自动计算**：修改任何数字后，结果会立即更新，无需每次都点按钮
- **高级设置默认隐藏**：点击“社保基数设置”旁边的箭头才会展开
- **公积金账户入账**：显示的是“个人+公司”两部分的总和，而不仅仅是你的扣除

## 【三】核心结构拆解（学习重点）

**页面由四个关键模块组成：**

1. **输入控制模块**（左侧区域）
   - 职责：收集用户输入的薪资参数
   - 包含：数字输入框、滑块、可折叠的高级设置面板
   - 设计亮点：使用`x-model`实现数据双向绑定，输入变化立即反映到数据模型

2. **结果展示模块**（右上卡片）
   - 职责：突出显示核心计算结果
   - 包含：实发工资卡片、扣除汇总卡片
   - 设计亮点：使用视觉层次（字体大小、颜色）强调最重要的信息

3. **数据可视化模块**（中间图表）
   - 职责：用图形直观展示工资构成
   - 实现：使用Chart.js库创建环形图
   - 设计亮点：颜色编码（蓝色=实发，绿色=公积金等）让理解更直观

4. **明细列表模块**（底部表格）
   - 职责：提供详细的扣除项目清单
   - 设计：简洁的列表布局，带悬停效果

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入工资数字 → Alpine.js数据绑定更新 → calculate()函数触发计算 →
更新result对象 → 图表和所有显示区域自动更新
```

**最值得学习的设计：**
**响应式数据流** - 整个应用围绕一个核心数据对象（`result`）构建，任何输入变化都会触发重新计算，然后所有显示组件自动同步更新。这种“单一数据源”的设计让代码维护变得简单。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：这个网页没有使用AI或Prompt，但我们可以从“计算逻辑”的角度来理解类似的设计思路。

**计算逻辑在这个页面中扮演什么角色？**
它解决的是“**规则应用问题**”：将复杂的社保、税务规则转化为可执行的代码逻辑。

**哪些信息是关键变量？**
1. 社保比例（硬编码为8%、2%、0.5%）
2. 个税阶梯税率表（if-else判断链）
3. 起征点（5000元）

**如果只改计算逻辑，不改界面，会发生什么？**
- 修改社保比例 → 影响所有用户的扣除计算结果
- 调整个税起征点 → 改变免税人群范围
- 更新税率表 → 反映最新的税务政策变化

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：替换使用场景（最安全）**
保持完全相同的界面结构，只改变主题。例如：
- 改为“投资收益计算器”：输入本金、年化收益率、投资期限
- 改为“房贷计算器”：输入贷款总额、利率、年限
- 改为“热量消耗计算器”：输入运动类型、时长、体重

**第二步：调整输入字段**
根据新场景修改输入控件：
- 增加/减少输入项
- 改变控件类型（如把滑块改为下拉菜单）
- 调整标签文字和提示信息

**第三步：修改计算逻辑**
在`calculate()`函数中重写计算规则：
- 定义新场景的数学公式
- 更新`result`对象的属性名
- 确保输出数据与显示模块匹配

**第四步：定制可视化**
修改图表的数据和标签：
- 更新`chart.data.labels`和`datasets[0].data`
- 调整颜色方案匹配新主题
- 可考虑更换图表类型（如柱状图、折线图）

## 【六】3–5 个可直接尝试的改造方向

1. **增加城市选择功能**
   - 添加城市下拉菜单（北京、上海、深圳等）
   - 根据城市动态加载不同的社保比例和公积金上限
   - 实现方式：创建一个城市配置对象，根据选择切换参数

2. **添加专项附加扣除**
   - 增加输入项：子女教育、住房贷款利息、赡养老人等
   - 在个税计算前先减去这些扣除额
   - 效果：更准确地反映实际可享受的税收优惠

3. **实现年度视图切换**
   - 添加“月度/年度”切换按钮
   - 年度视图显示年终奖计税、年度汇算清缴估算
   - 图表可切换显示月度分布或年度累计

4. **增加数据持久化**
   - 使用localStorage保存用户上次输入
   - 页面加载时自动恢复设置
   - 可添加“保存方案”功能，支持多个预设配置

5. **优化移动端体验**
   - 调整布局为单列显示（移动设备）
   - 增大触摸目标（按钮、滑块）
   - 添加结果分享功能（生成图片或链接）

## 【七】这个网页不适合做什么？（边界提醒）

**局限性：**
1. **非精确税务工具**：使用标准比例估算，未考虑：
   - 各地社保政策差异
   - 社保缴费上下限（封顶线）
   - 公积金最高缴存限额
   - 专项附加扣除的复杂规则

2. **静态计算模型**：
   - 无法处理薪资结构变化（如底薪+绩效）
   - 不考虑年终奖的单独计税方式
   - 未包含其他扣除（如企业年金、补充医疗）

3. **无历史数据**：
   - 不能查看薪资变化趋势
   - 无法比较不同时间点的购买力

**如果你需要：**
- **精确的个税计算**：使用国家税务总局官方APP或网站
- **复杂的薪资规划**：使用专业的财务规划软件或咨询会计师
- **多城市政策对比**：查找各地人社局官方发布的最新比例表
- **长期财务模拟**：使用电子表格（如Excel）建立更灵活的模型
