# STAR 面试故事库 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你需要准备一场重要的面试，特别是行为面试时，你可能会感到无从下手。你有一些零散的经历（比如做过的项目、校园活动、实习），但不知道如何把它们组织成面试官爱听的、有说服力的故事。这个工具就像一个“面试教练”，帮你把零碎的经历，按照专业的“STAR（情境-任务-行动-结果）”结构，整理成可以直接用于面试的、高质量的故事库。

**适合什么情况？**
- **面试准备初期：** 你有很多经历，但不知道哪些相关、如何讲述。
- **转行或跨岗位求职：** 需要将过往经历与新岗位的胜任力要求进行匹配和包装。
- **希望提升面试表现：** 想让自己的回答更有结构、更专业、更能体现个人价值。
- **需要快速产出素材：** 在短时间内（如收到面试通知后）需要准备多个面试故事。

**不适合什么情况？**
- **需要完全虚构经历：** 它基于你提供的真实素材进行优化和结构化，而不是凭空创造。
- **替代深度思考和自我复盘：** 它辅助你整理，但故事的核心逻辑、细节和真实性仍需你自己把握。
- **高度定制化的专业领域：** 对于法律、医学等有严格行业术语和评估标准的领域，生成的内容可能需要你进行二次专业审核。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **目标岗位：** 你想应聘的职位名称（如“产品经理”、“数据分析师”）。
2.  **核心胜任力关键词：** 这个岗位需要的能力（如“沟通协调”、“数据分析”、“项目管理”）。
3.  **经历素材：** 你过去相关的项目、实习、校园活动等，哪怕只是零散的描述。

**用户通常会做哪几步操作？**
1.  **配置：** 首次使用时，点击右上角齿轮图标，在弹出的设置窗口中填入你的 DeepSeek API Key（需要自行申请）。
2.  **填写：** 在左侧面板依次填写上述三个输入框。
3.  **生成：** 点击“生成 STAR 故事”按钮。
4.  **查看与使用：** 在右侧面板查看生成的、格式清晰的故事库，可以复制、导出，用于面试准备。

**输出结果长什么样？**
输出是一个结构化的 Markdown 文档，通常包含：
- **多个 STAR 故事：** 每个故事都清晰地分为 Situation（情境）、Task（任务）、Action（行动）、Result（结果）四个部分。
- **胜任力标签：** 指明每个故事体现了哪些核心能力。
- **追问准备：** 预测面试官可能针对这个故事提出的深入问题，并给出回答要点。
- **总结版本：** 提供“30秒简述”和“2分钟详述”两种口径，方便你在不同面试环节使用。

**有哪些容易忽略的使用细节？**
- **模型切换：** 右上角有“V3”（标准模型）和“R1”（推理模型）按钮。R1 模型会展示“深度思考过程”，让你看到 AI 是如何分析你的经历的，但生成速度可能稍慢。
- **自定义提示词：** 在设置中，你可以追加自己的要求（如“请多使用数据量化成果”），这会让生成的故事更符合你的个性化需求。
- **导出功能：** 除了复制，还可以导出为 TXT 或 JSON 文件，方便存档和进一步编辑。
- **经历素材的写法：** 不需要写成完整句子，列出关键点、项目名称、你的角色、做了什么、取得了什么效果即可，AI 会帮你组织和润色。

## 【三】核心结构拆解（学习重点）

这个页面由三个清晰的功能模块组成：

**1. 输入配置模块（左侧面板）**
- **职责：** 收集用户的核心意图和原始材料。这是整个应用的“燃料”。
- **包含：** 三个输入字段（岗位、能力、经历）和两个操作按钮（生成、清空）。
- **逻辑：** 用户在此模块定义问题（“我要针对什么岗位，展示什么能力，基于什么经历”）。

**2. AI 处理与输出模块（右侧面板）**
- **职责：** 展示 AI 的工作成果，并提供成果的后续操作（复制、导出）。
- **包含：** 结果展示区、操作按钮组、以及可选的“深度思考过程”折叠面板。
- **逻辑：** 这是“价值呈现区”。AI 将左侧的输入，通过一套固定的 Prompt 逻辑，转化为结构化的、可直接使用的面试素材。

**3. 系统控制模块（设置面板 & 全局状态）**
- **职责：** 管理应用的“后台”配置，控制 AI 的行为。
- **包含：** API Key 设置、模型选择、自定义提示词输入。
- **逻辑：** 这个模块连接了前端界面和后台的 AI 服务，是应用能运行起来的“开关”和“调音台”。

**输入 → 处理 → 输出 的逻辑链路：**
1.  **输入：** 用户在左侧面板填写信息。
2.  **触发：** 用户点击“生成”按钮。
3.  **组装：** 前端代码将输入信息与预设的 Prompt 模板、自定义提示词拼接，形成完整的“指令”（Prompt）。
4.  **请求：** 通过 `fetch` API，将指令和 API Key 发送给 DeepSeek 的接口。
5.  **流式处理：** 接收 AI 返回的数据流，边接收边在页面上显示，提升体验。
6.  **解析与展示：** 将 AI 返回的 Markdown 文本解析并渲染成美观的格式，在右侧面板展示。如果使用推理模型，还会单独解析并展示“思考过程”。
7.  **输出：** 用户对生成的内容进行复制或导出。

**最值得学习的设计：**
**“配置与内容分离”的架构。** 将可变的用户配置（API Key、模型、自定义提示词）通过设置面板集中管理，并利用浏览器的 `localStorage` 进行持久化保存。这使得核心的生成逻辑非常干净，只需要关心如何组装 Prompt 和调用 API，而所有“环境变量”都被优雅地隔离和管理起来。这种模式在构建需要用户配置的 AI 工具时非常实用。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接用户输入和 AI 能力的“翻译官”和“任务说明书”。它把用户零散的“岗位”、“能力”、“经历”信息，翻译成 AI 能理解的、具体的、结构化的创作任务。

**它解决的是“理解问题”还是“生成问题”？**
**两者兼有，但更侧重于“生成问题”。**
- **理解部分：** Prompt 中的 `你是一名面试教练` 设定了 AI 的角色，`基于候选人经历与胜任力要求` 指明了分析的基础。这解决了“从什么角度理解这些输入信息”的问题。
- **生成部分：** `输出 STAR 面试故事库` 和后面详细的 `输出结构`，严格规定了 AI 需要生成的内容格式和组成部分。这解决了“生成什么样的具体内容”的问题。

**哪些信息是 Prompt 中的关键变量？**
Prompt 模板中有三个明确的“占位符”，会被用户输入实时替换：
1.  `目标岗位：${this.form.jobTitle}`
2.  `核心胜任力：${this.form.competencies}`
3.  `经历素材：${this.form.experiences}`
此外，`额外要求：${this.promptConfig.custom}` 也是一个可选的变量，让用户能微调生成方向。

**如果只改 Prompt，不改代码，会发生什么变化？**
整个应用的功能会发生**根本性改变**。例如：
- 将角色从“面试教练”改为“短视频脚本编剧”，将输出结构从“STAR故事”改为“脚本分镜”，这个工具就变成了一个“短视频创意生成器”。
- 在输出结构中增加“可能的风险与应对方案”，那么生成的故事就会附带风险评估部分。
- 改变语言，如将使用中文改为使用英文，那么整个输出就会变成英文。
**Prompt 是定义这个工具“是什么”和“做什么”的核心。** 代码只是提供了一个收集输入、发送 Prompt、展示结果的壳子。

## 【五】如何模仿它，做出你自己的版本？

这是一个低风险的“三步替换法”：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标：** 先做出一个能跑通的、属于你自己的工具。
- **操作：**
    1.  修改网页标题和界面中的文字（如将“STAR 面试故事库”改为“周报生成器”）。
    2.  修改左侧输入框的标签和提示语（如“目标岗位”改为“本周工作”，“经历素材”改为“详细工作内容”）。
    3.  修改右侧输出区域的标题（如“STAR 输出”改为“周报草稿”）。
- **此时效果：** 界面变成了一个新工具，但点击生成会得到奇怪的“面试故事”，因为核心的 Prompt 还没改。

**第二步：调整输入字段与核心 Prompt**
- **目标：** 让 AI 开始为你新场景工作。
- **操作：**
    1.  在代码中找到 `buildPrompt()` 函数。
    2.  彻底重写这个函数返回的字符串。这是最关键的一步。
    3.  **举例（周报生成器）：** 将 Prompt 改为：“你是一名高效的职场人士。请根据我提供的一周工作内容，生成一份专业、简洁的周报。工作内容：${this.form.workContent}。输出结构：1) 核心成果 2) 项目进展 3) 遇到的问题与解决方案 4) 下周计划。”
    4.  根据新 Prompt 的需要，回头微调第一步中输入的字段（可能只需要一个“工作内容”文本框）。
- **此时效果：** 你的工具已经可以基于新逻辑生成内容了。

**第三步：改变输出形式或交互细节**
- **目标：** 优化体验，让它更贴心。
- **操作：**
    1.  修改结果区域的默认占位图标的文案。
    2.  调整导出功能，比如将“导出 TXT”改为“导出 MD”（Markdown）。
    3.  可以增加新的交互，比如在生成的周报每条内容前增加复选框，方便用户勾选确认。
- **此时效果：** 一个完整、可用的自定义 AI 工具诞生了。

**从哪里下手最安全？**
从 **第一步的界面文字替换** 和 **第二步的 `buildPrompt()` 函数重写** 开始。这两步不涉及复杂的 JavaScript 逻辑，只是修改字符串，风险极低，且能立刻看到方向性的改变。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“角色预设”下拉选择框：**
    - **操作：** 在输入区增加一个下拉菜单，选项如“应届生”、“资深工程师”、“转行者”。
    - **融合：** 将这个选项作为变量加入到 `buildPrompt()` 中，例如“你是一名为[应届生]提供指导的面试教练...”。
    - **效果：** AI 会根据不同角色调整故事叙述的重点和详略。

2.  **集成多模型 API（如 OpenAI GPT-4o、Claude）：**
    - **操作：** 在设置面板的模型选择区域，增加其他模型的选项和对应的 API Key 输入框。
    - **修改：** 在 `streamChat()` 函数中，根据选择的模型，动态切换请求的 URL (`fetch` 的地址) 和请求头。
    - **效果：** 用户可以选择自己更熟悉或效果更好的模型，提升工具的灵活性。

3.  **增加“历史记录”页面：**
    - **操作：**
        - 新建一个 `history.html` 页面。
        - 每次生成完成后，将 `{输入，输出，时间戳}` 保存到 `localStorage` 的一个数组里。
        - 在历史页面读取并展示这个数组，支持查看和删除。
    - **效果：** 方便用户回顾和复用之前准备过的故事，形成个人知识库。

4.  **优化交互：增加“示例”按钮：**
    - **操作：** 在输入框旁边增加一个“填充示例”小按钮。
    - **逻辑：** 点击后，用一段预设的示例文本（如一个产品经理的示例经历）自动填充三个输入框。
    - **效果：** 极大降低新用户的学习成本，让他们立刻明白这个工具该怎么用。

5.  **实现“渐进式生成”或“编辑优化”：**
    - **操作：** 生成故事后，在每个故事卡片上增加“扩写”、“精简”、“改写”等按钮。
    - **逻辑：** 点击按钮时，将当前故事文本和操作指令（如“请将这段 Action 部分扩写得更详细”）作为新的 Prompt 发送给 AI。
    - **效果：** 从“一次性生成”升级为“交互式共创”，用户体验和专业度大幅提升。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为最终的、唯一的面试答案：** AI 生成的内容是模板化的起点，可能缺乏你个人独有的情感、细节和思考深度。**你必须**将其内化，加入自己的真实体会，并熟练背诵至自然。
- **不适合处理高度机密或敏感的经历：** 你的经历素材会通过互联网发送给第三方 AI 服务商。**切勿**输入涉及国家秘密、公司未公开技术细节、个人隐私等敏感信息。
- **不适合评估你的面试通过概率：** 这个工具只负责“包装”和“结构化”你的经历，无法判断你的经历与目标岗位的匹配度，更无法预测面试官的个人偏好和决策。
- **如果用户想做 X，应该换什么工具或方式：**
    - **想进行模拟面试对话：** 应该使用专门的模拟面试平台或寻找真人教练进行对练。
    - **想深度剖析自身职业优势劣势：** 应该使用专业的职业测评工具（如盖洛普优势识别器）或进行职业咨询。
    - **想确保生成内容 100% 准确无误（如法律条文引用）：** 应该由领域专家人工审核，AI 仅作为辅助检索或初稿生成的工具。
