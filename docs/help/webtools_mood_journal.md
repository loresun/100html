# 心情气象台 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你希望养成一个简单记录每日情绪的习惯，就像记日记一样，但更轻松、更直观。你不需要长篇大论，只想快速标记今天的心情，并可选地加上几句话和几个标签。同时，你也想回顾过去几天的情绪变化，看看有没有什么规律。这个“心情气象台”就是为你设计的。它像一个数字化的情绪日记本，帮你捕捉和回顾日常感受。

**适合情况：**
- 希望开始情绪觉察，但不想写长篇日记。
- 想追踪一段时间内的心情变化趋势。
- 需要一个简单、美观、无压力的个人记录工具。

**不适合情况：**
- 需要深度心理分析或专业情绪治疗（它只是一个记录工具）。
- 需要多人协作或分享记录（数据仅保存在本地浏览器）。
- 需要处理大量、复杂的结构化数据。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **心情选择**：从五个表情（😄 很开心、😊 开心、😐 一般、😔 难过、😢 很难过）中选一个代表今天的心情。
2.  **日记输入（可选）**：一个文本框，可以写下今天发生的事情或想法。
3.  **标签选择（可选）**：从预设的标签（如工作、学习、运动等）中点击选择，可以多选。

**用户通常会做哪几步操作？**
1.  打开页面，看到“今天的心情如何？”的提示。
2.  点击一个最能代表你心情的表情按钮。
3.  （可选）在下方文本框里写几句话。
4.  （可选）点击几个相关的标签。
5.  点击页面底部蓝色的“保存今日心情”按钮。
6.  保存后，可以在下方“心情历史”区域看到刚刚的记录，以及页面顶部的统计数据（总记录、连续天数等）会更新。

**输出结果长什么样？**
- **即时反馈**：你选择的心情表情会高亮显示（有彩色外圈）。
- **历史记录**：保存后，一条新的“卡片”会出现在“心情历史”顶部。卡片上包含你选择的表情、心情标签、日记内容、你选的标签以及日期。
- **统计数据**：页面中间有四个数据卡片，分别显示：总记录条数、连续记录天数、本周平均心情和最常出现的心情。

**有哪些容易忽略的使用细节？**
- **每天只能保存一条记录**：如果你今天已经保存过，再次点击“保存”会覆盖之前的记录，而不是新增一条。
- **数据保存在本地**：所有记录都保存在你当前浏览器的本地存储中。如果你清除了浏览器数据或换了设备，记录会丢失。
- **连续天数计算**：它是从今天开始往前数，看有多少天是连续有记录的。如果中间断了一天，就会重新计算。
- **标签可以取消**：点击已选中的标签可以取消选择。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个主要模块，它们协同工作：

1.  **输入与记录模块** (`Today's Mood` 区域)
    *   **职责**：收集用户当天的所有输入数据（心情、日记、标签）。
    *   **逻辑**：用户通过点击和输入完成数据填充 → 点击“保存”按钮 → 数据被整理成一个“记录对象” → 该对象被存入一个总的记录列表 (`entries`)。

2.  **数据存储与管理模块** (JavaScript 中的 `moodApp` 对象)
    *   **职责**：作为整个应用的大脑。它管理着所有记录 (`entries` 数组)，处理所有用户操作（选择、保存、删除），并将数据持久化保存到浏览器的 `localStorage` 中。
    *   **逻辑**：`init()` 函数在页面加载时从 `localStorage` 读取历史数据 → 用户操作（如 `saveMoodEntry`）更新内存中的 `entries` 数组 → `$watch` 监听 `entries` 的变化，并自动将其同步回 `localStorage`。

3.  **统计与展示模块** (`Stats` 和 `History` 区域)
    *   **职责**：对存储的记录数据进行计算和可视化呈现。
    *   **逻辑**：`entries` 数组是数据源 → 通过计算属性（如 `streakDays`, `weekAverageMood`）实时计算出统计数据 → 通过循环 (`x-for`) 将 `entries` 数组渲染成一条条历史卡片。

4.  **交互与状态模块** (Alpine.js 数据绑定)
    *   **职责**：将前三个模块无缝连接起来，实现页面的动态响应。
    *   **逻辑**：页面元素（按钮、输入框）通过 `x-model`、`@click` 与 JavaScript 中的变量（如 `selectedMood`, `journalText`）绑定 → 用户交互改变变量 → 变量改变自动触发页面相关部分的更新（如高亮选中心情、重新计算统计值）。

**最值得学习的设计：**
**“单向数据流 + 响应式绑定”的简洁实现。** 整个应用的状态（数据）集中存储在 `moodApp()` 返回的对象中。用户的操作（输入）只修改这些状态变量，而页面的显示（输出）则完全由这些状态变量驱动。这种模式（类似于 Vue/React 的核心思想）让代码结构非常清晰，数据变化和界面更新自动同步，是构建现代交互式网页的基石。这里使用 Alpine.js 以极简的方式实现了这一模式，非常适合学习和入门。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **注意**：当前提供的代码版本**没有**集成 AI 或调用任何 API。它是一个纯前端、本地运行的应用。因此，本节将基于“如果我们要为它添加 AI 分析功能，Prompt 会如何设计”的假设进行讲解，这本身也是一个重要的学习点。

**假设场景**：我们在“保存今日心情”后，增加一个“AI 分析今日心情”的按钮，点击后将日记和心情发送给 AI，请求一些洞察。

**Prompt 在这个页面中扮演什么角色？**
Prompt 将是向 AI 模型发出的“指令”和“问题”，它将用户原始的数据（心情数值、日记文本、标签）转化为一个具体的分析请求，引导 AI 生成有意义的反馈。

**它解决的是“理解问题”还是“生成问题”？**
两者兼有。它首先要让 AI **理解**当前记录的内容和上下文（例如，用户今天选择了“难过”，日记里写了“项目 deadline 压力大”），然后请求 AI **生成**一段鼓励的话、一个简单的建议或一个情绪模式观察。

**哪些信息是 Prompt 中的关键变量？**
1.  **用户的心情数值和标签**：例如 `mood: 2 (难过)`, `tags: [‘工作’]`。
2.  **用户的日记文本**：例如 `journal: “今天工作压力很大，感觉有点喘不过气。”`。
3.  **分析的具体要求**：例如“请用温暖、支持性的口吻，写一段简短的鼓励话语”或“基于这个记录，提供一个简单的小建议”。

**示例 Prompt 结构：**
```
你是一个贴心的情绪助手。请根据以下用户的心情记录，生成一段简短的回复。
- 心情状态：[Mood_Label]，对应数值 [Mood_Value]。
- 用户日记：[Journal_Text]
- 相关标签：[Tags_List]

请用 [Tone] 的语气，专注于 [Focus_Area]。回复不超过 3 句话。
```

**如果只改 Prompt，不改代码，会发生什么变化？**
如果我们已经有一个调用 AI API 的函数，那么只修改 Prompt 中的 `[Tone]`（如从“温暖支持”改为“理性客观”）或 `[Focus_Area]`（如从“提供鼓励”改为“分析可能原因”），AI 返回的内容风格和重点就会发生巨大变化，而应用的其他功能（记录、存储、展示）完全不变。这体现了将“业务逻辑”（Prompt设计）与“工程逻辑”（代码）分离的灵活性。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地从模仿走向创新：

**第一步：替换核心主题与数据（最安全）**
保持 HTML 结构和 JS 框架（Alpine.js）完全不变。
*   **改什么**：将“心情”记录改为其他每日可记录的事物。
*   **怎么做**：
    1.  修改 `moodOptions` 数组。例如，改成 `bookOptions`：`[{value: 5, emoji: ‘📖’, label: ‘受益匪浅’, color: ‘…’}, …]` 用于记录每日阅读感受。
    2.  修改 `tagOptions` 数组，换成与新主题相关的标签，如 `[‘小说’, ‘科技’, ‘历史’, ‘自我提升’]`。
    3.  修改页面上的所有文字：将“心情”改为“阅读感受”，“日记”改为“读书笔记”等。
    4.  修改统计模块的标题，如“本周平均”改为“本周平均阅读评分”。

**第二步：调整输入与输出形式**
在第一步的基础上，调整交互细节。
*   **改什么**：输入组件和数据显示方式。
*   **怎么做**：
    1.  **输入**：可以把心情选择的 5 个按钮改成星级评分（5颗星），或者一个滑动条。
    2.  **输出**：在历史记录卡片上，除了显示 emoji，还可以用进度条或图表来可视化数值（如 `value: 4` 显示为 4/5 的进度条）。
    3.  可以增加一个“图片上传”区域，用于记录与主题相关的照片（需要学习 `FileReader` API 来预览图片并保存为 Base64 字符串到 `localStorage`）。

**第三步：改变数据逻辑与功能**
进行更深度的定制，可能需要修改更多的 JavaScript 逻辑。
*   **改什么**：数据存储的结构和计算逻辑。
*   **怎么做**：
    1.  **复杂数据**：如果你的记录需要更多字段（如“地点”、“关联人物”），就在 `saveMoodEntry` 函数创建的 `entry` 对象里添加新属性。
    2.  **新的统计**：如果你想计算“本月正能量天数”，就在计算属性部分仿照 `streakDays` 写一个新的计算函数。
    3.  **数据分组**：在历史记录部分增加筛选功能，例如“只看带有‘工作’标签的记录”。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“心情原因”多选输入**：
    *   **操作**：在标签区域下方，新增一个“可能原因”的选择区，提供如“睡眠不足”、“人际冲突”、“达成目标”等选项。这能让记录更精细，也为未来分析提供更多维度数据。

2.  **集成 AI 生成“每日寄语”**：
    *   **操作**：在保存心情后，自动或通过一个按钮，将当天的心情和日记作为 Prompt 的一部分，调用 OpenAI 或文心一言等大模型的 API，生成一句鼓励或反思的话，并显示在历史卡片中。这是将纯记录工具升级为轻度互动助手的关键一步。

3.  **将单页应用拆分为“记录页”与“分析页”**：
    *   **操作**：创建两个 HTML 文件。`index.html` 专注于当天的记录输入和保存。`insights.html` 则读取同样的 `localStorage` 数据，专注于数据可视化，例如使用 Chart.js 绘制过去 30 天的心情折线图、标签分布的饼图等。这符合“单一职责”原则。

4.  **优化体验：增加动画与确认反馈**：
    *   **操作**：保存成功时，不要用生硬的 `alert`，而是改为在页面顶部或按钮位置显示一个优雅的、几秒后自动消失的提示条（Toast Notification）。删除记录时，可以让卡片先有一个淡出收缩的动画，再真正从列表中移除。这些小细节能极大提升应用质感。

5.  **更换或扩展数据存储方式**：
    *   **操作**：`localStorage` 有容量限制且无法跨设备同步。可以尝试集成一个轻量级的前端数据库，如 `dexie.js` (IndexedDB 封装)，来存储更多记录。或者，增加一个“导出数据为 JSON 文件”和“从文件导入”的功能，方便用户备份和迁移。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为专业的心理健康工具**：它没有临床验证，不能诊断任何心理状况，也无法提供专业治疗建议。如果你或他人需要心理支持，请寻求合格的心理咨询师或医生的帮助。
2.  **不适合团队协作或公开分享**：所有数据私有地存储在本地浏览器中，没有用户系统，没有后端服务器，因此无法安全地与他人共享你的心情记录。如果需要团队情绪打卡，需要开发完整的全栈应用。
3.  **不适合长期、大规模的数据分析**：`localStorage` 通常有 5-10MB 的限制，且在前端进行复杂的数据查询和分析效率较低。如果你计划记录数年数据并进行深度挖掘，应考虑使用后端数据库和专门的数据分析工具。
4.  **不适合需要严格数据隐私的场景**：虽然数据在本地，但任何能物理接触你设备的人都能看到浏览器存储的数据。对于极度敏感的情绪记录，此工具不具备加密等高级安全特性。

**总结**：这个“心情气象台”是一个出色的**学习范本**和**个人轻量级工具**。它清晰地展示了如何用现代前端技术构建一个美观、交互流畅的数据记录应用。你的学习重点应放在其模块化设计、响应式状态管理和数据流上，并以此为基础，探索更广阔的功能可能性。
