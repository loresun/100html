# 决策矩阵知识卡片 - 学习与模仿指南

--------------------------------

## 【一】这个网页解决了什么问题？

这个网页解决了一个常见的思维困境：**当面临多个选择时，如何避免凭感觉做决定，而是用系统化的方法做出更理性的决策**。

**使用场景举例：**
- 你正在考虑换工作，手上有3个offer，各有优缺点，难以取舍
- 团队需要采购新软件，有5个备选方案，功能、价格、服务各不相同
- 你想买辆车，预算内有多款车型，需要综合考虑油耗、空间、安全性等因素
- 项目资源有限，需要决定先推进哪个功能模块

**适合的情况：**
- 决策涉及多个相互冲突的标准（如价格vs质量）
- 需要在多个选项中做出选择
- 希望决策过程透明、可解释（特别是团队决策时）
- 想要减少决策中的情绪干扰

**不适合的情况：**
- 紧急情况需要立即行动
- 决策标准无法量化（如“感觉好不好”）
- 只有单一明确的最优解
- 需要创造性突破而非选择现有方案

## 【二】使用方式（给第一次接触的人）

**这不是一个交互式工具，而是一个“知识卡片”**——它的目的是教会你方法，而不是帮你计算。

**用户通常会做这几步：**
1. **阅读理解**：先看“内容解释”部分，了解决策矩阵是什么
2. **确认适用性**：查看“适用场景”，判断自己的问题是否适合用这个方法
3. **学习模型**：观察SVG模型图，理解矩阵的结构和计算逻辑
4. **按步骤实践**：按照“操作步骤”的7个步骤，在自己的实际问题中应用
5. **模仿练习**：可以拿一个简单问题（如“午餐吃什么”）练习一遍

**输出结果：**
- 对决策矩阵方法的理解
- 一个清晰的决策框架思维
- 知道如何在自己的问题中应用这个方法

**容易忽略的细节：**
- 权重分配是关键：很多人随意给权重，但实际上需要认真思考每个标准的重要性
- 评分要一致：对每个选项的评分要使用相同的标准
- 总分不是唯一依据：有时需要看各分项得分，了解选项的优缺点分布

## 【三】核心结构拆解（学习重点）

这个页面由**5个核心模块**组成，每个模块承担特定职责：

### 模块1：标题与概述（card-header）
- **职责**：建立第一印象，明确主题
- **设计亮点**：渐变色背景+大标题，视觉上突出“这是重要知识”
- **学习点**：如何用视觉层次引导用户注意力

### 模块2：概念解释（第一个section）
- **职责**：回答“这是什么”和“为什么有用”
- **包含**：定义描述 + 核心观点列表
- **学习点**：用列表形式分解复杂概念，让抽象理论变得具体可操作

### 模块3：适用场景（第二个section）
- **职责**：帮助用户联想“我什么时候能用这个”
- **设计亮点**：图标+文字的卡片式布局，直观展示应用领域
- **学习点**：如何用具体例子降低学习门槛

### 模块4：可视化模型（第三个section）
- **职责**：将抽象概念可视化
- **包含**：SVG绘制的决策矩阵示例
- **最值得学习的设计**：**用代码生成的教学图示**
  - 不是静态图片，而是可修改的SVG
  - 用颜色区分不同类型数据（标准、选项、总分）
  - 包含完整的计算示例（权重×得分=总分）
  - 有视觉引导（箭头指向最优选择）

### 模块5：操作步骤（第四个section）
- **职责**：提供可执行的行动指南
- **设计亮点**：带编号的步骤卡片，每一步都有明确说明
- **学习点**：如何将方法论转化为用户能跟做的步骤

**输入→处理→输出逻辑：**
- 输入：用户的决策问题（在用户脑中）
- 处理：页面提供框架和方法指导
- 输出：用户学会了方法，能自己解决问题

## 【四】Prompt / AI 逻辑是如何被设计的？

**重要说明：这个页面目前没有AI功能**，但代码中预留了接口。

**如果这是AI增强版本，Prompt会如何设计？**
假设我们要添加“AI帮你构建决策矩阵”功能：

1. **Prompt扮演的角色**：将用户模糊的问题转化为结构化的决策框架
   
2. **解决的是“理解问题”**：AI需要理解用户的决策场景，然后：
   - 识别可能的选项
   - 提取关键评估标准
   - 建议合理的权重分配

3. **关键变量**：
   ```text
   用户输入：{决策问题描述}
   → AI输出：
     选项列表：[选项1, 选项2, ...]
     标准列表：[标准1(权重), 标准2(权重), ...]
     评分指导：针对每个标准，如何评分（1-10代表什么）
   ```

4. **如果只改Prompt**：
   - 可以改变AI的“思维风格”：从“商业分析”变成“个人生活建议”
   - 可以调整输出的详细程度：从简要框架到详细解释
   - 可以改变建议的权重分配逻辑

## 【五】如何模仿它，做出你自己的版本？

### 最安全的模仿路径：

**第一步：保持结构不变，替换内容主题**
- 选择另一个思维模型（如“SWOT分析”、“PDCA循环”）
- 直接替换：标题、解释文字、适用场景、操作步骤
- **不要动CSS和HTML结构**，这是最安全的部分

**第二步：替换可视化部分**
- 如果新主题也有矩阵/表格，可以修改SVG中的文字和颜色
- 如果完全不同（如流程图），可以找现成的SVG或简单绘制
- **关键**：确保可视化与文字解释一致

**第三步：调整细节设计**
- 修改颜色主题（改`:root`中的颜色变量）
- 更换图标（到[lucide.dev](https://lucide.dev)找合适的）
- 调整间距、字体大小等微调

**具体例子：做“SWOT分析知识卡片”**
1. 标题改为“SWOT分析”
2. 解释部分描述SWOT是什么
3. 适用场景换成：创业规划、产品评估、个人发展等
4. 可视化改为2×2矩阵（优势/劣势 vs 机会/威胁）
5. 操作步骤改为SWOT的分析步骤

- 共用相同的CSS样式，保持一致性

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不是决策执行工具**
   - 它教你方法，但不帮你执行
   - 你需要自己收集数据、评分、计算

2. **无法处理高度不确定性问题**
   - 如果标准难以量化（如“团队文化匹配度”）
   - 如果选项信息不全（如新产品无历史数据）

3. **可能过度简化复杂决策**
   - 真实决策常有非理性因素
   - 人际关系、直觉等无法放入矩阵

### 如果用户想做这些，应该换什么：

**“我想直接输入我的选项，自动得到答案”**
→ 需要真正的决策支持工具，如：
   - 专业的决策软件（如Expert Choice）
   - 交互式Web应用（需后端计算）

**“我的决策涉及很多人的意见”**
→ 需要协作工具，如：
   - 在线表单收集各方评分
   - 团队投票系统
   - 讨论区+矩阵结合的工具

**“我需要考虑未来不确定性”**
→ 需要更高级的分析方法：
   - 情景规划（Scenario Planning）
   - 决策树分析
   - 蒙特卡洛模拟
