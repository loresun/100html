### **【智能内容日历规划师】学习与使用指南**

#### **【一】这个网页解决了什么问题？**

想象一下，你是一个自媒体运营者、内容创作者或市场专员。你每周都要为社交媒体（如公众号、小红书、抖音）规划发布内容。这个过程通常很痛苦：要绞尽脑汁想选题、安排发布时间、还要确保内容风格统一。这个网页就是你的“AI内容运营助理”。

*   **使用场景**：当你需要为一个特定账号（如“职场干货分享”），面向特定人群（如“0-3岁职场新人”），规划未来一周、一个月甚至更长时间的内容发布日历时，这个工具能帮你快速生成一份结构化的排期表，并让AI为每个选题撰写初稿。
*   **适合情况**：适合需要**批量、周期性**产出内容的自媒体、知识付费、品牌营销等场景。它帮你从“想点子”的焦虑中解放出来，专注于内容的打磨和优化。
*   **不适合情况**：不适合需要**即时、一次性**创作（如写一封邮件、一篇独立长文），或者对创意独特性、文学性要求极高的场景（如写小说、诗歌）。它生成的是“可用的初稿”，而非“完美的终稿”。

#### **【二】使用方式（给第一次接触的人）**

1.  **页面输入是什么？**
    *   **账号设定**：你的账号是做什么的（定位），写给谁看（目标人群）。
    *   **规划参数**：从哪天开始规划、规划多久、每周发几篇。
    *   **已有灵感**：（可选）你可以先输入一些自己的想法，AI会优先考虑。
    *   **API密钥**：首次使用需要在右上角设置中，填入你的DeepSeek API密钥（这是调用AI能力的“钥匙”）。

2.  **用户通常会做哪几步操作？**
    *   **第一步：配置**。填写左侧边栏的所有信息，特别是账号定位和API密钥。
    *   **第二步：生成排期**。点击“生成排期计划”。几秒后，主界面的日历上就会填满AI为你规划的每日选题（标题、形式、目标）。
    *   **第三步：查看与编辑**。点击日历上的任意一天，会弹出详情窗口。你可以在这里修改AI生成的选题细节（标题、钩子等）。
    *   **第四步：生成内容**。在详情窗口中，点击“生成正文内容”，AI会基于你修改后的选题，写出一篇完整的文案草稿。
    *   **第五步：批量操作**。如果你对全部排期满意，可以点击“批量撰写所有文案”，让AI自动为所有未写文案的选题生成内容，你只需等待。
    *   **第六步：导出**。使用顶部的按钮，将整个排期表（含文案）导出为CSV或Excel文件，方便后续使用。

3.  **输出结果长什么样？**
    *   **视觉上**：一个直观的月历视图，每天有几个“卡片”，卡片上显示标题、内容形式，已生成文案的会有绿色对勾。
    *   **内容上**：每个选题包含“标题、形式、目标、钩子”四要素，以及由AI生成的、格式清晰的Markdown正文。

4.  **有哪些容易忽略的使用细节？**
    *   **本地自动保存**：你所有的输入和生成的内容都会自动保存在浏览器本地，刷新页面不会丢失。
    *   **提示词配置**：右上角的“提示词配置”按钮非常重要。你可以在这里修改AI生成排期和文案的“指令”，从而控制AI的风格和质量。
    *   **批量生成**：这是一个“队列任务”，会依次处理所有未生成文案的选题。中途可以停止，进度会保留。
    *   **日历点击**：只有规划周期内的日期（非灰色区域）可以点击打开详情弹窗。

#### **【三】核心结构拆解（学习重点）**

这个页面采用了经典的“**配置区-展示区-详情弹窗**”三层结构，逻辑清晰，职责分明。

1.  **左侧配置面板（输入与控制器）**
    *   **职责**：收集用户的所有原始输入（账号信息、时间、频率等），并触发核心的“生成”动作。它是整个应用的“大脑”和“开关”。
2.  **中部日历视图（状态展示器）**
    *   **职责**：以最直观的“日历”形式，展示所有已生成的内容排期状态。每个格子是一个“状态快照”，通过颜色、图标（对勾）、数量提示用户当前进度。它是应用的“仪表盘”。
3.  **详情/生成弹窗（深度交互与输出器）**
    *   **职责**：当用户需要深入处理某一个具体选题时，这个弹窗提供了完整的操作界面。左侧用于编辑选题元数据，右侧用于展示AI生成的最终文案。它实现了从“规划”到“产出”的闭环。

**逻辑链路**：
`用户在左侧输入` → `点击“生成排期”` → `应用将输入拼接成Prompt，调用AI API` → `AI返回结构化数据（JSON）` → `应用解析数据，更新内存中的日历数据` → `触发日历视图重新渲染` → `用户点击某一天` → `弹窗打开，加载该日数据` → `用户点击“生成正文”` → `应用再次调用AI API` → `AI返回Markdown文案` → `应用渲染并展示在弹窗右侧`。

**最值得学习的设计**：
*   **数据与视图分离**：应用的核心是内存中的一个对象 `state.calendarData`，它以日期为键，存储所有数据。日历视图和详情弹窗都只是这个数据的不同“表现形态”。任何修改（AI生成、用户编辑）都先更新这个核心数据，再触发视图更新。这种模式让代码逻辑非常清晰。
*   **批量任务队列与并发控制**：“批量撰写”功能实现了一个简单的任务队列，并控制了并发数（同时处理3个任务），既提高了效率，又避免因请求过多导致API被限制。进度条和日志的实时反馈也提升了用户体验。

#### **【四】Prompt / AI 逻辑是如何被设计的？**

在这个页面中，Prompt是连接用户意图与AI能力的“**翻译官**和**约束框架**”。

1.  **扮演的角色**：它主要解决“**生成问题**”。它将用户模糊的需求（“帮我规划一个职场号的内容”）转化为AI可以执行的、结构化的具体任务。
2.  **关键变量**：
    *   **系统提示词（System Prompt）**：定义了AI的角色和核心任务规则。例如：“你是一位资深的新媒体内容运营专家...请严格按照以下JSON格式返回数据...”。
    *   **用户提示词（User Prompt）**：包含了本次请求的所有具体变量，如`账号定位`、`目标人群`、`规划周期`等。这些是从网页表单中动态获取并拼接而成的。
    *   **账号背景信息**：这是一个可选的、更详细的上下文，会被拼接到用户提示词中，让AI对账号有更深的理解。
3.  **只改Prompt的影响**：**效果立竿见影，且无需改动代码**。
    *   如果你把系统提示词中的“资深新媒体运营专家”改成“幽默的段子手”，AI生成的内容风格会大变。
    *   如果你在用户提示词模板里增加一个“避免使用网络流行语”的要求，AI的输出就会更正式。
    *   如果你修改了JSON格式的要求，AI返回的数据结构就会变，但**前端代码可能因无法解析新格式而报错**。这说明Prompt设计需要与代码的数据处理逻辑相匹配。

#### **【五】如何模仿它，做出你自己的版本？**

这是一个绝佳的“**场景替换**”练习模板。请按以下安全路径操作：

*   **第一步：保持结构不变，替换使用场景**（最安全）。
    *   不要动任何HTML和JS代码。只改文字。
    *   将“智能内容日历规划师”改为“**我的每周健身计划器**”。
    *   将“账号定位”改为“**健身目标**”（如：增肌、减脂），“目标人群”改为“**自身情况**”（如：办公室久坐、新手）。
    *   将“选题标题”改为“**训练项目/食谱**”，“形式”改为“**训练类型/餐别**”，“目标”改为“**训练目标/营养目标**”。
    *   现在，它就变成了一个AI健身计划生成器！

*   **第二步：调整输入字段和Prompt**。
    *   在左侧边栏增加或删除几个输入框。例如，增加“**每日可用时间**”、“**可用器械**”。
    *   相应地，去`defaultPrompts`对象里修改提示词，告诉AI这些新信息的意义和如何使用它们。
    *   修改生成正文的Prompt，让AI从“写文案”变成“写详细的训练动作说明或食谱做法”。

*   **第三步：改变输出形式或展示方式**。
    *   如果你觉得日历视图不适合健身计划，可以把主区域的`calendar-grid`改成周计划列表（每周一栏）。
    *   修改`renderCalendar`函数，让它渲染列表而不是网格。
    *   这一步涉及JS DOM操作，是进阶学习点。

**从哪里下手最安全？** 从**第一步**开始。仅仅通过修改界面文字和两个核心Prompt，你就能在30分钟内创造出一个全新的工具。这会给你巨大的成就感。

#### **【六】3–5 个可直接尝试的改造方向**

1.  **增加内容“标签”或“分类”功能**：
    *   在详情弹窗的选题信息里，增加一个“标签”输入框（如：#干货 #案例 #互动）。
    *   在日历视图的卡片上，显示这些标签。这样一眼就能看出一个月的内容类型分布是否均衡。
    *   **如何做**：在`calendarData`的每个`item`对象里增加一个`tags: []`字段，在渲染时将其展示出来。

2.  **接入多模型API，并实现“AI画廊”对比**：
    *   除了DeepSeek，在API设置里增加OpenAI GPT、Claude等选项。
    *   在生成正文时，可以同时调用2-3个模型，在详情弹窗右侧以标签页形式并列展示它们的输出，让用户对比选择。
    *   **如何做**：复制`callDeepSeek`函数，改写成`callOpenAI`、`callClaude`。在生成内容时，并行调用它们，并将结果分别渲染。

3.  **拆解为“规划”与“执行”两个独立页面**：
    *   页面一（规划页）：只负责生成和调整排期日历。完成后，点击“进入执行阶段”。
    *   页面二（执行页）：以“任务看板”形式展示（待写/写作中/已完成）。每天登录后，直接来这里处理当天的任务，体验更专注。
    *   **如何做**：将`index.html`复制一份为`execute.html`。在规划页增加一个跳转链接，并通过URL参数或`localStorage`传递规划好的数据到执行页。

4.  **优化交互：增加“灵感池”与拖拽安排**：
    *   在左侧增加一个“灵感池”区域，用户或AI可以随时往里面添加零散的选题想法。
    *   允许用户将“灵感池”中的想法直接拖拽到日历的任意一天中，实现可视化排期。
    *   **如何做**：使用HTML5的拖放API（Drag and Drop）。在`state`中增加一个`ideaPool: []`数组，并实现对应的拖放事件处理函数来更新`calendarData`。

#### **【七】这个网页不适合做什么？（边界提醒）**

*   **不适合做精确的、事实性强的专业内容创作**：例如撰写法律文件、医疗报告、学术论文。AI可能生成看似合理但存在事实错误或逻辑漏洞的内容，需要领域专家严格审核。
*   **不适合替代深度创意和策略思考**：它生成的是基于模式和已有信息的“组合”与“延伸”，无法替代人类独有的洞察、情感表达和突破性创意。它是最好的“副驾驶”，但不是“驾驶员”。
*   **不适合无目的的内容生成**：如果你自己都不清楚账号的定位和目标，输入模糊的信息，只会得到模糊、平庸的结果。**Garbage in, garbage out**（垃圾进，垃圾出）的原则在这里同样适用。
*   **如果用户想做**：需要高度原创、带有强烈个人风格或情感深度的文学创作。
*   **应该换什么工具**：应该使用更专注于创造性写作的AI工具（如专门的小说生成器），或者回归到传统的写作流程中，将AI仅作为头脑风暴和克服写作障碍的辅助工具。
