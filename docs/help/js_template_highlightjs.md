# Highlight.js 代码高亮工具 - 帮助文档

--------------------------------

## 【一】这个网页解决了什么问题？

这个网页是一个**代码高亮展示与体验工具**。想象一下，你正在写技术博客、制作教学课件，或者需要在网页上展示一段代码。为了让代码更易读、更美观，你需要为不同编程语言的代码块添加颜色和样式。这个网页让你无需搭建复杂环境，就能快速预览不同主题风格下的代码高亮效果，并直接获取可复用的代码片段。

**适合场景：**
- 技术博主在撰写文章前，预览代码在不同主题下的显示效果。
- 开发者为自己项目的文档页面，挑选合适的代码高亮配色方案。
- 新手学习如何在网页中集成代码高亮功能，并有一个直观的参考。
- 需要快速复制一段格式优美的示例代码到自己的项目中。

**不适合场景：**
- 它不是代码编辑器，不能运行或调试代码。
- 它不是版本控制系统，不能管理代码的修改历史。
- 如果需要处理超长代码文件或进行复杂的语法分析，它可能不是最佳选择。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **预设代码**：页面已经提供了JavaScript、Python等四种语言的示例代码。
2.  **主题选择**：页面顶部有一排主题按钮（如Atom One Dark、GitHub Dark）。
3.  **自定义区域**：一个可以让你输入任意代码的文本框，以及一个选择编程语言的下拉菜单。

**用户通常会做哪几步操作？**
1.  **浏览与预览**：打开页面，首先看到的是几个不同语言、已经高亮好的代码块。你可以直接欣赏它们在不同配色下的效果。
2.  **切换主题**：点击顶部的不同主题按钮（如“Monokai”、“Dracula”），页面上所有代码块的颜色主题会立即切换。这是最直观的体验。
3.  **复制代码**：在任何代码块的右上角点击“📋 复制”按钮，该代码块的纯文本内容（不带颜色格式）会被复制到你的剪贴板。
4.  **自定义高亮**：在页面下方的“自定义代码高亮”区域：
    - 在下拉菜单中选择一种编程语言（如“Python”）。
    - 在左侧的文本框中输入或粘贴你自己的代码。
    - 点击“高亮”按钮，右侧区域会立即显示经过语法高亮处理后的结果。

**输出结果长什么样？**
- 输出就是**带有丰富色彩、根据语法结构着色的代码块**。例如，关键字是蓝色，字符串是绿色，注释是灰色。它看起来就像你在专业IDE（如VS Code）里看到的代码一样。
- 自定义高亮的结果会实时显示在右侧的预览框中。

**有哪些容易忽略的使用细节？**
- **主题切换是全局的**：你切换一个主题，页面上**所有**的代码块（包括预设示例和自定义结果）都会一起改变。这方便你统一评估主题效果。
- **复制的是纯文本**：“复制”按钮复制的是代码的原始文本，而不是带有HTML标签的高亮版本。这通常是你想要的，方便粘贴到编辑器里。
- **自定义后仍需切换主题**：在自定义区域高亮完代码后，如果你切换了页面顶部的主题，自定义区域的代码**也会随之改变主题**。这是一个联动的效果。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个职责明确的模块：

1.  **主题控制模块**
    - **位置**：页面顶部“选择主题”区域。
    - **职责**：管理整个页面的视觉风格（配色方案）。它存储了不同主题CSS文件的链接。
    - **逻辑**：用户点击按钮 → 函数`changeTheme()`被调用 → 替换页面中Highlight.js的CSS主题文件链接 → 页面所有代码样式刷新。

2.  **静态示例展示模块**
    - **位置**：页面中部的四个代码卡片（JavaScript, Python, TypeScript, HTML）。
    - **职责**：作为样板间，直观展示不同语言在高亮后的效果。每个卡片都包含语言标签、复制功能和代码内容。
    - **逻辑**：页面加载时，`hljs.highlightAll()`自动执行 → 识别`<code>`标签上的`language-xxx`类 → 应用高亮。

3.  **动态交互模块**
    - **位置**：“自定义代码高亮”区域。
    - **职责**：提供用户输入接口，并实时处理和高亮用户提供的代码。这是页面的“ playground ”（游乐场）。
    - **逻辑**：用户输入代码并选择语言 → 点击“高亮”按钮 → `highlightCustom()`函数调用`hljs.highlight()`API处理字符串 → 将返回的HTML结果插入到右侧预览区域。

4.  **辅助信息模块**
    - **位置**：“支持的语言”和“使用方法”区域。
    - **职责**：提供产品功能说明（支持哪些语言）和技术集成指南（如何在自己的项目中使用Highlight.js）。这是页面的“文档”部分。

**最值得学习的设计：**
**“配置与演示一体化”**。这个页面完美地将**配置项（主题）**、**静态演示（示例代码）**和**动态交互（自定义高亮）**结合在一起。用户每做一个选择（切换主题），都能立刻在所有演示案例上看到效果，这种即时反馈极大地提升了工具的实用性和教学价值。它不仅仅是一个功能页面，更是一个自包含的、可体验的说明书。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **重要提示**：当前这个网页**没有使用AI或Prompt**。它完全基于前端库（Highlight.js）的规则进行语法高亮。这是一个很好的对比案例：它展示了如何用**确定的规则和库**来解决一个结构化问题（代码着色）。

**我们可以将其逻辑类比为“规则引擎”：**
- **“规则”的角色**：Highlight.js库内置了190多种语言的语法规则（比如如何识别`if`语句、字符串、注释）。这些规则代替了“Prompt”，告诉程序如何分析代码文本。
- **它解决的是“理解问题”**：引擎需要“理解”一段文本中哪些部分是关键字、哪些是字符串，然后根据这个理解给不同部分打上标签（`<span class="hljs-keyword">`）。
- **关键变量**：在这个页面中，用户提供的**代码文本**和选择的**编程语言**，就是输入给这个“规则引擎”的关键变量。
- **如果只改“规则”**：如果我们不用Highlight.js，而换用另一个高亮库（比如Prism.js），页面的外观和效果可能会完全不同，因为背后的“规则”（语法解析方式）和“样式”（CSS类名）都变了。但页面的交互结构（主题切换、自定义输入）可以完全不变。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你自己的工具页面：

**第一步：替换核心内容，保持骨架不变（最安全）**
- 保留页面的整体布局：标题区、控制区、展示区、自定义区。
- **替换“静态示例”**：将JavaScript、Python的示例代码，换成你想展示的内容。比如，你想做一个“诗歌格式展示器”，就把代码换成不同体裁的诗歌（绝句、律诗、十四行诗）。
- **替换“支持的语言”**：将编程语言标签，换成你的内容分类标签，如“唐诗”、“宋词”、“现代诗”。

**第二步：调整交互逻辑和“规则引擎”**
- **修改“自定义区”的输入**：将语言选择下拉框`<select>`，改为体裁或风格选择框。
- **核心改造**：你需要找到或编写一个能处理你新内容的“高亮引擎”。例如，对于诗歌，你可能需要一个能自动标出“押韵字”、“平仄”的简单处理器。最初可以用一个简单的函数，只是给不同行涂上不同颜色。**这一步是用你自己的逻辑替换掉`hljs.highlight()`函数。**

**第三步：改变视觉主题和输出形式**
- **修改“主题”**：主题按钮不再切换代码高亮CSS，而是切换整个页面的配色方案，或者诗歌文字的字体、背景图。
- **调整输出样式**：改变`<pre>`和`<code>`标签的样式，让它们看起来不像代码框，而像一张精美的诗笺或卡片。

**从哪里下手最安全？**
从**第一步**开始最安全。先只改动HTML中那些你看得懂的、静态的文字和示例内容，不要动JavaScript。这样你能立刻得到一个外观不同但功能完好的页面，建立信心。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“主题预览图”或“主题描述”**：
    - **操作**：在每个主题按钮上，增加一个小色块，显示该主题的主色调。或者在鼠标悬停时，用一个小弹窗展示该主题的名字和简介（如“Atom One Dark: 深色主题，源自Atom编辑器”）。
    - **目的**：让用户在选择前对主题有更直观的认知，提升决策效率。

2.  **将“语言选择”升级为“智能检测”**：
    - **操作**：在自定义区域，增加一个“自动检测语言”的按钮。点击后，可以调用一个简单的本地检测函数（例如，根据`def`、`function`等特征词猜测），或调用一个轻量级API（需注意隐私），然后自动设置下拉框选项。
    - **目的**：提升工具的便捷性和科技感。

3.  **拆分页面，创建“主题画廊”和“代码库”**：
    - **操作**：制作两个页面。一个页面专门用于**浏览和比较所有主题**，同一段代码用所有主题并列显示。另一个页面作为**代码片段库**，分类展示更多语言的示例代码，并允许收藏。
    - **目的**：让功能更专注，信息架构更清晰。

4.  **优化交互体验**：
    - **操作**：为“自定义输入”文本框添加更多功能。例如：① 在右下角显示字数或行数。② 添加“清空”按钮。③ 实现按`Ctrl+Enter`快捷键触发“高亮”按钮。
    - **目的**：让核心交互更流畅、更符合用户习惯。

5.  **增加“导出”功能**：
    - **操作**：在自定义高亮结果区域，增加一个“复制为HTML”按钮。点击后，可以将高亮后的完整HTML结构（包含所有`<span>`标签）复制到剪贴板，方便用户直接粘贴到支持HTML的编辑器（如WordPress）。
    - **目的**：拓宽工具的使用场景，从“预览”延伸到“生产”。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为在线代码编辑器或IDE**：它不能运行代码、没有语法错误提示、没有代码补全、也不能调试。如果你需要编写和测试代码，请使用 [CodePen](https://codepen.io/)、[JSFiddle](https://jsfiddle.net/) 或本地开发环境（如VS Code）。
- **不适合高亮非标准或极其冷门的语言**：尽管支持190多种语言，但如果你使用的是一门非常小众或自定义的领域特定语言（DSL），Highlight.js可能没有对应的规则，高亮效果会很差或无效。这种情况下，你可能需要为其编写自定义语法规则。
- **不适合处理超长文档**：这个页面将所有处理放在浏览器前端。如果粘贴数万行的代码文件，可能会导致页面暂时卡顿，影响体验。对于长篇文档，更好的方式是在服务器端进行高亮处理，再发送给浏览器。
- **不适合需要深度定制语法规则的场景**：这个页面主要展示和切换**主题**（颜色）。如果你想彻底改变某种语言的语法高亮逻辑（例如，把所有的变量名用粗体显示），仅通过这个页面是做不到的，你需要深入研究并修改Highlight.js的底层语言定义文件。
