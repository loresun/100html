# PPT 连续图像生成器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你需要为一个重要的汇报制作PPT。你已经有了核心想法，但构思每一页的内容、标题、要点，并为每一页寻找风格统一、高质量的配图，这个过程非常耗时且需要创意。这个网页就是为了解决这个痛点而设计的。

**使用场景：**
*   **快速构思：** 当你有一个模糊的主题，需要快速生成一个结构清晰、逻辑完整的PPT大纲时。
*   **视觉统一：** 当你需要为PPT的每一页生成风格一致、连贯的配图，而不是东拼西凑风格各异的图片时。
*   **原型制作：** 在正式设计PPT之前，快速生成一个包含文字大纲和视觉草图的演示原型，用于内部讨论或获取反馈。

**不适合的情况：**
*   **需要精细排版和动画的最终PPT：** 它生成的是图像和文字大纲，不是可直接交付的PPTX文件。
*   **对图像有极高艺术性或特定版权要求：** 生成的图像基于AI模型，风格和细节可能不完全可控，且不适合直接用于商业成品。
*   **完全离线或没有API密钥的环境：** 它依赖外部AI服务，需要网络和有效的API密钥才能工作。

## 【二】使用方式（给第一次接触的人）

1.  **准备输入：**
    *   **API密钥：** 你需要准备至少一个AI服务的API密钥（如DeepSeek的，用于生成大纲）。
    *   **主题想法：** 想好你的PPT要讲什么，比如“新能源汽车市场分析”或“公司季度团队建设方案”。

2.  **操作步骤：**
    *   **第一步（配置与生成大纲）：**
        1.  在“配置中心”填写你的DeepSeek API密钥。
        2.  在“Step 1”区域，填写你的演示主题、期望页数、受众和风格基调。
        3.  点击 **“生成 PPT 大纲”**。稍等片刻，页面左侧的“大纲编辑区”就会列出生成的每一页标题、要点和初始的图片描述建议。
        4.  你可以在“大纲编辑区”自由修改每一页的标题、要点和图片提示词，让它更符合你的需求。
    *   **第二步（生成连续图像）：**
        1.  点击页面顶部的“步骤 2”标签页，切换到图像生成界面。
        2.  在“配置中心”填写用于生成图像的API密钥（OpenRouter或Google）。
        3.  在“Step 2”区域，设置你想要的统一视觉风格（如“科技蓝、扁平化插图”）和图片比例（如16:9）。
        4.  点击 **“开始生成连续图像”**。系统会按照大纲的顺序，一页一页地生成图片，并努力让前后图片的风格保持一致。
    *   **查看结果：** 所有生成的图片会显示在页面底部的“生成结果预览”区域。你可以看到每一页对应的图片。

3.  **输出结果长什么样？**
    *   **大纲：** 一个可编辑的列表，包含每页的标题、文字要点和图片提示词。
    *   **图像：** 一组尺寸统一、视觉风格连贯的图片，每张图都对应大纲中的一页内容。

4.  **容易忽略的使用细节：**
    *   **API密钥本地保存：** 你填写的API密钥只会保存在你自己的浏览器里，不会被上传到任何服务器，刷新页面后依然存在。
    *   **连续性强度滑块：** 在Step 2中，这个滑块控制着后一张图片参考前一张图片的程度。调高会让风格更统一，调低则给单张图片更多创作自由。
    *   **编辑大纲：** 在生成图像**之前**，务必在“大纲编辑区”仔细检查和修改图片提示词，这直接决定了最终图像的内容和质量。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为五个职责明确的模块：

1.  **配置管理模块（配置中心）**
    *   **职责：** 集中管理所有外部服务的连接信息（API密钥、模型选择）。它负责将配置保存到本地，并在不同功能间同步这些设置。
    *   **逻辑：** 用户输入配置 → 保存至 `localStorage` → 其他模块调用配置进行API请求。

2.  **大纲生成与编辑模块（Step 1 & 大纲编辑区）**
    *   **职责：** 接收用户对PPT的抽象描述（主题、页数等），调用文本AI（DeepSeek）生成结构化的内容大纲，并提供界面让用户进行精细化编辑。
    *   **逻辑：** 用户输入主题信息 → 拼接成Prompt → 调用DeepSeek API → 解析返回的JSON → 渲染为可编辑的卡片列表。

3.  **图像生成控制模块（Step 2）**
    *   **职责：** 接收用户对图像风格的统一要求（风格说明、比例、连续性强度），并协调整个连续出图流程。
    *   **逻辑：** 用户设置风格参数 → 触发生成 → 按顺序遍历大纲，为每一页构建图像Prompt → 调用图像生成API。

4.  **图像生成执行模块（`callImageApi`函数）**
    *   **职责：** 这是一个“引擎”，负责根据不同的供应商（OpenRouter/Google）将统一的请求参数转换为具体的API调用格式，并处理响应。
    *   **逻辑：** 接收Prompt和上一张图 → 根据供应商选择组装特定格式的请求体 → 发送请求 → 解析响应，提取图片数据。

5.  **结果展示模块（生成结果预览）**
    *   **职责：** 以网格画廊的形式清晰展示所有生成的结果，并附上页码和生成时使用的Prompt，方便追溯。

**最值得学习的设计：**
**“状态驱动的分步工作流”与“数据模型的桥接”**。页面通过一个核心的 `outlineSlides` 数组对象，将“AI生成的大纲”、“用户编辑后的内容”和“最终图像生成所需的Prompt”三者流畅地连接起来。`step` 变量控制视图切换，让复杂的多步操作变得清晰。这种设计让每个模块职责单一，数据流转明确，非常易于理解和扩展。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个页面中，Prompt是驱动两个AI步骤的“指令脚本”。

1.  **在大纲生成中（解决“生成问题”）：**
    *   **角色：** 扮演一位“专业PPT架构师”。
    *   **关键变量：** 用户输入的主题、页数、受众、风格基调被动态插入到Prompt模板中。
    *   **作用：** 它指导AI**生成**一个结构化的JSON数据，而不是泛泛而谈。系统指令“你只输出JSON数组”至关重要，确保了返回结果能被程序直接解析和使用。

2.  **在图像生成中（解决“理解与连续生成问题”）：**
    *   **角色：** 每一页图像的“视觉需求说明书”。
    *   **关键变量：** 当前页的标题、要点、用户编写的图片提示词，以及全局的“统一视觉风格说明”。`continuityStrength` 参数则通过API底层机制实现连续性，而非直接写在Prompt里。
    *   **作用：** 它指导AI**理解**当前页需要什么画面，并**结合**上一张图的视觉特征进行创作。Prompt中“保持与上一张图像风格一致，画面连续”这句话是给AI的明确指示。

**如果只改Prompt，不改代码：**
*   **改大纲Prompt：** 你可以让AI以不同的角色（如“小学教师”、“投资人”）来构思大纲，或者改变输出的结构（例如增加“演讲者备注”字段）。这会直接改变生成大纲的风格和内容维度。
*   **改图像Prompt模板：** 你可以调整描述画面的语言风格，例如加入更多艺术流派关键词（“梵高风格”、“赛博朋克”），或者改变构图指令的优先级，这会显著影响最终图像的审美取向。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的AI工具：

**第一步：替换核心场景，保持骨架**
*   **目标：** 做一个“短视频分镜脚本生成器”。
*   **操作：** 将“PPT大纲”的概念整体替换为“视频分镜”。把“页数”改成“镜头数”，“标题”改成“场景”，“要点”改成“动作/对白”，“图片提示词”改成“画面描述”。前端的标签文字全部对应修改，但标签、输入框、按钮的布局和交互逻辑完全不变。

**第二步：调整数据模型与Prompt**
*   **目标：** 让AI生成适合短视频脚本的数据。
*   **操作：** 修改 `outlineInput` 对象，增加“视频时长”、“目标平台”等字段。重写 `generateOutline` 函数中的Prompt，例如：“你是一位短视频编剧，请生成一个包含X个镜头的分镜脚本JSON，每个镜头包含scene（场景）、action（动作）、dialogue（对白）、visual_desc（画面描述）...”。
*   **安全提示：** 此时先只修改Prompt和前端显示字段，确保能生成和显示新的JSON结构，先不要动图像生成部分。

**第三步：改变输出与展示方式**
*   **目标：** 让结果更符合“分镜”的呈现方式。
*   **操作：** 图像部分可以暂时保留或改为其他功能。你可以把“生成结果预览”模块改成一个“分镜脚本表格”或“故事板视图”，把每一镜的文字描述和生成的图像并排展示。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“灵感库”或“风格预设”**
    *   **操作：** 在“风格基调”或“统一视觉风格说明”输入框旁边，增加一个下拉菜单或按钮组，内置一些写好的Prompt片段，如“【科技感】蓝紫色调、流光线条、未来主义”、“【温馨手绘】水彩质感、柔和光线、可爱插画”。用户点击即可填入，降低使用门槛。

2.  **拆分并优化“图像生成”策略**
    *   **操作：** 目前是严格顺序生成，一张失败则中断。可以改为：
        *   **队列生成：** 将所有页的任务加入队列，允许用户暂停、继续或重试失败的单页。
        *   **并行生成（无连续性时）：** 如果用户不需要连续性，可以同时发起多个请求，大幅缩短等待时间。

3.  **增加“PPT导出”功能**
    *   **操作：** 在结果预览区增加一个“导出为PPTX”按钮。点击后，可以使用前端的 `PPTXGenJS` 这类库，将 `outlineSlides` 中的文字和 `generatedImages` 中的图片（需转为Blob URL）自动排布到PPT的每一页，生成一个可下载的文件。

4.  **引入更便宜的图像生成API**
    *   **操作：** 在“图像供应商”选项中增加“Stable Diffusion via xxx”的选项。修改 `callImageApi` 函数，增加对新API（如SD的WebUI API或Replicate）的适配。这可以为你或用户提供更低成本的出图选择。

5.  **增强大纲编辑的交互**
    *   **操作：** 为“大纲编辑区”的每一页卡片增加“上移/下移”按钮来调整顺序，增加“删除”按钮，以及“使用AI优化此页提示词”的小按钮（针对单页再次调用AI进行润色）。这让工具从“半自动”向“交互式助手”进化。

## 【七】这个网页不适合做什么？（边界提醒）

*   **不适合制作最终交付的商务PPT：** 它缺乏专业的排版、字体管理、图表绘制、动画设置和公司模板套用等功能。生成的图像分辨率可能不适合大型喷绘，且AI生成内容在严肃商业场景中的版权归属存在争议。
    *   **应该怎么做：** 将本工具作为**构思和素材准备阶段**的利器。将生成的大纲和图片导入到PowerPoint、Keynote或Canva中，进行专业的二次设计和排版。

*   **不适合需要精确控制图像细节的场景：** 比如，你需要一幅包含特定公司Logo、特定人物肖像或复杂数据图表的图片。当前的文生图模型很难做到像素级的精确控制。
    *   **应该怎么做：** 对于这类需求，应使用专业的图形设计软件（如Photoshop、Illustrator），或结合“图生图”与“局部重绘”功能更专业的AI绘图工具。

*   **不适合完全无AI使用经验的用户直接使用：** 它需要用户自行申请和管理API密钥，理解Token消耗和费用，并能编写有效的图片提示词（Prompt）。
    *   **应该怎么做：** 如果你是面向小白的工具，需要考虑集成代理服务或提供更详细的引导教程，甚至内置免费的额度。
