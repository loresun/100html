# 《今天吃什么》帮助与学习文档

---

## 【一】这个网页解决了什么问题？

想象一下，你和朋友站在餐厅门口，或者打开外卖软件，面对无数选择却毫无头绪。这个网页就是为这种“选择困难症”时刻设计的。它像一个数字化的“转盘”或“抽签筒”，帮你从预设的菜单中随机挑选一个选项，打破僵局。

**适合场景：**
- 日常用餐（午餐/晚餐）决策
- 朋友聚餐时快速达成一致
- 个人想尝试新事物但不知从何开始
- 作为一个小工具，增加生活趣味性

**不适合场景：**
- 需要详细营养分析或热量计算
- 根据特定食材或预算进行复杂筛选
- 需要生成全新的、从未想过的菜谱创意（它只从已有列表中选择）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个内置的默认菜单（如红烧肉、披萨等）。
- 你可以通过“菜单管理”添加、删除菜品。
- 可以通过顶部的标签（如“中餐”、“西餐”）进行筛选。

**用户通常会做哪几步操作？**
1.  **初次打开**：页面中央会显示一个困惑的表情（🤔）和提示文字。
2.  **点击“帮我选一个”**：页面会模拟一个快速滚动的动画，然后随机定格在一道菜上，显示菜名、图标和标签。
3.  **（可选）筛选**：如果你今天只想吃“中餐”或“轻食”，可以点击上方对应的标签按钮，将其点亮。下次随机选择时，只会从符合标签的菜品中挑选。
4.  **（可选）管理菜单**：点击右上角的列表图标（≡），可以打开“菜单管理”面板。在这里你可以添加自己喜欢的菜（如“番茄炒蛋”），或删除不喜欢的菜。

**输出结果长什么样？**
选择完成后，页面中央会清晰展示：
- 一个大的食物表情图标（如 🍕）
- 醒目的菜名（如“披萨”）
- 一个代表分类的彩色小标签（如“西餐”）

**有哪些容易忽略的使用细节？**
- **标签筛选是“与”关系**：如果你同时选中了“中餐”和“聚餐”，系统会寻找同时拥有这两个标签的菜。由于默认菜单中标签是唯一的，所以通常只点一个标签即可。
- **添加新菜时的自动图标**：当你添加新菜时，系统会根据菜名中的关键字（如“肉”、“面”、“饭”、“鸡”）自动分配一个表情图标，这是一个贴心但简单的小功能。
- **数据会保存**：你对菜单的任何增删改操作，都会自动保存在你的浏览器本地。下次打开网页，你的个性化菜单还在。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个模块，各司其职：

1.  **展示模块 (Main Stage)**
    - **职责**：作为视觉焦点，显示当前状态（等待选择 / 选择结果）。
    - **逻辑**：初始显示引导文案和图标 → 用户点击选择 → 播放动画 → 显示最终结果（包含 `name`, `icon`, `tag`）。
    - **设计亮点**：使用了平滑的过渡动画（`x-transition`）和微动效（`bounce-slow`），让结果的出现更有仪式感和趣味性，提升了用户体验。

2.  **控制模块 (Controls)**
    - **职责**：接收用户的核心指令（开始选择）和次要指令（筛选）。
    - **逻辑**：一个主按钮触发 `spin()` 函数 → 筛选按钮组管理 `selectedTags` 数组。
    - **设计亮点**：主按钮有明确的交互反馈（点击缩放、加载旋转动画），状态文字（“帮我选一个”/“正在选择...”）清晰。

3.  **数据管理模块 (Menu Management Modal)**
    - **职责**：提供对核心数据（`foods` 数组）的增、删、改、查（CRUD）功能，并持久化保存。
    - **逻辑**：通过一个弹窗（Modal）管理 `foods` 数组 → 任何改动自动同步到 `localStorage`。
    - **设计亮点**：将复杂的数据管理功能收纳在一个可开关的弹窗内，保持了主界面的简洁。`localStorage` 的使用让工具具备了“记忆”能力。

4.  **逻辑与状态模块 (Alpine.js Data)**
    - **职责**：这是整个应用的大脑。它定义了所有数据（`foods`, `selectedTags`, `result`）和方法（`spin()`, `addItem()`），并处理它们之间的联动。
    - **逻辑链路**：
        `用户点击按钮` → `spin()方法被调用` → `根据selectedTags过滤foods数组得到候选池` → `模拟动画循环选取` → `最终确定一个结果并更新result变量` → `展示模块因result变化而自动更新界面`。
    - **最值得学习的设计**：**“响应式数据驱动UI”**。这是现代前端框架的核心思想。开发者只需要关心如何修改 `result`、`foods` 这些数据，而页面中带有 `x-text`、`x-show` 的元素会自动更新。这比直接用JavaScript去操作DOM元素要清晰和高效得多。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个网页的当前版本中，**并没有使用AI或Prompt**。它的核心逻辑是**基于规则的随机选择**。

- **它解决的是“选择问题”而非“生成问题”**：它不创造新内容，只是在你提供的选项中做随机决策。
- **“伪Prompt”**：你可以把用户**点击筛选标签**的行为，看作是在向系统输入一个简单的“提示”或“指令”，例如：“从‘中餐’里给我选一个”。
- **关键变量**：`selectedTags` 数组就是这里的“关键变量”，它决定了随机选择的范围。

**如果我们要为它加入AI，Prompt可能会如何设计？**
假设我们想让它根据“冰箱里的食材”来推荐菜，那么Prompt设计可能是：
> “我拥有[用户输入的食材，如：鸡蛋、番茄、米饭]。请从以下菜单中：`[foods数组]`，推荐一道最可能用上这些食材的菜。只返回菜名的JSON格式，如：`{“name”: “...”}`。”

**如果只改Prompt，不改代码，会发生什么？**
在现有代码框架下，只改Prompt（即改变筛选或生成的逻辑）是行不通的，因为根本没有调用AI的代码。但这句话提醒我们：**这个应用的结构（数据管理、UI展示）和AI逻辑层是解耦的**。你完全可以保留漂亮的界面和交互，只把 `spin()` 函数里那个简单的 `Math.random()` 选择逻辑，替换成调用AI API并根据复杂Prompt返回结果的逻辑。

## 【五】如何模仿它，做出你自己的版本？

这是一个经典的“随机选择器”模板。你可以遵循以下路径，安全地创造出自己的版本：

**第一步：替换核心概念与数据（最安全）**
- **目标**：做一个“今天看什么电影”、“今天听什么歌”、“周末去哪玩”选择器。
- **操作**：
    1.  修改标题（`<title>` 和 `<h1>` 里的文字和图标）。
    2.  替换 `defaultFoods` 数组。把 `name` 换成电影名、歌名、景点名，把 `icon` 换成对应的表情（🎬、🎵、🏞️），把 `tag` 换成类型（科幻、摇滚、公园）。
    3.  修改界面文字，如“不知道吃什么？”改为“不知道看什么？”。

**第二步：调整输入与筛选逻辑**
- **目标**：让筛选条件更符合你的新场景。
- **操作**：
    1.  如果电影选择器，`tag` 可以改为“时长”（短/中/长）或“氛围”（轻松/烧脑）。
    2.  在 `addItem()` 函数中，调整自动分配 `icon` 的逻辑关键字（例如，名字含“侠”给🎭，含“战”给💥）。

**第三步：改变输出展示形式**
- **目标**：让结果展示更丰富。
- **操作**：
    1.  在结果区域，除了 `name` 和 `icon`，可以增加更多字段。例如，电影选择器可以显示“推荐理由”或“豆瓣评分”（需要在数据对象中增加 `reason` 或 `rating` 属性）。
    2.  修改结果区域的HTML结构，用 `<p x-text="result.reason"></p>` 来显示新字段。

完成这三步，一个全新的、属于你的随机选择器就诞生了，而它的“骨骼”（状态管理、交互流程）依然健壮。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加权重或偏好系统**：
    - **操作**：在 `foods` 数组的每个对象里增加一个 `weight: 5` 属性（数字越大，被选中的概率越高）。修改 `spin()` 函数中的随机算法，使其成为加权随机。
    - **效果**：让你更喜欢的菜有更高几率出现，决策更“智能”。

2.  **接入AI，实现智能推荐**：
    - **操作**：在 `spin()` 函数中，将 `selectedTags` 和 `foods` 数组作为上下文，调用像 OpenAI 这样的AI API。Prompt 可以是：“用户今天想吃 `[selectedTags.join(‘, ‘)]` 类别的食物。请从以下菜单`[foods.map(f=>f.name)]`中，综合考虑美味、新鲜感和用户可能的口味，推荐一道菜。只返回菜名。”
    - **效果**：从“随机选”升级为“智能荐”，增加惊喜感和实用性。

3.  **增加“历史记录”与“排除近期”功能**：
    - **操作**：新增一个 `selectedHistory` 数组，每次选择后把结果ID存进去。在 `spin()` 过滤候选池时，排除最近N次选择过的菜品。
    - **效果**：避免连续几天吃到同样的东西，促进菜单消费的多样性。

4.  **优化交互体验**：
    - **操作**：为选择结果增加“再来一次”、“就吃这个了！（确认）”按钮。确认后，可以将结果以更醒目的方式固定，甚至生成一张带有菜名和图标的海报图片供分享。
    - **效果**：增强决策的终结感和分享的趣味性。

5.  **拆分为“发现”与“管理”两个页面**：
    - **操作**：将“菜单管理”弹窗的内容独立成一个新的HTML页面（如 `manage.html`）。在主页面只保留选择和展示功能，通过链接跳转到管理页面。
    - **效果**：使应用结构更清晰，适合菜单项非常多的复杂场景。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为专业的菜谱或营养工具**：它不提供烹饪步骤、食材清单、营养成分。如果你需要这些，应该使用“下厨房”、“薄荷健康”等专业应用。
- **不适合解决复杂的多约束决策**：例如“需要满足3人预算低于100元、包含一荤一素、且30分钟内能送达”。这种问题需要更复杂的过滤器和数据库查询，本工具简单的标签系统无法胜任。
- **不适合生成全新的创意**：它的本质是从已有库中抽样，而非无中生有。如果你需要“用冰箱里剩余的奇怪食材发明一道新菜”，你需要的是像ChatGPT这样的生成式AI对话工具。
- **不适合多人实时协作选择**：所有数据保存在本地你的浏览器里。如果想让朋友一起投票或实时看到你的选择，你需要开发后端服务和实时通信功能。

**总结**：这是一个**优雅地解决简单日常问题**的典范。它通过极致的专注（只做随机选择）、优秀的用户体验（动效、反馈）和可扩展的结构，成为了一个绝佳的学习模板和实用小工具。现在，你可以开始动手，用它作为基石，构建出解决你特定烦恼的个性化应用了。
