# AI Draw.io 绘图师 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你需要快速画一个流程图、系统架构图或组织结构图，但你不熟悉专业的绘图工具（如 Draw.io 的复杂操作），或者你只有文字描述，不知道如何开始。这个网页就像一个“会画图的翻译官”，你只需要用自然语言告诉它你想要什么图，它就能自动生成可编辑的图表文件。

**适合在什么情况下使用？**
- **快速原型设计：** 在会议或头脑风暴中，需要立刻将想法可视化。
- **学习辅助：** 想了解某个概念（如“三层架构”）的图示，但不想自己画。
- **文档制作：** 为你的报告、博客或项目文档快速生成配套图表。
- **轻度修改：** 对现有图表进行颜色、文字或布局的调整。

**不适合什么情况？**
- **高精度专业绘图：** 如果需要像素级精确控制、复杂自定义样式或大量交互逻辑，应使用专业的 Draw.io 桌面版或 Figma。
- **离线环境：** 它依赖 AI API 生成图表，没有网络无法工作。
- **完全替代人工设计：** 对于审美要求极高或需要独特创意设计的图表，AI 生成的结果可能仍需人工调整。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **核心输入：** 页面左侧的大文本框。在这里用文字描述你想画的图。
2.  **辅助输入：** 右上角的齿轮按钮（⚙️）里，需要填写你的 AI API 密钥和选择模型。

**用户通常会做哪几步操作？**
1.  **准备：** 点击右上角⚙️，填入你的 AI API 密钥（例如 DeepSeek 的密钥）并保存。
2.  **描述：** 在左侧文本框中，用清晰的语言描述图表。例如：“画一个用户登录系统的流程图，包含输入框、验证、成功和失败分支。”
3.  **生成：** 点击下方的 **“生成图表”** 按钮。
4.  **查看与调整：** 等待几秒后，右侧画布会显示出生成的图表。如果满意，可以使用下方的按钮下载或复制图表代码。如果不满意，可以：
    *   直接修改描述文字，再次点击“生成图表”。
    *   或者点击 **“对话修改”** 按钮，用聊天的方式告诉 AI 如何调整，比如“把所有的矩形变成圆角”或“给数据库节点标上红色”。

**输出结果长什么样？**
- **主输出：** 一个在右侧画布中渲染出的、可交互预览的图表（可以缩放、拖动画布）。
- **可导出的文件：** 一个标准的 `.drawio` 文件（本质是 XML），可以用 Draw.io 桌面或在线版打开和编辑。
- **可复制的代码：** 生成图表的原始 XML 源代码。

**有哪些容易忽略的使用细节？**
1.  **API 密钥是必须的：** 第一次使用前，**务必**先去设置面板填写有效的 API Key，否则无法生成。
2.  **描述越具体越好：** “画一个流程图”太模糊。“画一个包含开始、处理、判断、结束四步的流程图”效果更好。
3.  **版本历史：** 点击左上角的时钟按钮（🕐），可以查看所有生成过的图表版本，并能一键切换回旧版本。
4.  **加载本地文件：** 除了用 AI 生成，你也可以直接上传本地的 `.drawio` 或 `.xml` 文件进行查看和后续的“对话修改”。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为五个模块，像一个高效的生产线：

1.  **控制中心模块（左侧面板）**
    *   **职责：** 接收用户的“绘图意图”。包含描述输入框、生成按钮和文件上传入口。它是整个应用的“需求接收站”。
2.  **渲染展示模块（右侧画布）**
    *   **职责：** 可视化呈现图表。它使用 Draw.io 的官方 Viewer 库，将 XML 代码“画”成图形。是最终的“成果展示厅”。
3.  **AI 引擎模块（不可见，但最关键）**
    *   **职责：** 理解自然语言并生成专业代码。它不直接出现在页面上，但通过 API 调用工作。它是核心的“翻译官”和“代码生成器”。
4.  **会话与历史模块（侧边面板）**
    *   **职责：**
        *   **会话面板（对话修改）：** 提供迭代式修改的交互界面，让调整图表像聊天一样自然。
        *   **历史面板：** 记录每一次操作，提供“撤销/重做”到任意版本的能力。这是应用的“记忆中枢”。
5.  **配置管理模块（设置面板）**
    *   **职责：** 管理应用的外部依赖（API 地址、密钥、模型）。确保 AI 引擎能正常工作。

**逻辑链路：**
`用户描述（文本）` → `控制中心模块` → `（拼接Prompt）` → `AI 引擎模块` → `（生成XML代码）` → `渲染展示模块` → `（呈现图表）`
同时，`生成的XML` → `被保存到` → `历史模块`

**最值得学习的设计：**
**“对话式迭代”设计。** 它不仅支持“从头生成”，更通过“对话修改”功能，将一次性的生成变成了一个可循环、可引导的协作过程。用户无需重新描述整个图表，只需说“把那个改一下”，AI 就能基于现有图表进行修改。这极大地提升了工具的实用性和友好度，是 AI 应用交互设计的优秀范例。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是连接“用户模糊想法”和“精确图表代码”的**蓝图和指令集**。它严格规定了 AI 应该如何思考、输出什么格式、遵守什么规则。

**它解决的是“理解问题”还是“生成问题”？**
**两者都是，但更侧重于“生成问题”。** 它首先要让 AI 理解“用户想要一种图表”，但更关键的任务是约束 AI，让它必须输出**特定格式（Draw.io XML）、特定结构、且可直接使用的代码**，而不是一段描述图表的文字。

**哪些信息是 Prompt 中的关键变量？**
1.  **角色设定：** “你是一个 Draw.io (mxGraph) XML 生成专家。” —— 锁定 AI 的身份。
2.  **输出格式规则：** “直接输出 XML 代码，**不要使用 markdown 代码块**” —— 强制纯净输出，便于程序直接处理。
3.  **XML 结构模板：** 给出了从 `<mxfile>` 到 `</mxfile>` 的完整示例，包括属性要求。这是质量的保证。
4.  **样式与布局指南：** “使用标准的 mxGraph 样式”、“确保节点位置合理分布，**不要重叠**” —— 提升生成图表的美观度和可用性。
5.  **任务上下文：** 在“修改”模式下，Prompt 会包含“这是当前的 XML”和“用户的修改要求”，让 AI 在已有作品上工作。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个应用的能力，而无需写一行 JavaScript：
*   **改变图表类型：** 修改 Prompt，让 AI 生成 **PlantUML**、**Mermaid** 或 **Graphviz** 的代码，这个工具就瞬间变成了其他图表语言的生成器。
*   **改变风格：** 在 Prompt 中强调“使用黑白极简风格”或“所有形状填充渐变色彩”，生成的图表视觉风格会随之改变。
*   **增加规则：** 加入“必须包含版权水印文本”或“所有连线必须带箭头”，AI 就会在生成的代码里遵守这些新规则。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的 AI 工具：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **目标：** 做一个“AI 思维导图生成器”。
*   **操作：**
    1.  复制整个 HTML 文件。
    2.  修改标题和说明文字，如改为“AI MindMap 生成器”。
    3.  修改左侧输入框的提示语，如“描述你的思维导图中心主题和分支...”。
    4.  **最关键的一步：** 修改 `systemPrompt` 变量中的内容。将角色改为“思维导图 XMind/Markdown 生成专家”，将输出规则改为生成特定的思维导图文件格式（如 `.xmind` 的 XML 结构或纯 Markdown 列表）。你不需要懂这些格式的具体细节，可以先让 AI 帮你写一个基础版的 Prompt。
    5.  此时，你的应用已经能“生成另一种东西”了。

**第二步：调整输入字段或 Prompt**
*   **目标：** 让生成更可控。
*   **操作：**
    1.  在左侧面板增加几个下拉菜单或输入框，例如“主题风格”（商务/创意/简约）、“颜色主题”、“布局方向”。
    2.  修改 JavaScript 中拼接用户输入和 Prompt 的逻辑，将这些新参数也加入到发送给 AI 的消息中。例如：`请生成一个具有【商务】风格、【蓝色系】颜色主题的思维导图，描述如下：${用户描述}`。
    3.  这一步让你从“单一描述”进化到“带参数的描述”，生成结果更精准。

**第三步：改变输出形式或展示方式**
*   **目标：** 让结果展示更符合新场景。
*   **操作：**
    1.  如果生成的是 Markdown 格式的思维导图，你可以将右侧的 Draw.io 渲染器替换为一个 Markdown 渲染库（如 `marked.js`），并美化其样式。
    2.  或者，如果生成的是 `.xmind` 文件，可以保留下载功能，但将预览区改为一个简单的文件图标和说明，提示用户下载后使用专业软件打开。
    3.  这一步让你的应用从“内部预览”变得“形式匹配”，体验更完整。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“示例库”或“灵感按钮”：**
    *   **操作：** 在输入框下方增加一排按钮，如“流程图”、“时序图”、“ER图”。点击后，自动在输入框填入对应的优质描述模板（如：“生成一个描述 HTTP 请求过程的时序图，包含客户端、服务器和数据库”）。
    *   **效果：** 降低用户起步难度，同时也能保证输入描述的质量，让 AI 生成效果更好。

2.  **切换后端 AI 模型或 API：**
    *   **操作：** 在设置面板的“模型选择”下拉框中，增加 OpenAI 的 `gpt-4o`、Anthropic 的 `claude-3` 或国内的其他大模型选项。同时修改 `getApiConfig` 函数和 `fetch` 请求的格式，以适配不同 API 的细微差别（如 headers 和 body 结构）。
    *   **效果：** 用户可以根据成本、速度或对某模型生成代码的偏好自由选择，工具适用性更广。

3.  **将“对话修改”拆分为独立的“优化工作流”：**
    *   **操作：** 在“操作”面板增加“优化布局”、“检查样式”、“翻译为英文”等专用按钮。每个按钮背后对应一个精心编写的、特定任务的 Prompt（例如，优化布局的 Prompt 是：“请重新排列以下 XML 中的节点，使其布局更加对称、紧凑，消除不必要的空白区域。”）。
    *   **效果：** 将开放的聊天指令转化为封闭的、效果更可控的专项优化工具，提升专业性和效率。

4.  **增加“分享与协作”功能：**
    *   **操作：**
        1.  增加一个“生成分享链接”按钮，点击后将当前图表的 XML 压缩并编码，附加到当前 URL 的哈希（`#`）后面。
        2.  页面加载时，检查 URL 哈希，如果有数据则自动解码并渲染图表。
    *   **效果：** 用户可以将一个生成的图表通过一个链接直接分享给他人查看，无需对方安装任何软件，实现了轻量级协作。

5.  **本地模型集成（高级）：**
    *   **操作：** 利用 WebLLM 或 Ollama Web API 等技术，在设置中增加“使用本地模型”选项。当用户选择此选项时，将 API 请求发送到本地运行的模型服务（如 `http://localhost:11434/api/generate`）。
    *   **效果：** 为注重隐私或想在无网络环境使用的用户提供可能，是工具功能的重要延伸。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合生成高度艺术化或非标准图表：**
    *   **局限性：** AI 基于常见的图表规范和数据进行训练，对于抽象艺术、复杂信息图或完全自定义的视觉隐喻，生成能力有限。
    *   **应换工具：** 此类需求应使用 Adobe Illustrator、Canva 或专业的数据可视化库（如 D3.js）进行手动设计。

2.  **不适合处理实时数据或动态图表：**
    *   **局限性：** 它生成的是静态的 XML 定义文件。图表内容在生成那一刻就固定了，无法根据外部数据源（如数据库、API）实时更新。
    *   **应换工具：** 需要动态图表应使用 Tableau、Power BI，或编程使用 ECharts、Chart.js 等库。

3.  **不适合作为生产环境的核心图表编辑工具：**
    *   **局限性：** 它的编辑功能依赖于 AI 理解并重新生成，对于细微、频繁的手动调整效率很低。且预览器的编辑功能被禁用。
    *   **应换工具：** 正式的、需要精细编辑的图表制作，应直接使用 Draw.io、Lucidchart、Microsoft Visio 等专业工具。

4.  **不适合在无网络或 API 配额耗尽时使用：**
    *   **局限性：** 核心的生成功能完全依赖外部 AI API 服务。
    *   **应换方案：** 离线时，你只能使用其“加载本地文件”进行查看。请确保在关键工作前检查网络和 API 余额。
