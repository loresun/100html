## 【一】这个网页解决了什么问题？

**使用场景：**
假设你是一名内容创作者，需要为小红书平台制作一套风格统一、视觉精美的多图笔记。你有一个不错的主题（比如“极简主义家居好物”），但你不懂设计，也不想花几个小时在 Photoshop 或 Canva 里一张张地排版。这个工具就是你的“AI 设计助手”。你只需要输入主题，它就能帮你规划出整套笔记的结构（大纲），然后为每一页自动生成可以直接使用的、符合小红书 3:4 比例的 HTML 设计稿，并最终导出为高清图片。

**适合什么情况？**
- 需要快速批量生产风格统一的社交媒体配图。
- 没有专业设计技能，但希望产出有设计感的内容。
- 希望将文字内容（大纲、文案）快速转化为视觉稿。
- 需要探索同一主题下的多种视觉表现形式。

**不适合什么情况？**
- 需要像素级精确控制的设计（如品牌 VI 规范）。
- 需要复杂交互或动态效果的网页。
- 对图片质量要求极高（如商业印刷品），因为 AI 生成的图片来自随机图库。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **创作主题**：你想创作的内容核心，例如“周末露营装备清单”。
2.  **参考资料（可选）**：可以粘贴一些相关的文章、数据或补充说明，让 AI 生成的内容更准确。
3.  **全局设计风格**：描述你想要的视觉风格，如“多巴胺配色，活泼可爱”。你可以点击“随机”按钮让 AI 推荐一个。

**用户通常会做哪几步操作？**
1.  **配置 API**：首次使用，点击右上角“API 设置”，填入你的 DeepSeek API Key。
2.  **生成大纲**：输入主题后，点击“1. 生成大纲卡片”。AI 会规划出 4-6 张卡片的标题、内容和视觉建议。
3.  **编辑大纲**：在生成的每张卡片正面，你可以自由修改标题、核心内容和视觉建议。
4.  **生成设计**：点击单张卡片上的“生成此页设计”，或直接点击左侧的“2. 批量生成设计”，AI 会为每张大纲生成对应的 HTML 视觉稿。
5.  **预览与导出**：卡片会自动翻转，展示设计效果。你可以点击悬浮按钮“保存”单张图片，或点击左侧“导出所有图片”批量下载。

**输出结果长什么样？**
- **大纲阶段**：一个可编辑的卡片列表，每张卡片包含文字内容。
- **设计阶段**：每张卡片翻转后，会显示一张精美的、符合 3:4 比例的“图片”。这张“图片”实际上是一个用 HTML+CSS 渲染的网页，包含了排版、文字、颜色和背景图。
- **最终文件**：导出后得到一系列 PNG 图片（例如 `xhs_card_1.png`），尺寸为 1200x1600 像素（高清），可以直接上传到小红书。

**有哪些容易忽略的使用细节？**
- **API 设置是第一步**：不设置 API Key，所有生成功能都无法使用。
- **设计风格提示词很重要**：`全局设计风格` 这个输入框直接决定了最终卡片的美观程度。描述得越具体（如“莫兰迪色系，大量留白，使用衬线字体”），效果越好。
- **卡片是双面的**：正面（大纲模式）和背面（设计模式）通过翻转切换。生成设计后，鼠标悬停在设计稿上才会显示操作按钮。
- **可以手动编辑 HTML**：对 AI 生成的设计不满意？点击设计稿上的“编辑”按钮，可以进入代码编辑器直接修改 HTML 和 CSS，所见即所得。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，像一个高效的内容生产线：

**1. 控制面板模块（左侧边栏）**
- **职责**：接收用户的核心指令（主题、风格），并触发核心生产流程。
- **输入**：用户输入的主题、参考资料、设计风格描述。
- **处理**：将用户的自然语言指令整理成给 AI（DeepSeek API）的“任务描述”（Prompt）。
- **输出**：触发“生成大纲”和“批量生成设计”两个核心动作。

**2. 卡片工作区模块（右侧主区域）**
- **职责**：承载和展示从“文字大纲”到“视觉设计”的完整工作流。
- **子模块1：大纲编辑器**（卡片正面）
    - 展示和编辑由 AI 生成或用户自定的每页内容（标题、文案、视觉提示）。
    - 这是内容的“草稿”阶段。
- **子模块2：设计预览器**（卡片背面）
    - 渲染由 AI 根据大纲和风格生成的 HTML 代码，并模拟最终图片效果。
    - 这是内容的“成品”阶段。
- **巧妙的交互**：卡片翻转的动画，物理性地分隔了“编辑”和“预览”两种状态，体验非常直观。

**3. 服务与输出模块（背后逻辑）**
- **职责**：与 AI 通信，并将 HTML 转换为可用的图片。
- **AI 通信层**：调用 `callDeepSeek` 函数，将结构化的 Prompt 发送给 API，获取 JSON（大纲）或 HTML 代码（设计）。
- **渲染与导出层**：利用 `html2canvas` 库，将渲染好的 HTML 元素“截图”成 PNG 图片。

**最值得学习的设计：**
**“双阶段 Prompt 工作流”**。这是本页面的灵魂。
- **第一阶段 Prompt（生成大纲）**：要求 AI 返回一个结构化的 JSON，包含 `design_style` 和 `outline`。这相当于让 AI 先担任“内容策划”。
- **第二阶段 Prompt（生成单页设计）**：利用第一阶段的结果（`design_style` 和每张卡片的详情），要求 AI 担任“前端工程师”，输出可执行的 HTML 代码。
这种“策划 → 执行”的分工，将复杂任务拆解，让 AI 在每一步都目标明确，极大提高了输出结果的质量和可控性。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是给 AI 的“详细工作说明书”。它不是一个简单的问题，而是一个包含了**角色设定、任务背景、具体要求和输出格式**的完整指令集。

**它解决的是“理解问题”还是“生成问题”？**
两者都是，但更侧重于 **“生成问题”**。它的核心目标是引导 AI 生成**特定格式**的创造性内容（JSON 大纲 或 HTML 代码），而不仅仅是理解用户的输入。

**哪些信息是 Prompt 中的关键变量？**
1.  **用户输入**：`${input.topic}`, `${input.reference}`, `${card.title}`, `${card.content}` 等。这些是内容的原材料。
2.  **系统指令**：如“你是一个前端设计专家”、“返回一个 JSON 对象”、“只返回 HTML 代码”。这些控制了 AI 的角色和输出格式。
3.  **技术约束**：如“使用 Tailwind CSS”、“严禁使用 oklch, lch, lab 等现代颜色格式”。这些确保了生成结果的可用性（能被 `html2canvas` 正确转换）。

**如果只改 Prompt，不改代码，会发生什么变化？**
- **改变内容方向**：修改大纲生成的 Prompt，可以让 AI 规划“科普教程”而非“好物推荐”的结构。
- **改变设计风格**：在设计生成的 Prompt 中强化或修改风格描述，会直接影响卡片的配色、字体和布局。
- **改变输出格式**：例如，要求 AI 在 HTML 中加入特定的 CSS 类名，你就可以在前端代码中为这些类名预定义新的动画效果。
**Prompt 是控制 AI 行为的“软开关”**，修改它是成本最低、效果最直接的改造方式。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从安全到创新）：**

**第一步：替换“场景”和“外壳”**
- **目标**：理解整个数据流，但不改变核心逻辑。
- **操作**：
    1.  将“小红书笔记”替换为另一个固定比例的场景，如“手机壁纸（9:18.5）”、“公众号头图（2.35:1）”。
    2.  修改页面标题、Logo 和文字描述，将“卡片”改称为“壁纸”或“头图”。
    3.  **保持**：左侧的控制面板结构、卡片的翻转交互、生成与导出逻辑完全不变。

**第二步：调整输入字段和 Prompt**
- **目标**：让工具为你关心的领域服务。
- **操作**：
    1.  修改左侧输入框的标签和提示语。例如，将“创作主题”改为“壁纸主题”，“参考资料”改为“情绪关键词”。
    2.  **最关键的一步**：修改 `generateOutline` 和 `generateCardHtml` 函数中的 Prompt 文本。根据你的新场景，重新描述你对 AI 的期望。例如，为“手机壁纸”生成 Prompt：“你是一个视觉艺术家，请生成一套具有沉浸感和美感的手机壁纸设计，要求简洁、有焦点，避免文字过多...”

**第三步：改变输出形式或展示方式**
- **目标**：优化最终产品的体验。
- **操作**：
    1.  修改导出图片的尺寸（调整 `html2canvas` 中的 `width` 和 `height`）。
    2.  改变右侧工作区的布局，比如从网格列表变为横向滑动条，更适合预览长图。
    3.  在导出时增加水印选项或自定义文件名格式。

**从哪里下手最安全？**
**从修改 `input.topic` 的提示文字和 `generateOutline` 函数中的 Prompt 开始。** 这不会破坏任何程序逻辑，却能立刻改变 AI 生成内容的类型，让你最快看到效果，建立信心。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“视觉参考图”上传功能**：
    - **操作**：在控制面板添加一个文件上传按钮，允许用户上传1-3张参考图片。
    - **改造**：将上传的图片转换成 Base64 编码，并将其作为“参考资料”的一部分插入到生成设计的 Prompt 中，例如：“请参考附带的图片色调和构图风格进行设计。” 这能让 AI 的设计更贴近用户想要的“感觉”。

2.  **切换 AI 模型或集成多模型对比**：
    - **操作**：在顶部模型切换（Chat/Reasoner）旁边，增加“OpenAI GPT-4”或“Claude”的选项。
    - **改造**：复制 `callDeepSeek` 函数为 `callOpenAI`，修改 API 端点、请求头和密钥读取逻辑。在生成时让用户选择用哪个模型，甚至可以并行生成，对比不同模型的设计效果。

3.  **将“单页工作流”拆分为“策划”和“设计”两个独立页面**：
    - **操作**：创建 `plan.html` 和 `design.html`。
    - **改造**：在 `plan.html` 只保留大纲生成和编辑功能，完成后将大纲数据保存到 `localStorage` 或通过 URL 参数传递。在 `design.html` 读取数据，专注于 HTML 生成、编辑和导出。这样结构更清晰，也适合团队分工（策划负责前一页，设计负责后一页）。

4.  **增加“设计模板库”和“一键应用”**：
    - **操作**：在“全局设计风格”输入框下，增加一个“从模板选择”的下拉菜单。
    - **改造**：预定义5-10个写好的、高质量的 CSS 样式字符串（如 `.template-minimalist { ... }`）。当用户选择模板时，不仅将对应的描述填入 `input.designPrompt`，同时在生成 HTML 的 Prompt 末尾追加：“请在你的 HTML 中最外层的 div 上添加 class=‘template-minimalist’”。这样能更稳定地控制输出风格。

5.  **优化交互：添加“历史版本”和“撤销/重做”**：
    - **操作**：为每张卡片的数据对象增加一个 `history` 数组属性。
    - **改造**：每当卡片的 `html` 内容被修改（无论是 AI 生成还是手动编辑），都将旧的 `html` 快照存入 `history`。在卡片操作层增加“上一个版本”、“下一个版本”的按钮。这能极大降低用户试错的心理成本。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合做高精度、可重复的品牌设计**：AI 生成具有随机性，每次结果可能不同，无法保证品牌色号、字体、Logo 位置的绝对一致。**应该使用**：Figma、Adobe Illustrator 等专业设计软件，或建立严格的品牌设计系统。
- **不适合生成包含复杂逻辑或数据的图表**：虽然可以写 HTML/CSS，但让 AI 生成准确的柱状图、趋势线并绑定动态数据极其困难且不可靠。**应该使用**：ECharts、Chart.js 等专业图表库，或在 Excel/Google Sheets 中制作后截图。
- **不适合作为最终上线的网页代码**：AI 生成的 HTML 侧重于视觉呈现，可能包含冗余代码、不合理的标签嵌套或兼容性问题。**应该使用**：将其作为视觉原型，由前端工程师重构为生产级代码。
- **不适合处理极度依赖实时性或外部 API 的内容**：例如，生成一个显示实时股价或天气的卡片。工具本身没有后端，AI 也无法获取实时数据。**应该使用**：学习基础的前后端开发，自己调用相应的公开 API 来构建。
