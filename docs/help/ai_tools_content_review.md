# 内容合规审查助手 - 帮助与学习文档

---

## 【一】这个网页解决了什么问题？

**使用场景**：
想象你是一名新媒体编辑、市场文案或社区运营人员。你刚刚写完一篇公众号文章、产品介绍或用户评论回复，但不确定内容是否合规——会不会有违规词汇？有没有拼错重要人名？语气是否恰当？手动检查既耗时又容易遗漏。

这个网页就是你的“AI 合规助手”。你只需把内容粘贴进去，它就能自动分析，指出问题、给出修改建议，并打出一个合规分数。它特别适合在内容发布前做最后一道检查，或者用于培训新人了解合规边界。

**适合情况**：
- 检查营销文案、社交媒体帖子、产品描述
- 审核用户生成的评论、反馈
- 作为写作辅助工具，确保内容安全
- 用于团队合规培训，可视化展示问题点

**不适合情况**：
- 实时、高速的内容流审核（如直播弹幕）
- 需要100%法律效力的最终合规裁定（应咨询专业法务）
- 图像、音频、视频等非文本内容
- 需要理解复杂上下文或行业特定隐晦表达的场景

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **待审查内容**：中间左侧的大文本框，你可以粘贴或输入任何需要检查的文字。
2.  **审查规则**：点击右上角“审查规则配置”按钮，可以设置三类规则：
    *   **违规词库**：绝对不能出现的词（如“绝对化”、“第一”）。
    *   **敏感人名/产品名**：需要仔细核对拼写和引用的专有名词（如“DeepSeek”、“Elon Musk”）。
    *   **自定义规则**：用自然语言描述的其他要求（如“语气不能太生硬”、“必须包含至少一个表情符号”）。

**用户通常会做哪几步操作？**
1.  **配置API**：首次使用，点击右上角“API 设置”，填入你的 DeepSeek API Key（需要自行申请）。
2.  **设置规则**：点击“审查规则配置”，根据你的需求填写三类规则，然后保存。
3.  **输入内容**：在左侧文本框粘贴或输入需要检查的文案。
4.  **开始审查**：点击蓝色的“🔍 开始审查”按钮。
5.  **查看报告**：等待几秒到几十秒，右侧会显示审查报告，包括合规分数、问题列表和修改建议。

**输出结果长什么样？**
审查报告是一个视觉清晰的卡片，主要包含：
- **合规指数**：一个醒目的分数（0-100），颜色根据分数高低变化（绿/橙/红）。
- **审查总结**：一两句话的总体评价。
- **问题列表**：每个问题会显示：
    - **原文片段**：被标记的词句。
    - **修改建议**：AI 推荐的替换词句（如果有）。
    - **问题类型**：用标签标注是“违规”、“敏感”还是“建议”。
    - **原因**：解释为什么这里有问题。

**有哪些容易忽略的使用细节？**
1.  **规则是“与”的关系**：AI 会同时应用你设置的所有规则进行检查。
2.  **模型选择**：顶部可以切换“Chat”和“Reasoner (R1)”模型。R1 模型会显示“深度思考过程”，让你看到 AI 的分析思路，但响应可能更慢。
3.  **本地存储**：你设置的 API Key 和审查规则都保存在你的浏览器本地，换电脑或清除浏览器数据会丢失。
4.  **JSON 输出**：报告底部可以“查看原始 JSON”，这是 AI 返回的原始数据结构，适合开发者或需要进一步处理的情况。
5.  **文本框自动增高**：输入内容时，文本框高度会自动增加，无需手动拖动。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为四个主要模块：

**1. 配置与管理模块（顶部导航栏）**
*   **职责**：提供全局控制入口。
*   **包含**：模型切换按钮、规则配置入口、API 设置入口。
*   **设计亮点**：将“设置”与“核心操作”分离，保持主界面简洁。模型切换用按钮组直观呈现。

**2. 输入与触发模块（左侧面板）**
*   **职责**：接收用户输入的核心内容，并触发审查流程。
*   **包含**：自适应高度的文本输入框、主要的“开始审查”按钮、状态提示。
*   **输入→处理→输出链路**：
    *   **输入**：用户粘贴文本 + 已保存的规则配置。
    *   **处理**：点击按钮后，将输入内容和规则拼接成特定的 Prompt，调用 AI API。
    *   **输出**：触发审查，将状态变为“生成中”，并清空右侧区域准备接收结果。

**3. 状态与展示模块（右侧主区域）**
*   **职责**：向用户反馈当前状态，并最终呈现结构化的审查结果。
*   **包含三种状态**：
    *   **空状态**：引导用户开始操作。
    *   **加载状态**：显示加载动画，对于 R1 模型还会流式显示“思考过程”。
    *   **结果状态**：核心展示区，将 AI 返回的 JSON 数据渲染成可视化的报告卡片。
*   **设计亮点**：**状态驱动 UI**。页面完全由 `isGenerating`（是否生成中）和 `reviewResult`（审查结果）这几个核心状态变量控制显示内容，逻辑清晰。

**4. 规则配置模块（弹窗）**
*   **职责**：提供一个专注的界面，让用户详细定义审查标准。
*   **包含**：三个分类清晰的文本区域（违规词、敏感词、自定义规则）。
*   **设计亮点**：**分类与视觉编码**。用不同的图标和焦点框颜色（红、橙、蓝）区分三类规则，降低了用户的认知负担。

**最值得学习的设计：模块化与状态管理**
整个应用没有复杂的页面跳转，所有功能通过状态（`ref` 变量）和组件模块组合完成。左侧负责“输入和触发”，右侧负责“状态反馈和输出”，弹窗负责“详细配置”。这种结构使得功能增减非常方便，例如要增加一个“审查历史”功能，只需新增一个状态变量和一个展示模块即可，不会影响现有逻辑。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 扮演的角色**：
在这个页面中，Prompt 是连接“用户规则”和“AI 能力”的**翻译器**和**指令手册**。它把用户填写的零散规则和待审文本，转化成一个 AI 能够理解并执行结构化分析的任务。

**解决的是“生成问题”**：
更准确地说，它解决的是“**按照特定格式生成结构化分析结果**”的问题。AI 的核心任务是“生成”一份报告，但 Prompt 严格限定了这份报告的格式（JSON）、评分体系（0-100）、问题分类（violation/sensitive/suggestion）和内容要素。

**Prompt 中的关键变量**：
1.  **系统指令 (`systemPrompt`)**：定义了 AI 的“角色”（合规专家）和**必须遵守的输出格式**。这是确保 AI 返回可解析 JSON 的关键。
2.  **用户指令 (`userPrompt`)**：包含三个动态部分：
    *   `【待审查内容】`：用户输入的文本。
    *   `【审查规则】`：从 `rulesConfig` 中动态填入的违规词库、敏感词和自定义规则。

**如果只改 Prompt，不改代码，会发生什么？**
1.  **改变审查维度**：例如，在 Prompt 里要求 AI 额外检查“文案的积极情绪占比”，那么报告里就会多出这个维度，但页面可能无法正确显示（因为前端代码没有为这个新数据设计展示样式）。
2.  **调整严格程度**：通过修改系统指令中的语气，如从“严格审查”改为“提供友好优化建议”，AI 输出的口吻和问题严重性判断会发生变化。
3.  **更换任务类型**：如果把 Prompt 完全改成“请将以下文字翻译成英文并输出 JSON”，那么这个页面就瞬间变成了一个翻译工具，但按钮文字、界面提示还是“审查”，会显得很奇怪。

**结论**：Prompt 决定了 AI **做什么**和**输出什么**，而前端代码决定了如何**收集输入**和**展示输出**。两者需要紧密配合。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步打造一个属于你的 AI 工具：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **目标**：先理解整个数据流和界面结构。
*   **操作**：
    1.  复制整个代码文件。
    2.  修改标题和界面文字，例如把“内容合规审查助手”改为“**文章语法校对助手**”。
    3.  修改规则配置弹窗里的标签和提示文字，例如“违规词库”改为“**常见错别词库**”，“敏感人名”改为“**专业术语库**”。
    4.  此时，工具的外观和交互逻辑完全没变，只是文字描述变了。

**第二步：调整输入字段或 Prompt（核心改造）**
*   **目标**：让工具解决你的新问题。
*   **操作**：
    1.  修改 `systemPrompt` 和 `userPrompt`。这是核心。例如，对于“语法校对”，你的 Prompt 可以要求 AI 检查拼写、语法、标点，并输出错误类型和修正建议。
    2.  相应地，微调规则配置的输入项，使其符合新场景（比如保留“术语库”，去掉“违规词库”）。
    3.  此时，工具的功能已经改变了，但报告样式可能还不匹配。

**第三步：改变输出形式或展示方式（优化体验）**
*   **目标**：让前端展示匹配 AI 的新输出。
*   **操作**：
    1.  根据新 Prompt 中 AI 返回的 JSON 结构，调整 `reviewResult` 的展示代码。
    2.  例如，语法校对的结果可能包含“错误类型”（拼写、语法、标点），你需要修改前端，为这些新类型设计展示样式和颜色标签。
    3.  还可以调整布局，比如将“修改建议”用更突出的方式显示。

**从哪里下手最安全？**
从 **修改文字和 Prompt** 开始最安全。这不会破坏代码的运转逻辑（前提是保持 JSON 格式基本稳定），却能立刻改变工具的行为。先让工具在“幕后”跑通你的新想法，再去优化“台前”的展示界面。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“审查历史”功能**
    *   **操作**：在 `localStorage` 中保存每次的 `inputContent` 和 `reviewResult`。在左侧面板或新弹窗中增加一个历史记录列表，点击可以重新加载当时的审查内容和结果。
    *   **价值**：方便对比和回溯，提升了工具的实用性。

2.  **支持多模型/多平台 API**
    *   **操作**：在 API 设置弹窗中，增加一个下拉菜单，让用户选择模型提供商（如 DeepSeek, OpenAI, 智谱AI等）。根据选择，动态修改 `callDeepSeek` 函数中的请求 URL 和参数格式。
    *   **价值**：让工具不依赖单一服务，用户可以选择自己拥有或更便宜的 API。

3.  **优化交互：提供“一键替换”功能**
    *   **操作**：在每个问题项的“修改建议”旁边，增加一个“替换”小按钮。点击后，可以自动将左侧原文框中的 `original` 文本替换为 `suggestion` 文本。
    *   **价值**：将“检查”和“修改”流程打通，大幅提升内容修订效率。

4.  **引入“规则模板”与分享**
    *   **操作**：在规则配置弹窗中，增加“保存为模板”、“加载模板”的按钮。模板数据可以存储为 JSON 文件，并支持通过文本分享（如生成一个包含编码后规则配置的 URL 参数）。
    *   **价值**：方便团队统一标准，新人可直接加载团队的合规模板。

5.  **细分报告维度，增加可视化图表**
    *   **操作**：修改 Prompt，要求 AI 除了总体分数，再按“用词安全”、“事实准确性”、“语气态度”等维度分别打分。在前端，使用简单的柱状图或雷达图（可引入轻量图表库）来展示多维度的评分。
    *   **价值**：让报告更专业、更直观，用户能快速定位内容的具体短板。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做最终法律裁定**：
    *   **局限性**：AI 的理解基于训练数据和你的规则，可能无法覆盖最新的法律法规或极其特殊的案例。
    *   **正确做法**：对于涉及重大利益、版权、诽谤等法律风险的内容，此工具应作为“初筛助手”，最终必须由人类法务或合规专员复核。

2.  **不适合理解高度依赖上下文和文化的幽默、讽刺、隐喻**：
    *   **局限性**：AI 可能无法准确识别反话、圈内黑话或特定文化背景下的梗，从而误判为违规或敏感。
    *   **正确做法**：这类内容需要人工结合发布平台、受众群体进行综合判断。

3.  **不适合处理超长文本（如整本书籍）或进行批量高速处理**：
    *   **局限性**：前端界面和单次 API 调用适合处理单篇、长度适中的内容。超长文本可能超出模型上下文限制，批量处理需要排队，体验不佳。
    *   **正确做法**：需要处理长文档或批量文件时，应开发后端服务，实现文本分块、异步队列处理等功能。

4.  **不是一个通用的“文本分析”平台**：
    *   **局限性**：它的代码和交互是高度特化为“审查-报告”模式的。如果你想做情感分析、关键词提取、摘要生成等，虽然可以修改 Prompt 实现，但前端界面会显得不匹配。
    *   **正确做法**：以本项目为蓝本，根据新的分析目标，重新设计输入表单和结果展示视图，打造一个专用的新工具。
