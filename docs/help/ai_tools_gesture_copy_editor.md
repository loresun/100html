# 沉浸式体感文案编辑器 - 帮助文档

## 【一】这个网页解决了什么问题？

想象一下，你正想写一段社交媒体文案（比如小红书、朋友圈），但对着空白屏幕毫无灵感，或者写到一半卡住了。这个网页就是你的“体感写作伙伴”。

**使用场景：**
- **创意枯竭时**：你有一个模糊的想法（比如“深夜加班”），但不知道如何下笔或展开。
- **寻求不同风格**：你想探索同一个主题的多种表达方式（走心、幽默、干货）。
- **互动式创作**：你希望写作过程更有趣、更沉浸，而不是枯燥地打字。

**它适合：**
- 快速生成社交媒体风格的短文案草稿。
- 通过简单的肢体动作（点头、摇头）进行无键盘交互。
- 体验“AI协作”与“体感控制”结合的新奇创作流程。

**它不适合：**
- 撰写长篇文章、正式报告或需要严谨结构的文档。
- 需要精确控制每一个用词、反复修改的精细写作。
- 在无法使用摄像头或需要安静环境的场合（如图书馆）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **初始灵感**：一个文本框，让你输入最原始的想法（例如：“想写一篇关于深夜加班的emo文案”）。
2.  **API密钥**：首次使用需要在设置中填入你的 DeepSeek API Key（用于调用AI生成文案）。

**用户通常会做哪几步操作？**
1.  **启动**：在首页输入你的灵感，点击“启动引擎”。
2.  **授权**：允许网页使用你的摄像头。
3.  **创作**：页面中央会出现你的摄像头画面。AI会基于你的灵感，在屏幕左、右、下三个方向生成三个不同风格的后续句子选项。
4.  **选择**：
    *   **体感控制**：将头转向你想选择的选项方向（左转选A，右转选B，低头选C），并保持约1.5秒，倒计时结束后该选项会被确认。
    *   **手动点击**：你也可以直接用鼠标点击任意选项卡片。
5.  **延续**：被选中的句子会添加到上方不断增长的完整文案中。AI随即基于新的全文，再次生成三个新选项，如此循环。
6.  **完成**：当你对生成的文案满意时，可以点击“复制全文”或“导出”按钮保存结果。

**输出结果长什么样？**
- 最终输出是一段连贯的、由你多次选择拼接而成的完整文案，显示在页面顶部区域。
- 文案风格偏向小红书等平台的短平快、有网感的口语化表达。

**有哪些容易忽略的使用细节？**
1.  **摄像头镜像**：画面是镜像的（像照镜子），你向左转头，屏幕上的“你”向右转，但选项逻辑已适配，你只需凭直觉转向选项即可。
2.  **确认倒计时**：将头转向一个选项后，需要保持姿势直到倒计时结束（约1.5秒），这是为了防止误触。
3.  **“抬头重写”选项**：看向屏幕上方可以触发“重写”，让AI为当前上下文重新生成三个全新选项。
4.  **灵敏度设置**：在设置中，可以调整“灵敏度”。灵敏度低需要更大的头部动作才能触发，灵敏度高则小幅度动作即可。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为五个模块，像一个创作流水线：

1.  **输入与配置模块（首页）**
    *   **职责**：收集用户的初始创意和必要的API配置，是整个流程的起点。
    *   **包含**：灵感文本框、启动按钮、设置面板（API Key、灵敏度）。
    *   **逻辑**：用户输入 → 点击启动 → 验证配置 → 跳转到创作界面。

2.  **AI内容生成模块（大脑）**
    *   **职责**：核心的“思考”部分。接收当前文案上下文，调用AI API，生成符合要求的多个选项。
    *   **逻辑**：拼接Prompt → 调用DeepSeek API → 解析返回的JSON → 将三个选项填入对应位置。

3.  **体感交互捕捉模块（眼睛）**
    *   **职责**：通过摄像头和面部识别技术，将用户的头部动作转化为数字信号。
    *   **包含**：`<video>`元素捕捉视频流，`<canvas>`元素绘制画面和计算结果，MediaPipe Face Mesh库分析面部关键点。
    *   **逻辑**：摄像头画面 → Face Mesh识别鼻尖坐标 → 计算坐标偏移 → 判断头部朝向（左/右/上/下）。

4.  **选项展示与状态机模块（界面）**
    *   **职责**：直观地展示AI生成的选项，并管理整个创作过程的状态（哪个选项被激活、是否已选择等）。
    *   **包含**：左(A)、右(B)、下(C)、上(D重写)四个方向的选项卡片，顶部的文案展示区。
    *   **逻辑**：这是一个**状态机**。状态包括：“等待选择”、“选项A高亮倒计时”、“选项B被确认”、“文案已更新，请求生成新选项”。状态的变化驱动着页面视觉反馈和业务流程。

5.  **输出与工具模块（终点）**
    *   **职责**：处理创作成果，提供实用的结束操作。
    *   **包含**：“复制全文”、“导出为文本文件”、“重来”按钮。
    *   **逻辑**：将内存中的完整文案字符串提供给剪贴板或生成下载文件。

**最值得学习的设计：状态机与体感交互的融合**
这个网页最巧妙的地方在于，它**将复杂的、连续的面部动作，通过“状态机”简化为清晰的、离散的交互指令**。不是一直识别你的头在哪，而是设计了一套规则：“当头部持续朝向某个方向超过阈值时间，则触发一次‘选择’事件”。这种设计使得不稳定的体感输入变得可靠，并且与AI生成内容的异步等待过程完美结合（例如，在AI生成时暂停检测）。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 是向AI下达的“精确生产指令”。它决定了AI输出内容的质量、格式和风格。在这里，Prompt是连接“用户想法”和“AI创意”的桥梁。

**它解决的是“理解问题”还是“生成问题”？**
主要解决**生成问题**，但也包含了**理解上下文**的要求。Prompt需要让AI理解：1）用户的初始主题；2）目前已写出的所有内容；3）需要生成三种特定风格的短句；4）必须以严格的JSON格式返回。

**哪些信息是 Prompt 中的关键变量？**
1.  `{initialIdea.value}`：用户最初输入的想法，决定了文案的总体方向。
2.  `{fullText.value}`：当前已生成的所有文案，确保新句子能连贯上下文。
3.  **风格指令**：明确要求“左-情感”、“右-幽默”、“下-干货”，这是生成多样化选项的核心。
4.  **格式指令**：严格要求返回 `{“left”: “…”, “right”: “…”, “down”: “…”}` 的JSON，方便代码直接解析使用。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个应用的性质，而无需改动一行前端代码：
*   **改变领域**：将“小红书文案”改成“短视频脚本分镜”、“辩论论点”、“诗歌下一句”，它就变成了相应领域的创作工具。
*   **改变风格**：修改“情感、幽默、干货”的定义，就能产出完全不同气质的选项。
*   **改变选项数量**：比如要求生成5个选项，但前端界面只显示了3个，多出的2个会被忽略（除非你也改前端）。这说明了Prompt与前端界面需要协同设计。

## 【五】如何模仿它，做出你自己的版本？

你可以把它看作一个“体感选择器+AI内容生成器”的模板。按以下路径改造最安全：

**第一步：替换核心场景与Prompt（最安全，效果立竿见影）**
保持所有摄像头、界面代码不变。只修改 `generateOptions` 函数中的Prompt模板。例如，做一个“体感决策助手”：
*   **原Prompt**：关于小红书文案。
*   **新Prompt**：“你是一个决策顾问。用户当前面临的选择是：`{initialIdea}`（例如‘是否该换工作’）。请从三个角度提供思考方向：1. (Left) 情感与价值观层面；2. (Right) 风险与机遇层面；3. (Down) 实际行动与步骤层面。返回JSON。”

**第二步：调整输入字段和输出展示**
1.  **修改输入**：将“初始灵感”文本框的提示语从“写文案”改为“描述你的决策困境”。
2.  **修改输出**：将顶部“已生成文案”的标题改为“决策分析记录”。
3.  **修改选项标签**：将“Option A/B/C”改为“情感视角”、“风险视角”、“行动视角”。

**第三步：改变交互逻辑与界面布局**
这是更深度的定制，但结构依然清晰：
1.  **增加/减少选项**：如果你想做“是/否”二元选择，可以隐藏“下”选项，只保留“左（是）”、“右（否）”、“上（跳过）”。
2.  **改变触发动作**：在代码的 `processLandmarks` 函数中，你可以将识别“点头/摇头”改为识别“张嘴（同意）/皱眉（反对）”。这需要调整判断的面部关键点（如下巴、眉毛）。
3.  **更换UI主题**：修改CSS中的颜色变量（`–accent-color`等）和背景图，瞬间改变应用的整体视觉风格。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“语音输入”作为备选交互方式**
    *   **操作**：集成浏览器的Web Speech API。在界面底部增加一个麦克风按钮。点击后，用户可以说“选左边”、“重写”或“继续”等口令来替代头部动作。这对于不便做动作或摄像头不佳的环境非常有用。
    *   **价值**：提升无障碍访问能力，并提供多模态交互选择。

2.  **接入本地大模型或更换AI服务**
    *   **操作**：修改 `callDeepSeek` 函数。将请求URL和参数替换为其他API（如OpenAI、Claude、智谱AI）或本地运行的Ollama服务地址。同时需要调整Prompt格式以适应新模型的习惯。
    *   **价值**：降低成本、提高响应速度、或利用特定模型的专长（如更擅长写代码、更懂中文古诗词）。

3.  **将单页应用拆分为“练习模式”和“创作模式”**
    *   **操作**：在首页增加一个选择。**练习模式**：AI提供固定的句子片段，让用户纯粹练习用头部动作进行快速选择，并给出反应时间评分。**创作模式**：即当前模式。
    *   **价值**：降低新用户的学习门槛，让用户先熟悉交互，再投入创作。

4.  **为生成的文案增加“风格滤镜”**
    *   **操作**：在最终输出区域，增加几个按钮，如“转换为鲁迅风格”、“转换为深夜电台风”、“转换为正式邮件”。点击后，将 `fullText` 全文发送给AI，Prompt要求进行整体风格改写，并替换当前文案。
    *   **价值**：在生成完成后，提供二次加工的能力，让成品更符合最终发布平台的要求。

5.  **优化体验：增加历史分支与回溯功能**
    *   **操作**：每次用户做出选择时，不仅将文本添加到 `fullText`，还将当前状态（全文、当时的三个选项）保存到一个历史数组里。在界面侧边栏增加一个“时间线”面板，点击历史节点可以回溯到当时的决策点，并选择不同的分支。
    *   **价值**：解决创作中的“后悔药”问题，让用户可以探索不同的剧情发展路径，非常适合故事创作。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合进行精确、严肃的文本创作**
    *   **局限性**：AI生成的内容具有随机性，可能不符合事实、逻辑或特定品牌调性。它只是一个“灵感加速器”和“草稿生成器”。
    *   **正确工具**：对于正式文档、法律文书、学术论文，请使用专业的写作软件（如Word、Scrivener）并亲自撰写、反复修订。

2.  **不适合作为无障碍辅助工具的核心组件**
    *   **局限性**：它严重依赖摄像头和用户的面部活动能力，对于有运动障碍、视力障碍或无法使用摄像头的用户，基本功能会失效。虽然提供了手动点击备选，但并非设计核心。
    *   **正确方式**：如果要开发严肃的无障碍工具，应将键盘导航、屏幕阅读器兼容、语音控制作为**首要**和**默认**的交互方式，体感作为可选增强功能。

3.  **不适合处理高度复杂或需要长期记忆的对话**
    *   **局限性**：它的上下文仅限于当前 `fullText` 字符串。AI在生成新选项时，虽然能看到之前的全文，但无法记忆更早的“未被选中”的选项或用户的隐性偏好。
    *   **正确工具**：需要复杂对话记忆和个性化适应的场景，应使用更复杂的AI Agent框架，并设计专门的状态管理和记忆模块。

4.  **不适合在公共网络环境下不假思索地使用**
    *   **局限性**：你的API Key存储在浏览器的本地存储中，如果使用公共电脑，存在泄露风险。此外，发送到AI服务商的数据可能包含你的隐私想法。
    *   **正确做法**：在私人设备上使用，了解所用AI服务的隐私政策，对于敏感主题的创作，考虑使用具有隐私保护承诺的API或本地模型。
