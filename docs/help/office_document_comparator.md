# 多文档智能对比工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景**：
想象一下，你是一位内容编辑，收到了同事发来的合同第二版。你需要快速找出所有修改点，判断哪些是简单的错别字修正，哪些是可能影响条款的关键变更。或者，你是一名学生，想对比自己论文初稿和终稿的差异，看看导师具体修改了哪些地方。这个工具就是为这类场景设计的：**当你有两个相似但不同的文本（如合同、文章、代码、报告），需要快速、智能地找出差异并理解其含义时**。

**适合情况**：
- 对比合同、协议、法律文件的不同版本。
- 审阅文章、论文、报告的修改稿。
- 检查技术文档、产品说明书的更新内容。
- 分析政策、规章制度的前后变化。

**不适合情况**：
- 对比图片、PDF（非纯文本）或格式复杂的文档（如带复杂表格的Word）。
- 需要100%精确到字符的差异比对（如代码合并冲突，应使用专业的diff工具）。
- 一次性对比超过3个文档（该工具主要设计为两两对比）。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **两个文本框**：分别粘贴“原始版本”和“新版本”的文档内容。
2.  **对比选项**：几个复选框，用于选择你想关注哪些类型的变更（如新增、删除、数字变化等）。
3.  **API密钥**：首次使用需要在“设置”中填入你的DeepSeek API密钥。

**用户通常会做哪几步操作？**
1.  **准备**：点击“设置”按钮，填入你的DeepSeek API密钥并保存。
2.  **输入**：在左侧两个文本框中，分别粘贴或通过“上传文件”按钮导入两个版本的文本。
3.  **配置**：根据你的需求，勾选下方的对比选项（例如，如果你只关心数字变化，可以只勾选“重点关注数字变化”）。
4.  **执行**：点击绿色的“开始智能对比”按钮。
5.  **查看**：等待片刻，右侧会生成一份详细的对比报告。

**输出结果长什么样？**
右侧会生成一份结构清晰的Markdown格式报告，通常包含：
-   **变更统计**：以表格形式列出新增、删除、修改的数量。
-   **详细对比**：分门别类地列出具体变更内容，并用不同颜色或符号标注。
-   **风险提示**：对重要变更进行风险评级。
-   **语义分析**：如果启用，会尝试区分“实质性变更”和“简单的措辞调整”。
-   **建议**：基于分析给出后续行动建议。

**有哪些容易忽略的使用细节？**
1.  **必须先配置API**：第一次点击“开始智能对比”时，如果没填API密钥，会自动弹出设置窗口。
2.  **文件上传支持格式**：支持上传 `.txt` 和 `.md` 文件，其他格式（如 `.docx`）需要你先转换为纯文本。
3.  **“语义分析过程”可展开**：报告上方有一个“🧠 语义分析过程”的折叠区域，点击可以查看AI思考的中间步骤，这对理解分析逻辑很有帮助。
4.  **结果可复制和导出**：生成报告后，可以使用右上角的“复制”或“导出”按钮将结果保存下来。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，它们协同工作：

**1. 输入与配置模块（左侧）**
*   **职责**：收集用户的所有原始输入和偏好设置。
*   **组成**：
    *   **文档输入区**：两个文本区域，用于接收待对比的文本。支持直接粘贴和文件上传。
    *   **选项配置区**：一组复选框，让用户自定义对比的精细度和侧重点（如是否关注数字、是否进行语义分析）。
    *   **执行按钮**：触发整个对比流程。
*   **设计亮点**：将“要对比什么”（文档内容）和“怎么对比”（选项）清晰地分开，用户意图非常明确。

**2. AI处理与逻辑模块（核心，不可见）**
*   **职责**：作为大脑，根据用户输入和配置，组织问题（Prompt），调用AI API，并处理返回的数据流。
*   **工作流程**：
    1.  **组装Prompt**：将用户输入的**两个文档内容**和**勾选的选项**，组合成一个结构化的、给AI的指令（即System Prompt和User Prompt）。
    2.  **调用API**：将组装好的Prompt发送给DeepSeek API。
    3.  **流式处理**：实时接收AI返回的数据，并巧妙地将“思考过程”（reasoning）和“最终答案”（content）分离，分别展示。

**3. 结果展示与交互模块（右侧）**
*   **职责**：以友好、可操作的方式呈现AI的分析结果。
*   **组成**：
    *   **分析过程面板**：可折叠，展示AI的“思考链”，增加了透明度和可信度。
    *   **报告主面板**：将AI返回的Markdown文本渲染成美观易读的格式。
    *   **操作工具栏**：提供“复制”和“导出”功能，让结果变得有用。

**输入 → 处理 → 输出 的逻辑链路**：
```
用户输入文本和选项 → 前端组装成Prompt → 调用AI API → 流式接收并分离“思考”与“答案” → 前端渲染Markdown报告 → 用户可复制/导出
```

**最值得学习的设计**：
**“配置驱动”的Prompt生成**。这不是一个固定功能的AI工具。它的核心智慧在于：将用户在前端勾选的每一个选项（如“标注新增内容”），都动态地转换为给AI的**具体、可执行的指令条款**，并嵌入到最终的Prompt中。这使得工具的功能高度可定制，而无需修改核心代码。这是连接用户意图与AI能力的关键桥梁。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt扮演的角色**：
在这个工具中，Prompt扮演了 **“超级详细的作业指导书”** 的角色。它不仅仅是提一个问题，而是为AI定义了一个完整的分析框架、输出格式和评价标准。

**解决的是“理解问题”还是“生成问题”？**
两者兼有，但更侧重于 **“结构化生成”**。
1.  **理解**：Prompt通过System指令，让AI理解自己的角色是“文档对比专家”，并理解“实质性变更”等概念。
2.  **生成**：更关键的是，它严格规定了生成的**格式**（用Markdown标题、表格、列表）和**内容结构**（必须包含概览、统计、详细对比、风险提示等章节）。这确保了输出结果的一致性和可用性。

**Prompt中的关键变量**：
1.  `analysisRequirements`：由用户在前端勾选的选项动态生成的一段列表。这是Prompt中最灵活的部分，直接决定了AI报告会包含哪些章节。
2.  `documents[0].content` 和 `documents[1].content`：两个需要对比的原始文本，作为User Prompt的核心内容被传入。

**如果只改Prompt，不改代码，会发生什么变化？**
你可以彻底改变这个工具的行为和产出，而无需触碰任何HTML/JS代码。例如：
*   **改变用途**：将System Prompt中的“文档对比专家”改为“代码审查助手”，并调整输出格式为代码Diff风格，这个工具就变成了一个AI代码审查工具。
*   **调整深度**：在Prompt中要求AI“不仅列出差异，还要推测每次修改的意图或作者可能的心态”，报告就会更具洞察力。
*   **修改格式**：要求输出为JSON格式，那么这个工具就可以变成一个为其他系统提供结构化差异数据的API前端。

## 【五】如何模仿它，做出你自己的版本？

这是一个安全的“三步模仿法”，你可以循序渐进：

**第一步：保持结构不变，替换使用场景（最安全）**
*   **做什么**：不要改动任何代码。只修改网页标题、说明文字，以及**最重要的——重写System Prompt**。
*   **例子**：你想做一个“AI面试题对比工具”。那么，将System Prompt中的角色从“文档对比专家”改为“面试题目对比专家”，将对比对象从“合同条款”描述为“两道相似的算法面试题”，并让AI分析其考察重点、难度差异。
*   **效果**：你立刻得到了一个全新的工具，前端交互完全一样，但功能完全不同。

**第二步：调整输入字段或Prompt变量**
*   **做什么**：在第一步的基础上，根据新场景调整输入模块。
*   **例子**：你的“面试题对比工具”可能需要三个输入框：“题目一”、“题目二”、“岗位描述（可选）”。你需要在`documents`数组中增加一个对象，并在组装Prompt时将这个“岗位描述”作为额外背景信息传给AI。
*   **效果**：工具的输入更贴合你的专业需求，AI能获得更丰富的上下文，做出更精准的分析。

**第三步：改变输出形式或展示方式**
*   **做什么**：定制结果展示模块，使其更适合你的内容。
*   **例子**：对于面试题对比，你可能不希望用“风险提示”，而是想用“考察点分析”板块。你可以在Prompt中修改输出格式的章节标题，并考虑在前端为不同的“考察点”（如数据结构、时间复杂度）设计不同的高亮样式。
*   **效果**：最终的报告不仅内容定制化，外观也更专业化。

**从哪里下手最安全？**
**直接从第一步开始，修改 `systemPrompt` 字符串变量。** 这是整个应用的“灵魂”，改变它风险最低，效果最明显。你可以在浏览器的开发者工具中直接找到并修改这段字符串进行测试。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“对比基准”选择**：
    *   **操作**：在“对比选项”区域增加一个下拉菜单，让用户选择对比的粒度，如“以句子为单位”、“以段落为单位”或“以条款为单位”。
    *   **实现**：将这个选项作为新变量加入到`form`对象中，并在组装Prompt时将其转换为给AI的指令，例如：“请以‘条款’为单位进行对比，识别每个独立条款的新增、删除或修改。”

2.  **支持更多AI模型/API**：
    *   **操作**：在设置弹窗中，将模型选择从DeepSeek扩展到OpenAI GPT、Claude、智谱AI等。
    *   **实现**：在`apiConfig`中增加`provider`字段。在`callDeepSeek`函数（应重命名为`callAI`）中，根据`provider`和`model`的值，动态切换请求的URL、Headers和可能的请求体格式。

3.  **将“语义分析过程”可视化**：
    *   **操作**：不再只是展示AI思考的原始文本，尝试将其结构化。
    *   **实现**：在Prompt中要求AI将其思考过程以特定的JSON格式返回。前端接收到后，解析这个JSON，并用时间线、思维导图或步骤卡片等更直观的形式展示出来，让分析逻辑一目了然。

4.  **增加“历史对比记录”功能**：
    *   **操作**：在页面底部或侧边栏增加一个区域，保存用户每次的对比操作（时间、文档摘要、变更统计）。
    *   **实现**：使用浏览器的`localStorage`或`IndexedDB`存储每次对比的元数据和结果。提供一个列表视图，点击可以快速加载某次历史对比的输入和结果。

5.  **优化长文档体验**：
    *   **操作**：当对比非常长的文档时，AI可能无法一次性处理全部内容。
    *   **实现**：改造`compareDocuments`函数。在调用AI前，先对两个文档进行简单的分块（如按段落分割）。然后，循环处理每个块，或者只选取疑似有变更的段落（可通过简单的文本匹配预先筛选）发送给AI分析，最后汇总结果。这能提升长文档处理能力和效率。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做精确的版本控制（如Git Diff）**：
    *   **局限性**：它的目标是“智能理解”差异，而不是提供字符级精确、行号对应的差异比对。对于程序代码合并，它可能会漏掉一个分号或括号的修改，或者无法提供精确的代码行位置。
    *   **应该换用**：专业的代码对比工具（如Git内置的`diff`、VS Code的对比功能、Beyond Compare等）。

2.  **不适合处理非文本或格式复杂的文档**：
    *   **局限性**：它只能处理纯文本。如果文档的核心信息存在于格式、排版、图表、表格结构中（如一份财务报表PDF），此工具将完全失效或丢失关键信息。
    *   **应该换用**：支持OCR的PDF对比工具，或专门针对Office文档的商业对比软件。

3.  **不适合作为完全自动化的合规审查工具**：
    *   **局限性**：虽然它能提示风险，但AI的判断并非万无一失，尤其涉及法律、金融等高度专业和严谨的领域。它只是一个**辅助筛查和提效工具**，不能替代专业人士的最终判断。
    *   **正确使用方式**：用它来快速定位可能的问题点，然后将这些点交给法务、会计等专家进行最终审核。切勿依赖其报告做出直接决策。

4.  **不适合处理极度模糊或创造性的对比**：
    *   **局限性**：它的分析基于给定的文本和明确的指令。如果需要对比两首诗歌的意境、两幅画作的风格，或者判断两段音乐旋律的相似度，这种基于文本的、结构化Prompt的方法将难以胜任。
    *   **应该换用**：针对特定领域（如图像、音频）的AI模型和专门设计的工具。
