# 本周能量预算 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你每周开始前都会在笔记本上写下这周要做的事情：开会、写报告、做项目、学习新知识……但事情一多，就容易感到疲惫，不知道如何合理安排精力。这个网页就像一个**个人能量管理助手**，它帮你把一周的任务可视化，并让 AI 根据你的任务安排，给出如何分配精力、何时休息的建议。

**适合在什么情况下使用？**
- 每周日晚上或周一早上，规划新一周的工作与学习。
- 感觉最近很累，想看看自己的任务安排是否合理。
- 想尝试用数据（图表）和 AI 建议来优化自己的时间管理。

**不适合什么情况？**
- 需要精确到小时级别的日程安排（它只按天规划）。
- 需要多人协作或团队任务管理。
- 需要记录已完成任务的详细日志。

## 【二】使用方式（给第一次接触的人）

**1. 页面输入是什么？**
- 页面左侧有一个大的文本框，里面已经有示例文本。
- 你需要按照 `星期几, 任务名称, 能量值` 的格式，一行写一天的任务。
- 例如：`周一, 写项目计划, 8` 表示周一要做“写项目计划”这件事，你预估它会消耗你 8 点能量（满分 10）。

**2. 用户通常会做哪几步操作？**
- **第一步：修改或填写任务**。你可以直接在文本框里修改示例，或者清空后输入你自己的本周计划。
- **第二步：点击“生成预算”按钮**。页面会开始处理你的输入。
- **第三步：查看结果**。左侧会出现一个柱状图，直观展示你一周每天的能量消耗预估。右侧的“AI 建议”区域会生成针对你计划的优化建议。

**3. 输出结果长什么样？**
- **左侧图表**：一个绿色的柱状图，X 轴是星期几，Y 轴是能量值（0-10）。柱子越高，表示那天你预估消耗的能量越大。
- **右侧建议**：一段由 AI 生成的文字，通常包含 2-3 条建议，比如“周三能量消耗最高，建议将部分任务拆分到周四”，或者“周五能量较低，适合安排创意性工作”。

**4. 有哪些容易忽略的使用细节？**
- **必须先配置 API**：第一次使用时，需要点击右上角的齿轮图标（⚙️），在弹出的窗口中输入你的 DeepSeek API Key 并保存，否则无法生成 AI 建议。
- **格式必须正确**：任务、星期、能量值之间必须用**英文逗号**分隔，并且每行只写一天。
- **能量值是主观的**：这里的“能量”不是科学测量值，而是你**自己感觉**完成这件事的费力程度，1 表示很轻松，10 表示非常耗神。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块：

**1. 输入与配置模块**
- **位置**：页面左上角的文本框、右上角的设置按钮。
- **职责**：接收用户的一周任务数据（`rawInput`），以及管理调用 AI 所需的 API 配置信息。
- **逻辑**：用户输入文本 → 程序按行和逗号分割，解析出“日期、任务、能量值” → 数据准备好，等待处理。

**2. 可视化模块**
- **位置**：左侧文本框下方的图表区域。
- **职责**：将解析出来的“能量值”数据，用直观的柱状图展示出来。
- **逻辑**：解析后的数据 → 传递给 Chart.js 库 → 库根据数据绘制出对应高度和颜色的柱子。

**3. AI 建议生成模块**
- **位置**：页面右侧的卡片。
- **职责**：将用户的任务列表组合成一段话（Prompt），发送给 AI 模型，并将返回的建议展示给用户。
- **逻辑**：解析后的数据 → 拼接成一段给 AI 的指令（Prompt）→ 通过 API 发送给 DeepSeek → 收到回复后显示在页面上。

**最值得学习的设计：**
**“输入-处理-展示”的清晰分离**。这个页面没有把所有功能混在一起。输入只管收集数据，图表只管画图，AI 只管生成建议。这种模块化思想让你可以轻松地修改其中一部分（比如换一个图表库，或者换一个 AI 服务），而不影响其他部分。这是构建可维护 Web 应用的基础。

## 【四】Prompt / AI 逻辑是如何被设计的？

**1. Prompt 扮演的角色**
在这个页面中，Prompt 是**连接用户原始数据和 AI 有用建议的“翻译官”和“指令官”**。它把一行行枯燥的“周一, 开会, 5”数据，转换成一个 AI 能理解的、带有明确请求的完整问题。

**2. 它解决的是“生成问题”**
Prompt 的核心任务是**请求 AI 生成内容**（具体的建议），而不是帮助 AI 理解复杂问题。它基于用户提供的简单数据，要求 AI 扮演“能量管理教练”的角色来创造新内容。

**3. Prompt 中的关键变量**
查看代码中的这一行：
```javascript
const prompt = `本周任务与能量：${rows.map(row => `${row[0]} ${row[1]} 能量${row[2]}`).join('；')}\n请给出 2 条节奏优化建议 + 1 条能量补给建议。`;
```
- **`rows.map(...).join('；')`**：这是最关键的变量部分。它把用户输入的每一行数据，重新组织成更通顺的句子（如“周一 专注项目 能量7”），然后所有句子用分号连接。**你的任务数据就隐藏在这里**。
- **固定的指令部分**：`“请给出 2 条节奏优化建议 + 1 条能量补给建议。”` 这部分告诉 AI 需要生成什么类型、什么数量的建议，决定了回复的格式和方向。

**4. 如果只改 Prompt，不改代码，会发生什么？**
- **改变建议类型**：如果把 Prompt 最后的指令改成 `“请用幽默的口吻吐槽一下这个安排。”`，那么 AI 就会生成一段搞笑风格的吐槽，而不是严肃的建议。
- **改变输出结构**：如果改成 `“请按‘优点’、‘风险’、‘调整方案’三部分回答。”`，AI 的回复就会自动分成三个段落。
- **改变角色设定**：修改代码中 `system` 角色的内容，比如把“能量管理教练”改成“严厉的体育教练”，AI 的说话语气和角度会完全不同。

**简单来说，Prompt 是控制 AI 输出内容和风格的“遥控器”**。

## 【五】如何模仿它，做出你自己的版本？

如果你想做一个功能类似但主题不同的工具，可以遵循这个安全的模仿路径：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标**：先做出一个能跑起来的“新外壳”。
- **操作**：
    1. 修改网页标题和说明文字，比如改成“**本周阅读计划**”或“**项目风险评估**”。
    2. 修改输入框的提示文本（`placeholder`），例如改成 `“书名, 预计阅读小时数, 难度等级”`。
    3. 修改图表标签，把“能量消耗”改成“阅读时长”或“风险等级”。
    4. 修改 AI `system` 指令，把“能量管理教练”改成“阅读导师”或“项目经理”。
- **效果**：你会立刻得到一个外观不同、但底层逻辑完全一样的工具。

**第二步：调整输入字段或 Prompt**
- **目标**：让工具更贴合你的新场景。
- **操作**：
    1. 增加或减少输入字段。比如阅读计划可能需要“书籍类型”（小说/教材），那么格式可以改成 `“周一, 《书名》, 2, 教材”`。你需要相应修改数据解析的代码（`rows.map` 部分）。
    2. 精心设计新的 Prompt。根据新字段，告诉 AI 你想让它关注什么。例如：“根据提供的书籍类型和阅读时长，给出 1 条阅读方法建议和 1 条防止疲劳的建议。”
- **效果**：工具的核心功能开始为你特定的场景服务。

**第三步：改变输出形式或展示方式**
- **目标**：优化用户体验。
- **操作**：
    1. 改变图表类型。把柱状图（`type: 'bar'`）改成折线图（`type: 'line'`）来展示趋势，或改成饼图（`type: 'pie'`）来展示比例。
    2. 美化 AI 建议的展示。比如给建议加上序号、不同的背景色，或者把“节奏优化”和“能量补给”建议分开显示。
- **效果**：你的工具在视觉和交互上变得独一无二。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“能量类型”选择**：
    - **操作**：在每行输入后增加一个下拉菜单或第四个字段，让用户选择任务消耗的是“脑力”、“体力”还是“社交能量”。
    - **改造点**：修改数据解析逻辑，并在生成 Prompt 时告诉 AI：“以下是分类型的能量消耗……”。AI 就能给出更精细的建议，比如“脑力消耗集中在周三，建议穿插体力活动”。

2.  **替换为本地模型或其它 API**：
    - **操作**：将 `callLLM` 函数中的 API 地址和请求格式，改成 OpenAI、通义千问或 Kimi 的格式。如果你电脑性能足够，甚至可以尝试使用 `ollama` 运行本地模型，将 API 地址指向 `http://localhost:11434`。
    - **改造点**：只需修改 `fetch` 请求的 `url`、`headers` 和 `body` 结构。这是学习如何与不同 AI 服务交互的绝佳练习。

3.  **拆分为“规划”与“回顾”两个页面**：
    - **操作**：创建两个 HTML 文件。`plan.html` 就是当前页面，用于生成计划。`review.html` 则增加一个“实际消耗能量”的输入框，与“预估能量”对比，并让 AI 分析预估偏差的原因。
    - **改造点**：学习如何使用 `localStorage` 或 URL 参数在两个页面间传递一周的计划数据。

4.  **优化交互：添加示例库与一键填充**：
    - **操作**：在输入框旁边增加一个“加载示例”按钮，点击后可以从预设的几种典型周计划（如“程序员的一周”、“学生考试周”）中选择并自动填充文本框。
    - **改造点**：学习如何组织静态数据，以及通过按钮事件来更新页面状态（`rawInput.value`）。

5.  **增加历史记录与对比功能**：
    - **操作**：每次生成预算后，自动将本次的计划和 AI 建议保存到 `localStorage` 中。在页面底部增加一个区域，可以查看和对比过去几周的计划图表。
    - **改造点**：学习更复杂的数据持久化存储和检索，以及动态创建多个图表实例。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做精确的时间管理**：它只有“天”的维度，没有“小时”。如果你需要安排“上午 10-11 点开会，下午 2-4 点写代码”，应该使用日历软件（如 Google Calendar）或专业的日程管理工具。
2.  **不适合做任务执行跟踪**：它没有“完成状态”的概念，无法标记任务是否做完，也无法记录实际花费的时间。这类需求应使用 Todoist、滴答清单或 Notion 数据库。
3.  **不适合做科学的健康监测**：这里的“能量”是完全主观的感知，并非基于心率、睡眠等生理数据。真正的健康管理应结合可穿戴设备数据并由专业应用或人士指导。
4.  **生成的建议不具备专业权威性**：AI 建议基于通用模式，并非针对你个人身体状况的专业医疗或心理指导。如果感到持续疲惫或压力过大，它不能替代咨询医生或心理咨询师。

**总结**：这个网页是一个优秀的**个人规划辅助与思维启发工具**。它通过可视化和 AI 对话，帮助你从另一个角度审视自己的计划。它的强大之处在于**快速原型化和启发思路**，而不是替代那些需要严谨数据和复杂功能的生产力工具。
