# 运营周报/月报生成器 - 学习与使用指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你是一名运营人员，每周五下午都要为不同的领导（比如你的直属上级、业务VP、跨部门同事）准备不同侧重点的周报。你需要从一堆零散的数据、工作记录和聊天记录中，提炼出结构化的报告。这个过程枯燥、重复，而且容易遗漏关键信息。

这个网页就是你的“运营报告智能助理”。它帮你把**零散的运营信息**（数据、动作、问题、计划）和**汇报要求**（给谁看、什么节奏、什么风格），通过AI快速组合成多份**结构清晰、风格匹配**的正式报告。

**适合在什么情况下使用？**
- **向上汇报：** 需要为不同层级的领导（老板、总监、VP）准备不同详略程度的周报/月报。
- **多版本需求：** 同一份工作内容，需要同时产出“高层速览版”和“详细复盘版”。
- **快速启动：** 面对空白文档不知如何下笔，需要AI提供一个高质量的结构化模板。
- **思路整理：** 将自己的工作亮点、风险和计划输入后，看AI如何组织和表述，获得启发。

**不适合什么情况？**
- **需要100%精确数据报表：** 它生成的是**文本报告**，不是动态图表或实时数据看板。最终数据需要你核对。
- **完全替代人工思考：** 它根据你输入的信息加工，如果输入是“垃圾”，输出也很难是“黄金”。核心的业务判断和深度分析仍需你完成。
- **高度定制化的复杂分析：** 比如需要联动多个数据库、进行复杂归因模型分析的报告。

## 【二】使用方式（给第一次接触的人）

**1. 页面输入是什么？**
页面左侧面板就是你的“信息填报表”，分为几大块：
- **基础信息：** 项目名称、负责人。
- **时间范围：** 报告涵盖的起止日期。
- **报告节奏：** 你要生成日报、周报还是月报？（可多选）
- **汇报对象：** 报告是给老板、总监还是跨部门同事看？（可多选）
- **报告侧重点：** 本次报告更关注增长、渠道、活动还是用户？（可多选）
- **核心内容：** 四个文本框，分别填写“核心数据”、“工作亮点”、“风险问题”、“下期计划”。
- **输出偏好：** 选择报告的文风，以及是否需要AI提供图表建议或待办清单。

**2. 用户通常会做哪几步操作？**
1.  **填写基本信息**：先填好项目名和时间。
2.  **勾选组合**：根据本次汇报需要，勾选1个或多个“报告节奏”和“汇报对象”。（例如：同时勾选“周报”和“月报”，以及“老板”和“总监”，AI会生成2x2=4份报告）。
3.  **输入核心内容**：将你这周的工作情况，分门别类填到四个文本框里。不需要很工整，列出要点即可。
4.  **选择风格与偏好**：根据汇报对象选择文风（给老板选“高层速览”）。
5.  **点击生成**：点击绿色的“生成运营报告”按钮。
6.  **查看与导出**：在右侧查看AI生成的多份报告，可以复制单份或全部，也可以导出为TXT或CSV文件。

**3. 输出结果长什么样？**
右侧会以“卡片”形式展示每一份报告。例如：
- **卡片1标题：** 【周报 | 老板速览】
- **卡片内容：** 一份结构清晰、结论先行、语言精炼的报告，可能包含“执行摘要”、“本期进展”、“问题风险”、“下期计划”、“所需支持”等部分。
- **特别功能：** 点击卡片上的“思考过程”，可以看到AI生成这份报告时的推理链条（如果使用了深度思考模型）。

**4. 有哪些容易忽略的使用细节？**
- **并行生成：** 你勾选了几个“节奏”和几个“对象”，它就会同时生成几份报告，而不是一份份排队生成。
- **思考过程：** 在“模型选择”中切换到“DeepSeek R1 (深度思考)”，生成的报告卡片会多出一个“思考过程”折叠区块，让你看到AI的推理，这对学习写作逻辑很有帮助。
- **全局设置：** 第一次使用前，务必点击右上角的“设置”图标，填入你自己的DeepSeek API Key，否则无法生成。
- **提示词自定义：** 如果你对AI生成的报告结构不满意，可以点击右上角“提示词”，修改给AI的“指令模板”，从而改变报告的框架和语气。

## 【三】核心结构拆解（学习重点）

这个网页采用了清晰的分层架构，是值得学习的优秀设计。

**关键模块与职责：**

1.  **输入配置模块（左侧面板）：**
    - **职责：** 收集用户所有原始输入和偏好设置。它将零散的信息（项目、日期、勾选项、文本框）分类聚合。
    - **设计亮点：** 使用“按钮式多选”代替复杂的下拉菜单，操作直观。将“汇报对象”和“报告侧重点”分离，逻辑清晰。

2.  **AI引擎与提示词模块（核心逻辑层）：**
    - **职责：** 这是网页的“大脑”。它把左侧收集到的所有信息，按照预设的“提示词模板”进行组装，变成一段给AI的完整、清晰的指令。
    - **输入 → 处理 → 输出链路：**
        - **输入：** 用户填写的所有字段 + 选择的选项。
        - **处理：** `Actions.buildUserPrompt()` 方法像“填空”一样，把 `{{project}}`、`{{type}}` 等变量替换成用户的实际内容。
        - **输出：** 一段个性化的、包含具体上下文的任务指令，发送给AI API。

3.  **多任务并行生成模块：**
    - **职责：** 管理“一对多”的生成任务。如果你勾选了“周报+月报”和“老板+总监”，它会创建4个独立的生成任务。
    - **设计亮点：** 使用 `Promise.all()` 让4个任务同时进行，极大缩短等待时间。每个任务都有独立的状态（加载中、成功、错误），互不影响。

4.  **结果展示与管理模块（右侧面板）：**
    - **职责：** 以卡片列表形式展示所有生成的报告，并提供复制、导出等实用功能。
    - **设计亮点：** 每张卡片信息完整（类型、对象、内容、思考过程），操作独立（单独复制）。`Marked.js`库将AI返回的Markdown文本渲染成美观的HTML。

**最值得学习的设计：**
**“状态中心化”与“分层架构”**。整个应用的状态（用户输入、配置、生成结果）被统一存储在 `Store` 对象中。UI层只负责显示和触发事件，业务逻辑在 `Actions` 层处理，数据请求在 `Api` 层封装。这种结构使得代码易于维护、调试和扩展。例如，要增加一个输入字段，你只需要在 `Store.input` 中定义，然后在UI层渲染并更新Store即可，其他层的代码几乎不用动。

## 【四】Prompt / AI 逻辑是如何被设计的？

**1. Prompt 扮演的角色：**
在这个网页中，Prompt（提示词）是连接**用户原始意图**和**AI格式化输出**的“翻译官”和“导演”。它不是一个简单的提问，而是一个包含角色设定、任务说明、输出格式要求的完整工作指令。

**2. 解决的是“理解问题”还是“生成问题”？**
主要解决 **“生成问题”**，但也极大地解决了 **“理解问题”**。
- **理解问题：** 通过System Prompt（“你是资深运营负责人…”），让AI进入正确的角色和思维模式，理解它需要以什么身份和视角来工作。
- **生成问题：** 通过User Prompt（模板），明确告诉AI：请用A结构、B风格，将C、D、E这些信息组织起来，生成一份给F看的G类型报告。这直接规定了输出的**形态**。

**3. 提示词中的关键变量：**
User Prompt模板中的 `{{...}}` 都是关键变量，它们是连接用户输入和AI指令的管道：
- `{{project}}`, `{{dateRange}}`: **上下文变量**，提供报告背景。
- `{{type}}`, `{{audience}}`, `{{style}}`: **任务规格变量**，定义报告类型和风格。
- `{{metrics}}`, `{{highlights}}`, `{{risks}}`, `{{nextPlan}}`: **内容变量**，是报告的血肉。
- `{{focusAreas}}`, `{{extra}}`: **修饰变量**，进一步细化要求。

**4. 如果只改 Prompt，不改代码，会发生什么？**
整个网页的**输出内容和格式**会发生根本性变化，而网页界面和操作流程保持不变。
- **例子1：** 把System Prompt中的“资深运营负责人”改成“幽默的团队协调员”，AI生成的报告语气会从严肃专业变得轻松活泼。
- **例子2：** 在User Prompt模板最后加上“请用表格形式总结下期计划”，那么所有生成的报告都会多出一个表格。
- **例子3：** 把输出结构从“5段式”改成“SWOT分析”，报告的整体框架就全变了。

**这证明了Prompt是控制AI应用的“软开关”**，调整Prompt的成本远低于修改代码。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步打造一个属于你的AI工具：

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标：** 做一个“项目进度报告生成器”或“个人周报生成器”。
- **操作：**
    1.  修改网页标题和Logo。
    2.  **重命名左侧输入模块的标签：** 把“核心指标”改成“项目里程碑”，“关键动作”改成“本周完成工作”，“风险阻塞”改成“遇到挑战”。
    3.  **修改右侧的选项文字：** 把“汇报视角”的选项改成“给客户”、“给项目经理”、“给团队成员”。
- **此时，** 核心的代码架构、生成逻辑、UI布局都没变，你只是做了一次“翻译”工作，但已经得到了一个全新的工具。

**第二步：调整输入字段或 Prompt**
- **目标：** 让工具更贴合你的新场景。
- **操作：**
    1.  在 `Store.options` 中修改或增加选项数组（如增加新的“报告侧重点”）。
    2.  在 `Store.defaultPrompt.user` 中，微调提示词模板。比如在个人周报场景，可以加入“请用第一人称‘我’来叙述”。
    3.  在UI层 (`_renderOptions`方法) 渲染你新增的选项按钮。
- **提示：** 先改Store里的数据，再让UI同步，这是分层架构的好处。

**第三步：改变输出形式或展示方式**
- **目标：** 让结果展示更具个性。
- **操作：**
    1.  修改结果卡片的样式（CSS），比如为不同的“汇报对象”使用不同的卡片边框颜色。
    2.  在 `UI._renderReportCard` 方法中，调整HTML结构，例如增加一个“一键生成PPT大纲”的按钮。
    3.  修改导出功能，比如增加“导出为Markdown”的选项。
- **至此，** 你已经拥有了一个在外观、功能上都与众不同的衍生作品。

**从哪里下手最安全？**
从 **【第一步】** 开始最安全。因为你不触碰任何核心的业务逻辑代码（Actions层）和数据交互代码（Api层），只修改静态文本和配置。这能让你在零风险的情况下，彻底理解整个应用的数据流动和模块关系。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“历史数据对比”输入：**
    - **操作：** 在“核心指标”文本框下方，增加一个“去年同期数据”或“上期目标”的文本输入框。
    - **修改：** 在 `Store.input` 中增加字段（如 `comparativeData`），在Prompt模板中增加对应的变量 `{{comparativeData}}`，在UI层增加这个输入框并绑定事件。
    - **效果：** AI在分析数据变化时，可以引用你提供的对比数据，使报告分析更深入。

2.  **接入多模型API，实现“模型对比”：**
    - **操作：** 在“模型选择”下拉框中增加选项，如“GPT-4o”、“Claude 3.5”。
    - **修改：** 在 `Api.streamChat` 方法中，根据传入的 `model` 参数，动态切换API端点（URL）和请求头。在 `Store.config` 中保存新的模型配置。
    - **效果：** 用户可以生成同一份提示词下不同模型的输出结果，进行对比，选择最适合报告写作的模型。

3.  **拆分为“草稿模式”与“正式模式”两个页面/视图：**
    - **操作：** 在生成按钮旁增加一个“切换到草稿模式”的按钮。
    - **修改：** “草稿模式”下，Prompt模板更简单，要求AI“快速列出要点、提出关键问题”，不要求完整结构。可以设计一个更简洁的UI视图来切换。
    - **效果：** 满足用户不同阶段的需求：前期用“草稿模式”梳理思路，后期用“正式模式”生成终稿。

4.  **优化交互：增加“输入引导”和“示例填充”：**
    - **操作：** 在每个输入框（如“核心指标”）的标签旁，增加一个“?”图标。
    - **修改：** 点击“?”时，显示一个浮动提示框，给出填写示例（如：“GMV：100万，环比+15%；DAU：50万，同比+20%”）。甚至可以做一个“填入示例”按钮，一键用示例内容填充所有输入框。
    - **效果：** 极大降低新用户的学习成本，让他们立刻明白该怎么用。

5.  **增加“报告模板库”功能：**
    - **操作：** 在页面顶部增加一个“模板”下拉菜单。
    - **修改：** 预定义几套不同的Prompt模板（如“活动复盘模板”、“渠道分析模板”、“季度规划模板”）。用户选择模板后，自动切换System Prompt和User Prompt，并可能预填某些侧重点选项。
    - **效果：** 从“万能工具”升级为“专业工具箱”，针对不同场景开箱即用。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做实时数据仪表盘：**
    - **局限性：** 它生成的是静态文本报告，数据一旦生成就不会自动更新。
    - **替代方案：** 如果需要实时监控数据，应该使用像 **Tableau、Power BI、或Grafana** 这样的专业数据可视化工具，它们能连接数据库并实时刷新。

2.  **不适合进行复杂的数学计算或数据验证：**
    - **局限性：** AI可能会在报告中“捏造”或“算错”数据。它擅长文本组织和逻辑表述，但不擅长精确计算。
    - **替代方案：** 所有核心数据指标的计算和验证，应该在输入到这个工具**之前**，使用 **Excel、Google Sheets 或 Python Pandas** 等工具完成。本工具只负责“汇报”这些已验证的结果。

3.  **不适合替代面对面的深度沟通和战略讨论：**
    - **局限性：** 它生成的是一份书面沟通材料，无法捕捉非语言信息，也无法进行实时问答和思想碰撞。
    - **替代方案：** 重要的战略复盘、问题诊断和计划制定，仍然需要通过 **会议、工作坊、一对一沟通** 等形式进行。本工具生成的报告可以作为这些会议的**讨论基础或会议纪要**。

4.  **不适合生成高度创意或艺术化的内容：**
    - **局限性：** 它的Prompt设计目标是“结构化、可执行、专业性”，因此输出风格偏向商务和务实。
    - **替代方案：** 如果需要生成品牌故事、创意文案、社交媒体帖子等，应该使用专门为**创意写作**调优的Prompt或工具，其风格会更活泼、更具感染力。

**总结：** 把这个工具看作是你的“高级文书助理”或“初稿撰写机器人”。它负责将你的想法和材料快速整理成规整的文档，极大地提升效率。但最终的决策权、数据把关和深度思考，必须牢牢掌握在你——它的使用者手中。
