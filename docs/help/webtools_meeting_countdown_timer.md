# Webtools 工具箱 - 帮助文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人效率工具箱**，它解决了日常工作和学习中“工具分散、切换麻烦”的问题。

**使用场景举例：**
- 你正在准备一个会议，需要快速计算会议时长和成本，同时想用倒计时提醒自己。
- 你在学习时，需要一个番茄钟来管理专注和休息时间，并随手记录一些想法。
- 你临时需要换算单位、生成随机内容，或者快速记一笔账，但不想打开多个网站或应用。

**它适合在什么情况下使用？**
- **临时性、轻量级的任务**：当你只需要一个简单功能，不想安装独立App或打开复杂软件时。
- **多任务切换**：当你需要在几个不同的小工具间快速切换时（比如从计时切换到记账）。
- **离线或隐私场景**：数据主要保存在你的浏览器本地，无需上传到服务器。

**它不适合什么情况？**
- **复杂专业计算**：如财务建模、工程仿真等需要专业公式和大量数据处理的场景。
- **团队协作**：这个工具是个人使用的，没有分享、同步或多人编辑功能。
- **长期、大量的数据管理**：比如管理一整年的详细账本，或撰写长篇文档。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
页面中央是一个“卡片”，根据你选择的不同工具，输入框会变化。常见的输入有：
- **数字**：如设置分钟数、输入金额。
- **文本**：如添加待办事项、记录笔记。
- **选择**：如从下拉列表中选择单位。

**用户通常会做哪几步操作？**
1.  **选择工具**：页面加载后，你会看到一个工具（如“会议倒计时”）。如果需要其他工具，你需要返回主页（点击左上角“返回 Webtools”）选择。
2.  **设置参数**：在工具的输入区域填写或选择所需的信息。
3.  **触发操作**：点击对应的按钮，如“开始”、“计算结果”、“添加”。
4.  **查看结果**：结果会显示在输入区域下方。

**输出结果长什么样？**
输出结果通常以清晰、突出的方式展示在卡片内：
- **计时器类**：以大号字体显示剩余或已用时间。
- **计算器类**：以标签和数值的形式展示结果。
- **清单类**：以列表形式展示新增的项目。

**有哪些容易忽略的使用细节？**
- **自动保存**：笔记工具（`note`）在你输入时会**自动保存**（有400毫秒延迟），无需手动点击保存按钮。
- **键盘快捷键**：在清单工具中，在输入框按 **回车键（Enter）** 可以直接添加项目，无需点击按钮。
- **数据持久化**：你输入的数据（如笔记、清单、记账记录）通常保存在你的浏览器本地，刷新页面不会丢失，但**更换设备或浏览器会丢失**。
- **设置按钮**：右上角的齿轮按钮（⚙️）用于配置AI API，但大部分工具无需此设置即可使用。

## 【三】核心结构拆解（学习重点）

这个页面的设计非常模块化，是学习“如何用一个页面管理多种功能”的优秀范例。

**关键模块组成：**
1.  **导航栏**：提供返回主页和打开设置的入口，保持全局一致性。
2.  **工具容器**：页面中央的白色卡片，是所有工具共享的“舞台”。
3.  **工具逻辑分发器**：这是看不见但最重要的部分。页面根据当前工具的 `type` 属性，决定显示哪一套界面和绑定哪一套操作函数。

**每个模块承担什么职责？**
- **导航栏**：负责页面导航和全局设置。
- **工具容器**：负责提供统一的视觉框架和布局。
- **工具逻辑分发器**：负责“按需渲染”。它像是一个总控开关，`x-show="tool.type === 'timer'"` 这样的语句就是开关，确保同一时间只显示一种工具的界面。

**输入 → 处理 → 输出 的逻辑链路：**
1.  **输入绑定**：通过 `x-model`（如 `x-model="tool.input"`）将输入框与底层数据对象（`tool`）的属性实时绑定。用户一输入，数据就更新。
2.  **事件触发**：用户点击按钮（如 `@click="startTimer(tool)"`）会触发一个特定的JavaScript函数。
3.  **函数处理**：被触发的函数（如 `startTimer`）会操作 `tool` 对象中的数据（如开始计时循环、计算结果、添加数组项）。
4.  **输出响应**：由于数据是响应式的，`tool` 对象的变化会自动触发页面上所有绑定该数据的地方更新。例如，`x-text="formatTime(tool.remaining)"` 会立即显示新的时间。

**哪一部分是“这个网页最值得学习的设计”？**
**“工具类型驱动UI”的模式** 是最值得学习的。它没有为10个工具写10个独立的HTML页面，而是定义了一个标准的 `tool` 数据对象和一套统一的容器。每种工具只是这个对象的不同“形态”（`type`）。这极大地提高了代码的可维护性和可扩展性。要新增一个工具，你主要是在JavaScript中定义一种新的 `tool` 形态和其处理逻辑，然后在HTML中复制粘贴一个类似的 `div` 模块并修改细节即可。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：在当前提供的HTML代码中，并未直接展示AI调用或Prompt处理的界面逻辑，但设置面板中出现了DeepSeek API的配置项。这表明该工具箱设计预留了AI能力集成。以下分析基于这种架构设计思想。

**Prompt 在这个页面中扮演什么角色？**
在这个工具箱的上下文中，Prompt（提示词）很可能被设计为**增强型工具的“配方”或“指令”**。例如，在“文本工具”或“生成器”中，用户输入的内容（如“写一首关于春天的诗”）会与一个预设的、优化过的Prompt模板结合，再发送给AI模型。

**它解决的是“理解问题”还是“生成问题”？**
两者兼有，但更偏向于**解决生成问题**。
- **理解问题**：Prompt需要帮助AI正确理解用户的简短输入在特定工具场景下的意图（例如，用户在“会议纪要生成器”里输入“讨论预算”，AI需要知道要生成会议纪要格式的文本）。
- **生成问题**：Prompt的核心是引导AI生成**格式正确、内容相关、风格合适**的产出物。

**哪些信息是 Prompt 中的关键变量？**
1.  **用户输入**：用户在文本框直接输入的内容。
2.  **工具上下文**：当前是哪个工具（如“头脑风暴”、“邮件起草”），这决定了Prompt的模板。
3.  **工具参数**：例如在生成器中，用户可能还设置了“风格”、“长度”等选项，这些都会作为变量插入Prompt。

**如果只改 Prompt，不改代码，会发生什么变化？**
AI工具的行为和输出质量会发生**根本性变化**。
- **改变输出风格**：将Prompt从“用专业商务语言”改为“用轻松幽默的口语”，AI生成的文本风格会完全不同。
- **改变输出结构**：Prompt中详细规定“请分三点列出，每点以emoji开头”，AI的输出就会结构化。
- **提升或降低专业性**：Prompt中加入“你是一名资深项目经理”，AI的回复会更具专业洞察力。
- **甚至改变工具功能**：将“生成会议议程”的Prompt改为“生成用户故事描述”，这个工具就变成了另一个工具。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下“安全”路径，逐步创建你的专属工具箱：

**第一步：复制框架，理解数据驱动**
1.  复制整个HTML结构，特别是外层 `x-data` 和 `x-init` 的部分。
2.  重点研究 `standalone.js`（虽然未提供，但可推断）中 `webtoolPage` 函数返回的 `tool` 对象的基本结构。尝试在浏览器控制台打印 `tool`，看看它有哪些属性（`name`, `desc`, `type`, `values`等）。
3.  **安全起点**：先不要修改任何工具逻辑，只尝试修改一个现有工具的 `name` 和 `desc`，看看页面标题和描述是否成功变化。这能验证你理解了数据绑定。

**第二步：替换/新增一种工具类型**
1.  **场景替换**：选择一个最简单的工具类型（如 `counter` 计数器）。保持其代码不变，只改变它的使用场景。例如，把“目标”和“当前进度”的标签改为“今日喝水杯数”和“已喝杯数”。这让你熟悉界面与数据的映射关系。
2.  **新增类型**：在HTML中找到所有 `x-show="tool.type === ..."` 的 `div` 块。选择其中一个（如 `generator`）作为模板，复制整个 `div`，将 `x-show` 的条件改为一个新的类型名，例如 `my_tool`。然后，在JavaScript中（假设你能访问 `standalone.js`），参照其他工具的定义方式，为 `my_tool` 类型初始化一个对应的数据对象和简单的处理函数（比如弹个窗）。

**第三步：深度定制交互与样式**
1.  **调整输入**：在你新增或修改的工具模块里，增减输入框（`input`）、下拉菜单（`select`）或文本框（`textarea`）。记得在对应的 `tool` 数据对象中增加相应的属性来绑定（`x-model`）。
2.  **改变输出**：修改结果显示区域的HTML结构。例如，把简单的数字显示改为一个进度条（需要引入进度条HTML和更新逻辑）。
3.  **微调样式**：使用Tailwind CSS类修改颜色、间距、圆角等。例如，将按钮的 `bg-indigo-600` 改为 `bg-blue-500`。

## 【六】3–5 个可直接尝试的改造方向

1.  **为“清单工具”增加标签和过滤功能**
    - **操作**：在添加清单项目的输入框旁，增加一个“标签”输入框或下拉选择（如：工作、生活、学习）。在每个清单项目显示时，同时显示一个小标签。在列表上方增加几个按钮，点击可以筛选显示特定标签的项目。
    - **价值**：让简单的待办事项列表变得可管理，实用性大幅提升。

2.  **将“记账工具”升级为可视化图表**
    - **操作**：引入一个轻量级图表库（如Chart.js）。在记账工具的结果区域，增加一个“图表”选项卡。点击后，将 `tool.entries` 中的数据按分类汇总，绘制成饼图或柱状图，展示消费构成。
    - **价值**：从枯燥的数字列表变为直观的视觉分析，更符合记账的核心需求。

3.  **创建“API连接器”工具类型**
    - **操作**：新增一个 `type` 为 `api_caller` 的工具。界面提供URL输入框、请求方式选择（GET/POST）、请求体（JSON）输入框。点击“发送”按钮后，使用浏览器的 `fetch` API 发送请求，并将响应结果美观地展示出来。
    - **价值**：将工具箱升级为开发者的轻量级调试助手，测试后端接口非常方便。

4.  **实现工具间的数据传递**
    - **操作**：在导航栏或工具卡片顶部增加一个“复制结果到剪贴板”的通用按钮。更进阶的是，设计一个“流水线”模式：例如，在“文本工具”中处理完一段文字后，可以有一个按钮“发送到笔记工具”，自动将输出内容填入笔记工具的编辑区。
    - **价值**：打破工具间的孤岛，形成工作流，真正提升效率。

5.  **优化移动端体验**
    - **操作**：检查所有工具在手机竖屏下的布局。将 `md:grid-cols-2` 或 `md:grid-cols-3` 调整为在小屏幕下堆叠显示。确保所有按钮和输入框的触摸区域足够大（使用 `py-3` 增加内边距）。
    - **价值**：让这个工具箱在手机上也能舒适使用，扩展使用场景。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合处理敏感或机密数据**：虽然数据存在本地，但浏览器本地存储（LocalStorage）并非绝对安全，可能被同一设备上的其他扩展程序或恶意软件读取。**切勿**用它存储密码、密钥或高度敏感的私人文档。
2.  **不适合进行复杂、多步骤的自动化任务**：它每个工具的功能是独立且即时的，缺乏“宏”、“批量处理”或“条件判断”的能力。如果你需要“当计时器结束时，自动保存笔记并发送一封邮件”，你需要寻找专业的自动化软件（如Zapier, Make, 或编写脚本）。
3.  **不适合作为永久的知识库或文件管理系统**：浏览器本地存储有容量限制（通常5-10MB），且数据容易因清除浏览器数据而丢失。它只是一个**便签式**的临时工作区。重要的笔记、文档、大量数据应使用专业的笔记软件、云盘或数据库。
4.  **不适合需要极高精度或实时同步的任务**：网页中的计时器、倒计时会受到浏览器标签页休眠、电脑睡眠等因素的影响，可能产生微小误差。对于科学实验、体育比赛正式计时等场景，请使用专用软件或硬件。

**总结**：把这个工具箱想象成你办公桌上的一个**多功能笔筒**，里面有便签纸、计算器、秒表、小尺子。它方便、随手可得，能解决你80%的日常小问题。但对于撰写正式报告、管理大型项目或进行精密测量，你还是需要打开电脑上的专业软件。
