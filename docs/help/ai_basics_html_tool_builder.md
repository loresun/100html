# AI 全栈工具脚手架 - 帮助文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你有一个简单的工具想法（比如“周报生成器”、“图片描述生成器”），但不知道如何把它变成一个能运行的网页应用时，这个工具能帮你。它不直接生成代码，而是生成一份**给AI编程助手（如Cursor、Windsurf）的详细“施工图纸”**，让AI能更准确地为你编写出完整的单文件网页。

**适合：**
- 想快速验证一个工具想法，但前端技术不熟练的人
- 需要为特定场景（如团队周报、内容整理）制作一次性工具
- 学习如何向AI清晰地描述开发需求

**不适合：**
- 需要复杂后端、数据库或用户系统的项目
- 追求极致性能或需要精细定制UI的大型应用
- 已经熟悉完整开发流程的专业开发者

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **核心想法**：在文本框中描述你想做的工具（如“一个把会议录音转成会议纪要的工具”）
2. **视觉风格**：选择主色调（蓝、紫、绿等）
3. **技术偏好**：选择Vue 3（交互复杂）或Alpine.js（轻量简单）

**操作步骤：**
1. 在左侧“描述你的想法”区域，用自然语言写下你的需求
2. （可选）点击右上角齿轮图标，设置你的DeepSeek API Key（设置后AI会自动帮你扩写需求）
3. 点击“生成Prompt”按钮
4. 右侧会生成一份详细的提示词文档
5. 点击“复制提示词”，将其粘贴到Cursor、Windsurf或ChatGPT中
6. 让AI根据这份提示词为你编写代码

**输出结果长什么样？**
生成的是一个Markdown格式的技术需求文档，包含：
- 详细的需求描述（可能被AI扩写过）
- 严格的技术栈规范（用什么框架、如何调用API）
- 视觉风格要求
- 代码编写指令

**容易忽略的细节：**
- **API Key的作用**：如果设置了API Key，系统会用AI自动扩写你的需求，让提示词更详细
- **复制后如何使用**：生成的提示词需要**粘贴到AI编程工具中**，不是直接运行
- **技术栈选择**：Vue 3适合有复杂交互的工具，Alpine.js适合简单展示型工具

## 【三】核心结构拆解（学习重点）

**页面由四个关键模块组成：**

1. **配置管理模块**（右上角）
   - **职责**：管理API Key和模型选择，保存到浏览器本地
   - **设计亮点**：所有生成的工具都共享同一套配置，实现“一次设置，处处可用”

2. **需求输入模块**（左侧上部）
   - **职责**：收集用户原始想法、视觉偏好、技术选择
   - **设计亮点**：用最少的必填项（只需描述想法）启动流程

3. **AI需求扩写模块**（后台逻辑）
   - **职责**：当有API Key时，自动调用AI将模糊想法转为详细需求
   - **设计亮点**：用AI完善AI提示词，形成“增强回路”

4. **结构化Prompt生成模块**（核心）
   - **职责**：将用户输入+AI扩写+技术规范，组合成给编程AI的“施工图”
   - **设计亮点**：固定技术栈、强制API集成规范、包含完整UI要求

**输入→处理→输出链路：**
```
用户描述想法 → （可选：AI扩写需求） → 组合技术规范 → 生成结构化Prompt → 复制给编程AI
```

**最值得学习的设计：**
**“元提示词”的构造艺术**。这个页面本身就是一个“提示词生成器”，它教会AI如何生成代码。最巧妙的是：
- 它强制所有生成的工具都有统一的配置管理界面
- 它规定了具体的技术栈和API调用方式
- 它用“需求描述+技术规范”的双层结构，确保AI输出的一致性

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中的角色：**
扮演“技术产品经理”和“架构师”的双重角色。它不直接生成最终产品，而是生成一份**让另一个AI能高效工作的详细需求文档**。

**解决的是“理解问题”还是“生成问题”？**
主要解决“**理解问题**”。它把用户模糊的“我想要一个...”转化为AI程序员能精确理解的“请用Vue 3实现一个包含...功能的单文件应用”。

**Prompt中的关键变量：**
1. `detailedRequirements`：用户需求（可能被AI扩写过）
2. `techStack.value`：技术框架选择（Vue或Alpine）
3. `themeColor.value`：视觉主题色
4. **硬编码的技术规范**：API集成方式、配置读取逻辑、UI组件要求

**如果只改Prompt，不改代码，会发生什么？**
- 改变技术栈要求（如换成React）
- 改变API提供商（如换成OpenAI）
- 改变UI规范（如要求暗黑模式）
- 改变代码风格（如要求TypeScript）

**但注意**：页面中的“AI需求扩写”功能依赖于DeepSeek API，如果完全更换API提供商，这部分代码也需要调整。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 把“生成工具脚手架”换成其他场景，如“生成数据分析报告模板”、“生成产品需求文档框架”
- 只需修改页面标题、描述和示例文字
- **保持左侧输入+右侧输出的基本布局**

**第二步：调整输入字段**
- 根据新场景增加/减少输入项
- 例如做“报告生成器”，可以增加“报告类型”、“受众群体”、“长度要求”等字段
- **保持技术栈选择器**（这是核心学习点）

**第三步：修改Prompt模板**
- 在`generatePrompt`函数中，修改那个大的模板字符串
- 根据新场景调整“技术栈规范”和“视觉风格”部分
- **保留API集成规范**（这是本设计的精髓）

**第四步：改变输出形式**
- 如果生成的不是给AI的提示词，而是其他内容（如直接生成Markdown报告）
- 调整右侧预览区的样式和复制逻辑

**从哪里下手最安全？**
从**修改视觉主题色选项**开始。把`themeColor`的选项从“科技蓝、创意紫”改成你需要的配色方案。这是最表层、最安全的改动。

## 【六】3–5个可直接尝试的改造方向

**1. 增加“复杂度级别”选择器**
- 在技术栈选择旁增加“应用复杂度”下拉框
- 选项：极简版（仅HTML+CSS）、标准版（当前）、增强版（包含本地存储、导出功能）
- 根据选择动态调整Prompt中的技术要求

**2. 支持多AI模型提供商**
- 在设置中增加“API提供商”选择：DeepSeek、OpenAI、Claude、智谱AI等
- 根据选择动态调整Prompt中的API调用示例和配置结构
- 让生成的工具能适配不同厂商的API

**3. 添加“模板库”功能**
- 在输入区上方增加“从模板开始”按钮
- 提供几个预设模板：周报生成器、图片描述工具、代码解释器、会议纪要助手
- 点击模板后自动填充描述区域，用户只需微调

**4. 实现“实时预览”模式**
- 在右侧代码预览区增加标签页：“Prompt预览”和“生成工具预览”
- 点击“预览”时，用iframe实时渲染生成的工具（需要调用AI并执行代码）
- 这需要后端支持或使用浏览器的动态代码执行能力

**5. 增加“协作优化”功能**
- 在生成的Prompt中增加“团队协作规范”部分
- 包括：代码注释标准、Git提交信息格式、代码审查要点
- 让生成的工具代码更易于团队维护和迭代

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**

1. **不适合生成复杂应用**
   - 如果需求涉及用户登录、数据库、实时通信等
   - **应该换用**：专业的低代码平台（如Retool、Bubble）或学习完整的前后端开发

2. **不适合需要定制设计系统的项目**
   - 生成的工具遵循固定的Tailwind CSS样式
   - 如果需要独特的设计语言或复杂的动画
   - **应该换用**：专业的设计工具（Figma）配合前端框架手动开发

3. **不适合需要长期维护的产品**
   - 生成的是单文件HTML，难以模块化、测试和迭代
   - **应该换用**：标准的工程化项目结构（Vite + Vue/React + 状态管理）

4. **不适合对性能有极致要求的场景**
   - 所有依赖通过CDN加载，可能影响加载速度
   - **应该换用**：构建工具打包优化，或使用更轻量的解决方案

5. **不适合完全不懂技术描述的用户**
   - 用户仍需能用自然语言描述需求
   - 如果连“输入框”、“按钮”、“列表”这些概念都难以描述
   - **应该换用**：更直观的拖拽式建站工具（如Wix、Webflow）

---

**记住**：这个工具的价值在于“**用AI教会AI**”。你学到的不仅是做一个提示词生成器，更是如何构建清晰的开发规范，让AI成为可靠的技术执行者。从模仿它的结构开始，逐步加入你自己的理解和需求，你就能创造出属于自己的“AI协作工作流”。
