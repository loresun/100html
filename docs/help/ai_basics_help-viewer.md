# 帮助文档 - AI 内容创作工坊：学习指南

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你正在开发一个AI工具网站，里面有很多功能模块。每个模块都需要一份详细的说明文档，告诉用户怎么使用、有什么功能、需要注意什么。如果每份文档都单独做一个HTML页面，不仅开发麻烦，后期更新维护更是噩梦。

这个网页就是一个**智能文档查看器**。它专门解决“如何在一个统一的界面里，优雅地展示和管理大量Markdown格式的帮助文档”这个问题。

**适合的使用场景：**
- 你的项目有很多功能模块，每个都需要文档说明
- 你希望文档内容由非技术人员（如产品经理、运营）也能轻松编辑
- 你想让文档看起来专业、美观，有良好的阅读体验（目录导航、代码高亮等）
- 你需要文档支持直接在线编辑（比如链接到GitHub）

**不适合的情况：**
- 文档需要复杂的交互功能（如可编辑表格、实时计算）
- 文档内容需要严格的权限控制（不同用户看到不同内容）
- 文档数量极少（1-2页），直接写进HTML更简单

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
这个页面本身没有“表单输入”，它的输入来自**URL地址栏**。具体来说，是通过URL中的`?doc=`参数来指定要看哪个文档。

**用户通常会做哪几步操作？**
1. **直接访问**：打开页面时，如果没有指定文档，会看到一个欢迎界面，上面有几个示例文档链接
2. **点击示例**：点击“智能会议纪要助手”这样的链接，页面会自动加载对应的Markdown文档
3. **阅读文档**：文档会以美观的格式展示出来，左侧有自动生成的目录，可以点击跳转
4. **编辑文档**：如果想修改文档内容，可以点击右上角的“编辑此页”，会跳转到GitHub的编辑页面（如果配置了的话）

**输出结果长什么样？**
- 一个专业美观的文档阅读界面
- 左侧：自动生成的目录，根据文档标题层级显示
- 中间：格式化后的文档内容（支持标题、列表、代码块、表格、引用等Markdown语法）
- 顶部：显示当前文档名称
- 底部：版权信息和编辑链接

**有哪些容易忽略的使用细节？**
1. **URL参数是核心**：所有文档切换都通过修改URL参数实现，这意味着你可以把文档链接直接分享给别人
2. **支持前进后退**：浏览器前进后退按钮可以切换文档，因为页面监听了URL变化
3. **目录自动生成**：只有`#`、`##`、`###`这三个层级的标题会被收录到目录中
4. **代码高亮**：代码块需要指定语言（如` ```javascript `）才会被高亮显示
5. **编辑功能依赖GitHub**：点击“编辑此页”需要你的文档实际存放在GitHub仓库中

## 【三】核心结构拆解（学习重点）

这个页面由**5个关键模块**组成，每个模块职责明确：

### 模块1：导航与状态栏（顶部）
- **职责**：显示当前文档名称、提供返回链接、展示加载状态
- **设计亮点**：使用了毛玻璃效果（`backdrop-blur-md`）和粘性定位，滚动时始终可见

### 模块2：目录侧边栏（左侧）
- **职责**：自动分析文档标题，生成可点击的目录导航
- **关键逻辑**：通过正则表达式`/^(#{1,3})\s+(.+)$/gm`提取Markdown中的1-3级标题
- **交互细节**：不同层级标题有不同缩进和样式，点击平滑滚动到对应位置

### 模块3：文档内容区（中间）
- **职责**：渲染和展示Markdown内容
- **核心技术栈**：
  - `marked.js`：将Markdown文本转为HTML
  - `highlight.js`：为代码块添加语法高亮
  - 自定义CSS：美化所有Markdown元素（标题、列表、表格、引用等）

### 模块4：状态管理（Vue响应式数据）
- **职责**：管理页面所有状态变化
- **核心状态**：
  - `docPath`：当前文档路径（从URL获取）
  - `loading`：是否正在加载
  - `error`：错误信息
  - `htmlContent`：解析后的HTML
  - `toc`：目录数组
- **状态流转**：URL变化 → 触发加载 → 更新状态 → 重新渲染

### 模块5：错误与空状态处理
- **职责**：优雅处理各种异常情况
- **三种状态**：
  1. 加载中：显示旋转动画
  2. 加载失败：显示错误信息和重试按钮
  3. 无文档：显示欢迎界面和示例链接

**最值得学习的设计：**
**“URL驱动”的文档加载机制**。整个页面的核心逻辑是：监听URL参数变化 → 加载对应Markdown文件 → 解析渲染。这种设计让文档管理变得极其简单：你只需要在服务器上存放Markdown文件，然后通过不同的URL就能访问不同文档。这比传统的多页面方案要优雅得多。

## 【四】Prompt / AI 逻辑是如何被设计的？

在这个页面中，**Prompt并不是核心**，因为这是一个文档查看器，不是AI生成工具。但是，我们可以从中学到重要的**设计模式**：

**如果这是AI应用，Prompt会如何设计？**
假设我们要把它改造成“AI文档助手”，可以这样设计Prompt：

```markdown
你是一个专业的文档撰写助手。请根据以下要求生成帮助文档：

【文档主题】{{user_topic}}
【目标读者】{{target_audience}}
【文档类型】{{doc_type}}（如：使用指南、API文档、教程等）
【详细要求】{{specific_requirements}}

请按照以下结构组织内容：
1. 概述（解决什么问题）
2. 快速开始（3步上手）
3. 详细功能说明
4. 常见问题
5. 进阶技巧

要求：使用Markdown格式，包含代码示例和表格说明。
```

**在这个假设中：**
- Prompt解决的是“**生成问题**”——根据用户输入生成结构化的文档
- 关键变量：`user_topic`、`target_audience`、`doc_type`、`specific_requirements`
- 如果只改Prompt：生成的文档内容会变化，但页面的展示方式不变

**从当前页面学到的AI应用设计思路：**
即使没有AI，这个页面也展示了**良好的输入-处理-输出分离**：
- 输入：URL参数（或未来可能是用户输入的Prompt）
- 处理：Markdown解析、目录提取、代码高亮
- 输出：美观的文档界面

这种清晰的分离，正是构建AI应用时需要遵循的原则。

## 【五】如何模仿它，做出你自己的版本？

### 第一步：保持结构不变，替换使用场景（最安全）
不要碰代码逻辑，只改内容和样式：
1. 修改`sampleDocs`数组，换成你自己的文档列表
2. 修改CSS中的颜色（把蓝色主题`#3b82f6`换成你品牌的主色）
3. 修改页脚的公司名称和版权信息
4. 准备几个Markdown文档，放在`docs/`目录下

### 第二步：调整“输入”方式
当前是通过URL参数输入，你可以改为：
1. **下拉菜单选择**：在页面顶部加一个下拉框，选择文档后自动更新URL
2. **搜索框**：输入文档名称或关键词，过滤可用的文档
3. **分类导航**：按文档类型（教程、API、FAQ）分组展示

### 第三步：增强“输出”展示
1. **添加打印功能**：在文档右上角加“打印”按钮，优化打印样式
2. **暗色模式**：添加主题切换，支持暗色阅读
3. **字数统计**：在底部显示文档字数、阅读时间估计
4. **版本对比**：如果是API文档，可以切换不同版本查看差异

**从哪里下手最安全？**
从**修改`sampleDocs`和准备自己的Markdown文档**开始。这是零风险、立即见效的改动。你能马上看到自己的文档在这个漂亮的查看器里展示出来，获得正反馈后再进行下一步。

## 【六】3–5个可直接尝试的改造方向

### 1. 添加文档搜索功能
- **具体做法**：在导航栏添加搜索框
- **技术实现**：预先为所有文档建立索引（标题+内容），使用`lunr.js`或`FlexSearch`实现客户端搜索
- **用户体验**：输入关键词时实时显示匹配的文档和片段

### 2. 支持文档“收藏”或“最近阅读”
- **具体做法**：利用`localStorage`存储用户行为
- **实现细节**：
  ```javascript
  // 记录最近打开的文档
  const recentDocs = JSON.parse(localStorage.getItem('recentDocs') || '[]');
  recentDocs.unshift({ path: docPath, title: currentDoc, time: Date.now() });
  localStorage.setItem('recentDocs', JSON.stringify(recentDocs.slice(0, 5)));
  ```
- **展示位置**：在欢迎界面或侧边栏底部显示“最近阅读”

### 3. 添加文档评分或反馈
- **具体做法**：在每篇文档底部添加“这篇文档有帮助吗？”（是/否）按钮
- **数据收集**：将反馈发送到后端API，或使用Google Forms等无代码工具
- **进阶**：根据负面反馈多的文档，自动提醒维护者更新

### 4. 集成AI文档摘要
- **具体做法**：为长文档自动生成“TL;DR”（太长不看）摘要
- **技术方案**：
  - 简单版：提取前3段作为摘要
  - AI版：调用OpenAI API的`gpt-3.5-turbo`生成摘要
- **展示位置**：在文档顶部显示折叠的摘要框

### 5. 多语言支持
- **具体做法**：为同一份文档提供多种语言版本
- **实现方式**：
  - 文档命名：`meeting_minutes.zh-CN.md`、`meeting_minutes.en.md`
  - 语言切换器：在导航栏添加语言选择下拉框
  - 自动重定向：根据浏览器语言设置默认语言

## 【七】这个网页不适合做什么？（边界提醒）

### 局限性：
1. **不适合实时协作编辑**：这只是一个查看器，虽然可以跳转到GitHub编辑，但不支持多人同时在线编辑（如Google Docs那种）
2. **不适合敏感文档**：所有文档都是公开可访问的（通过URL），没有权限控制
3. **不适合超大文档**：如果单个Markdown文件超过1MB，加载和解析可能会有性能问题
4. **不适合动态内容**：文档内容是静态的，无法嵌入需要后端数据的动态组件

### 如果用户想做X，应该换什么工具：
- **想做在线协作编辑** → 使用[Notion](https://www.notion.so/)、[语雀](https://www.yuque.com/)或自建[Outline](https://www.getoutline.com/)
- **需要严格的权限管理** → 使用[Confluence](https://www.atlassian.com/software/confluence)或[GitBook](https://www.gitbook.com/)
- **文档需要复杂交互** → 考虑使用[Docusaurus](https://docusaurus.io/)、[VuePress](https://vuepress.vuejs.org/)等静态站点生成器
- **想要AI自动生成文档** → 结合当前页面+后端API，在加载文档前先调用AI生成内容
