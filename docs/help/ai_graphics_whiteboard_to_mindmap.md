# 会议白板转思维导图 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你刚刚结束了一场重要的团队会议。白板上画满了各种想法、任务和决策，大家用马克笔写下了密密麻麻的要点。现在，你需要把这些凌乱但宝贵的内容整理成一份清晰的思维导图，用于会议纪要、项目规划或分享给未参会的同事。

这个网页就是为此而生。你只需用手机拍下白板的照片，上传到这里，AI会自动识别照片中的文字和层级关系，并生成一个可直接编辑、导出的思维导图。它特别适合：
- **会议记录整理**：将白板上的头脑风暴结果结构化
- **课堂笔记转换**：将老师板书转化为易于复习的导图
- **项目规划可视化**：将手绘的项目框架转为电子版

**不适合的情况：**
- 照片模糊、光线极差或文字过于潦草时，识别准确率会下降
- 需要实时协作编辑（它更偏向“一次性转换”）
- 白板内容包含大量复杂图表、数学公式或专业符号

## 【二】使用方式（给第一次接触的人）

**第一步：准备你的“原料”**
- **输入**：一张清晰的白板/黑板照片（手机拍摄即可）
- 确保照片中的文字尽可能清晰可辨
- 建议在光线充足的环境下拍摄

**第二步：上传与识别**
1. 打开网页，点击左侧“上传白板照片”区域
2. 从电脑中选择你的照片（支持常见图片格式）
3. 照片预览出现后，点击蓝色的“开始识别”按钮
4. 等待几秒钟，AI正在分析照片内容

**第三步：查看与调整结果**
- 右侧区域会实时显示生成的思维导图
- 左侧下方会出现对应的“Mermaid代码”（一种文本化的图表描述语言）
- 如果对结果不满意，你可以：
  - 直接编辑代码文本，然后点击“重新渲染”
  - 重新上传更清晰的照片再次识别

**第四步：导出与使用**
- **复制代码**：将Mermaid代码复制到支持该语法的笔记软件（如Obsidian、Notion）
- **导出SVG**：下载为矢量图片，插入到PPT、文档中
- **继续编辑**：在网页上调整后，再导出

**容易忽略的细节：**
1. **首次使用需配置API**：点击右上角“模型配置”，按提示填写API Key（GLM-4V有免费额度）
2. **代码可手动微调**：AI可能无法完美识别所有层级关系，手动编辑代码比重新识别更快
3. **渲染失败有提示**：如果导图显示异常，页面会给出具体错误和建议，别慌

## 【三】核心结构拆解（学习重点）

这个页面由四个核心模块组成，像一条流水线：

**模块1：输入与上传区（左侧上部）**
- **职责**：接收用户图片，转换为AI可处理的格式
- **关键设计**：将图片文件通过`FileReader`转换为Base64编码，这是能通过网络传输给AI API的“通用语言”
- **输入→处理**：用户选择文件 → 浏览器读取 → 转换为Base64字符串 → 存储备用

**模块2：AI处理引擎（看不见的后台）**
- **职责**：连接视觉AI模型，发送图片和指令，接收分析结果
- **关键设计**：抽象了两种AI模型（GLM-4V和豆包视觉）的调用方式，通过配置切换，不修改核心逻辑
- **处理链路**：Base64图片 + Prompt指令 → 发送到对应API → 接收文本回复 → 提取Mermaid代码

**模块3：代码编辑与渲染区（左右联动）**
- **职责**：提供“可编辑的中间层”和“可视化结果”
- **关键设计**：**分离了“数据”和“展示”**。Mermaid代码是数据，右侧导图是展示。编辑代码，展示实时更新。
- **核心价值**：即使AI识别不完美，用户也能通过修改文本代码来调整图形，无需设计软件技能。

**模块4：配置与导出区（分散各处）**
- **职责**：管理设置、提供输出选项
- **设计亮点**：配置通过`localStorage`保存在本地，下次访问无需重新填写API Key

**最值得学习的设计：**
**“容错与修正管道”**。注意代码中的`validateAndFixMermaidCode`和`convertGraphToMindmap`函数。AI有时会返回错误的图表语法，这个网页没有直接报错，而是尝试自动修复、转换格式。这种“猜测用户意图并尽力补救”的设计，极大提升了用户体验。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt的角色：**
在这个页面中，Prompt不是让AI自由发挥的“创意指令”，而是**严格的格式转换说明书**。它告诉AI：“请按照X规则，把图片内容转换成Y格式。”

**解决什么问题：**
解决的是**结构化生成问题**。AI需要理解图片内容（识别问题），但更重要的是按照特定格式输出（生成问题）。Prompt的核心任务是约束输出格式。

**Prompt中的关键变量：**
1. **任务描述**：“识别白板照片中的手写内容，提取关键信息和层级关系”
2. **输出格式指令**：“必须使用mindmap语法格式，通过缩进表示层级关系”
3. **正面示例**：给出正确的Mermaid代码样板
4. **负面约束**：“禁止使用graph、flowchart或箭头语法”
5. **格式细节**：明确缩进空格数、根节点写法等

**如果只改Prompt，不改代码：**
- 改任务描述：如“识别白板中的待办事项” → AI会聚焦任务列表而非主题关系
- 改输出格式：如“生成Markdown列表” → 右侧渲染会失败（因为代码期待Mermaid格式）
- 改约束条件：如允许使用graph语法 → 可能不需要`convertGraphToMindmap`修复函数了

**学习要点**：好的Prompt是“对AI和对后续程序都友好的指令”。它既要让人看懂，也要让程序能稳定解析。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：替换场景，保持骨架**
- 将“白板照片转思维导图”改为你的场景，例如：
  - “商品照片转商品描述”
  - “手写笔记转结构化摘要”
  - “界面截图转HTML代码”
- **保持结构不变**：上传区、配置区、结果显示区
- 只修改页面标题、提示文字等表面内容

**第二步：调整输入和Prompt**
- 如果你的输入不是图片（比如是文本），修改上传模块
- **重点重写Prompt**：根据你的新场景，重新设计给AI的指令
  - 明确新任务：“分析这张商品图片，生成包含颜色、材质、特点的描述”
  - 明确新格式：“以JSON格式输出，包含title、features、price_range字段”
- 此时，右侧显示区可能暂时显示原始文本，没关系

**第三步：改变输出展示方式**
- 如果输出是JSON，不要用Mermaid渲染，改用`JSON.stringify`美化显示
- 如果输出是HTML代码，可以添加一个“预览iframe”来实时显示
- 调整导出功能：导出JSON文件、复制HTML代码等

**第四步：优化与个性化**
- 根据新场景添加专属功能（如商品场景可加“翻译成英文”按钮）
- 修改UI颜色、图标，让它符合你的品牌

**从哪里下手最安全？**
从**第二步的Prompt修改**开始。因为：
1. 不涉及复杂的前端逻辑
2. 立即能看到AI返回的变化
3. 即使失败，也不会破坏原有功能

## 【六】3–5个可直接尝试的改造方向

**1. 增加“多图连续分析”功能**
- **现状**：一次只能上传一张图
- **改造**：允许上传多张白板照片（如会议不同阶段的记录）
- **实现提示**：
  - 将`whiteboardImage`改为数组
  - 修改上传区域为多文件选择
  - 在Prompt中说明：“以下是同一会议的三张白板照片，请合并分析，生成统一的思维导图”
  - 将多张图片的Base64一起发送给AI（注意API可能有长度限制）

**2. 切换为本地AI模型，保护隐私**
- **现状**：依赖云端API，图片上传到外部服务器
- **改造**：集成本地运行的视觉模型（如使用Transformers.js）
- **实现提示**：
  - 添加“使用本地模型”选项
  - 页面加载时下载小型视觉模型文件
  - 在用户浏览器中直接分析图片，不上传
  - 适合处理敏感内容（如内部战略会议白板）

**3. 增加“模板选择”和“样式定制”**
- **现状**：思维导图只有一种默认样式
- **改造**：让用户选择不同风格
- **实现提示**：
  - 添加模板选择按钮：“商务风格”、“创意风格”、“简约风格”
  - 每个模板对应不同的Mermaid主题配置
  - 甚至可以修改节点形状、颜色方案
  - 代码层面：`mermaid.initialize`中的`theme`参数可动态更改

**4. 拆分为“上传-分析-编辑”三步页面**
- **现状**：所有功能在一个页面
- **改造**：适合更复杂的流程
- **实现提示**：
  - 页面1：上传和基础设置
  - 页面2：显示AI初步结果，提供快速修正选项（如合并重复节点）
  - 页面3：深度编辑和导出
  - 使用URL参数或localStorage在页面间传递数据

**5. 添加“历史记录”功能**
- **现状**：关闭页面后记录消失
- **改造**：保存每次转换记录
- **实现提示**：
  - 在`localStorage`中保存数组，包含时间、缩略图、代码
  - 添加侧边栏或新页面展示历史列表
  - 点击历史项可重新加载并编辑
  - 注意清理机制，避免存储空间过大

## 【七】这个网页不适合做什么？（边界提醒）

**1. 不适合作为实时协作白板**
- **局限性**：它是“拍照→转换”的单向流程，不能多人实时在同一导图上编辑
- **如果你需要**：团队实时协作绘制思维导图
- **应该换用**：Miro、FigJam、Whimsical等专业协作工具

**2. 不适合识别复杂图表或专业图纸**
- **局限性**：AI训练数据主要是自然场景和文档，对工程图纸、电路图、化学结构式识别能力有限
- **如果你需要**：将专业图纸转为CAD文件
- **应该换用**：专业的OCR软件或行业专用工具（如Mathpix for公式）

**3. 不适合处理超长或逻辑极其复杂的内容**
- **局限性**：思维导图适合层级关系，但不适合表现复杂流程、条件判断或时间线
- **如果你需要**：将会议讨论转化为项目甘特图或流程图
- **应该换用**：手动使用专业图表工具，或寻找专门“文本转流程图”的AI工具

**4. 不适合无网络环境使用**
- **局限性**：依赖云端AI API，断网时无法识别
- **如果你需要**：在离线环境（如飞机上、保密会议室）使用
- **应该考虑**：上述的“本地AI模型”改造方向，或准备离线备用方案

**记住**：工具都有其边界。这个网页的巧妙之处在于它精准地解决了一个特定痛点（白板转导图），而不是试图做一个“万能转换器”。理解这个边界，你就能更好地使用它，也能更明智地决定何时需要其他工具。
