# 运动消耗估算工具 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在健身或规划运动计划，想知道“跑步30分钟能消耗多少卡路里？”或者“游泳和骑自行车哪个更燃脂？”。这个网页就是一个**个人运动能量计算器**，它能根据你的体重、运动类型和时长，快速估算出运动消耗的热量。

**适合的使用场景：**
- 健身爱好者想了解不同运动的能量消耗差异
- 减肥人士需要监控每日运动消耗
- 运动新手想制定合理的运动计划
- 快速比较不同运动方案的效率

**不适合的情况：**
- 需要精确到个体代谢差异的专业医学计算
- 包含复杂身体指标（如体脂率、肌肉量）的详细分析
- 长期饮食与运动综合规划
- 竞技运动员的专业训练监控

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你会看到几个简单的输入框，通常包括：
- 你的体重（公斤或磅）
- 运动时长（分钟）
- 运动类型（可能有下拉选择）

**用户通常会做哪几步操作？**
1. 在“体重”框输入你的体重数字
2. 在“时长”框输入你计划运动的时间
3. 选择或输入运动类型（如跑步、游泳、骑行等）
4. 点击“计算结果”按钮

**输出结果长什么样？**
结果会清晰地显示在一个卡片中，例如：
```
估算消耗：320 千卡
相当于：1.5碗米饭的热量
```

**有哪些容易忽略的使用细节？**
- 注意单位：体重是公斤还是磅？时长是分钟还是小时？
- 有些运动可能有强度选项（如慢跑vs快跑）
- 结果只是估算值，实际消耗会因人而异
- 可以尝试不同组合，快速比较多种方案

## 【三】核心结构拆解（学习重点）

这个页面采用了**模块化设计**，可以轻松扩展成多种工具。让我们拆解它的核心结构：

**关键模块组成：**
1. **导航栏** - 返回入口和设置按钮
2. **工具标题区** - 显示当前工具名称和描述
3. **动态内容区** - 根据工具类型显示不同的界面
4. **设置面板** - API配置（虽然当前页面未使用AI，但预留了接口）

**每个模块的职责：**
- **导航栏**：提供页面导航和全局设置入口
- **标题区**：明确当前工具的功能定位
- **输入区**：收集用户数据，每种工具类型有不同的输入字段
- **操作区**：触发计算、开始、重置等动作
- **结果区**：以清晰格式展示计算结果

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入（体重、时长等） 
    ↓
点击“计算”按钮触发函数
    ↓
JavaScript执行预设的计算公式
    ↓
结果格式化并显示在界面上
```

**最值得学习的设计：**
**“工具类型”驱动界面切换**的设计模式。页面通过`tool.type`判断当前是哪种工具（计算器、计时器、清单等），然后只显示对应的HTML模块。这种设计让一个页面可以承载多种功能，代码复用性极高。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注：当前页面代码中虽然包含了API配置界面，但实际并未在运动消耗计算中使用AI。这里我们分析**如果**要加入AI功能，应该如何设计。

**Prompt在这个页面中可能扮演的角色：**
如果升级为AI版本，Prompt可以：
1. **理解自然语言输入** - 如“我想知道70公斤的人游泳45分钟消耗多少”
2. **生成个性化建议** - 根据用户目标推荐运动组合
3. **解释计算结果** - 用更生动的语言说明“320千卡意味着什么”

**解决的是“理解问题”还是“生成问题”？**
- **理解问题**：解析用户模糊的描述（“中等强度运动”）
- **生成问题**：创建个性化的运动方案描述

**Prompt中的关键变量：**
```javascript
// 假设的Prompt模板
const prompt = `
用户信息：
- 体重：${weight}公斤
- 运动类型：${exercise}
- 运动时长：${duration}分钟
- 用户目标：${goal}（如减肥、增肌、保持健康）

请计算消耗的热量，并用通俗易懂的方式解释结果。
`;
```

**如果只改Prompt，不改代码，会发生什么变化？**
- 改变AI回复的风格（严肃vs幽默）
- 增加或减少输出信息的详细程度
- 调整建议的侧重点（科学依据vs实用技巧）
- 改变单位解释方式（食物类比vs运动类比）

## 【五】如何模仿它，做出你自己的版本？

**安全上手路径：**

**第一步：保持结构不变，替换使用场景**
- 将“运动消耗”改为其他计算场景，如：
  - **学习时间统计** → 输入：科目、学习时长、效率系数
  - **旅行费用估算** → 输入：距离、交通方式、住宿标准
  - **阅读进度追踪** → 输入：书籍页数、每日阅读时间

**第二步：调整输入字段和计算公式**
1. 在HTML中找到输入字段部分（约第30-40行）
2. 修改`field.label`为你的新字段名
3. 在JavaScript中修改计算函数：
```javascript
// 原来的运动消耗计算
function calculateCalories(weight, duration, exerciseType) {
  return weight * duration * MET值[exerciseType];
}

// 改为你的计算逻辑，例如阅读进度
function calculateReadingProgress(totalPages, dailyTime, readingSpeed) {
  return (dailyTime * readingSpeed) / totalPages * 100;
}
```

**第三步：改变输出形式**
- 修改结果显示的文案
- 调整显示样式（单结果vs多结果卡片）
- 增加可视化元素（进度条、图表）

**从哪里下手最安全？**
从**修改文案和数字**开始最安全：
1. 先改页面标题和描述
2. 再改输入框的标签文字
3. 然后调整计算公式中的常数
4. 最后改结果展示的文案

## 【六】3–5个可直接尝试的改造方向

**1. 增加运动数据库**
- 问题：当前可能只有几种固定运动
- 改造：添加运动类型下拉选择，包含20+常见运动
- 实现：创建`exercises`数组，每项包含名称、MET值、描述
- 效果：用户可以从丰富选项中选择，无需手动输入

**2. 加入历史记录功能**
- 问题：每次刷新页面数据就丢失
- 改造：使用`localStorage`保存最近5次计算记录
- 实现：计算后自动保存，添加“历史记录”查看面板
- 效果：用户可以对比不同日期的运动计划

**3. 可视化结果展示**
- 问题：纯数字结果不够直观
- 改造：用进度条或饼图展示消耗占比
- 实现：引入简单图表库（如Chart.js精简版）
- 效果：一眼看出“跑步vs游泳”的能量消耗对比

**4. 个性化推荐系统**
- 问题：只有计算，没有建议
- 改造：根据计算结果给出简单建议
- 实现：添加规则逻辑，如“如果消耗>500，显示鼓励语”
- 效果：增加用户互动和动力

**5. 多单位支持**
- 问题：只有公斤和分钟
- 改造：添加单位切换（公斤/磅，分钟/小时）
- 实现：增加单位选择按钮，自动转换计算
- 效果：适应不同地区用户习惯

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不是专业医疗工具**
   - 它使用标准公式估算，不考虑个人代谢差异
   - 如果你需要精确的代谢率计算，应使用专业体测设备
   - **替代方案**：健身房的InBody测试或医疗机构的代谢检测

2. **不能替代营养师或教练**
   - 它只计算消耗，不涉及摄入和营养搭配
   - 减肥/增肌需要综合考虑饮食、休息、训练计划
   - **替代方案**：咨询注册营养师或认证健身教练

3. **无法处理复杂场景**
   - 间歇训练、组合运动、环境因素（温度、海拔）的影响
   - 特殊人群（孕妇、老年人、慢性病患者）的调整
   - **替代方案**：使用专业运动科学软件或咨询运动医学专家

4. **没有长期追踪功能**
   - 每次计算都是独立的，无法形成趋势分析
   - 不能生成周报、月报或进度图表
   - **替代方案**：使用健身APP（如Keep、悦跑圈）或Excel自制模板

**记住这个原则：**
这个工具最适合**快速估算和方案比较**，而不是**精确监控和长期规划**。把它当作决策的参考工具，而不是绝对的执行标准。
