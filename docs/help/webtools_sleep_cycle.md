# 睡眠质量追踪工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你想要了解自己的睡眠模式，但不想使用复杂的手机应用时，这个工具就派上用场了。比如，你最近感觉白天精神不佳，想看看是不是睡眠时间不足或质量不好。每天早上花30秒记录一下前一晚的睡眠情况，几周后就能看到清晰的趋势。

**适合情况：**
- 想建立简单的睡眠记录习惯
- 需要直观看到睡眠时长和质量的变化趋势
- 希望数据完全保存在本地，保护隐私
- 想要一个轻量级、无需安装的工具

**不适合情况：**
- 需要精确的睡眠阶段分析（如深睡、浅睡、REM）
- 需要与智能手环/手表等硬件设备同步
- 需要多人共享或团队协作功能
- 需要专业的医学睡眠分析

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **入睡时间**：选择你昨晚上床睡觉的时间
2. **起床时间**：选择你今天早上起床的时间
3. **睡眠质量**：通过5个表情按钮（😫到😄）评价昨晚的睡眠感受
4. **备注**：可选的文字记录，比如“睡前喝了咖啡”或“半夜醒来两次”

**用户通常会做哪几步操作？**
1. 每天早上起床后，打开这个页面
2. 调整“入睡时间”和“起床时间”（默认是23:00-07:00）
3. 点击一个表情来评价睡眠质量
4. （可选）在备注里写点影响睡眠的因素
5. 点击“保存记录”按钮
6. 查看顶部统计数据和图表的变化

**输出结果长什么样？**
- **顶部统计卡片**：显示平均睡眠时长、平均质量、连续记录天数和总记录数
- **趋势图表**：折线图展示最近14天的睡眠时长变化
- **最近记录列表**：按时间倒序显示最近的10条记录，每条包含日期、时间、时长、质量和备注

**容易忽略的使用细节：**
1. 数据完全保存在你的浏览器本地，换设备或清除浏览器数据会丢失记录
2. “连续记录”只计算连续的天数，如果中间断了一天，就会重新从1开始
3. 图表最多显示最近14天的数据，更早的数据只参与统计计算
4. 每条记录都可以点击垃圾桶图标删除，但需要确认

## 【三】核心结构拆解（学习重点）

这个页面由**四个核心模块**组成，每个模块职责清晰：

**1. 记录输入模块（Quick Log）**
- **职责**：收集用户的一次睡眠数据
- **输入**：时间选择器、表情按钮、文本框
- **处理**：将用户输入组装成一个完整的“睡眠日志”对象
- **输出**：触发`addLog()`函数，将新记录添加到数据列表

**2. 统计展示模块（Stats）**
- **职责**：实时计算并展示关键指标
- **输入**：整个`logs`数组
- **处理**：通过计算属性（getter）动态计算平均值、连续天数等
- **输出**：四个统计数字卡片

**3. 可视化模块（Chart）**
- **职责**：将数据变化趋势可视化
- **输入**：最近14条记录（反转后）
- **处理**：使用Chart.js绘制折线图
- **输出**：可交互的睡眠时长趋势图

**4. 历史记录模块（Recent Logs）**
- **职责**：展示和管理已保存的记录
- **输入**：最近10条记录
- **处理**：格式化日期显示，提供删除功能
- **输出**：可浏览、可删除的记录列表

**逻辑链路：**
```
用户输入 → 组装成log对象 → 添加到logs数组前端
         ↓
logs数组变化 → 触发三个响应式更新：
    1. 统计卡片重新计算
    2. 图表重新渲染
    3. 最近记录列表更新
         ↓
所有数据自动保存到localStorage
```

**最值得学习的设计：**
**响应式数据流**的设计。整个应用围绕一个核心数据源（`logs`数组），所有显示模块都是这个数据的“视图”。当数据变化时，所有相关部分自动更新，无需手动同步。这是现代前端框架的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

> 注意：当前版本**没有使用AI或Prompt**。这是一个纯前端的本地数据追踪工具。

**如果我们要为它添加AI功能，可以这样设计：**

**Prompt可能扮演的角色：**
1. **睡眠建议生成器**：基于历史数据，给出改善建议
2. **模式识别器**：从备注中提取关键词，发现规律
3. **预测模型**：预测未来睡眠质量

**解决的是“生成问题”**：
- 输入：用户的睡眠历史数据 + 当前记录
- 输出：个性化的文本建议（如“你周末的睡眠质量更好，建议保持规律作息”）

**Prompt中的关键变量：**
```javascript
const prompt = `
你是一个睡眠健康顾问。基于以下用户数据，给出3条具体建议：

最近7天平均睡眠：${avgHours}小时
平均质量评分：${avgQuality}/5
最近备注关键词：${extractKeywords(notes)}

请用中文回复，语气友好，每条建议不超过20字。
`;
```

**如果只改Prompt，不改代码：**
- 可以改变AI回复的风格（专业vs亲切）
- 可以调整建议的重点（时长vs质量vs规律性）
- 可以增加或减少建议的数量和详细程度

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 将“睡眠”换成其他每日追踪主题，如：
  - **喝水记录**：次数、毫升数、感受
  - **情绪日记**：情绪类型、强度、触发事件
  - **学习时间**：开始时间、结束时间、专注程度
- 只修改文字标签和图标，不碰代码逻辑

**第二步：调整输入字段**
- 修改`newLog`对象的字段名：
  ```javascript
  // 原版
  newLog: { bedtime, wakeup, quality, note }
  
  // 情绪日记版
  newLog: { moodType, intensity, trigger, note }
  ```
- 调整输入控件类型（如将时间选择器换成下拉菜单）

**第三步：改变计算逻辑**
- 修改`calculateDuration`类似的函数
- 调整统计指标的计算方式（如将“平均睡眠”改成“平均情绪分”）

**第四步：定制化展示**
- 修改图表的数据集和标签
- 调整颜色主题（修改Tailwind颜色类）

**从哪里下手最安全？**
从**文字替换**开始，然后是**字段名修改**，最后才是**计算逻辑**。这样每一步都能看到效果，不会一下子全乱。

## 【六】3–5 个可直接尝试的改造方向

**1. 增加数据输入维度**
- 添加“睡前活动”多选框（阅读、玩手机、运动等）
- 增加“日间精神”评分（与睡眠质量关联分析）
- 添加“ caffeine intake”（咖啡因摄入量）数字输入

**2. 增强可视化**
- 将单一线图改为双Y轴图表，同时显示时长和质量
- 添加月度视图的日历热图（像GitHub贡献图）
- 增加“最佳睡眠区间”的参考线（如7-9小时）

**3. 添加社交或对比功能**
- （需后端）匿名与同龄人/同地区平均值对比
- 添加“目标设置”功能，可视化实际vs目标
- 生成可分享的“睡眠报告”图片

**4. 改善数据持久化**
- 添加导出功能（CSV/JSON）
- 添加导入功能，支持从其他应用迁移
- 添加云同步选项（使用Firebase或Supabase）

**5. 增加智能提醒**
- 基于历史数据，在最佳时间推送“该睡觉了”提醒
- 当检测到连续几天睡眠不足时，给出警告
- 添加“成就系统”（连续7天记录、达到目标等）

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不是医学诊断工具**
   - 不能检测睡眠呼吸暂停、失眠症等疾病
   - 如果怀疑有睡眠障碍，应咨询专业医生
   - 替代工具：医用级睡眠监测设备、睡眠诊所

2. **数据精度有限**
   - 依赖用户主观回忆和评价
   - 无法测量实际的睡眠阶段（深睡、浅睡、REM）
   - 替代工具：智能手环（Fitbit、Apple Watch）、床垫传感器

3. **缺乏环境因素追踪**
   - 不能自动记录室温、噪音、光照等环境数据
   - 替代工具：智能家居传感器 + IFTTT集成

4. **单人使用限制**
   - 无法追踪家庭成员（如婴儿）的睡眠
   - 无法用于睡眠研究或团队健康项目
   - 替代工具：专门的家庭睡眠追踪应用

**如果用户想做...**
- **精确的睡眠阶段分析** → 使用智能手环+专用App
- **医学级的睡眠研究** → 咨询睡眠专科，进行多导睡眠图检查
- **家庭成员的睡眠管理** → 使用Baby Tracker类应用
- **与环境数据的关联分析** → 使用Home Assistant等智能家居平台

**最后提醒**：这个工具最大的价值在于它的**简单性和可模仿性**。你学到的不是“如何做一个睡眠应用”，而是“如何构建一个数据录入→存储→可视化→分析的完整前端流程”。这个模式可以迁移到无数个场景中。
