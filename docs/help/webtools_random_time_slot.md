# Webtools 工具箱 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人效率工具箱**，它解决了日常工作和学习中需要频繁切换不同工具的问题。

**使用场景举例：**
- 当你需要专注工作25分钟，然后休息5分钟时，可以使用“番茄钟”模块。
- 当你需要快速记录一笔开销时，可以使用“记账工具”模块。
- 当你需要临时记录一些想法时，可以使用“笔记工具”模块。
- 当你需要计算一些简单公式时，可以使用“公式计算器”模块。

**适合的情况：**
- 需要快速使用简单工具，不想安装多个App
- 希望所有工具都在一个页面内，切换方便
- 需要轻量级的计时、记录、计算功能

**不适合的情况：**
- 需要专业级的数据分析或复杂计算
- 需要长期、大量数据的存储和管理
- 需要团队协作或多设备同步

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 根据你选择的工具类型，输入框会变化：
  - 计时器：输入分钟数
  - 记账工具：输入金额、分类、备注
  - 公式计算器：输入各个参数值
  - 清单工具：输入待办事项

**用户通常会做哪几步操作？**
1. 从左侧导航栏选择需要的工具（虽然当前页面只显示“随机时间段”，但代码结构支持多种工具）
2. 在对应的输入框中填写信息
3. 点击“开始”、“计算”、“添加”等按钮
4. 查看下方显示的结果或状态

**输出结果长什么样？**
- 计时器：显示倒计时时间
- 记账工具：显示本月累计金额和记录列表
- 公式计算器：显示计算结果
- 清单工具：显示勾选状态的待办列表

**有哪些容易忽略的使用细节？**
1. 有些工具会自动保存数据到浏览器本地存储
2. 笔记工具有防抖功能，输入后400毫秒自动保存
3. 设置按钮在右上角，可以配置API密钥
4. 使用“返回Webtools”可以回到工具选择页面

## 【三】核心结构拆解（学习重点）

这个网页采用了**模块化设计**，非常值得学习：

**关键模块组成：**
1. **导航栏模块**：提供返回和设置入口
2. **工具容器模块**：根据`tool.type`动态显示不同工具
3. **工具类型模块**：10种独立的工具界面
4. **设置面板模块**：API配置弹窗

**每个模块的职责：**
- **导航栏**：页面导航和全局设置
- **工具容器**：根据当前工具类型渲染对应的UI
- **具体工具**：处理特定功能的输入、计算、展示
- **设置面板**：管理外部API配置

**输入 → 处理 → 输出 的逻辑链路：**
```
用户输入 → Alpine.js数据绑定 → JavaScript函数处理 → 更新数据模型 → 界面自动刷新
```

**最值得学习的设计：**
**条件渲染模式** - 使用`x-show="tool.type === 'xxx'"`来切换不同工具界面，这种设计让代码结构清晰，易于扩展新工具。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演什么角色？**
虽然当前页面没有直接使用AI功能，但代码中预留了API配置（DeepSeek API），说明这是一个**可扩展的AI工具平台**。

**它解决的是"理解问题"还是"生成问题"？**
从配置看，它准备解决**生成问题**（如文本生成、代码生成等），但当前版本主要专注于传统工具。

**哪些信息是Prompt中的关键变量？**
如果扩展AI功能，关键变量可能包括：
- 用户输入的文本或参数
- 选择的模型类型
- 系统预设的指令模板

**如果只改Prompt，不改代码，会发生什么变化？**
如果接入AI服务，只改Prompt可以：
- 改变AI的回复风格
- 调整生成内容的格式
- 添加特定的约束条件
- 但无法改变输入输出界面

## 【五】如何模仿它，做出你自己的版本？

**安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 复制整个HTML结构
- 修改`tool.type`的判断条件，比如把“记账工具”改成“运动记录”
- 只改文字标签，不动JavaScript逻辑

**第二步：调整输入字段或Prompt**
- 在对应的工具模块中，增减输入字段
- 比如在“清单工具”中增加“优先级”选择框
- 修改对应的数据模型字段

**第三步：改变输出形式或展示方式**
- 修改结果显示的HTML结构
- 比如把列表改成卡片式展示
- 添加图表或统计信息

**从哪里下手最安全？**
从**清单工具**开始最安全，因为它逻辑简单，只有添加、删除、勾选功能，容易理解和修改。

## 【六】3–5个可直接尝试的改造方向

**1. 增加数据可视化**
- 在记账工具中添加月度支出饼图
- 使用Chart.js或ECharts库
- 改造方向：在`tool.entries`数据变化时，重新绘制图表

**2. 添加分享功能**
- 为每个工具结果生成分享链接
- 使用URL参数保存当前状态
- 改造方向：在`calculate`或`runGenerator`函数中添加URL生成逻辑

**3. 实现工具组合**
- 让多个工具可以串联使用
- 比如：计时器结束后自动记录到清单
- 改造方向：在工具间添加事件监听和触发机制

**4. 添加主题切换**
- 实现深色/浅色模式
- 保存用户偏好到本地存储
- 改造方向：在`x-data`中添加`theme`变量和切换函数

**5. 扩展AI集成**
- 为笔记工具添加AI总结功能
- 为文本工具添加AI改写功能
- 改造方向：在对应工具中添加“AI处理”按钮和API调用

## 【七】这个网页不适合做什么？（边界提醒）

**明确局限性：**
1. **不适合复杂项目管理**：没有任务依赖、截止日期、优先级管理
2. **不适合团队协作**：所有数据存储在本地，无法共享
3. **不适合大数据量**：本地存储有容量限制（通常5MB）
4. **不适合离线复杂计算**：如果需要AI功能，必须联网

**如果用户想做X，应该换什么工具：**
- **想做团队任务管理** → 使用Trello、Asana、飞书
- **需要专业记账报税** → 使用随手记、MoneyWiz、QuickBooks
- **需要复杂公式计算** → 使用Excel、Google Sheets、Wolfram Alpha
- **需要长期知识管理** → 使用Notion、Obsidian、Logseq
