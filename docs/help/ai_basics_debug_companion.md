# AI 报错诊断室 - 帮助与学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在用 HTML、Vue 和 Tailwind 快速搭建一个网页（Vibe Coding），突然浏览器控制台弹出一个你看不懂的错误信息。你复制了错误信息，也找到了可能出问题的代码段，但就是不知道具体哪里错了、该怎么改。这个网页就是你的“AI 调试助手”。

**适合场景：**
- 当你遇到一个具体的 JavaScript 或 Vue 语法错误，但不确定如何修复时。
- 当你有一段代码运行结果不符合预期，想快速获得一个“第二意见”时。
- 在快速原型开发（Vibe Coding）过程中，希望不打断思路，快速解决技术卡点时。

**不适合场景：**
- 解决复杂的、涉及多个文件和模块的系统性架构问题。
- 调试网络请求、性能优化或浏览器兼容性问题。
- 替代系统性的代码审查或深入的学习。

## 【二】使用方式（给第一次接触的人）

1.  **页面输入是什么？**
    - **错误信息**：从浏览器开发者工具（Console）中复制粘贴的错误日志。
    - **相关代码片段**：你认为可能出问题的那部分 HTML、JavaScript 或 Vue 代码。

2.  **用户通常会做哪几步操作？**
    1.  在左侧“错误信息”框中，粘贴你看到的报错信息。
    2.  在“相关代码片段”框中，粘贴你怀疑有问题的代码。
    3.  点击蓝色的“开始诊断”按钮。
    4.  等待几秒钟，在右侧的“诊断报告”区域查看 AI 给出的分析结果。

3.  **输出结果长什么样？**
    输出是一份结构清晰的文本报告，通常包含：
    - **病因分析**：用通俗语言解释错误是怎么产生的。
    - **修复方案**：给出具体的代码修改建议。
    - **避坑指南**：提醒你在类似开发场景下如何避免再次踩坑。

4.  **有哪些容易忽略的使用细节？**
    - **API Key 配置**：这个工具需要连接 DeepSeek 的 AI 服务。你需要先在网站的“首页”或设置中配置好你的 API Key，否则它只会返回一个模拟结果。
    - **信息越全越好**：尽量提供完整的错误信息和足够上下文的代码片段，AI 的诊断会更准确。
    - **诊断需要时间**：点击按钮后会有加载动画，请耐心等待网络请求完成。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为两个主要模块：

1.  **输入与交互模块（左侧）**
    - **职责**：收集用户的问题描述（错误日志和代码）。
    - **构成**：两个文本输入框（`textarea`）和一个触发按钮（`button`）。
    - **逻辑**：用户填写信息 -> 点击按钮 -> 触发 `diagnose` 函数。

2.  **输出与展示模块（右侧）**
    - **职责**：展示 AI 的分析过程和最终结果。
    - **构成**：一个标题栏和一个内容显示区域。
    - **逻辑**：初始为空或加载状态 -> 收到 AI 回复后 -> 将回复文本（`report`）渲染到内容区。

**核心逻辑链路：**
**用户输入** (错误日志 + 代码片段) -> **前端组装** (拼接成 Prompt) -> **网络请求** (发送给 AI API) -> **后端处理** (AI 模型分析) -> **前端接收** (获取响应) -> **结果渲染** (显示诊断报告)。

**最值得学习的设计：**
**“问题-答案”的极简封装**。它将一个复杂的“代码调试”需求，抽象为两个简单的输入框和一个按钮，极大降低了使用门槛。整个页面的状态（是否在分析、报告内容）通过 Vue 的响应式数据 (`ref`) 进行管理，使得 UI 能自动、同步地更新，这是构建现代交互式 Web 应用的核心模式。

## 【四】Prompt / AI 逻辑是如何被设计的？

1.  **Prompt 的角色**：它是连接用户问题和 AI 能力的“翻译官”和“任务指挥官”。它告诉 AI“你是谁”（前端专家）、“你要做什么”（分析错误）以及“你该怎么回答”（按固定格式输出）。

2.  **解决的问题类型**：它主要解决 **“理解与生成”混合问题**。AI 需要先**理解**用户提供的错误和代码的语义，然后**生成**一份结构化的诊断报告。

3.  **Prompt 中的关键变量**：
    - **`systemPrompt`**：定义了 AI 的“人设”和回答的**固定格式**（病因分析、修复方案、避坑指南）。这是控制输出质量的关键。
    - **`userPrompt`**：包含了用户提供的**动态信息**（`errorLog` 和 `codeSnippet`），这是每次诊断的具体问题。

4.  **只改 Prompt 的后果**：
    - 修改 `systemPrompt` 中的“人设”（如改成“Python 后端专家”），AI 的分析角度和知识范围会完全改变。
    - 修改 `systemPrompt` 中的“输出格式”，报告的章节标题和结构会随之变化。
    - 修改 `temperature` 参数（代码中为 0.3），值越高，AI 的回答可能越有创造性但也更不稳定；值越低，回答则越保守和确定。

## 【五】如何模仿它，做出你自己的版本？

这是一个经典的“输入-处理-输出”型 AI 工具模板。你可以按以下安全路径进行模仿：

**第一步：替换核心场景与字段**
保持 HTML 结构和 Vue 逻辑完全不变。只修改：
- 页面标题和描述（如改成“AI 周报生成器”）。
- 输入框的标签和提示文字（如将“错误信息”改为“本周工作要点”，“代码片段”改为“下周计划”）。
- 按钮文字。

**第二步：调整 Prompt 指令**
在 `diagnose` 函数中，重写 `systemPrompt` 和组装 `userPrompt` 的方式，让它符合你的新场景。例如，让 AI 扮演“项目经理”，根据工作要点和计划生成周报。

**第三步：改变输出展示方式**
目前是纯文本输出。你可以尝试：
- 使用 `v-html` 或引入 `marked.js` 库来渲染 Markdown 格式，让报告更美观。
- 将输出结构化为多个可折叠的卡片区域。

**从哪里下手最安全？**
从 **第一步** 开始。先不改任何 JavaScript 代码，只改页面上看到的文字。这能让你立刻得到一个外观不同的新工具，并理解页面结构。成功后，再进入第二步修改 Prompt，这是功能改变的核心。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加输入维度，提升诊断精度**：
    - 增加一个下拉菜单，让用户选择错误类型（如“语法错误”、“运行时错误”、“Vue 警告”）。
    - 增加一个复选框，询问“是否使用了特定的 JS 库（如 axios、lodash）”。
    - 将这些新信息也加入到 `userPrompt` 中，让 AI 的诊断更有针对性。

2.  **更换或扩展 AI 模型后端**：
    - 代码中已预留从 `localStorage` 读取配置的结构。你可以很容易地添加对 OpenAI GPT、Claude 或国内其他大模型 API 的支持。
    - 在 UI 上增加一个模型选择器，让用户根据需求（速度、成本、效果）选择不同的模型。

3.  **优化交互与用户体验**：
    - **历史记录**：将每次的诊断记录（输入和输出）保存到 `localStorage`，并提供一个侧边栏列表供用户回顾。
    - **一键修复**：对于简单的语法错误，AI 回复中可以包含修正后的代码块。可以增加一个“复制修复代码”按钮，一键复制到剪贴板。
    - **加载状态优化**：在等待时，可以在报告区显示一个逐步出现的“思考过程”动画，缓解用户等待焦虑。

4.  **拆分为多步骤向导**：
    - 将当前的单页拆分为：1) 描述问题 -> 2) 上传/粘贴代码 -> 3) 查看报告。
    - 每一步作为一个独立的组件（Vue Component），通过状态管理导航。这更适合复杂问题的诊断。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合作为代码安全审计工具**：它不会深入检查代码中的安全漏洞（如 XSS、SQL 注入风险）。
2.  **不适合进行代码性能分析**：它无法分析你的代码执行效率、内存泄漏或算法复杂度。
3.  **不适合替代系统学习**：它给出的是针对具体问题的“药方”，而不是讲解背后原理的“教科书”。如果你不理解 AI 给出的修复方案，应该去查阅官方文档或教程。
4.  **不适合处理完全无法运行的代码**：如果错误导致页面完全崩溃，AI 可能无法获取足够上下文。此时，你应该使用浏览器的开发者工具进行更基础的调试。

**如果你想做的是：**
- **系统性地优化代码质量**：应该使用 ESLint、Prettier 等代码检查工具。
- **进行完整的应用测试**：应该学习并使用 Jest、Cypress 等测试框架。
- **搭建一个在线的代码编辑和运行环境**：应该考虑使用 CodeSandbox、StackBlitz 或 Monaco Editor 等专业方案。
