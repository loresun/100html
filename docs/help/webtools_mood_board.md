# 情绪画板 (Year in Pixels) 帮助与学习文档

---

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你想回顾过去一年，但记忆是模糊的。这个网页就像一个**数字化的情绪日记本**，让你用颜色和表情快速标记每一天的心情。它把抽象的感受变成可视化的“像素画”，让你一眼就能看到自己情绪变化的规律和模式。

**适合在什么情况下使用？**
- **个人情绪追踪**：想了解自己情绪周期、季节性变化或生活事件对心情的影响。
- **习惯养成辅助**：作为每日简短回顾的仪式，只需几秒钟。
- **自我觉察练习**：通过可视化数据，更客观地看待自己的情绪状态。
- **年终回顾**：生成一份独特的“情绪年报”，看到一年的情绪全景图。

**不适合什么情况？**
- **需要详细记录**：它只记录“情绪标签”，无法记录具体事件、原因或长篇感想。
- **专业心理治疗**：不能替代专业的情绪评估或治疗工具。
- **多人协作**：这是一个纯粹的个人工具，没有分享或协作功能。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- **你的心情**：通过点击上方5个彩色按钮（🤩 超棒、😊 开心、😐 还行、😔 低落、😫 糟糕）来选择当前要标记的心情。
- **日期格子**：页面中央是一个巨大的日历网格，每个格子代表一年中的某一天。

**用户通常会做哪几步操作？**
1. **选择心情**：点击上方情绪按钮中的一个（比如“开心”）。
2. **标记日期**：在网格中找到今天的日期（例如3月15日），点击对应的格子。
3. **重复操作**：每天回来，重复步骤1-2，标记当天的情绪。
4. **查看统计**：页面底部的统计区域会自动更新，显示每种情绪出现的次数。

**输出结果长什么样？**
- **视觉化日历**：一年365天变成彩色像素点，不同颜色代表不同情绪。
- **情绪统计**：底部显示每种情绪出现的具体天数。
- **最终效果**：随着时间推移，你会得到一幅属于你自己的“情绪色彩年历”。

**有哪些容易忽略的使用细节？**
- **清除功能**：选择了“橡皮擦”按钮后，点击格子可以清除该日的记录。
- **重置按钮**：右上角的“重置”会清空**整年**的数据，请谨慎使用。
- **自动保存**：每次点击后数据会自动保存到浏览器本地，关闭页面也不会丢失。
- **响应式设计**：在电脑上看到的是完整网格，在手机上会按月分块显示，更方便触摸操作。

## 【三】核心结构拆解（学习重点）

这个页面由**5个关键模块**组成，像搭积木一样协作：

**1. 情绪选择器（Controls）**
- **职责**：让用户选择当前要使用的“情绪颜色笔”。
- **设计亮点**：使用彩色按钮直观表示情绪，选中状态有视觉反馈（外圈光环）。

**2. 日历画布（Desktop Grid / Mobile Block）**
- **职责**：展示一年365天的可视化网格，并接收用户的点击标记。
- **设计亮点**：
  - **智能日期验证**：自动处理不同月份的天数（2月只有28/29天）。
  - **响应式适配**：电脑端用大网格，手机端按月折叠，体验更佳。

**3. 数据存储层（JavaScript 逻辑）**
- **职责**：在内存中管理“哪一天是什么情绪”的数据，并与浏览器本地存储同步。
- **关键函数**：
  - `setMood()`：处理点击，更新数据。
  - `save()`：将数据保存到`localStorage`。
  - `getStyle()`：根据数据决定每个格子的颜色。

**4. 统计面板（Stats）**
- **职责**：实时计算并展示每种情绪的出现频率。
- **设计亮点**：数据与情绪选择器联动，颜色保持一致。

**5. 状态管理（Alpine.js 的 x-data）**
- **职责**：作为整个应用的“大脑”，管理所有变量（当前选中的情绪、所有记录的数据等），并确保界面随数据自动更新。

**输入 → 处理 → 输出 的逻辑链路：**
```
用户点击情绪按钮 → 更新`activeMood`变量 → 用户点击日期格子 → 
调用`setMood(月份, 日期)` → 更新`pixels`对象 → 自动触发`save()`到本地存储 → 
界面通过`getStyle()`重新渲染格子颜色 → 统计面板通过`getMoodCount()`更新数字
```

**最值得学习的设计：**
**“状态驱动视图”的极简实现**。整个应用的核心就是一个JavaScript对象（`pixels`），记录着“日期->情绪ID”的映射。界面上的所有颜色、统计数字，都是这个对象的实时反映。Alpine.js框架让这种“数据变，界面自动变”的模式变得非常简单易懂，是学习现代前端交互设计的优秀范例。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **注意**：当前版本的“情绪画板”**没有使用AI或Prompt**。它是一个完全基于规则和用户输入的工具。这部分分析将展示**如果**要加入AI功能，可以如何思考设计。

**假设我们要添加一个AI分析功能：**
- **Prompt可能扮演的角色**：将用户的情绪数据转化为文字总结或洞察。
- **它解决的是“生成问题”**：从结构化数据（颜色格子）生成自然语言描述。

**示例Prompt设计：**
```
你是一位善于观察的生活教练。请根据用户提供的全年情绪数据，生成一份简短的年终情绪报告。

数据格式：每个月每天的情绪评分（1-5分，5为最好）。
当前数据：{{插入JSON格式的情绪数据}}

请从以下角度分析：
1. 整体情绪趋势（哪个月份情绪最好/最差）
2. 发现可能的模式（如：周末是否更快乐？）
3. 给出一条基于数据的积极建议

语气：温暖、鼓励、基于事实。
```

**Prompt中的关键变量：**
- `{{情绪数据}}`：从`pixels`对象转换而来的结构化数据。
- 分析角度和语气要求。

**如果只改Prompt，不改代码，会发生什么变化？**
- AI输出的**内容重点**会变（比如从“分析趋势”改为“寻找情绪触发点”）。
- 报告的**风格和语气**会变（比如从“教练风格”改为“朋友聊天风格”）。
- 但**输入和输出形式不变**：用户还是点击格子，最后得到一段文字报告。

## 【五】如何模仿它，做出你自己的版本？

**模仿路径（从最安全到最大胆）：**

**第一步：保持结构不变，替换使用场景（最安全）**
- **目标**：做一个“习惯追踪画板”。
- **操作**：
  1. 修改`moods`数组：把情绪改为习惯（如：{id: 1, name: ‘健身’, emoji: ‘💪’, color: ‘#3b82f6’}）。
  2. 修改标题和文字：“情绪画板” → “习惯打卡日历”。
  3. **无需改动任何核心逻辑**，因为数据结构（ID-颜色-名称）完全一致。

**第二步：调整输入字段或数据维度**
- **目标**：做一个“每日评分画板”（1-10分）。
- **操作**：
  1. 扩展`moods`数组：从5个情绪变为10个评分等级（1分到10分）。
  2. 为每个分数分配渐变色（如1分红色，10分绿色）。
  3. 可能需要调整按钮布局（10个按钮可能需要滚动或下拉选择）。

**第三步：改变输出形式或展示方式**
- **目标**：在日历旁边增加“月度热力图”。
- **操作**：
  1. 在统计面板下方新增一个`<canvas>`画布。
  2. 写一个新函数`drawHeatmap()`，将月度数据用更密集的热力图呈现。
  3. **关键**：新功能读取现有的`pixels`数据，但不修改核心的标记逻辑。

**从哪里下手最安全？**
从**修改`moods`数组**开始。这是应用的“皮肤”，改了立刻能看到变化，且几乎零风险。尝试把你的5个情绪换成5种活动、5种天气、5种精力等级……立刻就能得到一个全新的工具。

## 【六】3–5 个可直接尝试的改造方向

**1. 增加“备注”功能**
- **具体操作**：点击格子时，弹出一个小输入框，让用户输入简短的文字备注（如“因为项目上线很开心”）。
- **技术提示**：扩展`pixels`对象，从`{“1-1”: 5}`变为`{“1-1”: {mood: 5, note: “...”}}`。
- **体验优化**：鼠标悬停在有备注的格子上时，用Tooltip显示备注。

**2. 切换不同数据视图**
- **具体操作**：在顶部增加“周视图”、“季度视图”切换按钮。
- **技术提示**：写一个`transformData(viewType)`函数，将原始的`pixels`数据按周或季度分组计算平均情绪值。
- **展示变化**：周视图可以用7个长条表示一周7天的平均情绪。

**3. 添加简单的数据导出/导入**
- **具体操作**：增加“导出JSON”和“导入”按钮。
- **技术提示**：
  - 导出：`JSON.stringify(this.pixels)` 生成可下载的文件。
  - 导入：文件上传后，用`JSON.parse()`读取并赋值给`this.pixels`。
- **使用场景**：换电脑时迁移数据，或备份年度记录。

**4. 引入“情绪预测”或“模式识别”**
- **具体操作**：增加一个“分析模式”按钮，点击后高亮显示连续相同情绪的日期段。
- **技术提示**：遍历`pixels`数据，寻找连续3天以上相同情绪的时间段，然后给这些格子的样式添加一个“发光”或“脉冲”动画。
- **学习价值**：练习数据遍历和条件判断算法。

**5. 改为“团队情绪板”**
- **具体操作**：将数据存储从`localStorage`改为Firebase或Supabase数据库。
- **技术提示**：
  - 增加“创建房间”、“加入房间”功能。
  - 每个人用不同颜色标记（但共享同一个日历）。
  - 需要学习基础的后端即服务（BaaS）使用。
- **应用场景**：家庭情绪板、小团队士气追踪。

## 【七】这个网页不适合做什么？（边界提醒）

**1. 不适合做详细日记或事件记录**
- **局限性**：只能记录一个情绪标签，无法记录具体内容、图片、长篇思考。
- **替代方案**：如果需要详细记录，应使用Day One、Journey等专业日记应用，或自己开发一个带富文本编辑器的版本。

**2. 不适合做精确的情绪分析或心理评估**
- **局限性**：情绪分类简单（只有5种），没有强度细分，没有上下文记录。
- **替代方案**：专业心理评估工具（如PHQ-9、GAD-7量表）或更精细的情绪追踪应用（如Moodnotes）。

**3. 不适合长期存档或多设备同步**
- **局限性**：数据存储在单个浏览器的本地，清除浏览器数据会丢失记录，且无法在手机/电脑间同步。
- **替代方案**：如果需要云同步，必须接入后端数据库（如改造方向5所述）。

**4. 不适合处理复杂的时间逻辑**
- **局限性**：假设一年就是标准的12个月，没有处理闰秒、时区、半天情绪等复杂情况。
- **替代方案**：如果需要更精细的时间划分（如按小时追踪），需要完全重新设计数据结构和界面。

**5. 不适合作为生产环境工具**
- **局限性**：这是一个教学/原型性质的页面，没有错误处理、没有用户系统、没有数据备份机制。
- **替代方案**：如果希望作为正式产品使用，需要在当前基础上增加用户认证、数据加密、定期备份等生产级功能。
