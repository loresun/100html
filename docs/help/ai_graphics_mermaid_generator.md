# Mermaid 图表生成器 - 帮助与学习文档

--------------------------------

## 【一】这个网页解决了什么问题？

这个网页解决了一个非常具体且常见的痛点：**“我想画一个专业的图表来说明某个流程或结构，但我不想花时间学习复杂的绘图工具，也不想手动调整布局。”**

**典型使用场景：**
*   **写技术文档时**：需要快速绘制一个系统架构图、API调用时序图或数据库ER图。
*   **做项目汇报时**：需要清晰展示项目流程、状态转换或时间规划（甘特图）。
*   **梳理思路时**：需要将头脑中的逻辑关系（如思维导图、类继承关系）可视化出来。
*   **学习或教学时**：需要生成示例图表来辅助理解某个概念。

**它适合在什么情况下使用？**
*   当你对图表的大致内容有想法，但不确定如何用代码精确表达时。
*   当你需要快速生成一个结构清晰、风格统一的图表原型时。
*   当你希望图表能以纯文本代码的形式保存、分享和版本管理时。

**它不适合什么情况？**
*   **需要高度定制化美术设计**：它生成的是标准的技术图表，不是海报或信息图。
*   **绘制非结构化图形**：比如自由手绘、地图、复杂的示意图。
*   **实时协作绘图**：这是一个单人使用的工具，不支持多人同时编辑。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **你的想法描述**：在“AI生成”标签页，用文字描述你想画的图表内容（例如：“一个用户从登录到下单的完整流程图”）。
2.  **（可选）图表类型**：在描述上方，可以选择流程图、时序图、类图等具体类型。
3.  **（可选）直接编辑代码**：在“代码编辑”标签页，可以直接输入或修改Mermaid代码。

**用户通常会做哪几步操作？**
1.  **配置**：首次使用时，点击右上角“设置”按钮，填入你的DeepSeek API Key。
2.  **描述需求**：在左侧“AI生成”面板，选择图表类型，在文本框中详细描述你的需求。
3.  **一键生成**：点击“AI生成图表”按钮，等待几秒钟。
4.  **查看与调整**：生成后会自动切换到“代码编辑”标签页，并实时渲染出图表。你可以在此微调代码，图表会同步更新。
5.  **导出成果**：在右侧预览区上方，可以“复制代码”嵌入到文档中，或“导出SVG/PNG”图片使用。

**输出结果长什么样？**
*   **右侧预览区**：会显示一个清晰、自动布局的矢量图表。
*   **左侧编辑区**：会生成对应的Mermaid代码文本。这段代码就是图表的“源代码”，可以独立运行。

**有哪些容易忽略的使用细节？**
1.  **API Key是必需的**：第一次点击“AI生成”时，如果没配置Key，会弹出设置窗口。你需要去DeepSeek官网免费申请一个。
2.  **描述越详细越好**：AI会根据你的描述生成代码。说“一个登录流程”可能太简单，说“包含用户名密码验证、失败重试、成功跳转首页的登录流程图”会得到更准确的结果。
3.  **利用示例模板**：如果不确定如何描述，可以切换到“示例模板”标签页，直接加载现成的例子进行修改，这是最快的学习方式。
4.  **实时预览**：在“代码编辑”标签页修改代码时，右侧图表会**自动更新**（有轻微延迟），方便调试。
5.  **查看AI思考过程**：如果使用“DeepSeek Reasoner”模型，生成后可以展开“查看AI思考过程”，了解AI是如何一步步将你的描述转化为代码的，这对学习Mermaid语法非常有帮助。

## 【三】核心结构拆解（学习重点）

这个页面采用了清晰的**左右分栏、功能模块化**设计。

**关键模块与职责：**
1.  **控制与配置模块（顶部导航栏）**：
    *   **职责**：提供全局设置入口（API Key、模型选择、提示词定制）。
    *   **设计亮点**：将配置项收纳在弹窗中，保持主界面清爽。

2.  **输入与创作模块（左侧面板）**：
    *   **AI生成面板**：将**自然语言描述**转化为**结构化指令**（Prompt），发送给AI API。
    *   **代码编辑面板**：提供专业的代码编辑器体验（带行号），是直接操作“图表源代码”的地方。
    *   **示例模板面板**：提供学习起点和灵感，降低用户起步门槛。
    *   **职责**：收集用户意图，并提供多种输入路径（描述、代码、示例）。

3.  **输出与渲染模块（右侧面板）**：
    *   **预览区**：使用Mermaid.js库，将代码实时渲染为可视化图表。
    *   **导出功能区**：提供代码复制和图片导出（SVG/PNG）能力。
    *   **职责**：展示结果，并提供成果交付方式。

4.  **逻辑处理模块（Vue组件与JS逻辑）**：
    *   **职责**：协调各模块。监听输入变化，调用AI接口，处理返回数据，触发图表渲染，管理状态（如加载中、错误提示）。

**核心逻辑链路：**
```
用户描述（自然语言） 
    → 【AI生成面板】拼接Prompt，调用DeepSeek API 
    → 获得Mermaid代码 
    → 填入【代码编辑面板】 
    → 【输出与渲染模块】中的Mermaid.js库解析代码 
    → 渲染为SVG图表 
    → 用户可在【代码编辑面板】微调代码，形成闭环。
```

**最值得学习的设计：**
**“多模态输入”与“实时反馈”的闭环设计。** 它提供了三种截然不同的输入方式（AI描述、直接写码、使用模板），但最终都汇聚到同一个代码编辑器，并即时映射到同一个可视化预览。这种设计极大地扩展了工具的适用人群（从新手到专家），并创造了流畅的学习路径：用户可以从模板或AI生成开始，然后通过观察和修改代码来学习。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 在这里扮演着 **“翻译官”和“约束者”** 的双重角色。它负责将用户模糊的自然语言需求，“翻译”成AI能理解的、且符合Mermaid语法规范的精确任务。同时，它通过严格的规则“约束”AI的输出格式，确保返回的是纯净、可用的代码。

**它解决的是“理解问题”还是“生成问题”？**
主要解决的是 **“生成问题”** 。用户的需求（画一个流程图）是明确的，难点在于“如何生成正确的Mermaid代码”。Prompt通过提供详细的语法规范、示例和要求，引导AI生成符合特定格式和技术要求的代码。

**哪些信息是 Prompt 中的关键变量？**
1.  **`{chartType}`**：这是一个占位符，会被替换为用户在前端选择的图表类型（如“流程图”）。这确保了AI生成的代码类型与用户预期一致。
2.  **“只返回纯净的Mermaid代码”**：这是最重要的指令，强制AI剥离所有解释性文字，直接输出代码。
3.  **“使用中文标签”** 和 **“节点ID不使用中文”**：这些是具体的样式和语法规则，确保生成的图表既符合中文阅读习惯，又避免技术错误。

**如果只改 Prompt，不改代码，会发生什么变化？**
你可以彻底改变AI的“行为”和“产出风格”，而无需改动任何一行程序逻辑。例如：
*   将Prompt改为“生成风格极简的图表”，AI可能会生成节点更少、连线更简洁的代码。
*   在Prompt中增加“为所有节点添加浅蓝色背景”，生成的图表样式会立刻改变。
*   把Prompt改成用英文输出，那么所有图表标签都会变成英文。
*   **这就是Prompt设计的威力：通过修改文本，就能定制化AI的能力边界。**

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个类似的AI工具：

**第一步：替换核心场景与工具库（最安全）**
*   **目标**：先做出一个能跑通的“外壳”。
*   **行动**：
    1.  保留整体的HTML/CSS/Vue框架结构。
    2.  将 **Mermaid.js** 替换成另一个基于文本的图表或图形库，比如 **PlantUML**（同样是文本生成图表）、**Graphviz**（DOT语言），或者甚至是一个 **Markdown 预览器**。
    3.  将界面文字从“图表”改为你的新场景（如“系统架构图”、“网络拓扑图”、“文章预览”）。

**第二步：调整输入字段与Prompt**
*   **目标**：让你的工具解决新问题。
*   **行动**：
    1.  修改“AI生成”面板中的输入字段。例如，如果做食谱生成器，可以把“描述您的需求”改成“描述你想吃的菜”。
    2.  重写 `DEFAULT_SYSTEM_PROMPT`。这是核心！根据你的新工具库（如PlantUML）的语法，重新编写Prompt，告诉AI如何生成正确的代码。务必保留“只返回纯净代码”等关键指令。

**第三步：更换后端API与模型**
*   **目标**：适配你的开发环境或需求。
*   **行动**：
    1.  在代码中搜索 `api.deepseek.com`，将其替换为其他AI服务的API端点（如OpenAI、Claude、智谱AI等）。
    2.  修改请求头 `Authorization` 和请求体 `model` 等字段，以匹配新API的要求。
    3.  在前端设置面板中，更新模型选项列表。

**从哪里下手最安全？**
从 **第二步（修改Prompt）** 和 **第一步中的文字替换** 开始最安全。这不会破坏程序逻辑，却能立刻改变工具的功能定位。你可以先做一个能生成不同风格Mermaid图表的工具，来验证整个流程。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“图表风格”预设选择**：
    *   **操作**：在“图表类型”选择旁，增加一个“风格”下拉框，选项如“默认”、“极简”、“手绘风”、“深色主题”。
    *   **实现**：在Prompt中新增一个 `{chartStyle}` 变量，根据选择拼接不同的样式指令（如“使用手绘风格语法”）。Mermaid本身支持一些主题，也可以通过Prompt让AI添加样式定义。

2.  **增加“迭代优化”功能**：
    *   **操作**：在生成的图表预览下方，增加一个输入框“如何调整？”和“重新生成”按钮。
    *   **实现**：用户输入“把这两个节点合并”或“颜色改成红色”。点击按钮后，将用户最初的描述、已生成的代码和新的调整指令，一起作为新的用户消息发送给AI，要求其在原有代码基础上修改。

3.  **替换为本地模型或开源模型**：
    *   **操作**：将依赖的DeepSeek API换成在本地或自有服务器上部署的开源大模型（如Qwen、Llama）。
    *   **实现**：修改 `generateWithAI` 函数中的API地址和请求格式。这可以消除对第三方API Key的依赖，并可能降低成本、提高速度。

4.  **拆分为“生成”与“管理”两个页面**：
    *   **操作**：将当前单页应用拆解。
    *   **实现**：
        *   **页面A（生成器）**：保留核心的输入、生成、预览、导出功能。
        *   **页面B（图库）**：新增一个页面，利用浏览器本地存储（LocalStorage）或连接后端数据库，保存用户生成过的所有图表代码，并提供搜索、分类、再次编辑的功能。

5.  **优化交互：添加“语法提示”浮动窗**：
    *   **操作**：当用户在代码编辑器中将光标停留在某行时，在附近浮动显示该行Mermaid语法的简要说明或常见错误提示。
    *   **实现**：监听代码编辑器的光标位置，解析当前行或关键词，从一个预定义的语法帮助字典中查找并显示对应提示。这能极大提升代码编辑的学习体验。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做高保真UI/UX设计稿**：
    *   **局限性**：Mermaid专注于逻辑和结构可视化，而不是像素级完美的界面设计。它无法生成复杂的图标、控制具体的字体字号、或实现精细的交互状态。
    *   **应该换什么**：如果需要设计用户界面，应使用Figma、Sketch、Adobe XD等专业设计工具，或使用专门生成UI代码的AI工具。

2.  **不适合处理高度动态或交互式图表**：
    *   **局限性**：生成的图表是静态的（SVG/PNG）。虽然Mermaid支持一些点击事件，但本工具并未深度集成此功能，无法方便地创建可点击展开/收起、拖拽节点、实时更新数据的复杂交互图表。
    *   **应该换什么**：如果需要丰富的交互，应考虑使用D3.js、ECharts、AntV等专业的可视化JavaScript库进行开发。

3.  **不适合作为企业级、多用户的图表管理平台**：
    *   **局限性**：数据（API Key、图表代码）默认存储在用户浏览器本地。无法实现团队共享、权限管理、在线协作编辑、历史版本对比等高级功能。
    *   **应该换什么**：如果需要团队协作，应考虑使用Mermaid Live Editor的托管服务、Draw.io、或自建一个包含后端服务器和数据库的完整Web应用。

**总结**：这是一个强大的**个人生产力工具**和**学习原型**，它出色地解决了“从想法到可视化图表”的快速通路问题。它的价值在于“快速”和“文本驱动”，而不是“精细”和“协作”。理解这一点，你就能在正确的场景下最大化地利用它，也能明确知道何时该寻求更专业的解决方案。
