# SOP 标准流程文档生成器 - 帮助与学习指南

--------------------------------

## 【一】这个网页解决了什么问题？

想象一下，你是一家公司的部门主管或项目负责人，需要为团队制定一个清晰、可执行的工作流程（SOP）。手动撰写一份专业的SOP文档非常耗时，你需要考虑格式、步骤、风险点、检查清单等方方面面。这个网页就是你的“AI流程文档助手”。

**使用场景举例**：
- **新员工入职**：你需要为HR部门制定一份标准化的新员工入职指引。
- **客户投诉处理**：客服经理需要建立一个从接收到解决的完整投诉处理流程。
- **产品上线检查**：IT团队需要一个确保每次更新都万无一失的发布清单。

**它适合在什么情况下使用？**
- 当你需要快速生成一份结构清晰、内容完整的流程文档初稿时。
- 当你对某个流程有基本想法，但不确定如何将其规范化为专业文档时。
- 当你希望借助AI的“思维”来发现流程中可能被忽略的风险或优化点时。

**它不适合什么情况？**
- **高度机密或敏感信息**：不要将公司核心机密流程细节输入到公开的AI服务中。
- **需要即时、零延迟的协作**：它生成文档需要时间，不适合实时会议中的头脑风暴。
- **完全替代人工审核**：它生成的是“草稿”，最终必须由熟悉业务的人进行审核和调整。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
你需要提供以下信息：
1.  **选择模板**：从8个预设的流程类型（如客户服务、人力资源）中选择一个最接近的。
2.  **填写表单**：
    *   **流程名称**：给流程起个名字（如“月度财务报销流程”）。
    *   **适用部门/岗位**：谁用这个流程？
    *   **流程目的**：为什么要做这个流程？
    *   **流程步骤描述**：**这是最重要的部分**，用简单的几句话或列表描述主要步骤。
    *   **关键控制点**（可选）：哪些环节容易出错或需要特别注意？
    *   **涉及角色**（可选）：流程中会涉及到哪些岗位的人？

**用户通常会做哪几步操作？**
1.  **配置**：首次使用时，点击右上角“设置”按钮，输入你的DeepSeek API Key并选择模型（推荐R1）。
2.  **选择与填写**：在左侧区域选择一个模板，然后根据提示填写上述表单信息。
3.  **生成**：点击页面底部大大的紫色“生成 SOP 文档”按钮。
4.  **查看与使用**：在右侧区域等待并查看AI生成的完整Markdown格式文档。你可以复制内容或导出为`.md`文件。

**输出结果长什么样？**
生成的结果是一份**结构非常完整的Markdown文档**，通常包含：
*   封面信息（文档编号、版本、日期）
*   流程概述、目的、适用范围
*   详细的职责分工表格
*   分步骤的操作说明（含负责人、时间、输入输出、控制点）
*   异常处理、流程图、检查清单、FAQ、风险评估等可选章节
*   修订记录和签批栏

**有哪些容易忽略的使用细节？**
- **高级选项**：在表单底部有一个“高级选项”折叠区，可以勾选是否生成**流程图、检查清单、FAQ和风险分析**。默认是开启的，如果你不需要，记得关闭。
- **模型选择**：在设置中，`DeepSeek R1`模型会进行深度推理，生成过程会慢一些，但会展示“思考过程”，并且风险分析更深入。`DeepSeek V3`则生成速度更快。
- **步骤描述是关键**：你输入的步骤描述越清晰、逻辑越连贯，AI生成的文档质量就越高。用“1. 2. 3.”的列表格式输入效果最好。
- **本地存储**：你输入的API Key会保存在浏览器的本地存储中，下次打开页面无需重新输入。

## 【三】核心结构拆解（学习重点）

这个页面可以清晰地分为三个主要模块，它们协同工作：

**1. 输入与配置模块（左侧面板）**
*   **职责**：收集用户意图和配置信息。
*   **组成**：
    *   **模板选择器**：让用户快速定位到某一类流程，为后续的AI提示词提供上下文。
    *   **信息表单**：收集流程的核心要素（名称、步骤、角色等）。
    *   **高级选项开关**：让用户自定义输出文档的组成部分。
    *   **生成按钮**：触发整个流程的“引擎”。
*   **逻辑**：用户操作 → 数据被收集到 `form` 和 `apiConfig` 这两个Vue响应式数据对象中。

**2. AI处理与通信模块（不可见，但最关键）**
*   **职责**：与AI API对话，将用户输入转化为结构化文档。
*   **组成**：
    *   **提示词构建器** (`buildSystemPrompt`, `buildUserPrompt`)：这是**最值得学习的设计**。它不是一个简单的提问，而是精心设计了一个“系统角色”和一套完整的文档框架。系统提示词定义了AI的专家身份、输出格式和内容要求；用户提示词则填充了具体的流程信息。
    *   **API调用器** (`callDeepSeek`)：负责以流式传输的方式与DeepSeek API通信，并分别处理AI的“思考内容”和“最终回复”。
*   **逻辑**：表单数据 + 模板信息 → 拼接成专业的Prompt → 发送给AI API → 接收并解析流式返回的数据。

**3. 输出与展示模块（右侧面板）**
*   **职责**：向用户呈现AI的工作过程和最终成果。
*   **组成**：
    *   **状态指示器**：加载动画、空状态提示。
    *   **思考过程展示区**：如果使用R1模型，这里会展开显示AI的推理链，让生成过程更透明。
    *   **结果渲染区**：使用 `marked.js` 库将AI返回的Markdown文本实时渲染成美观易读的HTML。
    *   **操作按钮**：提供“复制”和“导出”功能，方便用户使用成果。
*   **逻辑**：接收AI返回的原始文本 → 分别存储“思考内容”和“最终回复” → 用Markdown解析器渲染 → 提供下载和复制。

**最值得学习的设计：**
**“框架填充式”的提示词工程**。开发者没有让AI“自由发挥”，而是预先定义了一个近乎完美的SOP文档模板（包含所有章节和格式），然后让AI根据用户输入的信息去“填充”这个模板。这确保了输出结果的高度结构化和一致性，极大提升了可用性。同时，通过“高级选项”开关，动态地从系统提示词中移除或添加某些章节，实现了输出的可定制化。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt在这里扮演了 **“产品经理”和“格式规范”** 的双重角色。它严格规定了AI应该输出什么（内容）、以什么形式输出（格式）、以及思考的深度（推理要求）。

**它解决的是“理解问题”还是“生成问题”？**
主要解决 **“结构化生成问题”** 。AI完全理解“生成一个流程文档”这个任务，难点在于如何生成得专业、完整、格式统一。Prompt通过提供详细的框架和示例，将开放的“创作”任务，转变为了可控的“填空”和“扩写”任务。

**哪些信息是 Prompt 中的关键变量？**
1.  **系统提示词中的变量**：
    *   `[流程名称]`, `[部门名称]`：由用户表单数据动态替换。
    *   `模板.name` 和 `模板.desc`：由用户选择的模板决定。
    *   **条件章节**：是否包含流程图、检查清单等，由 `form.value.includeXXX` 布尔值控制，决定整段章节描述是否被拼接到系统提示词中。
2.  **用户提示词中的变量**：
    *   所有表单字段（`form.value.processName`, `form.value.steps`等）都被直接填入，作为AI填充框架的具体依据。

**如果只改 Prompt，不改代码，会发生什么变化？**
这是改造这个应用最强大也最安全的方式：
*   **改变输出领域**：将系统提示词中的“SOP专家”改为“短视频脚本专家”，用户表单改为“视频主题、目标受众、时长”，你就能得到一个短视频脚本生成器。
*   **改变文档风格**：修改系统提示词中的“符合 ISO 标准”为“活泼有趣的团队内部Wiki风格”，整个文档的语气和排版建议都会变。
*   **增加/减少输出内容**：在系统提示词的“输出格式”部分增加一个“## 11. 所需资源预算”章节，AI就会在新生成的文档中尝试创建这一部分。
*   **改变模型行为**：调整 `temperature` 参数（在`callDeepSeek`函数中，当前是0.3），值越高（如0.8），生成的内容随机性、创造性越强；值越低，则越稳定、保守。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，安全地创建一个属于你的AI工具：

**第一步：保持结构不变，替换核心场景（最安全）**
*   **目标**：先做出一个能跑通的“新外壳”。
*   **操作**：
    1.  复制整个HTML文件。
    2.  修改 `<title>` 和导航栏中的标题，例如改为“周报生成器”。
    3.  修改左侧“模板选择”部分，将SOP模板（如客户服务、HR）换成你的场景模板（如“技术周报”、“销售周报”、“项目复盘报告”）。
    4.  修改表单的`label`和`placeholder`，把“流程名称”改成“报告主题”，把“流程步骤”改成“本周重点工作”，等等。**暂时不要动Vue代码里的变量名**（如`form.value.processName`），只改页面上显示的文字。
    5.  此时运行，你会发现它还能生成一个SOP文档，但界面文字已经变成了周报工具。这是第一步成功。

**第二步：调整输入字段与Prompt（核心改造）**
*   **目标**：让AI生成你想要的内容。
*   **操作**：
    1.  在Vue的 `setup()` 函数里，找到 `form` 这个响应式对象。根据你的需要，增加、删除或重命名字段。例如，增加 `form.value.projectProgress`（项目进度），删除 `form.value.controlPoints`。
    2.  **关键步骤**：重写 `buildSystemPrompt` 和 `buildUserPrompt` 函数。这是应用的灵魂。
        *   在 `buildSystemPrompt` 中，将角色从“SOP专家”改为“资深项目经理”或“高效能人士”。
        *   将输出格式的Markdown模板完全重写，改成周报或你需要的文档格式。
        *   在 `buildUserPrompt` 中，确保你新增或修改的表单字段被正确地拼接进去，作为AI生成新格式文档的素材。
    3.  修改“高级选项”，使其符合你的新场景（例如，选项变成“是否包含下周计划”、“是否生成数据图表描述”）。

**第三步：改变输出形式或展示方式（优化体验）**
*   **目标**：让结果更符合你的使用习惯。
*   **操作**：
    1.  如果你生成的文档不需要Markdown，而是纯文本列表，可以简化结果展示区的样式，甚至移除 `marked.js` 库。
    2.  修改“导出”功能（`exportResult`函数），将文件名从 `SOP_...` 改为 `WeeklyReport_...`，或者将文件格式从 `.md` 改为 `.txt`。
    3.  可以增加新的操作按钮，如“一键分享到Notion”（这需要接入Notion API，是更高级的改造）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“风格语气”选择器**：
    *   **操作**：在表单区增加一个下拉框，选项如“正式严谨”、“轻松活泼”、“简洁要点”。将这个选项作为一个变量（如`form.value.tone`）传入Prompt。在 `buildSystemPrompt` 中，根据这个变量添加一句指令，如“请使用轻松活泼的口吻撰写”。
    *   **效果**：同一份内容可以生成不同风格的文档，适应不同场合（如对内分享 vs 对外汇报）。

2.  **接入多模型API，实现“专家会诊”**：
    *   **操作**：在设置弹窗中增加一个选项，允许用户同时调用两个不同的AI模型（如DeepSeek R1和GPT-4o）。在 `generateSOP` 函数中，先后调用两个API，将第一个模型的结果作为第二个模型的输入或参考，让它们协作生成更优文档。
    *   **效果**：利用不同模型的特长（如一个擅长推理结构，一个擅长优化文案），提升最终输出质量。

3.  **拆分为“创建-管理-预览”多页面应用**：
    *   **操作**：将当前单页面拆解。
        *   `index.html`：当前页面，负责创建。
        *   `library.html`：一个历史文档库，使用 `localStorage` 或 `IndexedDB` 保存所有生成过的SOP，支持搜索、分类和再次编辑。
        *   `preview.html`：一个纯净的文档预览页面，专注于阅读和打印，从URL参数中获取文档ID并渲染。
    *   **效果**：工具变得更专业，更像一个真正的文档管理系统。

4.  **优化交互：增加步骤引导和示例填充**：
    *   **操作**：
        *   **引导**：在页面顶部增加一个分步引导条（Step 1: 选模板， Step 2: 填信息...），让新手更清晰。
        *   **示例**：在每个输入框旁边增加一个“填充示例”小按钮，点击后自动用一段高质量的示例文本填充当前输入框，供用户参考模仿。
    *   **效果**：极大降低新用户的使用门槛，提升输入信息的质量，从而间接提升AI输出质量。

5.  **本地化与离线增强**：
    *   **操作**：集成一个能在浏览器中运行的轻量级LLM（如通过WebAssembly运行Phi-3或Llama 3.1的小参数版本）。在设置中提供“使用本地模型”的选项。当用户没有API Key或需要处理敏感信息时，可以使用本地模型生成基础版本。
    *   **效果**：拓宽了工具的适用场景，增强了隐私性。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合生成极具创意或艺术性的内容**：它的Prompt设计是高度结构化和规范化的，旨在生成“标准文档”。如果你需要写小说、诗歌、广告创意文案，它的框架会成为一种束缚。
- **不适合作为实时决策或自动化执行工具**：它生成的是**文档**，是给人阅读和执行的指南，而不是一段可以直接嵌入到IT系统中运行的**代码**或**自动化脚本**。流程的落地执行仍需人工。
- **不适合处理极度复杂、充满未知和变化的动态流程**：对于需要实时感知环境、频繁做出临时决断的流程（如危机公关现场指挥），它生成的静态文档可能跟不上变化。这类场景更需要的是灵活的协作工具和应急预案库。
- **如果用户想做X，应该换什么工具或方式**：
    *   **想直接生成可执行的自动化脚本**：应使用专门的AI编程助手（如Cursor、GitHub Copilot）或流程自动化平台（如Zapier、Make的AI功能）。
    *   **想进行多轮深度对话来厘清一个模糊的想法**：应直接使用ChatGPT、Claude等聊天界面，进行自由的、无固定格式的讨论。
    *   **想管理一个团队所有流程文档的版本和权限**：应使用专业的文档协作与知识库平台，如Notion、Confluence、飞书文档等，本工具生成的Markdown可以很好地导入这些平台。
