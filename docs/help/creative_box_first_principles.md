# 第一性原理拆解器 - 学习与模仿指南

## 【一】这个网页解决了什么问题？

**使用场景：**
当你面对一个复杂、看似无解的问题时，比如“如何设计一个颠覆性的教育产品？”或“我们如何让城市交通零拥堵？”，这个工具能帮你跳出固有思维框架。它引导你像埃隆·马斯克或亚里士多德那样思考：不是基于现有方案去改进，而是回归问题最根本的物理定律、人性需求和逻辑公理，从头构建全新的解决方案。

**适合情况：**
- **创新构思阶段**：需要突破性创意时
- **问题分析**：当常规分析陷入死胡同时
- **学习思维方法**：想掌握第一性原理这种思考方式
- **团队头脑风暴**：为讨论提供结构化框架

**不适合情况：**
- 需要快速得到具体执行步骤的日常任务
- 已经有成熟、最优解决方案的常规问题
- 纯粹的情感倾诉或简单决策（如“中午吃什么”）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个文本框：输入你想拆解的复杂问题或宏大目标
- 三个示例标签：点击可直接填入预设问题

**用户通常会做哪几步操作？**
1. **输入问题**：在文本框中写下你的困惑，如“如何建立一个真正去中心化的社交媒体平台？”
2. **点击拆解**：按下“开始拆解”按钮
3. **等待分析**：页面会显示“正在追本溯源...”的加载动画
4. **阅读报告**：查看AI生成的结构化分析报告
5. **保存结果**：可复制内容或下载为Markdown文件

**输出结果长什么样？**
一份详细的Markdown格式报告，通常包含：
- **标题**：第一性原理拆解报告：[你的问题]
- **三个核心步骤**：
  1. 打破砂锅问到底（质疑假设、分解要素）
  2. 回归基本真理（寻找物理、人性、数学原理）
  3. 从头开始重构（提出创新路径）
- **结论**：最深刻的洞察总结

**容易忽略的使用细节：**
1. **右上角的齿轮图标**：点击可配置API（如果你有自己的AI服务）
2. **示例标签**：不仅是示例，点击后会自动开始分析
3. **报告上方的按钮**：可复制全文或下载为.md文件
4. **API设置**：如果默认API不可用，需要在这里配置自己的密钥

## 【三】核心结构拆解（学习重点）

这个页面由四个清晰模块组成：

**1. 输入与引导模块**
- **职责**：收集用户问题、降低使用门槛
- **包含**：标题说明、输入框、示例标签、行动按钮
- **设计亮点**：示例标签既展示用法，又可直接触发分析，减少了用户的思考负担

**2. 处理与状态模块**
- **职责**：管理分析过程、显示加载状态
- **包含**：加载动画、隐藏/显示逻辑
- **设计亮点**：明确的加载反馈（文字+动画）让用户知道系统正在工作

**3. 输出与展示模块**
- **职责**：呈现结构化分析结果、提供导出功能
- **包含**：报告标题、Markdown渲染区域、复制/下载按钮
- **设计亮点**：将AI返回的纯文本转换为美观的Markdown格式，提升可读性

**4. 配置模块（侧边栏）**
- **职责**：提供高级自定义选项
- **包含**：API地址、密钥、模型选择
- **设计亮点**：默认使用全局配置，但允许项目级覆盖，平衡了易用性和灵活性

**输入→处理→输出逻辑链路：**
```
用户输入问题 → 点击“开始拆解” → 显示加载状态 → 
→ 构建Prompt发送给AI → 接收AI回复 → 
→ 转换为HTML并渲染 → 显示完整报告 → 
→ 用户可复制/下载
```

**最值得学习的设计：**
**“示例即行动”模式**。示例标签不仅是静态提示，而是可点击的快捷入口。这种设计：
- 降低了新用户的尝试成本
- 展示了工具的潜力
- 让页面在空状态时也有互动性
这是很多AI工具忽略的细节，但对用户体验提升巨大。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt扮演的角色：**
在这个页面中，Prompt不是简单的“请回答问题”，而是**一套思维框架的指令集**。它告诉AI：“不要直接给答案，而是按照这个特定的方法论来思考。”

**解决的是“理解问题”还是“生成问题”？**
两者兼具，但更偏向**结构化思考过程**。它解决的是：
- **理解层面**：要求AI识别问题的本质，而非表面需求
- **生成层面**：按照预设的三步法（拆解→寻根→重构）生成内容

**Prompt中的关键变量：**
1. **用户问题**：`${problem}` - 这是唯一的动态部分
2. **系统角色**：“精通第一性原理的思维大师” - 设定AI的思考身份
3. **结构化模板**：固定的三步法框架，确保每次输出格式一致
4. **格式要求**：“使用清晰、专业的Markdown格式”

**如果只改Prompt，不改代码，会发生什么？**
- **改变分析框架**：比如从“第一性原理”改为“SWOT分析”或“5Why分析法”
- **改变输出风格**：从严谨学术变为轻松幽默
- **改变详细程度**：从详细拆解变为简洁要点
- **改变目标领域**：从通用问题拆解变为特定领域（如商业、技术、艺术）

**提示**：这个Prompt设计精妙之处在于，它用**明确的章节标题和引导性问题**约束了AI的思考路径，而不是让它自由发挥。

## 【五】如何模仿它，做出你自己的版本？

**最安全的模仿路径：**

**第一步：保持骨架，替换场景（最安全）**
- 复制整个HTML结构
- 修改标题和描述（如改为“SWOT分析生成器”）
- 替换示例问题为你的目标领域问题
- **此时先不碰JavaScript和API部分**

**第二步：调整Prompt，改变思维框架**
- 在`generateDecomposition`函数中找到`prompt`变量
- 将“第一性原理拆解法”替换为你想要的思考框架
- 保持`${problem}`这个变量位置不变
- **测试时使用相同的API设置**

**第三步：微调界面，匹配新场景**
- 修改按钮文字和图标（如“开始分析”）
- 调整颜色主题（CSS中的`#5E6AD2`）
- 修改输出部分的标题和说明
- **此时功能已完全改变，但代码结构不变**

**第四步：自定义输入和输出（进阶）**
- 在输入部分增加下拉菜单（如“分析类型”）
- 在输出部分增加新的交互（如“突出重点”按钮）
- 修改下载文件的命名规则

**从哪里下手最安全？**
从**修改文字内容**开始：标题、描述、示例、按钮文字。这些改动不会破坏功能，但能立即看到页面“变成你的”。

## 【六】3–5个可直接尝试的改造方向

**1. 增加分析维度选择**
- **操作**：在输入框上方添加单选按钮或下拉菜单
- **选项**：如“商业视角”、“技术视角”、“人文视角”
- **实现**：将选择的值加入Prompt中，如“请从${perspective}视角进行分析”
- **效果**：让工具从单一方法论变为多维度分析仪

**2. 改为本地模型或更换API**
- **操作**：在设置面板增加“服务提供商”选项
- **选项**：DeepSeek、OpenAI、智谱AI、本地Ollama
- **实现**：根据选择动态构建不同的API请求头和数据格式
- **效果**：降低使用成本，或利用不同模型的专长

**3. 增加“步骤引导”交互模式**
- **操作**：将一次性输出改为分步展示
- **实现**：让AI先输出第一步分析，用户确认或补充后，再继续下一步
- **界面**：类似问卷的“上一步/下一步”按钮
- **效果**：让思考过程更互动，用户可中途调整方向

**4. 添加“灵感库”或“案例对比”**
- **操作**：在输出区域下方增加一个折叠面板
- **内容**：展示类似问题的经典拆解案例
- **数据**：可硬编码几个优秀案例，或调用另一个API获取
- **效果**：为用户提供参考基准，激发更多思考

**5. 优化为“团队协作”版本**
- **操作**：增加“分享链接”和“添加评论”功能
- **实现**：将结果生成唯一ID，存入localStorage或简单后端
- **扩展**：允许多人查看同一份报告并添加批注
- **效果**：从个人思考工具变为团队讨论工具

## 【七】这个网页不适合做什么？（边界提醒）

**明确的局限性：**

1. **不是决策工具**
   - **它不能**：告诉你“应该选择A方案还是B方案”
   - **替代方案**：使用决策矩阵工具或成本效益分析工具

2. **不是执行计划生成器**
   - **它不能**：给出具体的“第一步做什么，第二天做什么”
   - **替代方案**：使用项目管理工具或OKR规划工具

3. **不擅长处理高度情感化或个人化问题**
   - **它不能**：很好地分析“我该不该辞职？”或“如何修复一段关系？”
   - **替代方案**：与真人交流，或使用专门的情感支持AI

4. **不验证事实或数据**
   - **它不能**：确保引用的“物理定律”或“历史案例”准确无误
   - **替代方案**：将它的输出作为思考起点，然后自行查证关键事实

5. **不适合快速、简单的查询**
   - **它不能**：高效回答“Python中如何排序列表？”这类问题
   - **替代方案**：直接使用搜索引擎或代码问答AI

**最重要的提醒：**
这个工具的价值在于**拓展你的思维边界**，而不是**替代你的批判性思考**。它给出的“创新路径”可能不切实际，它质疑的“假设”可能本来就是必要的约束。把它当作一个激发灵感的对话伙伴，而不是一个提供正确答案的权威。
