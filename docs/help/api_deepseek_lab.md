# DeepSeek 改写与提取工具 - 学习指南

## 【一】这个网页解决了什么问题？

想象一下，你正在准备一份重要的报告，但觉得自己的文字表达不够专业；或者你刚读完一篇长文章，想快速抓住核心要点；又或者你需要从一段文字中理清人物或概念之间的关系。这个网页就是为这些场景设计的。

**适合使用的情况：**
- 需要将口语化或粗糙的文字润色成专业、优美的表达
- 需要从长篇文章、会议记录或报告中快速提取关键信息
- 需要分析文本中的人物、事件或概念之间的关联
- 希望用不同的风格（商务、温暖、简洁）来表达同一内容

**不适合的情况：**
- 需要完全原创的内容创作（它基于你提供的文本进行加工）
- 需要高度专业领域的术语翻译或技术文档生成
- 需要实时对话或多轮交互的复杂任务
- 处理非常敏感或机密的信息（API调用会经过外部服务器）

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **文本内容**：在左侧的文本框中粘贴或输入你想要处理的文字
2. **任务模式**：选择你要做什么（润色改写、要点提取、关系抽取）
3. **输出风格**：选择你希望的文字风格（现代化简洁、专业商务、温暖细腻）

**用户通常会做哪几步操作？**
1. 点击右上角的设置按钮（齿轮图标），输入你的 DeepSeek API Key
2. 在左侧输入框中粘贴或输入需要处理的文本
3. 选择任务模式和输出风格
4. 点击“开始生成”按钮
5. 等待几秒钟，在右侧查看结果

**输出结果长什么样？**
- **润色改写**：直接显示改写后的优美文字
- **要点提取**：以清晰的卡片形式展示结构化要点
- **关系抽取**：以卡片形式展示“主体-关系-客体”的结构化信息
- **如果使用 R1 模型**：还可以展开查看 AI 的推理过程

**有哪些容易忽略的使用细节？**
1. **API Key 需要先配置**：第一次使用必须先在设置中输入 API Key
2. **模型选择**：右上角可以切换 V3（常规）和 R1（推理）模型，R1 会显示思考过程
3. **结构化输出**：要点提取和关系抽取会生成 JSON 格式数据，便于后续处理
4. **复制功能**：生成结果后，可以点击“复制结果”一键复制到剪贴板

## 【三】核心结构拆解（学习重点）

这个页面由四个主要模块组成：

**1. 配置与状态管理模块**
- **职责**：管理用户的 API Key、模型选择、页面设置
- **位置**：右上角的设置按钮和模型切换按钮
- **特点**：使用浏览器的 localStorage 保存配置，刷新页面不会丢失

**2. 输入控制模块**
- **职责**：接收用户的所有输入（文本、模式、风格）
- **位置**：左侧的整个面板
- **特点**：通过下拉菜单和文本框收集参数，为后续处理做准备

**3. AI 处理引擎模块**
- **职责**：构建 Prompt、调用 API、处理返回结果
- **位置**：代码中的 `buildPrompt()` 和 `runDeepSeek()` 函数
- **特点**：根据不同模式构建不同的 Prompt，处理 JSON 和纯文本两种返回格式

**4. 结果展示模块**
- **职责**：以合适的方式展示 AI 生成的内容
- **位置**：右侧的输出面板
- **特点**：智能判断输出类型（纯文本用 Markdown 渲染，结构化数据用卡片展示）

**输入 → 处理 → 输出的逻辑链路：**
```
用户输入文本 + 选择模式/风格
    ↓
构建对应的 Prompt（系统指令 + 用户指令）
    ↓
调用 DeepSeek API（携带 API Key 和参数）
    ↓
接收返回结果（纯文本或 JSON）
    ↓
根据模式决定如何渲染（Markdown 或结构化卡片）
    ↓
展示给用户 + 可选复制功能
```

**最值得学习的设计：**
**“模式驱动的 Prompt 构建”** - 这个设计非常巧妙。它没有为每个功能写死代码，而是通过 `buildPrompt()` 函数，根据用户选择的“模式”动态生成对应的 Prompt。这意味着：
- 增加新功能只需要增加一个模式选项和对应的 Prompt 模板
- 修改 Prompt 就能改变 AI 的行为，无需改动代码逻辑
- 实现了“配置化”的 AI 应用设计思路

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt 在这个页面中扮演什么角色？**
Prompt 在这里是“任务说明书”。它告诉 AI：
1. **角色**：你是什么专家（内容润色专家、分析助手等）
2. **任务**：具体要做什么（改写、提取、抽取关系）
3. **格式**：输出应该是什么样子（纯文本、JSON 结构）
4. **风格**：用什么语气和风格来完成

**它解决的是“理解问题”还是“生成问题”？**
主要是“理解问题”。用户输入的是原始文本，但 AI 需要知道：
- “改写”是什么意思？改到什么程度？
- “提取要点”要提取什么？怎么组织？
- “关系抽取”要抽什么关系？怎么表示？

Prompt 就是把这些模糊的需求变成 AI 能理解的明确指令。

**哪些信息是 Prompt 中的关键变量？**
1. **模式变量**（`this.mode`）：决定 Prompt 的整体框架
2. **风格变量**（`this.tone`）：在改写模式中影响文字风格
3. **用户文本**（`this.inputText`）：实际要处理的内容

**如果只改 Prompt，不改代码，会发生什么变化？**
这是本设计最强大的地方！例如：
- 把“专业商务”的 Prompt 描述改得更详细，AI 的输出就会更商务化
- 在要点提取的 Prompt 中要求“每个要点不超过10个字”，输出就会更简洁
- 在关系抽取的 Prompt 中增加“忽略时间关系”，AI 就会过滤掉时间相关的关系

**一句话总结**：Prompt 是连接用户意图和 AI 能力的桥梁，改 Prompt 就是改这座桥的“通行规则”。

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径（从易到难）：**

**第一步：保持结构不变，替换使用场景（最安全）**
- 把“改写/提取/关系”换成你的场景，比如：
  - 模式改为：翻译、扩写、简化
  - 风格改为：正式、幽默、诗意
- 只修改界面文字和 Prompt 模板，不动代码结构
- 测试：确保新场景下 AI 能正确理解你的意图

**第二步：调整输入字段或 Prompt**
- 增加新的输入参数，比如：
  - 为“翻译”模式增加“目标语言”下拉菜单
  - 为“扩写”模式增加“字数要求”输入框
- 在 `buildPrompt()` 函数中引用这些新参数
- 测试：观察新参数是否真的影响了输出结果

**第三步：改变输出形式或展示方式**
- 如果新功能需要不同的展示方式，比如：
  - “翻译”模式可能需要并排显示原文和译文
  - “情感分析”模式可能需要用图表展示情感分布
- 修改结果展示模块的渲染逻辑
- 测试：确保新展示方式清晰易懂

**从哪里下手最安全？**
**从修改 `buildPrompt()` 函数开始**。这是整个应用的核心逻辑，但修改它：
1. 风险最小：不会破坏页面结构
2. 效果最直接：改完立刻能看到 AI 行为的变化
3. 最容易理解：Prompt 是自然语言，比代码好懂

## 【六】3–5 个可直接尝试的改造方向

**1. 增加“自定义 Prompt”模式**
- **怎么做**：在模式下拉菜单中增加“自定义”选项
- **实现**：当选择“自定义”时，显示一个文本框让用户输入自己的 Prompt
- **价值**：让高级用户可以直接控制 AI，实现更灵活的功能

**2. 支持多轮对话**
- **怎么做**：保存每次的输入和输出，作为下一次对话的历史
- **实现**：在 `messages` 数组中保留历史消息
- **价值**：可以实现“基于上次结果继续修改”的迭代工作流

**3. 增加批量处理功能**
- **怎么做**：允许上传文本文件或粘贴多条文本（用分隔符隔开）
- **实现**：循环处理每条文本，结果汇总显示
- **价值**：提高处理效率，适合处理大量相似内容

**4. 集成更多 AI 模型**
- **怎么做**：在设置中增加“模型选择”，支持 OpenAI、Claude 等
- **实现**：根据选择的模型调用不同的 API 端点
- **价值**：用户可以根据任务特点选择最合适的模型

**5. 增加“模板库”功能**
- **怎么做**：预置一些常用的 Prompt 模板（如“写邮件”、“做总结”等）
- **实现**：点击模板自动填充模式和风格设置
- **价值**：降低使用门槛，让新手也能快速产出好结果

## 【七】这个网页不适合做什么？（边界提醒）

**1. 不适合处理超长文本**
- **限制**：大多数 API 有 token 长度限制（通常几千字）
- **如果超过**：文本会被截断，可能丢失重要信息
- **替代方案**：使用支持长文本的专门工具，或先手动分段处理

**2. 不适合需要100%准确性的任务**
- **限制**：AI 可能“幻觉”（编造信息）或误解细微差别
- **例如**：法律合同改写、医学诊断报告、精确的数据提取
- **替代方案**：人工审核 + AI 辅助，或使用专门领域的工具

**3. 不适合实时或高频使用**
- **限制**：API 调用有延迟，且可能产生费用
- **如果频繁使用**：可能遇到速率限制，响应变慢
- **替代方案**：对于高频场景，考虑本地部署模型或使用企业级 API

**4. 不适合完全替代人类创作**
- **本质**：这是“加工”工具，不是“创作”工具
- **如果期望**：输入一个标题就得到完整文章
- **替代方案**：使用专门的写作助手，或接受“多次迭代+人工修改”的工作流

**记住**：这个工具最好的使用方式是“人机协作”——你提供原材料和方向，AI 帮你加工和优化，最后由你把关和定稿。
