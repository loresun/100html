# 播客脚本生成器 - 学习与改造指南

--------------------------------

## 【一】这个网页解决了什么问题？

**使用场景**：当你计划录制一期播客，但不知道如何组织对话、安排时间、设计精彩环节时，这个工具能帮你快速生成一份结构化的对谈脚本。它特别适合内容创作者、自媒体人、教育工作者等需要定期产出音频内容的人。

**适合情况**：
- 需要快速启动一个新播客话题
- 希望对话更有条理，避免冷场或跑题
- 想要预先设计一些“金句”或亮点时刻
- 需要估算每个环节的时长

**不适合情况**：
- 即兴、无脚本的闲聊式播客
- 需要高度专业领域知识（如医学、法律）的严谨访谈
- 多人（超过3人）复杂对话场景
- 已经拥有成熟脚本，只需要微调的情况

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1. **播客主题/话题**：填写这期播客要讨论的核心内容
2. **主持人与嘉宾**：描述参与对话的人员（如：Host: 科技博主小王; Guest: 资深程序员老李）
3. **风格与时长**：选择对话的整体风格（轻松闲聊、深度对谈、快节奏科普）

**用户通常会做哪几步操作？**
1. 在左侧面板填写三个输入项
2. 点击“生成对谈脚本”按钮
3. 等待AI生成结果（约10-30秒）
4. 查看右侧生成的完整脚本
5. （可选）点击“导出脚本”保存为JSON文件

**输出结果长什么样？**
- **氛围与BGM建议**：推荐适合开场和背景的音乐风格
- **脚本时间轴**：按时间顺序排列的对话环节，每个环节包含：
  - 环节标题（如“开场白”）
  - 预估时长
  - 主持人(Host)和嘉宾(Guest)的对话要点
  - 本环节的“金句预埋”（设计好的精彩语句）

**有哪些容易忽略的使用细节？**
1. **首次使用需要设置API密钥**：点击右上角“设置”按钮，输入DeepSeek API Key
2. **嘉宾描述越详细越好**：不只是写名字，可以加上身份、特点（如“Guest: 资深程序员老李，擅长后端架构”）
3. **风格选择影响时长**：“轻松闲聊”约30-40分钟，“深度对谈”60分钟以上
4. **金句是“预埋”的**：不是必须说的，而是设计好的亮点，可以在录制时自然引出

## 【三】核心结构拆解（学习重点）

**页面由哪几个关键模块组成？**

1. **配置模块（左侧面板）**
   - 职责：收集用户输入，控制生成过程
   - 包含：三个输入字段 + 生成按钮

2. **展示模块（右侧主区域）**
   - 职责：显示生成结果，提供导出功能
   - 包含：空状态提示、BGM建议、时间轴脚本、导出按钮

3. **设置模块（弹窗）**
   - 职责：管理API配置
   - 包含：API密钥输入、保存功能

4. **导航模块（顶部）**
   - 职责：提供品牌标识和设置入口

**输入 → 处理 → 输出 的逻辑链路**
```
用户输入（主题+嘉宾+风格）
    ↓
拼接成结构化Prompt
    ↓
发送到DeepSeek API（要求返回JSON）
    ↓
解析API返回的JSON数据
    ↓
渲染为可视化时间轴界面
```

**最值得学习的设计**
**“时间轴可视化”设计**：这个页面没有把脚本做成纯文字，而是用时间轴的形式展示，让用户一眼就能看到：
- 对话的流程和节奏
- 每个环节的时长分布
- 关键节点（金句）的位置

这种设计把“结构化数据”变成了“可视化故事板”，非常适合音频内容的策划。

## 【四】Prompt / AI 逻辑是如何被设计的？

**Prompt在这个页面中扮演什么角色？**
Prompt是“翻译官”和“结构师”——它把用户简单的输入（主题、嘉宾、风格）翻译成AI能理解的详细要求，并规定AI必须按照特定的JSON结构返回结果。

**它解决的是“理解问题”还是“生成问题”？**
主要是**生成问题**，但也包含理解：
- 理解部分：让AI明白“播客脚本”是什么，需要包含哪些元素
- 生成部分：指导AI按照特定格式创造内容

**Prompt中的关键变量**
1. **主题**：${input.topic} - 决定内容方向
2. **嘉宾**：${input.guests} - 决定对话角色和视角
3. **风格**：${input.style} - 决定语调和节奏

**如果只改Prompt，不改代码，会发生什么变化？**
- 改**内容要求**：比如要求AI生成“辩论式”而非“对谈式”脚本
- 改**输出结构**：比如增加“广告插口”或“听众互动环节”
- 改**风格指令**：比如要求“更幽默”或“更学术”
- 改**角色设定**：把“professional podcast producer”改成“stand-up comedy writer”

代码只是负责发送和显示，真正的“智能”都在Prompt里。

## 【五】如何模仿它，做出你自己的版本？

**安全的模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 把“播客脚本”换成“短视频脚本”
- 输入字段改为：视频主题、出镜人物、视频类型（搞笑/科普/情感）
- 输出结构改为：分镜脚本（场景、镜头、台词）

**第二步：调整输入字段或Prompt**
- 增加“目标受众”字段（如：面向大学生/职场新人）
- 在Prompt中加入更具体的风格要求
- 修改JSON结构，比如把“dialogues”改成“shots”（镜头）

**第三步：改变输出形式或展示方式**
- 把时间轴改成“故事板”网格视图
- 增加“一键复制台词”功能
- 添加“预估拍摄时长”统计

**从哪里下手最安全？**
从**修改Prompt和字段标签**开始最安全——不改动页面布局和交互逻辑，只改变内容生成的方向。比如先做一个“TED演讲提纲生成器”，输入字段几乎一样，只是Prompt要求生成演讲提纲。

## 【六】3–5个可直接尝试的改造方向

**1. 增加“情绪曲线”可视化**
- **怎么做**：在时间轴上方添加一个情绪曲线图（轻松→紧张→高潮→收尾）
- **价值**：帮助创作者把控节目节奏，避免平淡

**2. 支持多嘉宾轮换对话**
- **怎么做**：在嘉宾输入框支持“Guest1: ..., Guest2: ...”格式
- **在Prompt中**：明确每个嘉宾的发言顺序和互动方式
- **在展示中**：用不同颜色区分不同嘉宾的发言

**3. 集成语音合成预览**
- **怎么做**：对接文本转语音API（如Azure TTS）
- **用户点击**任何一段对话，可以听到AI朗读的预览
- **价值**：帮助创作者感受实际录制的节奏和语气

**4. 改为“分步骤”生成**
- **怎么做**：把生成过程拆成两步：
  1. 先生成大纲（用户可调整）
  2. 再根据大纲生成详细脚本
- **价值**：给用户更多控制权，避免一次性生成不满意

**5. 增加“灵感库”功能**
- **怎么做**：保存历史生成的脚本，形成可搜索的案例库
- **用户可以从**案例库中选择相似脚本作为模板
- **价值**：积累自己的内容资产，越用越智能

## 【七】这个网页不适合做什么？（边界提醒）

**局限性说明：**

1. **不适合生成逐字稿**
   - 这个工具生成的是“要点”和“方向”，不是一字不差的台词
   - 如果你需要精确到每个字的脚本，应该使用更细致的Prompt或分步骤生成

2. **不适合替代真人创意**
   - AI提供的是“结构”和“灵感”，不是完整的创意
   - 个性化的故事、独特的观点、真实的情感——这些还需要真人补充

3. **不适合高度专业领域**
   - 对于法律、医疗、金融等需要严格准确性的领域
   - AI可能生成看似合理但不准确的内容
   - 应该作为“初稿”，由专业人士审核修改

4. **不适合实时协作**
   - 这是一个单人工具，没有多人编辑、评论、版本管理功能
   - 如果需要团队协作写脚本，应该考虑Notion、Google Docs等协作工具+AI插件

**如果用户想做X，应该换什么工具？**
- 想做**逐字采访稿** → 使用Otter.ai等转录工具+人工整理
- 想做**视频分镜** → 使用这个工具的改造版（如【五】所述）
- 想做**直播流程** → 使用类似工具，但增加“互动环节”、“抽奖时间”等模块
- 想做**专业学术访谈** → 使用这个工具生成初稿，然后由领域专家深度修改
