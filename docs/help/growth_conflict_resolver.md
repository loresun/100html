# 吵架复盘助手 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

**使用场景：**
当你和他人（伴侣、家人、朋友、同事）发生争执后，情绪尚未平复，但希望理性地理解这次冲突。你记得争吵的大致内容和对话，但不确定对方真正的意图是什么，也不知道如何开口和解。这个工具就像一个“情感翻译机”，帮你把情绪化的争吵内容，翻译成双方潜在的内心需求，并提供具体的和解方案。

**适合情况：**
- 个人情绪复盘，想从第三方视角理解冲突。
- 需要具体、可操作的和解话术参考。
- 冲突双方沟通意愿尚存，但缺乏有效沟通方法。

**不适合情况：**
- 涉及严重原则问题、法律纠纷或人身安全威胁的冲突。
- 需要即时、面对面的专业心理咨询或法律调解。
- 你完全不想和解，只想发泄情绪或“证明自己是对的”。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
1.  **吵架背景**：一个文本框，让你描述引发争吵的事件或情境。
2.  **主要争论内容**：一个更大的文本框，让你尽可能客观地回忆并写下双方的关键对话。

**用户通常会做哪几步操作？**
1.  **回忆与记录**：冷静下来后，回忆争吵过程，将背景和对话分别填入两个文本框。
2.  **点击分析**：点击页面中央蓝色的“深度解析矛盾”按钮。
3.  **等待与阅读**：等待几秒钟，AI会在页面右侧生成一份分析报告。

**输出结果长什么样？**
报告会以清晰的卡片形式呈现，包含三部分：
1.  **核心诉求分析**：将你和对方的争吵内容，提炼成“潜在需求”（如“需要被尊重”、“需要安全感”）。
2.  **和解话术建议**：提供2-3种不同风格（如“真诚道歉型”、“深度沟通型”）的具体开场白或沟通语句。
3.  **和事佬点评**：给出一句总结性的、温和的建议。

**有哪些容易忽略的使用细节？**
- **API Key配置**：首次使用前，你需要先配置自己的DeepSeek API Key。这个工具本身不提供AI能力，需要你“自带钥匙”。
- **客观描述**：在“争论内容”中，尽量像写剧本一样还原对话，而不是只写自己的感受（例如：“他说‘你从来不做家务’，我说‘我昨天才打扫过’”）。
- **JSON格式要求**：AI被严格指令要求返回JSON格式。如果返回出错，右侧会显示红色的错误日志，这通常是API Key错误或网络问题。

## 【三】核心结构拆解（学习重点）

这个页面是一个典型的 **“单页应用（SPA）”** ，由几个职责清晰的模块组成：

1.  **用户输入模块** (`<div class="space-y-6">`)
    - **职责**：收集原始、非结构化的用户故事（背景和对话）。
    - **设计亮点**：使用清晰的标签和占位符引导用户填写，将复杂的情绪回忆拆解成两个简单的步骤。

2.  **AI处理与通信模块** (`analyzeConflict` 函数)
    - **职责**：作为“大脑”，负责将用户输入打包成AI能理解的指令（Prompt），并调用外部AI API获取分析结果。
    - **逻辑链路**：`用户输入` → `拼接成特定格式的Prompt` → `发送给DeepSeek API` → `接收并清洗AI返回的JSON`。

3.  **结果展示模块** (`<div v-if="analysis">`)
    - **职责**：将AI返回的结构化数据（JSON）以友好、易读的视觉形式呈现给用户。
    - **设计亮点**：采用网格布局、颜色区分（红/蓝/灰）、卡片式设计，将“需求”、“话术”、“建议”分门别类，一目了然。

**最值得学习的设计：**
**“Prompt即接口”的设计模式**。开发者没有编写复杂的情绪分析算法，而是设计了一个精妙的**Prompt模板**。这个模板规定了AI思考的框架（分析需求、生成话术、给出建议）和输出的格式（严格的JSON）。整个应用的核心逻辑，其实就是维护和调用这个Prompt。这是一种高效利用大模型能力构建应用的核心思路。

## 【四】Prompt / AI 逻辑是如何被设计的？

- **Prompt扮演的角色**：它是整个应用的“**灵魂和指令集**”。它定义了AI在本应用中的角色（情感调解专家）、任务流程（先分析需求，再生成话术）以及必须遵守的输出规则（返回特定格式的JSON）。

- **解决的是“理解问题”还是“生成问题”？** 两者兼有。它首先要求AI**理解**争吵内容背后的“潜在需求”（理解问题），然后基于这个理解**生成**具体的和解话术和建议（生成问题）。

- **Prompt中的关键变量**：
    1.  `背景：${context.value}`：用户填写的背景故事。
    2.  `对话：${dialogue.value}`：用户填写的具体对话。
    3.  **严格的JSON格式定义**：这是确保程序能可靠解析AI回复的关键，它强制AI的输出是结构化的数据，而不是随意的文本。

- **如果只改Prompt，不改代码，会发生什么？**
    整个应用的功能和风格会彻底改变。例如：
    - 将Prompt中的角色从“情感调解专家”改为“辩论教练”，输出就会变成如何驳倒对方的技巧。
    - 修改JSON结构中的字段，比如增加一个`"commonGround"`（共同点）字段，AI就会在分析中额外寻找共识，但前端页面因为代码没改，无法显示这个新字段。
    - 放松格式要求（如删除“只返回JSON”），AI可能返回带解释的文本，导致前端解析失败，报错。

## 【五】如何模仿它，做出你自己的版本？

这是一个完美的“Prompt驱动型”应用模板。你可以按以下安全路径进行模仿：

**第一步：替换核心场景与字段（最安全）**
- 保持所有HTML、CSS、JS结构完全不变。
- 修改页面标题、说明文字（如改为“**会议复盘助手**”）。
- 修改两个输入框的标签和占位符（如“背景”改为“会议主题”，“对话”改为“会议中不同观点的交锋记录”）。

**第二步：重写核心Prompt**
- 这是赋予应用新灵魂的一步。根据你的新场景，重写 `analyzeConflict` 函数中的 `prompt` 变量。
- 例如，对于“会议复盘助手”，Prompt可以改为：“你是一个高效会议教练。请分析以下会议争论… 返回JSON格式：`{"coreIssues": [], "actionItems": [], "followUpEmailDraft": ""}`”
- **关键**：同时修改前端结果展示模块的HTML，使其与新Prompt定义的JSON字段名匹配。

**第三步：调整视觉风格**
- 修改Tailwind CSS的颜色类（如将`indigo-600`改为`emerald-600`）。
- 更换图标（利用Lucide图标库）。
- 调整布局和卡片样式，使其更符合新场景的调性（如商务、创意、教育等）。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“角色立场”选择**：
    - **操作**：在输入区增加一个下拉菜单，让用户选择“我是甲方/乙方/旁观者”。
    - **改造点**：将这个选择变量加入Prompt（如“请从[用户选择的角色]的视角进行分析…”），使分析更具针对性。

2.  **本地存储历史记录**：
    - **操作**：使用浏览器的`localStorage`，将每次的分析结果（时间、背景摘要、分析结果）保存为一个列表。
    - **改造点**：在页面侧边栏或底部增加一个“历史复盘”区域，点击可以回顾之前的分析，观察关系模式。

3.  **切换或支持多模型API**：
    - **操作**：在页面顶部或设置区域，增加一个API选择器（如DeepSeek、OpenAI、智谱AI）。
    - **改造点**：修改`analyzeConflict`函数，根据用户选择动态构造不同的API请求头和URL。这能让你对比不同模型的分析风格和成本。

4.  **增加“话术试练”交互**：
    - **操作**：在每一条“和解话术建议”卡片上，增加一个“试读”按钮。
    - **改造点**：点击后，调用浏览器的语音合成API（`speechSynthesis`）将话术朗读出来，帮助用户感受语气。

5.  **导出与分享功能**：
    - **操作**：在分析报告顶部增加“生成图片报告”和“复制文本”按钮。
    - **改造点**：使用`html2canvas`库将报告区域转为图片，或直接将结构化文本复制到剪贴板，方便用户保存或分享给信任的人（注意隐私）。

## 【七】这个网页不适合做什么？（边界提醒）

- **不适合作为专业心理或法律建议**：它的分析基于通用的大语言模型，无法替代心理咨询师、家庭治疗师或律师的专业诊断和介入。对于长期、复杂或创伤性的关系问题，请务必寻求专业帮助。

- **不适合处理实时争吵**：它是一个“复盘”工具，需要冷静期和文字整理的过程。如果你正在激烈的争吵中，希望有一个AI实时调停，这个工具无法实现。

- **不适合完全自动化沟通**：它提供的是“话术建议”，而非替你发送消息。关系的修复最终依赖于你真挚的、基于理解的沟通。切勿不经思考直接复制粘贴AI生成的话术。

- **隐私警告**：你输入的争吵细节会发送到第三方AI API服务器。尽管 reputable 的API提供商有隐私政策，但切勿在此工具中输入极其敏感的个人身份信息或机密。对于高度敏感的内容，考虑使用本地部署的大模型方案。
