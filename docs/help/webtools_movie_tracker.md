# 影视追踪工具 - 学习指南

## 【一】这个网页解决了什么问题？

**使用场景：**
想象一下，你经常在社交媒体或朋友推荐中看到各种电影、剧集，但总是忘记记下来。或者你已经看了一半的剧，过几天就忘了看到哪一集了。这个网页就像一个**个人观影笔记本**，让你可以：
- 快速记录想看的影视作品
- 标记当前观看状态（想看/在看/已看）
- 给看过的作品打分和写简短评价
- 按状态筛选查看不同列表

**适合：**
- 个人管理观影清单
- 记录观影进度和感受
- 作为简单的个人数据库使用

**不适合：**
- 需要多人协作的观影小组
- 需要详细影评、剧照、演员信息等专业功能
- 需要与流媒体平台（Netflix、Disney+等）同步

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 一个简单的文本输入框，用于输入电影或剧集名称

**用户通常会做哪几步操作？**
1. **添加影片**：在顶部输入框中输入想记录的影视名称，点击“添加”按钮
2. **标记状态**：为每部影片选择“想看”、“在看”或“已看”
3. **评分评价**：点击星星进行评分（1-5星），在输入框中写简短评价
4. **筛选查看**：点击顶部的筛选按钮，只看特定状态的影片
5. **删除记录**：将鼠标悬停在影片卡片上，点击右上角的垃圾桶图标删除

**输出结果长什么样？**
- 每部影片以卡片形式展示，包含标题、状态标签、评分、评价和最后更新时间
- 顶部显示已记录的总影片数
- 筛选按钮会显示各状态下的影片数量

**容易忽略的使用细节：**
1. **评分可取消**：点击已选中的星星可以取消评分（设为0星）
2. **评价自动保存**：在评价输入框输入后，只要离开输入框（或按回车）就会自动保存
3. **状态下拉菜单**：点击状态标签会显示下拉菜单，可以快速切换状态
4. **数据本地保存**：所有记录都保存在你的浏览器本地，换设备或清空浏览器数据会丢失

## 【三】核心结构拆解（学习重点）

这个页面由**4个关键模块**组成：

**1. 数据管理模块（JavaScript对象）**
- **职责**：存储所有影片数据，处理增删改查逻辑
- **包含**：`movies`数组、各种操作方法（addMovie、deleteMovie等）
- **输入→处理→输出**：用户操作 → 更新数据对象 → 触发界面重新渲染

**2. 界面展示模块（HTML + Alpine.js指令）**
- **职责**：根据数据动态生成和更新界面
- **包含**：顶部输入区、筛选区、影片列表、空状态提示
- **关键设计**：使用`x-for`循环渲染列表，`x-show`控制显示隐藏

**3. 状态筛选模块**
- **职责**：让用户按不同状态查看影片
- **包含**：筛选按钮组、`filteredMovies`计算属性
- **值得学习的设计**：筛选逻辑与数据分离，通过计算属性动态过滤

**4. 本地存储模块**
- **职责**：在浏览器关闭后仍能保存数据
- **包含**：`localStorage`的读取和写入
- **关键机制**：数据变化时自动保存，页面加载时自动恢复

**最值得学习的设计：**
**响应式数据绑定** - 数据（JavaScript对象）和界面（HTML）自动同步。当你修改数据时，界面自动更新；当你通过界面操作时，数据自动修改。这是现代前端框架的核心思想。

## 【四】Prompt / AI 逻辑是如何被设计的？

**注意**：这个网页**没有使用AI或Prompt**，它是一个纯前端的数据管理工具。但我们可以从这个角度思考：

**如果我们要添加AI功能，Prompt会扮演什么角色？**
假设我们想添加“智能推荐”功能：
- **解决的是“生成问题”**：根据用户已看影片，推荐类似的新影片
- **Prompt中的关键变量**：用户的历史评分、偏好类型、已看影片列表
- **如果只改Prompt**：可以改变推荐策略（比如从“基于内容”改为“基于协同过滤”）

**当前网页的“逻辑”设计值得学习的地方：**
虽然没有AI，但它的状态管理逻辑清晰：
- 每个影片有明确的属性（title, status, rating, comment）
- 状态转换有明确的定义（wish → watching → done）
- 数据流单向且可预测

## 【五】如何模仿它，做出你自己的版本？

**安全模仿路径：**

**第一步：保持结构不变，替换使用场景**
- 将“影视追踪”改为“书籍管理”、“游戏收藏”、“学习计划”等
- 修改状态选项：如书籍可改为“想读/在读/已读”，游戏可改为“想玩/在玩/已通关”
- **最小改动**：只改文字和颜色，确保基础功能正常

**第二步：调整数据字段**
- 在`movies`对象中添加/删除字段
- 例如书籍管理：添加“作者”、“页数”、“出版社”
- 游戏收藏：添加“平台”、“游戏时长”、“成就进度”
- **注意**：同时要修改`addMovie`函数中的默认值

**第三步：改变界面展示**
- 调整卡片布局，让新字段有合适的展示位置
- 可以添加新的交互元素（如下拉选择、日期选择器等）
- 修改筛选条件，支持按新字段筛选

**从哪里下手最安全？**
从**文字替换**开始最安全：
1. 修改页面标题和说明文字
2. 修改状态标签的文字
3. 修改输入框的提示文字
4. 修改颜色主题（CSS中的颜色值）

这样即使改错了，也不会影响核心功能。

## 【六】3–5个可直接尝试的改造方向

**1. 增加分类标签系统**
- 为每部影片添加“类型”标签（科幻、喜剧、悬疑等）
- 实现多标签筛选功能
- 在卡片上显示标签徽章

- 除了列表视图，增加时间线视图
- 按观看时间顺序排列
- 用可视化方式展示观影频率

**3. 集成电影数据库API**
- 连接TMDB（The Movie Database）API
- 输入影片名称时自动补全和获取海报
- 在卡片中显示海报、导演、演员等信息

**4. 添加数据导出功能**
- 将数据导出为CSV或JSON文件
- 实现数据导入功能（从文件恢复）
- 添加“一键备份”按钮

**5. 改进移动端体验**
- 优化小屏幕下的布局
- 添加滑动删除功能
- 实现离线PWA（渐进式Web应用）功能

## 【七】这个网页不适合做什么？（边界提醒）

**局限性：**

1. **不适合团队协作**
   - 数据只存在个人浏览器中
   - 无法与朋友共享观影清单
   - **替代方案**：使用Notion、Airtable等协作工具

2. **不适合专业影评**
   - 评价只能写简短文字
   - 没有富文本编辑（加粗、链接、图片）
   - **替代方案**：使用Letterboxd、豆瓣电影等专业平台

3. **不适合大量数据管理**
   - 没有搜索功能
   - 没有排序功能（只能按添加时间倒序）
   - **替代方案**：使用Excel或专业数据库工具

4. **不适合跨设备同步**
   - 清空浏览器缓存会丢失所有数据
   - 手机和电脑无法同步
   - **替代方案**：使用带云同步功能的应用

**记住**：这个工具的核心价值是**简单快速**。它不是为了替代专业工具，而是为了解决“随手记录”这个特定需求。当你需要更复杂的功能时，应该考虑更专业的解决方案。
