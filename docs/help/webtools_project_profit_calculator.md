# Webtools 工具箱 - 帮助与学习文档

## 【一】这个网页解决了什么问题？

这个网页是一个**个人效率工具箱**，它把日常工作和学习中常用的十几种小工具（如计算器、计时器、记账本、待办清单等）整合到了一个简洁的网页里。

**适合的使用场景：**
- **快速计算**：当你需要临时计算项目利润、汇率换算，但不想打开复杂的电子表格时。
- **时间管理**：需要专注工作（番茄钟）、记录会议时间（计时器）、或者测量任务耗时（秒表）。
- **随手记录**：突然有个想法要记下来，或者需要快速列个购物清单。
- **数据整理**：需要统计一些简单的收支，或者计数（比如今天喝了多少杯水）。

**不适合的情况：**
- **复杂数据处理**：比如需要图表分析、多表关联的财务计算。
- **团队协作**：所有数据都保存在你的浏览器本地，无法与他人共享。
- **长期、大量的数据存储**：虽然数据会保存在本地，但清除浏览器缓存就会丢失，不适合作为唯一的数据存储方案。

简单说，它是一个**轻量、快速、个人化**的“数字瑞士军刀”。

## 【二】使用方式（给第一次接触的人）

**页面输入是什么？**
- 页面本身没有固定的“首页”，它会根据你访问的链接（比如 `project_profit_calculator`）加载对应的工具。
- 每个工具都有自己特定的输入框，比如“项目利润计算器”会让你填写“收入”、“成本”等数字。

**用户通常会做哪几步操作？**
1.  **选择工具**：通过修改浏览器地址栏的链接（例如把 `project_profit_calculator` 改成 `timer`）来切换不同工具。通常，你会从一个工具列表页面跳转过来。
2.  **填写或设置**：在工具界面中找到输入区域，填入相应的数值或文字（如设置番茄钟的“专注25分钟，休息5分钟”）。
3.  **触发计算/开始**：点击工具对应的按钮，如“计算结果”、“开始计时”、“添加记录”。
4.  **查看结果**：结果会立刻显示在输入区域下方，通常以清晰、突出的方式呈现。

**输出结果长什么样？**
- **数字结果**：通常在一个有边框的卡片内，用大号字体显示最终数值（如利润、换算后的金额）。
- **列表结果**：如待办清单、记账条目，会以列表项的形式逐条显示，并可以勾选完成或删除。
- **动态显示**：计时器、秒表会实时跳动显示剩余或已过时间。

**有哪些容易忽略的使用细节？**
- **数据自动保存**：你在笔记工具里写的内容、在清单里添加的项目，都会**自动保存**在你当前设备的浏览器里。换一台电脑或清除缓存，数据就没了。
- **工具切换**：这个页面本身不提供工具菜单，切换工具需要修改网址或从其他页面跳转。这是它的一个设计特点。
- **设置按钮**：右上角的齿轮图标（⚙️）点击后可以配置AI API，但大部分基础工具（计算、计时）不需要这个。

## 【三】核心结构拆解（学习重点）

这个页面的设计非常清晰，采用了 **“一个框架，多种工具”** 的模块化思路。

**关键模块组成：**
1.  **导航栏**：提供“返回”和“设置”入口，保持界面整洁。
2.  **工具容器**：页面中间最大的白色卡片区域，是所有工具的“舞台”。
3.  **工具逻辑模块**：这是核心。页面根据当前工具的 `type`（如 `formula`， `timer`， `list`）来**动态渲染**对应的HTML结构和交互逻辑。
4.  **设置面板**：一个浮层，用于配置外部AI服务（本页示例中未直接使用，但结构已预留）。

**每个模块的职责：**
- **导航栏**：负责页面级的导航和设置触发。
- **工具容器**：负责接收一个 `tool` 数据对象，并根据其 `type` 属性，决定显示哪个“子工具界面”。
- **工具逻辑模块**：每个 `type` 对应一套完整的HTML模板和JavaScript函数（在引用的 `standalone.js` 中）。例如，`type: 'formula'` 负责渲染输入框和计算按钮；`type: 'timer'` 负责渲染时间显示和开始/暂停按钮。
- **设置面板**：管理用户配置，并可能将配置传递给需要AI功能的工具。

**输入 → 处理 → 输出 的逻辑链路：**
1.  **输入**：用户在对应工具的输入框（`<input>`）中填写数据，数据被绑定到 `tool` 对象的对应属性上（通过 `x-model`）。
2.  **处理**：用户点击按钮（如“计算结果”），触发一个JavaScript函数（如 `calculate(tool)`）。这个函数读取 `tool` 对象中用户输入的数据，执行计算、计时或添加列表项等操作。
3.  **输出**：处理函数将结果写回 `tool` 对象的某个属性（如 `tool.result`）。因为页面使用了响应式框架（Alpine.js），数据一旦变化，显示结果的HTML部分就会自动更新。

**最值得学习的设计：**
**基于数据驱动的UI渲染模式。** 整个页面的状态（显示哪个工具、工具里有什么数据、结果是什么）都封装在一个 `tool` 对象里。前端框架（Alpine.js）监听这个对象的变化，并自动更新DOM。这种设计让添加一个新工具变得非常容易：你只需要定义好这个工具对应的 `type`，以及它的数据结构和处理函数，然后在HTML里为这个 `type` 写一段模板即可。代码的复用性和可维护性很高。

## 【四】Prompt / AI 逻辑是如何被设计的？

> **注意**：在当前提供的HTML代码中，并没有直接展示调用AI的界面或逻辑。但页面预留了API配置面板，这表明它是一个**支持AI功能扩展的框架**。

**Prompt 在这个页面中可能扮演的角色：**
如果未来集成了AI工具（比如“文本工具”可能调用AI进行总结润色，“生成器”可能调用AI生成内容），那么：
- **Prompt是“指令”**：它告诉AI模型要做什么。例如，在“文本工具”中，Prompt可能是“请将以下用户输入的文字，改写成更正式的商务邮件风格”。
- **Prompt是“模板”**：它可能是一个包含变量的字符串。例如，“请根据{行业}和{产品特点}，生成一段50字的产品描述。” 这里的 `{行业}` 和 `{产品特点}` 就是用户在前端输入框里填的内容。

**它解决的是“生成问题”还是“理解问题”？**
在工具类场景中，更可能是**生成问题**。例如，根据用户输入的几个关键词，生成一个会议议程、一段代码或一首诗。当然，也可以用于**理解问题**，比如分析一段用户输入的情绪，但在这个效率工具箱的语境下，前者更常见。

**哪些信息是 Prompt 中的关键变量？**
关键变量就是用户在工具界面上输入的内容。例如：
- 在“项目利润计算器”中，变量可能是 `收入`、`成本`、`税率`。
- 在“文本工具”中，变量就是用户输入的那一大段文字。
这些变量会被“插入”到预设的Prompt模板中，形成完整的请求发送给AI。

**如果只改 Prompt，不改代码，会发生什么变化？**
假设“文本工具”的底层是调用AI，那么：
- **改变AI的行为**：将Prompt从“翻译成英文”改成“提取关键词”，那么同一个输入框和按钮，产出的结果就从翻译文本变成了关键词列表。
- **改变结果的风格和质量**：优化Prompt的措辞、增加约束条件（如“用列表形式输出”、“不超过100字”），会直接提升AI返回结果的有用性和规范性。
这意味着，**你可以通过精心设计Prompt，让同一个前端界面化身为功能迥异的各种AI小工具**，这是成本极低的创新方式。

## 【五】如何模仿它，做出你自己的版本？

你可以遵循以下路径，从简单到复杂地创建自己的工具箱：

**第一步：替换使用场景（最安全）**
- **目标**：保持现有代码结构完全不变，只替换工具的内容和计算逻辑。
- **操作**：找到 `standalone.js` 文件（虽然未提供，但可从HTML推断其存在），里面定义了所有工具的数据和函数。复制一个现有工具（如 `formula` 类型的工具）的配置，修改它的 `name`（名称）、`desc`（描述）、`fields`（输入字段的标签和单位），以及 `calculate` 函数里的计算公式。
- **举例**：把“项目利润计算器”改成“房贷计算器”，字段从【收入， 成本】改成【贷款总额， 年利率， 贷款年限】，公式改为房贷月供计算。

**第二步：调整输入与输出形式**
- **目标**：改变用户交互的方式。
- **操作**：
    - **增加输入类型**：在工具的 `fields` 数组中，不只是用 `type: number`，可以尝试 `type: range`（滑块）、`type: color`（颜色选择器）或 `type: select`（下拉菜单）。
    - **改变输出展示**：不只用数字显示结果。可以尝试用 `<progress>` 标签显示进度条，用简单的SVG画一个饼图，或者将多行结果用更漂亮的列表展示。

**第三步：引入新的工具类型**
- **目标**：添加一个完全不同的工具。
- **操作**：
    1.  在 `standalone.js` 中，参照现有结构，定义一个新的工具对象，并赋予一个独特的 `type`，例如 `type: 'dice'`（掷骰子）。
    2.  在HTML中，找到工具容器内部，仿照其他工具，为 `[x-show="tool.type === 'dice'"]` 编写一段HTML模板，包含你需要的按钮和显示区域。
    3.  在JS中，编写对应的函数（如 `rollDice(tool)`）来实现掷骰子的随机逻辑，并更新 `tool.result`。

**从哪里下手最安全？**
**从“公式计算器”（`type: 'formula'`）开始模仿是最安全的。** 因为它逻辑单纯（输入→计算→输出），HTML结构清晰，且不涉及复杂的定时器或状态管理。你几乎可以把它当作一个模板，只改文字和公式，就能快速做出一个可用的新工具。

## 【六】3–5 个可直接尝试的改造方向

1.  **增加“工具菜单”页面**：
    - **问题**：当前页面无法直接切换工具，体验不完整。
    - **改造**：创建一个 `index.html`，列出所有工具的名称、图标和描述。每个工具项都是一个链接，指向 `tool.html?name=工具类型`。在当前页面通过JavaScript读取网址参数，动态加载对应的工具。这样就有了一个完整可用的产品。

2.  **为“清单工具”增加分类和过滤**：
    - **问题**：待办事项多了以后会混乱。
    - **改造**：在添加待办时，增加一个“分类”下拉菜单（如“工作”、“生活”、“学习”）。在清单上方增加几个过滤按钮（“全部”、“未完成”、“工作”），点击后只显示对应分类的条目。这涉及到对 `tool.items` 数组的过滤显示。

3.  **将“记账工具”数据可视化**：
    - **问题**：只有数字总和，不直观。
    - **改造**：引入一个轻量级图表库（如Chart.js）。在记账工具下方，新增一个“图表”选项卡。点击后，将 `tool.entries` 中的数据按分类汇总，绘制成一个饼图或柱状图，直观展示消费构成。

4.  **为“文本工具”集成AI能力**：
    - **问题**：只能做本地文本处理（如计算字数），功能有限。
    - **改造**：利用已预留的API设置面板。在“文本工具”中增加一个“处理方式”下拉菜单，选项包括“本地统计字数”和“AI润色/总结/翻译”。当选择AI选项并点击按钮时，将用户输入的文本和选定的操作类型，组合成Prompt发送给配置好的AI API，并将返回的结果显示在输出框。

5.  **增加“数据导入/导出”功能**：
    - **问题**：数据锁在本地浏览器，无法备份或迁移。
    - **改造**：在设置面板或每个工具内，增加“导出数据”和“导入数据”按钮。导出时，将 `tool` 对象中关键数据转换为JSON字符串，并允许用户下载为一个 `.json` 文件。导入时，读取用户上传的JSON文件，将数据还原到 `tool` 对象中。这是提升工具实用性的关键一步。

## 【七】这个网页不适合做什么？（边界提醒）

1.  **不适合做严肃的财务或项目管理**：
    - **局限性**：计算逻辑相对简单，没有考虑复利、折旧、多人分摊等复杂场景；数据存储在本地，有丢失风险。
    - **替代方案**：对于正式的项目利润计算或财务管理，请使用专业的电子表格软件（如Excel、Google Sheets）或SaaS工具（如QuickBooks、用友）。

2.  **不适合做需要持久化、跨设备同步的核心数据记录**：
    - **局限性**：依赖浏览器本地存储，清除缓存、更换设备或浏览器都会导致数据消失。
    - **替代方案**：如果需要可靠的记录，应使用带有云同步功能的笔记应用（如Notion、语雀）、待办应用（Todoist、Microsoft To Do）或专业的会计软件。

3.  **不适合处理大量、复杂的文本或数据**：
    - **局限性**：界面是为快速、轻量的操作设计的。如果文本过长（如万字文章），在文本域中编辑会卡顿；如果记账条目超过几百条，列表渲染和操作会变慢。
    - **替代方案**：使用专业的文本编辑器或数据库前端应用。

**总结**：请将这个工具箱视为你的**数字便签纸**或**临时计算器**。它擅长解决“马上需要，用完即走”的轻量级任务，为你提供瞬时的工作流辅助，而不是取代那些功能完备的专业软件。
