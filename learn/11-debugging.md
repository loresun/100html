# 11｜如何调整 bug 与排查问题

## 目标与收益

- 学会定位最常见的前端问题。
- 能快速判断问题是“输入/提示词/参数/网络”哪一层。
- 拥有一套排查清单，减少盲查。

## 新手排查流程（从上到下）

1. **输入是否完整**：主题/对象/风格是否为空？
2. **提示词是否拼装正确**：是否漏字段？
3. **参数是否合理**：max_tokens 是否过小？
4. **网络/Key 是否异常**：API Key 是否有效？

## 常见问题分类

### 1. 没有输出

- 检查 API Key 是否存在。
- 检查网络是否被拦截。
- 确认请求函数是否被调用。

### 2. 输出格式乱

- 提示词里没有明确格式要求。
- temperature 太高导致随机性过强。

### 3. 输出内容偏题

- 输入信息太少，模型猜测。
- 没有写清角色与任务目标。

## 诊断清单（可复制）

- [ ] API Key 是否存在
- [ ] 请求是否成功（查看控制台）
- [ ] Prompt 是否包含必填字段
- [ ] 输出格式是否在提示词中要求
- [ ] 参数是否过高/过低

## 实践任务

1. 故意移除一个必填字段，观察输出变化。
2. 把 temperature 调到 0.9，再对比 0.2 输出。
3. 写出你常遇到的 3 个 bug，并记录解决方式。

## 常见坑

- 不看控制台直接猜问题。
- 盲目改提示词，忽略参数影响。
- 不记录问题与解决方案。
