# 20｜大模型基础与 API 认知

## 目标与收益

- 理解「API 是什么」以及它在大模型调用中的角色。
- 建立大模型常见概念的最小知识框架，避免概念混淆。
- 能用清晰的语言向新手解释：模型、接口、参数、上下文之间的关系。

## 入门先读（给新手的 5 句话）

1. API 就是“你和模型沟通的入口”，不是模型本身。
2. 模型能力 ≠ 事实正确性，输出需要校验。
3. 上下文窗口决定你能“带多少信息进来”。
4. 参数影响输出风格，提示词影响输出方向。
5. 模型调用像“流程”：输入 → 推理 → 输出。

## 关键概念

- **API（Application Programming Interface）**：应用程序接口，前端通过它把提示词发给模型，并拿回结果。
- **模型（Model）**：真正执行推理与生成的“引擎”，例如 chat 或 reasoner。
- **上下文窗口**：一次对话能携带的最大信息量，超出会被截断。
- **系统/开发/用户消息**：角色优先级，系统 > 开发 > 用户。
- **温度（temperature）**：控制输出随机性；越高越发散。
- **流式输出（streaming）**：边生成边显示结果，提升交互体验。

## 核心关系图（文字版）

```
用户输入 → 提示词模板 → API 请求 → 模型推理 → 流式输出 → UI 渲染
```

## 核心方法

### 1. 用一句话解释 API

> API 就是“把你的提示词交给模型，再把模型的回答拿回来”的通道。

### 2. 用三层理解大模型调用

- **请求层**：API 地址、密钥、模型名、参数
- **模型层**：推理与生成能力
- **展示层**：流式渲染、结果排版、复制导出

### 3. 常见参数最小记忆表

| 参数 | 作用 | 新手建议 |
| --- | --- | --- |
| model | 选择模型 | 默认使用项目推荐值 |
| temperature | 随机性 | 0.3 - 0.8 |
| max_tokens | 最大长度 | 先按需求给范围 |
| stream | 是否流式 | 统一开启 |

## 实践任务

1. 在任意工具中找到「模型选择 + API Key」配置区。
2. 用一句话解释：为什么要保存 API Key？
3. 观察流式输出与非流式输出的差别，写下体验差异。

## 常见坑

- 把 API 当作模型，忽略了模型选择与参数配置。
- 忽视上下文窗口，导致关键指令被截断。
- 过度依赖单次输出，不做校验。

## 延伸阅读与练习

- 练习：用 3 个比喻解释 API（如“快递通道/电话/管道”）。
- 练习：列出你最常用的 3 个参数，并写出它们的影响。
