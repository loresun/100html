# 21｜前端知识集成：框架、组件与交互

## 目标与收益

- 搭建前端知识的最小结构：框架 → 组件 → 交互 → 数据。
- 了解不同前端框架与组件的职责边界。
- 能把「想法 → 前端实现」拆成可执行步骤。

## 入门先读（给新手的 5 句话）

1. 前端框架是“组织页面与状态”的方式，不是设计稿。
2. 组件是可复用的 UI 块，不是一次性页面。
3. 交互 = 触发事件 + 更新状态 + 反馈结果。
4. 先写出流程，再写界面，效率更高。
5. 任何想法都能先做一个“最小版本”。

## A. 前端框架与组件

### 常见框架（本项目重点）

- **Vue 3**：适合复杂状态管理与大工具。
- **Alpine.js**：适合轻量交互与单文件工具。

### 组件类型速记

- **输入组件**：文本框、下拉、多选、滑块、文件上传
- **控制组件**：按钮、开关、步骤条
- **展示组件**：卡片、列表、表格、标签、时间线
- **反馈组件**：提示条、Loading、空状态

## B. 前端交互方式

### 1. 表单式交互

- 典型：填写表单 → 点击生成 → 输出结果
- 适合：结构化输入需求（文案/脚本/总结）

### 2. 即时反馈交互

- 典型：输入即预览、滑动即变化
- 适合：图文排版、卡片生成、样式调试

### 3. 分步引导交互

- 典型：步骤条、向导式流程
- 适合：复杂任务拆解（如完整营销流程）

## C. JavaScript 常见库（新手认知版）

- **marked.js**：Markdown 渲染为 HTML
- **lucide**：图标库
- **dayjs**：日期处理
- **clipboard API**：一键复制

> 本项目以“CDN + 单文件”为核心，优先选轻量库。

## D. 新手如何基于本项目实现自己的想法

### 1. 把想法拆成三句话

- 我要解决谁的问题？
- 输出需要什么格式？
- 用户需要哪些输入？

### 2. 找到相似工具作为模板

- 先选“最接近你的需求”的 HTML 文件。
- 修改标题、输入字段与提示词模板。

### 3. 用最小改动验证

- 先改输入字段 + 提示词。
- 输出先用纯文本展示。
- 再逐步加入样式与导出。

### 4. 保持交互闭环

- 让用户明确知道：输入了什么 → 得到什么 → 下一步做什么。

## 实践任务

1. 从根目录找一个与你的想法最接近的工具。
2. 把它的输入字段改成你的需求字段。
3. 用 3 行提示词替换原模板（先能跑通即可）。
4. 加一个「一键复制」按钮完成闭环。

## 常见坑

- 先写样式后写流程，导致后期重做。
- 组件过多，输入复杂，用户不敢填。
- 只做生成，不提供“下一步使用建议”。

## 延伸阅读与练习

- 练习：画出一个工具的交互流程图（输入 → 处理 → 输出）。
- 练习：把一个想法拆成 5 个可复用组件。
