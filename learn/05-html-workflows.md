# 05｜HTML 工作流与工具化实践

## 目标与收益

- 用单文件 HTML 搭建完整 AI 工作流。
- 理解「输入 → 处理 → 输出」的可视化与复用。
- 能把提示词、参数与 UI 绑定成一个可交付的工具。

## 新手理解框架（先记住这三件事）

1. 每个工具都只有三层：输入 → 处理 → 输出。
2. 提示词就是“处理层”的核心。
3. UI 的目标是让用户更快给出高质量输入。

## 核心思路

### 1. 工作流拆分

- **输入层**：结构化表单（主题、受众、风格、约束）
- **处理层**：提示词拼装、模型参数配置
- **输出层**：结果渲染、复制、导出

### 2. 组件化复用

- 输入组件：多选、滑块、标签、文件上传
- 输出组件：卡片、表格、步骤清单、导出按钮
- 提示词构建：模板函数 + 变量插值

### 3. 工具链设计

- 单工具可用 → 多工具联动 → 模板化工作流
- 每个工具输出可直接作为下一个工具输入

## 结构模板（可复制）

```
1. 用户输入（表单）
2. 生成 Prompt（模板 + 变量）
3. 调用模型（统一请求函数）
4. 输出渲染（HTML + 复制/导出）
```

## 新手 UI 清单

- [ ] 输入区域有示例占位文本
- [ ] 输出区域支持一键复制
- [ ] 参数区域可以折叠/展开
- [ ] 错误提示清晰可见

## 实践任务

1. 选一个已有 HTML 工具。
2. 抽象出它的「输入 → 输出」结构。
3. 补充一个可复用的提示词模块。
4. 加入“导出为文本”功能（按钮即可）。

## 常见坑

- 提示词逻辑写死，难以扩展。
- UI 过度复杂，导致学习成本高。
- 输出没有格式，用户无法直接用。

## 延伸阅读与练习

- 练习：把 2 个工具组合成“连续流程”。
- 练习：设计一个“工具配置卡”，记录默认参数。
