# 08｜进阶迁移：从轻量到专业

## 目标与收益

- 明确从“纯前端工具”迁移到“专业产品”的路径。
- 让经验可迁移到下一阶段（有后端、更强能力）。
- 建立“何时该上后端”的判断标准。

## 新手理解（先别急着上后端）

- 没有用户不要上后端。
- 有用户但成本低，也可以先别上后端。
- 只有在“用户需求逼你上”时再迁移。

## 迁移路线

### 1. 从静态到动态

- 静态部署 → 引入数据存储 → 用户体系
- 需求驱动后端（避免先搭后端再找用例）

### 2. 从单点到系统

- 多工具联动 → 工作流平台化
- Prompt 资产 → 标准化能力库

### 3. 从工具到产品

- 指标体系：激活、留存、付费、转介绍
- 模板升级：行业模板、场景库、案例库

## 迁移时机判断

- 用户数量增长带来协作/保存需求
- 单用户成本无法下降
- 需要更稳定的模型调度与数据安全

## 迁移后的能力清单

- 用户登录与资产保存
- 工作流编排与模板管理
- 统一的 API 网关与配额控制
- 运营后台与数据分析

## 新手迁移清单

- [ ] 有明确增长指标
- [ ] 有稳定的付费用户
- [ ] 成本压力明显
- [ ] 用户对“保存/协作”有需求

## 实践任务

1. 写下你需要后端的 3 个触发条件。
2. 设计一个“工作流平台”的核心功能列表。
3. 给现有工具增加一个可复用模块（例如模板库入口）。

## 常见坑

- 没有明确指标就引入复杂架构。
- 把“迁移”当成重写，忽视复用价值。
- 过度设计，导致开发周期被拖长。

## 延伸阅读与练习

- 练习：写一份“从纯前端到全栈”的路线图。
- 练习：制定一个“阶段性里程碑计划”。
