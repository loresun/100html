# 06｜纯前端产品架构（无后端）

## 目标与收益

- 明确「无后端」AI 产品的架构边界。
- 知道如何降低成本、提升安全性与可用性。
- 能够在纯前端场景下进行版本发布与维护。

## 新手理解方式

- 纯前端 = 只有 HTML/JS/CSS。
- 所有请求都从浏览器发出。
- 服务器只负责“静态托管”。

## 架构核心

- **前端直连 API**：在浏览器里请求模型服务。
- **本地存储**：API Key 存储在 localStorage。
- **静态部署**：纯静态资源托管（无服务器）。

## 关键实践

### 1. 安全与隐私

- 提醒用户 API Key 只保存在本地。
- 提供一键清除缓存与密钥。
- 避免在前端日志里输出敏感信息。

### 2. 成本控制

- 引导用户选择合适模型。
- 提前限制输出长度。
- 对高频操作增加“确认/节流”。

### 3. 错误处理

- 统一提示：API Key 缺失/额度不足/网络异常。
- 引导用户查看日志或帮助文档。
- 对网络失败提供重试按钮。

## 典型架构流程

```
用户输入 → 组装 Prompt → 前端请求模型 → 输出渲染 → 本地缓存
```

## 新手检查清单

- [ ] API Key 有说明与风险提示
- [ ] 有清除缓存/密钥入口
- [ ] 有错误提示与重试按钮
- [ ] 输出有复制或导出

## 实践任务

1. 在工具里加入“清除本地密钥”按钮。
2. 设计 3 种错误提示文案。
3. 写出「纯前端架构优势」的说明卡片。

## 常见坑

- API Key 未提示风险，用户不信任。
- 没有错误兜底，导致用户放弃。
- 忘记配置跨域或部署静态资源。

## 延伸阅读与练习

- 练习：写一个“本地存储管理”操作说明。
- 练习：为你的工具设计一个“体验指南页”。
