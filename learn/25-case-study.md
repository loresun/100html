# 25｜案例拆解：从想法到工具

## 目标与收益

- 通过一个完整示例理解“需求 → 交互 → 提示词 → 结果”。
- 学会从现有工具中迁移思路。
- 能够独立完成一个最小可用版本。

## 案例主题

**目标**：做一个“活动宣传文案生成器”。

## 1. 需求拆解

- 用户是谁：运营/市场/活动组织者
- 输出是什么：标题 + 正文 + CTA
- 输入是什么：活动主题、时间、地点、亮点

## 2. 交互流程

1. 用户填写四个字段
2. 点击生成
3. 输出结果可复制

## 3. 提示词模板

```
你是活动文案策划。
活动主题：{主题}
时间：{时间}
地点：{地点}
亮点：{亮点}
输出：标题 3 个 + 正文 1 篇 + CTA 1 句。
风格：{风格}
```

## 4. UI 组件建议

- 输入区：文本框 + 时间选择 + 多行文本
- 输出区：卡片 + 一键复制
- 反馈：加载状态 + 空状态

## 5. 最小可用版本（MVP）

- 先实现：输入 → 生成 → 输出
- 暂缓：多模板、多风格、导出

## 6. 复用路径

- 找到最接近的文案类工具作为模板
- 替换标题、字段与提示词
- 保持交互结构不变

## 实践任务

1. 选一个文案类工具作为基础。
2. 按上面的字段完成替换。
3. 生成 3 条示例并调整提示词。
