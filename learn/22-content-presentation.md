# 22｜技术呈现方式：HTML 与 Markdown 的分工

## 目标与收益

- 明确「哪些内容适合用 HTML 呈现，哪些适合用 Markdown」。
- 能设计“界面 + 文档”的组合式输出结构。
- 为后续扩展学习资料建立可复用的呈现规范。

## 核心原则

1. **界面与交互用 HTML**：可视化、可操作、可互动。
2. **知识与说明用 Markdown**：结构清晰、便于维护、易于扩展。
3. **分工清晰**：HTML 负责体验，Markdown 负责内容。

## A. 适合用 HTML 呈现的内容

- **界面布局**：导航、卡片、分栏、工具面板
- **组件样式**：按钮、输入框、标签、提示框
- **交互状态**：加载、空状态、错误提示
- **结果展示**：卡片、表格、时间线、流程图

### HTML 呈现示例（文字版）

```
[输入区] 主题 + 受众 + 风格
[按钮] 生成内容
[输出区] 卡片形式展示结果
```

## B. 适合用 Markdown 呈现的内容

- **知识说明**：基础概念、参数解释、常见问题
- **操作指南**：步骤列表、注意事项、常见坑
- **学习路径**：章节目录、任务清单、术语解释
- **可复制模板**：提示词范式、示例对话

## C. 推荐的内容分层结构

```
第 1 层：HTML 工具页（可交互）
第 2 层：Learn 文档（可学习/可复用）
第 3 层：项目 README（整体入口）
```

## D. 新手可直接套用的写法

### Markdown 小节模板

- 目标与收益
- 关键概念
- 核心方法
- 实践任务
- 常见坑

### HTML 页面结构模板

- 顶部导航
- 左侧输入
- 右侧结果
- 说明区或提示区

## 实践任务

1. 选择一个你常用的工具页，列出它的 3 个核心组件。
2. 把该工具的使用说明写成 Markdown（含步骤与注意事项）。
3. 对比：哪些内容更适合放在 HTML 页面上？哪些放在文档？

## 常见坑

- 把所有说明都塞进 HTML 页面，导致页面过长。
- 文档只讲概念，不提供可执行步骤。
- HTML 页面缺少空状态与提示文字。

## 延伸阅读与练习

- 练习：用 Markdown 写一个“3 分钟上手指南”。
- 练习：把一个工具拆成「界面说明 + 操作步骤」两块内容。
