一段代码，理解 AI 对话的本质

当你在 ChatGPT 或 DeepSeek 网页上打字时，背后发生的其实就是一次 API 请求。 下面这段代码看起来很长，但别担心——我们会像拆礼物一样，一层一层把它拆开讲清楚。

Terminal / 终端 
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${DEEPSEEK_API_KEY}" \
  -d '{
        "model": "deepseek-v4-flash",
        "messages": [
          {"role": "system", "content": "You are a helpful assistant."},
          {"role": "user", "content": "Hello!"}
        ],
        "stream": false
      }'
1

curl 是什么？

curl 是一个命令行工具，作用就像是一个"快递员"——它帮你把请求送到指定的网址，然后把结果带回来。

生活化比喻：
想象你要给 DeepSeek 公司寄一封信。curl 就是那个帮你送信的快递小哥， https://api.deepseek.com/chat/completions 就是收件地址。

2

-H 请求头是什么意思？

-H 代表 Header（请求头），就像信封上的信息——告诉对方这封信的格式和你的身份。

"Content-Type: application/json"

告诉服务器："我发给你的内容是 JSON 格式 的。"
就像告诉收件人："这是一封中文信，请用中文阅读。"

"Authorization: Bearer ${DEEPSEEK_API_KEY}"

这是你的 身份凭证（API Key），就像进入 VIP 会员区需要出示会员卡。
${DEEPSEEK_API_KEY} 是一个变量，需要替换成你在 DeepSeek 平台申请的真实 Key。

3

-d 后面的内容是什么？

-d 代表 Data（数据），就是你要发送的"信件内容"。这里的内容是用 JSON 格式写的。 

{
  "model": "deepseek-v4-flash",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Hello!"}
  ],
  "stream": false
}
model

选择使用哪个 AI 模型。deepseek-v4-flash 是 DeepSeek 的 V4 Flash 模型。

messages

对话消息列表。包含角色（system/user/assistant）和内容。

stream

是否流式输出。false 表示等 AI 全部生成完再返回。

4

messages 里的角色是什么意思？

AI 对话就像一场舞台剧，不同角色有不同的职责：

system

导演：设定 AI 的性格、能力和行为规范。用户看不到，但会影响 AI 的全部回复。

user

观众/提问者：就是你！你输入的问题或指令。

assistant

演员/AI：AI 的回复内容。多轮对话时需要把历史回复也传进去。

5

高级参数：精细控制 AI 的行为

进阶

除了基础的 model 和 messages，你还可以加入这些参数来"微调"AI 的表现：

"temperature" 范围: 0 ~ 2

创造力/随机性调节器。数值越高，回答越有创意但可能"跑偏"；数值越低，回答越稳定但可能"死板"。

0 = 最确定 ← 0.7 = 平衡（推荐） → 2 = 最随机

使用场景：写代码/翻译用 0~0.3；日常对话用 0.7；创意写作/头脑风暴用 1.0+

"max_tokens" 整数

回复长度上限。限制 AI 最多生成多少个 token（约等于 0.7 个汉字或 0.75 个英文单词）。

例如："max_tokens": 1000 约等于限制回复在 700 字左右。不设置则由模型自行决定长度。

"top_p" 范围: 0 ~ 1

核采样。另一种控制随机性的方式。0.1 表示只考虑概率最高的 10% 词汇，1 表示考虑所有词汇。

建议：通常只调 temperature 或 top_p 其中一个，同时调两个容易产生不可预期的结果。

"stream" true / false

流式输出。设为 true 时，AI 会像打字一样一个字一个字返回，而不是等全部生成完再返回。

体验差异：ChatGPT 网页版那种"打字机效果"就是 stream=true 的效果，用户体验更好但代码处理更复杂。

"frequency_penalty"

重复惩罚（-2~2）。正数让 AI 避免重复已说过的话，适合长文写作。

"presence_penalty"

话题惩罚（-2~2）。正数鼓励 AI 聊新话题，适合头脑风暴。

完整示例：带高级参数的请求 

{
  "model": "deepseek-v4-flash",
  "messages": [
    {"role": "system", "content": "你是一个创意写作助手"},
    {"role": "user", "content": "写一首关于春天的诗"}
  ],
  "temperature": 1.0,
  "max_tokens": 500,
  "top_p": 0.9,
  "stream": true,
  "frequency_penalty": 0.5
}
6

Response 收到回信长什么样？

当你发送请求成功后，服务器会回给你一个 JSON 包裹。理解它，你才能把 AI 的话提取出来展示给用户。 

{
  "id": "chatcmpl-a1b2c3d4...",
  "object": "chat.completion",
  "created": 1677652288,
  "model": "deepseek-v4-flash",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "你好！我是 DeepSeek 智能助手，很高兴为你服务。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 20,
    "total_tokens": 30
  }
}
choices[0].message.content

最重要的数据！这就是 AI 真正回复的文本内容。写代码时通常这样提取：data.choices[0].message.content。

usage

账单明细。告诉你这次对话消耗了多少 Token（提示词+回答），用于计算成本。

finish_reason

结束原因。"stop" 表示正常说完；"length" 表示字数达到上限被迫截断。

7

前端开发避坑指南

经验

把 API 集成到网页时，新手容易踩这些坑：

千万别暴露 API Key

浏览器端代码是对所有人可见的。在真实上线项目中，必须通过后端服务器转发请求，不要把 Key 直接写在前端 JS 里（除非像本站一样是纯本地教学演示）。

记得加 Loading 状态

AI 响应通常需要几秒到几十秒。必须给按钮加上禁用状态和 Loading 动画，防止用户以为死机了而疯狂点击。

处理超时和错误

网络可能会断，ApiKey 可能会欠费。一定要用 try...catch 包裹代码，并给用户友好的错误提示（参考 API 错误指南）。

JSON 格式化

AI 返回的文本里可能包含 Markdown 符号（如 ```json ... ```）。在 JSON.parse() 之前，记得先清洗掉这些多余字符。

总结：一句话理解 API 请求

调用 AI API 就像写一封信：

curl = 快递公司
URL = 收件地址
Headers = 信封信息（格式 + 身份证明）
-d 后面的 JSON = 信件内容（你要问什么、用哪个模型）
高级参数 = 额外要求（创造力、长度限制、是否打字机效果...）
