为什么会报错？别慌！

对接 API 就像是在和一台非常"死板"的机器打电话。如果你的发音稍微不标准，或者说的话它听不懂，它就会直接挂断，并丢给你一个 错误代码（Status Code）。

这些代码其实是线索。只要看懂了这些数字，你就知道问题出在哪里了。

4xx 开头：即使是你的锅，也能修 （客户端错误）

400 Bad Request

请求格式错误

从人话翻译："如果你填的表单乱七八糟，我看不懂。"

常见原因：JSON 格式写错了（少个逗号、引号）、缺了必填项、参数类型不对（要数字给了文字）。
401 Unauthorized

未授权 / 没登录

从人话翻译："你是谁？我不认识你，没带工牌不让进。"

常见原因：API Key 忘了填、填错了、或者过期了。
403 Forbidden

禁止访问

从人话翻译："我知道你是谁，但你没资格进这个房间。"

常见原因：账号余额不足、权限不够、IP 地址被封禁。
404 Not Found

找不到资源

从人话翻译："你给的地址是空的，这里没人住。"

常见原因：API 网址（URL）写错了、请求还是 v1 版本但服务已经升级到 v3 了。
429 Too Many Requests

请求太频繁

从人话翻译："你说话太快了，我反应不过来，歇会儿再说。"

常见原因：短时间内发了太多请求，触碰了频率限制（Rate Limit）。

5xx 开头：服务器的锅，你先歇会儿 （服务端错误）

500 Internal Server Error

服务器内部错误

从人话翻译："服务器崩了 / 厨师把菜炒糊了。"

这不是你的问题。通常是因为服务商的代码出 Bug 了，或者数据库挂了。

502 Bad Gateway 504 Gateway Timeout

网关错误 / 超时

从人话翻译："线路繁忙 / 客服电话打不通。"

中间的代理服务器连接不上后面的主服务器，或者主服务器处理太慢超时了。

遇到 5xx 怎么办？

别急着改代码。等几分钟再试，或者去服务商的官网看有没有公告说系统维护。

JSON 解析错误：信寄到了，但字我不认识

有时候 HTTP 状态码是 200（代表成功），但你还是拿不到数据。这通常是因为返回的内容不是标准的 JSON 格式，导致程序解析失败。

情况 1：格式不完整 

{
  "message": "Hello World"

就像一句话没说完，程序不知道在哪里结束，所以报错。

情况 2：返回了 HTML 网页 

<!DOCTYPE html>
<html>...</html>

你以为会收到数据，结果服务器因为报错直接给你返回了一个"错误页面"。尝试用 JSON 解析器去读网页代码，当然会报错。

调试小技巧：
如果遇到 `Unexpected token < in JSON at position 0` 这种错误，通常意味着你收到的不是 JSON，而是一个以 `<` 开头的 HTML 页面。 复习一下 JSON 格式 >
