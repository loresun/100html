基础模式 #01

一进一出（Single Turn）

核心特征：最简单高效的API交互模式，实现即时响应的单轮对话。用户在文本框输入内容，点击提交后直接获得AI的完整回答。
技术优势：响应速度快（通常2-10秒），实现简单，用户体验直观，服务器压力小。
适用场景：文本改写、语言翻译、内容总结、问题解答、风格转换、格式化处理等所有单次交互任务。
性能特点：并发处理能力强，可同时服务数百用户，每次调用消耗token固定可控。

技术优势：输入标准化，结果质量高，参数可复用，支持模板化批量生成，用户操作更规范。
适用场景：邮件生成、合同起草、报告撰写、产品描述、营销文案、简历制作等需要多要素组合的内容创建。
性能特点：单次调用成本略高但效果更佳，支持参数预设和快捷填充，可实现半自动化内容生产。

基础模式 #03

一进多出（N-Best）

核心特征：单次输入生成多个候选方案，利用AI的随机性创造多样化选择。用户可对比选择最佳结果，大幅提升创意质量。
技术优势：一次调用获得多个方案，降低重复请求成本，提供更丰富的创意选择，满足不同偏好需求。
适用场景：标题生成、口号创作、文案变体、创意命名、社交媒体内容、广告语制作等需要创意多样性的任务。
性能特点：成本效率高（相比多次单独调用），结果质量可控，支持用户主观选择，适合A/B测试场景。

📝 输入: 单一文本
🎲 处理: 单次调用+n=K
🎯 输出: K条候选卡片

基础模式 #04

核心特征：对多个输入项执行相同的处理逻辑，实现批量化自动处理。输入输出数量一一对应，大幅提升处理效率。
技术优势：支持并发处理，大幅节省人工时间，处理逻辑一致性强，质量稳定可控，适合规模化应用。
适用场景：文档批量翻译、内容批量润色、数据批量分析、图片批量描述、评论批量分类等重复性处理任务。
性能特点：并发处理能力强，处理速度快，支持进度追踪，可中断和恢复，适合大数据量场景。

# RAG知识库构建和查询系统 from langchain.vectorstores import Chroma from langchain.embeddings import HuggingFaceEmbeddings from langchain.text_splitter import RecursiveCharacterTextSplitter from langchain.document_loaders import PyPDFLoader import openai # 1. 文档处理和向量化 def build_knowledge_base(doc_paths): documents = [] for path in doc_paths: loader = PyPDFLoader(path) docs = loader.load() text_splitter = RecursiveCharacterTextSplitter( chunk_size=1000, chunk_overlap=200 ) documents.extend(text_splitter.split_documents(docs)) embeddings = HuggingFaceEmbeddings( model_name="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2" ) vectorstore = Chroma.from_documents( documents=documents, embedding=embeddings, persist_directory="./knowledge_base" ) return vectorstore # 2. RAG查询处理 def rag_query(question, vectorstore, top_k=3): relevant_docs = vectorstore.similarity_search(question, k=top_k) context = "\n".join([doc.page_content for doc in relevant_docs]) prompt = f""" 基于以下文档内容回答问题： 文档内容： {context} 问题：{question} 答案： """ response = openai.ChatCompletion.create( model="gpt-3.5-turbo", messages=[{"role": "user", "content": prompt}], temperature=0.1 ) return { "answer": response.choices[0].message.content, "sources": [doc.metadata for doc in relevant_docs] }
